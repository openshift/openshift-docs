= Updating the boot loader on {op-system} nodes using bootupd
include::_attributes/common-attributes.adoc[]
:context: updating-bootloader-rhcos

toc::[]

[role="_abstract"]
To update the boot loader on {op-system} nodes using `bootupd`, you must either run the `bootupctl update` command on {op-system} machines manually or provide a machine config with a `systemd` unit.

Unlike `grubby` or other boot loader tools, `bootupd` does not manage kernel space configuration such as passing kernel arguments.
To configure kernel arguments, see xref:../../nodes/nodes/nodes-nodes-managing.adoc#nodes-nodes-kernel-arguments_nodes-nodes-managing[Add kernel arguments to nodes].

For example, you can use `bootupd` to update the boot loader to protect against the BootHole vulnerability.

[NOTE]
====
On clusters that use the `x86_64` or ARM CPU architecture, {op-system} automatically updates the boot loader when a node gets upgraded to a new operating system image. For UEFI systems, the `bootloader-update.service` updates the boot loader inside the EFI System Partition. For Legacy BIOS systems, the `bootloader-update.service` writes the boot loader directly to the boot sectors. With these clusters, there is no need to manually update the boot loader.
====
