. Change to the `clusterresourceoverride-operator` namespace.
+
[source,terminal]
----
$ oc project clusterresourceoverride-operator
----

. Optional: Create a `ClusterResourceOverride` object for the Cluster Resource Override Operator:

.. Create a YAML file similar to the following:
+
[source,yaml]
----
apiVersion: operator.autoscaling.openshift.io/v1
kind: ClusterResourceOverride
metadata:
    name: deployment
spec:
  podResourceOverride:
    spec:
      memoryRequestToLimitPercent: 50
      cpuRequestToLimitPercent: 25
      limitCPUToMemoryPercent: 200
----
+
where
+
--
`metadata.name`:: Specifies a name for the CR. Use `cluster` for legacy single-profile mode, or any custom name (for example, `production`, `development`) for multi-profile mode.
`spec.podResourceOverride.spec.memoryRequestToLimitPercent`:: Specifies the percentage to override the container memory limit, if used, between 1-100. The default is `50`. This parameter is optional.
`spec.podResourceOverride.spec.cpuRequestToLimitPercent`:: Specifies the percentage to override the container CPU limit, if used, between 1-100. The default is `25`. This parameter is optional. Deprecated in favor of `cpuRequestOverride.type: LimitRelative`.
`spec.podResourceOverride.spec.limitCPUToMemoryPercent`:: Specifies the percentage to override the container memory limit, if used. Scaling 1 Gi of RAM at 100 percent is equal to 1 CPU core. This is processed before overriding the CPU request, if configured. The default is `200`. This parameter is optional.
--

+
.. Create the pod by running the following command:
+
[source,terminal]
----
$ oc create -f <file_name>.yaml
----
+
For example:
+
[source,terminal]
----
$ oc create -f cro-cr.yaml
----

. Optional: Create a `ClusterResourceOverride` object that also sets a container’s CPU request to a percentage of the CPU request already in the pod:

.. Create a YAML file similar to the following:
+
[source,yaml]
----
apiVersion: operator.autoscaling.openshift.io/v1
kind: ClusterResourceOverride
metadata:
    name: development
spec:
  podResourceOverride:
    spec:
      cpuRequestOverride:
        type: RequestRelative
        requestRelative:
          percent: 50
      memoryRequestToLimitPercent: 25
      limitCPUToMemoryPercent: 200
----
+
where
+
--
`metadata.name`:: Specifies a name for the CR. Use `cluster` for legacy single-profile mode, or any custom name (for example, `production`, `development`) for multi-profile mode.
`spec.podResourceOverride.spec.cpuRequestOverride.type`:: Specifies the strategy for CPU request override: `LimitRelative` (percentage of CPU limit) or `RequestRelative` (percentage of existing CPU request).
`spec.podResourceOverride.spec.cpuRequestOverride.requestRelative.percent`:: When using `RequestRelative` type, specifies the percentage of the existing CPU request to use as the new request.  For example, 50 means the request is halved, 75 means it is reduced to 75% of the original. This parameter is optional.
`spec.podResourceOverride.spec.memoryRequestToLimitPercent`:: Specifies the percentage to override the container memory limit, if used, between 1-100. The default is `50`. This parameter is optional.
`spec.podResourceOverride.spec.limitCPUToMemoryPercent`:: Specifies the percentage to override the container memory limit, if used. Scaling 1 Gi of RAM at 100 percent is equal to 1 CPU core. This is processed before overriding the CPU request, if configured. The default is `200`. This parameter is optional.
--
