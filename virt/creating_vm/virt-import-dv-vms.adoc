= Import a virtual machine image using the DataVolume API
:context: virt-import-dv-vms

toc::[]

[role="_abstract"]
You can import a virtual machine (VM) image into your cluster by using the `DataVolume` API. You can create a data volume from a container registry, web page, or object storage that contains the image.

////
Documentation Outline
=====================

Target persona: Advanced users, Cluster Administrators
User journey stage: Expand / Adopt
Job to be done: As an advanced user, I want to manage and import VM images
from diverse sources (HTTP, S3, oVirt, VMware, registry) using the DataVolume
API so that I can provision PVCs for OpenShift Virtualization on specialized
hardware (e.g., amd64, arm64, or s390x).

## Procedure: Importing a VM image from a container registry
proc-importing-vm-image-from-container-registry.adoc

Prerequisites:
- Access to the container registry
- Registry credentials stored in a Secret (if private)
- `virtctl` and `oc` CLI tools installed

Steps:
1. Create a DataVolume manifest with `source.registry.url`
   (docker:// prefix format)
2. (Optional) Set `pullMethod: node` to use the node docker cache
3. (Optional) Specify `platform.architecture` for multi-arch images (TP)
4. Apply the manifest with `oc create -f`
5. Monitor import progress with `oc get dv`

Verification:
- Confirm DV reaches `Succeeded` phase
- Confirm PVC is created and bound

## Procedure: Importing a VM image from an HTTP or HTTPS source
proc-importing-vm-image-from-http-source.adoc

Prerequisites:
- VM image accessible via HTTP/HTTPS URL
- (Optional) TLS certificates for custom CAs stored in a ConfigMap
- `oc` CLI tool installed

Steps:
1. Create a DataVolume manifest with `source.http.url`
2. (Optional) Reference a `certConfigMap` for custom CA certificates
3. (Optional) Reference a `secretRef` for basic auth credentials
4. Apply the manifest with `oc create -f`
5. Monitor import progress with `oc get dv`

Verification:
- Confirm DV reaches `Succeeded` phase
- Confirm PVC is created and bound

## Procedure: Importing a VM image from S3 object storage
proc-importing-vm-image-from-s3-object-storage.adoc

Prerequisites:
- VM image stored in an S3-compatible bucket
- S3 access credentials stored in a Secret
- `oc` CLI tool installed

Steps:
1. Create a Secret with S3 access key and secret key
2. Create a DataVolume manifest with `source.s3.url` and `secretRef`
3. (Optional) Specify a custom S3 endpoint for non-AWS S3 services
4. Apply the manifest with `oc create -f`
5. Monitor import progress with `oc get dv`

Verification:
- Confirm DV reaches `Succeeded` phase
- Confirm PVC is created and bound

## Reference: DataVolume source fields
ref-datavolume-source-fields.adoc

Reference table of supported DataVolume source types and their fields:
- `source.registry` — url, pullMethod, secretRef, certConfigMap, platform
- `source.http` — url, secretRef, certConfigMap, extraHeaders, secretExtraHeaders
- `source.s3` — url, secretRef, certConfigMap
- `source.blank` — (no subfields)
- `source.pvc` — namespace, name
- `source.snapshot` — namespace, name

Include supported content types (QCOW2, raw, ISO, archive) per source.
