[role="_abstract"]
The Cluster Observability Operator (COO) is an optional component of OpenShift Logging that provides UI visualization capabilities in the OpenShift web console. The COO enables you to query and view logs directly in your browser without external tools, and correlate logs with metrics and distributed traces.

[id="what-coo-provides_{context}"]
== What the Cluster Observability Operator provides

The Cluster Observability Operator adds observability visualization features to the OpenShift web console. When you install the COO alongside Vector and Loki, you can interact with your logs through built-in UI plugins rather than relying on external dashboards.

Core capabilities:

**Logs tab in the web console**:: A dedicated "Logs" tab appears in the OpenShift web console where you can query logs using LogQL, filter by namespace or pod, and view log lines with syntax highlighting.

**LogQL query interface**:: Query your Loki-stored logs directly in the browser using the LogQL query language. The interface provides query suggestions and helps you build label selectors.

**Observability UI plugins**:: The COO provides several UI plugins that enhance the OpenShift console:
+
* **Logging UI plugin**: Query and view logs
* **Dashboards UI plugin**: Visualize metrics
* **Monitoring UI plugin**: View alerts and Prometheus metrics
* **Distributed tracing UI plugin**: View trace data
* **Troubleshooting UI plugin**: Correlate signals to identify issues

**Signal correlation**:: The COO includes Korrel8r, an open source project that correlates logs, metrics, and traces. Korrel8r helps you navigate from an alert to related logs, or from a log entry to related traces, making troubleshooting faster.

[id="multi-tenant-monitoring_{context}"]
== Multi-tenant monitoring capabilities

Beyond log visualization, the COO provides standalone, customizable monitoring stacks that complement the default OpenShift monitoring:

**Namespace-scoped monitoring**:: Create independent monitoring stacks for specific namespaces or teams. Each stack has its own Prometheus instance, Alertmanager, and visualization.

**Standalone Prometheus instances**:: Deploy multiple Prometheus instances that collect metrics independently. This is useful in multi-tenant environments where teams need separate monitoring configurations.

**Thanos Querier (optional)**:: Query multiple Prometheus instances from a central location for a unified view across monitoring stacks.

**Alertmanager (optional)**:: Configure alert routing and notification channels specific to each monitoring stack.

These multi-tenant capabilities enable platform teams to provide observability-as-a-service to application teams, where each team can customize their monitoring and alerting without affecting other teams.

[id="incident-detection-and-correlation_{context}"]
== Incident detection and correlation

The COO includes features for grouping related alerts and identifying root causes:

**Incident detection**:: Automatically groups related alerts into incidents. Instead of seeing 20 individual alerts when a service fails, you see one incident with all related alerts grouped together.

**Korrel8r signal correlation**:: Navigates between different types of observability data:
+
* From an alert to the pod logs that triggered it
* From a log error message to related distributed traces
* From a metric spike to the audit logs showing who made configuration changes

This correlation reduces the time spent jumping between different tools and dashboards during troubleshooting.

[id="coo-in-openshift-logging_{context}"]
== COO in OpenShift Logging deployments

The Cluster Observability Operator is optional. You can deploy OpenShift Logging with Vector and Loki without installing the COO. In that case, you query Loki using external tools like Grafana or the Loki CLI.

Installing the COO is valuable when:

* You want to query logs without leaving the OpenShift web console
* You need to correlate logs with metrics and traces in one interface
* You are managing a multi-tenant cluster and want to provide namespace-scoped observability
* You prefer browser-based visualization over external dashboards

The COO is managed separately from the Vector and Loki operators. It has its own release cycle and can be installed or removed independently.

[id="coo-architecture_{context}"]
== COO architecture

The Cluster Observability Operator manages several components:

**UI Plugin deployments**:: Pods that serve the web console UI plugins for logging, dashboards, monitoring, and tracing visualization.

**Monitoring stacks**:: When you create a `MonitoringStack` custom resource, the COO deploys a Prometheus instance, optional Thanos Querier, and optional Alertmanager for that stack.

**Korrel8r instance**:: The signal correlation engine that understands the relationships between alerts, logs, metrics, and traces.

**Console plugin registration**:: The COO automatically registers its UI plugins with the OpenShift web console so they appear in the interface without manual configuration.
