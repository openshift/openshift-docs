= About Vector collector

[role="_abstract"]
Vector is the high-performance log collection engine in OpenShift Logging. Introduced in OpenShift Logging 6.0 as the replacement for Fluentd, Vector collects logs from all pods and containers, transforms the data, and forwards it to configured destinations.

[id="what-vector-does_{context}"]
== What Vector does

Vector is a high-performance observability data pipeline written in Rust. In OpenShift Logging, Vector serves as the log collector that runs on every node in your cluster.

Vector's primary functions:

Collects logs:: Vector runs as a DaemonSet with one pod on each node. It collects logs from all containers running on that node, including application logs, infrastructure logs, and audit logs.

Transforms log data:: Vector can parse, filter, and enrich log data before forwarding. This includes extracting structured fields from JSON logs, adding Kubernetes metadata (namespace, pod name, labels), and filtering out unwanted log entries.

Routes to destinations:: Vector forwards logs to one or more destinations based on your configuration. You can send logs to a local Loki instance, external log platforms like Splunk or CloudWatch, or both simultaneously.

[id="vector-architecture_{context}"]
== Vector architecture in OpenShift

Vector is deployed as a DaemonSet in the `openshift-logging` namespace. This deployment pattern ensures that every node in your cluster has a Vector pod collecting logs from that node's containers.

The Vector collector:

* Reads container logs from `/var/log/pods/` on each node
* Automatically discovers new pods and containers as they are created
* Extracts Kubernetes metadata from the pod specifications
* Processes logs according to the ClusterLogForwarder configuration
* Forwards processed logs to configured outputs

[id="vector-in-logging-6_{context}"]
== Vector in OpenShift Logging 6.0 and later

Vector became the default log collector starting with OpenShift Logging 6.0, replacing Fluentd which was used in Logging 5.x releases. The transition to Vector provides:

* High performance with low resource consumption due to Rust implementation
* Built-in support for logs and metrics in a single pipeline
* Vector Remap Language (VRL) for powerful log transformation
* Better backpressure handling and retry mechanisms
* Unified configuration model

If you are using OpenShift Logging 6.0 or later, you are using Vector as your log collector.

[id="vector-configuration_{context}"]
== Vector configuration

Vector is configured through the `ClusterLogForwarder` custom resource (CR), which is managed by the Red Hat OpenShift Logging Operator. The ClusterLogForwarder CR defines:

* **Inputs**: Which logs to collect (application, infrastructure, or audit)
* **Filters**: How to transform or filter log data
* **Outputs**: Where to send logs (Loki, CloudWatch, Splunk, Kafka, or other destinations)
* **Pipelines**: How inputs, filters, and outputs connect together

You do not configure Vector directly. Instead, the Logging Operator reads your ClusterLogForwarder CR and generates the appropriate Vector configuration.
