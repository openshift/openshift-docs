= Security compliance standards in {microshift-short}

[role="_abstract"]
{microshift-short} supports multiple host-level security postures for regulated edge environments.
Use CIS Level 2 hardening together with, or independently from, FIPS mode depending on your organizational mandates.

[id="microshift-cis-security-standards-fips_{context}"]
== Relationship to FIPS mode

FIPS mode controls cryptographic module behavior on the host and in {microshift-short} containers.
CIS Level 2 hardening controls broader host security configuration such as networking defaults, auditing, and firewall policy.

You can enable both when your environment requires cryptographic validation and CIS host hardening.
Configure FIPS when you install {op-system-base}, then apply CIS hardening and the {microshift-short}-required overrides before or after you install {microshift-short} RPM packages, according to your deployment process.

[id="microshift-cis-security-standards-boundaries_{context}"]
== Scope boundaries

The following boundaries apply to the current CIS Level 2 support for {microshift-short}:

* Package mode (RPM) is supported.
* {op-system-ostree} and {op-system-image} deployments are not covered in this documentation.
* Host compliance is assessed with OpenSCAP on the {op-system-base} system, not with the {ocp} Compliance Operator.
* Some CIS rule failures remain after a successful {microshift-short} deployment because of required container platform behavior.
