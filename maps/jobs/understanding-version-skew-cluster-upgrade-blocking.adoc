= Understanding Version Skew & Cluster Upgrade Blocking
:context: understanding-version-skew-cluster-upgrade-blocking

[role="_abstract"]
When updating or scaling an OpenShift Container Platform cluster, learn how to understand how version skew between node boot images and the running cluster version is detected by the Machine Config Operator so that you can prevent cluster upgrades from being blocked and ensure newly scaled nodes launch with a compatible operating system version. Automatic Mode: Available as the default for AWS, Google Cloud, Azure, and vSphere clusters when boot image management is enabled. The Machine Config Operator (MCO) automatically updates the version string upon cluster updates. Manual Mode: The default for all other platforms. The cluster administrator must manually update the version string in the MachineConfiguration object whenever boot images are updated None Mode: Disables skew monitoring entirely. It emits a Prometheus alert warning about potential scale-up issues (except on single-node OpenShift and bare-metal clusters, where alerts are suppressed).
