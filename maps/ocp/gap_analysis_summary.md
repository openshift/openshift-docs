# JTBD job map gap analysis

Modules used by the live documentation that no job map includes. Generated by `scripts/jtbd_gap_analysis.py`.

## The files

| File | One row is | Use it to |
| --- | --- | --- |
| `gap_analysis_main.csv` | an assembly with uncovered modules | pick what to map next |
| `gap_analysis_<branch>_unique.csv` | an assembly whose gap exists only on that branch | find branch-specific work |
| `gap_analysis_modules.csv` | a module, per assembly that includes it | look up one module, or filter to a directory |

Start with `gap_analysis_main.csv`. Sort by `uncovered` descending for the biggest wins, or by `coverage` ascending for the least-touched areas. Filter `all_branches` to `yes` for work that backports verbatim.

The two are joinable on `source_assembly`: find an assembly worth mapping in the rollup, then filter `gap_analysis_modules.csv` to that assembly for the module list to put in the job map.

Column meanings:

- `total_modules` / `uncovered` — modules the assembly includes, and how many no job map has picked up.
- `coverage` — the share already in a job map. `0%` means the assembly has not been touched at all.
- `all_branches` — `yes` if every uncovered module in the row is also a gap on every branch, so mapping it on `main` backports verbatim. `partial` means some modules are newer than the oldest branch. `no` means none of them are shared.
- `gap_on` / `gap_branch_count` — which branches a module is missing from, and how many.

## Regenerating

```
git worktree add --detach /tmp/jtbd-gap/4.20 upstream/enterprise-4.20
git worktree add --detach /tmp/jtbd-gap/4.21 upstream/enterprise-4.21
git worktree add --detach /tmp/jtbd-gap/4.22 upstream/enterprise-4.22
git worktree add --detach /tmp/jtbd-gap/5.0 upstream/enterprise-5.0

python scripts/jtbd_gap_analysis.py analyze . --label main \
    -o /tmp/jtbd-gap/main.json
python scripts/jtbd_gap_analysis.py analyze /tmp/jtbd-gap/4.20 --label 4.20 \
    -o /tmp/jtbd-gap/4.20.json
python scripts/jtbd_gap_analysis.py analyze /tmp/jtbd-gap/4.21 --label 4.21 \
    -o /tmp/jtbd-gap/4.21.json
python scripts/jtbd_gap_analysis.py analyze /tmp/jtbd-gap/4.22 --label 4.22 \
    -o /tmp/jtbd-gap/4.22.json
python scripts/jtbd_gap_analysis.py analyze /tmp/jtbd-gap/5.0 --label 5.0 \
    -o /tmp/jtbd-gap/5.0.json

python scripts/jtbd_gap_analysis.py report /tmp/jtbd-gap/*.json \
    --base main --outdir maps/ocp
```

Includes are matched textually; `ifdef` and `ifeval` are not evaluated, so a module included only under a non-OCP condition counts as live. The gap is over-reported rather than under-reported.
