= Creating the AWS Bedrock credentials secret by using the CLI

[role="_abstract"]
Use the command line interface to store the credentials that {ols-long} uses to authenticate with {aws-short} Bedrock.

{aws-short} Bedrock supports multiple authentication methods: Bearer token, IAM keys, and IAM keys with STS role assumption.

.Prerequisites

* You have access to the {oc-first} as a user with the `cluster-admin` role. Alternatively, you are logged in to a user account that has permission to create a secret to store the Provider tokens.

* You have installed the {ols-long} Operator.

* You have an {aws-short} infrastructure account with active permission to access your required models.

.Procedure

. Create a YAML file that has the credential secret for {aws-short} Bedrock.
+
Use the following example to create the Secret using a Bearer token:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: bedrock-credentials
  namespace: openshift-lightspeed
type: Opaque
stringData:
  apitoken: <mantle-bearer-token>
----

. Optional: As another option, you can use {aws-short} IAM keys to authenticate your LLM provider. Use the following example to authenticate by using IAM keys:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: bedrock-credentials
  namespace: openshift-lightspeed
type: Opaque
stringData:
  aws_access_key_id: <aws-access-key-id>
  aws_secret_access_key: <aws-secret-access-key>
----

. Optional: If your primary access keys must assume a specific role to call {aws-short} Bedrock, use IAM keys with STS role assumption. Use the following example:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: bedrock-credentials
  namespace: openshift-lightspeed
type: Opaque
stringData:
  aws_access_key_id: <aws-access-key-id>
  aws_secret_access_key: <aws-secret-access-key>
  role_arn: arn:aws:iam::123456789012:role/BedrockAccessRole
----

. Create the Secret by running the following command:
+
[source,terminal]
----
$ oc create -f <secret_filename>.yaml
----
