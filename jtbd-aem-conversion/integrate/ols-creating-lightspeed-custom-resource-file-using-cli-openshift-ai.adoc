= Creating the {ols-long} custom resource file for {rhoai} by using the CLI

[role="_abstract"]
Use the command line interface to create the custom resource (CR) file required to deploy {ols-long} with your {rhoai} provider.

.Prerequisites

* You have access to the {oc-first} and have logged in as a user with the `cluster-admin` role. As another option, you have logged in to a user account that has permission to create a cluster-scoped CR file.

* You have a {rhoai} provider available for use with the {ols-long} Service.

* You have installed the {ols-long} Operator.

.Procedure

. Create an `OLSConfig` file that has the YAML content for your {rhoai} provider.
+
Use the following example to create the `OLSConfig` CR to configure {ols-long} with your {rhoai} provider:
+
[source,yaml]
----
apiVersion: ols.openshift.io/v1alpha1
kind: OLSConfig
metadata:
  name: cluster
spec:
  llm:
    providers:
    - credentialsSecretRef:
        name: rhoai-api-keys
      models:
      - name: <model_name>
      name: red_hat_openshift_ai
      type: rhoai_vllm
      url: <url>
  ols:
    defaultProvider: red_hat_openshift_ai
    defaultModel: <model_name>
----
+
* `spec.llm.providers.credentialsSecretRef.name` specifies the name of the Secret that has the API key for the provider. By default, the {rhoai} API key requires a token as part of the request. If your {rhoai} endpoint does not require a token, you must still set the token value to any valid string for the request to authenticate.
+
* `spec.llm.providers.url` specifies the URL endpoint for the provider. The URL must end with `v1` to be valid. For example, `\https://<model_name>.<domain_name>.com:443/v1`.

. Run the following command so that the Operator deploys {ols-long} using the information in the YAML configuration file.
+
[source,terminal]
----
$ oc create -f /path/to/config-cr.yaml
----
