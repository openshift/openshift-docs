= Creating the {ols-long} custom resource file for AWS Bedrock by using the CLI

[role="_abstract"]
Use the command line interface to create the custom resource (CR) file required to deploy {ols-long} with your {aws-short} Bedrock provider.

.Prerequisites

* You have access to the {oc-first} and have logged in as a user with the `cluster-admin` role. As another option, you have logged in to a user account that has permission to create a cluster-scoped CR file.

* You have an {aws-short} Bedrock provider available for use with the {ols-long} Service.

* You have installed the {ols-long} Operator.

* You have created the credentials secret for your {aws-short} Bedrock provider.

.Procedure

. Create an `OLSConfig` file that has the YAML content for your {aws-short} Bedrock provider.
+
Use the following example to create the `OLSConfig` CR to configure {ols-long} with your {aws-short} Bedrock provider:
+
[source,yaml]
----
apiVersion: ols.openshift.io/v1alpha1
kind: OLSConfig
metadata:
  name: cluster
spec:
  llm:
    providers:
      - credentialsSecretRef:
          name: bedrock-credentials
        models:
        - name: anthropic.claude-opus-4-7
        - name: deepseek.v3.1
        name: bedrock
        type: bedrock
        url: https://bedrock-mantle.us-east-1.api.aws
  ols:
    defaultModel: anthropic.claude-opus-4-7
    defaultProvider: bedrock
----

. Run the following command so that the Operator deploys {ols-long} using the information in the YAML configuration file.
+
[source,terminal]
----
$ oc create -f /path/to/config-cr.yaml
----
