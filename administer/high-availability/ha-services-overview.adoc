= Keep serverless workloads available through disruptions
:context: ha-services-overview

toc::[]

[role="_abstract"]
You can keep serverless workloads available during node drains, upgrades, and zone failures by configuring high availability (HA) replicas for the Knative Serving and Knative Eventing control-plane components.

include::snippets/serverless-ha-intro.adoc[]

Leader election is enabled by default, so the control plane survives the loss of a single controller without any configuration on your part. To keep workloads available when a node drains, an upgrade rolls through, or a zone fails, set the number of replicas for each control-plane component and control how aggressively {ocp-product-title} is allowed to evict them.

Configure high availability separately for each part of the installation that your workloads depend on:

* Knative Serving components, such as the `activator`, `autoscaler`, `controller`, and the Kourier gateway.

* Knative Eventing components, and the Knative broker implementation for Apache Kafka if you use it.

Each of these is configured through its own custom resource, and each supports overriding the default pod disruption budgets when the defaults are too strict or too permissive for your cluster.
