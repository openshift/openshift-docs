= Configure and deploy {ols-long} autonomous agents
include::_attributes/common-attributes.adoc[]
:context: ols-configuring-deploying-agentic-lightspeed

toc::[]

[role="_abstract"]
Configure and deploy {ols-long} autonomous agents so that you can describe a cluster problem in plain language and have an agent investigate and resolve it for you. Instead of running diagnostic commands and correlating the output yourself, you delegate the task: the agent connects to a large language model (LLM) provider, queries live cluster state through its tools, reasons across multiple steps, and returns findings or applies the fix. After you install the {ols-long} Operator, complete this configuration to turn on that end-to-end troubleshooting and remediation workflow in your {ocp-product-title} cluster.

:FeatureName: {ols-long} autonomous agents
include::snippets/technology-preview.adoc[]
:FeatureName!:

[IMPORTANT]
====
{ols-long} autonomous agents is available in the {ols-long} 2.0 release stream. The configuration in this document applies to {ols-long} 2.0 and later versions.
====

[NOTE]
====
The instructions assume that you are configuring {ols-long} autonomous agents using the `kubeadmin` user account. If you are using a regular user account with `cluster-admin` privileges, read the section of the documentation that discusses Role-Based Access Control (RBAC).
====

To configure {ols-long} autonomous agents, you create a credentials secret for your LLM provider, an `LLMProvider` custom resource (CR) that defines the provider connection, and an `Agent` CR that pairs the provider with a model. You then confirm that the agent is deployed and ready to handle requests.
