= Route TLS requests to services
include::_attributes/common-attributes.adoc[]
:context: routing-tls-requests-to-services

toc::[]

[role="_abstract"]
To route encrypted TLS traffic to a backend that terminates TLS, configure a Gateway API `TLSRoute` custom resource (CR). A `TLSRoute` CR matches the Server Name Indication (SNI) hostname from the TLS handshake and forwards the still-encrypted connection. `TLSRoute` is the only Gateway API route kind that supports TLS passthrough.

The `openshift-default` GatewayClass does not support passthrough or mixed-mode listeners. Use a GatewayClass whose implementation supports TLSRoute passthrough, such as {SMProductName}. Confirm the GatewayClass name that your mesh or ingress implementation provides before you deploy these resources.

Do not attach a `TLSRoute` CR to a listener that uses `tls.mode: Terminate`. That combination is an extended Gateway API feature and is not part of the standard-channel passthrough profile. To terminate TLS at the gateway for HTTP applications, use an HTTPS listener with an `HTTPRoute` CR.

To route TLS passthrough traffic, complete the following tasks:

* Configure a TLS passthrough listener on a compatible gateway.
* Optional: Share port `443` between a passthrough listener and a terminated HTTPS listener when your implementation supports mixed mode.
* Create a `TLSRoute` CR that matches SNI hostnames and forwards traffic to a backend service.
