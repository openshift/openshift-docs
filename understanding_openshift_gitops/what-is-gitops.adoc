= What is OpenShift GitOps?
:context: what-is-gitops

toc::[]

[role="_abstract"]
GitOps is a declarative way to implement continuous deployment for cloud native applications. You can use GitOps to create repeatable processes for managing {OCP} clusters and applications across multicluster Kubernetes environments.

The GitOps workflow pushes an application through development, testing, staging, and production. GitOps either deploys a new application or updates an existing one, so you only need to update the repository; GitOps automates everything else.

GitOps is a set of practices that use Git pull requests to manage infrastructure and application configurations. In GitOps, the Git repository is the only source of truth for system and application configuration. This repository contains a declarative description of the infrastructure you need in your specified environment. An automated process ensures your environment matches the described state. The repository also contains the entire state of the system, so changes are visible and auditable. By using GitOps, you resolve the issues of infrastructure and application configuration sprawl.

GitOps defines infrastructure and application definitions as code. It uses this code to manage multiple workspaces and clusters, simplifying the creation of infrastructure and application configurations. You can store the configuration of clusters and applications in Git repositories, then follow the Git workflow to apply these repositories to your chosen clusters. You can apply the core principles of developing and maintaining software in a Git repository to the management of your cluster and application configuration files.
