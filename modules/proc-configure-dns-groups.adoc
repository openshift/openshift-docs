= Configure DNS groups on existing clusters

[role="_abstract"]
You can migrate an existing deployment to use DNS groups by creating an active-groups TXT record and assign each DNS operator to a group. Create the TXT record before configuring the operators so that groups serving traffic remain active during the migration.

.Prerequisites

* You installed {prodname} on the {ocp} clusters that you want to configure.
* You installed the {oc-first} and have administrator access to those clusters.
* You installed the `kubectl-kuadrant_dns` CLI and added it to your `PATH`.

.Procedure

. Connect to the cluster that contains the DNS provider credentials `Secret` object.

. Add the group that currently serves traffic to the active-groups TXT record by running the following command:
+
[source,terminal]
----
$ kubectl-kuadrant_dns add-active-group _<group_id>_ --providerRef <namespace>/<name> --domain <domain>
----
+
* Replace `_<group_id>_` with the group ID that you will assign to the DNS operator.
* Replace `_<domain>_` with the domain of the managed zone.
* Replace `_<namespace>_` with the namespace containing the DNS provider credentials `Secret` object.
* Replace `_<name>_` with the name of the DNS provider credentials `Secret` object.
+
This command creates `kuadrant-active-groups.<domain>` if it does not exist, or adds the group to the existing active list. 

. Verify the active groups by running the following command:
+
[source,terminal]
----
$ kubectl-kuadrant_dns get-active-groups --providerRef _<namespace>_/_<name>_ --domain _<domain>_
----
+
* Replace `_<domain>_` with the domain of the managed zone.
* Replace `_<secret_namespace>_` with the namespace containing the DNS provider credentials `Secret` object.
* Replace `_<secret_name>_` with the name of the DNS provider credentials `Secret` object.

.Example TXT record
[source,terminal]
----
Record name: kuadrant-active-groups.<domain>
Record type: TXT
Value: "version=1;groups=GROUP_ID1&&GROUP_ID2"
----

. Connect to the cluster containing the DNS operator that you want to configure.

. Assign the operator to its group by updating the `dns-operator-controller-env` config map:
+
[source,terminal]
----
$ oc patch configmap dns-operator-controller-env --namespace _<namespace>_ --type merge --patch '{"data":{"GROUP":"_<group_id>_"}}'
----
+
* Replace `_<namespace>_` with the namespace containing the DNS operator.
* Replace `_<group_id>_` with the group ID that you want to assign to the DNS operator.

. Restart the DNS operator to apply the group assignment:
+
[source,terminal]
----
$ oc rollout restart deployment dns-operator-controller-manager --namespace _<namespace>_
----

. Repeat the operator configuration steps for each remaining cluster.

.Verification

. Check the operator logs for the configured group ID:
+
[source,terminal]
----
$ oc logs deployment/dns-operator-controller-manager --namespace _<namespace>_ --container manager
----
.Example output 
[source,terminal]
----
{"level":"info","ts":"2006-1-2T15:4:5","logger":"setup","msg":"overriding group flag with \"group1\" value"}
{"level":"info","ts":"2006-1-2T15:4:5","logger":"setup","msg":"using group: group1"}
----

. Check the group assignment of the `DNSRecord` CRs:
+
[source,terminal]
----
$ oc get dnsrecords -A -o custom-columns='NAMESPACE:.metadata.namespace,NAME:.metadata.name,OWNER_ID:.status.ownerID,GROUP:.status.group' --watch
----

.Example output of TXT records
----
heritage=external-dns
external-dns/group=<GROUP ID>
external-dns/owner=<ownerID>
external-dns/targets=...
external-dns/version=1
----
