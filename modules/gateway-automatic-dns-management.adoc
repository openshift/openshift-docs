= Automatic DNS management

[role="_abstract"]
When you deploy a `Gateway` object in the `openshift-ingress` namespace to use automatic DNS management, you must configure listener route attachment rules to support multi-namespace deployments.

[NOTE]
====
Setting `spec.listeners[*].allowedRoutes.namespaces.from` to `Same` on a Gateway in `openshift-ingress` restricts route attachment to the `openshift-ingress` namespace. If left unset, the Gateway defaults to this same behavior and only accepts route attachments from its own namespace. If you deploy `HTTPRoute`, `GRPCRoute` or `TLSRoute` objects in user namespaces, you cannot attach routes to the Gateway.
====

The following example creates a Gateway in the `openshift-ingress` namespace with a listener hostname under the cluster base domain, enabling automatic DNS management. The example also sets `allowedRoutes.namespaces.from` to `Selector` to allow route attachment from labeled application namespaces.

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: managed-dns-gateway
  namespace: openshift-ingress
spec:
  gatewayClassName: openshift-gateway-manager
  listeners:
  - name: https
    hostname: "*.gwapi.<domain>"
    port: 443
    protocol: HTTPS
    tls:
      mode: Terminate
      certificateRefs:
      - name: gwapi-wildcard 
    allowedRoutes:
      namespaces:
        from: Selector
        selector:
          matchLabels:
            gateway-access: "true"
----

where:

`metadata.namespace`:: Deploying in `openshift-ingress` enables automatic DNS record management by the Ingress Operator.
`spec.listeners.hostname`:: Replace `<domain>` with your cluster base domain. You can run the following command to get your domain name:
+
[source,terminal,subs="+quotes"]
----
$ oc get dns.config.openshift.io cluster -o jsonpath='{.spec.baseDomain}'
----
+
`spec.listeners.allowedRoutes.namespaces.from`:: Configured to `Selector` (or `All`) so route resources in designated application namespaces can attach. `Same` is not supported for cross-namespace application routes.

When you deploy a `Gateway` in the `openshift-ingress` namespace, the Ingress Operator automatically provisions DNS records for each listener hostname. You can verify that DNS is configured correctly by checking the `DNSReady` condition on the `Gateway` resource:

[source,terminal]
----
$ oc -n openshift-ingress get gateway managed-dns-gateway -o jsonpath='{.status.conditions[?(@.type=="DNSReady")]}' | jq
----

.Example output
[source,json]
----
{
  "lastTransitionTime": "2025-01-15T12:00:00Z",
  "message": "All the listeners have DNS ready",
  "reason": "AllListenersReady",
  "status": "True",
  "type": "DNSReady"
}
----

If `DNSReady` is `False`, inspect the listener-level conditions for specific failure reasons. For more information, see "Verifying Gateway infrastructure status".
