= Configuring DNS for on-premise gateways

[role="_abstract"]
Configure DNS records manually on on-premise environments to ensure clients can reliably resolve your gateway.

The Ingress Operator creates a `DNSRecord` custom resource (CR) from the listener hostname only when the `Gateway` CR is in the `openshift-ingress` namespace and the hostname matches the cluster base domain. If you create the gateway in another namespace, the Operator does not create a `DNSRecord` CR, and you must publish DNS yourself.

On on-premise platforms, a `DNSRecord` CR in `openshift-ingress` is marked as unmanaged because the Ingress Operator does not implement on-premise DNS providers. You must still configure DNS records to point to the IP address of your load balancer.

.Prerequisites
* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the {oc-first}.
* You have configured a load balancer controller, such as MetalLB, for your cluster.
* Your gateway has been assigned an external network address by the load balancer.
* Your gateway is located in the `openshift-ingress` namespace.

.Procedure

. Retrieve the external IP address assigned to your gateway by the load balancer by running the following command:
+
[source,terminal]
----
$ oc -n openshift-ingress get gateway <gateway_name>
----
+
Note the IP address listed in the `ADDRESS` column.

. Access your organization's DNS provider or server.

. Create a DNS record, such as an A record or wildcard A record, that maps the listener's hostname to the external IP address of your gateway.
