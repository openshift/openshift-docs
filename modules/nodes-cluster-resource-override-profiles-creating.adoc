= Create a project-level resource override

[role="_abstract"]
You can create a `ResourceOverride` custom resource (CR) so that selected pods in an {product-title} project use their own CPU and memory override ratios. Project overrides apply ratios that differ from the cluster-wide `ClusterResourceOverride` object.

For descriptions of every field, see xref:#nodes-cluster-resource-override-profiles-reference_{context}[Project-level resource override parameters].

.Prerequisites

* The Cluster Resource Override Operator is installed.
* A `ClusterResourceOverride` CR named `cluster` exists.
* You have the `admin` or `edit` role on the project.
* For `memoryRequestToLimitPercent`, `cpuRequestToLimitPercent`, and `limitCPUToMemoryPercent`, the containers have a memory or CPU limit in the pod spec or from a `LimitRange` object.
* For `cpuRequestToRequestPercent`, the containers have a CPU request in the pod spec or from a `LimitRange` object.

.Procedure

. Add the Cluster Resource Override opt-in label to the project:
+
[source,terminal]
----
$ oc label namespace <project_name> clusterresourceoverrides.admission.autoscaling.openshift.io/enabled=true
----
+
.Example
[source,terminal]
----
$ oc label namespace my-namespace clusterresourceoverrides.admission.autoscaling.openshift.io/enabled=true
----
+
If the project already has the label, the command reports that the namespace was not labeled. You can continue to the next step.

. Create a `ResourceOverride` object YAML file (for example, `ro-cr.yaml`):
+
[source,yaml]
----
apiVersion: autoscaling.openshift.io/v1
kind: ResourceOverride
metadata:
  name: stateless
  namespace: my-namespace
spec:
  podResourceOverride:
    spec:
      memoryRequestToLimitPercent: 50
      cpuRequestToRequestPercent: 50
  podSelector:
    matchLabels:
      tier: stateless
----
+
where:
+
--
`metadata.name`:: Specifies the name of the object. The name must be unique in the project. If more than one object matches a pod, the webhook applies the object whose name comes first in alphabetical order.
`metadata.namespace`:: Specifies the project where the override applies. The project must have the `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled: "true"` label.
`spec.podResourceOverride.spec.memoryRequestToLimitPercent`:: Specifies the percentage of the container memory limit to use as the memory request, from 1 to 100. This parameter is optional.
`spec.podResourceOverride.spec.cpuRequestToRequestPercent`:: Specifies the percentage of the existing CPU request to use as the CPU request, from 1 to 100. The webhook applies this value after the other configured overrides and calculates it from the CPU request on the original pod. This parameter does not require a CPU limit. This parameter is optional.
`spec.podSelector`:: Optional. Specifies the pods in the project that use these ratios. If you omit `podSelector`, or leave it empty, every pod in the project matches this object.
`spec.podSelector.matchLabels`:: Specifies labels that a pod must have to match this object. The pod must include every label in the map.
--

. Create the `ResourceOverride` object:
+
[source,terminal]
----
$ oc create -f <file_name>.yaml
----
+
.Example
[source,terminal]
----
$ oc create -f ro-cr.yaml
----

.Verification

* Confirm that the object exists:
+
[source,terminal]
----
$ oc get resourceoverride stateless -n my-namespace
----
