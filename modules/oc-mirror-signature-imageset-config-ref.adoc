= ImageSetConfiguration fields for signature mirroring

[role="_abstract"]
The `ImageSetConfiguration` file defines which images the oc-mirror plugin mirrors to your disconnected registry. When signature verification is required, you must ensure that all necessary images are included in the configuration, because the oc-mirror plugin mirrors signatures only for images that are explicitly defined.

The following sections describe the key fields in the `ImageSetConfiguration` file that are relevant to signature mirroring.

[id="oc-mirror-signature-imageset-platform_{context}"]
== Platform images

The `mirror.platform` section specifies which {product-title} release images to mirror. These images are required for cluster installation and upgrades.

[cols="2,4", options="header"]
|===
|Field |Description

|`mirror.platform.channels`
|Specifies the release channels to mirror. Each channel entry includes the channel name and optional version constraints. The signatures for all images in the specified channels are automatically mirrored.

|`mirror.platform.channels.name`
|The name of the release channel, such as `stable-{product-version}` or `fast-{product-version}`.

|`mirror.platform.channels.minVersion`
|The minimum version to include from this channel. Versions below this value are not mirrored.

|`mirror.platform.channels.maxVersion`
|The maximum version to include from this channel. Versions above this value are not mirrored.

|`mirror.platform.graph`
|When set to `true`, the oc-mirror plugin builds and pushes the graph-data image, which is required for the OpenShift Update Service (OSUS). Set this to `true` if you use OSUS for cluster updates.
|===

[id="oc-mirror-signature-imageset-operators_{context}"]
== Operator images

The `mirror.operators` section specifies which operator catalogs and packages to mirror. Operator images and their signatures are mirrored based on the catalog and package configuration.

[cols="2,4", options="header"]
|===
|Field |Description

|`mirror.operators.catalog`
|The operator catalog index image to mirror. Use the full registry path, such as `registry.redhat.io/redhat/redhat-operator-index:v{product-version}`.

|`mirror.operators.packages`
|A list of specific operator packages to include. If omitted, all packages in the catalog are mirrored.

|`mirror.operators.packages.name`
|The name of the operator package to mirror.

|`mirror.operators.packages.channels`
|Specifies which channels of the operator to mirror. You must always include the default channel for the operator package.
|===

[id="oc-mirror-signature-imageset-additional_{context}"]
== Additional images

The `mirror.additionalImages` section specifies additional images to mirror that are not part of a release channel or operator catalog. This section is critical for mirroring support images that are required for cluster operations and debugging.

[cols="2,4", options="header"]
|===
|Field |Description

|`mirror.additionalImages`
|A list of additional images to mirror. Each image must be specified with its full registry path.

|`mirror.additionalImages.name`
|The full path to the image, including the registry hostname. You can specify images by tag or by digest. Signatures are mirrored for all images in this list.
|===

[IMPORTANT]
====
You must use explicit registry hostnames for all images listed under `additionalImages`. Without explicit hostnames, the plugin mirrors the images to unexpected target paths and signature verification might fail.
====

[id="oc-mirror-signature-imageset-example_{context}"]
== Complete example for disconnected environments

The following example `ImageSetConfiguration` file includes platform images, Day 2 Operators commonly used in telecommunications environments, and support images required for debugging and troubleshooting:

[source,yaml]
----
kind: ImageSetConfiguration
apiVersion: mirror.openshift.io/v2alpha1
mirror:
  platform:
    channels:
    - name: stable-{product-version}
      minVersion: {product-version}.0
      maxVersion: {product-version}.0
    graph: true
  operators:
    - catalog: registry.redhat.io/redhat/redhat-operator-index:v{product-version}
      packages:
      - name: cluster-logging
        channels:
        - name: stable
      - name: elasticsearch-operator
        channels:
        - name: stable
      - name: local-storage-operator
        channels:
        - name: stable
      - name: metallb-operator
        channels:
        - name: stable
      - name: sriov-network-operator
        channels:
        - name: stable
      - name: ptp-operator
        channels:
        - name: stable
      - name: node-feature-discovery-operator
        channels:
        - name: stable
  additionalImages:
  # Support images for debugging and troubleshooting
  - name: registry.redhat.io/openshift4/ose-must-gather:v{product-version}
  - name: registry.redhat.io/openshift4/ose-tools-rhel9:v{product-version}
  - name: registry.redhat.io/openshift4/ose-cli:v{product-version}
  # Universal Base Images
  - name: registry.redhat.io/ubi9/ubi:latest
  - name: registry.redhat.io/ubi9/ubi-minimal:latest
----

The support images serve the following purposes:

`ose-must-gather`:: Required for the `oc adm must-gather` command, which collects diagnostic data from the cluster.

`ose-tools-rhel9`:: Required for the toolbox container, which provides a debugging environment with common troubleshooting tools.

`ose-cli`:: Required for the `oc debug` command, which creates a debug pod on a node.

[id="oc-mirror-signature-imageset-third-party_{context}"]
== Third-party and community catalogs

Certified, marketplace, and community operator catalogs contain third-party content. Red{nbsp}Hat does not guarantee the availability or validity of signatures for images in these catalogs. If you include third-party catalogs in your `ImageSetConfiguration` file and signature verification is required, verify that the source images have valid sigstore signatures before mirroring.

To mirror images from third-party catalogs without signatures, you can disable signature mirroring by using the `--remove-signatures` flag:

[source,terminal]
----
$ oc mirror --config=imageset-config.yaml <destination_registry> --remove-signatures
----

[WARNING]
====
Disabling signature mirroring prevents signature verification for the mirrored images. Use this option only for images that do not have sigstore signatures at the source registry.
====
