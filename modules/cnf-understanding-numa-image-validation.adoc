= Understanding NUMA image validation

[role="_abstract"]
The NUMA Resources Operator validates scheduler and Resource Topology Exporter (RTE) images to ensure that only trusted images run with elevated privileges.

[id="cnf-understanding-scheduler-image-validation_{context}"]
== Scheduler image validation

The NUMA Resources Operator validates scheduler images to ensure that only trusted images run with scheduler privileges.

By default, the operator enforces the following validation rules for images specified in the `NUMAResourcesScheduler` custom resource `spec.imageSpec` field:

Digest-based references required:: The image reference must use a SHA-256 digest format. For example, `registry.redhat.io/openshift4/noderesourcetopology-scheduler-rhel9@sha256:abc123...` is valid, but `registry.redhat.io/openshift4/noderesourcetopology-scheduler-rhel9:v5.0` is rejected.

Trusted digest list:: To be valid, the image digest must be either:

* Included in the operator's trusted list of production scheduler images for the current release channel, or

* The final digest released in the previous release channel.

If you specify an image that does not meet these requirements, the operator sets the `NUMAResourcesScheduler` resource status to `Degraded` with reason `InvalidSchedulerImage`, and the scheduler pods are not created.

[NOTE]
====
The `spec.imageSpec` field is required. You must specify a scheduler image using a digest-based reference. For standard deployments, use the production scheduler image for your {product-title} release from `registry.redhat.io`. In disconnected environments, mirror this image to your registry and reference it by digest. If anything causes the digest to change from the original one, it needs to be added to the extendable list of digests.
====

* Check the scheduler validation status by running the following command:
+
[source,terminal]
----
$ oc get numaresourcesscheduler numaresourcesscheduler \
  -o jsonpath='{range .status.conditions[?(@.type=="Degraded")]}{.status}{" - "}{.reason}{": "}{.message}{"\n"}{end}'
----
+
The following example illustrates a typical validation failure output:
+
[source,terminal]
----
True - InvalidSchedulerImage: image "registry.example.com/custom-scheduler:v1.0" must be referenced by digest, not by tag
----

[id="cnf-understanding-rte-image-validation_{context}"]
== RTE image validation

The NUMA Resources Operator validates Resource Topology Exporter (RTE) images to ensure that only trusted images run with RTE privileges on worker nodes.

By default, the operator enforces the following validation rules for images specified in the `NUMAResourcesOperator` custom resource `spec.exporterImage` field:

Digest-based references required:: The image reference must use a SHA-256 digest format. For example, `registry.redhat.io/openshift4/numaresources-rhel9-operator@sha256:abc123...` is valid, but `registry.redhat.io/openshift4/numaresources-rhel9-operator:v5.0` is rejected.

Trusted digest list:: To be valid, the image digest must be either:

* Included in the operator's trusted list of production RTE images for the current release channel, or

* The final digest released in the previous release channel.

If you specify an image that does not meet these requirements, the operator sets the `NUMAResourcesOperator` resource status to `Degraded` with reason `InvalidExporterImage`, and the RTE daemon set pods are not created.

[NOTE]
====
The `spec.exporterImage` field is optional. If not specified, the operator uses the default RTE image for your {product-title} release. For standard deployments, the default image is sufficient. In disconnected environments, mirror the production RTE image to your registry and reference it by digest. If anything causes the digest to change from the original one, it needs to be added to the extendable list of digests.
====

* Check the RTE validation status by running the following command:
+
[source,terminal]
----
$ oc get numaresourcesoperator numaresourcesoperator \
  -o jsonpath='{range .status.conditions[?(@.type=="Degraded")]}{.status}{" - "}{.reason}{": "}{.message}{"\n"}{end}'
----
+
The following example illustrates a typical validation failure output:
+
[source,terminal]
----
True - InvalidExporterImage: image "registry.example.com/custom-rte:v1.0" must be referenced by digest, not by tag
----
