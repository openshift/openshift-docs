= Configuring listener routing and security settings

[role="_abstract"]
To ensure that your applications receive only authenticated and authorized traffic, you must specify the allowed protocols and ports for your gateway. If you are routing secure traffic, you must also configure TLS settings. You can define these parameters by configuring the `spec.listeners` field in your `Gateway` custom resource (CR).

[IMPORTANT]
====
If your gateway is accessible from other namespaces, always configure the `spec.listeners[].allowedRoutes[].namespaces.selector` field with a selector for the permitted namespaces. By specifying a namespace selector, you prevent possible misuse or hijacking of the gateway from other namespaces.

If nothing is listed in the `spec.listeners[].allowedRoutes[]` field, the gateway is accessible only from the same namespace.
====

.Prerequisites

* You have logged in as a user with `cluster-admin` privileges.
* You have created the `GatewayClass` resource and named the resource `openshift-default`.
* You have obtained the cluster domain name by using the `oc get ingresses.config/cluster -o jsonpath={.spec.domain}` command. You need the domain name for the procedure.
* You have chosen a subdomain for your `Gateway` listener hostnames so that the hostnames have the `*.<subdomain>.<domain>` format, such as `gateways.domain.com`. Use the this wildcard hostname for the following prerequisite:
** Create a certificate, such as `wildcard.crt`, and a key, such as `wildcard.key`, for hostnames in that domain.
** Configure the certificate to allow wildcard hostnames to have the `*.gateways.domain.com` format.
** You have created a Secret by using the following command. Use the certificate name and key name from the earlier prerequisite step.
+
[source,terminal]
----
$ oc -n openshift-ingress create secret tls gwapi-wildcard --cert=wildcard.crt --key=wildcard.key
----

.Procedure

. Create or edit a `Gateway` YAML file to include your listener configuration.
+
The following example demonstrates a `Gateway` CR with two listeners, one for HTTP and one for HTTPS. For detailed descriptions of the listener fields, see "Gateway listener configuration reference". With this example configuration, only `HTTPRoute` custom resources (CRs) in namespaces that have the `env: "prod"` label can attach to the secured endpoint. The resources use the certificate specified in the `tls.certificateRefs` field. For more information about the `HTTPRoute` CR, see "Securing HTTPRoutes". 
+
[source,yaml]
----
kind: Gateway
apiVersion: gateway.networking.k8s.io/v1
metadata:
  name: <example_gateway>
  namespace: openshift-ingress
spec:
  gatewayClassName: openshift-default
  listeners:
  - protocol: HTTP
    port: 80
    name: http
    hostname: "dev.<subdomain>.<domain>"
    allowedRoutes:
      namespaces:
        from: Selector
        selector:
          matchLabels:
            env: "dev"
  - protocol: HTTPS
    port: 443
    name: https
    hostname: "*.<subdomain>.<domain>"
    tls:
      mode: Terminate
      certificateRefs:
        - name: gwapi_wildcard
          kind: Secret
    allowedRoutes:
      namespaces:
        from: Selector
        selector:
          matchLabels:
            env: "prod"
----
+
where:
+
`listeners.tls`:: Specifies the TLS settings for secure communication, including the mode, and the Kubernetes secret containing the certificate keypair. In the example YAML file, TLS is terminated at the Gateway by using a certificate stored in a Kubernetes Secret called `gwapi_wildcard`. You must ensure that the specified Kubernetes Secret exists before you create the Gateway CR.
`listeners.tls.mode`:: Specifies the mode. {product-title}{product-version} only supports the `Terminate` mode.

. Apply the `Gateway` CR by running the following command:
+
[source,terminal]
----
$ oc apply -f <gateway_cr>.yaml
----
