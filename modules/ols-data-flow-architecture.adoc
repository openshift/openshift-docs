= Data flow architecture

[role="_abstract"]
{ols-long} communicates directly with your configured large language model (LLM) provider endpoint. No {red-hat}-managed cloud services or proxies are involved in the data path between {ols-long} and the LLM provider during active chat interactions.

When you submit a prompt, the {ols-long} Service pod on your local cluster sends the request directly to your configured LLM provider endpoint. Supporter providers include Azure AI Foundry, OpenAI, and self-hosted models served by {ocp-product-title} AI. The LLM provider returns its response directly to the {ols-long} Service pod. {red-hat} infrastructure does not process, route, or store any prompt or response data during this exchange.

Separately, if telemetry is enabled, {ols-long} sends conversation data to {red-hat} by using the {red-hat} Insights system. This telemetry transmission is independent of the prompt and response data flow and can be disabled.

The following diagram shows the trust boundary between your cluster and external systems. It shows which processing stays in your cluster, what crosses to the LLM provider, what crosses to external tools during an Agentic Run, and where the telemetry channel diverges from the prompt and response data path.
