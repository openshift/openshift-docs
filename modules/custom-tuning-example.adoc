= Custom tuning examples

[role="_abstract"]
The following examples demonstrate custom tuning configurations for {product-title} nodes using the Node Tuning Operator.

*Using TuneD profiles from the default CR*

The following CR applies custom node-level tuning for
{product-title} nodes with label
`tuned.openshift.io/ingress-node-label` set to any value.

.Example: custom tuning using the openshift-control-plane TuneD profile
[source,yaml]
----
apiVersion: tuned.openshift.io/v1
kind: Tuned
metadata:
  name: ingress
  namespace: openshift-cluster-node-tuning-operator
spec:
  profile:
  - data: |
      [main]
      summary=A custom OpenShift ingress profile
      include=openshift-control-plane
      [sysctl]
      net.ipv4.ip_local_port_range="1024 65535"
      net.ipv4.tcp_tw_reuse=1
    name: openshift-ingress
  recommend:
  - match:
    - label: tuned.openshift.io/ingress-node-label
    priority: 10
    profile: openshift-ingress
----

[IMPORTANT]
====
Custom profile writers are strongly encouraged to include the default TuneD
daemon profiles shipped within the default Tuned CR. The example above uses the
default `openshift-control-plane` profile to accomplish this.
====

*Using built-in TuneD profiles*

Given the successful rollout of the NTO-managed daemon set, the TuneD operands
all manage the same version of the TuneD daemon. To list the built-in TuneD
profiles supported by the daemon, query any TuneD pod in the following way:

[source,terminal]
----
$ oc exec $tuned_pod -n openshift-cluster-node-tuning-operator -- find /usr/lib/tuned/ -name tuned.conf -printf '%h\n' | sed 's|^.*/||'
----

You can use the profile names retrieved by this in your custom tuning specification.

.Example: using built-in hpc-compute TuneD profile
[source,yaml]
----
apiVersion: tuned.openshift.io/v1
kind: Tuned
metadata:
  name: openshift-node-hpc-compute
  namespace: openshift-cluster-node-tuning-operator
spec:
  profile:
  - data: |
      [main]
      summary=Custom OpenShift node profile for HPC compute workloads
      include=openshift-node,hpc-compute
    name: openshift-node-hpc-compute

  recommend:
  - match:
    - label: tuned.openshift.io/openshift-node-hpc-compute
    priority: 20
    profile: openshift-node-hpc-compute
----

In addition to the built-in `hpc-compute` profile, the example above includes
the `openshift-node` TuneD daemon profile shipped within the default
Tuned CR to use OpenShift-specific tuning for compute nodes.

*Connection tracking hash sizing*

The size of the connection tracking hash is a kernel module parameter, not a sysctl. It cannot be set by using the `[sysctl]` section of a TuneD profile. To size the connection tracking hash, use the `[net]` section, which passes the setting to the `net` TuneD plugin as a module parameter.

Settings applied through the `[net]` plugin take effect at run time: they require no node reboot and no machine config pool rollout. This differs from matching profiles with `machineConfigLabels`, which triggers a machine config pool rollout.

.Example: sizing the connection tracking hash by using the net plugin
[source,yaml]
----
apiVersion: tuned.openshift.io/v1
kind: Tuned
metadata:
  name: openshift-node-conntrack
  namespace: openshift-cluster-node-tuning-operator
spec:
  profile:
  - data: |
      [main]
      summary=Custom OpenShift node profile with a larger connection tracking hash
      include=openshift-node
      [net]
      nf_conntrack_hashsize=2097152
    name: openshift-node-conntrack
  recommend:
  - match:
    - label: tuned.openshift.io/connection-tracking
    priority: 25
    profile: openshift-node-conntrack
----

To apply the profile and verify the connection tracking hash size on a node, use the following steps.

. Label a node to apply the profile to:
+
[source,terminal]
----
$ oc label node <node_name> tuned.openshift.io/connection-tracking=
----

. Verify that the TuneD profile is active on the node:
+
[source,terminal]
----
$ oc exec $tuned_pod -n openshift-cluster-node-tuning-operator -- tuned-adm active
----
+
where `$tuned_pod` is the name of a TuneD pod running on the node, as listed by the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-cluster-node-tuning-operator -l openshift-app=tuned -o wide
----

. Verify that the connection tracking hash size was set on the node:
+
[source,terminal]
----
$ oc debug node/<node_name> -- cat /sys/module/nf_conntrack/parameters/hashsize
$ oc debug node/<node_name> -- sysctl net.netfilter.nf_conntrack_buckets
----

Both the `hashsize` module parameter and the `net.netfilter.nf_conntrack_buckets` sysctl report the new value, `2097152` in this example. The change does not require a node reboot.

To roll back the change, remove the node label or delete the `Tuned` custom resource. The `hashsize` module parameter and the `net.netfilter.nf_conntrack_buckets` sysctl return to their previous values without a node reboot.

[WARNING]
====
Keys in the `[sysctl]` section that are not real sysctls are skipped: the profile is still applied and is displayed as active, and the only sign of the failure is an error in the TuneD pod log. For example, `net.netfilter.nf_conntrack_hashsize` is not a valid sysctl. Set the connection tracking hash size through the `[net]` section, as shown in the preceding example.
====

*Overriding host-level sysctls*

Various kernel parameters can be changed at runtime by using `/run/sysctl.d/`, `/etc/sysctl.d/`, and `/etc/sysctl.conf` host configuration files. {product-title} adds several host configuration files which set kernel parameters at runtime; for example, `net.ipv[4-6].`, `fs.inotify.`, and `vm.max_map_count`. These runtime parameters provide basic functional tuning for the system prior to the kubelet and the Operator start.

The Operator does not override these settings unless the `reapply_sysctl` option is set to `false`. Setting this option to `false` results in `TuneD` not applying the settings from the host configuration files after it applies its custom profile.

.Example: overriding host-level sysctls
[source,yaml]
----
apiVersion: tuned.openshift.io/v1
kind: Tuned
metadata:
  name: openshift-no-reapply-sysctl
  namespace: openshift-cluster-node-tuning-operator
spec:
  profile:
  - data: |
      [main]
      summary=Custom OpenShift profile
      include=openshift-node
      [sysctl]
      vm.max_map_count=>524288
    name: openshift-no-reapply-sysctl
  recommend:
  - match:
    - label: tuned.openshift.io/openshift-no-reapply-sysctl
    priority: 15
    profile: openshift-no-reapply-sysctl
    operand:
      tunedConfig:
        reapply_sysctl: false
----
