= New features and enhancements

[role="_abstract"]
This release adds improvements related to the following components and concepts.

[id="microshift-5-0-enhanced-metrics_{context}"]
== Enhanced metrics

With this release, you can enable optional Kubernetes metric exporters on {microshift-short} so that edge nodes expose Prometheus-compatible metrics that align with {ocp} observability practices. Install each exporter individually by using optional RPM packages:

* `node-exporter` for hardware and operating system metrics
* `metrics-server` for the Kubernetes resource metrics API, including `oc adm top nodes` and `oc adm top pods`
* `kube-state-metrics` for the state of Kubernetes API objects

{microshift-short} does not deploy the full Cluster Monitoring Operator stack. External tools, such as a local OpenTelemetry Collector or a remote Prometheus database, can scrape the exporter endpoints after you install the packages.

[id="microshift-5-0-support-rhel-10-2_{context}"]
== Support for MicroShift on RHEL 10.2

With this release, {microshift-short} 5.0 supports new installations on {op-system-base-full} {op-system-version} and {op-system-base} {op-system-version-10} for the `x86_64` and `aarch64` architectures. Support for {op-system-base} {op-system-version-10} is generally available. You can continue to install and run {microshift-short} 5.0 on {op-system-base} {op-system-version}.

[id="microshift-5-0-cis-level-2_{context}"]
== Designed for CIS Level 2 compliance
With this release, you can run {microshift-short} on a {op-system-base-full} host that is hardened to the Center for Internet Security (CIS) Level 2 benchmark. CIS Level 2 support covers RPM package-mode installations on `x86_64` and `aarch64` architectures. Host hardening uses Red{nbsp}Hat Ansible CIS roles with documented overrides, and you verify compliance with OpenSCAP. Image-based deployments such as {op-system-ostree} and {op-system-image} are out of scope for the initial CIS Level 2 support.

[id="microshift-5-0-tls-curves_{context}"]
== Enhanced TLS curves

With this release, the {microshift-short} ingress controller advertises a default set of TLS curves that includes `X25519MLKEM768`, a hybrid post-quantum key-exchange group. Clients that do not support `X25519MLKEM768` can negotiate another advertised curve: `X25519`, `P-256, `P-384`, or `P-521`.

[id="microshift-5-0-custom-dns_{context}"]
== Custom DNS configuration

With this release, you can replace the built-in CoreDNS `Corefile` by setting the `dns.configFile` parameter to the absolute path of a custom `Corefile` on the host. Use a custom `Corefile` for advanced networking, such as split-horizon DNS, custom forwarding rules, and conditional zone delegation. After the initial restart, {microshift-short} applies later edits to that file without another service restart when the `Corefile` includes the reload plugin.

[id="microshift-5-0-cryptography-bom_{context}"]
== Cryptography Bill of Materials

With this release, {microshift-short} includes a Cryptography Bill of Materials (CryptoBOM) for the release. The CryptoBOM lists the cryptographic components that the release uses, including algorithms, ciphers, protocols, libraries, and related key material. You can use the CryptoBOM to review the cryptographic posture of the release for security audits and compliance verification.
