= Monitor cluster provisioning status

[role="_abstract"]
You can monitor the progress of a `ProvisioningRequest` custom resource (CR) by watching its status conditions and provisioning phase. The O-Cloud Manager updates the resource status as provisioning advances through hardware allocation, cluster installation, and configuration stages.

.Prerequisites

* You have applied the `ProvisioningRequest` CR to the hub cluster, or committed it to the GitOps repository for ArgoCD synchronization.

.Procedure

. Watch the `ProvisioningRequest` CR status in real time by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -w
----
+
* Replace `<uuid>` with the UUID of the `ProvisioningRequest` CR.

. View detailed status conditions for the request by running the following command:
+
[source,terminal]
----
$ oc describe provisioningrequests.clcm.openshift.io <uuid>
----
+
The following status conditions indicate provisioning progress:
+
[cols="1,1,2",options="header"]
|===
|Condition |Status |Description

|`ProvisioningRequestValidated`
|`True`
|The `ProvisioningRequest` has been validated.

|`ClusterInstanceRendered`
|`True`
|The `ClusterInstance` has been successfully rendered and validated.

|`ClusterResourcesCreated`
|`True`
|The necessary cluster resources have been created.

|`NodeAllocationRequestRendered`
|`True`
|The `NodeAllocationRequest` has been successfully rendered.

|`HardwareProvisioned`
|`True`
|Hardware provisioning is complete.

|`HardwareConfigured`
|`True`
|Firmware and BIOS configuration has been applied.

|`HardwareNodeConfigApplied`
|`True`
|Hardware node configuration is applied to the rendered `ClusterInstance`.

|`ClusterProvisioned`
|`True`
|Cluster installation is complete.

|`ConfigurationApplied`
|`True`
|Configuration has been successfully applied via {rh-rhacm} enforce policies.
|===

. Check the high-level provisioning phase by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -o jsonpath='{.status.provisioningStatus.provisioningPhase}'
----
+
The `provisioningPhase` progresses through the following values:
+
* `pending` - The request is queued and awaiting processing.
* `progressing` - Provisioning is actively in progress.
* `fulfilled` - All stages completed successfully.
* `failed` - An error occurred during provisioning.

. If provisioning fails, inspect the status conditions to identify which stage encountered an error by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -o jsonpath='{.status.conditions}' | jq .
----
+
Failed conditions include a `message` field with details about the failure cause. Common failures include hardware allocation timeout, cluster installation errors, or policy compliance failures.
