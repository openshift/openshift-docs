= Resource Detection Processor

[role="_abstract"]
The Resource Detection Processor identifies host resource details in alignment with OpenTelemetry's resource semantic standards.

Using the detected information, this processor can add or replace the resource values in telemetry data.

You can use this processor with multiple detectors such as the Docker metadata detector or the `OTEL_RESOURCE_ATTRIBUTES` environment variable detector.

This processor supports traces and metrics.

:FeatureName: The Resource Detection Processor
include::snippets/technology-preview.adoc[]

The following {ocp-product-title} permissions are required for the Resource Detection Processor:

[source,yaml]
----
kind: ClusterRole
metadata:
  name: otel-collector
rules:
- apiGroups: ["config.openshift.io"]
  resources: ["infrastructures", "infrastructures/status"]
  verbs: ["get", "watch", "list"]
# ...
----
The following `OpenTelemetryCollector` custom resource configures the Resource Detection Processor:

[source,yaml]
----
# ...
  config:
    processors:
      resourcedetection:
        detectors: [openshift]
        override: true
    service:
      pipelines:
        traces:
          processors: [resourcedetection]
        metrics:
          processors: [resourcedetection]
# ...
----

The following `OpenTelemetryCollector` custom resource configures the Resource Detection Processor with an environment variable detector:

[source,yaml]
----
# ...
  config:
    processors:
      resourcedetection/env:
        detectors: [env]
        timeout: 2s
        override: false
# ...
----
where:

`detectors`:: Specifies which detector to use. In this example, the environment detector is specified.

By default, the `openshift` detector connects to the cluster's API server using the in-cluster service account token and CA bundle. If the Collector cannot use these defaults, for example when it runs outside the cluster or must reach the API server through a custom endpoint, you can override the connection settings:

[source,yaml]
----
# ...
  config:
    processors:
      resourcedetection:
        detectors: [openshift]
        openshift:
          address: "https://api.example.com:6443"
          token: "${env:OPENSHIFT_TOKEN}"
          tls:
            ca_file: ca.pem
            insecure_skip_verify: false
        override: true
# ...
----

`openshift.address`:: Overrides the OpenShift API server address. Defaults to the in-cluster API server address derived from the `KUBERNETES_SERVICE_HOST` and `KUBERNETES_SERVICE_PORT` environment variables.
`openshift.token`:: Overrides the bearer token used to authenticate against the OpenShift API server. Defaults to the service account token mounted into the pod.
`openshift.tls`:: Client-side TLS configuration used to connect to the OpenShift API server. Defaults to the CA bundle of the service account.
