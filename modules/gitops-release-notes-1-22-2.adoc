== Fixed issues

Upgrade path warning for annotation-based resource tracking::
Before this update, users upgrading from {gitops-title} versions earlier than 1.19 without explicitly setting `.spec.resourceTrackingMethod` in the Argo CD custom resource (CR) experienced a default resource tracking behavior change: from label-based to annotation-based tracking, without notification. This change caused applications to display unexpected label diffs on resources managed by external controllers, such as Namespaces, Subscriptions, and Secrets. As a consequence, application status changed to `OutOfSync`, and syncing the application deleted labels managed by other controllers on Secret resources, even when `ignoreDifferences` was configured. With this update, the {gitops-shortname} Operator logs a warning message during upgrade when `.spec.resourceTrackingMethod` is not explicitly set, alerting users to the resource tracking method change. As a result, users can take action before upgrading by explicitly configuring the resource tracking method in the Argo CD custom resource.
+
To avoid issues during upgrade, set `.spec.resourceTrackingMethod` to `label` in the Argo CD custom resource before upgrading if you want to continue using label-based tracking:
+
[source,yaml]
----
apiVersion: argoproj.io/v1beta1
kind: ArgoCD
metadata:
  name: example-argocd
spec:
  resourceTrackingMethod: label
----
+
Example warning message:
+
[source,terminal]
----
WARNING: resource tracking method in argocd-cm is changing from 'label' to the default
'annotation' because .spec.resourceTrackingMethod is not set. ...
----
+
For more information about annotation-based resource tracking, migration steps, and the upstream Argo CD default behavior change, see Additional Resources.
+
link:https://redhat.atlassian.net/browse/GITOPS-10904[GITOPS-10904]

Image Updater supports Applications that use Source Hydrator::
Before this update, the Argo CD Image Updater failed to commit updates for Applications that use `spec.sourceHydrator` instead of `spec.source`. When you used Helm write-back methods (`helmvalues:./values.yaml` custom target or the `argocd` write-back method), the Image Updater logged a success message but did not commit the updated image tag to Git. With this update, the Argo CD Image Updater correctly handles the source configuration for Source Hydrator Applications. As a result, the Image Updater processes image updates as expected for Applications using `spec.sourceHydrator`.
+
link:https://redhat.atlassian.net/browse/GITOPS-11441[GITOPS-11441]

Image Updater webhook server no longer crashes with TLS 1.2::
Before this update, the Argo CD Image Updater entered `CrashLoopBackOff` state when the webhook server was enabled by the {gitops-shortname} Operator due to newly introduced changes for TLS Post-Quantum Cryptography (PQC) support. With this update, TLS 1.3 ciphers are filtered out when the minimum TLS version is set to TLS 1.2, as TLS 1.3 ciphers are not configurable in TLS 1.2 contexts. As a result, the Image Updater webhook server starts successfully when enabled by the {gitops-shortname} Operator.
+
link:https://redhat.atlassian.net/browse/GITOPS-11515[GITOPS-11515]

Rollouts extension compatible with React 19::
Before this update, following the React 19 upgrade in Argo CD, the Argo Rollouts extension failed to load in the Argo CD web UI, resulting in a `TypeError: Cannot read properties of undefined (reading 'hasOwnProperty')` error. With this update, the Argo Rollouts UI extension has been updated for compatibility with React 19. As a result, the extension loads and functions as expected within the Argo CD web UI.
+
link:https://redhat.atlassian.net/browse/GITOPS-11604[GITOPS-11604]

Image Updater properly handles terminated Git processes::
Before this update, the Argo CD Image Updater pod accumulated orphaned Git child processes over time with increased load, causing subsequent Git operations to fail. With this update, the Argo CD Image Updater container uses `tini` as the entry point to ensure proper signal handling and process cleanup. As a result, the Argo CD Image Updater performs image updating more reliably under load.
+
link:https://redhat.atlassian.net/browse/GITOPS-11648[GITOPS-11648]
