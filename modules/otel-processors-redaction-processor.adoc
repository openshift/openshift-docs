= Redaction Processor

[role="_abstract"]

You can use the Redaction Processor as one of the measures to ensure compliance with legal, privacy, or security requirements. This processor deletes span, log, and metric datapoint attributes that do not match the allowed list. This processor also masks attribute values that match listed blocked values.

:FeatureName: The Redaction Processor
include::snippets/technology-preview.adoc[]

The following `OpenTelemetryCollector` custom resource configures the Redaction Processor:

[source,yaml]
----
processors:
  redaction:
    allow_all_keys: false
    allowed_keys:
      - description
      - group
      - id
      - name
    ignored_keys:
      - safe_attribute
    ignored_key_patterns:
      - "^safe_.*"
      - ".*_trusted$"
    redact_all_types: true
    blocked_key_patterns:
      - ".*token.*"
      - ".*api_key.*"
    blocked_values:
      - "4[0-9]{12}(?:[0-9]{3})?"
      - "(5[1-5][0-9]{14})"
    allowed_values:
      - ".+@mycompany.com"
    hash_function: md5
    summary: debug
    url_sanitizer:
      enabled: true
      attributes: ["http.url", "url"]
      sanitize_span_name: true
----
where:

`allow_all_keys`::
Allows all keys and disables the `allowed_keys` list when set to `true`. Does not affect the `blocked_values` list, so you can set this to `true` if you only intend to block values.

`allowed_keys`::
Lists span, log, and datapoint attribute keys. If the `allowed_keys` field is empty, no attributes are allowed, and all span attributes are removed.

`ignored_keys`::
Ignores exact key matches of specified attributes and allows them to pass without redaction. Ignored attributes are processed first so they are always allowed and never blocked. Use this field only where all data is safe to send to the telemetry system.

`ignored_key_patterns`::
Lists regular expressions for ignoring keys by regular expression pattern matching. Keys that match these patterns are allowed to pass without redaction.

`redact_all_types`::
Checks incoming fields for sensitive data based on their `AsString()` representation.

`blocked_values`::
Lists regular expressions for blocking values of allowed span attributes. Values that match are masked. Applies to the values of the allowed keys. The regular expressions are applied in the order in which they are listed in the configuration.

`allowed_values`::
Lists regular expressions for allowing values of blocked span attributes. Values that match are not masked. Applies to the values of the allowed keys. When both the `allowed_values` list and `blocked_values` list are configured, the `allowed_values` list takes precedence. As a result, a value matching an entry in the `allowed_values` list is not masked even if it also matches `blocked_values`.

`blocked_key_patterns`::
Lists blocked span attribute key patterns. Span attributes that match the regular expressions on the list are masked.

`hash_function`::
Defines the function for hashing the values instead of masking them with a fixed string. By default, no hash function is used, and masking with a fixed string is performed. The supported hash functions are `md5`, `sha1`, `sha3` (SHA-256), `hmac-sha256`, and `hmac-sha512`.

`summary`::
Controls the verbosity level of the diagnostic attributes that the processor adds to spans, logs, or datapoints when it redacts or masks other attributes. In some contexts, a list of redacted attributes leaks information, while it is valuable when integrating and testing a new configuration. These values are supported: `silent` omits the summary attributes; `debug` includes both redacted key counts and names in the summary; `info` includes just the redacted key counts in the summary. Setting `summary: silent` suppresses all audit attributes. When summary is set to `debug` or `info`, the processor appends diagnostic attributes to each span, log record, or metric datapoint describing the actions it took.

`url_sanitizer`::
Configures URL sanitization to remove variable elements from the URL, causing high cardinality issues. When `enabled: true`, controls whether URL sanitization is active. Enables sanitization of URLs in specified attributes by removing potentially sensitive information like UUIDs, timestamps, and other non-essential path segments. This is particularly useful for reducing cardinality in telemetry data while preserving the essential parts of URLs for troubleshooting.

`attributes`::
Lists attribute keys that contain URLs to be sanitized.

`sanitize_span_name`::
Controls whether span names must be sanitized for URLs. The default value is `true`.
When enabled with `true`, span names for client and server span types that contain "/" characters are automatically sanitized. This helps reduce cardinality issues caused by high-variability URL paths in span names while preserving essential routing information. Set to `false` to disable span name sanitization while keeping attribute sanitization active.
