= Redaction Processor

[role="_abstract"]
You can use the Redaction Processor as one of the measures to ensure compliance with legal, privacy, or security requirements. This processor deletes resource, span, log, and metric datapoint attributes that do not match the `allowed_keys` list. This processor also masks attribute values that match the `blocked_values` list. In log records, the processor applies the same rules to the log body.

:FeatureName: The Redaction Processor
include::snippets/technology-preview.adoc[]

The following `OpenTelemetryCollector` custom resource configures the Redaction Processor:

[source,yaml]
----
# ...
  config:
    processors:
      redaction:
        allow_all_keys: false
        allowed_keys:
          - description
          - group
          - id
          - name
          - service.name
          - session_token
          - http.url
          - url
        ignored_keys:
          - safe_attribute
        ignored_key_patterns:
          - "^safe_.*"
          - ".*_trusted$"
        redact_all_types: true
        blocked_key_patterns:
          - ".*token.*"
          - ".*api_key.*"
        blocked_values:
          - "4[0-9]{12}(?:[0-9]{3})?"
          - "(5[1-5][0-9]{14})"
        allowed_values:
          - ".+@mycompany.com"
        hash_function: hmac-sha256
        hmac_key: ${env:REDACTION_HMAC_KEY}
        summary: debug
        url_sanitizer:
          enabled: true
          attributes: ["http.url", "url"]
          sanitize_span_name: true
# ...
----
where:

`allow_all_keys`::
Allows all keys and disables the `allowed_keys` list when set to `true`. Does not affect the `blocked_values` list, so you can set this to `true` if you only intend to block values.

`allowed_keys`::
Lists the attribute keys to keep. The processor removes all other attributes from resources, scopes, spans, span events, log records, and metric datapoints, and all other keys from log bodies that are maps. For example, the processor removes the `service.name` resource attribute unless it is on this list. If the `allowed_keys` field is empty and `allow_all_keys` is `false`, the processor removes all attributes.

`ignored_keys`::
Ignores exact key matches of specified attributes and allows them to pass without redaction. Ignored attributes are processed first so they are always allowed and never blocked. Use this field only where all data is safe to send to the telemetry system.

`ignored_key_patterns`::
Lists regular expressions for ignoring keys by regular expression pattern matching. Keys that match these patterns are allowed to pass without redaction.

`redact_all_types`::
Checks attribute values of all types, not only strings, by using their string representation. For example, the processor can then mask a credit card number that is stored as an integer. The processor stores a masked value as a string. The default value is `false`, which means that the processor checks only string values.

`blocked_values`::
Lists regular expressions for blocking values of allowed attributes. Values that match are masked. Applies to the values of the allowed keys. The regular expressions are applied in the order in which they are listed in the configuration.

`allowed_values`::
Lists regular expressions for allowing values of blocked attributes. Values that match are not masked. Applies to the values of the allowed keys. When both the `allowed_values` list and `blocked_values` list are configured, the `allowed_values` list takes precedence. As a result, a value matching an entry in the `allowed_values` list is not masked even if it also matches `blocked_values`. A match on any part of a value exempts the whole value from masking, so make these expressions as specific as possible.

`blocked_key_patterns`::
Lists regular expressions for attribute keys whose values are masked completely. Applies to the allowed keys only, because the processor removes all other keys.

`hash_function`::
Defines the function for hashing the values instead of masking them with a fixed string. By default, no hash function is used, and masking with a fixed string is performed. The supported hash functions are `md5`, `sha1`, `sha3` (SHA3-256), `hmac-sha256`, and `hmac-sha512`. The `hmac-sha256` and `hmac-sha512` functions require the `hmac_key` setting. In FIPS environments, use `sha3`, `hmac-sha256`, or `hmac-sha512`.

`hmac_key`::
Defines the secret key for the `hmac-sha256` and `hmac-sha512` hash functions. The key must be at least 32 bytes long for `hmac-sha256` and at least 64 bytes long for `hmac-sha512`. Load the key from a secret, for example through an environment variable.

`summary`::
Controls the verbosity level of the diagnostic attributes that the processor adds to spans, logs, or datapoints when it redacts or masks other attributes. The supported values are `silent`, which is the default and adds no diagnostic attributes, `info`, which adds the counts of the affected keys, and `debug`, which adds the counts and the key names. In some contexts, a list of redacted keys leaks information, but this list is useful when you integrate and test a new configuration.

`url_sanitizer`::
Configures URL sanitization, which replaces variable URL elements such as UUIDs and numeric IDs with `+*+`. This reduces the cardinality of telemetry data while preserving the essential parts of URLs for troubleshooting.

`url_sanitizer.enabled`::
Enables URL sanitization when set to `true`. The default value is `false`. In logs pipelines, the processor then also sanitizes log bodies, regardless of the `url_sanitizer.attributes` setting, and can replace a whole log message with `+*+`.

`url_sanitizer.attributes`::
Lists attribute keys that contain URLs to be sanitized. The keys must also be allowed.

`url_sanitizer.sanitize_span_name`::
Controls whether the processor sanitizes span names for URLs. The default value is `true`.
When enabled, the processor sanitizes the span names of client and server spans that contain "/" characters, which reduces cardinality from high-variability URL paths while preserving routing information. If you set this field to `false`, the processor keeps sanitizing attributes but not span names.
