= Tech Preview limitations and support

[role="_abstract"]
C2CC is a Technology Preview feature. Understand its limitations, security considerations, and support options before deploying it in production environments.

== Limitations

* **No authentication or encryption by default.**
  Any host that can reach (or spoof) the configured next-hop IP can inject traffic into the cluster.
  Because SNAT is bypassed, that traffic can carry an attacker-chosen source IP that matches NetworkPolicy allow rules.

* **Non-overlapping CIDRs required.**
  Pod and service CIDRs must not overlap across clusters.
  C2CC does not handle overlapping CIDRs.
  Plan unique CIDRs for each cluster before the first boot.

* **Static full-mesh configuration.**
  Each cluster lists every other cluster in its configuration.
  This does not scale to large fleets without external configuration automation.
  C2CC is validated with up to three interconnected clusters.

* **Restart required for changes.**
  The C2CC configuration is read at startup.
  Any change (adding or removing remotes, DNS TTLs, routing tables) requires a {microshift-short} restart.

* **NetworkPolicies are your responsibility.**
  C2CC does not create NetworkPolicy resources.
  Namespaces with default-deny ingress must explicitly allow the remote pod CIDRs.

* **No MTU adjustment by C2CC.**
  Cross-cluster traffic leaves the host as plain IP at the pod MTU.
  On jumbo-frame networks, set the pod MTU explicitly in `/etc/microshift/ovn.yaml`.
  When using IPsec, leave headroom for ESP overhead.

* **Validation failures block startup.**
  Invalid C2CC configuration (overlapping CIDRs, routing loops, bad masks, duplicate next-hops or domains) prevents {microshift-short} from starting.
  Check `journalctl -u microshift` for the specific error.

== Support exception for production use

Customers who require C2CC in production before it reaches general availability can request a support exception through the standard Red{nbsp}Hat support exception process.
A support exception enables upgrades to a later GA version without reinstallation.
