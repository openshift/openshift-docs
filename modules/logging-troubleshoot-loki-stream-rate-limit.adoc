= Troubleshoot per-stream rate limit errors

[role="_abstract"]
Diagnose and resolve situations where a single log stream is exceeding the configured per-stream ingestion rate limit.

A log stream is a unique combination of labels, such as container name, host, namespace, pod name, and log type. A single container producing 3 MB per second of logs generates approximately 259 GB per day.

.Prerequisites

* You have administrator permissions.
* You have installed the OpenShift CLI (`oc`).

.Procedure

. Confirm that per-stream rate limit discards are occurring by running the following PromQL query in the OpenShift web console under *Observe* -> *Metrics*:
+
[source,promql]
----
sum by (tenant, reason) (rate(loki_discarded_samples_total[2m]))
----
+
A nonzero value with `reason="StreamRateLimit"` confirms per-stream rate limit discards.

. Review ingester pod logs to identify the stream exceeding the limit:
+
[source,terminal]
----
$ ns="openshift-logging"
$ for pod in $(oc -n ${ns} get pod -l app.kubernetes.io/component=ingester \
    -o jsonpath='{.items[*].metadata.name}'); do
    oc -n ${ns} logs ${pod} | grep "Per stream rate limit exceeded" | tail -3
  done
----
+
The error message identifies the stream labels (namespace, pod name, container name) that are hitting the limit.

. Choose one or more of the following actions, in order of preference:

.. *Enable stream sharding (automatic, recommended first step):* Stream sharding dynamically adjusts ingestion across shards and minimizes per-stream rate limit issues without manual limit adjustments. Verify that your {loki-op} version includes the stream sharding fix (delivered in {logging-title-uc} 5.9.0 and later). If stream sharding is not resolving the issue, continue with the following steps.

.. *Reduce the log volume from the affected container:* Identify whether the container is in verbose or DEBUG mode, or whether it is malfunctioning. Reduce log verbosity at the application level where possible.

.. *Reduce log size by applying filters:* Apply one or more of the following filters to the affected tenant in the `ClusterLogForwarder` configuration:
+
--
* API audit policy filters (for audit logs)
* Content-based filters
* Metadata-based filters
--

.. *Increase the per-stream rate limit:* Update the `LokiStack` custom resource to increase `perStreamRateLimit` and `perStreamRateLimitBurst`. The recommended maximum values are 5 MB per second for `perStreamRateLimit` and 20 MB for `perStreamRateLimitBurst`. Do not set `perStreamRateLimit` to a value greater than `ingestionRate`. For the configuration steps, see "Configure LokiStack ingestion limits".

.. *Increase the number of LokiStack ingesters:* Adding ingester replicas increases the total ingestion capacity and distributes the per-stream load. For the configuration steps, see "Scale LokiStack deployments".
