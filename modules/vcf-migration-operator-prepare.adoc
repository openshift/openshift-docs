= Prepare a cluster for VCF migration

[role="_abstract"]
Before starting a migration with the {vcf-migration-operator}, verify cluster readiness, remove the {vmw-short} Container Storage Interface (CSI) driver, and remove resources that can interfere with machine replacement.

.Prerequisites

* Your cluster and target vCenter meet the migration requirements.
* You have installed the {oc-first} and logged in with `cluster-admin` privileges.
* You have a current etcd backup.

.Procedure

. Check the running cluster version and verify that no cluster update is in progress by running the following command:
+
[source,terminal]
----
$ oc get clusterversion version
----

. Verify that `VSphereMultiVCenterDay2` is listed in `status.featureGates[].enabled` for the running cluster version by running the following command:
+
[source,terminal]
----
$ oc get featuregate cluster -o yaml
----
+
The migration cannot start if this feature gate is unavailable or disabled.

. Verify that all cluster Operators report `AVAILABLE=True` by running the following command:
+
[source,terminal]
----
$ oc get clusteroperators
----
+
Resolve cluster health issues before continuing.

. Check the storage driver for existing persistent volumes (PVs) by running the following command:
+
[source,terminal]
----
$ oc get pv -o custom-columns=NAME:.metadata.name,DRIVER:.spec.csi.driver
----
+
Do not continue if a PV uses `csi.vsphere.vmware.com`. Removing the driver does not migrate volume data.

. Remove the {vmw-short} CSI driver by running the following command:
+
[source,terminal]
----
$ oc patch clustercsidrivers.operator.openshift.io csi.vsphere.vmware.com --type=merge -p '{"spec":{"managementState":"Removed"}}'
----
+
Keep `storages.operator.openshift.io/cluster` set to `Managed`. Changing the storage Operator to `Unmanaged` or `Removed` can cause the separate cluster health check to fail. A preflight warning about the `Managed` storage Operator does not block migration.

. Check for resources that interfere with machine replacement by running the following command:
+
[source,terminal]
----
$ oc get machinehealthchecks,machineautoscalers,clusterautoscalers -A
----
+
Save the YAML definitions of any `ClusterAutoscaler`, `MachineAutoscaler`, and user-created `MachineHealthCheck` resources, and remove these resources before starting the migration. The `machine-api-termination-handler` machine health check in the `openshift-machine-api` namespace can remain.
+
The preflight checks reject these resources even if their activity is paused.

.Verification

* Verify that the {vmw-short} CSI driver management state is `Removed` by running the following command:
+
[source,terminal]
----
$ oc get clustercsidrivers.operator.openshift.io csi.vsphere.vmware.com -o jsonpath='{.spec.managementState}{"\n"}'
----
