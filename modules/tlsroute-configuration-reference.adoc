= TLSRoute configuration reference

[role="_abstract"]
To attach a `TLSRoute` custom resource (CR) to a passthrough listener and select which SNI hostnames it handles, you configure `spec.parentRefs`, `spec.hostnames`, and `spec.rules`. A `TLSRoute` CR must attach to a listener whose protocol is `TLS` and whose TLS mode is `Passthrough`.

You can customize your `TLSRoute` CR using the following fields:

`spec.parentRefs`::
Lists the parent `Gateway` CRs that the route wants to attach to. On {product-title}, set `name` to the gateway and, when the gateway is in another namespace, set `namespace` to `openshift-ingress`. Use `sectionName` to bind the route to the passthrough listener. Attachment succeeds only when that listener allows `TLSRoute` CRs from the route namespace.

`spec.hostnames`::
Required. Lists fully qualified SNI hostnames to match against the TLS ClientHello. You can specify from 1 to 16 hostnames. IP addresses are not permitted. You can prefix a hostname with a wildcard label (`*.`) as the first label only. Hostname intersection with the listener follows the same routing rules as other Gateway API routes: at least one hostname must intersect, and non-intersecting hostnames are ignored. If none intersect, the controller sets the `Accepted` condition to `False` for that parent.

`spec.rules`::
Defines where matching TLS connections are sent. A `TLSRoute` CR supports a single rule. Each rule must include at least one `backendRefs` entry. If a backend reference is invalid, the implementation rejects the connection for the portion of traffic assigned to that backend.

`rules.backendRefs`::
Identifies the Kubernetes Service that terminates TLS. `name` and `port` are required. The gateway forwards the encrypted stream to this service. It does not decrypt the traffic.

[NOTE]
====
A `TLSRoute` CR has no matches or filters. Routing is by SNI hostname only. Weighted `backendRefs` is an extended Gateway API feature; specify a single backend unless you confirm that your implementation supports weights.
====

== Example: SNI passthrough to a TLS backend

The following example forwards TLS connections whose SNI hostname is `passthrough.<example_domain.tld>` to a service that listens on port `443`:

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: TLSRoute
metadata:
  name: <example_tls_route>
  namespace: <example_application>
spec:
  parentRefs:
  - name: <example_gateway>
    namespace: openshift-ingress
    sectionName: tls
  hostnames:
  - passthrough.<example_domain.tld>
  rules:
  - backendRefs:
    - name: <tls_backend>
      port: 443
----
* `sectionName: tls` attaches the route only to the passthrough listener.
* `hostnames` must be set. Omitting them is not valid for `TLSRoute` CRs.
* The backend service, not the gateway, presents the TLS certificate.
