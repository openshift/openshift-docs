= Creating a TLSRoute custom resource

[role="_abstract"]
To direct passthrough TLS traffic from a gateway listener to a backend that terminates TLS, you must create a `TLSRoute` custom resource (CR). The route matches the Server Name Indication (SNI) hostname from the TLS handshake and forwards the encrypted connection.

.Prerequisites

* You created a target backend service that terminates TLS.
* You configured a parent `Gateway` CR with a listener that uses `protocol: TLS` and `tls.mode: Passthrough`.
* You know the name and namespace of the parent `Gateway` CR.

.Procedure

. Create a `TLSRoute` CR file that references your passthrough listener, SNI hostnames, and backend service, and save it as `tlsroute.yaml`:
+
[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: TLSRoute
metadata:
  name: <example_tls_route>
  namespace: <example_application>
spec:
  parentRefs:
  - name: <example_gateway>
    namespace: openshift-ingress
    sectionName: tls
  hostnames:
  - passthrough.<example_domain.tld>
  rules:
  - backendRefs:
    - name: <tls_backend>
      port: 443
----
+
* `sectionName` must match the passthrough listener `name` on the parent `Gateway` CR. If your gateway also has an HTTPS listener, set `sectionName` so the route does not attach to the wrong listener.
* `hostnames` is required. The values must intersect with the listener hostname and must be fully qualified domain names. IP addresses are not permitted.
* If your `TLSRoute` and `Gateway` CRs are in different namespaces, the listener must allow routes from the `TLSRoute` namespace.
+
For field details, see xref:tlsroute-configuration-reference_{context}[].

. Apply the `TLSRoute` CR file to your cluster:
+
[source,terminal]
----
$ oc apply -f tlsroute.yaml
----

.Verification

* Verify that the parent gateway accepted the `TLSRoute` CR:
+
[source,terminal]
----
$ oc get tlsroute <example_tls_route> -n <example_application> -o jsonpath='{.status.parents[*].conditions[?(@.type=="Accepted")].status}'
----
+
A value of `True` means the passthrough listener accepted the route. If the `status.parents` list is empty, confirm that the listener protocol is `TLS`, the mode is `Passthrough`, and the hostnames intersect.
