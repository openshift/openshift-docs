= Creating a TLSRoute custom resource

[role="_abstract"]
To direct passthrough TLS traffic from a gateway listener to a backend that terminates TLS, you must create a `TLSRoute` custom resource (CR). The route matches the Server Name Indication (SNI) hostname from the TLS handshake and forwards the encrypted connection.

.Prerequisites

* You created a target backend service that terminates TLS.
* You configured a parent `Gateway` CR with a listener that uses `protocol: TLS` and `tls.mode: Passthrough`.
* The parent gateway uses a `GatewayClass` object that supports TLS route passthrough.
* You know the name and namespace of the parent `Gateway` CR.

.Procedure

. Create a `TLSRoute` CR file that references your passthrough listener, SNI hostnames, and backend service, and save it as `tlsroute.yaml`:
+
[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: TLSRoute
metadata:
  name: <example_tls_route>
  namespace: <gateway_namespace>
spec:
  parentRefs:
  - name: <example_gateway>
    sectionName: passthrough-listener
  hostnames:
  - db.<example_domain.tld>
  rules:
  - backendRefs:
    - name: <tls_backend>
      port: 8443
----
+
--
where:

`sectionName`:: Specifies the passthrough listener `name` on the parent `Gateway` CR. Set this field when the parent has more than one TLS listener so the route attaches to the intended listener.
`hostnames`:: Specifies a list of one or more fully qualified SNI hostnames. IP addresses are not permitted. At least one hostname must intersect with the listener `hostname` on the parent `Gateway` CR. Hostnames that do not intersect are ignored. This field is required.
--

. Apply the `TLSRoute` CR file to your cluster:
+
[source,terminal]
----
$ oc apply -f tlsroute.yaml
----

.Verification

* Verify that the parent gateway accepted the `TLSRoute` CR:
+
[source,terminal]
----
$ oc get tlsroute <example_tls_route> -n <gateway_namespace> -o jsonpath='{.status.parents[*].conditions[?(@.type=="Accepted")].status}'
----
+
A value of `True` means the passthrough listener accepted the route. If the `status.parents` list is empty, confirm that the listener protocol is `TLS`, the mode is `Passthrough`, the `GatewayClass` object supports TLS route passthrough, and the hostnames intersect.
