= Autonomous triggering and alert filtering

[role="_abstract"]
When a cluster alert fires, the system filters authorized alerts and triggers an investigation automatically so that incident response begins without manual intervention.

The agent monitors Prometheus alerts and triggers investigations automatically. The `lightspeed-agentic-alerts-adapter` periodically polls the Alertmanager API for firing alerts. When a firing alert is detected, the adapter checks it against the `filtering` section defined in the `alerts-adapter-config` ConfigMap. If the alert matches the filters, the adapter automatically creates an `AgenticRun` custom resource to start an investigation.

Filtering is based on Alertmanager receivers. A receiver is a named configuration in Alertmanager that defines where notifications for matching alerts are sent, for example email, Slack, PagerDuty, or a webhook. Alertmanager routes each firing alert to one or more receivers based on the alert's labels, such as `severity` or `namespace`, according to the routing rules defined in the Alertmanager configuration.

The adapter does not introduce a separate policy mechanism to decide which alerts to investigate. Instead, it reuses the receiver names already defined in your Alertmanager configuration: you authorize the adapter to act on an alert by listing the corresponding receiver name under `filtering.allowedReceivers`.

The `alerts-adapter-config` ConfigMap serves as the platform-level control. Combined with dynamically scoped RBAC, sandboxed execution, and mandatory human approval, this architecture provides multiple layers of safety.
