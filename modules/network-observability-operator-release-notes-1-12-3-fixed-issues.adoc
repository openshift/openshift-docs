= Network Observability Operator 1.12.3 fixed issues

[role="_abstract"]
The Network Observability Operator 1.12.3 release contains several fixed issues that improve system status reporting and user experience.

Surfaced missing RBAC permissions for customized namespaces in FlowCollector status::
Before this update, when the `FlowCollector` resource was configured with `spec.namespace` set to a non-default namespace value, but the required `ClusterRoleBindings` (CRBs) were not manually created for service accounts in that namespace, the Network Observability Operator did not surface a clear error message. As a consequence, users encountered FlowLogsPipeline pods in `CrashLoopBackOff` state without an actionable indication in the `FlowCollector` status of the missing role-based access control (RBAC) permissions, requiring examination of FlowLogsPipeline logs to diagnose the issue. Additionally, `ClusterRoleBindings` remained available for service accounts in the `netobserv` namespace even when that namespace was unused, creating a potential namespace squatting security risk.
+
With this release, the Network Observability Operator detects missing RBAC permissions for custom namespaces and reports them in the `FlowCollector` status with actionable error messages. The Operator also prevents namespace squatting by ensuring `ClusterRoleBindings` are scoped appropriately. As a result, users receive clear guidance when required manual RBAC configuration is missing, and the security posture is improved.
+
