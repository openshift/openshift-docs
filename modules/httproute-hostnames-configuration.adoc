= HTTPRoute hostnames

[role="_abstract"]
To select which HTTP `Host` headers an `HTTPRoute` custom resource (CR) handles, you configure the `spec.hostnames` field. A hostnames matches requests before the route rules are evaluated.

The `hostnames` field lists fully qualified domain names that must match the HTTP Host header before the controller evaluates route rules. Implementations ignore any port in the `Host` header.

- You can specify a maximum of 16 hostnames, which cannot be IP addresses.
- You can prefix a hostname with a wildcard label (`{asterisk}.`) as the first label only. For example, `{asterisk}.example.com` is valid, but `{asterisk}foo.example.com` is not. A wildcard hostname is a suffix match. For example, `{asterisk}.example.com` matches `shop.example.com` and `foo.shop.example.com`, but does not match `example.com`.

The Ingress Operator installs a `ValidatingAdmissionPolicy` admission policy that validates `HTTPRoute` CR hostnames against cluster security policies.

The Ingress Operator creates `DNSRecord` CRs for listener hostnames when the `Gateway` CR is in the `openshift-ingress` namespace and the hostname matches the cluster base domain. If you create the `Gateway` CR in another namespace, the Operator does not create `DNSRecord` CRs for that gateway. The Operator does not create DNS records for hostnames that you set only on an `HTTPRoute` CR. Set HTTPRoute hostnames that match, or are subdomains of, the attached listener hostnames.

Hostname matching between a listener and an `HTTPRoute` CR is an intersection used for routing, not a permission check:

* If both the listener and the route set hostnames, at least one hostname must intersect or the route is not accepted. The controller sets the `Accepted` condition to `False` on that parent, typically with the `NoMatchingListenerHostname` reason.
* If both set hostnames and some route hostnames do not intersect, the controller ignores the non-intersecting hostnames and uses only the intersection.
* If the route omits hostnames, it inherits the listener hostname.
* If the listener omits hostnames, any attaching route can claim hostnames. Always set a listener hostname unless you are defining a catch-all route.

When multiple `HTTPRoute` CRs specify intersecting hostnames, the controller prefers the route whose matching non-wildcard hostname has the most characters, then the matching hostname with the most characters.

The following example shows an `HTTPRoute` CR whose hostnames must fall under the parent listener hostname `*.<example_domain.tld>`.

* Incoming requests are matched against `hostnames` before `rules` are evaluated.
* A listener hostname of `*.<example_domain.tld>` accepts these hostnames. Hostnames outside that suffix, such as `app.other.tld`, do not intersect and are not accepted.

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: <example_route>
  namespace: <example_application>
spec:
  parentRefs:
  - name: <example_gateway>
    namespace: openshift-ingress
    sectionName: https
  hostnames:
  - app1.<example_domain.tld>
  - app2.<example_domain.tld>
  rules:
  - backendRefs:
    - name: <example_service>
      port: 8080
----
