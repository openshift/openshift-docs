= About cloud identity credential injection for virtual machines

[role="_abstract"]
You can inject cloud provider service account tokens into a virtual machine (VM) guest by using containerPath volumes and virtiofs. This enables VMs running on managed {product-title} clusters to authenticate with cloud provider APIs without managing static credentials.

[id="virt-cloud-credential-injection-overview_{context}"]
== How credential injection works

Managed {product-title} platforms such as Red{nbsp}Hat OpenShift Service on AWS (ROSA) and Azure Red{nbsp}Hat OpenShift (ARO) use platform-native identity mechanisms to authenticate workloads with cloud provider APIs. For pods, the platform webhook automatically injects short-lived, scoped tokens into the pod filesystem. However, VM guests cannot natively access files from the pod filesystem.

ContainerPath volumes bridge this gap by exposing a path from the virt-launcher pod filesystem to the VM guest by using virtiofs. The credential injection workflow is as follows:

. A `ServiceAccount` is annotated with the cloud provider identity binding, such as an AWS IAM role ARN or an Azure client ID.
. The platform webhook detects the annotation and injects a projected volume containing a short-lived authentication token into the virt-launcher pod.
. A `containerPath` volume source in the VM specification points to the injected token path in the virt-launcher pod.
. A `virtiofs` filesystem device in the VM specification exposes the token to the VM guest as a mounted filesystem.
. Applications inside the VM guest use the token to authenticate with cloud provider APIs.

[id="virt-supported-backing-volume-types_{context}"]
== Supported backing volume types

ContainerPath volumes support the following backing volume types:

* `ConfigMap`
* `Secret`
* `Projected`
* `DownwardAPI`
* `EmptyDir`

[id="virt-containerpath-live-migration_{context}"]
== Live migration considerations

ContainerPath volumes are compatible with live migration for the following backing volume types:

* `Secret`
* `ConfigMap`
* Sidecar-populated volumes

`EmptyDir` volumes without sidecar containers do not survive live migration.

[NOTE]
====
ContainerPath volumes are read-only from the VM guest perspective.
====
