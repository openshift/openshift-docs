= AzurePrivateLinkService conditions reference

[role="_abstract"]
The `AzurePrivateLinkService` custom resource exposes 5 status conditions that you inspect to verify the end-to-end private link chain for a hosted cluster with `Private` or `PublicAndPrivate` topology.

All 5 conditions must be `True` before the private Kubernetes API Server path is considered provisioned. Use the following conditions to diagnose incomplete or failed private connectivity.

To retrieve the current conditions from the cluster, run the following command:

[source,terminal]
----
$ oc get azureprivatelinkservices -n clusters-<cluster_name> -o yaml
----

Replace `<cluster_name>` with the name of your hosted cluster.

.AzurePrivateLinkService status conditions
[cols="2,^1,3", options="header"]
|===
|Condition name
|Expected state
|What it indicates

|`AzureInternalLoadBalancerAvailable`
|`True`
|If this condition is missing, verify that the HyperShift Operator's {azure-short} Private Link credentials, or managed identity, can read the load balancers in the management cluster resource group, and check the `AzurePLSCreated` condition message for errors.

|`AzurePLSCreated`
|`True`
|The Azure Private Link Service instance has been provisioned and is registered.
`AzureInternalLoadBalancerAvailable` must be `True` before this condition can become `True`.

|`AzurePrivateEndpointAvailable`
|`True`
|The Azure Private Endpoint has been created and its connection to the Private Link Service has been approved.
If `False`, the PE might be in a pending state awaiting approval; check the Azure portal for pending PE connection requests.

|`AzurePrivateDNSAvailable`
|`True`
|The Azure Private DNS zone and DNS records for the private Kubernetes API Server hostname have been provisioned.
If `False`, DNS records might not yet be propagated; wait and re-check.
For peered VNets, verify that the Private DNS zone is linked to each peered VNet.

|`AzurePrivateLinkServiceAvailable`
|`True`
|The HyperShift Operator sets `AzurePrivateLinkServiceAvailable` and `AzurePLSCreated` to `True` as soon as the Private Link Service is ready, before the Private Endpoint and DNS records exist. The Control Plane Operator sets the final value only after the Private Endpoint and DNS are reconciled. The value for `AzurePrivateLinkServiceAvailable` can be `True` briefly while the chain is still incomplete. To get a more reliable signal, check `AzurePrivateEndpointAvailable` and `AzurePrivateDNSAvailable`.
|===

[NOTE]
====
All 5 conditions must be `True` before you attempt to connect to the Kubernetes API Server endpoint over the private network path. If any condition is `False`, diagnose sequentially from `AzureInternalLoadBalancerAvailable` through `AzurePrivateLinkServiceAvailable`, as each resource depends on the previous one being provisioned.
====
