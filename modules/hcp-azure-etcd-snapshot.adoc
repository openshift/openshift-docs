= Backup and restore for {hcp} on {azure-short}

[role="_abstract"]
You can back up and restore a self-managed {hcp} on {azure-first} by using {oadp-first} 1.6. Automated backups capture the etcd state and associated {azure-short} infrastructure resources. If etcd data loss or corruption occurs, you can restore the cluster from a snapshot on the same management cluster.

[id="hcp-azure-etcd-snapshot-limitations_{context}"]
== Limitations for disaster recovery on {hcp} on {azure-short}

Review the following limitations before you design a disaster recovery (DR) strategy for {hcp} on {azure-short}. The same-cluster-only restriction and mandatory compute node reprovisioning have the most significant impact on DR architecture and site selection.

[cols="2,4", options="header"]
|===
|Limitation |Details

|Same-cluster restore only
|Cross-management-cluster restore is not currently supported. Only same-cluster restore, restoring to the management cluster from which the backup was taken, is validated for {azure-short}.

|{oadp-short} required
|Automated restore requires {oadp-short} 1.6 with the built-in `hypershift` plugin. No manual restore path is supported for self-managed {azure-short} {hcp}.

|`restoreSnapshotURL` immutability
|The `spec.etcd.managed.storage.restoreSnapshotURL` field is enforced as immutable by validation (`MaxItems=1`). The {oadp-short} plugin sets this field automatically at `HostedCluster` creation time during a restore. You cannot update the field after the `HostedCluster` resource is created, and you do not need to set it manually.

|No in-place restore
|The existing `HostedCluster` resource must be deleted before restore. Restoring to a running cluster is not supported. All etcd persistent volume claims (PVCs) must be removed before the restore command is run.

|Compute node reprovisioning
|Compute nodes are reprovisioned after a restore. Plan for workload disruption during recovery. Applications running on compute nodes experience downtime while nodes are reprovisioned and rejoin the cluster.

|Technology Preview (`HCPEtcdBackup` feature gate)
|etcd snapshot restore requires the `HCPEtcdBackup` feature gate on the HyperShift Operator. This feature is a Technology Preview feature and is not intended for production use.

|Single snapshot per restore
|Only one snapshot URL is accepted per restore (`MaxItems=1`). Fallback snapshot support, where you automatically retry a restore with a secondary snapshot if the first fails, is not available. Select a good backup before you run the restore command.
|===
