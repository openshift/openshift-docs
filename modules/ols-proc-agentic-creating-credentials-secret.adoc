= Store provider credentials for Agentic {ols-long}

[role="_abstract"]
Agentic {ols-long} reads the credentials for your large language model (LLM) provider from a {k8s} `Secret` in the `openshift-lightspeed` operator namespace. You create one credentials secret for each provider backend, and the `LLMProvider` custom resource (CR) references the secret by name. The required keys depend on the provider type.

.Prerequisites

* You have installed the {ols-long} Operator.
* You have logged in to the cluster as a user with the `cluster-admin` role, or with permission to create resources in the `openshift-lightspeed` namespace.
* You have the credentials for your LLM provider.

.Procedure

. Create a credentials secret in the `openshift-lightspeed` namespace that contains the keys required by your provider type. The following example creates a secret for a direct Anthropic provider:
+
[source,terminal]
----
$ oc create secret generic llm-credentials \
  --from-literal=ANTHROPIC_API_KEY=<api_key> \
  -n openshift-lightspeed
----

. Confirm that the secret exists by running the following command:
+
[source,terminal]
----
$ oc get secret llm-credentials -n openshift-lightspeed
----

.Next steps

* Create an `LLMProvider` CR that references this secret for your provider type. See the configuration procedure for your provider.

[NOTE]
====
Store credentials only in the credentials secret. Do not place credentials directly in the `LLMProvider` or `Agent` CRs. To rotate credentials, update the secret and allow the deployment to use the new values.
====
