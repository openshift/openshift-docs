= Custom Metrics Autoscaler Operator 2.20.0 release notes

Issued: 22 September 2026

[role="_abstract"]
You can review the following release notes to learn about the bug fixes provided in this release of the Custom Metrics Autoscaler Operator.

The following advisory is available for the Custom Metrics Autoscaler Operator:

* link:https://access.redhat.com/errata/RHBA-2026:TBD[RHBA-2026:TBD]

[IMPORTANT]
====
Before installing this version of the Custom Metrics Autoscaler Operator, remove any previously installed Technology Preview versions or the community-supported version of Kubernetes-based Event Driven Autoscaler (KEDA).
====

New features and enhancements::

The following items are new features in this release:

* Configurable replica counts for Custom Metrics Autoscaler components. You can set the replica count for the Custom Metrics Autoscaler Operator, the metrics server, and the admission webhooks independently in the `KedaController` custom resource. Use the `spec.operator.replicas`, `spec.metricsServer.replicas`, and `spec.admissionWebhooks.replicas` fields. With more than one replica, the component stays available if a pod fails. If you do not set a replica count, the component runs one replica by default.
+
The Operator uses leader election, so a second Operator replica serves as a standby. Additional Operator replicas do not increase availability. You can run more than two replicas of the metrics server and the admission webhooks.
+
For more information, see xref:../../../nodes/cma/nodes-cma-autoscaling-custom-install.adoc#nodes-cma-autoscaling-keda-controller-edit_nodes-cma-autoscaling-custom-install[Edit the Keda Controller CR].

* Environment variables for Custom Metrics Autoscaler components. You can set environment variables in the `KedaController` custom resource (CR) for the Custom Metrics Autoscaler components: the KEDA operator, the metrics server, and the admission webhook. A value replaces an environment variable of the same name on that component, including a variable set by the Custom Metrics Autoscaler Operator.
+ 
For example, the `KEDA_HTTP_DEFAULT_TIMEOUT` environment variable sets the HTTP client timeout for scalers, in milliseconds. Without this setting, outbound HTTP requests initiated by individual scalers fall back to hard-coded client defaults, which could cause failures in high-latency network environments.
+
For the environment variables that change component behavior, see the link:https://keda.sh/docs/2.20/operate/cluster/[KEDA cluster documentation].
+
For more information on editing the `KedaController` CR, see xref:../../../nodes/cma/nodes-cma-autoscaling-custom-install.adoc#nodes-cma-autoscaling-keda-controller-edit_nodes-cma-autoscaling-custom-install[Edit the Keda Controller CR].

* Support the HTTP Add-on extension. The Custom Metrics Autoscaler supports the HTTP Add-on extension which allows you to automatically scale an HTTP-based application by using the number of HTTP requests to that application. 
+
For more information, see Scaling applications based on HTTP traffic.

Bug fixes::
* Before this update, the `default` scaling strategy for scaled jobs was missing. With this fix, the `default` strategy has been added back to the `scaledjobs` custom resource. As a result, you can select the default strategy with scaled jobs. (link:https://redhat.atlassian.net/browse/OCPBUGS-121352[OCPBUGS-121352])
+
[NOTE]
====
This issue was initially addressed in the Custom Metrics Autoscaler 2.19.0-3 release through link:https://redhat.atlassian.net/browse/OCPBUGS-98657[OCPBUGS-98657]. However, the fix did not fully address the problem. Updating to the Custom Metrics Autoscaler 2.19.0-4 release will fix this issue.
====
