= Metrics for user-defined networks

[role="_abstract"]
You can use OVN-Kubernetes metrics to monitor user-defined network (UDN) reconciliation and programming performance. These metrics help you find when a UDN is ready and identify bottlenecks when you create or scale UDNs.

The following metrics are available from the `ovnkube-cluster-manager` and `ovnkube-controller` metrics endpoints.

[cols="1,1a,1"]
|===
| Name | Description | Explanation

|`ovnkube_clustermanager_udn_reconciliation_duration_seconds`
|`name`: specifies the UDN or cluster user-defined network (CUDN) name
|The total time to reconcile a UDN, including `NetworkAttachmentDefinition` (NAD) creation, node allocation, and status updates.

|`ovnkube_clustermanager_udn_workflow_phase_duration_seconds`
|* `name`: specifies the UDN or CUDN name
* `phase`: specifies one of `queue_wait`, `nad_sync`, `async_node_allocation`, or `network_ready`
|The wall-clock duration of each UDN workflow phase. Use this metric to identify which phase is causing delays during UDN creation.

|`ovnkube_clustermanager_udn_node_alloc_operation_duration_seconds`
|* `name`: specifies the UDN or CUDN name
* `operation`: specifies one of `parse_annotations`, `allocate_subnets`, `allocate_tunnel_id`, or `update_node_annotations`
|The time spent in per-node allocation operations. Layer 3 networks record `parse_annotations` and `allocate_subnets`; layer 2 primary networks record `allocate_tunnel_id`; all networks record `update_node_annotations`.

|`ovnkube_controller_udn_nbdb_programmed_duration_seconds`
|`topology`: specifies the UDN topology, such as `layer2` or `layer3`
|The time to program OVN northbound database (NBDB) logical objects during UDN network controller initialization.
|===
