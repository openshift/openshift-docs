[role="_abstract"]
[.pr:microshift .pr:openshift-enterprise .pr:openshift-origin .pr:openshift-rosa-hcp]#You can deploy {product-title} to one of the major cloud service providers (CSPs): {aws-first}, {gcp-full}, or Microsoft Azure.# [.pr:openshift-dedicated .pr:openshift-rosa]#You can deploy {product-title} on NVIDIA GPU instance types.#

[role="pr:microshift pr:openshift-enterprise pr:openshift-origin pr:openshift-rosa-hcp"]
Two modes of operation are available: a fully managed deployment and a self-managed deployment.

* [.pr:microshift .pr:openshift-enterprise .pr:openshift-origin .pr:openshift-rosa-hcp]#In a fully managed deployment, everything is automated by Red{nbsp}Hat in collaboration with CSP. 
You can request an {product-title} instance through the CSP web console, and the cluster is automatically created and fully managed by Red{nbsp}Hat. 
Red Hat manages infrastructure operations, including node failure recovery and environment maintenance.
Red{nbsp}Hat is fully responsible for maintaining the uptime of the cluster.
The fully managed services are available on {aws-short}, {azure-short}, and {gcp-short}. 
For {aws-short}, the {product-title} service is called (Red{nbsp}Hat {product-title} Service on AWS). 
For Azure, the service is called Azure Red{nbsp}Hat OpenShift. 
For {gcp-short}, the service is called OpenShift Dedicated on {gcp-short}.#

* [.pr:microshift .pr:openshift-enterprise .pr:openshift-origin .pr:openshift-rosa-hcp]#In a self-managed deployment, you are responsible for instantiating and maintaining the {product-title} cluster. 
Red{nbsp}Hat provides the {product-title} install utility to support the deployment of the {product-title} cluster in this case. The self-managed services are available globally to all CSPs.#

[IMPORTANT]
====
The compute instance must be a GPU-accelerated compute instance. Additionally, the GPU type must match the list of supported GPUs from NVIDIA AI Enterprise. For example, T4, V100, and A100 are part of this list.
====

You can choose one of the following methods to access the containerized GPUs:

* GPU passthrough to access and use GPU hardware within a virtual machine (VM).

* GPU (vGPU) time slicing when the entire GPU is not required.
