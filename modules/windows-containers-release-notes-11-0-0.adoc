= Release notes for Red Hat Windows Machine Config Operator 11.0.0

Issued: DD Mm 2026

[role="_abstract"]
You can review the following release notes to learn about the new features and bug fixes in the Windows Machine Config Operator (WMCO) version 11.0.0.

The components of the WMCO version 11.0.0 were released in TBD.

[id="wmco-11-0-0-new-features_{context}"]
== New features and improvements

Windows Machine Config Operator metrics server follows the cluster TLS security profile::
The WMCO metrics server uses the TLS security profile configured for the cluster when the `spec.tlsAdherence` parameter is set to `StrictAllComponents` and `spec.tlsSecurityProfile` parameter is configured on the cluster API server. When you change the cluster TLS profile or the adherence policy, the Operator restarts and applies the new settings. This keeps the metrics server aligned with the cluster TLS policy, including a custom profile.

For more information, see "Cluster TLS security profile for the Windows Machine Config Operator metrics server".

Kubernetes upgrade::
The WMCO now uses Kubernetes version 1.36.

Windows exporter log troubleshooting documentation::
The troubleshooting documentation now describes how to locate Windows exporter logs. The `windows-exporter` process runs without a `kube-log-runner` wrapper and writes its log file directly to `C:\var\log\windows_exporter\windows_exporter.log`.

For more information, see xref:../../windows_containers/windows-containers-troubleshooting.adoc#collecting-kube-node-logs-windows_windows-containers-troubleshooting[Collecting Kubernetes node logs for Windows containers].

== Bug fixes

* Before this update, old `ovnkube-client-.pem` certificate files would accumulate indefinitely in the `C:\k\cni\config` directory, because the `hybrid-overlay` service generates a new time-stamped certificate daily during certificate rotation. As a consequence, the accumulated certificates could cause unnecessary disk usage growth over time. With this release, the Windows Instance Config Daemon (WICD) now has cleanup logic for older files, which runs during the normal reconciliation loop (every 2 minutes) and keeps only the 2 most recent certificates, deleting any older certificates. As a result, old `ovnkube-client-.pem` certificate files are now automatically pruned, so that only the latest required certificates remain and disk usage no longer grows unbounded from stale cert files. (link:https://issues.redhat.com/browse/OCPBUGS-86246[OCPBUGS-86246])

* Before this update, the Windows Prometheus recording rule for `instance:node_cpu_utilisation:rate1m` recorded the CPU idle rate. The Linux recording rule with the same name records CPU utilization. As a consequence, the OpenShift Virtualization HighCPUWorkload alert fired for Windows nodes that had low CPU utilization, because the alert treated idle time as utilization. With this release, the Windows recording rule records CPU utilization. As a result, instance:node_cpu_utilisation:rate1m reports CPU utilization for Windows nodes, and the HighCPUWorkload alert fires when a Windows node is highly utilized. (link:https://issues.redhat.com/browse/OCPBUGS-85061[OCPBUGS-85061])

* Before this update, the SSH connection between the WMCO and a Windows node would terminate when the WMCO rebooted the node after a configuration update. As a consequence, the WMCO incorrectly treated the SSH disconnection as a reboot failure, preventing the Windows node from completing required reboots. With this release, the reboot validation process is modified to ignore SSH termination errors and instead verify a successful reboot by using explicit node reachability checks and the SSH reconnection. As a result, Windows nodes successfully reboot upon node configuration changes. (link:https://issues.redhat.com/browse/OCPBUGS-90077[OCPBUGS-90077])

* Before this update, the CRI plug-in in the Windows Machine Config Operator (WMCO) containerd 1.7.27 runtime copied image-config labels onto the container and treated them like the CRI labels, including labels in the reserved `containerd.io/` and `io.cri-containerd` namespaces. As a consequence, a crafted image label could have reached the `restart-monitor` logger and caused the logger to run a command with `host-root` privileges from that label on the Windows node. With this release, the WMCO updates the Windows containerd runtime from 1.7.27 to 1.7.33. The updated runtime filters those reserved namespaces from image-config labels and preserves ordinary image labels and labels supplied by the CRI request. As a result, a label in a reserved containerd or CRI namespace does not reach the `restart-monitor` logger. (link:https://issues.redhat.com/browse/OCPBUGS-123789[OCPBUGS-123789])
