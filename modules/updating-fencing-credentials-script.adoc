= Update fencing credentials by using the script

[role="_abstract"]
You can use the credential update script to simplify updating Baseboard Management Controller (BMC) credentials for fencing in a two-node {product-title} cluster.
The script handles credential updates automatically, eliminating error-prone manual configuration.

.Prerequisites

* You have administrative access to the control plane nodes.
* You have necessary permissions to run the credential update script.
* You have the new BMC credentials for the fencing devices, including the Redfish API endpoint, username, and password.

.Procedure

. Log in to a control plane node with SSH by running the following command:
+
[source,terminal]
----
$ ssh core@<control_plane_node_ip>
----
+
Replace `<control_plane_node_ip>` with the IP address of your control plane node.

. Locate the credential update script on the control plane node by running the following command:
+
[source,terminal]
----
$ ls -la /path/to/credential-update-script
----
+
Replace `/path/to/credential-update-script` with the full path.

. Run the credential update script by using the following command:
+
[source,terminal]
----
# /path/to/credential-update-script
----
+
Replace `/path/to/credential-update-script` with the full path to the script on your system.

. Enter your new BMC credentials when prompted by the script:
+
The script prompts you to enter the Redfish API endpoint, BMC username, and BMC password for each node.
Supply the correct credentials for each prompt and proceed to the next node when directed.

. Check the script output to confirm successful completion:
+
The script displays a completion message and reports any errors that occurred during the update process.

.Verification

To verify that the credential update is successful:

. The credential update script completed without errors in its output.

. All Pacemaker resources are in a `Started` state with no authentication errors:
+
[source,terminal]
----
$ sudo pcs status
----

. The openshift-etcd secret exists and has a recent timestamp:
+
[source,terminal]
----
$ oc get secret -n openshift-etcd
----

.Troubleshooting

If the credential update script fails or reports errors:

. Check the script output for specific error messages related to credential format or BMC connectivity.

. Verify that the new BMC credentials are correct and that the Redfish API endpoint is reachable from the control plane nodes.

. If the script fails repeatedly, contact your infrastructure team or Red Hat support for assistance.

. Provide the script output and any relevant Pacemaker logs that are available by running the following command:
+
[source,terminal]
----
$ sudo journalctl -u pacemaker
----

.Next steps

* Monitor the cluster for several hours to confirm that Pacemaker can successfully authenticate with the BMC using the new credentials.
* If a node becomes unresponsive and requires fencing, verify that Pacemaker can power off or isolate the node without credential-related errors.
