= Trace context propagation in the {mcpg}

[role="_abstract"]
You can correlate {mcpg} activity with broader {DTShortName} across your infrastructure. The {mcpg} router extracts W3C Trace Context headers from incoming requests, enabling automatic integration with {service-mesh} tracing systems such as Istio and Envoy.

[id="con-mcp-gateway-w3c-trace-context-header-support_{context}"]
== W3C Trace Context standard header support

The router extracts the `traceparent` header from incoming requests. This header follows the W3C Trace Context standard and has trace ID, parent span ID, and sampling information.

Clients can pass an explicit `traceparent` header for end-to-end observability. When the header is present, the {mcpg} continues the existing trace. When the header is absent, the router creates a new root trace.

== Automatic service mesh integration

When {mcpg} runs in a {service-mesh} environment such as Istio, the mesh sidecar automatically injects the `traceparent` header into requests. The {mcpg} router extracts this header and uses it to continue the trace, creating child spans that appear in the same distributed trace as the mesh traffic.

This automatic integration means that tool calls flowing through the {mcpg} are displayed as part of the same trace timeline as other mesh services, without requiring explicit client configuration.

[id="con-mcp-gateway-resource-attributes_{context}"]
== Resource attributes

Every router span emitted by the {mcpg} includes resource attributes that give service metadata:

* `service.name`: Service identifier. Default is `mcp-gateway`.
* `service.version`: Service version.
* `git.revision`: Git commit hash of the deployed version.
* `go.version`: `Go` runtime version.

These attributes help you correlate spans across deployments and identify which version of the {mcpg} generated specific trace data.
