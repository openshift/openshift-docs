= Decision tree for choosing a deployment model

[role="_abstract"]
Use this decision tree to select the appropriate Argo CD deployment model based on your requirements, scale, and operational constraints.

*Deployment model selection*

Follow this decision tree to choose between traditional Argo CD and Argo CD Agent architectures:

. *Do you manage applications on a single cluster or multiple clusters?*
+
** Single cluster → Use traditional Argo CD with namespace-scoped or cluster-scoped instance
** Multiple clusters → Continue to question 2

. *Do managed clusters have network restrictions or firewall constraints?*
+
** Yes, clusters are in isolated networks or behind firewalls → Use Argo CD Agent architecture
** No, hub cluster has direct network access to all managed clusters → Continue to question 3

. *Do you need to manage more than 100 clusters?*
+
** Yes → Use Argo CD Agent architecture for better scalability
** No → Continue to question 4

. *Do you need agents to operate autonomously during network outages?*
+
** Yes → Use Argo CD Agent in autonomous mode
** No → Use traditional Argo CD or Argo CD Agent in managed mode

. *Do you need to minimize resource usage on the hub cluster?*
+
** Yes → Use Argo CD Agent to distribute reconciliation workload to spoke clusters
** No → Traditional Argo CD is sufficient

*Instance scope selection*

After choosing a deployment model, select the instance scope:

. *Do applications need cluster-admin permissions to deploy cluster-scoped resources?*
+
** Yes → Use cluster-scoped Argo CD instance
** No → Use namespace-scoped Argo CD instance

. *Do multiple teams need isolated Argo CD instances?*
+
** Yes → Create multiple namespace-scoped instances, one per team
** No → Use the default cluster-scoped instance or a single custom instance

*Operational mode selection (Agent architecture only)*

If you selected Argo CD Agent architecture, choose the operational mode:

. *Must agent clusters continue deployments if the hub is temporarily unavailable?*
+
** Yes → Use autonomous mode
** No → Use managed mode for centralized control

. *Do you need the hub to have full visibility into agent cluster state?*
+
** Yes → Use managed mode
** No → Autonomous mode provides more independence

*Recommended configurations*

The following table shows recommended architectures for common deployment scenarios:

[cols="1,2,1",options="header"]
|===
|Scenario |Recommended architecture |Instance scope
|Development team on single cluster |Traditional Argo CD |Namespace-scoped
|Platform team managing cluster infrastructure |Traditional Argo CD |Cluster-scoped (default)
|Multi-cluster with good network connectivity |Traditional Argo CD with cluster secrets |Cluster-scoped
|Multi-cluster with network constraints |Argo CD Agent (managed mode) |Cluster-scoped
|Edge deployments requiring autonomy |Argo CD Agent (autonomous mode) |Cluster-scoped
|Multi-tenant platform with team isolation |Traditional Argo CD, multiple instances |Namespace-scoped per team
|===
