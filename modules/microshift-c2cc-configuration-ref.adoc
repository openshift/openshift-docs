= C2CC configuration reference

[role="_abstract"]
All C2CC settings live under the `clusterToCluster` section of the {microshift-short} configuration file.
Use this reference when configuring remote clusters, DNS caching, routing tables, and health probes.

.C2CC configuration fields definitions table
[cols="1,2"]
|===
|Parameter|Description

|`clusterToCluster`
|The `clusterToCluster` section of the {microshift-short} configuration file defines the configurable parameters for cluster-to-cluster communication. All of the following parameters in this table are subsections in the `clusterToCluster` section of the {microshift-short} configuration. C2CC is disabled when `remoteClusters` is empty.

|`remoteClusters`
|Is a subgroup that lists the remote clusters. Add one entry per remote cluster on every host in a full-mesh topology.

|`remoteClusters.nextHop`
|Specifies the next-hop IP addresses of the remote node. At most one IPv4 and one IPv6 address are allowed. The addresses must not equal the local node IP or duplicate another remote. This field is required.

|`remoteClusters.clusterNetwork`
|Specifies the remote pod CIDRs. The CIDRs must not overlap with local or other remote CIDRs. The minimum mask is `/8` for IPv4 or `/32` for IPv6. This field is required.

|`remoteClusters.serviceNetwork`
|Specifies the remote service CIDRs. The same constraints apply as for `clusterNetwork`. The list must have the same number of entries with matching IP families. This field is required.

|`remoteClusters.domain`
|Specifies an optional DNS suffix for the remote cluster. The value must be a valid DNS subdomain, unique across remotes, and not `cluster.local`. When set, Services on the remote cluster are resolvable as `<svc>.<ns>.svc.<domain>`. When unspecified, `domain` defaults to `""` (no DNS forwarding for this remote).

|`probeInterval`
|Specifies the interval between health probes to each remote cluster. The value is a Go duration string between `1s` and `5m`. When unspecified, `probeInterval` defaults to `10s`.

|`dns`
|`dns` is a subgroup that specifies DNS cache settings for remote domains.

|`dns.cacheTTL`
|Specifies the maximum TTL in seconds for positive DNS cache entries for remote domains. A value of `0` disables caching. When unspecified, `cacheTTL` defaults to `10`.

|`dns.cacheNegativeTTL`
|Specifies the maximum TTL in seconds for negative (NXDOMAIN/NODATA) DNS cache entries. A value of `0` disables caching. When unspecified, `cacheNegativeTTL` defaults to `10`.

|`routing`
|`routing` is a subgroup that specifies Linux policy routing table IDs for C2CC routes.

|`routing.routeTableID`
|Specifies the Linux policy routing table for routes to remote CIDRs. The range is `1`–`252` and the value must differ from `serviceRouteTableID`. When unspecified, `routeTableID` defaults to `200`.

|`routing.serviceRouteTableID`
|Specifies the Linux policy routing table for service routes via the OVN management port. The range is `1`–`252` and the value must differ from `routeTableID`. When unspecified, `serviceRouteTableID` defaults to `201`.

|===

The routing table IDs only need to be changed if other software on the host (for example, NetworkManager dispatcher scripts or VPN tooling) already uses tables `200` and `201`.

== IPv6 and dual-stack example

C2CC supports IPv6-only and dual-stack clusters.
The local and remote clusters must have compatible IP families: for every remote CIDR family there must be a matching-family `nextHop` entry.

.Dual-stack remote cluster configuration
[source,yaml]
----
clusterToCluster:
  remoteClusters:
  - nextHop:
    - 192.168.1.20
    - 2001:db8:0:1::20
    clusterNetwork:
    - 10.45.0.0/16
    - fd01:0:0:1::/64
    serviceNetwork:
    - 10.46.0.0/16
    - fd02:0:0:1::/112
    domain: cluster-b.remote
----

`clusterNetwork` and `serviceNetwork` must have the same number of entries with matching IP families at each position (at most one IPv4 and one IPv6 CIDR each).

== Disabling C2CC

Remove the C2CC configuration snippet (or the `remoteClusters` entries) and restart {microshift-short}:

[source,terminal]
----
$ sudo rm /etc/microshift/config.d/50-c2cc.yaml
$ sudo systemctl restart microshift
----

On startup, the controller detects that C2CC is disabled and cleans up all C2CC-owned state: OVN static routes, kernel routes and rules, nftables rules, node annotations, the probe deployment, and the `RemoteCluster` resources.

Remember to remove the remote CIDRs from the firewall trusted zone as well.

If you overrode `routing.routeTableID` or `routing.serviceRouteTableID`, disable in two stages so the cleanup targets the right tables: first remove only the `remoteClusters` entries while keeping the `routing` overrides and restart, then remove the rest of the `clusterToCluster` section and restart again.
