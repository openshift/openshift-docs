= Configuring logging for the virtual machine proxy

[role="_abstract"]

The proxy on a virtual machine writes its own diagnostic output to the systemd journal. Access logs are configured separately, and the mesh-wide default does not work on a virtual machine, so route them to a file instead.

View the diagnostic output of the proxy by running the following command on the virtual machine:

[source,terminal]
----
$ sudo journalctl -u istio-proxy
----

[IMPORTANT]
====
Setting the `meshConfig.accessLogFile` field to `/dev/stdout` configures access logging for every proxy in the mesh. This works for workloads that run as pods, where the container runtime captures standard output, but not on a virtual machine, where the proxy runs as a systemd service and `/dev/stdout` is a symbolic link to `/proc/self/fd/1`. When Envoy attempts to open that path, it logs an error for every listener:

[source,terminal]
----
0.0.0.0_8000: unable to open file '/dev/stdout': No such device or address
virtualOutbound: unable to open file '/dev/stdout': No such device or address
virtualInbound: unable to open file '/dev/stdout': No such device or address
----

Configure a file-based extension provider and apply it to the virtual machine workload with a `Telemetry` resource instead.
====

.Procedure

. Add a file access log extension provider to the `Istio` resource:
+
[source,yaml]
----
apiVersion: sailoperator.io/v1
kind: Istio
metadata:
  name: default
spec:
  namespace: istio-system
  values:
    meshConfig:
      extensionProviders:
      - name: vm-file-logger # <1>
        envoyFileAccessLog:
          path: /var/log/istio/access.log # <2>
----
<1> The name that the `Telemetry` resource references.
<2> The path on the virtual machine that the proxy writes access logs to.

. Apply the updated `Istio` custom resource (CR) by running the following command:
+
[source,terminal]
----
$ oc apply -f istio.yaml
----

. Create a `Telemetry` resource named `vm-access-logging.yaml` in the namespace of the virtual machine workload:
+
[source,yaml]
----
apiVersion: telemetry.istio.io/v1
kind: Telemetry
metadata:
  name: vm-access-logging
  namespace: external-vm
spec:
  accessLogging:
  - providers:
    - name: vm-file-logger
----
+
A namespace-scoped `Telemetry` resource applies to every proxy in that namespace, including proxies that run as sidecars in pods. Use this scope only when the namespace contains virtual machine workloads exclusively.
+
If the namespace also contains workloads that run as pods, restrict the resource to the virtual machine workload with a label selector that matches the labels in the `WorkloadGroup` resource:
+
[source,yaml]
----
apiVersion: telemetry.istio.io/v1
kind: Telemetry
metadata:
  name: vm-access-logging
  namespace: external-vm
spec:
  selector:
    matchLabels:
      app: vm-app # <1>
  accessLogging:
  - providers:
    - name: vm-file-logger
----
<1> Applies the configuration only to proxies whose workload carries this label. Proxies in pods continue to use the mesh-wide access log configuration.

. Apply the `Telemetry` resource by running the following command:
+
[source,terminal]
----
$ oc apply -f vm-access-logging.yaml
----
