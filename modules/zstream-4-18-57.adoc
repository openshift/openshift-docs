== Fixed issues

* Before this update, the web console GraphQL endpoint disabled introspection queries over HTTP requests but not over WebSocket connections. As a consequence, the GraphQL schema could still be enumerated by sending introspection queries over the WebSocket transport, allowing information disclosure about available operations and types. With this release, the web console rejects introspection queries over both HTTP and WebSocket transports. As a result, the GraphQL schema information is no longer accessible through either connection method, fully mitigating the information disclosure risk. (link:https://issues.redhat.com/browse/OCPBUGS-113759[OCPBUGS-113759])

* Before this update, when a node with an assigned EgressIP was rebooted, the cluster manager immediately reassigned the EgressIP to a new node without waiting for the old node to remove it. As a consequence, both the old and new nodes responded to ARP requests for the same EgressIP with different MAC addresses, causing MAC address flapping. This could overload network switches, trigger port blocking, or disrupt network infrastructure depending on the configuration. With this release, the EgressIP removal process on the old node is prioritized to complete before the new node announces the IP. As a result, MAC address flapping and associated network disruptions are prevented. (link:https://issues.redhat.com/browse/OCPBUGS-129152[OCPBUGS-129152])
