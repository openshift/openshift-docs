= Scenario 1: Vector only (forward-only)

*Choose this scenario if:*

* You already have a centralized log management platform (Splunk, ELK, Datadog, etc.)
* You do not need local log queries in OpenShift
* You want minimal resource usage in your cluster
* Setting up object storage in your cluster is not feasible
* Compliance requires all logs to go to an external system immediately

*What you need to plan:*

* External log destination configuration (CloudWatch, Splunk, Kafka endpoints, credentials)
* Network connectivity from cluster to external systems
* Log retention policies on the external platform
* Log filtering and transformation rules (if needed)

*What you do NOT need:*

* Object storage setup
* Loki sizing calculations
* Query performance tuning
* Console UI configuration

*Resource requirements:*

* *CPU*: Vector DaemonSet uses ~100m CPU per node (varies with log volume)
* *Memory*: Vector DaemonSet uses ~128-256 MiB per node
* *Storage*: No persistent storage required (Vector buffers in memory)

*Estimated installation time:* 15-30 minutes

*Go to these planning topics:*

* xref:../plan/plan-your-logging-installation.adoc#plan-your-logging-installation[Plan your logging installation]

*Skip these planning topics:*

* Choose a LokiStack storage backend (not applicable)
* Size your LokiStack deployment (not applicable)
