= Rollouts in the GitOps Console

The {gitops-shortname} Console plugin provides list and details pages for Argo Rollouts in the {OCP} web console. You can search and filter Rollouts, create them from a YAML template, scale replicas, inspect revisions and pods, and open Rollouts in the Developer Topology view.

The *Rollouts* page is available when the Rollout custom resource definition is installed on the cluster.

.Prerequisites

* Your cluster installs the Rollout CRD.
* You activate the {gitops-shortname} Console plugin.
* You reach the {OCP} web console.
* You hold permissions that allow listing Rollouts in at least one namespace.

.Procedure

To access the Rollouts list page:

. Switch to the *Administrator* perspective and select *GitOps* -> *Rollouts*.

. Optional: Reduce the list to one namespace by picking a project from the *Project* dropdown, or view every namespace by selecting all projects.

The list page provides filtering, search, and creation controls. For more information, see "Filter, search, and paginate resources" and "Common console features". The following filters are available:

* *Rollout Status*: Healthy, Paused, Progressing, Degraded

The Rollouts table columns include: *Name*, *Namespace*, *Status*, *Pods*, *Labels*, *Selector*, *Last Updated*, and row actions.

When the list has results, a *Topology view* control opens the Developer Topology graph. For more information, see "Graphs and topology views".


In the *Developer* perspective, the {OCP} Console *Topology* view can show Rollout workloads when:

* The Rollout CRD is installed

When those conditions are met:

* Rollout nodes include a visual decorator
* Selecting a Rollout opens *Details* and *Overview* sidebar tabs
* Context actions include *Edit Rollout* and *Delete Rollout*

Use the *Topology view* control on the Rollouts list, Details tab, or Pods tab to open that graph.

From Details or Pods, the Rollout is selected in the graph.

To view Rollout details:

. From the Rollouts list, click a Rollout name.

. The details page breadcrumb shows *Rollouts* -> *Rollout details*.

. Use the page header *Actions* menu for the same edit and delete actions as the list. On the *Revisions* tab, the header actions switch to revision controls (*Promote*, *Full Promote*, *Abort*, *Retry*, *Restart*).

The details page includes the following tabs.


The *Details* tab summarizes identity, scale, strategy, and status.

Section title: *Rollout details*.

*Summary (left)*

* *Name*, with a *Topology view* control that opens the Developer Topology graph for this Rollout
* *Namespace*
* *Labels*, with *Edit*
* *Annotations*
* *Created at*
* *Owner*

*Status and configuration (right)*

* *Replicas*: Desired replica count, with inline scale controls when you have update permission
* *Status*: Current rollout phase (*Healthy*, *Paused*, *Progressing*, *Degraded*, or similar), with an optional status message
* *Strategy*: *Blue-Green* or *Canary*
* Strategy-specific fields:
** *Canary*: *Stable Service*, *Canary Service*, and *Analysis Templates*
** *Blue-Green*: *Active Service* and *Preview Service*

*Conditions*

Below the summary, the *Conditions* section shows Rollout status conditions. If none are reported, the section shows *No conditions found*.


The *YAML* tab provides a live editor for the Rollout manifest. For more information, see "Common console features".


The *Revisions* tab shows the Rollout and its ReplicaSet revision history in a tree table, similar to `oc argo rollouts get rollout` (including live updates comparable to `--watch`).

Section title: *Rollout Revisions*.

Toolbar and header actions:

* *Promote*, *Full Promote*, and *Abort* — available when the Rollout is *Progressing* or *Paused*
* *Retry* — available when the Rollout is *Degraded*
* *Restart* — always available

|===
| Column | Description

| *Name*
| Rollout, revision ReplicaSet, or nested pod name

| *Kind*
| Resource kind

| *Status*
| Health or phase for the row

| *Age*
| Age of the resource

| *Info*
| Labels such as *Stable*, *Active*, *Preview*, or *Canary*, plus pod and image summary
|===

*Rollback* is available from a non-current revision's row actions when you have patch permission. Rollback is disabled for the current revision.


The *Pods* tab lists pods associated with the Rollout. The table supports filtering, search, sorting, and pagination. A *Topology view* control can open the graph with this Rollout selected.

* *Filtering*: Filter pods by *Health Status* (Running, Pending, Terminating, CrashLoopBackOff, Completed, Failed, Unknown)
* *Table columns*: *Name*, *Namespace*, *Traffic*, *Status*, *Ready*, *Restarts*, *Owner*, *Memory*, *CPU*, *Created At*, and row actions

Pod row actions can include *Edit labels*, *Edit annotations*, *Edit Pod*, and *Delete*.


The *Events* tab shows Kubernetes events for the Rollout object, using the standard console event stream for that resource.
