= Agent self-registration considerations

When you use agent self-registration, consider the following behavior and security aspects.

*Behavior notes*

Manual secrets take precedence:: Cluster secrets that you create manually with the `argocd-agentctl agent create` command are not modified or replaced by the self-registration process. You can run both manually registered and self-registered agents in the same environment.

Token refresh:: Self-registered secrets include a JWT bearer token for the resource proxy. If the JWT signing key is rotated, the principal automatically refreshes the token the next time the agent connects.

Labels:: The principal always applies the `argocd-agent.argoproj-labs.io/self-registered-cluster: "true"` label to self-registered cluster secrets. If you configure additional labels in the `clusterSecretLabels` field, the principal applies those labels when it creates the secret.

*Security considerations*

Authentication requirements:: Self-registration does not bypass authentication. Only agents with valid credentials can connect and register. You must still create and distribute valid TLS certificates to your agent clusters.

Shared client certificate:: All self-registered agents share a single client certificate for resource proxy mTLS authentication. The agent's identity comes from the JWT bearer token, not the certificate. Protect the shared client certificate secret with role-based access control (RBAC) to prevent unauthorized access.

Access control:: When you enable self-registration, any authenticated agent can register with the principal. Ensure that you control who can obtain trusted credentials by limiting access to the certificate authority and the shared client certificate.

*Configuration parameters*

The following table describes the configuration parameters for agent self-registration:

[cols="1,2,1",options="header"]
|===
|Parameter
|Description
|Required

|`selfRegistration.enabled`
|Enables automatic cluster secret creation when an authenticated agent connects. Set to `false` by default.
|Yes

|`selfRegistration.clientCertSecretName`
|Name of the secret that contains the shared client certificate. The secret must include `tls.crt`, `tls.key`, and `ca.crt` keys.
|Yes (when enabled)

|`selfRegistration.clusterSecretLabels`
|Custom labels applied to cluster secrets created for self-registered agents. Useful for organizing or selecting those secrets.
|No
|===
