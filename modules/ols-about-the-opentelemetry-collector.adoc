= How the OpenTelemetry Collector handles audit and trace data

[role="_abstract"]
{ols-long} integrates with the OpenTelemetry (OTEL) Collector to export audit and distributed trace data to your observability platform. This integration is one half of the dual-emission audit architecture; structured JSON output to stdout is the other half and is always active.

== OTEL spans

Each audit event generates an OTEL span. The span carries the same fields as the corresponding JSON log entry and uses the interaction `trace_id` as the OTEL trace ID. This lets you view a complete interaction timeline as a distributed trace in any OTEL-compatible backend such as Jaeger or Tempo.

== Endpoint configuration

You configure the OTEL Collector endpoint through the `spec.audit.otel.endpoint` field on the `OLSConfig` or `AgenticOLSConfig` CR. The endpoint must be a gRPC OTLP address, for example:

[source,yaml]
----
spec:
  audit:
    otel:
      endpoint: grpc://otel-collector.observability.svc.cluster.local:4317
----

You can configure the OTEL endpoint on `OLSConfig`, `AgenticOLSConfig`, or both independently.

== Graceful degradation

Configuring an OTEL endpoint is optional. When no endpoint is configured:

* The system initializes a no-op OTEL exporter.
* All audit events are still written as structured JSON to stdout.
* No errors or warnings are generated due to a missing OTEL endpoint.

You can add or update the OTEL endpoint at any time by editing the CR. The operator reconciles the change without restarting the service.
