= Ambient mesh in the console

[role="_abstract"]

The console visualizes {istio} ambient mode on {ocp-product-title}: ztunnel, waypoint proxies, ambient namespaces, and the Layer 4 and Layer 7 traffic they carry.

{KialiServer} must be able to read the namespace where ztunnel runs. On {ocp-product-title} that namespace is often the control plane namespace. Without that access, ambient badges and ambient graph options do not appear.

A control plane that runs ambient mode shows an ambient badge on the Namespaces page and on the Mesh page. A namespace labeled `istio.io/dataplane-mode=ambient` is enrolled in the ambient mesh. The Namespaces page then shows how many ambient data planes and how many sidecar data planes that namespace has.

Workloads, applications, and services in the ambient mesh show a badge. The badge states whether traffic is redirected to ztunnel for Layer 4 features, and whether a waypoint proxy adds Layer 7 features. When a waypoint handles the workload, the workload detail page links to that proxy. Ambient connections use HBONE rather than plain TCP.

The graph collects metrics from ztunnel and from waypoint proxies. Without a waypoint, the graph shows Layer 4 traffic only. With a waypoint, the graph can show Layer 7 traffic as well. Enable waypoint nodes in the graph display options when you need to see those proxies.

Workload logs can include ztunnel and waypoint entries next to the application logs. Traces appear after you deploy waypoint proxies, because waypoints generate the traces.

Layer 7 {istio} objects in an ambient namespace, such as HTTP routing or HTTP authorization, take effect only when traffic is enrolled on a waypoint with the `istio.io/use-waypoint` label. The console warns when an object needs a waypoint that is not in place. Layer 4-only policies and virtual services that bind only to ingress or egress gateways do not need a waypoint.
