= {SMProductName} version 3.5 new features and enhancements

[role="_abstract"]

This release makes {SMProductName} 3.5 generally available, adds new features, addresses Common Vulnerabilities and Exposures (CVEs), and is supported on {ocp-product-title} 4.20 and later.

For lists of supported component versions (such as the {istio} control plane) and feature support levels, see:

* "{SMProductShortName} component versions"
* "{SMProductShortName} feature support tables"

Ambient multi-cluster is generally available::
Ambient multi-cluster support, introduced in {SMProduct} 3.3 as a Technology Preview, is fully supported with this release. {SMProductShortName} supports the multi-primary multi-network topology, where each cluster runs its own control plane and communicates through ambient east-west gateways. With HBONE mutual TLS, workloads communicate securely across clusters. Before deploying this topology, review the documented configuration requirements and known limitations.
+
link:https://redhat.atlassian.net/browse/OSSM-14671[OSSM-14671]

IPv6 single-stack and dual-stack networking support for ambient mode is generally available::
{SMProduct} can operate on clusters with IPv6 single-stack or dual-stack networking, enabling deployment in cloud environments that require IPv6.
+
To enable dual-stack operation:
+
** Configure your Kubernetes cluster for dual-stack networking (Kubernetes 1.23 or later).
** Set the `ISTIO_DUAL_STACK` environment variable to `true` in your Istio configuration.
** Configure `pilot.ipFamilyPolicy` to `RequireDualStack` in your Istio installation.
+
Once configured, ambient proxies automatically route traffic to both IPv4 and IPv6 endpoints without requiring changes to applications. Organizations can operate a single mesh across different network types rather than maintaining separate infrastructure for each protocol.
+
link:https://redhat.atlassian.net/browse/OSSM-15863[OSSM-15863]

Security-hardened configuration for internet-facing gateway proxies::
Gateway proxies can use a new `EDGE` profile that applies security-focused settings for internet-facing deployments. The profile configures a subset of Envoy edge proxy hardening recommendations through standard {Istio} APIs, reducing the need for custom `EnvoyFilters` for these settings.
+
The `EDGE` profile provides:
+
** Defaults for Envoy listener and cluster buffers, HTTP timeouts, and downstream HTTP/2 limits.
** Enhanced header and path handling for edge-proxy deployments.
** Support for configuring a global downstream connection limit through `ProxyConfig.connectionSettings.profile`.
+
Enable the profile by setting `ProxyConfig.connectionSettings.profile` to `EDGE`. Existing gateway configurations are not affected unless the profile or individual `ConnectionSettings` fields are explicitly configured.
+
link:https://redhat.atlassian.net/browse/OSSM-11503[OSSM-11503]

Upgrade {SMProduct} two versions at a time in sidecar mode::
You can upgrade sidecar mode deployments two versions at a time with the `RevisionBased` strategy, reducing upgrade time and workload disruption. For example, upgrading directly from {SMProduct} 3.3 to 3.5 requires only one workload restart instead of multiple restarts at each intermediate version.
+
The `InPlace` strategy still upgrades {SMProduct} one version at a time.
+
link:https://redhat.atlassian.net/browse/OSSM-14856[OSSM-14856]
