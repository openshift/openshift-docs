= Creating a hosted control plane with a PublicAndPrivate topology

[role="_abstract"]
You can create a hosted cluster with `PublicAndPrivate` Kubernetes API Server topology to enable simultaneous public-internet access and private {azure-short} VNet access.

`PublicAndPrivate` topology suits regulated environments that require private control-plane networking while maintaining CI/CD pipeline access from the public internet.

[IMPORTANT]
====
The `topology` field is immutable for transitions involving `Public` topology. You can change between `PublicAndPrivate` and `Private` after cluster creation, but you cannot change to or from `Public` without creating a new cluster. Plan your topology selection carefully before provisioning.
====

.Prerequisites

* You have an {azure-short} account with permissions to create hosted clusters and the required workload identities, including the Control Plane Operator workload identity.
* You have an {azure-short} VNet in your target region.
* You have a public {azure-short} DNS zone for the externally published DNS records of the cluster.
* You have a dedicated NAT subnet in the VNet of the management cluster with `privateLinkServiceNetworkPolicies` disabled.
* The HyperShift Operator is installed with the `--private-platform {azure-short}` flag.
* When the `--private-platform` flag is set to `Azure`, the HyperShift Operator requires one of the following flags: `--azure-private-creds`, `--azure-private-secret`, or `--azure-pls-managed-identity-client-id`. The Operator uses those credentials to look up the internal load balancer and create the Private Link Service in the management cluster resource group.
* External DNS is configured on the management cluster with {azure-short} credentials and a domain filter that enables the DNS to manage records in that zone.

[IMPORTANT]
====
For private {azure-short} hosted clusters, do not set the domain of the OAuth route hostname to `<cluster_name>.<base_domain>` or to a parent domain of `<cluster_name>.<base_domain>`. The resulting Private DNS zone can shadow `*.apps` records and break console and route resolution.

For example, if you have the `hcp-two` cluster name and `example.com` base domain, do not use `hcp-two.example.com`. Use a non-overlapping domain, such as `external-dns.example.com`. This configuration cannot be corrected after cluster creation; you must re-create the cluster with a different domain.
====

.Procedure

. Create a `HostedCluster` manifest, as shown in the following example.
+
[NOTE]
====
This example shows only the topology-specific fields.
====
+
[source,yaml]
----
apiVersion: hypershift.openshift.io/v1beta1
kind: HostedCluster
metadata:
  name: <cluster_name>
  namespace: clusters
spec:
  platform:
    type: Azure
    azure:
      topology: PublicAndPrivate
      private:
        type: PrivateLink
        privateLink:
          natSubnetID: <nat_subnet_resource_id>
----
+
where:
+
--
`<cluster_name>`:: Specifies the name of your hosted cluster.
`<nat_subnet_resource_id>`:: Specifies the {azure-short} resource ID of the NAT subnet. This subnet must have `privateLinkServiceNetworkPolicies` disabled and must reside in the VNet of the management cluster. This subnet is optional; if it is omitted, the controller creates the NAT subnet in the VNet of the management cluster's internal load balancer. For more information, see "Preparing a subnet for a private hosted cluster on Azure".
--

. Apply the manifest to your cluster by entering the following command:
+
[source,terminal]
----
$ oc apply -f <manifest_file>.yaml
----

. Monitor the cluster provisioning status by entering the following command:
+
[source,terminal]
----
$ oc get hostedcluster <cluster_name> -n clusters -w
----

.Verification

* Check the `Available` condition to confirm the control plane is up by entering the following command:
+
[source,terminal]
----
$ oc get hostedcluster <cluster_name> -n clusters \
  -o jsonpath='{.status.conditions[?(@.type=="Available")]}'
----
+
For a full connectivity verification procedure, see "Verifying endpoint accessibility for a PublicAndPrivate hosted cluster on {azure-short}".
