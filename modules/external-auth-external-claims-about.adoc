= About external claims sourcing for additional identity information

[role="_abstract"]
You can configure {product-title} to fetch user identity information from external HTTP endpoints during authentication, supplementing the claims in the identity provider's JSON Web Token (JWT) with data from external services.

:FeatureName: External claims sourcing
include::snippets/technology-preview.adoc[]

When users belong to many groups or require extended identity attributes, JWT tokens can exceed HTTP header size limits, causing users to lose group-based access. External claims sourcing lets the webhook authenticator retrieve identity information directly from external endpoints, keeping the token within size limits.

Configure external claims sourcing by adding the `externalClaimsSources` field to the `oidcProviders` configuration in the `authentication.config.openshift.io/cluster` resource. You can configure up to 5 external sources per OIDC provider, with up to 16 claim mappings and 16 predicates per source.

[id="external-auth-external-claims-authentication-modes_{context}"]
== Authentication modes

Request-provided token::
Passes the user's ID token from the incoming request to the external endpoint. Use with standard OIDC `UserInfo` endpoints that accept bearer tokens.

Client credential::
Uses OAuth2 client credentials to obtain a separate access token for the external endpoint. Use with APIs that require their own authentication, such as the Microsoft Graph API.

[id="external-auth-external-claims-how-it-works_{context}"]
== How external claims sourcing works

. The Kubernetes API server receives an authentication request and forwards a `TokenReview` to the oauth-apiserver webhook.
. The webhook validates the JWT token from the identity provider.
. For each configured external claims source, the webhook concurrently requests the external endpoints.
. Common Expression Language (CEL) expressions in the `mappings` configuration extract claim values from each response.
. The webhook returns the combined identity, including both token claims and externally sourced claims, to the Kubernetes API server.

If an external source is unreachable or returns an error, its claims are excluded and authentication proceeds with a partial identity. If an externally sourced claim has the same name as a JWT token claim, the externally sourced value overwrites the token value.

[id="external-auth-external-claims-cel-expressions_{context}"]
== CEL expressions

External claims sourcing uses CEL expressions in three contexts:

URL path expression::
Constructs the request path for the external endpoint. Must return a list of strings joined with `/` to form the URL path. The `claims` variable provides access to JWT token claims.

Mapping expression::
Extracts claim values from the external endpoint response body. The `response.body` variable provides access to the parsed JSON response. Must return a string or string array value.

Predicate expression::
Controls whether an external source is queried for a given request. Must return a boolean value. The `claims` variable provides access to JWT token claims. When no predicates are configured, the source is always queried.
