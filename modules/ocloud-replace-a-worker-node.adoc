= Replace a worker node in a provisioned cluster

[role="_abstract"]
You can replace one or more worker nodes in a single update to the `ProvisioningRequest` custom resource. The O-Cloud Manager processes the replacement sequentially, removing the old nodes before provisioning new ones.

.Prerequisites

* The cluster is fully provisioned with `ClusterProvisioned=Completed` status on the `ProvisioningRequest` CR.
* Available `BareMetalHost` resources exist in the resource pool with labels matching the worker node group that you define in the `resourceSelector` field.
* No upgrade operation is in progress on the cluster.

.Procedure

. Edit the `ProvisioningRequest` CR to simultaneously remove old worker node entries and add new worker node entries in the `spec.templateParameters.clusterInstanceParameters.nodes` array by running the following command:
+
[source,terminal]
----
$ oc edit provisioningrequests.clcm.openshift.io <uuid>
----
+
where:
+
`<uuid>`:: Specifies the UUID of the `ProvisioningRequest` CR for the target cluster.
+
Remove the entries for the worker nodes you want to replace and add entries for the replacement nodes in the same edit. Because the total node count does not change, no `ConfigMap` or `ClusterTemplate` update is required. For example:
+
[source,yaml]
----
spec:
  templateParameters:
    clusterInstanceParameters:
      nodes:
        - hostName: master-1.cluster.example.com
        - hostName: master-2.cluster.example.com
        - hostName: master-3.cluster.example.com
        - hostName: worker-1.cluster.example.com
        - hostName: worker-4.cluster.example.com  # replacement node
          nodeNetwork:
            config:
              dns-resolver:
                config:
                  server:
                    - 198.51.100.1
----
+
* The old worker entry, `worker-2.cluster.example.com`, is removed and a new entry, `worker-4.cluster.example.com`, is added in the same update.

. Apply the updated `ProvisioningRequest` CR to the hub cluster, or commit it to the GitOps repository for ArgoCD synchronization.


.Verification

* Verify that the `ProvisioningRequest` CR returns to `fulfilled` after the replacement completes by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -o jsonpath='{.status.provisioningStatus.provisioningPhase}'
----
+
The `ProvisioningRequest` status shows `ClusterProvisioned=InProgress` throughout the swap, with the message reflecting which phase is active. The `provisioningPhase` returns to `fulfilled` when all replacement nodes have joined the cluster.
