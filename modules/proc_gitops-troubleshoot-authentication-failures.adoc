= Authentication and login failures

[role="_abstract"]
Troubleshoot authentication and login failures when accessing the Argo CD web console or CLI, including password issues, SSO failures, and RBAC errors.

.Prerequisites

* You have access to the {OCP} cluster.
* You have permissions to view secrets and logs in the `openshift-gitops` namespace.

.Procedure

. For default admin login failures:
+
.. Retrieve the current admin password:
+
[source,terminal]
----
$ oc get secret openshift-gitops-cluster -n openshift-gitops -o jsonpath='{.data.admin\.password}' | base64 -d ; echo
----
+
.. Verify you are using the correct password without trailing spaces or newlines.
+
.. If the password has been changed manually, reset it by deleting the secret:
+
[source,terminal]
----
$ oc delete secret openshift-gitops-cluster -n openshift-gitops
----
+
The Operator regenerates the secret with a new password.

. For SSO login failures:
+
.. Check SSO configuration in the Argo CD ConfigMap:
+
[source,terminal]
----
$ oc get cm argocd-cm -n openshift-gitops -o yaml | grep -A20 dex.config
----
+
.. Verify the SSO connector URL, client ID, and client secret are correct.
+
.. Check Dex logs for authentication errors:
+
[source,terminal]
----
$ oc logs deployment/openshift-gitops-dex-server -n openshift-gitops
----
+
.. Common SSO errors:
+
*** *Invalid redirect URI:* Update the redirect URI in your identity provider to match the Argo CD server URL.
*** *Client secret mismatch:* Verify the client secret in the `argocd-secret` matches the identity provider configuration.
*** *Clock skew:* Ensure system clocks are synchronized between Argo CD and the identity provider.

. For "Permission denied" errors after successful login:
+
.. Check user RBAC configuration:
+
[source,terminal]
----
$ oc get cm argocd-rbac-cm -n openshift-gitops -o yaml
----
+
.. Verify the user has the necessary policy:
+
*Example RBAC policy:*
[source,yaml]
----
policy.csv: |
  p, role:developer, applications, get, */*, allow
  p, role:developer, applications, sync, */*, allow
  g, user@example.com, role:developer
----
+
.. Apply updated RBAC configuration:
+
[source,terminal]
----
$ oc apply -f argocd-rbac-cm.yaml
----

. For CLI login failures:
+
.. Verify the server URL is correct:
+
[source,terminal]
----
$ argocd login $(oc get route openshift-gitops-server -n openshift-gitops -o jsonpath='{.status.ingress[0].host}')
----
+
.. For SSO login via CLI:
+
[source,terminal]
----
$ argocd login <server> --sso
----
+
.. If using self-signed certificates, add the `--insecure` flag:
+
[source,terminal]
----
$ argocd login <server> --insecure
----

. Check Argo CD server logs for authentication errors:
+
[source,terminal]
----
$ oc logs deployment/openshift-gitops-server -n openshift-gitops | grep -i auth
----

. Verify the Argo CD server is responding:
+
[source,terminal]
----
$ curl -k https://$(oc get route openshift-gitops-server -n openshift-gitops -o jsonpath='{.status.ingress[0].host}')/api/version
----
+
*Example output:*
[source,json]
----
{"Version":"v3.4.3+unknown"}
----

.Verification

Log in to the Argo CD web console or CLI successfully with valid credentials. Users should have appropriate permissions based on their assigned roles.

[NOTE]
====
After updating RBAC policies, users may need to log out and log back in for the changes to take effect.
====
