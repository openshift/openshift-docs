= The {mcpg} audit trail

[role="_abstract"]
Use router audit logs and optional Envoy access logs to inspect MCP requests, correlate request identifiers, and investigate HTTP responses.

The router provides structured audit entries with a log-safe session identifier. You can also configure JSON access logging on the `Gateway` workload by using the Istio Telemetry API. These are different log formats; router audit field definitions do not describe Envoy access log fields.

For routed requests, {mcpg} can set the following routing headers:

* `x-mcp-method`
* `x-mcp-toolname`
* `x-mcp-servername`

You can include these routing headers in Envoy access logs through `%REQ(...)%` format strings. Do not log the raw `Mcp-Session-Id` header, which can contain a bearer credential. Use `request_id` and `traceparent` for request correlation and the router audit `session` field for log-safe session correlation.

To add an identity field to Envoy access logs, configure token validation and the `x-auth-identity` success-response header in the `AuthPolicy` CRs for both broker and back-end routes. In the sample configuration, these route sets use the `mcp` and `mcps` listeners. Do not treat this header as authenticated identity for requests that have not passed authentication.

The resulting Envoy access log records request headers, HTTP response status, timing, and upstream information on the `Gateway` pod standard output (`stdout`). HTTP `200` does not prove that an MCP or tool operation succeeded.
