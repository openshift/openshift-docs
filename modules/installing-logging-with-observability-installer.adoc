= Install logging by using the ObservabilityInstaller CRD

[role="_abstract"]
You can install the {clo}, {loki-op}, and the logging UI plugin simultaneously by creating an `ObservabilityInstaller` resource with the logging capability enabled. The {coo-full} installs and configures all required components automatically.

.Prerequisites

* You have administrator permissions.
* You have installed the {oc-first}.
* You have installed the {coo-first}.
* You have access to a supported object storage provider. The supported providers are Amazon S3, Google Cloud Storage, and Azure Blob Storage.

.Procedure

. Create the `observability` namespace:
+
[source,yaml]
----
apiVersion: v1
kind: Namespace
metadata:
  name: observability
----

. Apply the `Namespace` object by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----

. Create a `Secret` object containing your object storage credentials. The following example uses Amazon S3. For Google Cloud Storage or Azure Blob Storage, see xref:../install/prepare-object-storage-for-lokistack.adoc#prepare-object-storage-for-lokistack[Preparing object storage for LokiStack] for the required secret fields.
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: logging-loki-s3
  namespace: observability
stringData:
  access_key_secret: <aws_secret_access_key>
----
+
where:

`metadata.name`:: Specify a name for the secret. You reference this name in the `ObservabilityInstaller` resource.
`metadata.namespace`:: You must create the secret in the `observability` namespace.
`stringData.access_key_secret`:: Specify the AWS secret access key for the S3 bucket.

. Apply the `Secret` object by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----

. Create an `ObservabilityInstaller` resource with the logging capability enabled:
+
[source,yaml]
----
apiVersion: observability.openshift.io/v1alpha1
kind: ObservabilityInstaller
metadata:
  name: logging
  namespace: observability
spec:
  capabilities:
    logging:
      enabled: true
      lokiStack:
        size: 1x.extra-small
        storageClassName: <storage_class>
        objectStorage:
          s3:
            bucket: <bucket_name>
            endpoint: <endpoint_url>
            region: <aws_region>
            accessKeyID: <aws_access_key_id>
            accessKeySecret:
              name: logging-loki-s3
              key: access_key_secret
----
+
where:

`spec.capabilities.logging.enabled`:: Set to `true` to enable the logging capability.
`spec.capabilities.logging.lokiStack.size`:: Specify the deployment size for the `LokiStack` instance. Valid values are `1x.demo`, `1x.pico`, `1x.extra-small`, `1x.small`, and `1x.medium`.
`spec.capabilities.logging.lokiStack.storageClassName`:: Specify the name of the storage class to use for `LokiStack` persistent volume claims.
`spec.capabilities.logging.lokiStack.objectStorage.s3.bucket`:: Specify the name of the S3 bucket.
`spec.capabilities.logging.lokiStack.objectStorage.s3.endpoint`:: Specify the S3 endpoint URL, for example `+https://s3.us-east-1.amazonaws.com+`.
`spec.capabilities.logging.lokiStack.objectStorage.s3.region`:: Specify the AWS region of the bucket, for example `us-east-1`.
`spec.capabilities.logging.lokiStack.objectStorage.s3.accessKeyID`:: Specify the AWS access key ID.
`spec.capabilities.logging.lokiStack.objectStorage.s3.accessKeySecret.name`:: Specify the name of the secret that has the AWS secret access key.
`spec.capabilities.logging.lokiStack.objectStorage.s3.accessKeySecret.key`:: Specify the key within the secret that holds the AWS secret access key value.

. Apply the `ObservabilityInstaller` object by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----

.Verification

. Check the logging capability status by running the following command:
+
[source,terminal]
----
$ oc get obsinstall logging -n observability
----
+
The `LOGGING` column shows `Ready` when all logging components are running.

. Verify that the `LokiStack` instance is ready by running the following command:
+
[source,terminal]
----
$ oc get lokistack -n observability
----

. Verify that the `ClusterLogForwarder` is running by running the following command:
+
[source,terminal]
----
$ oc get clusterlogforwarder -n observability
----

[NOTE]
====
If components do not reach a ready state, check that the secret name and namespace match the values in the `ObservabilityInstaller` resource, and that the object storage credentials are correct. Inspect events with `oc describe obsinstall logging -n observability` for details.
====
