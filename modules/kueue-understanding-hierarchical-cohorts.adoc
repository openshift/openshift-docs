= Hierarchical cohorts

[role="_abstract"]
Use hierarchical cohorts to share unused quota between teams and control how much each group can borrow or lend. You can organize cluster queues into a hierarchy and add shared quota at different levels.

A cohort tree has cohorts and cluster queues. Each cohort is a cluster-scoped `Cohort` object that organizes quota but does not accept workloads. Cluster queues are the final level in a cohort tree and accept workloads.

A root cohort does not have a `spec.parentName` field. In a child cohort, the `spec.parentName` field identifies the parent cohort. To move a cohort, change its `spec.parentName` field. Moving a cohort also moves all cohorts and cluster queues below it to the new parent.

You can share unused quota only within the same cohort tree. To add shared quota, define the `nominalQuota` field in the `spec.resourceGroups` field of the `Cohort` object. This quota supplements the nominal quota from cluster queues.

For each resource in a child cohort, you can set two limits in the `spec.resourceGroups` field:

`borrowingLimit`:: Restricts how much quota a child cohort and the cohorts and cluster queues below it can borrow through its parent.
`lendingLimit`:: Restricts how much unused quota a child cohort and the cohorts and cluster queues below it can lend through its parent.

Set either limit to `0` to prevent that type of sharing. Omit a limit to leave that type of sharing unrestricted for the resource.

The following example assigns engineering and research departments to separate cohorts. The cohorts share quota from a root cohort:

[source,text]
----
shared-resources
├── engineering
│   └── frontend-queue
└── research
    └── ml-queue
----

The `reclaimWithinCohort` and `borrowWithinCohort` preemption policies on a cluster queue apply across the cohort tree.

With fair sharing enabled, you can set the `spec.fairSharing.weight` field on each `Cohort` object. These weights give cohorts with the same parent, and the cluster queues below them, different shares of common resources.

[WARNING]
====
Do not create a cycle in a cohort hierarchy. A cycle disables all cohorts and cluster queues in the hierarchy and stops admission of new workloads. Remove the cycle to restore admission.

Deleting a cohort immediately removes its quota and its parent connection. Workloads that {kueue-name} already admitted continue to run, but new workloads cannot borrow through the removed connection.
====
