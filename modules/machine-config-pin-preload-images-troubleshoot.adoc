= Troubleshooting pinned images

[role="_abstract"]
Use the `MachineConfigNode` status, Machine Config Operator (MCO) logs, and on-node CRI-O configuration to diagnose pinned image failures.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.

.Procedure

. Confirm that the `PinnedImageSet` exists and targets the expected pool:
+
[source,terminal]
----
$ oc get pinnedimagesets
$ oc get pinnedimageset <pinned_image_set_name> -o yaml
----
+
Verify that `metadata.labels` includes `machineconfiguration.openshift.io/role` for the intended machine config pool, such as `worker`, `master`, or a custom pool role.

. Check whether the set is associated with nodes in that pool:
+
[source,terminal]
----
$ oc get machineconfignode <node_name> -o jsonpath='{.status.pinnedImageSets}{"\n"}'
$ oc describe machineconfignode <node_name>
----
+
If `status.pinnedImageSets` does not list your object, the label does not match a pool that includes the node, or the MCO has not reconciled the object yet.

. Inspect degraded conditions and error messages:
+
[source,terminal]
----
$ oc get machineconfignode <node_name> -o yaml | grep -A20 'PinnedImageSets'
----
+
Common signals include `PinnedImageSetsDegraded` with reason `PrefetchFailed`, and `lastFailedGenerationError` messages such as a failed `podman manifest inspect`.

. Verify that the node can inspect and pull the image:
+
[source,terminal]
----
$ oc debug node/<node_name> -- chroot /host podman manifest inspect <registry>/<repository>@sha256:<digest>
----
+
If inspection fails with authorization errors, update the cluster pull secret or registry credentials that the node uses. If inspection fails because the registry is unreachable, fix networking or pin images from a local mirror.

. Check free space on the node container storage:
+
[source,terminal]
----
$ oc debug node/<node_name> -- chroot /host df -h /var/lib/containers
----
+
If the filesystem is full, free space or reduce the pinned image list, then re-apply the `PinnedImageSet`.

. Confirm that CRI-O received the pinned image configuration:
+
[source,terminal]
----
$ oc debug node/<node_name> -- chroot /host cat /etc/crio/crio.conf.d/50-pinned-images
----
+
If the file is missing, the pin did not complete for that node. Recheck MCO and machine config daemon logs:
+
[source,terminal]
----
$ oc logs -n openshift-machine-config-operator deploy/machine-config-controller --tail=200 | grep -i pinned
$ oc logs -n openshift-machine-config-operator -l k8s-app=machine-config-daemon --tail=200 | grep -i pinned
----

.Additional troubleshooting tips

* On single-node {product-title} clusters, target the `master` machine config pool. The `worker` pool may have no member nodes.
* Image references must use digests. Tag-only references are rejected or never pinned.
* A successful manual `crictl pull` does not mean pinning succeeded. Pinning also requires the MCO to write `/etc/crio/crio.conf.d/50-pinned-images` and report success on the `MachineConfigNode`.
* For low-bandwidth sites, allow more time for the first pull and prefer smaller per-pool image sets.
