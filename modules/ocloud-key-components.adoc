= Key components

[role="_abstract"]
The O-Cloud Manager introduces several custom resources (CRs) that work together to manage the cluster lifecycle. You interact with these resources when configuring templates, provisioning clusters, and managing hardware.

`ClusterTemplate` CR:: An immutable blueprint that defines the cluster topology, hardware defaults, and configuration policies for a class of clusters. Each `ClusterTemplate` references `ConfigMap` resources that supply cluster installation defaults and policy template defaults. These defaults are merged with site-specific values at provisioning time.

`ProvisioningRequest` CR:: A mutable resource that represents the desired state of a single managed cluster. Creating a `ProvisioningRequest` triggers provisioning; updating it drives Day-2 operations such as configuration changes, scaling, and upgrades. Each `ProvisioningRequest` references a `ClusterTemplate` and supplies site-specific parameters.

`HardwareProfile` CR:: An optional resource that defines target firmware levels and BIOS settings for a class of servers. When specified in a `ClusterTemplate`, the O-Cloud Manager applies the hardware profile during initial provisioning or as a Day-2 update.

`BareMetalHost` CR:: Represents a physical server registered in the hub cluster inventory. Each `BareMetalHost` includes metadata labels used for resource selection and a BMC connection that the Bare Metal Operator uses for power management and hardware inspection.

`HardwareData` CR:: Auto-populated by the Bare Metal Operator after inspecting a `BareMetalHost`. Contains detailed hardware characteristics including CPU architecture, thread count, memory size, NIC speed and count, and storage device capacity. Used by the O-Cloud Manager for hardware-based resource selection.

`ResourcePool` CR:: Groups bare-metal resources at a site for allocation. When processing a `ProvisioningRequest`, the O-Cloud Manager selects hosts from the appropriate resource pool based on the resource selectors defined in the `ClusterTemplate`.

`Location` and `OCloudSite` CRs:: Represent the infrastructure hierarchy. A `Location` identifies a geographic place where infrastructure is deployed. An `OCloudSite` represents a logical site at a given location and references both a `Location` and one or more `ResourcePool` resources.
