= Configure {mcpg} listeners

[role="_abstract"]
Connect your {mcpg} to your agentic AI systems by adding public and internal listeners to your `Gateway` custom resource (CR).

The `mcp` listener handles public MCP client traffic. The `mcps` listener handles traffic for registered MCP servers with `*.mcp.local` hostnames. Both HTTP listeners must use the same port so the router can route `tools/call` requests to the backend server.

For HTTPS, use one wildcard listener for both public and backend traffic. The public hostname and all backend `HTTPRoute` hostnames must match that wildcard, because `tools/call` routing stays within the same listener.

.Prerequisites

* You are logged in to your {ocp} cluster.
* You created a gateway custom resource (CR).
* You installed {mcpg}.
* You configured a gateway API provider.

.Procedure

. If the `mcp` and `mcps` listeners are not already present, add them to your `Gateway` CR by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc patch gateway _<mcp_gateway>_ -n _<gateway_namespace>_ --type='json' -p='[
  {
    "op": "add",
    "path": "/spec/listeners/-",
    "value": {
      "name": "mcp",
      "hostname": "_<mcp.apps.openshift.example.com>_",
      "port": 8080,
      "protocol": "HTTP",
      "allowedRoutes": {
        "namespaces": {
          "from": "All"
        }
      }
    }
  },
  {
    "op": "add",
    "path": "/spec/listeners/-",
    "value": {
      "name": "mcps",
      "hostname": "*.mcp.local",
      "port": 8080,
      "protocol": "HTTP",
      "allowedRoutes": {
        "namespaces": {
          "from": "All"
        }
      }
    }
  }
]'
----
+
* Replace `_<mcp_gateway>_` with the name of your {mcpg}.
* Replace `_<gateway_namespace>_` with the namespace where your `Gateway` object is applied.
* Replace `_<mcp.apps.openshift.example.com>_` with your public MCP hostname.
* The `*.mcp.local` hostname matches the internal hostnames used by MCP server `HTTPRoute` CRs.
* If you created the `Gateway` object by using the example in the preceding procedure, these listeners are already present. Skip the patch and continue with verification.

. Verify that both listeners are working by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc get gateway _<mcp_gateway>_ -n _<gateway_namespace>_ -o yaml
----
+
* Replace `_<mcp_gateway>_` with the name of your {mcpg} deployment.
* Replace `_<gateway_namespace>_` with the namespace where your `Gateway` object is applied.
* The conditions `Accepted: True` and `Programmed: True` are expected in the `status` of the output.

.Verification

* Check the status your listeners and related objects by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc describe gateway _<mcp_gateway>_ -n _<gateway_namespace>_
----
+
** Replace `_<mcp_gateway>_` with the name of your {mcpg} deployment.
** Replace `_<gateway_namespace>_` with the namespace where your `Gateway` object is applied.
+
