= About the resource override object fields

[role="_abstract"]
You can review `ResourceOverride` spec and status fields when you author or inspect a namespaced override.

Ratio fields use the same semantics as the cluster-scoped `ClusterResourceOverride` object, but are located under the `spec.podResourceOverride` path.

Use the following fields as needed when creating a `ResourceOverride` object:

.ResourceOverride spec fields
[cols="2,1,3,1", options="header"]
|===
| Field
| Value
| Description
| Default

| `memoryRequestToLimitPercent`
| Integer 1-100
| If a container memory limit is specified or defaulted, the memory request is overridden to this percentage of the limit.
| `50`

| `cpuRequestToLimitPercent`
| Integer 1-100
| If a container CPU limit is specified or defaulted, the CPU request is overridden to this percentage of the limit.
| `25`

| `limitCPUToMemoryPercent`
| Integer
| If a container memory limit is specified or defaulted, the CPU limit is overridden to a percentage of the memory limit.
Scaling 1 Gi of RAM at 100 percent is equal to 1 CPU core.
This field is processed before CPU request overrides.
| `200`

| `cpuRequestToRequestPercent`
| Integer 1-100
| Sets the CPU request to this percentage of the original CPU request: `original_cpu_request × percent / 100`. The field is applied last and uses the original request from before other overrides.
| N/A

| `podSelector`
| Label selector
| Optional.
Selects pods in the `ResourceOverride` namespace by `metadata.labels`.
If you omit the field or set `podSelector: {}`, the object matches every pod in the namespace.
| N/A
|===

After the `ResourceOverride` object is created, you can view the status of the object in the object output. 

.ResourceOverride status conditions
[cols="1,1,2", options="header"]
|===
| Type
| Reason
| Description

| `ValidationFailure`
| `InvalidParameters`
| If `True`, the spec has an invalid ratio or an invalid `podSelector` field. After the controller reconciles the object, this condition is present. A valid spec has status `False`.

| `Ignored`
| `NamespaceNotOptedIn`
| If `True`, the namespace does not have the `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled=true` label. When the namespace is opted in, this condition has status `False`.
|===

The controller writes `status.conditions` after it reconciles the object.

.Example status conditions for a valid spec in an opted-in namespace
[source,yaml]
----
apiVersion: autoscaling.openshift.io/v1
kind: ResourceOverride
metadata:
  name: example
  namespace: my-namespace
# ...
status:
  conditions:
  - status: "False"
    type: Ignored
  - status: "False"
    type: ValidationFailure
# ...
----

.Example status conditions when `ValidationFailure` or `Ignored` is `True`
[source,yaml]
----
apiVersion: autoscaling.openshift.io/v1
kind: ResourceOverride
metadata:
  name: example
  namespace: my-namespace
# ...
status:
  conditions:
  - reason: NamespaceNotOptedIn
    status: "True"
    type: Ignored
  - reason: InvalidParameters
    status: "True"
    type: ValidationFailure
# ...
----
