= ResourceOverride custom resource fields

[role="_abstract"]
A `ResourceOverride` custom resource (CR) sets per-project override ratios. Ratio fields use the same values as the cluster-wide `ClusterResourceOverride` object, and they are located under `spec.podResourceOverride`.

On a `ClusterResourceOverride` object, the same ratio fields are under `spec.podResourceOverride.spec`.

.`ResourceOverride` spec fields
[cols="2,3",options="header"]
|===
|Field
|Description

|`spec.podResourceOverride.memoryRequestToLimitPercent`
|If a container memory limit is specified or defaulted, the memory request is overridden to this percentage of the limit, between 1-100. If you omit this field, the memory request is not overridden.

|`spec.podResourceOverride.cpuRequestToLimitPercent`
|If a container CPU limit is specified or defaulted, the CPU request is overridden to this percentage of the limit, between 1-100. If you omit this field, the CPU request is not overridden from the CPU limit.

|`spec.podResourceOverride.limitCPUToMemoryPercent`
|If a container memory limit is specified or defaulted, the CPU limit is overridden to a percentage of the memory limit. Scaling 1Gi of RAM at 100 percent is equal to 1 CPU core. This field is processed before CPU request overrides. If you omit this field, the CPU limit is not overridden.

|`spec.podResourceOverride.cpuRequestToRequestPercent`
|Sets the CPU request to this percentage of the original CPU request, between 1-100: `original_cpu_request × percent / 100`. Omit this field to leave request-relative CPU override disabled. This field has no default. A CPU limit is not required. This field is applied last and uses the original CPU request, including when `cpuRequestToLimitPercent` is also set.

|`spec.podSelector`
|Optional label selector for pods in the `ResourceOverride` namespace. If you omit the field or set `podSelector: {}`, the object matches every pod in the namespace.
|===

After the object is created, the controller writes `status.conditions`.

.`ResourceOverride` status conditions
[cols="1,1,2",options="header"]
|===
|Type
|Reason
|Description

|`ValidationFailure`
|`InvalidParameters`
|If `True`, the spec has an invalid ratio or an invalid `podSelector` field. A valid spec has status `False`.

|`Ignored`
|`NamespaceNotOptedIn`
|If `True`, the namespace does not have the `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled=true` label. When the namespace is opted in, this condition has status `False`.
|===

.Example status conditions for a valid object in an opted-in namespace
[source,yaml]
----
apiVersion: autoscaling.openshift.io/v1
kind: ResourceOverride
metadata:
  name: example
  namespace: my-namespace
# ...
status:
  conditions:
  - status: "False"
    type: Ignored
  - status: "False"
    type: ValidationFailure
# ...
----
