= Reverting fencing tuning to defaults

[role="_abstract"]
You can restore fencing parameters to their default values when removing custom tuning from your two-node {product-title} cluster. This ensures all changes are properly reverted before deletion.


[IMPORTANT]
====
Do not run `oc delete mc 99-fencing-parameter-tuning` without reverting first. Deleting the `MachineConfig` removes the tuning service but does not undo the Pacemaker changes. The tuned values remain active in the cluster configuration.
====

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have the `oc` CLI tool installed.
* The fencing parameter tuning `MachineConfig` is currently applied.

.Procedure

. Run the `apply-fencing-tuning.sh` script with the `--revert` flag by running the following command:
+
[source,terminal]
----
$ ./apply-fencing-tuning.sh --revert
----
+
For more information about the content of the `apply-fencing-tuning.sh` script, see "Applying a fencing tuning preset".

. Wait for the Machine Config Operator (MCO) to roll out the default values to both control plane nodes by running the following command:
+
[source,terminal]
----
$ oc get mcp master -w
----
+
Wait until `UPDATED` is `True` and `UPDATING` is `False`.

. After the rollout completes, delete the `MachineConfig`resource by running the following command:
+
[source,terminal]
----
$ oc delete mc 99-fencing-parameter-tuning
----

. Wait for the MCO to roll out the deletion:
+
[source,terminal]
----
$ oc get mcp master -w
----

.Verification

. Verify that the Corosync token is back to the default value by running the following command:
+
[source,terminal]
----
$ oc debug node/<master-node> -- chroot /host pcs cluster config show | grep token
----
+
The output shows `token: 3000`.

. Verify that both nodes are in the `Ready` state by running the following command:
+
[source,terminal]
----
$ oc get nodes
----
