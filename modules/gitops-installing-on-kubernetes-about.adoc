= About installing {gitops-title} on non-OpenShift Kubernetes platforms

[role="_abstract"]
You can install the {gitops-title} Operator on non-OpenShift Kubernetes platforms such as Amazon Elastic Kubernetes Service (EKS), Google Kubernetes Engine (GKE), Azure Kubernetes Service (AKS), or vanilla Kubernetes clusters. Red Hat delivers the {gitops-title} Operator as an OCI Helm chart published to `registry.redhat.io`. The {gitops-title} Operator uses the same container images and code that runs on {OCP}.

The {gitops-title} Operator detects whether it is running on an {OCP} or non-OpenShift Kubernetes platform and adjusts its behavior accordingly. On non-OpenShift platforms, the Operator uses standard Kubernetes resources instead of OpenShift-specific resources.

*Platform behavior on non-OpenShift Kubernetes*

The {gitops-title} Operator detects the platform type at startup and adjusts its behavior:

* *API detection*: Detects non-OpenShift environments and skips OpenShift-specific controllers such as `ClusterVersion`, OpenShift Routes, and console plugins.
* *Ingress and networking*: Uses standard Kubernetes Ingress or LoadBalancer resources for external access to Argo CD instead of OpenShift Routes.
* *RBAC and security*: Uses standard Kubernetes RBAC and Pod Security Standards instead of Security Context Constraints (SCCs).
* *Authentication*: Uses standard OIDC provider integration for single sign-on authentication instead of OpenShift integrated OAuth.
