= Pre-upgrade checklist

[role="_abstract"]
Complete this checklist before upgrading {gitops-title} to ensure a smooth upgrade process and minimize the risk of disruption.

*Review release notes*

* [ ] Read the release notes for the target version
* [ ] Identify breaking changes or deprecations
* [ ] Review new features and configuration changes
* [ ] Check compatibility matrix for {OCP} version support
* [ ] Verify component version updates (Argo CD, Helm, Kustomize)

*Backup configurations*

* [ ] Export all Argo CD custom resources:
+
[source,terminal]
----
$ oc get argocd -A -o yaml > argocd-backup.yaml
$ oc get applications -A -o yaml > applications-backup.yaml
$ oc get appprojects -A -o yaml > appprojects-backup.yaml
$ oc get applicationsets -A -o yaml > applicationsets-backup.yaml
----

* [ ] Backup Argo CD ConfigMaps:
+
[source,terminal]
----
$ oc get cm argocd-cm -n openshift-gitops -o yaml > argocd-cm-backup.yaml
$ oc get cm argocd-rbac-cm -n openshift-gitops -o yaml > argocd-rbac-cm-backup.yaml
$ oc get cm argocd-ssh-known-hosts-cm -n openshift-gitops -o yaml > argocd-ssh-known-hosts-cm-backup.yaml
$ oc get cm argocd-tls-certs-cm -n openshift-gitops -o yaml > argocd-tls-certs-cm-backup.yaml
----

* [ ] Backup Argo CD Secrets (excluding sensitive data):
+
[source,terminal]
----
$ oc get secrets -n openshift-gitops --field-selector type=Opaque -o yaml > argocd-secrets-backup.yaml
----

* [ ] Document custom configurations and integrations

*Verify current state*

* [ ] Confirm all applications are in Synced and Healthy state:
+
[source,terminal]
----
$ argocd app list
----

* [ ] Verify no pending synchronizations or stuck operations
* [ ] Check that all Argo CD pods are running:
+
[source,terminal]
----
$ oc get pods -n openshift-gitops
----

* [ ] Review Argo CD server logs for existing errors:
+
[source,terminal]
----
$ oc logs deployment/openshift-gitops-server -n openshift-gitops --tail=100
----

* [ ] Verify cluster resources are within capacity (CPU, memory, storage)

*Test in non-production*

* [ ] Perform the upgrade in a non-production environment first
* [ ] Test all critical applications sync successfully after upgrade
* [ ] Verify custom scripts, hooks, and integrations still work
* [ ] Validate RBAC policies and authentication after upgrade
* [ ] Document any issues encountered and their resolutions

*Plan maintenance window*

* [ ] Schedule the upgrade during a maintenance window
* [ ] Notify stakeholders of planned downtime
* [ ] Plan for rollback if the upgrade fails
* [ ] Ensure sufficient time for testing after upgrade
* [ ] Have support resources available during the window

*Check dependencies*

* [ ] Verify {OCP} cluster version is supported by target {gitops-title} version
* [ ] Check that custom resource definitions (CRDs) are compatible
* [ ] Verify external integrations (SSO, Vault, monitoring) support the new version
* [ ] Confirm Git repository access and credentials are current
* [ ] Test network connectivity to external dependencies

*Prepare rollback plan*

* [ ] Document current Operator version:
+
[source,terminal]
----
$ oc get csv -n openshift-gitops-operator
----

* [ ] Understand rollback limitations (Operator upgrades are generally not reversible)
* [ ] Prepare to redeploy applications from Git if needed
* [ ] Document steps to restore from backups
* [ ] Identify critical applications that must be restored first

*Communication*

* [ ] Notify development teams of the upgrade schedule
* [ ] Inform users about potential service disruption
* [ ] Prepare communication templates for upgrade status updates
* [ ] Establish escalation procedures for upgrade issues
* [ ] Document contact information for support resources

*Post-upgrade validation*

* [ ] Plan to verify all applications sync successfully
* [ ] Prepare smoke tests for critical applications
* [ ] Schedule time to review logs and metrics after upgrade
* [ ] Plan to monitor application health for 24-48 hours
* [ ] Document lessons learned for future upgrades

[TIP]
====
Create a checklist document specific to your environment and update it after each upgrade with lessons learned and environment-specific steps.
====
