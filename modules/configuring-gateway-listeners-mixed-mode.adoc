= Configure mixed-mode listeners on a shared port

[role="_abstract"]
To serve terminated HTTPS traffic and TLS passthrough on the same port, you can configure two listeners with distinct hostnames. One listener uses `HTTPS` with `tls.mode: Terminate` for `HTTPRoute` custom resources (CRs) and decrypts at the gateway. The other uses `TLS` with `tls.mode: Passthrough` for `TLSRoute` CRs and forwards the encrypted connection to a backend that terminates TLS. The gateway matches the Server Name Indication (SNI) hostname to select the listener.

[IMPORTANT]
====
Same-port mixed mode requires an implementation that supports both `TLSRoute` passthrough and a `TLS` passthrough listener plus an `HTTPS` terminate listener on the same port. The `openshift-default` `GatewayClass` object does not support passthrough or mixed-mode listeners. Use a `GatewayClass` object whose implementation supports that combination, such as {SMProductName}.
====

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the {oc-first}.
* You have a `GatewayClass` CR whose implementation supports `TLSRoute` passthrough and mixed-mode listeners on the same port.
* You have a TLS certificate `Secret` for the terminated HTTPS listener.

.Procedure

. Create a `Gateway` CR that defines both listeners on port `443`. Save the file as `gateway-mixed-mode.yaml`:
+
--
The following example uses distinct hostnames so that the listeners do not conflict.

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: <shared_port_gateway>
  namespace: <gateway_namespace>
spec:
  gatewayClassName: <gatewayclass_name>
  listeners:
  - name: passthrough-listener
    hostname: "db.<example_domain.tld>"
    protocol: TLS
    port: 443
    tls:
      mode: Passthrough
    allowedRoutes:
      kinds:
      - kind: TLSRoute
  - name: terminate-listener
    hostname: "app.<example_domain.tld>"
    protocol: HTTPS
    port: 443
    tls:
      mode: Terminate
      certificateRefs:
      - name: <gateway_tls_cert>
        kind: Secret
    allowedRoutes:
      kinds:
      - kind: HTTPRoute
----

where:

`gatewayClassName`:: must name a `GatewayClass` object whose implementation supports both `TLSRoute` passthrough and mixed-mode listeners on the same port. Do not set this field to `openshift-default`.
`passthrough-listener`:: matches the SNI hostname, selects an attached `TLSRoute` CR, and forwards the encrypted connection to that route's backend service. Do not set `certificateRefs` on that listener.
`terminate-listener`:: terminates TLS for `HTTPRoute` CRs. You must set `certificateRefs`.
--

. Apply the `Gateway` CR by running the following command:
+
[source,terminal]
----
$ oc apply -f gateway-mixed-mode.yaml
----
