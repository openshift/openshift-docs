= Configure mixed-mode listeners on a shared port

[role="_abstract"]
To serve terminated HTTPS traffic and TLS passthrough on the same port, you can configure two listeners with distinct hostnames. One listener uses `HTTPS` with `tls.mode: Terminate` for `HTTPRoute` custom resources (CRs). The other uses `TLS` with `tls.mode: Passthrough` for `TLSRoute` CRs. {product-title} routes can mix edge and passthrough on port `443` by using Server Name Indication (SNI). This Gateway API analogue does not apply to the `openshift-default` GatewayClass.

[IMPORTANT]
====
Same-port mixed mode requires a Gateway API implementation that supports TLSRoute passthrough, such as {SMProductName}. The `openshift-default` GatewayClass does not support passthrough or mixed-mode listeners.
====

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the {oc-first}.
* You have a `GatewayClass` CR whose implementation supports TLSRoute passthrough. Do not use `openshift-default`.
* You have a TLS certificate `Secret` for the terminated HTTPS listener.

.Procedure

. Create or edit a `Gateway` CR that defines both listeners on port `443`. Save the file as `gateway-mixed-mode.yaml`:
+
--
The following example uses distinct hostnames so the listeners do not conflict. For conflict rules, see "Understand listener routing conflicts".

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: <shared_port_gateway>
  namespace: <gateway_namespace>
spec:
  gatewayClassName: <gatewayclass_name>
  listeners:
  - name: passthrough-listener
    hostname: "db.<example_domain.tld>"
    protocol: TLS
    port: 443
    tls:
      mode: Passthrough
    allowedRoutes:
      kinds:
      - kind: TLSRoute
  - name: terminate-listener
    hostname: "app.<example_domain.tld>"
    protocol: HTTPS
    port: 443
    tls:
      mode: Terminate
      certificateRefs:
      - name: <gateway_tls_cert>
        kind: Secret
    allowedRoutes:
      kinds:
      - kind: HTTPRoute
----
+
* `gatewayClassName` must name a GatewayClass whose implementation supports TLSRoute passthrough. Do not set this field to `openshift-default`.
* `passthrough-listener` forwards encrypted TLS to a `TLSRoute` CR. Do not set `certificateRefs` on that listener.
* `terminate-listener` terminates TLS for `HTTPRoute` CRs. You must set `certificateRefs`.
--

. Apply the `Gateway` CR by running the following command:
+
[source,terminal]
----
$ oc apply -f gateway-mixed-mode.yaml
----
