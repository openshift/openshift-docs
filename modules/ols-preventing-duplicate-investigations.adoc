= Prevent duplicate investigations

[role="_abstract"]
To avoid running duplicate investigations, which consume cluster resources and LLM tokens, the adapter provides the following settings in the `alerts-adapter-config` ConfigMap:

`preRunDelay`:: The minimum time an alert must be firing before the adapter starts an investigation. This delay filters out transient alerts that might resolve on their own. The default is `0s`, which starts an investigation as soon as an alert is detected.
`postRunDelay`:: The time to wait after an investigation finishes before the adapter investigates the same firing alert again. This delay prevents repeated analysis of an alert that is still firing after the `AgenticRun` ended. The default is `1h`. Set the value to `0s` to disable the delay.
`deduplication.ignoredLabels`:: The alert labels that the adapter excludes when it determines whether two alerts represent the same problem. Excluding labels that change between occurrences, such as `pod`, prevents a restarted workload from triggering a new investigation for a problem that is already under investigation. The default value is `pod`, `instance`, `endpoint`, and `uid`.

The following example sets each value:

[source,yaml]
----
preRunDelay: 2m
postRunDelay: 1h
deduplication:
  ignoredLabels:
    - pod
    - instance
    - endpoint
    - uid
----
