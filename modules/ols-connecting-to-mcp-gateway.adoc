= Connecting {ols-long} to an MCP gateway

[role="_abstract"]
Connect {ols-long} to a Model Context Protocol (MCP) gateway so that all MCP tool calls route through a single, centrally managed endpoint instead of connecting to each MCP server individually.

An MCP gateway aggregates multiple MCP servers behind one endpoint. When you connect {ols-long} to the gateway, the Service discovers and calls tools from all of the MCP servers that are registered behind the gateway through a single connection. Routing tool calls through the gateway allows platform teams to apply consistent authentication, authorization, and policy enforcement to every tool call, without changing the {ols-long} configuration for each MCP server.

From the perspective of {ols-long}, the gateway is a single MCP server. You add the gateway endpoint to the `mcpServers` specification and, if the gateway hosts more than one virtual MCP server, select the virtual MCP server that you want {ols-long} to use.

:FeatureName: The MCP server feature
include::snippets/technology-preview.adoc[]
:FeatureName!:

.Prerequisites

* You have installed the {ols-long} Operator.

* You have configured a large language model provider.

* You have configured the `OLSConfig` CR file, which automatically deploys the {ols-long} Service.

* An MCP gateway is deployed and reachable from the cluster, and the MCP servers that you want {ols-long} to use are registered behind it.

* You have the gateway endpoint URL. The gateway typically exposes a Streamable HTTP endpoint at the `/mcp` path.

* If you select a virtual MCP server by using a header value, you have created a secret that contains the header value. Ensure that the secret has the key name `header`.

.Procedure

. Edit the {ols-long} `OLSConfig` custom resource (CR) file by running the following command:
+
[source,terminal]
----
$ oc edit olsconfig cluster
----

. Add `MCPServer` to the `spec.featureGates` specification and add the gateway endpoint to the `spec.mcpServers` specification. This basic setup uses only the root gateway endpoint and does not select a virtual MCP server:
+
[source,yaml]
----
apiVersion: ols.openshift.io/v1alpha1
kind: OLSConfig
metadata:
  name: cluster
spec:
  featureGates:
    - MCPServer
  mcpServers:
    - name: mcp-gateway
      url: https://<gateway_address>:8080/mcp
      timeout: 30
      headers:
        - name: Authorization
          valueFrom:
            type: kubernetes
----
+
where
+
`spec.featureGates`:: Specifies the MCP server functionality on the {ols-long} pod.
`spec.mcpServers.name`:: Specifies the name of the gateway connection.
`spec.mcpServers.url`:: Specifies the gateway endpoint URL. Use the gateway `/mcp` path for the Streamable HTTP transport.
`spec.mcpServers.timeout`:: Specifies the time that the gateway has to respond to a query. If the Service does not receive a response within the time specified, the connection times out. In this example, the timeout is 30 seconds.
`spec.mcpServers.headers`:: Specifies the headers that {ols-long} sends to the gateway as an array of structured objects.
`Authorization` header:: Authenticates {ols-long} to the gateway. The `kubernetes` type provides the user's bearer token so that the gateway can authorize the request.

. Optional: If the gateway hosts more than one virtual MCP server, add the `X-Mcp-Virtualserver` header to select the virtual MCP server that you want {ols-long} to use. In this example, the built-in cluster introspection MCP server remains enabled because `spec.ols.introspectionEnabled` is `true` by default:
+
[source,yaml]
----
apiVersion: ols.openshift.io/v1alpha1
kind: OLSConfig
metadata:
  name: cluster
spec:
  featureGates:
    - MCPServer
  ols:
    introspectionEnabled: true
  mcpServers:
    - name: mcp-gateway
      url: https://<gateway_address>:8080/mcp
      timeout: 30
      headers:
        - name: Authorization
          valueFrom:
            type: kubernetes
        - name: X-Mcp-Virtualserver
          valueFrom:
            type: secret
            secretRef:
              name: <virtual_server_secret>
----
+
where
+
`spec.ols.introspectionEnabled`:: Enables the built-in cluster introspection MCP server and is `true` by default. Keep this field set to `true` to continue using the built-in introspection server alongside the gateway.
`X-Mcp-Virtualserver` header:: Selects the virtual MCP server on the gateway that {ols-long} uses. The `secret` type reads the header value from the referenced secret.
`spec.mcpServers.headers.valueFrom.secretRef.name`:: Specifies the name of the secret that contains the header value. Ensure that the secret has the key name `header`.

. Optional: If an {product-title} MCP server that is registered behind the gateway provides cluster introspection, you can replace the built-in introspection server with the introspection MCP server on the gateway. Set `spec.ols.introspectionEnabled` to `false` so that {ols-long} does not also connect to the built-in introspection server, and add the `X-Mcp-Virtualserver` header to select the introspection MCP server on the gateway:
+
[source,yaml]
----
apiVersion: ols.openshift.io/v1alpha1
kind: OLSConfig
metadata:
  name: cluster
spec:
  featureGates:
    - MCPServer
  ols:
    introspectionEnabled: false
  mcpServers:
    - name: mcp-gateway
      url: https://<gateway_address>:8080/mcp
      timeout: 30
      headers:
        - name: Authorization
          valueFrom:
            type: kubernetes
        - name: X-Mcp-Virtualserver
          valueFrom:
            type: secret
            secretRef:
              name: <introspection_server_secret>
----
+
where
+
`spec.ols.introspectionEnabled`:: Set this field to `false` to route cluster introspection through the gateway instead of the built-in MCP server. This setting prevents {ols-long} from connecting to the built-in introspection server in addition to the gateway.
`X-Mcp-Virtualserver` header:: Selects the introspection MCP server on the gateway that replaces the built-in introspection server. The `secret` type reads the header value from the referenced secret.
`spec.mcpServers.headers.valueFrom.secretRef.name`:: Specifies the name of the secret that contains the header value. Ensure that the secret has the key name `header`.

. Save and close the text editor to apply the changes.
+
The save operation applies the updates and connects the {ols-long} Service to the MCP gateway.
