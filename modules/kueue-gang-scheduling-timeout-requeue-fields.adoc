= Gang scheduling timeout and requeue fields

[role="_abstract"]
The `spec.config.gangScheduling.byWorkload` fields in {kueue-name} configure readiness timeouts and requeue behavior.

The `byWorkload` field supports the following fields:

.`spec.config.gangScheduling.byWorkload` fields
[cols="2,3,2,2",options="header"]
|===
|Field
|Description
|Valid values
|If omitted

|`timeoutSeconds`
|Sets the start timeout for an admitted workload to reach the `PodsReady=True` condition. Allow enough time for image pulls, initialization, and resource provisioning.
|`30`–`86400` seconds
|Uses `1800` seconds (30 minutes).

|`recoveryTimeoutSeconds`
|Sets the recovery timeout for a workload to return to the `PodsReady=True` condition after one or more pods lose readiness. A value of `0` disables recovery timeout checks. The start timeout still applies.
|`0`–`86400` seconds
|Uses the value of `timeoutSeconds`.
|===

The `requeuingStrategy` field supports the following fields. If you include `requeuingStrategy`, specify at least one field. An empty `requeuingStrategy: {}` value is invalid.

.`spec.config.gangScheduling.byWorkload.requeuingStrategy` fields
[cols="2,3,2,2",options="header"]
|===
|Field
|Description
|Valid values
|If omitted

|`timeReference`
|Selects which timestamp {kueue-name} uses to order a workload in the queue after a readiness timeout.
|`Eviction` uses the eviction time. `Creation` uses the workload creation time.
|Uses `Eviction`.

|`retryLimit`
|Limits repeated admission attempts after readiness timeouts. After a workload uses all retries, the next timeout deactivates the workload. The `spec.active` field of the `Workload` object changes to `false`.
|`1`–`200`
|Sets no retry limit.

|`backoffBaseSeconds`
|Sets the base delay before a workload can be admitted again. The delay increases exponentially with the retry count.
|`30`–`3600` seconds
|Uses `60` seconds.

|`backoffMaxSeconds`
|Sets the maximum delay before a workload can be admitted again. If you set both delay fields, `backoffBaseSeconds` must not exceed `backoffMaxSeconds`.
|`30`–`7200` seconds
|Uses `3600` seconds.
|===

After the configured delay, the workload must still meet quota and other admission requirements before {kueue-name} can admit it again.
