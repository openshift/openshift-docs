= About BGP routing for Google Cloud

[role="_abstract"]
Border Gateway Protocol (BGP) Cloud Connector integrates {product-title} with the {gcp-short} Cloud Router allowing direct, routed connectivity to {VirtProductName} virtual machines (VMs) on {gcp-short}.

By using the BGP Cloud Connector, you do not need Network Address Translation (NAT).

:FeatureName: BGP routing for {VirtProductName} on {gcp-short}
include::snippets/technology-preview.adoc[leveloffset=+1]

VM workloads are often designed to require that a network interface of the VM is routable to and from an outside network on the same IP address the VM sees.
Mechanisms to do this on on-premise networks, such as localnet bridges, require an external Layer 2 network.
{gcp-short} Virtual Private Cloud (VPC) networks operate at Layer 3.

By using the BGP Cloud Connector, you can use compute nodes as routers to pass traffic between workloads within your cluster and the VPC network of the cluster.
BGP Cloud Connector configures compute nodes to establish BGP peering sessions with the {gcp-short} Cloud Router.
On {gcp-short}, a VM cannot establish BGP peering with a Cloud Router until it joins a Network Connectivity Center (NCC) router appliance spoke.
BGP uses this configuration to advertise pod and VM network routes from Cluster User Defined Networks (CUDNs) directly into your {gcp-short} VPC network.

BGP Cloud Connector consists of the following two core layers:

* Cloud infrastructure layer, where the underlying {gcp-short} VPC network, subnets, Cloud Router, and NCC hub get provisioned alongside your cluster.
* In-cluster Operator layer, where an Operator that manages cluster-wide and project-scoped custom resources (CRs) configure routing, BGP peering, and network interfaces.

The Operator automatically discovers the BGP neighbors and the remote autonomous system number (ASN) from the interfaces of the Cloud Router and establishes BGP peering sessions between designated compute nodes and the Cloud Router by generating `FRRConfiguration` CRs.

The Operator also automates the following required {gcp-short}-side networking configuration:

* Managing NCC router appliance spokes and Cloud Router BGP peers dynamically as nodes scale, reboot, or undergo cluster upgrades.
* Enabling IP forwarding on the network interfaces of compute nodes by setting the `canIpForward` flag, so BGP-enabled compute nodes can forward external traffic.
* Enabling nested virtualization on compute nodes that host {VirtProductName} VMs.
+
[IMPORTANT]
====
Enabling nested virtualization restarts the compute node.
The BGP Cloud Connector enables nested virtualization by default when it adds a compute node as a BGP router.
====

The following list details key benefits of using the {gcp-short} Cloud Router with BGP Cloud Connector:

* Direct, NAT-free routed connectivity between VM network interfaces and the VPC network.
* Native cloud routing integration without custom downstream implementations.
* Compatibility with standard enterprise BGP tools and multicloud architectures.
