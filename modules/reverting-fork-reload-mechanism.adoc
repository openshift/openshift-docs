= Reverting to the fork-and-reload mechanism

[role="_abstract"]
The Ingress Operator includes the `spec.configurationManagement` API field to manage how HAProxy applies route updates. When DCM encounters an operation that it cannot handle dynamically, the router falls back to the standard fork-and-reload mechanism.

The fallback mechanism is automatic and does not require administrator intervention.
//For more information about the `configurationManagement` API field, see "IngressController [operator.openshift.io/v1]".

The router writes a new `haproxy.config` file and reloads HAProxy, which forks a new process to handle incoming connections.

The standard fork-and-reload mechanism configures `spec.configurationManagement` field directly on the `IngressController` CR.

.Procedure

* If you need to enable dynamic updates, enter the following command:
+
[source,terminal]
----
$ oc -n openshift-ingress-operator patch ingresscontrollers/default \
  --type=merge \
  --patch='{"spec":{"configurationManagement":"Dynamic"}}'
----

* If you need to revert to the fork-and-reload mechanism, enter the following command:
+
[source,terminal]
----
$ oc -n openshift-ingress-operator patch ingresscontrollers/default \
  --type=merge \
  --patch='{"spec":{"configurationManagement":"ForkAndReload"}}'
----
