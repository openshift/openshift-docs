= Troubleshoot log lines that exceed the Loki size limit

[role="_abstract"]
Resolve errors that occur when individual log lines exceed the maximum size that LokiStack accepts.

LokiStack enforces a maximum size of 256 KB for individual log lines. The Loki distributor discards log lines that exceed this limit and does not retry them. Unlike rate limit errors, Vector does not retry these requests. The log lines are permanently lost.

[IMPORTANT]
====
The `LokiStack` CR is not available on Grafana-hosted Loki. This procedure does not apply to Grafana-hosted Loki servers.
====

.Prerequisites

* You have administrator permissions.
* You have configured the Log Forwarder API to forward logs to Loki.
* The LokiStack distributor pod logs show errors similar to the following:
+
[source,text]
----
level=error ... details="Max entry size '256000' bytes exceeded for stream '{kubernetes_container_name="<container_name>", kubernetes_namespace_name="<namespace>", ...}'"
----

.Procedure

. Run the following query in the OpenShift web console under *Observe* -> *Metrics* to confirm that LokiStack is discarding oversized log lines and to discover the tenants that the size limit affects:
+
[source,promql]
----
sum by (tenant, reason) (irate(loki_discarded_samples_total[2m]))
----
+
A nonzero result with `reason="LineTooLong"` confirms that LokiStack is discarding log lines because they exceed the 256 KB limit.

. Confirm that the collector receives 400 errors from LokiStack by reviewing the collector logs:
+
[source,terminal]
----
$ oc -n openshift-logging logs -l app.kubernetes.io/component=collector | grep "400 Bad Request"
----
+
.Example output
[source,text]
----
2024-11-28T17:43:30.744862692Z ERROR sink{component_kind="sink" ...}: vector::sinks::util::retries: Non-retriable error; dropping the request. error=Server responded with an error: 400 Bad Request
----
+
The `Non-retriable error` message confirms that Vector is dropping the request and the log lines are permanently lost.

. Find the source of the oversized log lines by reviewing the distributor pod logs:
+
[source,terminal]
----
$ for pod in $(oc get pods -o name -l app.kubernetes.io/component=distributor -n openshift-logging); \
  do oc logs $pod -n openshift-logging; \
  done | grep "Max entry size '256000' bytes exceeded for stream"
----
+
The error message includes stream labels such as `kubernetes_namespace_name`, `kubernetes_pod_name`, and `kubernetes_container_name` that identify the source container.

. Reduce the size of log lines produced by the affected container:
+
--
* Reduce the log verbosity of the application to prevent it from producing log lines over 256 KB.
* Change the application log format to produce shorter, structured log lines.
* Use a prune filter to remove large fields from log records before they reach LokiStack. For more information, see xref:../configure/configure-filters.adoc#configure-filters[Configure filters].
--
