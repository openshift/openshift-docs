= Verify an Agentic {ols-long} deployment

[role="_abstract"]
After you configure the credentials secret, the `LLMProvider` custom resource (CR), and the `Agent` CR, verify that Agentic {ols-long} is operating and can run a tool-calling workflow.

.Prerequisites

* You have created the credentials secret in the `openshift-lightspeed` namespace.
* You have created an `LLMProvider` CR and at least the `default` `Agent` CR.

.Procedure

. Confirm that the `LLMProvider` resource exists and shows the expected provider type by running the following command:
+
[source,terminal]
----
$ oc get llmprovider
----
+
.Example output
[source,terminal]
----
NAME             TYPE        AGE
vllm-anthropic   Anthropic   2m
----

. Confirm that the `default` `Agent` resource exists and references the correct provider and model by running the following command:
+
[source,terminal]
----
$ oc get agent default
----
+
.Example output
[source,terminal]
----
NAME      LLM              MODEL       AGE
default   vllm-anthropic   <model_id>  2m
----

. Confirm that the operator and workload pods are running in the `openshift-lightspeed` namespace by running the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-lightspeed
----
+
[NOTE]
====
This command verifies only that the operator and its workloads are present and running. It does not confirm that the provider connection or tool calling works. The `Agent` CR is configuration only and does not report a status or readiness condition. Agentic {ols-long} creates sandbox pods when an `AgenticRun` is reconciled, so an end-to-end check of the provider pathway and tool calling requires that you run an `AgenticRun`, as described in the following step.
====

. Perform an end-to-end check by submitting a query that requires a tool call, either through the web console or by creating an `AgenticRun`, and confirm that Agentic {ols-long} returns the tool result. A successful tool call confirms that the provider pathway preserves tool calls and structured outputs.

.Troubleshooting

* If the deployment does not return tool results when you use a self-hosted vLLM server, confirm that you configured the Anthropic provider pathway instead of the OpenAI-compatible pathway. The OpenAI provider pathway can suppress tool calls on vLLM. For more information, see "Choose an LLM provider pathway for Agentic {ols-long}".
* If the `LLMProvider` resource is rejected, confirm that the per-provider block matches the `spec.type` value and that the credentials secret exists in the `openshift-lightspeed` namespace with the required keys.
