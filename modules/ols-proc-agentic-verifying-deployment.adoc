= Verify the {ols-long} autonomous agents deployment

[role="_abstract"]
After you configure the credentials secret, the `LLMProvider` custom resource (CR), and the `Agent` CR, verify that {ols-long} autonomous agents is operating and can process an `AgenticRun`.

.Prerequisites

* You have created the credentials secret in the `openshift-lightspeed` namespace.
* You have created an `LLMProvider` CR and at least the `default` `Agent` CR.

.Procedure

. Confirm that the `LLMProvider` resource exists and shows the expected provider type by running the following command:
+
[source,terminal]
----
$ oc get llmprovider
----
+
.Example output
[source,terminal]
----
NAME             TYPE        AGE
vllm-anthropic   Anthropic   2m
----

. Confirm that the `default` `Agent` resource exists and references the correct provider and model by running the following command:
+
[source,terminal]
----
$ oc get agent default
----
+
.Example output
[source,terminal]
----
NAME      LLM              MODEL       AGE
default   vllm-anthropic   <model_name>  2m
----

. Confirm that the operator and workload pods are running in the `openshift-lightspeed` namespace by running the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-lightspeed
----
+
[NOTE]
====
This command verifies only that the operator and its workloads are present and running. It does not confirm that the provider connection works. The `Agent` CR is configuration only and does not report a status or readiness condition. {ols-long} autonomous agents creates sandbox pods when an `AgenticRun` is reconciled, so to check the deployment end to end, you must run an `AgenticRun`, as described in the following step.
====

. Submit a test `AgenticRun` by running the following command:
+
[source,terminal]
----
$ oc apply -f - <<EOF
apiVersion: agentic.openshift.io/v1alpha1
kind: AgenticRun
metadata:
  name: test
  namespace: openshift-lightspeed
spec:
  request: |
    Is this OpenShift cluster healthy?
  analysis:
    agent: default
EOF
----

. Confirm that the `AgenticRun` appears in the *Agentic Runs* section of the {product-title} web console.

.Troubleshooting

* If the `AgenticRun` does not complete successfully when you use a self-hosted vLLM server, confirm that you configured the Anthropic provider pathway instead of the OpenAI-compatible pathway.
* If the `LLMProvider` resource is rejected, confirm that the per-provider block matches the `spec.type` value and that the credentials secret exists in the `openshift-lightspeed` namespace with the required keys.
