= Cluster autoscaling parameters using the {rosa-cli}

[role="_abstract"]
You can add the following parameters to the cluster creation command to configure autoscaler parameters when using the {rosa-cli-first}.

.Configurable autoscaler parameters available with the {rosa-cli}

[cols="4",options="header"]
|===
|Setting
|Description
|Type or Range
|Example/Instruction

|`--autoscaler-max-pod-grace-period _int_`
|Gives pods graceful termination time before scaling down, measured in seconds. Replace _int_ in the command with the number of seconds you want to use.
|`integer`
|`--autoscaler-max-pod-grace-period 0`

|`--autoscaler-pod-priority-threshold _int_`
|The priority that a pod must exceed to cause the cluster autoscaler to deploy additional nodes. Replace _int_ in the command with the number you want to use, can be negative.
|`integer`
|`--autoscaler-pod-priority-threshold -10`

|`--autoscaler-max-node-provision-time _string_`
|Maximum time that the cluster autoscaler waits for a node to be provisioned. Replace _string_ in the command with an integer and time unit (ns,us,µs,ms,s,m,h).
|`string`
|`--autoscaler-max-node-provision-time 35m`

|`--autoscaler-max-nodes-total _int_`
|Maximum amount of nodes in the cluster, including the autoscaled nodes. Replace _int_ in the command with the number you want to use.
|`integer`
|`--autoscaler-max-nodes-total 180`

|`--autoscaler-scaling-mode _string_`
|Enables or disables scale-down globally.
|`enum`: `ScaleUpOnly`, `ScaleUpAndScaleDown`
|`--autoscaler-scaling-mode ScaleUpAndScaleDown`

|`--autoscaler-scale-down-delay-after-add _string_`
|Wait time after a scale-up event before evaluating scale-down.
|`duration`: `0h` to `24h`
|`--autoscaler-scale-down-delay-after-add 10m`

|`--autoscaler-scale-down-delay-after-delete _string_`
|Wait time after a node deletion before evaluating the next scale-down.
|`duration`: `0h` to `24h`
|`--autoscaler-scale-down-delay-after-delete 0s`

|`--autoscaler-scale-down-delay-after-failure _string_`
|Wait time after a failed scale-down before retrying.
|`duration`: `0h` to `24h`
|`--autoscaler-scale-down-delay-after-failure 3m`

|`--autoscaler-scale-down-unneeded-time _string_`
|How long a node must remain underutilized before it is eligible for removal.
|`duration`: `0h` to `24h`
|`--autoscaler-scale-down-unneeded-time 10m`

|`--autoscaler-scale-down-utilization-threshold _float_`
|Node utilization threshold below which a node becomes a candidate for scale-down.
|`percent`: `0%` to `100%` or `0.0` to `1.0`
|`--autoscaler-scale-down-utilization-threshold 0.5`

|`--autoscaler-expanders _strings_`
|Scale-up strategy configuration used when selecting which node group to expand. Accepts a comma-separated list of up to 3 values.
|`list`: a maximum of 3 values, such as: `LeastWaste`, `Priority`, and `Random`
|`--autoscaler-expanders Priority,LeastWaste`

|`--autoscaler-balancing-ignored-labels _strings_`
|Comma-separated list of node labels to ignore when comparing machine pool or node pool similarity.
|`string list`: a maximum of 64 items
|`--autoscaler-balancing-ignored-labels topology.ebs.csi.aws.com/zone`

|`--autoscaler-max-free-difference-ratio _float_`
|Maximum free resource difference allowed for node pools to be considered similar.
|`percent`: `0%` to `100%` or `0.0` to `1.0`
|`--autoscaler-max-free-difference-ratio 0.1`

|`--kube-client-qps _float_`
|Maximum queries per second (QPS) sent by the cluster autoscaler to the Kubernetes API server.
|`float`
|`--kube-client-qps 200`

|`--kube-client-burst _int_`
|Maximum burst of queries sent by the cluster autoscaler to the Kubernetes API server before rate limiting applies.
|`integer`
|`--kube-client-burst 300`

|===
