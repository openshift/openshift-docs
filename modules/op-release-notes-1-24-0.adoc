= Release notes for {pipelines-title} 1.24.0

[role="_abstract"]
{pipelines-title} General Availability (GA) 1.24 is available on {OCP} 4.14, 4.16, 4.18, 4.19, 4.20, 4.21, and 4.22.

[id="new-features-and-enhancements-1-24-0_{context}"]
== New features and enhancements

[id="tekton-results_{context}"]
=== Tekton Results

Server-Side Apply for Tekton Results finalizer management::
The Tekton Results controller now manages finalizers on `PipelineRun` and `TaskRun` resources using Server-Side Apply (SSA) instead of Merge patch. This reduces retries and Kubernetes API requests during reconciliation while seamlessly handling in-flight resources during upgrades.
+
link:https://issues.redhat.com/browse/SRVKP-8541[SRVKP-8541]


Time-based query support for the Splunk logging plugin::
The Tekton Results Splunk logging plugin now supports time-based queries that limit search windows using start and end timestamps, optimizing Splunk queries and reducing infrastructure load.
+
link:https://issues.redhat.com/browse/SRVKP-14266[SRVKP-14266]

Custom JSON field extraction and line formatting for Loki logging plugin::
Tekton Results introduces `LOGGING_PLUGIN_JSON_MAP` to define custom JSON field extraction mappings, and `LOGGING_PLUGIN_LINE_FORMAT` to define custom log line output formatting for the Loki logging plugin.
+
link:https://issues.redhat.com/browse/SRVKP-14266[SRVKP-14266]

[id="pipelines-as-code_{context}"]
=== Pipelines as Code

Support service accounts for Bitbucket Data Center scoped tokens::
Bitbucket Data Center provider configuration with HTTP scoped tokens no longer requires specifying a user in the `Repository` custom resource, allowing service accounts with scoped tokens to authenticate directly.
+
link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]

Direct OpenTelemetry SDK tracing setup::
{pac} configures tracing directly using the OpenTelemetry SDK instead of Knative's `config-observability` ConfigMap, enabling `parentbased_*` samplers via the `OTEL_TRACES_SAMPLER` environment variable for consistent distributed tracing.
+
link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]

AI-powered code review pipeline (Paco)::
{pac} introduces a Tekton `PipelineRun` integration for automated AI code reviews on pull requests. Triggered by `/paco review` or `/paco summary` PR comments, it provides diff analysis, difficulty scoring, and security sensitivity detection.
+
link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]

Webhook validation for GitHub comment strategy setting::
An admission webhook validates the `comment_strategy` field in the `Repository` custom resource for GitHub providers, rejecting invalid values at admission time.
+
link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]



=== Manual Approval Gate

Default NetworkPolicies for Manual Approval Gate::
The `ManualApprovalGate` custom resource now creates default NetworkPolicies that restrict ingress and egress traffic for its controller and webhook workloads. These policies are enabled by default. To opt out, set `spec.networkPolicy.disabled: true` in the `ManualApprovalGate` custom resource.


=== MultiCluster (Technology Preview)

CEL-based routing policies in Tekton Kueue::
Tekton Kueue supports CEL-based routing policies for `PipelineRun` placement. New CEL functions allow per-`PipelineRun` routing decisions based on runtime attributes such as labels, annotations, or event types, replacing the all-or-nothing `multiKueueOverride` boolean setting.
+
The following new CEL functions are available:

* `managedBy(value)`: Sets `spec.managedBy` to route a `PipelineRun` resource to a custom controller.
* `multiKueue()`: Sets `spec.managedBy` for MultiKueue routing.
* `multiKueue(queueName)`: Sets `spec.managedBy` and overrides the Kueue queue label.
+
You can use these functions in conditional CEL expressions to route `PipelineRun` resources to different clusters based on runtime attributes.
link:https://redhat.atlassian.net/browse/SRVKP-12732[SRVKP-12732]


NetworkPolicy support for OpenShift Pipelines Operator::
Red Hat OpenShift Pipelines Operator now ships default `NetworkPolicy` resources restricting network access for its controller and proxy-webhook pods to only DNS, Kubernetes API server, Prometheus metrics, and webhook traffic. Additionally, the `TektonPipeline` custom resource gains a `spec.networkPolicy` field (mirroring `TektonTrigger`) so proxy-webhook network policies can be reconciled, overridden, or disabled per component.
+
link:https://redhat.atlassian.net/browse/SRVKP-12050[SRVKP-12050]

Support for CustomRuns in Tekton Results::
Tekton Results now stores and records `CustomRun` (`tekton.dev/v1beta1`) resources alongside `TaskRun` and `PipelineRun` resources. `CustomRun` resources created by custom task controllers are automatically recorded in the Tekton Results database.
+
link:https://redhat.atlassian.net/browse/SRVKP-11436[SRVKP-11436]

Persistent date-range filter on PipelineRuns and TaskRuns list pages::
The PipelineRuns list page and TaskRuns list page now feature a persistent date-range filter with standard time presets, querying both live cluster activity and archived data from Tekton Results. Filter selections are automatically saved to individual user profiles and persist across all sessions and devices.
+
link:https://issues.redhat.com/browse/SRVKP-12008[SRVKP-12008]

Persistent datasource filter on PipelineRuns and TaskRuns list pages::
The datasource filter on the PipelineRuns and TaskRuns list pages is now persistent. The selected data source (Cluster or Archived) is automatically saved to the user profile and preserved across all sessions and devices.
+
link:https://issues.redhat.com/browse/SRVKP-12009[SRVKP-12009]

Default PVC configuration for Pipeline workspaces in UI::
You can now configure a default PersistentVolumeClaim (PVC) for a Pipeline workspace. When a default workspace and PVC are configured, the Start Pipeline modal automatically pre-populates the workspace with the selected PVC, reducing manual configuration steps.
+
link:https://redhat.atlassian.net/browse/SRVKP-12527[SRVKP-12527]

Option to toggle optional task parameters in Pipeline Builder::
A new "Show required task params only" toggle is available in the Pipeline Builder UI. When enabled, optional task parameters are hidden from the sidebar and the YAML editor switches to read-only mode to prevent parameter corruption while keeping the view uncluttered.
+
link:https://redhat.atlassian.net/browse/SRVKP-12530[SRVKP-12530], link:https://redhat.atlassian.net/browse/SRVKP-12531[SRVKP-12531]

Compressed termination messages for Tekton Tasks::
Termination messages are now compressed with zlib when `enable-termination-message-compression` is enabled, increasing effective result capacity from ~33 to ~187 results (a 5.7x improvement). This compression has no effect when `results-from` is set to `sidecar-logs`.
+
link:https://redhat.atlassian.net/browse/SRVKP-7717[SRVKP-7717]

OpenTelemetry observability migration and metric updates::
OpenShift Pipelines components (including Tekton Pipelines, Pipelines as Code, and Manual Approval Gate) have migrated observability infrastructure from OpenCensus to OpenTelemetry. Standard Knative/OTel metrics prefixes (`kn_workqueue_*`, `http_client_*`, `go_*`) replace legacy `tekton_pipelines_controller_*` infrastructure metrics.
+
link:https://redhat.atlassian.net/browse/SRVKP-8534[SRVKP-8534], link:https://redhat.atlassian.net/browse/SRVKP-8544[SRVKP-8544], link:https://redhat.atlassian.net/browse/SRVKP-11514[SRVKP-11514]

Centrally managed TLS profile support in Pipelines as Code controller::
The Pipelines as Code controller now inherits TLS configuration settings directly from the OpenShift APIServer TLS Profile (`config.openshift.io/v1`), ensuring central TLS profile consistency and supporting Post-Quantum Cryptography (PQC) readiness.
+
link:https://redhat.atlassian.net/browse/SRVKP-9681[SRVKP-9681]

GitHub API rate limit event emission in Pipelines as Code::
Pipelines as Code now emits Kubernetes events and log entries when GitHub API rate limits are exhausted. This surfaces rate limit exhaustion distinctly as a Repository event rather than reporting generic authentication failures.
+
link:https://redhat.atlassian.net/browse/SRVKP-10951[SRVKP-10951]

Forgejo and Gitea ListOrgTeams API caching::
Pipelines as Code now caches `ListOrgTeams` API responses per organization during ACL checks, preventing redundant API calls when evaluating multiple allowed teams in Forgejo or Gitea provider integrations.
+
link:https://redhat.atlassian.net/browse/SRVKP-11532[SRVKP-11532]

== Fixed issues

* **RecordSummary timestamps missing for completed runs:** Before this update, `RecordSummary` `StartTime` was always `NULL`, and `EndTime` was `NULL` for failed, timed-out, or canceled runs because timestamps were read from Knative conditions instead of run status. With this update, timestamps are read directly from `Status.StartTime` and `Status.CompletionTime` fields. As a result, `RecordSummary` timestamps are correctly populated for all run outcomes. link:https://issues.redhat.com/browse/SRVKP-14266[SRVKP-14266]
* **Reconciler shared state race condition:** Before this update, the reconciler stored per-reconciliation state on the shared controller struct, allowing concurrent reconciliations to overwrite namespace decisions. With this update, per-reconciliation state is isolated from the shared struct. As a result, concurrent reconciliations operate independently without race conditions. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **AI analysis execution on successful PipelineRuns:** Before this update, default AI/LLM roles ran analysis only for failed `PipelineRun` resources. With this update, default AI roles run for all completed `PipelineRun` executions regardless of status outcome. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **Error wrapping in PAC installation detection:** Before this update, `DetectPacInstallation` formatted errors using `%s` instead of `%w`, causing error contexts to be lost. With this update, `%w` is used for proper error wrapping. As a result, error chain inspection functions correctly. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **GitLab token rotation write access verification:** Before this update, GitLab token auto-rotation revoked old tokens prior to updating Kubernetes Secrets, risking credential loss if Secret writes failed. With this update, a server-side dry-run Secret update is executed before revoking old tokens. As a result, permission errors are detected early, preventing credential loss. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **GitLab branch creation push events:** Before this update, GitLab Push Hook payloads with empty commit arrays were rejected during new branch creation. With this update, payloads are accepted using the target commit SHA. As a result, branch creation events on GitLab correctly trigger pipeline runs. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **GitLab source lookups pinned to event SHA:** Before this update, GitLab source provenance used mutable branch references for looking up `.tekton` definitions. With this update, the immutable event SHA is used for all source lookups. As a result, `PipelineRun` definitions are pinned to the exact revision that triggered the event. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **Nil content handling in Gitea file retrieval:** Before this update, nil content returned for missing files caused controller nil pointer panics. With this update, a nil check guards missing file responses. As a result, missing files are handled gracefully without controller crashes. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **Bitbucket Cloud token CLI updates:** Before this update, updating Bitbucket Cloud tokens via `tkn pac` CLI did not prompt for Atlassian account emails, resulting in 401 authentication errors. With this update, the CLI prompts for and stores Atlassian account emails. As a result, authentication succeeds after token rotation. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **Controller HTTP listener graceful shutdown:** Before this update, the controller HTTP listener did not monitor context cancellation, hanging on `SIGTERM` signals. With this update, the listener monitors context cancellation and shuts down cleanly. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **Repository configuration error logging and events:** Before this update, repository configuration errors lacked sufficient debugging context. With this update, errors are logged with full repository URL and commit SHA context, and a Kubernetes Event is emitted on configuration failure. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **Provider logger consistency:** Provider logging now consistently uses `v.Logger` across all providers to ensure log messages include standard provider, repository, and event ID context variables. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **Nil pointer dereference crashes:** Potential nil pointer dereference paths across core packages have been identified via static analysis and resolved. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **Webhook deployment Prometheus metrics port:** `containerPort` and Service port definitions for Prometheus metrics on port 9090 have been added to the webhook deployment. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **Kubernetes event timestamp population:** Emitted Kubernetes events now properly populate `FirstTimestamp`, `LastTimestamp`, `Count`, and `ReportingController` fields. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]
* **OpenTelemetry schema version panic:** Package version mismatches between `knative.dev/pkg` and `semconv` have been updated to compatible versions, resolving OpenTelemetry schema panics. link:https://issues.redhat.com/browse/SRVKP-14264[SRVKP-14264]


* **TektonDashboard API in Provided APIs:** Previously, the `TektonDashboard` custom resource definition incorrectly appeared under the Provided APIs section on the operator details page in the OpenShift console. This issue is now resolved, and the `TektonDashboard` custom resource definition is properly excluded from OpenShift operator bundles. link:https://issues.redhat.com/browse/SRVKP-13891[SRVKP-13891]

* **Operator component finalizers:** Previously, when a component such as Tekton Chains or Tekton Results was disabled in the `TektonConfig` custom resource, component-specific finalizers remained on existing pipeline runs, preventing them from being deleted without manual intervention. This issue is now resolved. link:https://issues.redhat.com/browse/SRVKP-9231[SRVKP-9231]

* **Operator CLI version reporting:** Previously, the OpenShift Pipelines CLI (`opc`) and Tekton CLI (`tkn`) reported `devel` as the operator version instead of the release version number. This issue is now fixed, and the CLI binaries report the correct operator release version. link:https://issues.redhat.com/browse/SRVKP-13934[SRVKP-13934]

* **Tekton Results retention policy agent database connection:** Previously, the `retention-policy-agent` pod failed to connect to the `tekton-results-postgres-service` database service at startup due to missing network egress rules. This issue is now fixed, and the retention policy agent connects successfully to execute retention policies. link:https://issues.redhat.com/browse/SRVKP-14235[SRVKP-14235]

* **SRVKP-9638:** Pipelines using path-based or CEL filters now correctly trigger when a pull request is merged in Bitbucket Data Center, ensuring file changes in merge commits are detected.
* **SRVKP-10477:** When a merge request originates from an inaccessible fork, Pipelines as Code posts a descriptive comment on the MR detailing the missing permissions or token scoping required.
* **SRVKP-10945:** Fixed an issue where custom parameters passed to the `/test` command (e.g., `/test custom1=value`) were incorrectly parsed as PipelineRun names, bypassing `on-comment` annotation matching.
* **SRVKP-11201:** Fixed a stale caching issue in the console plugin that prevented deleted or pruned `PipelineRun` and `TaskRun` resources from being removed promptly from the UI list view.
* **SRVKP-12918:** Fixed a badge count calculation issue on responsive toolbar viewports where total selected values were displayed instead of active filter categories.

[id="deprecated-features-1-24-0_{context}"]
== Deprecated features

Tekton Hub commands in tkn CLI::
Tekton Hub integration in the `tkn` CLI is now deprecated in favor of Artifact Hub. Commands such as `check-upgrade`, `downgrade`, `get`, `info`, `reinstall`, `search`, and `upgrade` currently target Tekton Hub and will display a deprecation warning. Users should migrate to Artifact Hub by passing `--type artifact` to `tkn hub install`.
+
link:https://redhat.atlassian.net/browse/SRVKP-11950[SRVKP-11950], link:https://redhat.atlassian.net/browse/SRVKP-10462[SRVKP-10462]

[id="removed-features-1-24-0_{context}"]
== Removed features

* **Tekton Hub removal:** Tekton Hub and its custom resource (`TektonHub`) are removed in Red Hat OpenShift Pipelines 1.24. Searching, installing, and resolving catalog tasks and pipelines now use Artifact Hub or the cluster resolver. If your cluster contains an existing `TektonHub` custom resource, delete the resource before upgrading to 1.24.

Tekton Hub integration in Pipelines as Code::
Tekton Hub integration has been removed from Pipelines as Code. All Tekton Hub-specific resolver code, configuration fields, and documentation have been removed, leaving Artifact Hub as the supported hub integration.
+
link:https://redhat.atlassian.net/browse/SRVKP-12188[SRVKP-12188]
