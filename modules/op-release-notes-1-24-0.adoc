= StatefulSet-based controller sharding is now generally available

[role="_abstract"]
The `statefulset-ordinals` feature flag is now generally available in {pipelines-title} 1.24. This feature transitions controller performance scaling from traditional leader election to StatefulSet-based ordinal sharding.

* *Improved throughput:* StatefulSet-based sharding delivers 3–5× faster `PipelineRun` completion under high concurrency levels by distributing workload processing evenly across all controller replicas using hash-based sharding.
* *Backward compatibility:* Controller behavior remains fully compatible when upgrading from Technology Preview implementations (versions 1.18 to 1.23). Existing pipeline execution definitions do not require modification.
* *Resource planning:* Enabling StatefulSet sharding increases CPU utilization, raises controller memory overhead by approximately 12%, and elevates `etcd` write pressure. Evaluate adjacent cluster infrastructure before you enable this feature in production.

== Leader election compared to StatefulSet sharding

High availability (HA) mode provides fault tolerance across multiple controller replicas. {pipelines-title} supports two implementation approaches:

* *Leader election:* The standard Kubernetes HA pattern. One controller holds the lease and processes all reconciliation work, while standby replicas take over if the leader fails.
* *StatefulSet-based sharding:* Distributes reconciliation work across all active controller replicas. Each pod receives a stable identity (`controller-0`, `controller-1`) and processes a deterministic workload subset using `hash(key) % N`, where `N` is the total pod count.

.Comparison of HA implementation approaches
[cols="1,2,2",options="header"]
|===
| Operational metric | Leader election | StatefulSet-based sharding

| Primary objective
| Automatic failover and operational simplicity
| Maximum throughput and active resource utilization

| Replica execution
| Single active leader; remaining pods standby
| All replicas actively process workloads in parallel

| Work assignment
| Single lease lock owner
| Consistent pod mapping (`hash(key) % N`)

| Target workload
| Standard resiliency requirements
| Large-scale pipelines with high `PipelineRun` concurrency
|===
