= Configure multi-architecture filtering for oc-mirror plugin v2

[role="_abstract"]
To filter mirrored architectures, add a `platforms` field to each section of your `ImageSetConfiguration` file that you want to filter. Identify each node architecture in your cluster, then set matching `os` and `architecture` values in the `platforms` field.

.Prerequisites

* You have oc-mirror plugin v2 installed.
* You have a pull secret or registry credentials file for the target registry.
* You have created an `ImageSetConfiguration` file.
* Your target registry supports sparse manifests, for example, {quay} with the `FEATURE_SPARSE_INDEX` value set to `true` in the `config.yaml` file.

.Procedure

. Identify the architecture of each node in your disconnected cluster by running the following command:
+
[source,terminal]
----
$ oc get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.nodeInfo.architecture}{"\n"}{end}'
----

. Open the `ImageSetConfiguration` file in a text editor.

. Add a `platforms` field to each section of your `ImageSetConfiguration` file to filter by architecture.
+
.Example `ImageSetConfiguration` file
[source,yaml]
----
apiVersion: mirror.openshift.io/v2alpha1
kind: ImageSetConfiguration
mirror:
  platform:
    channels:
      - name: stable-<product_version>
    platforms:
      - os: linux
        architecture: amd64
      - os: linux
        architecture: arm64
  operators:
    - catalog: registry.redhat.io/redhat/redhat-operator-index:v<product_version>
      platforms:
        - os: linux
          architecture: amd64
        - os: linux
          architecture: arm64
  helm:
    repositories:
      - name: <repo_name>
        url: <repo_url>
        charts:
          - name: <chart_name>
            version: "<chart_version>"
            platforms:
              - os: linux
                architecture: amd64
              - os: linux
                architecture: arm64
  additionalImages:
    - name: registry.redhat.io/ubi9/ubi:latest
      platforms:
        - os: linux
          architecture: amd64
        - os: linux
          architecture: arm64
----
+
where:

`mirror.platform.platforms`:: Specifies one or more target platforms by using `os` and `architecture` sub-fields. Supported architecture values are `amd64`, `arm64`, `s390x`, and `ppc64le`.

`mirror.operators.platforms`:: Specifies the compute architectures to mirror for this catalog entry. If omitted, oc-mirror plugin v2 mirrors all architectures present in the source.

`mirror.helm.repositories.charts.platforms`:: Specifies the compute architectures to mirror for container images referenced in this Helm chart. If omitted, oc-mirror plugin v2 mirrors all architectures present in the source.

`mirror.additionalImages.platforms`:: Specifies the compute architectures to mirror for this additional image. If omitted, oc-mirror plugin v2 mirrors all architectures present in the source.
+
[NOTE]
====
The `platforms` field replaces the deprecated `architectures` field. Use `platforms` in new configurations.

When you set `platforms` under `mirror.platform`, the filter does not automatically propagate to the `operators`, `helm`, or `additionalImages` fields. Set the `platforms` field explicitly in each section you want to filter.
====

. Save the configuration file.

. Run the oc-mirror plugin v2 with your updated configuration.
+
For more information, see "Mirroring an image set to a mirror registry".

.Verification

* Confirm that only the expected platforms are present in the target registry by running the following command:
+
[source,terminal]
----
$ oc image info --registry-config <pull_secret> docker://<target_registry>/<image>:<tag>
----
+
.Example output
[source,terminal]
----
OS            DIGEST
linux/amd64   sha256:b4c7a91802c09a5a748fe19ddd99a8ffab52d8a31db3a081a956a87f22a22ff8
linux/arm64   sha256:7b046404572ac96202d82b6cb029b421dddd40e88c73bbf35f602ffc13017f21
----
+
The output lists only the architectures specified in the `platforms` field of your `ImageSetConfiguration` file. If the output includes architectures you did not specify, verify that you set the `platforms` field correctly in each section of the file.
