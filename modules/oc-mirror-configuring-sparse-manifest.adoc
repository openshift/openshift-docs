= Configure multi-architecture filtering for oc-mirror v2

[role="_abstract"]
You can configure oc-mirror v2 to mirror only the architectures your cluster requires for platform releases, Operator catalogs, and additional images by adding a `platforms` field to your `ImageSetConfiguration` file.

.Prerequisites

* You have oc-mirror v2 installed.
* You have access to the disconnected cluster with a valid `kubeconfig`.
* You have a pull secret or registry credentials file for the target registry.
* Your target registry supports sparse manifests, for example, Quay 3.17 or later with `FEATURE_SPARSE_INDEX: true` set in `config.yaml`. For more information, see link:https://docs.redhat.com/en/documentation/red_hat_quay/3.17/html/manage_red_hat_quay/arch-mirroring-intro[Mirroring images with Red Hat Quay].

.Procedure

. Identify the architecture of each node in your disconnected cluster by running the following command:
+
[source,terminal]
----
$ oc get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.nodeInfo.architecture}{"\n"}{end}'
----

. If you do not yet have an `ImageSetConfiguration` file, create one with the following baseline content:
+
[source,yaml]
----
apiVersion: mirror.openshift.io/v2alpha1
kind: ImageSetConfiguration
mirror:
  platform:
    channels:
      - name: stable-<product_version>
  operators:
    - catalog: registry.redhat.io/redhat/redhat-operator-index:v<product_version>
  additionalImages:
    - name: registry.redhat.io/ubi9/ubi:latest
----

. Open the `ImageSetConfiguration` file in a text editor.

. Add `platforms` filtering under `mirror.platform` to include only the architectures your cluster requires:
+
[source,yaml]
----
apiVersion: mirror.openshift.io/v2alpha1
kind: ImageSetConfiguration
mirror:
  platform:
    channels:
      - name: stable-<product_version>
    platforms:
      - os: linux
        architecture: amd64
      - os: linux
        architecture: arm64
----
+
where:

`mirror.platform.platforms`:: Specifies one or more target platforms using `os` and `architecture` sub-fields. Supported architecture values are `amd64`, `arm64`, `s390x`, and `ppc64le`.
+
[NOTE]
====
The `platforms` field replaces the deprecated `architectures` field. Use `platforms` in new configurations.
====

. Add a `platforms` list to each Operator catalog entry to filter architectures per catalog:
+
[source,yaml]
----
  operators:
    - catalog: registry.redhat.io/redhat/redhat-operator-index:v<product_version>
      platforms:
        - os: linux
          architecture: amd64
----
+
where:

`operators.platforms`:: Specifies the compute architectures to mirror for this catalog entry, overriding the top-level `mirror.platform.platforms` value. If omitted, the top-level value applies.

. Add `platforms` to each entry under `mirror.additionalImages` to filter architectures for additional images:
+
[source,yaml]
----
  additionalImages:
    - name: registry.redhat.io/ubi9/ubi:latest
      platforms:
        - os: linux
          architecture: amd64
----

. Save the configuration file.

. Run oc-mirror plugin v2 with your updated configuration. Use the command that matches your mirroring workflow:
+
.. To mirror images to a local disk, run the following command:
+
[source,terminal]
----
$ oc mirror -c ./imageset-config.yaml file://<mirror_directory> --v2
----
+
where:

`<mirror_directory>`:: Specifies the path to your local storage directory.
+
.. To mirror images from a local disk to the target registry, run the following command:
+
[source,terminal]
----
$ oc mirror -c ./imageset-config.yaml --from file://<mirror_directory> docker://<target_registry> --v2
----
+
where:

`<target_registry>`:: Specifies the hostname and port of your disconnected registry.
+
.. To mirror images directly from the source to the target registry, run the following command:
+
[source,terminal]
----
$ oc mirror -c ./imageset-config.yaml --workspace file://<mirror_directory> docker://<target_registry> --v2
----

.Verification

* Confirm that only the expected platforms are present in the target registry by inspecting a mirrored manifest list by running the following command:
+
[source,terminal]
----
$ $ oc image info --registry-config <pull-secret> docker://<target-registry>/<image>:<tag>
----
