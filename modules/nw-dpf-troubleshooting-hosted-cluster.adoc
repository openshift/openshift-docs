= Troubleshoot hosted cluster issues

[role="_abstract"]
Use this procedure to diagnose and resolve issues with the DPU hosted cluster, including CSR approval failures, kubeconfig access problems, and worker node join failures.

.Prerequisites

* The DPF HCP Provisioner is installed and configured.
* DPU provisioning has completed successfully.
* You have access to both the management cluster and hosted cluster kubeconfig files.

.Procedure

. Verify that the hosted cluster is accessible:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/hosted-cluster.kubeconfig
$ oc cluster-info
----
+
If the cluster is not accessible, check the HyperShift hosted control plane status on the management cluster.

. Switch to the management cluster and check the HyperShift components:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/management-cluster.kubeconfig
$ oc get pods -n clusters-$HOSTED_CLUSTER_NAME
----
+
Verify that all HyperShift control plane pods are running:
+
* `etcd-*`
* `kube-apiserver-*`
* `kube-controller-manager-*`
* `kube-scheduler-*`

. Check the DPF HCP Provisioner status:
+
[source,terminal]
----
$ oc get dpfhcpprovisioner -n dpf-operator-system -o yaml
----
+
Look for status conditions indicating provisioner health and any error messages.

. Return to the hosted cluster and check for pending CSRs:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/hosted-cluster.kubeconfig
$ oc get csr --sort-by=.metadata.creationTimestamp
----
+
.Example output
[source,terminal]
----
NAME        AGE   SIGNERNAME                                    REQUESTOR                 CONDITION
csr-abc12   5m    kubernetes.io/kube-apiserver-client-kubelet   system:bootstrap:abcd12   Pending
csr-def34   3m    kubernetes.io/kubelet-serving                 system:node:dpu-worker-1  Pending
----

. Approve pending CSRs manually if automatic approval is failing:
+
[source,terminal]
----
$ oc adm certificate approve <csr-name>
----
+
For multiple pending CSRs:
+
[source,terminal]
----
$ oc get csr -o name | xargs oc adm certificate approve
----

. Verify that DPU worker nodes are joining the hosted cluster:
+
[source,terminal]
----
$ oc get nodes
----
+
.Example output
[source,terminal]
----
NAME           STATUS   ROLES    AGE   VERSION
dpu-worker-1   Ready    worker   10m   v1.35.0
dpu-worker-2   Ready    worker   10m   v1.35.0
----

. If nodes are not joining, check the bootstrap token validity:
+
[source,terminal]
----
$ oc get secrets -n kube-system | grep bootstrap-token
----
+
Bootstrap tokens have a limited lifetime. If they have expired, the HCP Provisioner should create new ones automatically.

. Check the kubelet logs on DPU worker nodes:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/management-cluster.kubeconfig
$ oc debug node/<dpu-enabled-worker-node>
----
+
[source,terminal]
----
sh-4.4# chroot /host
sh-4.4# journalctl -u kubelet -f
----
+
Look for authentication errors or certificate issues.

. Verify the DPU cluster networking configuration:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/hosted-cluster.kubeconfig
$ oc get pods -n openshift-ovn-kubernetes -o wide
----
+
Ensure that OVN-Kubernetes pods are running on the DPU ARM cores.

.Troubleshooting tips

**CSR approval failures:**::
* Verify that the HCP Provisioner has the correct RBAC permissions
* Check the provisioner logs for certificate approval errors
* Ensure that the cluster CA is correctly configured

**Node join failures:**::
* Verify that the bootstrap kubeconfig is correctly generated
* Check network connectivity between DPUs and the hosted control plane
* Ensure that the kubelet configuration includes the correct API server endpoint

**Control plane access issues:**::
* Verify that the hosted cluster VIP is correctly configured and accessible
* Check LoadBalancer service status for the hosted control plane
* Ensure that MetalLB is correctly configured for service exposure

**Network connectivity problems:**::
* Verify VTEP network configuration between DPUs
* Check that the DPU high-speed network is correctly configured
* Ensure that required ports are open for inter-DPU communication
