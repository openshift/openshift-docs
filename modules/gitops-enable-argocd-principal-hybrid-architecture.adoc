= Enable the principal component in hybrid architecture

Enable the principal component on the Argo CD instance that already manages your applications.

.Prerequisites

* You have installed the principal component. For more information, see _Installing the principal component_.
* You have created the necessary PKI certificates for secure communication between the principal and agent.
* You have created an agent using the `argocd-agentctl agent create` command.

.Procedure

* Configure the `ArgoCD` custom resource (CR) on the control plane cluster:
+
[source,yaml]
----
apiVersion: argoproj.io/v1beta1
kind: ArgoCD
metadata:
  name: argo-cd-principal
spec:
  argoCDAgent:
    principal:
      enabled: true
      labelSelector: "argocd-agent=true"
      destinationBasedMapping: true
      namespace:
        allowedNamespaces:
          - "*"
----
+
where:
+
`labelSelector`:: Restricts the principal to labeled resources only. Existing applications without this label remain unaffected.
`destinationBasedMapping`:: Routes applications to agents based on destination cluster name rather than namespace.
`allowedNamespaces`:: Specifies the namespaces where the principal watches Argo CD resources.
+
[IMPORTANT]
====
In a hybrid architecture, do not disable the hub's application controller. Both the application controller and the principal component must run simultaneously to support both push and pull reconciliation models.
====
