= Operator life cycles

[role="_abstract"]
Red{nbsp}Hat Operators that you install from the software catalog can have a different release cadence and support timeline than {product-title}. Starting with {product-title} 4.14, Red{nbsp}Hat classifies Operator maintenance life cycles so that you can plan updates and remain within support boundaries.

These classifications matter when Operators have version dependencies on each other. For example, {rh-rhacm-first} depends on a supported version of the {mce}. Review the life cycle of each Operator before you install or update it, especially in disconnected environments where you must mirror and pin Operator versions in advance.

Operator version lines that are not available on {product-title} 4.14 or later are not part of this classification.

The following life cycle classifications apply to Operators that Red{nbsp}Hat ships for {product-title}:

[cols="2a,8a",options="header"]
|===
|Classification |Description

|Platform Aligned
|The Operator is released and maintained in close alignment with the {product-title} cluster version. It shares the same full support and maintenance support phases as the aligned cluster version. You typically remain on a given Operator minor version for the life of that cluster version and apply Operator patches to receive bug fixes and security advisories.

|Platform Agnostic
|The Operator is released independently of {product-title}. Multiple Operator minor versions can be supported in parallel on a given cluster version, and each Operator minor version generally has a shorter life cycle than the cluster. You select the Operator minor version by using the Operator Lifecycle Manager (OLM) update channel. Plan to update to a newer Operator minor version when the current version reaches the end of its life cycle or when you update the cluster.

|Rolling Stream
|The Operator provides a single rolling stream of updates. Fixes and features are introduced in that stream with a variable cadence. To remain supported, you must continue to validate and update to the latest Operator release. New releases support all in-maintenance {product-title} versions.
|===

For current support dates and the classification of each Operator, see _OpenShift Operator Life Cycles_.
