= Re-initializing the SPIRE server datastore

[role="_abstract"]
Re-initialize the {spiffe-full} Runtime Environment (SPIRE) server datastore when you need the nested server to abandon its current certificate authority (CA) immediately. SPIRE otherwise waits until the next CA rotation. {zero-trust-full} does not delete the datastore for you.

.Prerequisites

* You logged in to the nested cluster with the `cluster-admin` role.
* You already set `spec.upstreamAuthority.spire` on the nested server.
* You scheduled a maintenance window. The reset invalidates existing SPIRE identities on the nested cluster.

[WARNING]
====
Deleting the PVC removes the SPIRE server datastore and makes workload identities from the nested server unusable. Schedule the reset in a maintenance window.
====

.Procedure

. Scale the SPIRE server to zero by running the following command:
+
[source,terminal]
----
$ oc scale statefulset/spire-server -n zero-trust-workload-identity-manager --replicas=0
----

. Wait until the pod disappears by running the following command:
+
[source,terminal]
----
$ oc wait pod/spire-server-0 -n zero-trust-workload-identity-manager --for=delete --timeout=180s
----

. Delete the SPIRE server data PVC by running the following command:
+
[source,terminal]
----
$ oc delete pvc spire-data-spire-server-0 -n zero-trust-workload-identity-manager
----

. Scale the SPIRE server back to one replica by running the following command:
+
[source,terminal]
----
$ oc scale statefulset/spire-server -n zero-trust-workload-identity-manager --replicas=1
----

. Wait for the rollout by running the following command:
+
[source,terminal]
----
$ oc rollout status statefulset/spire-server -n zero-trust-workload-identity-manager
----

.Verification

* Confirm that the parent server signed the new CA by running the following command:
+
[source,terminal]
----
$ oc logs pod/spire-server-0 -c spire-server -n zero-trust-workload-identity-manager | grep "X509 CA"
----
+
The log includes `X509 CA prepared`, `self_signed=false`, and a non-empty `upstream_authority_id`.
