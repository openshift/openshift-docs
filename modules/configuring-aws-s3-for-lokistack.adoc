= Configure Amazon S3 for LokiStack

[role="_abstract"]
As a cluster administrator, you can use {aws-first} object storage to store logs. Amazon S3 is a well-tested and natively supported backend for LokiStack.

.Prerequisites
* You have an AWS account with permissions to create S3 buckets and IAM policies.
* You have created an S3 bucket.
* You have created IAM credentials with the required S3 API permissions. See the object storage permissions requirements.
* You have cluster administrator permissions.

.Procedure

. Create an object storage secret with the name `logging-loki-aws`:
+
--
For standard AWS authentication by using a public endpoint:
[source,terminal]
----
$ oc create secret generic logging-loki-aws \
  -n openshift-logging \
  --from-literal=bucketnames="<bucket_name>" \
  --from-literal=endpoint="https://s3.<region>.amazonaws.com" \
  --from-literal=access_key_id="<aws_access_key_id>" \
  --from-literal=access_key_secret="<aws_access_key_secret>" \
  --from-literal=region="<aws_region>"
----
where:

`bucketnames`::
  The name of your S3 bucket.

`endpoint`::
  The S3 endpoint URL. Use the format `\https://s3.<region>.amazonaws.com` for standard AWS regions.

`region`::
  The AWS region where your bucket is located (for example, `us-east-1`).

For private AWS S3 virtual private cloud (VPC) interface endpoints (AWS PrivateLink):
[source,terminal]
----
$ oc create secret generic logging-loki-aws \
  -n openshift-logging \
  --from-literal=bucketnames="<bucket_name>" \
  --from-literal=endpoint="https://bucket.vpce-<vpce_id>.s3.<region>.vpce.amazonaws.com" \
  --from-literal=access_key_id="<aws_access_key_id>" \
  --from-literal=access_key_secret="<aws_access_key_secret>" \
  --from-literal=region="<aws_region>"
----
where:

`endpoint`::
  The AWS S3 VPC interface endpoint URL. In environments requiring all traffic to stay within private network boundaries to comply with security policies or avoid NAT gateway data processing costs, use an AWS PrivateLink VPC interface endpoint URL with the virtual-hosted-style format: `\https://bucket.vpce-<vpce_id>.s3.<region>.vpce.amazonaws.com`. When configuring this URL, observe the following requirements:
+
* Use the literal prefix `bucket.`. Do not replace `bucket` with the actual name of your S3 bucket. The {loki-op} requires the literal prefix `bucket.vpce-<vpce_id>...` and rejects endpoint URLs that specify an actual bucket name as a prefix.
* The `<region>` specified in the `endpoint` URL must match the value provided in the `region` field. If the regions do not match, the {loki-op} rejects the secret with an error similar to `expected region <region>, got <extracted_region>`.
* Do not append a path or bucket name to the end of the `endpoint` URL.
* Path-style access is not supported for VPC interface endpoints. The `forcepathstyle` setting defaults to `false`, which is required for virtual-hosted-style VPC endpoints.

For clusters with Security Token Service (STS) enabled:
[source,terminal]
----
$ oc -n openshift-logging create secret generic logging-loki-aws \
  --from-literal=bucketnames="<s3_bucket_name>" \
  --from-literal=region="<bucket_region>" \
  --from-literal=audience="<oidc_audience>"
----
where:

`audience`::
  Optional OIDC audience annotation. Default value is `openshift`.
--

.Verification
Run the following command to verify that the secret was created successfully:
[source,terminal]
----
$ oc get secret logging-loki-aws -n openshift-logging
----
