= Connect a vLLM server through the OpenAI-compatible provider

[role="_abstract"]
To use a self-hosted vLLM server for autonomous and tool-calling workloads, configure {ols-long} autonomous agents with the `OpenAI` provider and the OpenAI-compatible API endpoint that vLLM exposes. You create a credentials secret, an `LLMProvider` custom resource (CR) that points to your vLLM endpoint, and an `Agent` CR that uses that provider.

Because {rhelai} ships a vLLM server, this pathway is also suitable for disconnected environments that host vLLM locally.

.Prerequisites

* You have installed the {ols-long} Operator.
* You have logged in to the cluster as a user with the `cluster-admin` role, or with permission to create cluster-scoped custom resources.
* You have a running vLLM server that exposes the OpenAI-compatible API endpoint, and the {ols-long} autonomous agents deployment can reach it over a secure connection.
* The model that your vLLM server serves supports function calling.
* You have the API key for your vLLM server, if the endpoint requires authentication.

.Procedure

. Create a credentials secret in the `openshift-lightspeed` namespace that contains the authentication details for your vLLM server:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: vllm-credentials
  namespace: openshift-lightspeed
type: Opaque
stringData:
  OPENAI_API_KEY: <api_key> # <1>
----
<1> The API key for your vLLM server. The provider sends this value as an `Authorization: Bearer <token>` header. If your vLLM endpoint does not require authentication, set this key to any non-empty placeholder value, such as `EMPTY`. The deployment requires `OPENAI_API_KEY` to be set to a non-empty value to pass its readiness check.

. Apply the secret by running the following command:
+
[source,terminal]
----
$ oc apply -f <secret_filename>.yaml
----

. Create an `LLMProvider` CR that uses the `OpenAI` type and points to your vLLM endpoint:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: LLMProvider
metadata:
  name: vllm-openai
spec:
  type: OpenAI
  openAI:
    credentialsSecret:
      name: vllm-credentials # <1>
    url: <vllm_endpoint_url> # <2>
----
<1> The name of the credentials secret that you created in the `openshift-lightspeed` namespace.
<2> The base URL of your vLLM server's OpenAI-compatible API endpoint, which typically ends in `/v1`, for example `https://<vllm_host>/v1`.

. Create an `Agent` CR that references the `LLMProvider` and specifies the model to use:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: Agent
metadata:
  name: default # <1>
spec:
  llmProvider:
    name: vllm-openai # <2>
  model: <model_name> # <3>
  maxTurns: 200
----
<1> The `default` agent must exist. The deployment uses it when a workflow step does not specify an agent.
<2> The name of the `LLMProvider` CR that you created.
<3> The identifier of the model that your vLLM server serves. The model must support function calling to participate in autonomous workflows.

. Apply the custom resources by running the following command:
+
[source,terminal]
----
$ oc apply -f <cr_filename>.yaml
----

.Verification

. Confirm that the `LLMProvider` and `Agent` resources exist by running the following commands:
+
[source,terminal]
----
$ oc get llmprovider vllm-openai
----
+
[source,terminal]
----
$ oc get agent default
----

. Submit a query that requires a tool call, and confirm that {ols-long} autonomous agents returns the tool result.
