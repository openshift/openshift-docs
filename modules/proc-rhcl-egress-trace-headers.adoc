= Prevent trace headers from reaching external services

[role="_abstract"]
Stop your egress `Gateway` object from sending the `traceparent`, `tracestate`, and `baggage` headers to external services. These headers expose details of your internal infrastructure, such as trace identifiers and internal state.

By default, {service-mesh} propagates trace context to upstream services. On an egress `Gateway` object, the upstream service is outside your cluster.

.Prerequisites

include::snippets/egress-gateway-prereqs.adoc[]

.Procedure

. Optional: To confirm that trace headers reach the external service, send a request to an endpoint that echoes the request headers by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc exec -n egress-test test-client -- \
    curl -sS "http://${EGRESS_IP}/headers" -H "Host: _<api.example.com>_" --max-time 10
----
+
Replace `_<api.example.com>_` with the hostname of your external service. The trace context is leaking if the response includes the `traceparent`, `tracestate`, or `baggage` headers.

. Create a `Telemetry` object that disables trace context propagation on the pods of your egress `Gateway` object by using the following example:
+
[source,yaml,subs="+quotes"]
----
apiVersion: telemetry.istio.io/v1
kind: Telemetry
metadata:
  name: _<egress_no_trace_propagation>_
  namespace: _<gateway_system>_
spec:
  selector:
    matchLabels:
      gateway.networking.k8s.io/gateway-name: _<kuadrant_egressgateway>_
  tracing:
    - disableContextPropagation: true
----
+
* Replace the `metadata.namespace` value with the namespace where you applied your egress `Gateway` object.
* Replace the `spec.selector.matchLabels` value with the name of your egress `Gateway` object. Without the selector, the setting applies to every proxy in the namespace, including the gateways that handle incoming traffic.
* This configuration stops the `traceparent`, `tracestate`, and `X-B3-*` headers from reaching external services, and keeps span reporting in place. Trace propagation from the `wasm-shim` module to Authorino and Limitador is unaffected, because the `wasm-shim` module adds trace context to the internal gRPC calls rather than to the outbound request.

. Apply the `Telemetry` object by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<egress_no_trace_propagation>_
----
+
Replace `_<egress_no_trace_propagation>_` with the name of the file that holds your telemetry configuration.

. To remove the `baggage` header, which the `disableContextPropagation` field does not cover, add a `RequestHeaderModifier` filter to each egress `HTTPRoute` object by using the following example:
+
[source,yaml]
----
filters:
  - type: RequestHeaderModifier
    requestHeaderModifier:
      remove:
        - baggage
----

. Apply the updated `HTTPRoute` object by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<api_external_httproute>_
----
+
Replace `_<api_external_httproute>_` with the name of the file that holds the `HTTPRoute` object of your external service.

.Verification

* Send a request to an endpoint that echoes the request headers by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc exec -n egress-test test-client -- \
    curl -sS "http://${EGRESS_IP}/headers" -H "Host: _<api.example.com>_" --max-time 10
----
+
The response no longer includes the `traceparent`, `tracestate`, or `baggage` headers.
