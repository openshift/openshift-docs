= Fixed issues

[role="_abstract"]
The following issues are fixed in this release of {LoggingProductName}. Some linked Jira tickets are accessible only with Red Hat credentials.

`log-file-metric-exporter` metrics server now enforces HTTP connection timeouts::
Before this update, the `log-file-metric-exporter` metrics server was configured without connection timeouts. As a consequence, slow or malicious clients could hold connections open indefinitely, exhausting file descriptors and goroutines in the exporter, which stopped log-volume metrics from being reported and could cause collector pods to restart. With this update, explicit timeouts are enforced for all HTTP connections to the metrics server. As a result, slow or malicious clients are disconnected within bounded time, protecting collector pod stability and ensuring that log-volume metrics continue to be reported.
+
https://redhat.atlassian.net/browse/LOG-9939[LOG-9939]

Collector pods no longer fail to start due to incompatible buffer state files after an upgrade::
Before this update, when upgrading with `AtLeastOnce` delivery mode and a LokiStack output configured, pre-existing on-disk buffer state files from a prior Vector version could cause collector pods to fail to start with the error `Configuration error. error=Sink "output_default_lokistack_audit": error occurred when building buffer`. As a consequence, log collection stopped on affected nodes and could not be restored without manual intervention. With this update, Vector handles incompatible buffer state files gracefully during startup. As a result, collector pods start successfully even when pre-existing buffer state files contain records from an incompatible prior version.
+
https://redhat.atlassian.net/browse/LOG-9942[LOG-9942]


Vector collector pods no longer enter `CrashLoopBackOff` due to duration arithmetic overflow::
Before this update, under certain filesystem state or timing conditions, a Rust integer arithmetic overflow in Vector's file-server duration tracking code caused the `vector-worker` thread to panic with `overflow when subtracting durations`. As a consequence, the collector pod entered `CrashLoopBackOff`, stopping log collection entirely on affected nodes. With this update, the duration subtraction uses saturating arithmetic that clamps to zero on underflow instead of panicking. As a result, Vector collector pods remain stable regardless of the filesystem state or timestamp conditions on the underlying node.
+
https://redhat.atlassian.net/browse/LOG-10093[LOG-10093]

Loki Operator now ships Loki 3.7.7::
Before this update, the Loki Operator shipped an earlier version of Loki. As a consequence, users were not receiving the bug fixes, performance improvements, and security patches included in Loki 3.7.7. With this update, the migration to the `thanos-io/objstorage` backend is backported to enable the Loki version update, and the Loki Operator ships Loki 3.7.7. As a result, all Loki components run version 3.7.7, incorporating upstream improvements from that release.
