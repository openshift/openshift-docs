== Fixed issues

* Before this update, Image-Based Installation (IBI) with a proxy configuration wrote the user-provided `noProxy` value directly into the cluster configuration without adding the cluster, service, and machine network Classless Inter-Domain Routing (CIDR) blocks and internal host names required for in-cluster communication. As a consequence, the `noProxy` value did not match the proxy settings applied by the Machine Config Operator template, causing the Operator to detect a configuration drift and trigger an additional node reboot during installation. With this release, IBI enriches the `noProxy` setting by using the same logic as standard installations, aligning the initial proxy configuration with the Machine Config Operator template and preventing the extra reboot. (link:https://issues.redhat.com/browse/OCPBUGS-112324[OCPBUGS-112324])

* Before this update, the web console required cloud credentials during Operator installation on Workload Identity clusters. As a consequence, users could not install certain Operators such as External Secrets Operator or cert-manager through the OperatorHub Console on clusters running in cloud-specific Workload Identity or Federated Identity modes. With this release, cloud provider fields are optional during Operator installation on Workload Identity clusters. As a result, Operators can be installed successfully without requiring cloud credentials. (link:https://issues.redhat.com/browse/OCPBUGS-114054[OCPBUGS-114054])

* Before this update, the `EventRecorder` component of the Machine Config Operator was incorrectly initialized and prevented emission of the `drain-failure` events when a drain operation failed. As a consequence, administrators did not receive proper event notifications when node drains were blocked by the `PodDisruptionBudgets` or other policies, making it difficult to troubleshoot drain failures. With this release, the `EventRecorder` component is properly initialized to emit drain events. As a result, `drain-failure` events are successfully emitted and visible in cluster events, improving observability of drain operations. (link:https://issues.redhat.com/browse/OCPBUGS-114390[OCPBUGS-114390])

* Before this update, in vSphere installer-provisioned infrastructure clusters using static IPs, the control plane machine set (CPMS) Operator was not copying the name server into the CPMS when the CPMS was deleted. As a consequence, the CPMS Operator would identify current control plane machines as not valid and would identify the control plane machines as needing to be re-created. With this release, the CPMS Operator logic is updated to copy the name server definition into the CPMS when the clusters used static IPs. As a result, the name server information is configured in the CPMS when re-creating the CPMS cluster instance. (link:https://issues.redhat.com/browse/OCPBUGS-114721[OCPBUGS-114721])

* Before this update, the Node Tuning Operator reconciliation used the rate-limited work queue for all event enqueues. As a consequence, node-tuning configuration was delayed for cluster nodes greater than 100. With this release, the Node Tuning Operator reconciliation loop uses the rate-limited work queue only for failures instead of all event enqueues. As a result, node-tuning configuration for cluster nodes greater than 100 is not delayed. (link:https://issues.redhat.com/browse/OCPBUGS-114730[OCPBUGS-114730])

* Before this update, the short description for the `info` command in the Performance Profile Creator (PPC) tool was not updated after the cluster inspection was moved. As a consequence, inconsistencies between the parent help and the info help occurred when you ran the PPC tool. With this release, the short description for the `info` command in the PPC tool is updated to match the current CLI. As a result, the help inconsistencies do not occur when you run the tool. (link:https://issues.redhat.com/browse/OCPBUGS-115719[OCPBUGS-115719])

* Before this update, the collection and emission of SELinux conflict metrics was inefficient and consumed excessive system resources. As a consequence, cluster performance degraded during metric collection cycles, leading to delayed reporting and high CPU overhead. With this release, the collection and emission logic is optimized to streamline data processing. As a result, metric collection is significantly faster, improving overall cluster performance and responsiveness. (link:https://issues.redhat.com/browse/OCPBUGS-117657[OCPBUGS-117657])
