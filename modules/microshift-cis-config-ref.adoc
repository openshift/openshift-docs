= CIS Level 2 firewall and configuration reference for {microshift-short}

[role="_abstract"]
Use this reference when you prepare a CIS Level 2 host for {microshift-short}.
It summarizes required firewall access, playbook overrides, OpenSCAP profile names, expected CIS rule failures, and common remediation steps.

[id="microshift-cis-config-ref-firewall_{context}"]
== Required firewall access

CIS hardening enables `firewalld` and denies traffic by default.
Configure the following access for {microshift-short}:

.Required trusted sources
[cols="2,1,3",options="header"]
|===
|Source |Required |Description

|`10.42.0.0/16` or your custom cluster network CIDR
|Yes
|Host-network pod access to other pods

|`169.254.169.1`
|Yes
|Host-network pod access to the {product-title} API server
|===

.Common optional ports
[cols="1,1,3",options="header"]
|===
|Port |Protocol |Description

|`80`
|TCP
|HTTP applications through the router

|`443`
|TCP
|HTTPS applications through the router

|`6443`
|TCP
|HTTPS API server access

|`30000`-`32767`
|TCP or UDP
|`NodePort` services
|===

For complete firewall procedures, see the {microshift-short} firewall documentation.

[id="microshift-cis-config-ref-overrides_{context}"]
== Hardening playbook overrides

Set the following Ansible role variables to `false` so that the CIS role does not disable IP forwarding:

For {op-system-base} {op-system-version-major}:

* `sysctl_net_ipv4_ip_forward`
* `sysctl_net_ipv6_conf_all_forwarding`

For {op-system-base} {op-system-version-major-10}:

* `sysctl_net_ipv4_ip_forward`
* `sysctl_net_ipv4_conf_all_forwarding`
* `sysctl_net_ipv4_conf_default_forwarding`
* `sysctl_net_ipv6_conf_all_forwarding`
* `sysctl_net_ipv6_conf_default_forwarding`

[id="microshift-cis-config-ref-troubleshooting_{context}"]
== Troubleshooting

Pods cannot reach other pods or the API server::
Verify that `firewalld` trusts the cluster network CIDR and `169.254.169.1`, then reload the firewall.

Ingress routes are unreachable::
Open router ports such as `80/tcp` and `443/tcp` in the appropriate firewall zone.

OpenSCAP reports IP forwarding failures after {microshift-short} starts::
Expected.
OVN-Kubernetes requires IP forwarding.
Ensure your hardening playbook used the documented overrides so that the CIS role does not fight {microshift-short} at boot.

`audit_rules_privileged_commands` fails after RPM install::
Regenerate and load privileged-command audit rules after you install {microshift-short} packages.

Networking fails immediately after CIS hardening::
Confirm that the playbook set the IP forwarding role variables to `false` and that {microshift-short} has started so that it can enable forwarding.
