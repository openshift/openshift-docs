= Simulating an etcd failure

[role="_abstract"]
To test your cluster restore workflow, you first simulate an etcd failure on nonrecovery nodes.

[IMPORTANT]
====
You must have SSH access to the cluster. Without SSH access, you cannot disable etcd or manage the `kubelet` service on nonrecovery nodes.
====

.Prerequisites

* You have SSH access to control plane hosts.
* You have installed the {oc-first}.

.Procedure

. Use SSH to connect to each of your nonrecovery nodes to disable etcd and the `kubelet` service:

.. Disable etcd by running the following command:
+
[source,terminal]
----
$ sudo /usr/local/bin/disable-etcd.sh
----

.. Delete variable data for etcd by running the following command:
+
[source,terminal]
----
$ sudo rm -rf /var/lib/etcd
----

.. Disable the `kubelet` service by running the following command:
+
[source,terminal]
----
$ sudo systemctl disable kubelet.service --now
----

. Exit every SSH session.

. Ensure that your nonrecovery nodes are in a `NOT READY` state by running the following command:
+
[source,terminal]
----
$ oc get nodes
----

.Next steps

* Restore to an earlier cluster state by using an etcd backup.
