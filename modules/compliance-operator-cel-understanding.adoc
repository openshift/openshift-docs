= CEL profiles and the Compliance Operator

[role="_abstract"]
The Compliance Operator Common Expression Language (CEL) scanner evaluates custom platform checks that you define with `CustomRule` objects and enable in `TailoredProfile` objects.

The Common Expression Language (CEL) is a lightweight expression language that {product-title} also uses for API validation.
In the Compliance Operator, CEL expressions run against Kubernetes API resources that you declare in each rule's `inputs` field.
CEL profiles complement, but do not replace, Extensible Configuration Checklist Description Format (XCCDF) profiles that OpenSCAP evaluates on nodes and the platform.

[id="compliance-operator-cel-understanding-workflow_{context}"]
== How CEL tailored profiles work

A CEL tailored profile combines the following objects:

`CustomRule`:: Defines a single CEL check, including the expression, severity, and Kubernetes resources to evaluate.
`TailoredProfile`:: Selects which `CustomRule` or CEL `Rule` objects to run and sets the scan type with the `compliance.openshift.io/product-type` annotation.
`ScanSettingBinding`:: Binds the tailored profile to a `ScanSetting` object and starts a compliance scan.
`ComplianceCheckResult`:: Stores the `PASS` or `FAIL` outcome for each enabled rule after the scan completes.

You can combine multiple `CustomRule` objects in one `TailoredProfile` when every rule uses the CEL scanner.
Leave `spec.extends` empty when you build a profile only from custom CEL rules.
To customize a shipped CEL `Profile` object, set `spec.extends` to that profile name and use `enableRules` or `disableRules` with `kind: Rule` entries that reference CEL rules only.

For general tailoring concepts that apply to OpenSCAP profiles, see the tailoring documentation in Additional resources.
