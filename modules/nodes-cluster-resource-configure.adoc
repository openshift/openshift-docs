= Configuring single-profile mode overcommit

[role="_abstract"]
You can configure the Cluster Resource Override Operator to help control overcommit on all opted-in namespaces in your cluster.

You set cluster-wide ratios on the `ClusterResourceOverride` object named `cluster` and opt in each project where you want the Operator to control overcommit by adding a namespace label. 

After you create the `ClusterResourceOverride` object and apply the `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled: "true"` label to a namespace, the Operator modifies only new pods that in the labeled namespace. The Operator does not modify pods in the namespace that are already running.

.Prerequisites

* The Cluster Resource Override Operator must be installed.

* Default container limits are specified in a `LimitRange` object for the project, or limits are configured in `Pod` specs, if you use `memoryRequestToLimitPercent`, `cpuRequestToLimitPercent`, or `limitCPUToMemoryPercent`.

.Procedure

. Change to the `clusterresourceoverride-operator` namespace.
+
[source,terminal]
----
$ oc project clusterresourceoverride-operator
----

. Configure single-profile mode by creating a cluster-wide `ClusterResourceOverride` object:

.. Create a YAML file similar to the following:
+
[source,yaml]
----
apiVersion: operator.autoscaling.openshift.io/v1
kind: ClusterResourceOverride
metadata:
    name: deployment
spec:
  podResourceOverride:
    spec:
      memoryRequestToLimitPercent: 50
      cpuRequestToLimitPercent: 25
      limitCPUToMemoryPercent: 200
----
+
where
+
--
`metadata.name`:: Specifies a name for the CR. Must be `cluster` for the legacy single-profile mode.
`spec.podResourceOverride.spec.memoryRequestToLimitPercent`:: Specifies the percentage to override the container memory limit, if used, between 1-100. The default is `50`. This parameter is optional.
`spec.podResourceOverride.spec.cpuRequestToLimitPercent`:: Specifies the percentage to override the container CPU limit, if used, between 1-100. The default is `25`. This parameter is optional.
`spec.podResourceOverride.spec.limitCPUToMemoryPercent`:: Specifies the percentage to override the container memory limit, if used. Scaling 1 Gi of RAM at 100 percent is equal to 1 CPU core. This is processed before overriding the CPU request, if configured. The default is `200`. This parameter is optional.
--
+
.. Create the pod by running the following command:
+
[source,terminal]
----
$ oc create -f <file_name>.yaml
----
+
For example:
+
[source,terminal]
----
$ oc create -f cro-cr.yaml
----

. Ensure the following label has been added to the Namespace object for each project where you want the Cluster Resource Override Operator to control overcommit:
+
[source,yaml]
----
apiVersion: v1
kind: Namespace
metadata:

# ...

  labels:
    clusterresourceoverrides.admission.autoscaling.openshift.io/enabled: "true"

# ...
----
+
where:
+
--
`metadata.labels.clusterresourceoverrides.admission.autoscaling.openshift.io/enabled: "true"`:: Specifies that you want to use the Cluster Resource Override Operator with this project.
--
