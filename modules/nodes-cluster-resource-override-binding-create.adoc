= Creating a ClusterResourceOverrideBinding object

[role="_abstract"]
To assign a `ClusterResourceOverride` profile to specific namespaces and optionally filter which pods receive the override, you can create a `ClusterResourceOverrideBinding`. A cluster resource override binding is required when using the Cluster Resource Override Operator in multi-profile mode.

.Prerequisites

* You have created one or more `ClusterResourceOverride` profiles in the `openshift-cluster-resource-override` namespace.
* You have access to the cluster as a user with the `cluster-admin` role.

.Procedure

. Create a `ClusterResourceOverrideBinding` object for the Cluster Resource Override Operator:

.. Create a YAML file similar to the following:
+
[source,yaml]
----
apiVersion: operator.autoscaling.openshift.io/v1
kind: ClusterResourceOverrideBinding
metadata:
  name: production-binding
spec:
  overrideRef: production-profile
  namespaceSelector:
    matchLabels:
      environment: production
----
+
where:
+
--
`metadata.name`:: Specifies a unique name for this binding.
`spec.overrideRef`:: Specifies the name of the `ClusterResourceOverride` profile to apply.
`spec.namespaceSelector`:: Specifies label selectors to match namespaces. Use `matchLabels` for exact matches or `matchExpressions` for complex selections.
`spec.podSelector`:: (Optional) Specifies label selectors to match pods within the selected namespaces. Pods that do not match are not mutated. When omitted, all pods in matching namespaces are mutated.
--

.. Optional: To restrict the override to specific pods within the matching namespaces, add a `podSelector`:
+
[source,yaml]
----
apiVersion: operator.autoscaling.openshift.io/v1
kind: ClusterResourceOverrideBinding
metadata:
  name: api-server-binding
spec:
  overrideRef: development-profile
  namespaceSelector:
    matchLabels:
      environment: development
  podSelector:
    matchLabels:
      tier: application
----

.. Create the binding:
+
[source,terminal]
----
$ oc create -f <file-name>.yaml
----
+
For example:
+
[source,terminal]
----
$ oc create -f cro-binding.yaml
----

.Verification

. Check that the binding was created:
+
[source,terminal]
----
$ oc get clusterresourceoverridebindings
----

. Check that pods in the selected namespaces are receiving the override by checking the pod spec:
+
[source,terminal]
----
$ oc get pod <pod-name> -n <namespace> -o yaml
----
+
The output should show modified resource requests and limits according to the applied profile.
