= Logging capability in the ObservabilityInstaller CRD

[role="_abstract"]
The `ObservabilityInstaller` custom resource definition (CRD) provides a simplified method for deploying the full logging stack on {product-title}. When you enable the logging capability, the {coo-full} automatically installs and configures the required Operators and operands.

[IMPORTANT]
====
The `ObservabilityInstaller` logging capability is a Technology Preview feature only. Technology Preview features are not supported with Red Hat production service level agreements (SLAs) and might not be functionally complete. Red Hat does not recommend using them in production. These features provide early access to upcoming product features, enabling customers to test functionality and provide feedback during the development process.
====

When you create an `ObservabilityInstaller` resource with `spec.capabilities.logging.enabled: true`, the {coo-short} deploys the following components in the `observability` namespace:

* The {loki-op}, which manages the `LokiStack` log store
* The {clo}, which manages log collection and forwarding
* A `LokiStack` instance configured with the object storage you specify
* A `ClusterLogForwarder` that collects application and infrastructure logs and forwards them to the {coo-short}-managed `LokiStack`
* The logging UI plugin, which adds a *Logs* tab to the {product-title} web console

The `ClusterLogForwarder` collects application and infrastructure logs only. Audit logs are not collected, and the `ObservabilityInstaller` forwards logs only to the `LokiStack` it manages. Custom log forwarding outputs are not supported in this configuration.

Use the `ObservabilityInstaller` when you want a simplified, preconfigured logging installation. Use the manual installation method when you require audit log collection, custom log forwarding, or fine-grained control over the `LokiStack` configuration.
