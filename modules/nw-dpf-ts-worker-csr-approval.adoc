= Worker node CSR approval failures

[role="_abstract"]
If worker node certificate signing requests (CSRs) are not being approved automatically, verify the approval process, network connectivity, and authentication configuration.

Check pending CSRs on management cluster::
List all pending CSRs on the management cluster:
+
[source,terminal]
----
$ oc get csr | grep Pending
----
+
Manually approve CSRs if automatic approval is not working:
+
[source,terminal]
----
$ oc adm certificate approve <csr-name>
----

Verify CSR approval automation::
Check if the CSR approval process is configured correctly:
+
[source,terminal]
----
$ oc get clusterrolebinding | grep csr
----
+
Ensure that the appropriate service accounts have CSR approval permissions.

Check worker node bootstrap process::
Verify that worker nodes have the correct bootstrap configuration:
+
[source,terminal]
----
$ oc debug node/<worker-node-name>
----
+
[source,terminal]
----
sh-4.4# chroot /host
sh-4.4# cat /etc/kubernetes/bootstrap-secrets/kubeconfig
----
+
Ensure that the bootstrap kubeconfig is valid and accessible.

Verify network connectivity for CSR submission::
Check that worker nodes can reach the API server for CSR submission:
+
[source,terminal]
----
sh-4.4# curl -k https://<api-server-url>:6443/healthz
----
+
Ensure that firewall rules allow CSR traffic from worker nodes.

Check HBN bridge configuration::
Verify that the Host-Based Networking bridge is correctly configured:
+
[source,terminal]
----
$ oc get pods -n openshift-hbn -o wide
----
+
Ensure that HBN pods are running and the `br-dpu` bridge is active:
+
[source,terminal]
----
sh-4.4# ip link show br-dpu
----

Review kubelet logs for CSR errors::
Check kubelet logs for CSR submission errors:
+
[source,terminal]
----
sh-4.4# journalctl -u kubelet | grep -i csr
----
+
Look for authentication failures or network connectivity issues during CSR submission.
