= Bug fixes and security updates in version 4.11.6

[role="_abstract"]
This release includes the following enhancements and bug fixes:

//ROX-35019
* With this release, Red{nbsp}Hat improved vulnerability reporting accuracy for Red{nbsp}Hat container images. Scanner V4 now prioritizes vulnerability data from Red{nbsp}Hat Vulnerability Exploitability eXchange (VEX) over OSV.dev data when both sources report the same vulnerability. As a result, you receive severity assessments and CVSS scores that reflect Red{nbsp}Hat's product-specific security analysis.

//ROX-37265
* With this release, Red{nbsp}Hat improved the behavior of the `ROX_SCANNER_V4_RED_HAT_LAYERS_RED_HAT_VULNS_ONLY` flag that you can set to `true` to limit vulnerability reporting for Red{nbsp}Hat images to Red{nbsp}Hat security data only. Previously, users who configured this variable set it on the Scanner V4 matcher deployment, and that is still supported. However, to take advantage of the improvements, you must now set the flag on the Central deployment. Note that configuring this flag can lead to unintended results, such as false negatives, and Red{nbsp}Hat recommends configuring it only for specific situations. See the guidance in the following documentation:

** link:https://access.redhat.com/solutions/7141930[Discrepancy in CVE reported in RHACS and RedHat catalog Image]
** link:https://access.redhat.com/solutions/7129189[Why does RHACS give OSV or NVD’s CVSS scores instead of Red Hat’s?]

//ROX-35020
* With this release, Red{nbsp}Hat added transparency to vulnerability reporting. The vulnerability details now include a *CVE Origin* field. This field identifies the source of the vulnerability data. As a result, you can distinguish between Red{nbsp}Hat-authoritative assessments and community-sourced vulnerability data.
+
[NOTE]
====
The origin field will be set to "Other" for all existing scans. After upgrading to this release, as images are re-scanned by Scanner V4, the origin field will be updated.
====

//ROX-37293
* Fixed a bug that caused suppression of OSV.dev data for Red{nbsp}Hat content to intermittently not work as expected. 

//ROX-36432
* Before this update, some nodes displayed stale scan timestamps even though Central continued to update the node regularly. This occurred when users created the default Scanner V4 integration before node scanning was available and it lacked the NODE_SCANNER category. With this release, Red{nbsp}Hat fixed the integration reconciliation logic. As a result, node scan timestamps update correctly.

//ROX-37454
* With this release, Red{nbsp}Hat updated the {product-title-short} Operator metadata in OperatorHub. The documentation link now points to the correct version, and the Console Plugin is no longer labeled as Technology Preview. As a result, users installing from OperatorHub receive accurate product information.

This release also addresses the following security vulnerabilities:

//ROX-37347
* Central issues new authentication tokens in case of SAML response replay (link:https://access.redhat.com/security/cve/CVE-2026-103314[CVE-2026-103314])
