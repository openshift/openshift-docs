= Enable cross-cluster service discovery for SPIRE-federated meshes

[role="_abstract"]

Configure remote secrets to enable each cluster's {istio} control plane to discover and communicate with services on the other cluster.
Remote secrets contain credentials that allow the control planes to query each other's Kubernetes API servers for service endpoints.

.Prerequisites

* You have installed {istio} on both clusters with SPIRE integration and federation support.
* You have deployed East-West gateways on both clusters.
* You have set the required environment variables for both clusters.

.Procedure

. Create a remote secret on Cluster B that provides access to Cluster A's API server:
+
[source,terminal]
----
$ export KUBECONFIG="${CLUSTER_A_KUBECONFIG}"
$ istioctl create-remote-secret \
  --name=cluster-a \
  --context=$(oc config current-context) | \
  kubectl apply -f - --kubeconfig="${CLUSTER_B_KUBECONFIG}" -n ${OSSM_NS}
----
+
This command extracts the Kubernetes API server credentials from Cluster A and creates a secret on Cluster B.
The {istio} control plane on Cluster B uses this secret to discover services running on Cluster A.

. Create a remote secret on Cluster A that provides access to Cluster B's API server:
+
[source,terminal]
----
$ export KUBECONFIG="${CLUSTER_B_KUBECONFIG}"
$ istioctl create-remote-secret \
  --name=cluster-b \
  --context=$(oc config current-context) | \
  kubectl apply -f - --kubeconfig="${CLUSTER_A_KUBECONFIG}" -n ${OSSM_NS}
----
+
This command extracts the Kubernetes API server credentials from Cluster B and creates a secret on Cluster A.
The {istio} control plane on Cluster A uses this secret to discover services running on Cluster B.

.Verification

. Verify the remote secret exists on Cluster A:
+
[source,terminal]
----
$ export KUBECONFIG="${CLUSTER_A_KUBECONFIG}"
$ oc get secret istio-remote-secret-cluster-b -n ${OSSM_NS}
----

. Verify the remote secret exists on Cluster B:
+
[source,terminal]
----
$ export KUBECONFIG="${CLUSTER_B_KUBECONFIG}"
$ oc get secret istio-remote-secret-cluster-a -n ${OSSM_NS}
----
+
Both secrets should exist before proceeding to deploy cross-cluster workloads.
