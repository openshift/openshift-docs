= Sparse manifests in oc-mirror plugin v2

[role="_abstract"]
You can use sparse manifests in oc-mirror plugin v2 to mirror only the compute architectures your disconnected cluster uses, while keeping the manifest list and its digest unchanged.

Many {product-title} images, including release payloads and Operator images, ship as multi-architecture manifest lists. Each manifest list is a single top-level object that references per-architecture manifests for variants such as `amd64`, `arm64`, `ppc64le`, and `s390x`. Each per-architecture manifest points to the image blobs for that architecture.

[id="oc-mirror-sparse-manifest-behavior_{context}"]
== How sparse manifests work

A sparse manifest keeps the original manifest list and its digest. The manifest list still declares every supported architecture, but the mirror registry stores and serves blobs only for the architectures you mirrored.

For example, when you mirror only `amd64`, the sparse manifest in the mirror registry might look like the following:

.Sparse manifest registry state when mirroring `amd64` only
[cols="1,1,1",options="header"]
|===
|Architecture |Blobs |Mirror status

|`amd64`
|Present
|Mirrored

|`arm64`
|Not present
|Not mirrored

|`ppc64le`
|Not present
|Not mirrored

|`s390x`
|Not present
|Not mirrored
|===

[IMPORTANT]
====
Sparse manifests require a mirror registry that supports sparse manifest lists and allows manifest list validation checks to be disabled. Registries that require every child manifest referenced in a manifest list to be present reject or break sparse manifests.
====
