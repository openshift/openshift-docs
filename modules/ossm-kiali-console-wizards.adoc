= Configuration wizards

[role="_abstract"]

Wizards in the console create, update, and delete {istio} routing objects without writing YAML first. The wizard writes the same custom resources that you can later edit in the YAML editor. Saving requires permission to create or update that resource in the namespace on {ocp-product-title}.

Open a wizard from the *Actions* menu on a service, a workload, or a namespace.

== Service actions

Request routing:: Create ordered routing rules. Each rule has an optional request match on HTTP headers, URI, scheme, method, or authority, and a set of destination weights. {istio} applies the first matching rule.

Fault injection:: Inject an HTTP delay or abort a request with a status code so you can test how a service handles failures.

Traffic shifting:: Send a percentage of HTTP or TCP traffic to each workload version.

Request timeouts:: Set an HTTP timeout and a retry policy.

Gateways:: In advanced options, expose the service through an existing gateway or create a gateway.

Circuit breaker:: In advanced options, set a connection pool and outlier detection for an upstream host.

Traffic policy:: In advanced options, set TLS, load balancing, and generate a `PeerAuthentication` object for the service.

The wizard shows a YAML preview. You can edit that YAML before you create the object.

== Workload and namespace actions

On a workload, you can enable or disable sidecar injection on that workload, even when the namespace default is different.

On a namespace, you can open the graph, applications, workloads, services, or {istio} configuration for that namespace. You can also label the namespace for sidecar injection, label it for a canary {istio} revision, or generate traffic policies from the traffic that the graph currently shows. Generated traffic policies create `AuthorizationPolicy` objects that allow only the communication that is already in the graph.
