= Storage requirements

[role="_abstract"]
The hosting cluster must have a storage solution that supports VM disk images and meets the latency requirements of `etcd`.

Use {lvms-first} backed by NVMe drives for virtualized control plane storage.
{lvms} writes directly to local disks, providing the consistent low latency that `etcd` requires.
Use dedicated NVMe drives for control plane VM disks to ensure predictable performance.

[IMPORTANT]
====
Do not use {odf-first} for control plane VM disk storage.
{odf-short} replicates data across multiple storage nodes, which can cause unpredictable latency spikes during synchronization that affect `etcd` performance.
====

During installation of the virtualized control plane, KubeVirt Redfish requires a shared storage location for the installation ISO.
When the installer mounts boot media through the Redfish API, KubeVirt Redfish creates a data volume, downloads the installation ISO into that volume, and attaches the volume to the VM as virtual media.
Because control plane VMs can be scheduled on any worker node in the hosting cluster, the storage location for the installation ISO must be accessible from all nodes.
Do not use a node-local storage class such as {lvms} for this volume.
