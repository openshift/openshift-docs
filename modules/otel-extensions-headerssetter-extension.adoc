= Headers Setter Extension

[role="_abstract"]
The Headers Setter Extension sets headers on the outgoing requests of exporters. You can use this extension to send a tenant ID or an API key to a backend. For example, you can set the `x-scope-orgid` header for a multitenant backend.

:FeatureName: The Headers Setter Extension
include::snippets/technology-preview.adoc[]
:!FeatureName:

The extension acts as an authenticator for an exporter that supports the `auth` setting, such as the OTLP gRPC Exporter and the OTLP HTTP Exporter. You can take the value of a header from one of the following sources:

* A static string.
* A file, which the extension watches for changes. For example, you can mount a Kubernetes secret that is rotated.
* A header or other metadata of the request that the Collector received.

The following `OpenTelemetryCollector` custom resource configures the Headers Setter Extension to forward the `x-scope-orgid` header of incoming requests and to set two more headers:

[source,yaml]
----
# ...
  config:
    extensions:
      headers_setter:
        headers:
          - key: x-scope-orgid
            action: upsert
            from_context: x-scope-orgid
            default_value: <default_tenant>
          - key: x-environment
            action: upsert
            value: <environment_name>
          - key: x-api-key
            action: upsert
            value_file: <path_to_file>

    receivers:
      otlp:
        protocols:
          grpc:
            include_metadata: true

    processors:
      batch:
        metadata_keys:
          - x-scope-orgid

    exporters:
      otlp:
        endpoint: "<endpoint>"
        auth:
          authenticator: headers_setter

    service:
      extensions: [headers_setter]
      pipelines:
        traces:
          receivers: [otlp]
          processors: [batch]
          exporters: [otlp]
# ...
----
where:

`headers`:: Required. The list of headers to set.
`key`:: Required. The name of the header. Use lowercase names, because the Collector reads the metadata of gRPC requests with lowercase keys.
`action`:: How to set the header. The supported values are `insert`, `update`, `upsert`, and `delete`. The default value is `upsert`.
`value`:: A static value for the header.
`value_file`:: The path to a file with the value of the header. The extension reloads the file when it changes. Mount the file into the Collector pod, for example from a secret, by using the `volumes` and `volumeMounts` fields of the custom resource.
`from_context`:: The name of a header or other metadata of the request that the Collector received. The receiver must set the `include_metadata` field to `true`.
`default_value`:: The value to use when `from_context` does not find the header in the request.
`include_metadata`:: Set this field to `true` on the protocol of the receiver, such as `grpc`, so that the headers of incoming requests are available to the `from_context` field.
`metadata_keys`:: The request metadata keys that the Batch Processor uses to group telemetry data. Telemetry data with different values for these keys is not batched together.
`authenticator`:: The ID of the Headers Setter Extension. Set this field on the exporter.

Set exactly one of the following fields for each header: `value`, `value_file`, or `from_context`. The Collector does not start if a header has more than one value source.

[WARNING]
====
If your pipeline includes the Batch Processor and you use the `from_context` field, set the `metadata_keys` field of the Batch Processor to the headers that you read. Otherwise, the Batch Processor drops the metadata of the incoming requests, and the header is missing or uses the value of `default_value`.
====
