= Configuring StatefulSet-based controller sharding

[role="_abstract"]
You can configure the {pipelines-title} controller to use StatefulSet-based ordinal sharding instead of leader election. StatefulSet sharding improves `PipelineRun` throughput for high-concurrency workloads by distributing work evenly across all replicas.

Before you enable StatefulSet sharding, consider the following capacity and operational guidance:

* *Memory and CPU:* Plan for an estimated 12% memory overhead increase and higher CPU utilization across controller replicas.
* *Cluster load:* Monitor `etcd` latency, API server request rates, and controller workqueue depth when deploying multiple sharded replicas in production.

.Prerequisites

* You have administrator access to the {product-title} cluster.
* You have installed the OpenShift CLI (`oc`).

.Procedure

. Patch the `TektonConfig` custom resource to enable `statefulset-ordinals` and set equal values for `replicas` and `buckets`:
+
[source,terminal]
----
$ oc patch tektonconfig config --type merge -p '{"spec":{"pipeline":{"performance":{"statefulset-ordinals":true,"replicas":3,"buckets":3}}}}'
----
+
[IMPORTANT]
====
The value of `buckets` **must be equal** to the value of `replicas`. Matching these values is required for correct hash-based work distribution across controller pods.
====

. Verify that the controller pods are updated and running:
+
[source,terminal]
----
$ oc get pods -n openshift-pipelines -l app=tekton-pipelines-controller
----
