= {cgu-operator-full}

[role="_abstract"]
{cgu-operator-full} is an Operator that runs on the {product-title} hub cluster to manage the progressive rollout of cluster upgrades, Operator upgrades, and configuration changes to managed cluster fleets. 

It supports configurable batch sizes, per-cluster labeling, and optional pre-caching of images before upgrades.

New in this release::

* {cgu-operator} events are now generally available.
{cgu-operator} emits Kubernetes events during `ClusterGroupUpgrade` reconciliation that you can consume with event-driven automation to trigger custom integrations.

Description::
+
--
{cgu-operator} is an Operator that runs only on the hub cluster for managing how changes like cluster upgrades, Operator upgrades, and cluster configuration are rolled out to the network. {cgu-operator} supports the following features:

* Progressive rollout of policy updates to fleets of clusters in user configurable batches.
* Per-cluster actions add `ztp-done` labels or other user-configurable labels following configuration changes to managed clusters.
* {cgu-operator} supports optional pre-caching of {product-title}, {olm} Operator, and additional images to {sno} clusters before initiating an upgrade. The pre-caching feature is not applicable when using the recommended image-based upgrade method for upgrading {sno} clusters.
** Specifying optional pre-caching configurations with `PreCachingConfig` CRs.

** Configurable image filtering to exclude unused content.

** Storage validation before and after pre-caching, using defined space requirement parameters.

* Kubernetes events emitted at global, batch, and per-cluster scope during policy remediation.
You can consume these events with Event Driven Ansible to trigger automation when clusters finish remediation, instead of polling the hub cluster for state.
--

Limits and requirements::

* {cgu-operator} supports concurrent cluster upgrades in batches of 500.
* Pre-caching is limited to {sno} cluster topology.
* Consuming {cgu-operator} events from outside the hub cluster requires the Multicluster Global Hub Operator, which republishes the events to Kafka in `CloudEvents` format.
This reference design covers only this consumption path.
* When the Multicluster Global Hub agent runs on the same hub cluster as {cgu-operator}, you must set `installAgentOnLocal` to `true` in the `MulticlusterGlobalHub` CR to forward local events to the Kafka bus.
* Retention of events on the hub cluster is governed by the API server `--event-ttl` setting.
Do not treat the hub cluster as a durable event store.

Engineering considerations::

* The `PreCachingConfig` custom resource (CR) is optional. You do not need to create it if you want to pre-cache platform-related images only, such as {product-title} and {olm}.
* {cgu-operator} supports the use of hub-side templating with Red Hat Advanced Cluster Management policies.
* Use the `reason` and `action` fields to identify {cgu-operator} events in automation.
Event message text is intended for human readers, is capped at 1024 bytes, and is not a stable interface.
* {cgu-operator} emits `CguSuccess` at cluster, batch, and global scope, and emits `CguTimedout` at both batch and global scope.
Filter on the `cgu.openshift.io/event-type` annotation so that a single outcome does not trigger automation more than once.
* Annotations that carry cluster or policy lists are truncated to stay within the Kubernetes 64 KiB annotation size limit.
When truncation occurs, {cgu-operator} adds the `cgu.openshift.io/truncated` annotation with the name of the truncated annotation as its value.
Account for this when you consume the `cgu.openshift.io/batch-clusters` annotation at large batch sizes.
* {cgu-operator} does not emit a per-cluster timeout event.
Clusters that time out produce a cluster-scoped start event with no corresponding terminal event.
Track timeouts by using the batch-scoped and global `CguTimedout` events.
* Configuration of Event Driven Ansible, Ansible Automation Platform, and the Kafka broker is outside the scope of this reference specification.
