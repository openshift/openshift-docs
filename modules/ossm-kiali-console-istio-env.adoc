= {istio} labels and console actions

[role="_abstract"]

The console expects the `app` and `version` labels that {istio} adds to telemetry. If the mesh uses a different pair, such as `app.kubernetes.io/name` and `app.kubernetes.io/version`, set that pair in the `Kiali` custom resource. The console accepts one pair for the whole mesh. It cannot use `app` on some workloads and `app.kubernetes.io/name` on others.

[source,yaml]
----
spec:
  istio_labels:
    app_label_name: app
    version_label_name: version
----

{KialiServer} detects the root namespace of each {istio} control plane. You do not set `external_services.istio.root_namespace`. That field was removed in Kiali 2.16. Validations that depend on mesh-wide defaults use the detected root namespace.

The console can label a namespace for sidecar injection. That action is on by default. Turn it off with `spec.kiali_feature_flags.istio_injection_action: false`.

Canary upgrade actions are off by default. Set `spec.kiali_feature_flags.istio_upgrade_action` to `true` to show them in the namespace actions menu. From Kiali 2.23, those actions are on the Namespaces page. The mesh page lists namespaces that still need to move to the canary control plane. On {SMProduct}, prefer the documented update process over the console upgrade action unless you are running a canary revision on purpose.
