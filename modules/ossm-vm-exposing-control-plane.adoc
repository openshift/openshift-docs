= Exposing the control plane to the virtual machine

[role="_abstract"]

The proxy on the virtual machine connects to the control plane on port 15012 to receive configuration through the xDS protocol and to have its workload certificates signed. Expose that port with a passthrough route rather than through the east-west gateway.

A route publishes the control plane under a hostname in the cluster ingress domain, which the virtual machine can resolve on its own. The east-west gateway offers only a load balancer address, which the virtual machine would have to map to the in-cluster name `istiod.istio-system.svc` through an `/etc/hosts` entry that must be updated whenever the address changes.

.Procedure

. Create a `Route` resource named `istiod-route.yaml` similar to the following example:
+
[source,yaml]
----
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: istiod-15012
  namespace: istio-system
spec:
  host: istiod.istio-system.svc.<ingress_domain> # <1>
  to:
    kind: Service
    name: istiod
  port:
    targetPort: 15012
  tls:
    termination: passthrough # <2>
    insecureEdgeTerminationPolicy: None
----
<1> Must match the value of the `ISTIOD_CUSTOM_HOST` variable in the `Istio` resource. Replace `<ingress_domain>` with the cluster ingress domain.
<2> Passes the connection through to the control plane, which terminates TLS itself. The proxy on the virtual machine authenticates the control plane against the mesh root certificate, so the router must not re-encrypt or terminate the connection.

. Apply the `Route` resource by running the following command:
+
[source,terminal]
----
$ oc apply -f istiod-route.yaml
----

.Verification

. Extract the mesh root certificate by running the following command:
+
[source,terminal]
----
$ oc get configmap istio-ca-root-cert -n istio-system -o jsonpath='{.data.root-cert\.pem}' > root-cert.pem
----

. Confirm that the control plane answers on port 443 with a certificate that is valid for the route hostname by running the following command:
+
[source,terminal]
----
$ openssl s_client -connect istiod.istio-system.svc.<ingress_domain>:443 \
  -servername istiod.istio-system.svc.<ingress_domain> \
  -CAfile root-cert.pem </dev/null 2>/dev/null | grep "Verify return code"
----
+
*Example output:*
+
[source,terminal]
----
Verify return code: 0 (ok)
----
+
A verification failure indicates that the `ISTIOD_CUSTOM_HOST` variable does not match the route hostname. Confirm that the two values are identical.
