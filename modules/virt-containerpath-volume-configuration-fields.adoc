[id="virt-containerpath-volume-configuration-fields_{context}"]
= containerPath volume configuration fields

[role="_abstract"]
The following tables describe the fields for configuring a containerPath volume source and virtiofs filesystem device in a `VirtualMachine` manifest.

[id="virt-containerpath-volume-source-fields_{context}"]
== containerPath volume source fields

.`spec.template.spec.volumes[].containerPath` fields
[cols="1,1,2",options="header"]
|===
|Field
|Type
|Description

|`path`
|`string`
|The absolute path in the virt-launcher pod compute container to expose to the VM guest. The path must correspond to an existing volume mount in the pod. Paths that contain `..` or that follow symbolic links outside the container filesystem are not permitted.
|===

[id="virt-virtiofs-filesystem-device-fields_{context}"]
== virtiofs filesystem device fields

.`spec.template.spec.domain.devices.filesystems[]` fields
[cols="1,1,2",options="header"]
|===
|Field
|Type
|Description

|`name`
|`string`
|The name of the filesystem device. This must match the name of a corresponding `containerPath` volume defined in `spec.template.spec.volumes[]`.

|`virtiofs`
|`object`
|An empty object (`{}`) that indicates the filesystem is exposed by using virtiofs.
|===

[id="virt-supported-backing-volumes-reference_{context}"]
== Supported backing volume types

The `containerPath` volume source supports paths that correspond to the following Kubernetes volume types mounted in the virt-launcher pod:

.Supported backing volume types
[cols="1,2",options="header"]
|===
|Volume type
|Live migration support

|`ConfigMap`
|Supported

|`Secret`
|Supported

|`Projected`
|Supported

|`DownwardAPI`
|Supported

|`EmptyDir`
|Supported only if the volume is populated by a sidecar container
|===

[id="virt-cloud-provider-annotation-reference_{context}"]
== Cloud provider annotation reference

The following annotations are used to bind a `ServiceAccount` to a cloud provider identity:

.Cloud provider ServiceAccount annotations
[cols="1,1,2",options="header"]
|===
|Annotation
|Platform
|Description

|`eks.amazonaws.com/role-arn`
|AWS (ROSA)
|Specifies the ARN of the AWS IAM role to assume by using IRSA. The platform webhook injects a projected token volume into the pod.

|`azure.workload.identity/client-id`
|Azure (ARO)
|Specifies the client ID of the Azure managed identity to use for workload identity federation. Requires the `azure.workload.identity/use: "true"` label on the pod template.
|===
