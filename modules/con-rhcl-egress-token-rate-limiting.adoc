= Token rate limiting for outbound AI traffic

[role="_abstract"]
To cap the number of artificial intelligence (AI) tokens that your workloads consume through an egress `Gateway` object, apply a `TokenRateLimitPolicy` custom resource (CR) to the route that reaches the external AI service.

include::snippets/egress-gateway-ossm.adoc[]

A `TokenRateLimitPolicy` CR uses the same `wasm-shim` module and Limitador infrastructure on egress as it does on ingress. The egress `Gateway` object extracts the `usage.total_tokens` field from the response body of the external AI service and counts the value against the limits that you configure. The policy specification is the same for both directions of traffic, so you do not need any egress-specific fields.

With a `TokenRateLimitPolicy` CR on an egress `Gateway` object, you can:

* Apply a single token budget to all outbound traffic that reaches an external AI service.
* Give each workload its own token budget by combining the policy with workload identity from an `AuthPolicy` CR.
* Assign different budgets to different groups of workloads, such as a default tier and a premium tier.

Token consumption is counted after the external AI service responds, because the token count is only available in the response body. As a result, the gateway checks the remaining budget before it forwards a request, and reports the actual consumption after the response arrives.
