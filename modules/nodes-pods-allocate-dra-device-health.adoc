= About device health monitoring

[role="_abstract"]
If you have a failing pod on a device that was allocated by using Dynamic Resource Allocation (DRA), you can use the pod status to determine if the pod failure is due to a problem with the device.

When a DRA driver detects that an allocated device has become unhealthy, it reports this status back to the kubelet. This health information is then exposed directly in the pod status. The kubelet populates the `allocatedResourcesStatus` field in the status of each container, detailing the health of each device assigned to that container. Each resource health entry can include an optional message field with additional human-readable context about the health status, such as error details or failure reasons.

If the kubelet does not receive a health update from a DRA driver within a timeout period, the device's health status is marked as `Unknown`. You can use your DRA drivers to configure this timeout on a per-device basis by setting the `health_check_timeout_seconds` field in the `DeviceHealth` gRPC message. If not specified, the kubelet uses a default timeout of 30 seconds. This allows different hardware types (for example, GPUs, FPGAs, or storage devices) to use appropriate timeout values based on their health-reporting characteristics.

In the example pod output, you can see the pod failed because of a temperature issue with the device where the pod is running, not the application running on the pod:

[source,terminal]
----
apiVersion: v1
kind: Pod
metadata:
  name: test
# ...
status:
# ...
  containerStatuses:
  - name: my-gpu-intensive-container
    allocatedResourcesStatus:
    - name: claim:gpu-claim/gpu-request
      resources:
      - resourceID: example.com/gpu-a1b2-c3d4
        health: Unhealthy
        message: GPU temperature exceeds threshold
----
where:

* `status.containerStatuses.allocatedResourcesStatus.name` is the name of the resource claim used to obtain the device.
* `status.containerStatuses.allocatedResourcesStatus.resources.resourceID` is the unique ID of the device that was allocated.
* `status.containerStatuses.allocatedResourcesStatus.resources.health` is the currently reported state of the device, one of the following states:
** `Healthy` indicates the device is operating normally
** `Unhealthy` indicates the driver reported a problem (treated as temporary; Kubernetes does not distinguish permanent failure)
** `Unknown` indicates health cannot be determined, for example the kubelet got no update before the timeout, or the driver unregistered
* `status.containerStatuses.allocatedResourcesStatus.resources.message` is the reason behind the health value by using text from the DRA driver. Typically the message displays for an `Unhealthy` status.

The following example shows a healthy device:

[source,terminal]
----
apiVersion: v1
kind: Pod
metadata:
  name: test
# ...
status:
# ...
  containerStatuses:
  - name: my-gpu-intensive-container
    allocatedResourcesStatus:
    - name: claim:example-claim
      resources:
      - resourceID: example.com/device=dev0-dra-example-com
        health: Healthy
        
----

The following example shows a device with an unknown status:

[source,terminal]
----
apiVersion: v1
kind: Pod
metadata:
  name: test
# ...
status:
# ...
  containerStatuses:
  - name: my-gpu-intensive-container
    allocatedResourcesStatus:
    - name: "claim:my-gpu-claim"
      resources:
      - resourceID: "example.com/gpu-a1b2-c3d4"
        health: "Unknown"
----
