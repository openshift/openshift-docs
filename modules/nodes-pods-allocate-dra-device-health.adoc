= About device health monitoring

[role="_abstract"]
If you have a failing pod on a device that was allocated by using Dynamic Resource Allocation (DRA), you can use the pod status to determine whether the failure is caused by the underlying device rather than the application, without relying only on application logs.

When a DRA driver detects that an allocated device has become unhealthy, it reports this status back to the kubelet. This health information is then exposed directly in the pod status. The kubelet populates the `allocatedResourcesStatus` field in the status of each container, detailing the health of each device assigned to that container as `Healthy`, `Unhealthy`, or `Unknown`. Each resource health entry can include an optional message field with additional context about the health status, such as error details or failure reasons.

If the kubelet does not receive a health update from a DRA driver within a timeout period, the device's health status is marked as `Unknown`. You can use your DRA driver to configure this timeout on a per-device basis by setting the `health_check_timeout_seconds` field in the `DeviceHealth` message in the DRA driver’s health gRPC stream. If not specified, the kubelet uses a default timeout of 30 seconds. This allows different hardware types, such as for example, GPUs, FPGAs, or storage devices, to use appropriate timeout values based on their health-reporting characteristics.

In the example pod output, you can see the pod failed because of a temperature issue with the device where the pod is running, not the application running on the pod:

[source,terminal]
----
apiVersion: v1
kind: Pod
metadata:
  name: test
# ...
status:
# ...
  containerStatuses:
  - name: my-gpu-intensive-container
    allocatedResourcesStatus:
    - name: claim:gpu-claim/gpu-request
      resources:
      - resourceID: example.com/gpu-a1b2-c3d4
        health: Unhealthy
        message: GPU temperature exceeds threshold
----
where:

* `status.containerStatuses.allocatedResourcesStatus.name` is the name of the resource claim used to obtain the device.
* `status.containerStatuses.allocatedResourcesStatus.resources.resourceID` is the unique ID of the device that was allocated.
* `status.containerStatuses.allocatedResourcesStatus.resources.health` is the current reported state of the device, one of the following states:
** `Healthy` indicates the device is operating normally
** `Unhealthy` indicates the driver reported a problem.
** `Unknown` indicates the health cannot be determined, for example the kubelet was not updated before the timeout.
* `status.containerStatuses.allocatedResourcesStatus.resources.message` is the reason behind the health value obtained from text supplied by the DRA driver. Typically the message displays only for an `Unhealthy` status.

The following example shows a healthy device:

[source,terminal]
----
apiVersion: v1
kind: Pod
metadata:
  name: test
# ...
status:
# ...
  containerStatuses:
  - name: my-gpu-intensive-container
    allocatedResourcesStatus:
    - name: claim:example-claim
      resources:
      - resourceID: example.com/device=dev0-dra-example-com
        health: Healthy
        
----

The following example shows a device with an unknown status:

[source,terminal]
----
apiVersion: v1
kind: Pod
metadata:
  name: test
# ...
status:
# ...
  containerStatuses:
  - name: my-gpu-intensive-container
    allocatedResourcesStatus:
    - name: "claim:my-gpu-claim"
      resources:
      - resourceID: "example.com/gpu-a1b2-c3d4"
        health: "Unknown"
----
