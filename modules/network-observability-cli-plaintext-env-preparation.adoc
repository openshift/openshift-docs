= Prepare your environment for plain text capture

[role="_abstract"]
Verify that your cluster meets the requirements for plain text capture and ensure the Network Observability eBPF agent has the necessary permissions.

.Prerequisites

* The {oc-first} is installed.
* The Network Observability CLI (`oc netobserv`) plugin is installed.
* Access to the cluster with `cluster-admin` privileges.

.Procedure

. Verify the kernel version supports kTLS if you plan to capture kTLS traffic:
+
[source,terminal]
----
$ oc debug node/<node_name> -- chroot /host uname -r
----
+
kTLS requires kernel version 4.17 or later. For full kTLS functionality, kernel version 5.2 or later is recommended.

. Verify kTLS kernel module is loaded:
+
[source,terminal]
----
$ oc debug node/<node_name> -- chroot /host lsmod | grep tls
----
+
.Example output
[source,terminal]
----
tls                    151552  0
----
+
If the `tls` module is not listed, kTLS is not available on the node.

. Verify that the Network Observability eBPF agent has the required security context:
+
[source,terminal]
----
$ oc get daemonset netobserv-ebpf-agent -n netobserv -o yaml | grep -A 10 securityContext
----
+
The agent requires `privileged: true` and the `SYS_ADMIN` capability to attach eBPF programs to TLS library functions.

. Identify processes to exclude from plain text capture to reduce noise:
+
[source,terminal]
----
$ oc get pods -n openshift-kube-apiserver
$ oc get pods -n openshift-etcd
----
+
Common processes to exclude include:
+
* `kube-apiserver`
* `etcd`
* `openshift-apiserver`
+
You will configure process exclusions in the `FlowCollector` custom resource.

.Verification

. Verify the eBPF agent pods are running successfully:
+
[source,terminal]
----
$ oc get pods -n netobserv -l app=netobserv-ebpf-agent
----
+
.Example output
[source,terminal]
----
NAME                         READY   STATUS    RESTARTS   AGE
netobserv-ebpf-agent-abc12   1/1     Running   0          5m
netobserv-ebpf-agent-def34   1/1     Running   0          5m
----
