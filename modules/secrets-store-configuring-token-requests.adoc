= Configuring token requests for Workload Identity Federation

[role="_abstract"]
You can configure the {secrets-store-operator} to use Workload Identity Federation (WIF) by specifying the service account token audience. This enables credential-free authentication to cloud provider secret stores.

.Prerequisites

* The {secrets-store-operator} is installed on the cluster.
* You are using Workload Identity Federation with a supported provider, such as AWS, Azure, Google Cloud Platform, or HashiCorp Vault.
* You have configured your cloud provider to trust your {product-title} cluster's OIDC provider.
* You have access to the cluster with `cluster-admin` privileges.

.Procedure

. Edit the `Driver` custom resource for the {secrets-store-operator}:
+
[source,terminal]
----
$ oc edit driver.csidriver.openshift.io/secrets-store.csi.k8s.io
----

. Locate or add the `tokenRequests` section in the `spec` field. Configure the `audience` parameter based on your cloud provider requirements:
+
[source,yaml]
----
apiVersion: csidriver.openshift.io/v1
kind: Driver
metadata:
  name: secrets-store.csi.k8s.io
spec:
  tokenRequests:
    - audience: "api://AzureADTokenExchange" <1>
----
<1> Specify the audience value required by your cloud provider or secret management system. The audience must match the value configured in your cloud provider's trust policy.
+
[NOTE]
====
The required audience value varies by cloud provider:

* *Azure Key Vault*: Use `api://AzureADTokenExchange`
* *AWS Secrets Manager*: Use your cluster's OIDC provider URL, for example: `https://rh-oidc.s3.us-east-1.amazonaws.com/<cluster-id>`
* *Google Secret Manager*: Typically uses the default service account token audience
* *HashiCorp Vault*: Use the audience configured in your Vault Kubernetes authentication backend
====

. For environments that require multiple audiences or additional token request parameters, you can specify multiple token request entries:
+
[source,yaml]
----
apiVersion: csidriver.openshift.io/v1
kind: Driver
metadata:
  name: secrets-store.csi.k8s.io
spec:
  tokenRequests:
    - audience: "api://AzureADTokenExchange"
    - audience: "vault.example.com"
----

. Save and apply the changes to the custom resource.

.Verification

. Verify that the {secrets-store-operator} driver pods have been updated with the token request configuration:
+
[source,terminal]
----
$ oc get pods -n openshift-cluster-csi-drivers -l app=secrets-store-csi-driver
----

. Check the driver configuration to confirm the token request settings:
+
[source,terminal]
----
$ oc get driver.csidriver.openshift.io/secrets-store.csi.k8s.io -o jsonpath='{.spec.tokenRequests}' | jq
----
+
.Example output
[source,terminal]
----
[
  {
    "audience": "api://AzureADTokenExchange"
  }
]
----

. Create a test pod that mounts secrets from your external secret store to verify that Workload Identity Federation authentication works correctly:
+
[source,terminal]
----
$ oc apply -f <test-pod-yaml>
----

. Check the pod logs to confirm successful authentication and secret mounting:
+
[source,terminal]
----
$ oc logs <test-pod-name>
----
+
Successful authentication indicates that the service account token with the specified audience is being accepted by your cloud provider's identity federation system.
