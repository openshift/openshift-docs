= Configuring token requests for Workload Identity Federation

[role="_abstract"]
You can configure the {secrets-store-operator} to use Workload Identity Federation (WIF) by specifying the service account token audience. This enables secure, credential-free authentication to external secret management systems across multiple cloud providers.

Workload Identity Federation allows your {product-title} workloads to access cloud provider services without storing long-lived credentials. Instead, the {secrets-store-operator} uses short-lived service account tokens with a specified audience to authenticate to external secret stores.

.Prerequisites

* The {secrets-store-operator} is installed on the cluster.
* You are using Workload Identity Federation with a supported provider, such as AWS, Azure, Google Cloud Platform, or HashiCorp Vault.
* You have configured your cloud provider to trust your {product-title} cluster's OIDC provider.
* You have access to the cluster with `cluster-admin` privileges.

.Procedure

. Edit the `ClusterCSIDriver` custom resource for the {secrets-store-operator}:
+
[source,terminal]
----
$ oc edit clustercsidrivers.operator.openshift.io secrets-store.csi.k8s.io
----

. Locate or add the `tokenRequests` section under `spec.driverConfig.secretsStore`. Set the type to `Managed` and configure the audience based on your cloud provider requirements:
+
[source,yaml]
----
apiVersion: operator.openshift.io/v1
kind: ClusterCSIDriver
metadata:
  name: secrets-store.csi.k8s.io
spec:
  driverConfig:
    driverType: SecretsStore
    secretsStore:
      tokenRequests:
        type: Managed
        managed:
          audiences:
            - audience: "api://AzureADTokenExchange"
              expirationSeconds: 3600
----
+
where:

`spec.driverConfig.secretsStore.tokenRequests.managed.audiences[].audience`:: Specify the audience value required by your cloud provider or secret management system. The audience must match the value configured in the trust policy of your cloud provider. For more information regarding audience value associated with different cloud providers, see corresponding cloud provider documentation.

`spec.driverConfig.secretsStore.tokenRequests.managed.audiences[].expirationSeconds`:: Optional. Specify the token validity duration in seconds. Valid range is 600 to 315,360,000 seconds. If omitted, the platform applies a default value.

. For environments that require multiple audiences, you can specify multiple audience entries:
+
[source,yaml]
----
apiVersion: operator.openshift.io/v1
kind: ClusterCSIDriver
metadata:
  name: secrets-store.csi.k8s.io
spec:
  driverConfig:
    driverType: SecretsStore
    secretsStore:
      tokenRequests:
        type: Managed
        managed:
          audiences:
            - audience: "sts.amazonaws.com"
              expirationSeconds: 3600
            - audience: "api://AzureADTokenExchange"
              expirationSeconds: 3600
----

. Save and apply the changes to the custom resource.

.Verification

. Verify that the {secrets-store-operator} driver pods have been updated with the token request configuration:
+
[source,terminal]
----
$ oc get pods -n openshift-cluster-csi-drivers | grep secrets-store
----
+
.Example output
[source,terminal]
----
secrets-store-csi-driver-node-bhp2d                  3/3     Running   0          45s
secrets-store-csi-driver-node-xyz12                  3/3     Running   0          45s
secrets-store-csi-driver-operator-74696fc7bc-qjrl8   1/1     Running   0          7m40s
----

. Check the `ClusterCSIDriver` configuration to confirm the token request settings:
+
[source,terminal]
----
$ oc get clustercsidrivers.operator.openshift.io secrets-store.csi.k8s.io -o jsonpath='{.spec.driverConfig.secretsStore.tokenRequests}' | jq
----
+
.Example output
[source,terminal]
----
{
  "managed": {
    "audiences": [
      {
        "audience": "api://AzureADTokenExchange",
        "expirationSeconds": 3600
      }
    ]
  },
  "type": "Managed"
}
----

. Create a test pod that mounts secrets from your external secret store to verify that Workload Identity Federation authentication works correctly:
+
[source,terminal]
----
$ oc apply -f <test-pod-yaml>
----

. Check the pod logs to confirm successful authentication and secret mounting:
+
[source,terminal]
----
$ oc logs <test-pod-name>
----
+
Successful authentication indicates that the service account token with the specified audience is being accepted by your cloud provider's identity federation system.
