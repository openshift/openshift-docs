= LLMProvider custom resource configuration

[role="_abstract"]
The `LLMProvider` custom resource (CR) is a cluster-scoped resource in the `agentic.openshift.io/v1alpha1` API group that defines the connection to a large language model (LLM) provider. The `spec.type` field selects the provider backend, and you must configure exactly one matching per-provider block.

.LLMProvider spec fields
[cols="1,1,2", options="header"]
|===
| Field | Required | Description

| `spec.type`
| Yes
| The provider backend. Allowed values are `Anthropic`, `GoogleCloudVertex`, `OpenAI`, `AzureOpenAI`, and `AWSBedrock`. You must configure the per-provider block that matches this value.

| `spec.anthropic`
| When `type` is `Anthropic`
| Anthropic configuration. Contains `credentialsSecret.name` and an optional `url` endpoint override. The credentials secret must contain the `ANTHROPIC_API_KEY` key.

| `spec.openAI`
| When `type` is `OpenAI`
| OpenAI configuration. Contains `credentialsSecret.name` and an optional `url` endpoint override. The credentials secret must contain the `OPENAI_API_KEY` key.

| `spec.googleCloudVertex`
| When `type` is `GoogleCloudVertex`
| Google Cloud Vertex AI configuration. Contains `credentialsSecret.name`, `projectID`, `region`, the required `modelProvider` field (`Anthropic`, `Google`, or `OpenAI`), and an optional `url` endpoint override. The credentials secret must contain the `GOOGLE_APPLICATION_CREDENTIALS` key.

| `spec.awsBedrock`
| When `type` is `AWSBedrock`
| {aws-first} Bedrock configuration. Contains `credentialsSecret.name`, the required `region` field, and an optional `url` endpoint override. The credentials secret must contain the `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` keys.

| `spec.azureOpenAI`
| When `type` is `AzureOpenAI`
| {azure-openai} configuration. Contains `credentialsSecret.name`, the required `endpoint` field, an optional `apiVersion` field, and an optional `url` endpoint override. The credentials secret must contain the `AZURE_OPENAI_API_KEY` key.
|===

[NOTE]
====
The per-provider block must match the `spec.type` value. If the block does not match the type, or if more than one block is set, the cluster rejects the resource. The credentials secret must exist in the `openshift-lightspeed` namespace.
====
