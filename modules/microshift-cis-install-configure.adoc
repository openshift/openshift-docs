= Installing and configuring {microshift-short} on a CIS Level 2 host

[role="_abstract"]
Install {microshift-short} RPM packages on a CIS Level 2 hardened host, open the required firewall access, regenerate privileged-command audit rules, start {microshift-short}, and verify that workloads run.

.Prerequisites

* You hardened the host and applied the IP forwarding playbook overrides.
* You completed the RPM installation prerequisites for {microshift-short}, including repository configuration and a pull secret.
* You have root or `sudo` privileges on the host.
* You installed the `oc` CLI.

.Procedure

. Install {microshift-short} from RPM packages by following the standard package-mode installation procedure.
+
CIS hardening enables `firewalld` and restricts traffic.
Configure the firewall before or immediately after installation so that the API server, router, and pod networking can function.

. Configure required firewall trusted sources and any optional ports that your workloads need.

. If you installed {microshift-short} after you applied CIS hardening, regenerate audit rules for privileged binaries so that they cover binaries from {microshift-short} RPMs:
+
[source,terminal]
----
$ sudo find / -xdev \( -perm -4000 -o -perm -2000 \) -type f 2>/dev/null | \
  awk '{print "-a always,exit -F path=" $1 " -F perm=x -F auid>=1000 -F auid!=unset -k privileged"}' | \
  sudo tee /etc/audit/rules.d/99-privileged-post-install.rules > /dev/null
$ sudo augenrules --load
----

. Start {microshift-short}:
+
[source,terminal]
----
$ sudo systemctl enable --now microshift
----

. Wait for the node to become ready:
+
[source,terminal]
----
$ oc get node
----

. Deploy a smoke-test application that uses persistent storage and is exposed through an ingress route to validate scheduling, storage, and ingress on the hardened host.

.Verification

* The `microshift` service is active.
* The node reports `Ready`.
* The smoke-test application is reachable through its route and can read and write persistent storage.
* A postinstall OpenSCAP scan shows only the documented unavoidable CIS rule failures for IP forwarding, container file ownership, and kubelet volume permissions, plus any site-specific exceptions that you approved.
