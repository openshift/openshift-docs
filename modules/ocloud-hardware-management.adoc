= Declarative hardware management for bare-metal servers

[role="_abstract"]
In large-scale deployments with heterogeneous hardware across multiple sites, manually tracking which servers meet the requirements for each cluster and ensuring consistent firmware baselines becomes impractical. The O-Cloud Manager automates hardware allocation, firmware preparation, and BIOS configuration as part of the provisioning workflow, using the infrastructure hierarchy of `Location`, `OCloudSite`, and `ResourcePool` resources to organize servers across your fleet.

Servers are registered in the hub cluster as `BareMetalHost` CRs with metadata labels that identify resource pool membership, server type, and other characteristics. The Bare Metal Operator connects to each host's BMC, inspects the physical hardware, and populates a `HardwareData` resource with CPU, memory, NIC, and storage details. This inspection data enables automatic hardware-aware selection without requiring operators to manually verify server specifications at each site.

The `HardwareProfile` CR defines the desired firmware levels and BIOS settings for a class of servers. This eliminates manual BMC configuration across your fleet and ensures that every server of a given class runs a consistent, vendor-validated baseline before cluster installation begins. The hardware manager applies the profile during initial provisioning (Day-0) or as a Day-2 update when firmware patching or performance tuning is required. A `HardwareProfile` is optional — servers can be provisioned without one if firmware and BIOS management is handled externally.

When processing a `ProvisioningRequest` CR, the O-Cloud Manager selects servers from resource pools using a two-stage filtering process defined in the `ClusterTemplate` CR. This ensures the correct class of server is assigned to the correct node role without manual server-by-server assignment, even in racks with mixed hardware:

Label-based filtering:: Selects `BareMetalHost` CRs by labels such as server type, location identifiers, or resource selector labels.
Hardware data filtering:: Further filters hosts based on their `HardwareData` resource, matching criteria such as CPU architecture, thread count, memory size, NIC speed and count, and storage type and capacity.

Together, these filtering stages and the optional `HardwareProfile` application automate the path from bare-metal inventory to installation-ready hardware without manual intervention at each site.
