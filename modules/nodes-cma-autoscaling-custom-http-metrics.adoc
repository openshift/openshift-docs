= Configure HTTP scaling metrics

[role="_abstract"]
You can scale an HTTP workload on the number of in-flight requests, the request rate, or both. Set the metric on the `InterceptorRoute` resource. The scaled object `cooldownPeriod` field controls how long the metrics must stay at zero before the workload scales down.

The horizontal pod autoscaler calculates the replica count for one metric as `ceil(currentMetricValue / targetValue)`. For example, a concurrency target of `100` and a current concurrency of `250` produces three replicas. When you set both metrics, the metric that requires more replicas is used.

Requests that match a static route are not included in these metrics and do not cause the workload to scale up.

.Prerequisites

* An `InterceptorRoute` resource and a scaled object exist for the workload.

.Procedure

. Set `spec.scalingMetric` on the `InterceptorRoute` resource.
+
To scale on concurrent in-flight requests, use `concurrency`:
+
[source,yaml]
----
spec:
  scalingMetric:
    concurrency:
      targetValue: 100 <1>
----
<1> Specifies the target number of in-flight requests for each replica. The interceptor increments the count when a request arrives and decrements it when the response completes.
+
To scale on requests per second, use `requestRate`:
+
[source,yaml]
----
spec:
  scalingMetric:
    requestRate:
      targetValue: 10 <1>
      window: 1m <2>
      granularity: 1s <3>
----
<1> Specifies the target requests per second for each replica.
<2> Specifies the time window used to average the rate. The default is `1m`.
<3> Specifies the bucket size inside the window. The default is `1s`.
+
To use both metrics, set `concurrency` and `requestRate` under `scalingMetric`.

. Apply the updated resource by running the following command:
+
[source,terminal]
----
$ oc apply -f interceptorroute.yaml
----
