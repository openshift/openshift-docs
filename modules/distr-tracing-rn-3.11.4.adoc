The distributed tracing 3.11.4 release resolves these Common Vulnerabilities and Exposures (CVEs):

`klauspost/compress` no longer crashes when decompressing malformed zstd streams::
Before this update, the Zstandard (zstd) decompression logic in the `klauspost/compress` Go library contained an integer handling error in its normalized count parsing. A remote attacker could send a specially crafted two-block zstd compressed stream to an application that decompressed untrusted input, which caused the decoder to retain stale decode-table state and perform an out-of-bounds read. As a consequence, the application stopped with an unhandled runtime panic, resulting in a denial of service (DoS). With this update, the library correctly parses the normalized counts and validates the decode-table state. As a result, malformed zstd streams no longer crash the application.
+
link:https://access.redhat.com/security/cve/CVE-2026-116591[CVE-2026-116591]

`decode-uri-component` no longer makes a service unresponsive when decoding malformed input::
Before this update, the `decode-uri-component` package decoded input that contained numerous malformed percent-encoded sequences by using an inefficient fallback routine. When a remote attacker sent such crafted input, the fallback routine consumed excessive processor resources and blocked the application event loop. As a consequence, the application stopped handling incoming traffic, which rendered the service unresponsive to all users. With this update, the package handles malformed percent-encoded sequences efficiently, without blocking the event loop. As a result, crafted input no longer renders the service unresponsive.
+
link:https://access.redhat.com/security/cve/CVE-2026-118664[CVE-2026-118664]
