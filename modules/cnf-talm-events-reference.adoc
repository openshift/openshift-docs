= {cgu-operator-full} event reference

[role="_abstract"]
The {cgu-operator-first} emits Kubernetes events during `ClusterGroupUpgrade` reconciliation. Each event includes a reason, action, and type that you can use to filter events in Event Driven Ansible rulebooks. The `reason` and `action` fields are the stable contract for event filtering; do not match on message text. Events also include annotations that provide additional metadata about the event scope, affected clusters, and policies.

== Event types

The following table describes the events that {cgu-operator} emits during policy remediation.

.{cgu-operator} event types
[cols="1,2,1,1,2", options="header"]
|====
|Reason
|Action
|Type
|Scope
|Description

|`CguCreated`
|`BuildingRemediationPlan`
|Normal
|Global
|A new `ClusterGroupUpgrade` resource is found by the reconciler.

|`CguStarted`
|`RemediationStarted`
|Normal
|Global
|The reconciler has started remediating policies based on the remediation plan.

|`CguStarted`
|`RemediationInBatchStarted`
|Normal
|Batch
|Policy remediation has started for the clusters in a specific batch of the remediation plan.

|`CguStarted`
|`RemediationInClusterStarted`
|Normal
|Cluster
|Policy remediation has started for a specific cluster.

|`CguSuccess`
|`RemediationCompleted`
|Normal
|Global
|All policies have been successfully remediated for all clusters in the remediation plan.

|`CguSuccess`
|`RemediationInBatchCompleted`
|Normal
|Batch
|Policy remediation has finished successfully for all clusters in a specific batch.

|`CguSuccess`
|`RemediationInClusterCompleted`
|Normal
|Cluster
|Policy remediation has finished successfully for a specific cluster.

|`CguTimedout`
|`RemediationTimeout`
|Warning
|Global
|Some clusters timed out while remediating policies across the entire remediation plan.

|`CguTimedout`
|`RemediationInBatchTimeout`
|Warning
|Batch
|Some clusters in the current batch timed out while remediating policies.

|`CguValidationFailure`
|`RemediationOnHoldDueToValidationFailure`
|Warning
|Global
|The validation of the `ClusterGroupUpgrade` resource failed due to missing clusters, missing policies, invalid policies, or ambiguous policies.
|====

== Event annotations

{cgu-operator} events include annotations that provide structured metadata for filtering and processing. The annotation keys use the `cgu.openshift.io/` prefix.

.{cgu-operator} event annotations
[cols="2,1,2", options="header"]
|====
|Annotation
|Possible values
|Description

|`cgu.openshift.io/event-type`
|`global`, `batch`, `cluster`
|Indicates the scope of the event. Use this annotation to filter events by scope in rulebook conditions.

|`cgu.openshift.io/cluster-name`
|Cluster name string
|Identifies the specific cluster for cluster-scoped events. Present only on events with `cluster` scope.

|`cgu.openshift.io/batch-clusters`
|Comma-separated cluster names
|Lists the clusters in the current batch. Present on batch-scoped events.

|`cgu.openshift.io/batch-clusters-count`
|Integer
|The number of clusters in the current batch. Present on batch-scoped events.

|`cgu.openshift.io/total-clusters-count`
|Integer
|The total number of clusters in the remediation plan. Present on global-scoped and batch-scoped `CguStarted` and `CguSuccess` events.

|`cgu.openshift.io/total-batches-count`
|Integer
|The total number of batches in the remediation plan. Present on global `CguStarted` events.

|`cgu.openshift.io/timedout-clusters`
|Comma-separated cluster names
|Lists the clusters that timed out during remediation. Present on `CguTimedout` events.

|`cgu.openshift.io/missing-clusters`
|Comma-separated cluster names
|Lists the clusters specified in the `ClusterGroupUpgrade` resource that do not exist. Present on `CguValidationFailure` events.

|`cgu.openshift.io/missing-clusters-count`
|Integer
|The number of missing clusters. Present on `CguValidationFailure` events when clusters are missing.

|`cgu.openshift.io/missing-policies`
|Comma-separated policy names
|Lists the policies that do not exist. Present on `CguValidationFailure` events.

|`cgu.openshift.io/invalid-policies`
|Comma-separated policy names
|Lists the policies that are invalid. Present on `CguValidationFailure` events.

|`cgu.openshift.io/ambiguous-policies`
|Comma-separated policy names
|Lists the policies that are duplicated across different namespaces. Present on `CguValidationFailure` events.

|`cgu.openshift.io/truncated`
|Annotation key string
|Indicates that another annotation on this event was truncated to stay within the Kubernetes 64 KiB annotation size limit. The value is the key of the annotation that was truncated.
|====

[NOTE]
====
The `cgu.openshift.io/event-type` annotation indicates the event scope (`global`, `batch`, or `cluster`). This is different from the Kubernetes event `type` field, which indicates severity (`Normal` or `Warning`).
====

== CloudEvent field mapping

The Multicluster Global Hub agent transforms {cgu-operator} Kubernetes events into CloudEvents for Kafka. Not all Kubernetes event fields are carried over—notably, the `action` and `related` fields are not included. To identify a specific event, filter on `reason` combined with the `cgu.openshift.io/event-type` annotation for scope. The following table shows the field mapping.

.Kubernetes event to CloudEvent field mapping
[cols="1,1,2", options="header"]
|====
|Kubernetes event field
|CloudEvent field
|Description

|`metadata.name`
|`eventName`
|The name of the Kubernetes event.

|`metadata.namespace`
|`eventNamespace`
|The namespace of the Kubernetes event.

|`reason`
|`reason`
|The event reason (for example, `CguSuccess`, `CguTimedout`).

|`note`
|`message`
|The event message text.

|`type`
|`type`
|The event type (`Normal` or `Warning`).

|`metadata.annotations`
|`annotations`
|The event annotations as a JSON object.

|`reportingController`
|`reportingController`
|The controller that reported the event.

|`reportingInstance`
|`reportingInstance`
|The instance of the controller that reported the event.

|`metadata.creationTimestamp`
|`createdAt`
|The event timestamp.

|`regarding.name`
|`cguName`
|The name of the `ClusterGroupUpgrade` resource.

|(derived)
|`leafHubName`
|The name of the managed hub cluster.
|====
