[id="examples-unsafe_{context}"]
= Examples of unsafe CRD changes

[role="_abstract"]
Review the example unsafe custom resource definition (CRD) changes to recognize modifications that trigger the CRD upgrade safety preflight check.

The following examples use this baseline `CustomResourceDefinition` object:

.Example CRD object
[source,yaml]
----
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  annotations:
    controller-gen.kubebuilder.io/version: v0.13.0
  name: example.test.example.com
spec:
  group: test.example.com
  names:
    kind: Sample
    listKind: SampleList
    plural: samples
    singular: sample
  scope: Namespaced
  versions:
  - name: v1alpha1
    schema:
      openAPIV3Schema:
        properties:
          apiVersion:
            type: string
          kind:
            type: string
          metadata:
            type: object
          spec:
            type: object
          status:
            type: object
          pollInterval:
            type: string
        type: object
    served: true
    storage: true
    subresources:
      status: {}
----

[id="scope-change_{context}"]
== Scope change

The following example changes the `spec.scope` field from `Namespaced` to `Cluster`:

.Example scope change in a CRD
[source,yaml]
----
spec:
  group: test.example.com
  names:
    kind: Sample
    listKind: SampleList
    plural: samples
    singular: sample
  scope: Cluster
  versions:
  - name: v1alpha1
----

.Example error output
[source,text]
----
validating upgrade for CRD "example.test.example.com": scope: scope changed : "Namespaced" -> "Cluster"
----

[id="stored-version-removal_{context}"]
== Removal of a stored version

The following example removes the existing stored version, `v1alpha1`:

.Example removal of a stored version in a CRD
[source,yaml]
----
versions:
- name: v1alpha2
  schema:
    openAPIV3Schema:
      properties:
        apiVersion:
          type: string
        kind:
          type: string
        metadata:
          type: object
        spec:
          type: object
        status:
          type: object
        pollInterval:
          type: string
      type: object
----

.Example error output
[source,text]
----
validating upgrade for CRD "example.test.example.com": storedVersionRemoval: stored versions removed : [v1alpha1]
----

[id="removal-existing-field_{context}"]
== Removal of an existing field

The following example removes the `pollInterval` property field from the `v1alpha1` schema:

.Example removal of an existing field in a CRD
[source,yaml]
----
versions:
- name: v1alpha1
  schema:
    openAPIV3Schema:
      properties:
        apiVersion:
          type: string
        kind:
          type: string
        metadata:
          type: object
        spec:
          type: object
        status:
          type: object
      type: object
----

.Example error output
[source,text]
----
validating upgrade for CRD "example.test.example.com": existingFieldRemoval: removed field : v1alpha1.^.pollInterval
v1alpha1: ^.pollInterval: type: type changed : "string" -> ""
----

[id="addition-required-field_{context}"]
== Addition of a required field

The following example changes the `pollInterval` property to a required field:

.Example addition of a required field in a CRD
[source,yaml]
----
versions:
- name: v1alpha1
  schema:
    openAPIV3Schema:
      properties:
        apiVersion:
          type: string
        kind:
          type: string
        metadata:
          type: object
        spec:
          type: object
        status:
          type: object
        pollInterval:
          type: string
      type: object
      required:
      - pollInterval
----

.Example error output
[source,text]
----
validating upgrade for CRD "example.test.example.com": v1alpha1: ^: required: new required fields: [pollInterval]
----
