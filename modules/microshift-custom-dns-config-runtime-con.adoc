= Updating a custom Corefile at runtime

[role="_abstract"]
After you set the `dns.configFile` parameter and restart {microshift-short}, {microshift-short} watches the custom Corefile on the host. When you save changes to that file, {microshift-short} updates the `Corefile` key in the `dns-default` config map in the `openshift-dns` namespace. You do not restart the {microshift-short} service to apply those content changes.

CoreDNS applies the updated config map only if the custom Corefile includes the `reload` plugin. Keep that plugin in the file so that DNS changes take effect without restarting {microshift-short} or the DNS pods.

The file watcher applies only to the Corefile path that was set when {microshift-short} started. Restart the {microshift-short} service when you make either of the following changes:

* You change the `dns.configFile` value in the `config.yaml` file or in a configuration snippet.
* You enable or disable `dns.hosts` in the {microshift-short} configuration. The `dns.configFile` and `dns.hosts.status: Enabled` settings remain mutually exclusive.

[IMPORTANT]
====
The {microshift-short} configuration YAML file is read only when the service starts. Runtime watching does not apply to `config.yaml` or to configuration snippets. Only the contents of the already configured Corefile are synchronized without a restart.
====

An invalid edit to the Corefile can break DNS resolution on a running node. Verify the `dns-default` config map and the DNS pods after you change the file.
