= HTTPRoute status conditions reference

[role="_abstract"]
To verify that your `HTTPRoute` custom resource (CR) is attached to a parent gateway and ready to route traffic, review its `status` conditions. A healthy `HTTPRoute` CR reports a status of `True` for the `Accepted` and `ResolvedRefs` conditions on each parent.

The controller writes `HTTPRoute` status per parent gateway in the `status.parents` list. An empty list means the route is not attached to any gateway. Route availability also depends on the parent `Gateway` CR and listener `status` conditions.

You can interpret the `HTTPRoute` status using the following fields:

`status.parents`::
Lists each parent resource, usually a `Gateway` CR, that is associated with the route and the status of the route for that parent. The controller that manages the parent adds an entry when it first sees the route and updates the entry when the route or gateway changes. Unresolved parent references are not added. The list can include a maximum of 32 parents.

`parents.parentRef`::
Identifies the parent from `spec.parentRefs` that this status entry describes, including `name`, `namespace`, `kind`, and optional `sectionName` or `port`.

`parents.controllerName`::
Identifies the controller that wrote this status entry. For the {product-title} Gateway API implementation, this value is `openshift.io/gateway-controller/v1`.

`parents.conditions`::
Reports the status of the route for that parent. The controller sets the `Accepted` condition when the parent exists, supports this route kind, and the controller has access to the route. A route is considered accepted if the gateway implements at least one of its rules. The `Accepted` condition might be unset when the parent does not exist, the route kind is unsupported, or the controller cannot access the route namespace.

[IMPORTANT]
====
The `PartiallyInvalid` condition is set only when its status is `True`. A missing `PartiallyInvalid` condition is the healthy state.
====

.HTTPRoute status conditions
[cols="1,1,3",options="header"]
|===
|Condition |Status |Description and common reasons

|`Accepted`
|`True`
|The parent gateway accepted the route and implements at least one of its rules. The common reason is `Accepted`.

|`Accepted`
|`False`
|The parent gateway rejected the route. Common reasons include `NotAllowedByListeners` (no listener `allowedRoutes` criteria permit the route), `NoMatchingListenerHostname` (no listener hostname intersects with the route hostnames), `NoMatchingParent` (the `parentRef` `port` or `sectionName` does not match a listener), `UnsupportedValue` (an enumerated value is not recognized), or `IncompatibleFilters` (a rule combines incompatible filters, such as `URLRewrite` and `RequestRedirect`).

|`Accepted`
|`Unknown`
|The controller has not reconciled the route yet. The common reason is `Pending`.

|`ResolvedRefs`
|`True`
|The controller resolved all object references on the route. The common reason is `ResolvedRefs`.

|`ResolvedRefs`
|`False`
|At least one reference is invalid. Common reasons include `RefNotPermitted` (a cross-namespace `backendRef` lacks a `ReferenceGrant`), `InvalidKind` (the referenced group or kind is unknown or unsupported), `BackendNotFound` (the referenced backend does not exist), or `UnsupportedProtocol` (the backend application protocol is not supported).

|`PartiallyInvalid`
|`True`
|The route contains a mix of valid and invalid rules. This condition is never set to `False` or `Unknown`. The common reason is `UnsupportedValue`. The condition message starts with `Dropped Rule` when the controller ignores invalid rules and keeps accepted valid rules, or `Fall Back` when the controller reverts to the last known good configuration.
|===

.Example `HTTPRoute` CR status output showing a rejected attachment
[source,yaml]
----
# ...
status:
  parents:
  - parentRef:
      group: gateway.networking.k8s.io
      kind: Gateway
      name: generic-gateway
      namespace: openshift-ingress
    controllerName: openshift.io/gateway-controller/v1
    conditions:
    - type: Accepted
      status: "False"
      reason: NotAllowedByListeners
      message: "No listener allowedRoutes criteria permit this route"
      observedGeneration: 1
      lastTransitionTime: "2025-01-12T10:00:00Z"
    - type: ResolvedRefs
      status: "True"
      reason: ResolvedRefs
      message: "All references resolved"
      observedGeneration: 1
      lastTransitionTime: "2025-01-12T10:00:00Z"
----
