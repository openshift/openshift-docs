= Configuring Tekton Results for records in a multicluster environment

[role="_abstract"]
In a multicluster {pipelines-shortname} environment, you can configure Tekton Results to store `PipelineRun` and `TaskRun` records from all spoke clusters in a centralized external PostgreSQL database. You can then query execution records from the hub cluster.

In this architecture:

* The *hub cluster* runs only the Tekton Results API server to query centralized records, with the watcher and retention policy agent disabled.
* Each *spoke cluster* runs the Tekton Results watcher, API server, and retention policy agent to write pipeline execution data to the shared database.

.Prerequisites

* You have configured the hub and spoke clusters for multicluster support, including scaling `tekton-results-watcher` and `tekton-results-retention-policy-agent` to `0` replicas on the hub cluster. For more information, see xref:../resource/configuring-multicluster-support.adoc#op-configuring-hub-cluster-multicluster_{context}[Configuring the hub cluster for multicluster].
* You have installed the {pipelines-shortname} Operator on the hub and spoke clusters.
* You have provisioned an external PostgreSQL database instance (for example, on Amazon RDS for PostgreSQL) that is network-accessible from both the hub cluster and all spoke clusters.
* You have installed the `psql` client and the `oc` CLI.
* You have access to the hub and spoke clusters as a user with `cluster-admin` permissions.

.Procedure

. Verify connectivity to your external PostgreSQL database by running the following commands:
+
[source,terminal]
----
$ export PGPASSWORD='<password>'
$ psql -h <db_host> -U <db_user> -d tekton-results
----
+
Replace `+<password>+`, `+<db_host>+`, and `+<db_user>+` with your PostgreSQL credentials and endpoint.

. On the *hub cluster* and on *each spoke cluster*, create the `tekton-results-postgres` secret in the `openshift-pipelines` namespace by running the following command:
+
[source,terminal]
----
$ oc create secret generic tekton-results-postgres \
  --namespace=openshift-pipelines \
  --from-literal=POSTGRES_USER=<db_user> \
  --from-literal=POSTGRES_PASSWORD=<password>
----
+
[NOTE]
====
If the `tekton-results-postgres` secret already exists, update it by using the `oc patch` or `oc edit` command.
====

. On the *hub cluster* and on *each spoke cluster*, patch the `TektonConfig` custom resource to connect Tekton Results to the external PostgreSQL database by running the following command:
+
[source,terminal]
----
$ oc patch tektonconfig config --type=merge -p '{
  "spec": {
    "result": {
      "is_external_db": true,
      "db_host": "<db_host>",
      "db_port": 5432,
      "db_sslmode": "prefer"
    }
  }
}'
----
+
Replace `+<db_host>+` with the hostname of your external PostgreSQL instance.

. Wait for the Tekton Results API pods to restart automatically and reach the `Ready` state on the hub and spoke clusters by running the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-pipelines -l app.kubernetes.io/part-of=tekton-results -w
----

.Verification

. Create and run a `PipelineRun` in a custom namespace on the hub cluster so that MultiKueue schedules it to a spoke cluster.
. Wait for the `PipelineRun` to complete.
. Query the execution records from the hub cluster by using the Tekton Results CLI (`tkn results`) or the Tekton Results API, and confirm that `PipelineRun` and `TaskRun` records are stored in the external PostgreSQL database and are queryable from the hub cluster.
