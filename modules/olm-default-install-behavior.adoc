= Default Operator install modes and behavior

[role="_abstract"]
When you install an Operator in {product-title} by using the web console, the available installation modes depend on the install modes supported by the Operator.

Single namespace:: Installs the Operator in the selected namespace to watch and be made available for use in that namespace.

All namespaces:: Installs the Operator in the default `openshift-operators` namespace to watch and be made available to all namespaces in the cluster. In some cases, an Operator author can define metadata to suggest a different installation namespace.

Selecting an install mode does not restrict the permissions granted to the Operator to the selected namespaces. Review the permissions requested by the Operator before installation.

OLM can add permissions for Operator-provided APIs to the `admin`, `edit`, and `view` cluster roles through role aggregation. By default:

* `admin` grants read and write access to most resources, including roles and role bindings.
* `edit` grants read and write access to most resources, including secrets and workloads, but not roles or role bindings.
* `view` grants read access to most resources, excluding secrets, roles, and role bindings.

A `RoleBinding` grants permissions within the namespace where the binding exists, excluding cluster-scoped resources. A `ClusterRoleBinding` grants permissions across the cluster. Aggregation and other bindings can add permissions, so review the current role rules and all applicable bindings to determine user access.

User permissions do not limit Operator permissions. Before granting access to the Operator installation namespace, review permissions to read secrets, create service account tokens, or create workloads.
