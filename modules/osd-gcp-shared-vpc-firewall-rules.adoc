= Configure reduced permissions for a Shared VPC host project on {gcp-short}

[role="_abstract"]
Instead of granting broad administrative roles such as `roles/compute.networkAdmin` and `roles/compute.securityAdmin` on the host project, you can grant a custom role with minimal permissions. This approach significantly reduces the permissions required for Shared VPC installations and improves the security posture of your {gcp-short} environment.

.Prerequisites

* You have a {gcp-short} Shared VPC host project configured and enabled. For more information, see _Enable a host project_ in the _Additional Resources_ section.
* You have the `gcloud` CLI installed and authenticated with sufficient permissions to create custom roles and manage IAM policy bindings on the host project.
* You have created the required firewall rules for your cluster on the host project. For more information, see _Create firewall rules for reduced Workload Identity Federation permissions on {gcp-short}_ in the _Additional Resources_ section.
* You have created a Workload Identity Federation (WIF) configuration and know the service account emails for `osd-deployer`, `osd-control-plane`, and `openshift-machine-api-gcp` in the service project. For more information, see _Create a Workload Identity Federation configuration_ in the _Additional Resources_ section.
* You have created your own DNS zone in the host project and configured the required DNS records for your cluster. For more information, see _Create a DNS zone for your cluster on {gcp-short}_ in the _Additional Resources_ section.

.Procedure

. Set the following environment variables. Replace the placeholder values with your actual project and service account details:
+
[source,terminal]
----
$ HOST_PROJECT=<host_project_id>
$ DEPLOYER_SA=<osd_deployer_sa_email>
$ CONTROL_PLANE_SA=<osd_control_plane_sa_email>
$ MACHINE_API_SA=<machine_api_sa_email>
----
+
where:

`<host_project_id>`:: The ID of the {gcp-short} host project that owns the Shared VPC.
`<osd_deployer_sa_email>`:: The email address of the `osd-deployer` service account in your service project, for example `osd-deployer-<id>@<service_project>.iam.gserviceaccount.com`. This value is available in the WIF configuration output.
`<osd_control_plane_sa_email>`:: The email address of the `osd-control-plane` service account in your service project, for example `osd-control-plane-<id>@<service_project>.iam.gserviceaccount.com`. This value is available in the WIF configuration output.
`<machine_api_sa_email>`:: The email address of the `openshift-machine-api-gcp` service account in your service project, for example `openshift-machine-api-gcp-<id>@<service_project>.iam.gserviceaccount.com`. This value is available in the WIF configuration output.

. Create a custom IAM role on the host project with the minimal permissions required for Shared VPC access:
+
[source,terminal]
----
$ gcloud iam roles create osd_shared_vpc_role \
  --project=$HOST_PROJECT \
  --title="OSD Shared VPC Minimal Access" \
  --permissions=compute.firewalls.get,compute.networks.get,compute.subnetworks.get,compute.subnetworks.list,compute.subnetworks.use,compute.subnetworks.useExternalIp,compute.projects.get,resourcemanager.projects.get
----
+
[NOTE]
====
For Private Service Connect (PSC) clusters with bring your own (BYO) DNS Zones and BYO firewall rules, you can omit the `compute.subnetworks.useExternalIp` permission from the custom role. This permission is only required for public clusters.
====
+
The following table describes each permission in the custom role:
+
[cols="1,2",options="header"]
|===
| Permission | Description

| `compute.firewalls.get`
| Read firewall rule information from the host project. Required for pre-flight checks that verify firewall rules are present and configured correctly.

| `compute.networks.get`
| Read VPC network information from the host project.

| `compute.subnetworks.get`
| Read subnet information from the host project.

| `compute.subnetworks.list`
| List subnets in the host project.

| `compute.subnetworks.use`
| Use subnets in the host project for creating instances.

| `compute.subnetworks.useExternalIp`
| Assign external IP addresses to instances that use host project subnets. This permission is required for public clusters only.

| `compute.projects.get`
| Read compute project metadata from the host project.

| `resourcemanager.projects.get`
| Read general project-level information such as project ID and name.
|===

. Grant the custom role to the `osd-deployer`, `osd-control-plane`, and `openshift-machine-api-gcp` service accounts on the host project:
+
[source,terminal]
----
$ gcloud projects add-iam-policy-binding $HOST_PROJECT \
  --member="serviceAccount:$DEPLOYER_SA" \
  --role="projects/$HOST_PROJECT/roles/osd_shared_vpc_role" &&\
  gcloud projects add-iam-policy-binding $HOST_PROJECT \
  --member="serviceAccount:$CONTROL_PLANE_SA" \
  --role="projects/$HOST_PROJECT/roles/osd_shared_vpc_role" &&\
  gcloud projects add-iam-policy-binding $HOST_PROJECT \
  --member="serviceAccount:$MACHINE_API_SA" \
  --role="projects/$HOST_PROJECT/roles/osd_shared_vpc_role"
----
+
[NOTE]
====
The `openshift-machine-api-gcp` service account requires host project permissions so that new nodes created on day two can connect to the Shared VPC network.
====

.Verification

* Verify that the custom role was created with the expected permissions:
+
[source,terminal]
----
$ gcloud iam roles describe osd_shared_vpc_role --project=$HOST_PROJECT
----

* Verify that the role bindings were applied:
+
[source,terminal]
----
$ gcloud projects get-iam-policy $HOST_PROJECT \
  --flatten="bindings[].members" \
  --filter="bindings.role:roles/osd_shared_vpc_role" \
  --format="table(bindings.members)"
----
