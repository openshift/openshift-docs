= Configure the Alertmanager adapter for autonomous triggering

[role="_abstract"]
When you set up autonomous troubleshooting for the first time, configure the Alertmanager adapter to process critical alerts so that the agent can automatically begin investigating cluster incidents.

By default, the `lightspeed-agentic-alerts-adapter` pod runs in your cluster but does not process alerts. You must configure the adapter to automatically process critical alerts before the agent can monitor your cluster and generate proposed remediation plans.

.Prerequisites

* You are logged in to the {ocp-product-title} web console as a cluster administrator.

* The {ols-long} autonomous agents Operator is installed and configured.

.Procedure

. In the web console, select the `openshift-lightspeed` project from the *Project* drop-down menu.

. In the navigation menu, click *Workloads* -> *ConfigMaps*.

. Click the `alerts-adapter-config` ConfigMap, and then edit its configuration.

. In the `filtering` section of the configuration, uncomment `- critical` under `allowedReceivers` to authorize the adapter to process critical alerts:
+
[source,yaml]
----
filtering:
  allowedReceivers:
    - critical
----

. Click *Save*.

Alternatively, if the `alerts-adapter-config` ConfigMap does not exist, you can create it and enable the adapter by using the CLI:

. Create the `alerts-adapter-config` ConfigMap by running the following command:
+
[source,terminal]
----
$ oc apply -f - <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: alerts-adapter-config
  namespace: openshift-lightspeed
data:
  config.yaml: |
    filtering:
      allowedReceivers:
      - critical # <1>
    tools:
      skills: # <2>
        - image: quay.io/openshiftanalytics/agentic-skills:latest
          paths:
            - /skills/cluster-troubleshoot/investigate-alert
EOF
----
<1> The alert receivers that the adapter is authorized to process.
<2> The container image and paths that provide the troubleshooting skills the agent uses to investigate matching alerts.

. Enable the adapter by patching the `OLSConfig` CR to reference the ConfigMap by running the following command:
+
[source,terminal]
----
$ oc patch olsconfig cluster --type=merge -p '{
  "spec": {
    "ols": {
      "deployment": {
        "alertsAdapter": {
          "configMapRef": {
            "name": "alerts-adapter-config"
          }
        }
      }
    }
  }
}'
----

. Wait for the alerts adapter deployment to roll out by running the following command:
+
[source,terminal]
----
$ oc rollout status deployment/lightspeed-agentic-alerts-adapter \
  -n openshift-lightspeed --timeout=300s
----

.Verification

. In the web console, navigate to *Agentic Runs*.

. Verify that new runs appear when critical alerts fire on the cluster.
