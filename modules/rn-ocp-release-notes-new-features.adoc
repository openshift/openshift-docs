[id="ocp-release-notes-storage-group-snap-ga_{context}"]
=== CSI volume group snapshots is generally available 
Container Storage Interface (CSI) volume group snapshots use a label selector to group multiple persistent volume claims (PVCs) for snapshotting. A volume group snapshot represents copies from multiple volumes that are taken at the same point-in-time. This can be useful for applications that contain multiple volumes. This feature needs to be supported by the CSI driver.

{rh-storage} supports volume group snapshots.

{product-title} 4.18 introduced CSI volume group snapshots as a Technology Preview feature. {product-title} 5.0 supports this feature as generally available.

For more information about CSI volume group snapshots, see xref:../storage/container_storage_interface/persistent-storage-csi-group-snapshots.adoc#persistent-storage-csi-group-snapshots[CSI volume group snapshots].

[id="ocp-release-notes-storage-changed-block-tp_{context}"]
=== Changed block tracking (Technology Preview)
Changed block tracking (CBT) identifies the data blocks that change between two snapshots of a persistent volume, so backup solutions can copy only what changed rather than the entire volume.

CBT enables efficient, incremental backups and disaster recovery for persistent volumes (PVs) managed by Container Storage Interface (CSI) drivers that support this feature. Consumers can request a list of the blocks that changed between two snapshots, which is useful for backup solution vendors. By backing up only changed blocks instead of entire volumes, backup processes are faster and more efficient.

CBT was introduced in {product-title} 4.20 as Developer Preview. For 5.0, it is supported as Technology Preview.

For more information about CBT, see the Red Hat Knowledgebase solution link:https://access.redhat.com/solutions/7146879[How to use Changed Block Tracking (Tech Preview) in OpenShift 5.0].

[id="ocp-release-notes-storage-selinux-mount-opt-upcoming-ga-default_{context}"]
=== Upcoming SELinux mount option default for RWO/RWX volumes
For {product-title} 5.0, ReadWriteOnce (RWO) and ReadWriteMany (RWX) volumes use recursive relabeling by default. However, {product-title} 5.1 is targeted to have RWO and RWX volumes use mount option by default.

Some pods might not start when SELinux mount option behavior is applied. To prepare for a future upgrade to 5.1, cluster administrators must either:

* Fix your applications, so that the upgrade is safe.
+
{product-title} reports SELinux-related conflicts when creating pods, and on running pods, to make you aware of potential conflicts, and to help you resolve them. For more information about this reporting, see the Red Hat Knowledgebase article link:https://access.redhat.com/solutions/7131398[OpenShift reports SELinux-related conflicts when creating Pods (Red{nbsp}Hat Knowledgebase)].

* Opt-out from the new default behavior, per pod or namespace.
+
If you are unable to resolve the SELinux-related conflicts, you can proactively opt-out of the future move to mount option as default for selected pods or namespaces. To opt out, see xref:../storage/understanding-persistent-storage.adoc#using_selinuxChangePolicy_pod-opt-out_understanding-persistent-storage[Opting out of the SELinux mount option default].

For more information about SELinux mount option for RWO/RWX, see xref:../storage/understanding-persistent-storage.adoc#using_selinuxChangePolicy_overview-mount-option-rwo-rwx_understanding-persistent-storage[RWO and RWX and SELinux mount option].
