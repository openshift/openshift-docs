[id="ocp-release-notes-networking_{context}"]
== Networking

// OSDOCS-20704
Updated IPv6 support policy::
+
{product-title} supports IPv6, including single-stack and dual-stack networking, wherever the underlying infrastructure platform provides IPv6. This model applies across {product-title} deployment models.
+
IPv6 is fully supported on the following platforms, where the platform provides IPv6 connectivity:
+
--
* Bare-metal, user-provisioned, and platform-agnostic clusters, when the customer network provides IPv6
* {vmw-full}
* {rh-openstack-first}
* {ibm-power-name} and {ibm-power-vc-name}
* {ibm-z-name} and {ibm-linuxone-name}
* {ibm-cloud-name} classic infrastructure
* {oci-first}
--
+
IPv6 is supported with platform-specific limitations on the following platforms:
+
--
* {aws-first}: Dual-stack cluster installation remains a Technology Preview feature. Dual-stack installation is not supported in {aws-short} Wavelength Zones. Classic Load Balancers do not support IPv6. For service-level IPv6 support, see link:https://docs.aws.amazon.com/vpc/latest/userguide/aws-ipv6-support.html[{aws-first} services that support IPv6].
* {azure-full}: Dual-stack virtual networks are supported. IPv6-only virtual machines are not supported. For additional {azure-short} IPv6 limitations, see link:https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/ipv6-overview#limitations[{azure-full} IPv6 limitations].
* {gcp-first}: Dual-stack and IPv6-only addressing are available for some services. For the service matrix, see link:https://docs.cloud.google.com/vpc/docs/ipv6-support[{gcp-first} IPv6 support].
* {alibaba}: Dual-stack VPCs are supported. IPv6-only VPCs are not supported. See link:https://www.alibabacloud.com/help/en/vpc/frequently-asked-questions[{alibaba} VPC FAQ].
* Nutanix: Guest IPv6 is supported only on unmanaged (Network Controller) VLAN subnets when the physical fabric provides IPv6. Basic VLAN subnets do not support IPv6. See link:++https://portal.nutanix.com/page/documents/details?targetId=Prism-Central-Guide-vpc_7_3:mul-explore-vm-view-pc-r.html++[Nutanix Prism VMs summary view].
* {oci-c3} and {oci-edge}: IPv6 is limited to SR-IOV virtual network interface cards (VNICs). See link:https://docs.oracle.com/iaas/releasenotes/compute-cloud-at-customer/release-note-m3-12-oct2025.htm[{oci-c3} October 2025 release notes].
* {VirtProductName}: Support for single-stack IPv6 clusters is limited to the OVN-Kubernetes `localnet` topology and the Linux bridge Container Network Interface (CNI) plugin.
--
+
IPv6 is not available on the following platforms because the vendor does not provide IPv6:
+
--
* Microsoft Azure Stack Hub. See link:https://learn.microsoft.com/en-us/azure-stack/user/azure-stack-network-overview[Azure Stack Hub networking].
* {ibm-cloud-name} VPC infrastructure. See link:https://cloud.ibm.com/docs/vpc?topic=vpc-limitations[{ibm-cloud-name} VPC limitations] and link:https://cloud.ibm.com/docs/infrastructure-hub?topic=infrastructure-hub-compare-infrastructure[Comparing classic and VPC infrastructure].
* {ibm-power-server-name}. Private subnets are documented as IPv4 CIDR only. See link:https://cloud.ibm.com/docs/power-iaas?topic=power-iaas-configuring-subnet[Configuring a private network subnet].
* {oda-first}. See link:https://docs.oracle.com/en/engineered-systems/oracle-database-appliance/19.22/cmtrx/faqs-oracle-database-appliance-networks.html[{oda} Networks FAQ].
--
+
For OVN-Kubernetes dual-stack configuration requirements that apply to all IPv6 clusters, see xref:../networking/ovn_kubernetes_network_provider/about-ovn-kubernetes.adoc#nw-ovn-kubernetes-limitations_about-ovn-kubernetes[OVN-Kubernetes IPv6 and dual-stack limitations].

Support for Fibre Channel over Ethernet (FCoE)::
+
With this update, the Fibre Channel over Ethernet (FCoE) protocol is supported for clusters running the x86_64 architecture. FCoE in {op-system} consists of the following packages:
+
--
// From https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/6/html/6.4_technical_notes/fcoe-utils
* fcoe-utils. The fcoe-utils packages provide Fibre Channel over Ethernet (FCoE) utilities, such as the fcoeadm command line tool for configuring FCoE interfaces, and the fcoemon service to configure DCB Ethernet QOS filters.
* lldpad. The Link Layer Discovery Protocol daemon package (lldpad) provides critical visibility and management capabilities for network infrastructure, reducing troubleshooting time.
// From https://redhat.atlassian.net/browse/OCPSTRAT-2580--
--
+
FCoE is a protocol to transmit Fibre Channel frames over Ethernet networks. For more information, see link:https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/managing_storage_devices/configuring-fibre-channel-over-ethernet_managing-storage-devices[Configuring Fibre Channel over Ethernet (Red Hat Enterprise Linux documentation)].
