Dual stack enabled for {product-title} clusters on {aws-first}::
+
With this update, {product-title} clusters on {aws-first} can be configured to use dual-stack networking. This allows for both IPv4 and IPv6 addresses to be used for network traffic. Currently, single stack IPv6 is not supported. For more information, see xref:../networking/networking_operators/cluster-network-operator.adoc#nw-operator-cr_cluster-network-operator[Cluster Network Operator configuration object].

[id="ocp-release-notes-storage_{context}"]
== Storage

CSI volume group snapshots is generally available::
Container Storage Interface (CSI) volume group snapshots use a label selector to group multiple persistent volume claims (PVCs) for snapshotting. A volume group snapshot represents copies from multiple volumes that are taken at the same point-in-time. This can be useful for applications that contain multiple volumes. This feature needs to be supported by the CSI driver.
+
{rh-storage} supports volume group snapshots.
+
{product-title} 4.18 introduced CSI volume group snapshots as a Technology Preview feature. {product-title} 5.0 supports this feature as generally available.
+
For more information about CSI volume group snapshots, see xref:../storage/container_storage_interface/persistent-storage-csi-group-snapshots.adoc#persistent-storage-csi-group-snapshots[CSI volume group snapshots].

Changed block tracking (Technology Preview)::
Container Storage Interface (CSI) Changed block tracking (CBT) enables compatible backup applications to identify block ranges that changed between two snapshots of the same underlying CSI block-storage volume.
+
Backup applications can use changed-block metadata to reduce the data read and transferred for incremental backups. The API can also identify allocated block ranges in a single snapshot, allowing backup applications to skip unallocated ranges when creating a full backup of that snapshot. These operations return metadata, not the snapshot data itself. The backup application reads and backs up the relevant data separately. 
+
CBT was introduced in {product-title} 4.20 as Developer Preview. For 5.0, it is supported as Technology Preview.
+
CBT requires support from both the CSI driver and the backup application.
+
For more information about CBT, see the Red{nbsp}Hat Knowledgebase solution link:https://access.redhat.com/solutions/7146879[How to use Changed Block Tracking (Tech Preview) in OpenShift 5.0] 
// ??? and xref:../storage/container_storage_interface/persistent-storage-csi-changed-block-tracking.adoc[Overview of Changed block tracking].

Upcoming SELinux mount option default for RWO/RWX volumes::
For {product-title} 5.0, ReadWriteOnce (RWO) and ReadWriteMany (RWX) volumes use recursive relabeling by default. However, {product-title} 5.1 is targeted to have RWO and RWX volumes use mount option by default.
+
Some pods might not start when SELinux mount option behavior is applied. 
+
To prepare for a future upgrade to 5.1, cluster administrators *must* do one of the following or the upgrade will be blocked:
+
* Fix your applications, so that the upgrade is safe.
+
{product-title} reports SELinux-related conflicts when creating pods, and on running pods, to make you aware of potential conflicts, and to help you resolve them. For more information about this reporting, see the Red Hat Knowledgebase article link:https://access.redhat.com/solutions/7146569[OpenShift reports alert SELinuxMountGAReadinessWorkloadsDetected and the cluster is not upgradeable. (Red{nbsp}Hat Knowledgebase)].

* Opt-out from the new default behavior, per pod or namespace.
+
If you are unable to resolve the SELinux-related conflicts, you can proactively opt-out of the future move to mount option as default for selected pods or namespaces. To opt out, see xref:../storage/understanding-persistent-storage.adoc#using_selinuxChangePolicy_pod-opt-out_understanding-persistent-storage[Opting out of the SELinux mount option default].

For more information about SELinux mount option for RWO/RWX, see xref:../storage/understanding-persistent-storage.adoc#using_selinuxChangePolicy_overview-mount-option-rwo-rwx_understanding-persistent-storage[RWO and RWX and SELinux mount option].
