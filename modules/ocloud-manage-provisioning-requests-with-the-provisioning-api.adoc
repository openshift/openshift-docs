= Manage provisioning requests with the Provisioning API

[role="_abstract"]
You can create, monitor, update, and delete provisioning requests through the O-Cloud Manager Provisioning API. This interface is designed for Service Management and Orchestration (SMO) frameworks and external automation systems that do not have direct `oc` access to the hub cluster. The Provisioning API accepts the same parameters as the `ProvisioningRequest` custom resource (CR).

.Prerequisites

* You authenticated to the O-Cloud Manager REST API and set the `API_BASE_URL` and `MY_TOKEN` environment variables.
* A validated `ClusterTemplate` CR exists on the hub cluster.
* Bare-metal servers with resource selector labels matching the `ClusterTemplate` CR requirements are onboarded.

.Procedure

. Set the Provisioning API base URL by running the following command:
+
[source,terminal]
----
$ export PROV_URL="https://${API_BASE_URL}/o2ims-infrastructureProvisioning/v1"
----

. Create a provisioning request by running the following command:
+
[source,terminal]
----
$ curl -ks -X POST \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${MY_TOKEN}" \
  "${PROV_URL}/provisioningRequests" -d \
  '{
    "provisioningRequestId": "123e4567-e89b-12d3-a456-426614174000",
    "name": "sno1-request",
    "description": "SNO cluster for site rack-a",
    "templateName": "sno-ran-du",
    "templateVersion": "v4-Y-Z-1",
    "templateParameters": {
      "nodeClusterName": "sno1",
      "oCloudSiteId": "site-rack-a",
      "clusterInstanceParameters": {
        "clusterName": "sno1",
        "baseDomain": "example.com",
        "nodes": [
          {
            "hostName": "sno1.example.com"
          }
        ]
      },
      "policyTemplateParameters": {
        "cpu-isolated": "2-31",
        "cpu-reserved": "0-1,32-33"
      }
    }
  }' | jq
----
+
* The `provisioningRequestId` must be a valid UUID.
* The `templateParameters` structure is identical to the `spec.templateParameters` field of the `ProvisioningRequest` CR. For details on each parameter, see _Provision a cluster using a ProvisioningRequest_.
+
[NOTE]
====
For advanced templating strategies and to configure hardware selection overrides for specific sites, see xref:ocloud-configuring-advanced-hardware-management[Configure advanced hardware management].
====

. Check provisioning status by running the following command:
+
[source,terminal]
----
$ curl -ks -H "Authorization: Bearer ${MY_TOKEN}" \
  "${PROV_URL}/provisioningRequests/123e4567-e89b-12d3-a456-426614174000" | jq -r '.status'
----

. Delete a provisioning request to deprovision the cluster by running the following command:
+
[source,terminal]
----
$ curl -ks -X DELETE -H "Authorization: Bearer ${MY_TOKEN}" \
  "${PROV_URL}/provisioningRequests/123e4567-e89b-12d3-a456-426614174000"
----

.Verification

* After creating a provisioning request, query its status and verify that the `provisioningPhase` progresses from `pending` to `progressing` to `fulfilled`.
