= Understanding custom DNS configuration

[role="_abstract"]
By default, {microshift-short} renders an internal CoreDNS Corefile for the node. You can replace that built-in configuration by setting the `dns.configFile` parameter in the {microshift-short} configuration file to the absolute path of a custom Corefile on the host filesystem.

Use a custom Corefile when the default DNS configuration does not meet advanced networking requirements. Typical use cases include split-horizon DNS, custom forwarding rules, and conditional zone delegation.

[WARNING]
====
You are responsible for the correctness of a custom CoreDNS configuration. An invalid Corefile can break DNS resolution or cause intermittent errors. Red{nbsp}Hat support for issues that involve a custom Corefile is limited to commercially reasonable efforts. Support might require you to reproduce the issue without the custom configuration.
====

If you do not set `dns.configFile`, or you leave the value empty, {microshift-short} uses the built-in Corefile.

The `dns.configFile` and `dns.hosts` parameters are mutually exclusive. If you set `dns.configFile` and you also set `dns.hosts.status` to `Enabled`, {microshift-short} fails to start.

When you set `dns.configFile`, the custom Corefile must meet the following constraints. If any constraint fails, {microshift-short} fails to start:

* The path must be absolute. For example, `/etc/microshift/dns/Corefile`.
* The file must exist.
* The file must be a regular file.
* The file must be readable.
* The file must not be empty.
* The file must not exceed 1 MiB.
