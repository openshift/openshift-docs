= Pausing and restarting the Vertical Pod Autoscaler Operator

[role="_abstract"]
You can pause Vertical Pod Autoscaler Operator (VPA) behavior by deleting the `VerticalPodAutoscalerController` custom resource (CR) without the need to uninstall the Operator.

Deleting the Vertical Pod Autoscaler Controller removes the pods and operands for the VPA components, but does not remove the required Operator pods and operands. Any VPAs in your cluster stop updating recommendations, but are not deleted. 

You can restart the VPAs by creating a new `VerticalPodAutoscalerController` CR.

You can disable this behavior by removing the `autoscaling.openshift.io/default-vpa-controller-created` from the `openshift-vertical-pod-autoscaler` namespace object.

////
$ oc get namespace openshift-vertical-pod-autoscaler -o yaml

[source,terminal]
----
apiVersion: v1
kind: Namespace
metadata:
  annotations:
    autoscaling.openshift.io/default-vpa-controller-created: "true"
# ...
  name: openshift-vertical-pod-autoscaler
----
////

. Delete the `VerticalPodAutoscalerController` object to pause the VPA by running the following command:
+
[source,terminal]
----
$ oc delete VerticalPodAutoscalerController default -n openshift-vertical-pod-autoscaler
----

. Verify that the VPA operand deployments are removed by running the following command:
+
[source,terminal]
----
$ oc get all -n openshift-vertical-pod-autoscaler
----

+

$ oc get pods -n openshift-vertical-pod-autoscaler

Only the Operator pod remains.

. Re-create the `VPAController` custom resource from a YAML file to resume the VPA. For more information, see "Use the Vertical Pod Autoscaler Operator" in this section.

.. Create a VPA CR YAML file similar to the following example:
+
[source,yaml]
----
apiVersion: autoscaling.openshift.io/v1
kind: VerticalPodAutoscalerController
metadata:
  name: default
  namespace: openshift-vertical-pod-autoscaler
spec:
  deploymentOverrides:
    admission:
      container:
        resources: {}
      nodeSelector:
        node-role.kubernetes.io/worker: ""
      tolerations:
      - key: "my-example-node-taint-key"
        operator: "Exists"
        effect: "NoSchedule"
    recommender:
      container:
        resources: {}
      nodeSelector:
        node-role.kubernetes.io/worker: ""
      tolerations:
      - key: "my-example-node-taint-key"
        operator: "Exists"
        effect: "NoSchedule"
    updater:
      container:
        resources: {}
      nodeSelector:
        node-role.kubernetes.io/worker: ""
      tolerations:
      - key: "my-example-node-taint-key"
        operator: "Exists"
        effect: "NoSchedule"
----

.. Create the VPA CR:
+
[source,terminal]
----
$ oc create -f <file-name>.yaml
----

. View the VPA operands by running the following command:
+
[source,terminal]
----
$ oc get all -n openshift-vertical-pod-autoscaler
----
+
All of the necessary VPA operands are running, as previously listed.

. View the VPA pods by running the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-vertical-pod-autoscaler
----
+
All of the necessary VPA operands are running, as previously listed.

. Verify that your VPAs are running by running the following command:
+
[source,terminal]
----
$ oc get vpa <vpa-name> --output yaml
