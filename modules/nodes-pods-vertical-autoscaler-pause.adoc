= Pausing and restarting the Vertical Pod Autoscaler Operator

[role="_abstract"]
You can pause Vertical Pod Autoscaler Operator (VPA) behavior by deleting the `VerticalPodAutoscaler` custom resource (CR). Re-creating the CR restarts the VPA.

Pausing the VPA stops functionality without the need to uninstall the Operator. You can restart the VPA by creating a new `VerticalPodAutoscaler` CR.

// Operator namespace annotation for default controller creation
	DefaultVPAControllerAnnotation = "autoscaling.openshift.io/default-vpa-controller-created"

.Procedure

+
[source,terminal]
----
$ oc get VerticalPodAutoscalerController -n openshift-vertical-pod-autoscaler
----

[source,terminal]
----

openshift-vertical-pod-autoscaler   default   30m
----

. Re-create the `VPAController` custom resource from a YAML file to resume the VPA. For more information, see "Use the Vertical Pod Autoscaler Operator" in this section.

.. Create a VPA CR YAML file similar to the following example:
+
[source,yaml]
----
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler
metadata:
  name: vpa-recommender
spec:
  targetRef:
    apiVersion: "apps/v1"
    kind:       Deployment
    name:       frontend
  updatePolicy:
    updateMode: "InPlaceOrRecreate"
  resourcePolicy:
    containerPolicies:
    - containerName: my-opt-sidecar
      mode: "Off"
  recommenders:
    - name: my-recommender
----

.. Create the VPA CR:
+
[source,terminal]
----
$ oc create -f <file-name>.yaml
----
+
After a few moments, the VPA learns the resource usage of the containers in the pods associated with the workload object.

. Verify that the VPA operand deployments are running by running the following command to view the VPA recommendations:
+
[source,terminal]
----
$ oc get vpa <vpa-name> --output yaml
----
+
