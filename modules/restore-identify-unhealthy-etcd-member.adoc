= Identifying an unhealthy etcd member

[role="_abstract"]
Check whether your cluster has an unhealthy etcd member by reviewing etcd member availability. Identifying the affected member enables you to determine the failure type and choose the correct replacement procedure.

Use the procedures in this assembly when one etcd member is unhealthy and the majority of control plane hosts are still available.

[NOTE]
====
If you have lost the majority of your control plane hosts, use disaster recovery to restore to a previous cluster state instead of this procedure. For more information, see "Restoring to a previous cluster state".

If the control plane certificates are not valid on the member being replaced, recover from expired control plane certificates instead of this procedure. For more information, see "Recovering from expired control plane certificates".

If a control plane node is lost and a new one is created, the etcd cluster Operator handles generating the new TLS certificates and adding the node as an etcd member.
====

.Prerequisites

* You confirmed access to the cluster as a user with the `cluster-admin` role.
* You created an etcd backup.

.Procedure

* Check the status of the `EtcdMembersAvailable` status condition by running the following command:
+
[source,terminal]
----
$ oc get etcd -o=jsonpath='{range .items[0].status.conditions[?(@.type=="EtcdMembersAvailable")]}{.message}{"\n"}{end}'
----
+
.Example output
[source,terminal]
----
2 of 3 members are available, ip-10-0-131-183.ec2.internal is unhealthy
----
