= Configure audit logging and tracing

[role="_abstract"]
Configure compliance audit logging for {ols-official} to produce a durable, reconstructable record of AI actions. This feature supports regulatory requirements such as the EU AI Act by capturing who asked what, what the AI proposed, who approved it, and what the system executed. It is enabled by default on both {ols-long} and agentic {ols-long}.

.Prerequisites

* You have logged in to the {ocp-product-title} web console as a user with the `cluster-admin` role.
* You have access to the {oc-first}.
* You have installed the {ols-long} Operator and deployed the {ols-long} service.

.Procedure

. To disable audit logging for {ols-long}, set `spec.audit.enabled` to `false` in the `OLSConfig` CR:
+
[source,yaml]
----
spec:
  audit:
    enabled: false
----
+
[IMPORTANT]
====
Disabling audit logging might violate regulatory compliance requirements. Ensure that disabling audit logs aligns with your organization's compliance and security policies before proceeding.
====

. To disable audit logging for agentic {ols-long}, set `spec.audit.enabled` to `false` in the `AgenticOLSConfig` CR:
+
[source,yaml]
----
spec:
  audit:
    enabled: false
----

. Optional: To export audit events to an OpenTelemetry Collector, add the `spec.audit.otel.endpoint` field to the relevant CR. You can configure this on `OLSConfig`, `AgenticOLSConfig`, or both, independently:
+
[source,yaml]
----
spec:
  audit:
    enabled: true
    otel:
      endpoint: grpc://otel-collector.observability.svc.cluster.local:4317
----

. Apply the updated CR:
+
[source,terminal]
----
$ oc apply -f <cr-file>.yaml
----
+
Example output:
+
[source,terminal]
----
olsconfig.ols.openshift.io/cluster configured
----

.Verification

* To verify that audit events are being emitted for {ols-long}, inspect the service pod logs and filter for JSON audit entries:
+
[source,terminal]
----
$ oc logs -n openshift-lightspeed deployment/lightspeed-app-server | grep '"event"'
----
+
Each audit entry appears as a structured JSON line containing an `event` field, a `trace_id`, a `user_id`, and a `timestamp`.

* To verify audit events for agentic {ols-long}, inspect the agentic operator logs:
+
[source,terminal]
----
$ oc logs -n openshift-lightspeed deployment/lightspeed-agentic-operator | grep '"event"'
----
