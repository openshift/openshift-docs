= Deploy secured cluster services by using the Operator

[role="_abstract"]
You can install secured cluster services on your Kubernetes clusters by using the {product-title-short} Operator, which creates the `SecuredCluster` custom resource.
You must install the secured cluster services on every cluster in your environment that you want to monitor.

If you have already installed the {product-title-short} Operator on the cluster you are securing, you do not have to install the Operator again. If this is a new cluster that does not have the Operator installed, you must install it. See "Install the {product-title-short} Operator on other platforms".

[IMPORTANT]
====
When you install {product-title}:

* You must first install the `Central` custom resource because the `SecuredCluster` custom resource installation is dependent on certificates that Central generates.
* If you are installing the `SecuredCluster` custom resource on the same cluster as Central, it is recommended to install it in the same namespace as Central. Using a different namespace can result in duplicate Scanner deployments.
====

.Prerequisites

* The {product-title-short} Operator is installed on the cluster. For more information, see "Install the {product-title-short} Operator on other platforms".
* You have generated a cluster registration secret (CRS) or an init bundle.

.Procedure

. Create the `stackrox` namespace where you will create the `SecuredCluster` custom resource, unless you already created it for the Central installation:
+
[source,terminal]
----
$ kubectl create namespace stackrox
----
. Optional: Depending on where you are deploying the image from, create an image pull secret:
* If you are not deploying from the Red Hat image registry, you do not need an image pull secret. You can omit the following steps for generating a token and applying the secret.
* If you are deploying directly from the Red Hat image registry, you must have one of the following:
** A cluster-wide image pull secret
** ** An image pull secret for the {product-title-short} Operator (that was installed in the `rhacs-operator` namespace) and application component images such as Central, Scanner, and Sensor. You only need one of these secrets for each namespace in which you deploy {product-title-short}. If you already installed Central into this namespace, you can use the pull secret that you previously created and used with Central.
.. Generate a registry service account access token by using the Red Hat Customer Portal. For instructions, see "Creating Registry Service Accounts".
.. After you have generated the token, go to the *OpenShift Secret* tab on your *Token Information* page and download a secret suitable for use on Kubernetes clusters. 
.. Apply the secret in the namespace you just created, for example, `stackrox`:
+
[source,terminal]
----
$ kubectl apply -f <path-to-secret/pull-secret.yaml> -n stackrox
----
.  Apply the CRS or the init bundle in the namespace you created. For example, to apply the CRS, enter:
+
[source,terminal]
----
$ kubectl create -f <file_name.yaml> -n <namespace>
----
+
where:

<file_name.yaml>:: Specifies the file name of the CRS.
<namespace>:: Specifies the project name, or namespace, that you created. 

. Create a YAML file for the `SecuredCluster` custom resource:
+
[source,yaml,subs="+quotes"]
----
apiVersion: platform.stackrox.io/v1alpha1
kind: SecuredCluster
metadata:
  name: stackrox-secured-cluster-services
  namespace: stackrox
spec:
  imagePullSecrets:
    - name: _<pull_secret_name>_
  clusterName: _<cluster_name>_
  centralEndpoint: _<central_address>_
----
+
where:
+
--
`_<pull_secret_name>_`:: Specifies the pull secret that was configured for the Operator. If you have a cluster-wide image pull secret configured, you can omit the `imagePullSecrets` field.
`_<cluster_name>_`:: Specifies a unique name to identify this cluster, for example, `prod-west`.
`_<central_address>_`:: Specifies the address of your Central instance, for example, `central.example.com:443`. Omit the field (or use the default value of `central.stackrox.svc:443`) only if you are installing secured cluster services on the same cluster as Central, installed in the namespace `stackrox`.
--

. Apply the custom resource:
+
[source,terminal,subs="+quotes"]
----
$ kubectl apply -f _<securedcluster_cr_file>_.yaml
----

.Verification

. Wait for secured cluster services to become ready:
+
[source,terminal]
----
$ kubectl -n stackrox get securedcluster
----
Confirm that secured cluster services have been installed (`AVAILABLE`=`True` and `PROGRESSING`=`False`).
+
.Example output
----
NAME                                VERSION   MESSAGE                                                 PROGRESSING   AVAILABLE
stackrox-secured-cluster-services   4.11.0     StackRox Secured Cluster Services has been installed.   False         True
----
. Verify that the secured cluster services are running:
+
.Example output
----
$ kubectl get pods -n stackrox
----
+
