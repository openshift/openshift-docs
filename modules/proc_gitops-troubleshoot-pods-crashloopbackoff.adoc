= Argo CD pods in CrashLoopBackOff

[role="_abstract"]
Troubleshoot Argo CD component pods that are in CrashLoopBackOff state due to resource constraints, configuration errors, or dependency issues.

.Prerequisites

* You have `cluster-admin` or sufficient permissions to view pods and logs in the `openshift-gitops` namespace.
* You have access to the {OCP} web console or CLI.

.Procedure

. Identify which pod is crashing:
+
[source,terminal]
----
$ oc get pods -n openshift-gitops
----
+
*Example output showing crashed pod:*
[source,terminal]
----
NAME                                            READY   STATUS             RESTARTS   AGE
openshift-gitops-application-controller-0       0/1     CrashLoopBackOff   5          10m
----

. Check pod events for the root cause:
+
[source,terminal]
----
$ oc describe pod <pod_name> -n openshift-gitops
----
+
Look for events indicating the failure reason, such as:
+
* `OOMKilled` - Out of memory
* `Error` - Application crash
* `ImagePullBackOff` - Cannot pull container image

. Check pod logs for error messages:
+
[source,terminal]
----
$ oc logs <pod_name> -n openshift-gitops --previous
----
+
Use `--previous` to view logs from the crashed container.

. Common causes and solutions:
+
** *Out of memory (OOMKilled):*
+
... Increase memory limits in the Argo CD CR:
+
[source,yaml]
----
apiVersion: argoproj.io/v1beta1
kind: ArgoCD
metadata:
  name: openshift-gitops
  namespace: openshift-gitops
spec:
  controller:
    resources:
      limits:
        memory: 4Gi
      requests:
        memory: 2Gi
----
+
... Apply the updated CR:
+
[source,terminal]
----
$ oc apply -f argocd.yaml
----
+
** *Redis connection failures:*
+
... Check Redis pod status:
+
[source,terminal]
----
$ oc get pods -n openshift-gitops -l app.kubernetes.io/name=openshift-gitops-redis
----
+
... If Redis is unhealthy, check its logs:
+
[source,terminal]
----
$ oc logs <redis_pod_name> -n openshift-gitops
----
+
... Restart Redis if needed:
+
[source,terminal]
----
$ oc delete pod <redis_pod_name> -n openshift-gitops
----
+
** *Configuration errors:*
+
... Review the Argo CD custom resource for syntax errors:
+
[source,terminal]
----
$ oc get argocd openshift-gitops -n openshift-gitops -o yaml
----
+
... Validate ConfigMaps for formatting issues:
+
[source,terminal]
----
$ oc get cm argocd-cm -n openshift-gitops -o yaml
----
+
... Fix configuration errors and wait for the Operator to reconcile.
+
** *Insufficient disk space:*
+
... Check node disk usage:
+
[source,terminal]
----
$ oc debug node/<node_name> -- df -h /var
----
+
... Free up disk space or provision additional storage.
+
** *Image pull errors:*
+
... Verify image pull secrets exist:
+
[source,terminal]
----
$ oc get secrets -n openshift-gitops | grep pull-secret
----
+
... Check the image registry is accessible:
+
[source,terminal]
----
$ oc describe pod <pod_name> -n openshift-gitops | grep -A5 "Failed to pull image"
----

. Check resource quotas and limit ranges:
+
[source,terminal]
----
$ oc describe resourcequota -n openshift-gitops
$ oc describe limitrange -n openshift-gitops
----
+
Adjust quotas if the pod cannot start due to resource constraints.

. If the pod continues crashing, collect diagnostic information:
+
[source,terminal]
----
$ oc adm inspect namespace/openshift-gitops --dest-dir=gitops-diagnostics
----

.Verification

After applying fixes, verify the pod starts successfully and remains running:

[source,terminal]
----
$ oc get pods -n openshift-gitops -w
----

The pod should transition to `Running` state with `READY 1/1`.

[TIP]
====
Enable higher log verbosity temporarily to capture more diagnostic information:

[source,yaml]
----
spec:
  controller:
    logLevel: debug
----
====
