= Reserve OVS-DPDK CPUs with a performance profile

[role="_abstract"]
Create or update a `PerformanceProfile` custom resource (CR) that reserves CPUs for OVS-DPDK by setting `spec.cpu.ovsDpdk`. You can optionally add the load-balancing annotation in the same CR; see _Disable load balancing on OVS-DPDK CPUs_ for when that extra hardening is useful.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the OpenShift CLI (`oc`).
* You have identified the CPU topology and NUMA locality of the OVS-DPDK NICs on the target nodes.
* Workload partitioning is enabled at install time by setting `CPUPartitioningAllNodes`, or the `kubelet` CPU Manager `strict-cpu-reservation` policy option is configured on the target nodes. The performance profile populates the workload partitioning CPU sets.
* You understand that this feature is Technology Preview.

.Procedure

. Generate a base performance profile by using the Performance Profile Creator (PPC) tool with a must-gather from your cluster:

.. Collect a must-gather from the cluster:
+
[source,terminal]
----
$ oc adm must-gather
----

.. Generate the base profile by running the PPC tool:
+
[source,terminal,subs="attributes+"]
----
$ podman run --entrypoint performance-profile-creator \
  -v <path_to_must_gather>:/must-gather:z \
  registry.redhat.io/openshift4/ose-cluster-node-tuning-rhel9-operator:v{product-version} \
  --must-gather-dir-path /must-gather \
  --mcp-name=<mcp_name> \
  --reserved-cpu-count=<reserved_count> \
  --rt-kernel=true \
  --split-reserved-cpus-across-numa=false \
  --power-consumption-mode=ultra-low-latency \
  > my-performance-profile.yaml
----
+
Replace `<mcp_name>` with the name of the machine config pool for the target nodes. For {sno}, use `--mcp-name=master`.
+
For more information about PPC arguments, see "Running the Performance Profile Creator using Podman".

. Edit the generated profile to add `spec.cpu.ovsDpdk` and optionally add the load-balancing annotation. Move the CPUs you want to assign to OVS-DPDK from the `isolated` set to the new `ovsDpdk` field. Ensure that the `reserved`, `ovsDpdk`, and `isolated` sets do not overlap.
+
.Example performance profile with OVS-DPDK CPUs
[source,yaml]
----
apiVersion: performance.openshift.io/v2
kind: PerformanceProfile
metadata:
  name: ovs-dpdk-isolation
  annotations:
    performance.openshift.io/cpu-load-balancing-ovs-dpdk: "disable"
spec:
  cpu:
    reserved: "0-1"
    ovsDpdk: "2-3"
    isolated: "4-7"
  machineConfigPoolSelector:
    pools.operator.machineconfiguration.openshift.io/worker: ""
  nodeSelector:
    node-role.kubernetes.io/worker: ""
----
+
where:

* `performance.openshift.io/cpu-load-balancing-ovs-dpdk: "disable"` is optional. Set it only when you need stronger scheduler isolation for PMD threads. Omit the annotation for the base reservation. For why and when to use this annotation, see _Disable load balancing on OVS-DPDK CPUs_.
* `spec.cpu.reserved` lists CPUs for operating system and platform components.
* `spec.cpu.ovsDpdk` lists CPUs reserved for OVS-DPDK PMD threads. Do not reuse this set for unrelated DPDK applications. The PPC tool does not generate this field. You must add it manually.
* `spec.cpu.isolated` lists CPUs for `Guaranteed` application pods.
* `spec.machineConfigPoolSelector` matches the machine config pool for the target nodes.
* `spec.nodeSelector` matches the node role for the target nodes. On single-node {product-title}, use `node-role.kubernetes.io/master: ""` and set `machineConfigPoolSelector` to `pools.operator.machineconfiguration.openshift.io/master: ""`.

. Apply the performance profile:
+
[source,terminal]
----
$ oc apply -f my-performance-profile.yaml
----

. Wait for the Machine Config Operator to apply the configuration and for the target nodes to reboot. Confirm that the relevant machine config pool has finished updating:
+
[source,terminal]
----
$ oc get mcp
----
+
The pool that matches your profile selector must show `UPDATED=True` and `UPDATING=False`.

. Verify that the performance profile is available:
+
[source,terminal]
----
$ oc get performanceprofile ovs-dpdk-isolation -o yaml
----
+
Confirm that the `Available` condition is `True`. If the profile is `Degraded` with reason `OvsDpdkCPUsPrerequisiteNotMet`, enable workload partitioning or `strict-cpu-reservation` and reapply the profile.

.Verification

* Confirm that the `PerformanceProfile` status shows `Available=True`.
* Complete the checks in _Verify OVS-DPDK CPU isolation_ to confirm node-level configuration.
