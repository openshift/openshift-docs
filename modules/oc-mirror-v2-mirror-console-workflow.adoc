= OpenShift Mirror Console workflow

[role="_abstract"]
Plan your mirror operation in the OpenShift Mirror Console by reviewing the workflow from installation and registry authentication to configuration, mirroring, and verification.

The following workflow prepares mirrored content on disk for a disconnected environment. Publishing that content to a disconnected registry is a separate task.

[cols="1,3",options="header"]
|===
|Stage
|User task

|Install the console
|Start the OpenShift Mirror Console container and open the console in a browser.

|Configure registry access
|Add a pull secret and verify authentication for the registries that contain the images you need.

|Update catalog digests, if needed
|Sync Operator catalog digests when you need digests newer than those bundled in the console image.

|Prepare a configuration
|Create a configuration or load an existing `ImageSetConfiguration` file. Select the platform channels, Operator catalogs, and additional images that you need to mirror.

|Review and save
|Review the generated configuration on the *Preview* tab. Save the configuration in the console so that it is available on the Mirror Operations page.

|Run the mirror operation
|Select the saved configuration and a destination folder on the Mirror Operations page. Start the operation to copy the configured content to that folder.

|Verify the result
|Monitor the running operation on the Mirror Operations page. After the operation completes, confirm that it has a *Success* status on the History page.
|===

*Save Configuration* stores the configuration in the console. *Download YAML* saves a copy on your computer. Downloading a copy does not make it available for mirror operations.

After completing mirror operations, you can review operation history and manage cached data as needed. These maintenance tasks are separate from the initial mirroring workflow.
