= OpenShift Mirror Console workflow

[role="_abstract"]
Plan your mirror operation in the OpenShift Mirror Console by reviewing the workflow from installation and registry authentication to configuration, mirroring, and verification.

The following workflow prepares mirrored content on disk for a disconnected environment. Publishing that content to a disconnected registry is a separate task.

[cols="1,3",options="header"]
|===
|Stage
|Purpose

|Console installation
|The console runs in a container and provides a browser interface.

|Registry access
|A pull secret provides credentials for the registries that contain the required images. Authentication verification confirms registry access.

|Catalog digests
|Optional catalog synchronization retrieves digests newer than those bundled in the console image.

|Image selection
|A new or imported `ImageSetConfiguration` file identifies the content to mirror.

|Configuration review
|The *Preview* tab displays the generated configuration. Saved configurations are available for mirror operations.

|Mirroring
|A mirror operation copies the configured content to the selected destination folder.

|Result verification
|The History page displays a *Success* status when an operation completes successfully.
|===

*Save Configuration* stores the configuration in the console. *Download YAML* saves a copy on your computer. Downloading a copy does not make it available for mirror operations.

After completing mirror operations, you can review operation history and manage cached data as needed. These maintenance tasks are separate from the initial mirroring workflow.
