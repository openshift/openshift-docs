= Configure container image signature verification

[role="_abstract"]
Configure the Argo CD Image Updater to verify cosign signatures before updating container images in your applications.

.Prerequisites

* You have enabled the Argo CD Image Updater feature.

* You have a cosign ECDSA key pair.
+
If you do not have a key pair, generate one by running the following command:
+
[source,terminal]
----
$ cosign generate-key-pair
----
+
This command generates a `cosign.key` private key file and a `cosign.pub` public key file.

* You have signed the container image by its manifest digest.
+
[source,terminal]
----
$ cosign sign --key cosign.key <registry>/<repository>@<digest>
----
+
[IMPORTANT]
====
Always sign images by digest rather than by tag. The `cosign sign` command resolves a tag to its manifest digest internally. Signing by digest explicitly associates the signature with the intended image digest and prevents a later tag change from pointing to a different image.
====

.Procedure

. Create a Kubernetes Secret that contains the PEM-encoded cosign public key. Create the Secret in the same namespace as the ImageUpdater CR:
+
[source,terminal]
----
$ oc create secret generic myapp-cosign-pubkey \
    --from-file=cosign.pub=./cosign.pub \
    -n openshift-gitops
----
+
The resulting Secret has the following structure:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: myapp-cosign-pubkey
  namespace: openshift-gitops
data:
  cosign.pub: <base64-encoded PEM public key>
----

. Configure the `imagesVerification` field in your ImageUpdater CR.
+
The following example enables signature verification globally for all images in the CR:
+
[source,yaml]
----
apiVersion: argocd-image-updater.argoproj.io/v1alpha1
kind: ImageUpdater
metadata:
  name: my-image-updater
  namespace: openshift-gitops
spec:
  imagesVerification:
    enabled: true
    cosignKey:
      secretName: myapp-cosign-pubkey
      key: cosign.pub
  applicationRefs:
    - namePattern: "my-app-*"
      images:
        - alias: "frontend"
          imageName: "myorg/frontend:~2.0"
        - alias: "backend"
          imageName: "myorg/backend:~1.5"
----
+
The following fields configure signature verification:
+
`spec.imagesVerification.enabled`:: Enables (`true`) or disables (`false`) signature verification. The default is `true` when the `imagesVerification` block is present.
`spec.imagesVerification.cosignKey.secretName`:: Specifies the name of the Kubernetes Secret that contains the PEM-encoded cosign public key. The Secret must be in the same namespace as the ImageUpdater CR.
`spec.imagesVerification.cosignKey.key`:: Specifies the key in the Secret's `data` map that contains the PEM-encoded public key, such as `cosign.pub`.

. Optional: To disable verification for a specific image while keeping it enabled for other images, set `enabled: false` at the image level.
+
The following example disables verification for the `nginx-sidecar` image while retaining global verification for other images:
+
[source,yaml]
----
spec:
  imagesVerification:
    enabled: true
    cosignKey:
      secretName: myapp-cosign-pubkey
      key: cosign.pub
  applicationRefs:
    - namePattern: "my-app-*"
      images:
        - alias: "frontend"
          imageName: "myorg/frontend:~2.0"
        - alias: "nginx-sidecar"
          imageName: "nginx:~1.26"
          imagesVerification:
            enabled: false
----
+
In this example, the `frontend` image is verified against the configured public key. The `nginx-sidecar` image is updated without signature verification because its image-level setting overrides the global setting.

. Optional: When you use annotation-based image configuration (`useAnnotations: true`), configure `imagesVerification` at the `applicationRef` level. The global `spec.imagesVerification` field is not used for annotation-based application references.
+
The following example configures signature verification for an application reference that uses annotations:
+
[source,yaml]
----
spec:
  applicationRefs:
    - namePattern: "my-app-*"
      labelSelectors:
        matchLabels:
          image-updater: my-image-updater
      useAnnotations: true
      imagesVerification:
        enabled: true
        cosignKey:
          secretName: myapp-cosign-pubkey
          key: cosign.pub
----

.Verification

When an image fails signature verification, the controller skips that image and logs an error. Other images in the same ImageUpdater CR continue to be processed if they pass verification or have verification disabled. A verification failure for one image does not block reconciliation of the entire CR.
