= Configure replicas for external-secrets components

[role="_abstract"]
To run more than one instance of an `external-secrets` component, set the number of pod replicas for that component in the `ExternalSecretsConfig` custom resource (CR).

.Prerequisites

* You have access to the cluster with `cluster-admin` privileges.
* You have created the `ExternalSecretsConfig` CR.

.Procedure

. Edit the existing `externalsecretsconfig.yaml` file to add the `componentConfigs` field under the `spec.controllerConfig` field as follows:
+
[source,yaml]
----
apiVersion: operator.openshift.io/v1alpha1
kind: ExternalSecretsConfig
metadata:
  name: cluster
spec:
  controllerConfig:
    componentConfigs:
      - componentName: ExternalSecretsCoreController
        deploymentConfigs:
          replicas: 2
      - componentName: Webhook
        deploymentConfigs:
          replicas: 2
----
+
where:

`spec.controllerConfig.componentConfigs.componentName.deploymentConfigs.replicas`:: Specifies the desired number of pod replicas for the component deployment. The value must be at least 1. The maximum value is 10. If you do not specify a value, the default is 1.

. Apply the file by running the following command:
+
[source,terminal]
----
$ oc apply -f externalsecretsconfig.yaml
----

.Verification

. Verify that the deployment uses the `replicas` value by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.replicas}'
----
+
The output displays the `replicas` value you configured.

. Verify that the `ExternalSecretsCoreController` component uses leader election by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="external-secrets")].args}'
----
+
The output includes `--enable-leader-election=true`.

. Optional: Verify that a replica holds a leader election lease in the operand namespace by running the following command:
+
[source,terminal]
----
$ oc get lease -n external-secrets
----
+
The output lists a lease with a non-empty holder identity for the active leader.

. Optional: If the cluster runs the `CertController` component, verify that the component uses leader election by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets-cert-controller -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="cert-controller")].args}'
----
+
The output includes `--enable-leader-election=true`.
