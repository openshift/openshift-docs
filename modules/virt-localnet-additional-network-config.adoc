= Additional network configuration for localnet networks

[role="_abstract"]
After you connect a virtual machine (VM) to a localnet network, you can configure micro segmentation, MAC address management, and IP address management for the VM network.

Micro segmentation:: You can use the `MultiNetworkPolicy` API to create network policies that manage traffic for VMs attached to secondary networks. For example, you can create policies that allow or deny traffic based on specific ports, IP addresses and ranges, or labels. For more information, see "Configuring multi-network policy" in the Additional resources section.
+
The following example `MultiNetworkPolicy` manifests block all traffic to VMs on the localnet in a given namespace except for access to port 80 from one specific external IP address:
+
[source,yaml]
----
---
apiVersion: k8s.cni.cncf.io/v1beta1
kind: MultiNetworkPolicy
metadata:
  name: deny-by-default
  namespace: red
  annotations:
    k8s.v1.cni.cncf.io/policy-for: red/provider-network-100
spec:
  podSelector: {}
  policyTypes:
  - Ingress
---
apiVersion: k8s.cni.cncf.io/v1beta1
kind: MultiNetworkPolicy
metadata:
  name: allow-ingress-80
  namespace: red
  annotations:
    k8s.v1.cni.cncf.io/policy-for: red/provider-network-100
spec:
  podSelector:
    matchLabels:
      vm: my-virtual-machine
  policyTypes:
    - Ingress
  ingress:
  - from:
    - ipBlock:
        cidr: 203.0.113.50/32
    ports:
    - protocol: TCP
      port: 80
----

MAC address management:: By default, the KubeMacPool component allocates MAC addresses for VM network interfaces from a shared MAC address pool. This ensures that each network interface is assigned a unique MAC address. You can request a specific MAC address when creating the VM. For more information, see "Managing MAC address pools for network interfaces" in the Additional resources section.

IP address management:: {VirtProductName} does not support IP address management (IPAM) for VMs that use localnet networks. You can configure a static or dynamic IP address when you create a VM by using one of the following methods:
+
--
* *DHCP server*: Use your enterprise DHCP server running on the assigned VLANs.
* *Cloud-init*: Use the cloud-init API to set IP configuration through the `VirtualMachine` manifest, as in the following example:
+
[source,yaml]
----
kind: VirtualMachine
spec:
# ...
  template:
  # ...
    spec:
      volumes:
      - cloudInitNoCloud:
          networkData: |
            version: 2
            ethernets:
              eth0: <1>
                addresses:
                - 10.10.10.14/24 <2>
----
<1> The name of the network interface in the guest operating system.
<2> The static IP address and subnet mask to assign to the VM.
* *Custom solution*: You can set the IP address in the VM image or assign it by using Ansible.
--

Host IP address configuration:: You can assign an IP address to {product-title} nodes to access the secondary network by editing the `NodeNetworkConfigurationPolicy` manifest.
+
--
The following example shows a dynamic host IP configuration. This example assumes that the default gateway and DNS are configured through a different interface:

[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: network-config
spec:
  desiredState:
    interfaces:
    - name: br1
      type: ovs-bridge
      state: up
      ipv4:
        dhcp: true
        auto-dns: false
        auto-gateway: false
        enabled: true
      # ...
----

For a static IP address, you must use one `NodeNetworkConfigurationPolicy` with a node selector per node, as in the following example:

[source,yaml]
----
---
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: network-config-node1
spec:
  nodeSelector:
    kubernetes.io/hostname: node1
  desiredState:
    interfaces:
    - name: br1
      type: ovs-bridge
      state: up
      ipv4:
        dhcp: false
        address:
        - ip: 192.168.122.201
          prefix-length: 24
        enabled: true
      # ...
---
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: network-config-node2
spec:
  nodeSelector:
    kubernetes.io/hostname: node2
  desiredState:
    interfaces:
    - name: br1
      type: ovs-bridge
      state: up
      ipv4:
        dhcp: false
        address:
        - ip: 192.168.122.202
          prefix-length: 24
        enabled: true
      # ...
----
