= Troubleshoot collector and ClusterLogForwarder alerts

[role="_abstract"]
When a collector or `ClusterLogForwarder` alert fires, you can use diagnostic commands to identify the root cause and apply remediation steps. These alerts indicate issues with log collection, output error rates, or the `ClusterLogForwarder` resource status.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` cluster role.
* You have installed the {oc-first}.

.Procedure

. Identify the alert that fired and note the namespace and resource name from the alert labels.

. View the status of all `ClusterLogForwarder` resources:
+
[source,terminal]
----
$ oc get clusterlogforwarder -A
----

. Check the detailed status of the affected `ClusterLogForwarder` resource:
+
[source,terminal]
----
$ oc describe clusterlogforwarder <name> -n <namespace>
----
+
Review the `status.conditions` section for warnings or errors.

. For the `ClusterLogForwarderNotReady` alert, view the full status conditions:
+
[source,terminal]
----
$ oc get clusterlogforwarder <name> -n <namespace> -o yaml
----
+
Look for conditions with `status: "False"` to identify the specific validation error. Correct any invalid input, output, or pipeline configuration in the `ClusterLogForwarder` spec.

. For the `ClusterLogForwarderOutputErrorRate` alert, check the collector pod logs for error details:

.. List the collector pods in the affected namespace:
+
[source,terminal]
----
$ oc get pods -n <namespace> -l app.kubernetes.io/component=collector
----

.. View the logs for the collector pod identified in the alert:
+
[source,terminal]
----
$ oc logs <pod_name> -n <namespace>
----
+
Look for connection errors, authentication failures, or timeout messages for the affected output.

.. Verify that the output receiver is reachable from the cluster and that any credentials in the output secret are valid.

. For the `CollectorSourceDiscardedLogs` alert, check the input configuration in the `ClusterLogForwarder` spec:
+
[source,terminal]
----
$ oc get clusterlogforwarder <name> -n <namespace> -o jsonpath='{.spec.inputs}'
----
+
If log lines exceed the `maxMessageSize` limit, increase the value of `maxMessageSize` in the relevant input `tuning` configuration to prevent the collector from discarding log events.
