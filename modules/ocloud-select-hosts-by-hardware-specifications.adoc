= Select hosts by hardware specifications

[role="_abstract"]
You can define the base hardware selection criteria in a `ClusterTemplate` CR using the `resourceSelector` field in `hwMgmtDefaults` specification. 

The `resourceSelector` field supports both label selectors that match `BareMetalHost` CR labels and `hardwaredata/` selectors that match against the inspected `HardwareData` CR for physical characteristics such as CPU, memory, NICs, and storage devices. You can use either or both together. This base configuration applies to all clusters provisioned with this template unless overridden with `hwMgmtParameters` in the `ProvisioningRequest` CR.

.Prerequisites

* The O-Cloud Manager Operator is installed on the hub cluster.
* Bare-metal servers are onboarded and their `HardwareData` CRs are populated by Bare Metal Operator inspection.
* You have an existing `ClusterTemplate` CR or are creating a new one.
* If your template references `HardwareProfile` CRs, those CRs must exist in the O-Cloud Manager Operator namespace ,`oran-o2ims`, regardless of the namespace where the `ClusterTemplate` CR is stored.

.Procedure

. Define the `resourceSelector` in your `ClusterTemplate` CR's `hwMgmtDefaults.nodeGroupData[]` entry to include hardware data criteria. The following example selects hosts with at least 64 CPU threads, 128 GiB RAM, four 25 Gbps NICs, and two NVMe storage devices:
+
[source,yaml]
----
# ...
spec:
  templateDefaults:
    hwMgmtDefaults:
      nodeGroupData:
        - name: controller
          role: master
          resourceSelector:
            server-type: dell-xr8620t
            hardwaredata/cpu_model;substring;icase: "Xeon"
            hardwaredata/num_threads;gte: "64"
            hardwaredata/ramMebibytes;gte: "131072"
            hardwaredata/nics;speedGbps>=25;count>=4: "present"
            hardwaredata/storage;type==NVME;count>=2: "present"
# ...
----
+
where:
+
`server-type: dell-xr8620t`:: A label selector. Short keys without a domain prefix are automatically expanded to `resourceselector.clcm.openshift.io/server-type`. The label must exist on the `BareMetalHost` CR's `metadata.labels`. You can use fully qualified keys such as `resourceselector.clcm.openshift.io/server-colour` directly.
`hardwaredata/cpu_model;substring;icase: "Xeon"`:: A string field selector with qualifiers. The `hardwaredata/` prefix indicates matching against the `HardwareData` CR. String fields support the following qualifiers:
+
* _(no qualifier)_ - exact match
* `icase` - case-insensitive exact match
* `substring` - substring match
* `substring;icase` - case-insensitive substring match
+
Available string fields: `productname` (system product name), `manufacturer` (system manufacturer), `cpu_arch` (CPU architecture such as `x86_64` or `arm64`), and `cpu_model` (CPU model string).
`hardwaredata/num_threads;gte: "64"`:: An integer field selector with a comparison operator. Integer fields support the following operators specified as qualifiers:
+
* _(no qualifier)_ or `eq` - equal
* `neq` - not equal
* `gt` - greater than
* `gte` - greater than or equal
* `lt` - less than
* `lte` - less than or equal
+
Available integer fields: `num_threads` (CPU thread count) and `ramMebibytes` (RAM size in mebibytes). All values must be quoted strings.
`hardwaredata/nics;speedGbps>=25;count>=4: "present"`:: A NIC compound selector. NIC criteria use the `hardwaredata/nics` prefix followed by semicolon-separated sub-criteria. The value must always be `"present"`. Available NIC sub-criteria:
+
* `model` - NIC model string (operators: `==`, `!=`, `~` for contains, `!~` for does not contain)
* `speedGbps` - NIC speed in Gbps (operators: `==`, `!=`, `>`, `>=`, `<`, `\<=`)
* `count` - number of NICs matching the other sub-criteria (operators: `==`, `!=`, `>`, `>=`, `<`, `\<=`)
+
When `model` or `speedGbps` are specified, they filter the NIC set first. The `count` sub-criterion is then evaluated against the filtered subset. Append `icase` to the key for case-insensitive model matching, for example `hardwaredata/nics;model~0x8086;icase;count>=4`.
`hardwaredata/storage;type==NVME;count>=2: "present"`:: A storage compound selector. Storage criteria use the `hardwaredata/storage` prefix followed by semicolon-separated sub-criteria. The value must always be `"present"`. Available storage sub-criteria:
+
* `type` - storage type: `NVME`, `SSD`, or `HDD` (operators: `==`, `!=`, `~`, `!~`)
* `model` - device model string (operators: `==`, `!=`, `~`, `!~`)
* `vendor` - device vendor string (operators: `==`, `!=`, `~`, `!~`)
* `name` - device name or alternate name (operators: `==`, `!=`, `~`, `!~`)
* `sizeBytes` - device size in bytes (operators: `==`, `!=`, `>`, `>=`, `<`, `\<=`)
* `count` - number of devices matching the other sub-criteria (operators: `==`, `!=`, `>`, `>=`, `<`, `\<=`)
+
Filtering sub-criteria (`type`, `model`, `vendor`, `name`, `sizeBytes`) narrow the device set first. The `count` sub-criterion is then evaluated against the filtered subset.
+
[NOTE]
====
All criteria within a `resourceSelector` must match for a `BareMetalHost` CR to be selected (AND logic). Only hosts in the `Available` provisioning state are evaluated.
====

. Apply the `ClusterTemplate` CR to the hub cluster, or commit it to the GitOps repository for ArgoCD synchronization.

.Verification

* Verify that the `ClusterTemplate` passes validation by running the following command:
+
[source,terminal]
----
$ oc get clustertemplates.clcm.openshift.io -A
----
+
A `STATE` of `Completed` confirms that the template and its resource selector configuration are valid.
