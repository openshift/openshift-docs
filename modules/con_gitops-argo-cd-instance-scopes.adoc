= Argo CD instance scopes

[role="_abstract"]
Choose the appropriate instance scope for your Argo CD deployment based on security requirements and operational boundaries. Instance scope determines what cluster resources the Argo CD instance can deploy and manage.

*Namespace-scoped instances*

Namespace-scoped instances have permissions limited to specific namespaces. Use namespace-scoped instances when:

* Multiple teams share the same cluster and need isolated GitOps environments
* You want to restrict what resources developers can deploy
* You follow least-privilege security principles
* Each team manages only their own applications and namespaces

*Benefits:*

* Strong security boundaries between teams
* Prevents accidental or malicious changes to resources outside the team's scope
* Simplifies access control by mapping instance permissions to namespace permissions

*Limitations:*

* Cannot deploy cluster-scoped resources like CustomResourceDefinitions, ClusterRoles, or cluster-wide operators
* Each team needs a separate Argo CD instance, increasing management overhead
* Cross-namespace dependencies require careful coordination

For more information, see xref:../plan/plan-a-gitops-deployment.adoc#gitops-namespace-scoped-instance_plan-a-gitops-deployment[Namespace-scoped instance].

*Cluster-scoped instances*

Cluster-scoped instances have cluster-admin permissions and can deploy any Kubernetes resource. Use cluster-scoped instances when:

* Platform teams need to manage cluster infrastructure and operators
* Applications require cluster-scoped resources
* You manage a small number of clusters or have centralized operations
* You trust all users with access to the Argo CD instance

*Benefits:*

* Can deploy any resource type, including cluster-scoped resources
* Simplifies deployment of infrastructure components and operators
* Single instance can manage all applications across all namespaces

*Limitations:*

* Broader security impact if compromised
* Requires careful RBAC configuration to prevent unauthorized access
* Less isolation between teams and applications

For more information, see xref:../plan/plan-a-gitops-deployment.adoc#gitops-cluster-scoped-instance_plan-a-gitops-deployment[Cluster-scoped instance].

*Default cluster-scoped instance*

The {gitops-title} Operator automatically creates a default cluster-scoped Argo CD instance in the `openshift-gitops` namespace. This instance:

* Has cluster-admin permissions by default
* Is immediately available after Operator installation
* Provides a quick start for evaluating {gitops-title}
* Can be customized like any other Argo CD instance

Use the default instance for platform-level deployments or as a shared instance for small teams. For production multi-tenant environments, create additional namespace-scoped or cluster-scoped instances with appropriate permissions.

For more information, see xref:../plan/plan-a-gitops-deployment.adoc#gitops-default-cluster-scoped-instance_plan-a-gitops-deployment[Default cluster-scoped instance].

*Choosing instance scope*

The following table shows recommended instance scopes for common use cases:

[cols="1,2,2",options="header"]
|===
|Use case |Recommended scope |Rationale
|Development team managing applications |Namespace-scoped |Limits blast radius, enforces security boundaries
|Platform team managing cluster infrastructure |Cluster-scoped |Needs access to cluster-wide resources
|Multi-tenant platform |Multiple namespace-scoped |Provides isolation between tenants
|Small organization with trusted users |Cluster-scoped (default) |Simplifies operations, reduces management overhead
|Edge deployments with limited resources |Namespace-scoped |Minimizes resource usage per instance
|===
