= Requirements for connecting to external APIs

[role="_abstract"]
To grant access to external APIs that are not accessible directly through the public internet, you can set up a `Gateway` object and secure the traffic with {prodname} policies.

You must use Istio as the `Gateway` object provider and the cluster must reach the backend API over the network.

.Required capabilities
[cols="1,1,2",options="header"]
|===
| Provider | Resource | Function

| Istio-specific
| `ServiceEntry`
| Registers an external hostname in the service mesh so it becomes routable.

| Istio-specific
| `DestinationRule`
| Configures TLS origination to the external backend.

| Istio-specific
| `Hostname` backendRef
| Allows an `HTTPRoute` object to reference the `ServiceEntry` object as a backend.

| Extended Gateway API
| `HTTPRouteHostRewrite`
| The `URLRewrite` hostname filter is an Extended Gateway API feature. The gateway provider must support it.
|===

If you are using a different gateway provider, it must support these or equal mechanisms.

[IMPORTANT]
====
The `openshift-default` `GatewayClass` installs a lightweight Istio with the Cluster Ingress Operator (CIO), but restricts the API surface to standard Gateway API resources. Vendor-specific Istio resources are not supported. See "Configuring Gateway API" for details about what is available, and "Integrate OpenShift Gateway API with OpenShift Service Mesh" for adding full {ossm} support.
