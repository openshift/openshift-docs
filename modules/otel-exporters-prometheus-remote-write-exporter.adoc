= Prometheus Remote Write Exporter

[role="_abstract"]
The Prometheus Remote Write Exporter exports metrics to compatible back ends.

The following `OpenTelemetryCollector` custom resource configures the Prometheus Remote Write Exporter:

[source,yaml]
----
# ...
  config:
    exporters:
      prometheusremotewrite:
        endpoint: "https://my-prometheus:7900/api/v1/push"
        tls:
          ca_file: ca.pem
          cert_file: cert.pem
          key_file: key.pem
          insecure: false
          insecure_skip_verify: false
          reload_interval: 1h
          server_name_override: <name>
          min_version: "1.2"
          max_version: "1.3"
        target_info: true
        export_created_metric: true
        max_batch_size_bytes: 3000000
        timeout: 10m
        retry_on_failure:
          enabled: true
          initial_interval: 50ms
          max_interval: 30s
          max_elapsed_time: 10m
        remote_write_queue:
          enabled: true
          queue_size: 10000
          num_consumers: 5
    service:
      pipelines:
        metrics:
          exporters: [prometheusremotewrite]
# ...
----
where:

`endpoint`:: Endpoint for sending the metrics.
`tls`:: Client-side TLS configuration. Defines paths to TLS certificates.
`insecure`:: Disables TLS on the client connection when set to `true`. This setting is ignored if a CA file is also configured. The default is `false`.
`insecure_skip_verify`:: Skips verifying the certificate when set to `true`. The default is `false`.
`reload_interval`:: Specifies the time interval at which the certificate is reloaded. If the value is not set, the certificate is never reloaded. The `reload_interval` field accepts a string containing valid units of time such as `ns`, `us`, `ms`, `s`, `m`, `h`. Set this value to an interval shorter than your certificate lifetime if you use automated certificate rotation.
`server_name_override`:: Overrides the virtual hostname of authority, such as the authority header field in requests. That is, it overrides the server name in the TLS handshake. You can use this for testing or when the connection hostname differs from the server name in the certificate.
`min_version`:: Sets the minimum supported TLS protocol version. This parameter is optional. The default is `1.2`.
`max_version`:: Sets the maximum supported TLS protocol version. This parameter is optional. The default is `1.3`.
`target_info`:: When set to `true`, creates a `target_info` metric for each resource metric.
`export_created_metric`:: When set to `true`, exports a `_created` metric for the Summary, Histogram, and Monotonic Sum metric points.
`max_batch_size_bytes`:: Maximum size of the batch of samples that is sent to the remote write endpoint. Exceeding this value results in batch splitting. The default value is `3000000`, which is approximately 2.861 megabytes.
`timeout`:: Sets the maximum time that the exporter spends on a single export request, including all retries. The default is `5s`. When this time elapses, the exporter drops the request even if `retry_on_failure` has time remaining. Set this value to at least the length of the back-end outage that you want to tolerate, and to at least `retry_on_failure.max_elapsed_time`.
`retry_on_failure`:: Configures retries with exponential backoff for failed export requests. The settings `initial_interval`, `max_interval`, and `max_elapsed_time` control the backoff timing. Retries stop when either `max_elapsed_time` or `timeout` is reached, whichever is shorter, and the request is dropped. The default `initial_interval` is `50ms`, the default `max_interval` is `30s`, and the default `max_elapsed_time` is `5m`. Enabled by default.
`remote_write_queue`:: Configures the in-memory queue that buffers requests while the exporter sends them to the remote write endpoint. The settings `enabled`, `queue_size`, and `num_consumers` control whether the queue is used, how many requests it can hold, and how many consumers send requests concurrently. When the queue is full, new data is dropped. The queue is not persistent, so its contents are lost if the Collector restarts. Enabled by default with `queue_size: 10000` and `num_consumers: 5`.

[WARNING]
====
* This exporter drops non-cumulative monotonic, histogram, and summary OTLP metrics.

* You must enable the `--web.enable-remote-write-receiver` feature flag on the remote Prometheus instance. Without it, pushing the metrics to the instance using this exporter fails.

* With the default settings, the exporter retries a failed request for only 5 seconds, because the default `timeout` is `5s`. If the remote write endpoint is unavailable for longer, the exporter logs `Exporting failed. Dropping data.` and the metrics collected during the outage are permanently lost. To tolerate longer outages, increase both `timeout` and `retry_on_failure.max_elapsed_time`.

* This exporter does not support the generic `sending_queue` setting. Use `remote_write_queue` instead. Configuring `sending_queue` causes the Collector to fail to start.
====
