[id="configuring-tuning-environment-variables_{context}"]
= Environment variables for troubleshooting and performance tuning

[role="_abstract"]
{product-title-short} components expose several environment variables that you
can use to troubleshoot issues and tune performance in large or heavily loaded
environments. Use these variables only when directed by a support case or when
you understand the impact of the change, because incorrect values can degrade
performance or stability. The variables are grouped by the component on which
you set them: Central services (Central and Central DB), Scanner services
(Scanner, Scanner DB, and Scanner V4), and secured cluster services (Admission
controller, Collector, Sensor, and the config controller).

[NOTE]
====
Default values and availability can change between {product-title-short}
releases. Confirm the default and the exact behavior for your version before you
change a variable in production.
====

[id="setting-environment-variables_{context}"]
== Setting environment variables

You can set these variables in one of the following ways, depending on how you
installed {product-title-short}:

* *Operator installations*: Add the variable to the `customize.envVars` field of
the relevant custom resource (CR), for example the `Central` CR for Central and
Central DB, or the `SecuredCluster` CR for Sensor, Collector, and the Admission
controller.
+
[source,yaml]
----
apiVersion: platform.stackrox.io/v1alpha1
kind: Central
metadata:
  name: stackrox-central-services
  namespace: stackrox
spec:
  customize:
    envVars:
      - name: ROX_POSTGRES_MIGRATION_STATEMENT_TIMEOUT
        value: "4h"
----

* *Helm or manifest installations*: Set the variable directly on the deployment,
for example:
+
[source,terminal]
----
$ oc -n stackrox set env deploy/central ROX_POSTGRES_MIGRATION_STATEMENT_TIMEOUT=4h
----

After you change a variable, the affected pod restarts to apply the new value.

[id="central-troubleshooting-tuning-environment-variables_{context}"]
== Central environment variables

Set these variables on the `central` deployment. They control request handling,
report generation, reprocessing, registry access, and memory behavior for the
Central pod.

[options="header", cols="2m,1,3"]
|===
|Environment variable |Default |Description

|ROX_MEMLIMIT
|Container memory limit
|Soft memory limit, in bytes, for the Go runtime. Central sets `GOMEMLIMIT` to approximately 95% of this value. This is the primary knob for reducing out-of-memory (OOM) kills. If `GOMEMLIMIT` is set directly, it takes precedence.

|ROX_CENTRAL_RATE_LIMIT_PER_SECOND
|0 (no limit)
|Maximum number of API requests per second that Central accepts from all sources combined. Set a limit to protect an overloaded Central from request storms.

|ROX_CENTRAL_RATE_LIMIT_THROTTLE_DURATION
|10s
|Maximum time a request waits when the rate limit is reached. A value of less than one second rejects excess requests immediately.

|ROX_CENTRAL_MAX_INIT_SYNC_SENSORS
|0 (no limit)
|Maximum number of sensors that can perform their initial synchronization with Central in parallel. Cap this value to reduce Central load and memory spikes during reconnection storms in multi-cluster deployments.

|ROX_GRPC_MAX_MESSAGE_SIZE
|24 MB
|Maximum gRPC message size accepted by Central. Increase this value if large secured clusters send payloads that exceed the default.

|ROX_REPORT_EXECUTION_MAX_CONCURRENCY
|5
|Maximum number of vulnerability and compliance reports that Central runs concurrently. Lower this value to reduce Central load during report generation.

|ROX_REPORT_MAX_ROWS
|1000000
|Maximum number of rows in a generated report. Increase this value if reports are truncated; this also increases memory use during report generation.

|ROX_ORPHANED_CVES_RETENTION_DURATION_DAYS
|2
|Number of days that orphaned CVEs are retained before pruning.

|ROX_REPROCESSING_INTERVAL
|4h
|Interval at which Central reprocesses deployment and image risk. Increasing the interval reduces load; decreasing it makes risk data more current.

|ROX_REGISTRY_CLIENT_TIMEOUT
|10s
|Overall HTTP client timeout for registry calls during scanning. This value also acts as the connection timeout for registries accessed through a proxy.

|ROX_REGISTRY_TLS_CHECK_CACHE_TTL
|15m
|Time-to-live for cached image-registry TLS check results. Caching these results speeds up Central event processing. This variable replaces the former `ROX_SENSOR_REGISTRY_TLS_CHECK_CACHE_TTL` variable and can be set on Central, Sensor, or both.

|ROX_ENABLE_CENTRAL_DIAGNOSTICS
|true
|Enables the Central diagnostic and debug-bundle endpoints that are used to collect support data. Disable only if you must restrict these endpoints.
|===

[id="central-db-troubleshooting-tuning-environment-variables_{context}"]
== Central DB environment variables

Set these variables on the `central` deployment; they are applied by the
application to database operations. They are separate from PostgreSQL server
settings such as `statement_timeout`, `shared_buffers`, and `max_connections`,
which are configured in the `central-db` configuration (`postgresql.conf`), not
through environment variables.

[options="header", cols="2m,1,3"]
|===
|Environment variable |Default |Description

|ROX_POSTGRES_MIGRATION_STATEMENT_TIMEOUT
|2h
|Statement timeout applied to database statements that run during a schema migration or upgrade. Increase this value when upgrades of large Central databases fail with a `context deadline exceeded` error during migration.

|ROX_POSTGRES_DEFAULT_TIMEOUT
|60s
|Default per-statement timeout for normal PostgreSQL queries issued by Central. Increase this value if legitimate queries time out on very large databases.

|ROX_POSTGRES_DEFAULT_CURSOR_TIMEOUT
|10m
|Timeout for cursor-based statements that stream large result sets.

|ROX_POSTGRES_DEFAULT_PRUNING_TIMEOUT
|3m
|Statement timeout for pruning operations. Increase this value if pruning queries time out on large tables.

|ROX_PRUNE_INTERVAL
|1h
|Frequency at which the pruner runs to remove data according to retention settings.

|ROX_PRUNE_ORPHANED_WINDOW
|30m
|Age after which records that arrive asynchronously, such as process indicators, are treated as orphaned and become eligible for pruning. Tune this value if you observe pruner performance issues.

|ROX_POSTGRES_NETWORK_FLOW_DELETE_TIMEOUT
|3m
|Statement timeout for deleting network-flow records during flow pruning.

|ROX_POSTGRES_NETWORK_FLOW_QUERY_TIMEOUT
|3m
|Statement timeout for querying network-flow records.

|ROX_POSTGRES_QUERY_RETRY_TIMEOUT
|5m
|Overall timeout for retrying failed PostgreSQL queries.

|ROX_SLOW_QUERY_THRESHOLD
|30s
|Threshold above which queries are logged as slow queries.
|===

[id="scanner-troubleshooting-tuning-environment-variables_{context}"]
== Scanner and Scanner DB environment variables

The following variables govern image scanning and vulnerability-definition
updates. Except where noted, set them on the `central` deployment, because
Central dispatches scans and retrieves vulnerability definitions.

[options="header", cols="2m,1,3"]
|===
|Environment variable |Default |Description

|ROX_SCAN_TIMEOUT
|10m
|Timeout for a single image scan. Increase this value if scans of large images time out.

|ROX_MAX_PARALLEL_IMAGE_SCAN_INTERNAL
|30
|Maximum number of image scans that run in parallel. Tune this value to balance scan throughput against Central and Scanner load.

|ROX_MAX_PARALLEL_AD_HOC_SCAN_INTERNAL
|5
|Maximum number of parallel ad hoc (delegated) scans. This value is subtracted from `ROX_MAX_PARALLEL_IMAGE_SCAN_INTERNAL`.

|ROX_SCANNER_VULN_UPDATE_INTERVAL
|5m
|Frequency at which Central queries the Scanner V2 vulnerability endpoint for definition updates.

|ROX_OFFLINE_MODE
|false
|Prevents {product-title-short}, including the scanners, from reaching the internet and forces the use of offline vulnerability definitions. Set this variable in disconnected environments.

|ROX_SCAN_DB_DL_BASE_URL
|`https://install.stackrox.io/scanner`
|Base URL from which offline Scanner definitions are downloaded. Change this value to point to an internal mirror.

|ROX_SCANNER_GRPC_ENDPOINT
|`scanner.stackrox.svc:8443`
|gRPC endpoint that Sensor uses to reach the local Scanner (slim) in a secured cluster.
|===

[id="scanner-v4-troubleshooting-tuning-environment-variables_{context}"]
== Scanner V4 environment variables

Variables with the `ROX_` prefix are set on the client side (Central or Sensor).
Variables with the `SCANNER_V4_` prefix are read inside the Scanner V4 Indexer,
Matcher, and DB pods and are derived from the Scanner V4 configuration; set them
on the corresponding Scanner V4 deployment.

[options="header", cols="2m,1,3"]
|===
|Environment variable |Default |Description

|ROX_SCANNER_V4_INDEXER_ENDPOINT
|`scanner-v4-indexer.stackrox.svc:8443`
|Endpoint used to reach the Scanner V4 Indexer in the cluster.

|ROX_SCANNER_V4_GRPC_MAX_RESPONSE_SIZE
|24 MB
|Maximum gRPC response size that a Scanner V4 client accepts. Pair this value with the server-side `ROX_GRPC_MAX_MESSAGE_SIZE`.

|ROX_SCANNER_V4_MANIFEST_GC_INTERVAL
|4h
|Interval between manifest garbage-collection runs in the Indexer.

|ROX_SCANNER_V4_MANIFEST_GC_THROTTLE
|100
|Number of manifests garbage-collected per non-full run in the Indexer.

|SCANNER_V4_INDEXER_GET_LAYER_TIMEOUT
|1m
|Timeout for GET requests that download image layers during indexing. Increase this value if layer downloads time out on slow registries.

|SCANNER_V4_MATCHER_VULNERABILITIES_URL
|Version-specific bundle URL
|Source URL for the vulnerability bundle that the Matcher loads. Change this value to point to an internal mirror in disconnected environments.

|SCANNER_V4_MATCHER_INDEXER_ADDR
|Unset (use local Indexer)
|Forces the Matcher to fetch index reports from a remote Indexer at the specified `host:port`.

|SCANNER_V4_MATCHER_READINESS
|database
|Readiness strategy for the Matcher: `database` reports ready when the database connection succeeds; `vulnerability` reports ready only after vulnerabilities are loaded at least once.

|SCANNER_V4_MATCHER_VULN_BUNDLE_ALLOWLIST
|Empty (import all)
|Restricts which vulnerability bundles are imported per cycle, for example `alpine,nvd`. Restricting bundles speeds up updates, but excluded bundles are not used for detection.

|SCANNER_V4_INDEXER_DATABASE_CONN_STRING
|`host=/var/run/postgresql`
|PostgreSQL connection string that the Indexer uses to reach the Scanner V4 DB.

|SCANNER_V4_MATCHER_DATABASE_CONN_STRING
|`host=/var/run/postgresql`
|PostgreSQL connection string that the Matcher uses to reach the Scanner V4 DB.

|STACKROX_SCANNER_V4_UPDATER_INTERVAL
|62ms (about 16 requests per second)
|Rate-limit interval for HTTP requests made by the offline vulnerability-bundle updater job. Values below the default are ignored.
|===

[id="admission-controller-troubleshooting-tuning-environment-variables_{context}"]
== Admission controller environment variables

Set these variables on the `admission-control` deployment.

[NOTE]
====
The admission controller request timeout, fail-open behavior, and bypass
settings are not environment variables. Configure them in the admission
controller settings of the `SecuredCluster` CR or in the cluster configuration
in the {product-title-short} portal.
====

[options="header", cols="2m,1,3"]
|===
|Environment variable |Default |Description

|ROX_ADMISSION_CONTROL_IMAGE_CACHE_MAX_SIZE
|200 (MB)
|Maximum size of the in-process image cache used for policy evaluation. When enforcement is enabled, the Operator sets this value to 500. Increase this value in environments with many distinct images.

|ROX_ADMISSION_CONTROL_IMAGE_CACHE_TTL
|4h
|How long enriched image entries remain valid before they are evicted and re-fetched. This value is aligned with the Central reprocessing interval.

|ROX_ADMISSION_CONTROL_IMAGE_NAME_CACHE_ENABLED
|true
|Caches the mapping from image name to cache key so that mutable tags reuse the scan cache without re-fetching. Disable this variable when image tags are frequently repointed.
|===

[id="collector-troubleshooting-tuning-environment-variables_{context}"]
== Collector environment variables

Set these variables on the `collector` daemon set.

[NOTE]
====
Collector runtime configuration and namespace-collection filtering are not
environment variables. Runtime configuration is delivered through the
`collector-config` config map, and namespace filtering is configured through the
Helm chart or the `SecuredCluster` CR.
====

[options="header", cols="2m,1,3"]
|===
|Environment variable |Default |Description

|COLLECTION_METHOD
|CORE_BPF
|Runtime collection method used by Collector. The legacy value `EBPF` is treated as `CORE_BPF`.

|ROX_MEMLIMIT
|Container memory limit
|Sets the Go soft memory limit to approximately 95% of the container memory limit. This is the primary memory-tuning knob for Collector.

|ROX_PROCESSES_LISTENING_ON_PORT
|true
|Enables collection of processes listening on ports (PLOP). This feature can significantly increase data volume; disable it if Collector or Central load is too high.

|ROX_CALL_NODE_INVENTORY_ENABLED
|true on {ocp} 4 and later, otherwise false
|Enables the node-inventory scanning container that supports node scanning.

|ROX_METRICS_PORT
|`:9091` or `disabled`
|Enables or disables the Prometheus metrics endpoint. This variable is controlled by the monitoring exposure setting.
|===

[id="sensor-troubleshooting-tuning-environment-variables_{context}"]
== Sensor environment variables

Set these variables on the `sensor` deployment. They control event processing,
deduplication, network-flow handling, process filtering, and the connection to
Central.

[options="header", cols="2m,1,3"]
|===
|Environment variable |Default |Description

|ROX_CENTRAL_ENDPOINT
|`central.stackrox.svc:443`
|Host and port that secured cluster components use to reach Central.

|ROX_EVENT_PIPELINE_QUEUE_SIZE
|1000
|Size of the Sensor event-processing pipeline queue. Increase this value to absorb bursts of events, at the cost of memory.

|ROX_MAX_DEDUPER_ENTRIES_PER_MESSAGE
|200000
|Maximum number of deduper entries sent per message during synchronization with Central.

|ROX_DEDUPER_STATE_TIMEOUT
|30s
|Timeout for synchronizing deduper state with Central on reconnection.

|ROX_MAX_EVENT_HASH_SIZE
|1000000
|Maximum number of event hashes retained per cluster for deduplication. Higher values use more memory.

|ROX_NETFLOW_MAX_UPDATE_SIZE
|150000
|Maximum number of network-flow updates per message sent to Central.

|ROX_NETFLOW_MAX_CACHE_SIZE
|800000
|Maximum number of entries in the Sensor network-flow cache.

|ROX_NETFLOW_CACHE_LIMITING
|false
|Enables enforcement of the network-flow cache size limit.

|ROX_NETFLOW_CLOSED_CONN_REMEMBER_DURATION
|6m
|How long closed connections are remembered before they are purged from the cache.

|ROX_SENSOR_NETFLOW_OFFLINE_BUFFER_SIZE
|100
|Number of network-flow batches buffered while Sensor is disconnected from Central.

|ROX_NETWORK_BASELINE_OBSERVATION_PERIOD
|1h
|Observation window used to build network baselines.

|ROX_SENSOR_CONNECTION_RETRY_INITIAL_INTERVAL
|10s
|Initial backoff interval for Sensor-to-Central reconnection attempts.

|ROX_SENSOR_CONNECTION_RETRY_MAX_INTERVAL
|5m
|Maximum backoff interval for Sensor-to-Central reconnection attempts.

|ROX_PROCESS_FILTER_MODE
|Unset
|Selects a preset level of process-filtering aggressiveness. When set, it overrides the individual fan-out and path-match settings.

|ROX_SENSOR_PROCESS_INDICATOR_BUFFER_SIZE
|50000
|Buffer size for process indicators before they are flushed.

|ROX_SENSOR_BUFFER_SCALE_CEILING
|3
|Maximum multiplier applied to Sensor detector buffer sizes under load.

|ROX_CONTAINER_ID_RESOLUTION_GRACE_PERIOD
|2m
|Grace period allowed to resolve container IDs before related events are dropped.

|ROX_K8S_CLIENT_CONTENT_TYPE
|Client default
|Wire format used by the Kubernetes client for watches, for example protobuf or JSON. This value affects API server load.

|ROX_OFFLINE_MODE
|false
|Runs the secured cluster in offline mode, preventing external fetches.
|===

[id="config-controller-troubleshooting-tuning-environment-variables_{context}"]
== Config controller and security policy environment variables

Set these variables on the config controller.

[options="header", cols="2m,1,3"]
|===
|Environment variable |Default |Description

|ROX_CONFIG_CONTROLLER_RECONCILE_INTERVAL
|30m
|Interval at which the config controller re-checks that the desired state in Central matches the `SecurityPolicy` custom resources when you use policy as code.

|ROX_DECLARATIVE_CONFIG_RECONCILE_INTERVAL
|20s
|Interval at which Central reconciles declarative configuration.
|===
