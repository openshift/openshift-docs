= Scenario 2: Vector + Loki

*Choose this scenario if:*

* You need fast local queries for troubleshooting recent issues
* 30-day log retention is sufficient for your operational needs
* You have or can provision S3-compatible object storage
* You want to use Grafana or LogQL for log analysis
* You may also forward logs externally for long-term retention

*What you need to plan:*

* Object storage backend (Amazon S3, Google Cloud Storage, Azure Blob, OpenShift Data Foundation, or S3-compatible)
* Object storage capacity (log volume determines storage needs)
* LokiStack deployment size (1x.demo, 1x.pico, 1x.extra-small, 1x.small, or 1x.medium)
* Cluster resources (CPU, memory, persistent volumes for Loki components)
* IAM roles or service accounts for object storage access
* Log retention period (up to 30 days)
* External forwarding destinations (if also forwarding logs)

*What you do NOT need:*

* Console UI configuration (query using Grafana or Loki CLI)
* Multi-tenant monitoring setup
* Signal correlation configuration

*Resource requirements:*

* *Vector*: Same as Scenario 1 (~100m CPU, 128-256 MiB memory per node)
* *Loki*: Depends on deployment size:
** *1x.extra-small*: 5 vCPUs, 7.5 GiB memory, 150 GiB PV storage
** *1x.small*: 11 vCPUs, 18 GiB memory, 300 GiB PV storage
** *1x.medium*: 38 vCPUs, 72 GiB memory, 450 GiB PV storage
* *Object storage*: Cannot be predicted before installation; start with 1 TB and monitor actual usage

*Estimated installation time:* 1-2 hours (includes object storage setup)

*Go to these planning topics:*

* xref:../plan/plan-your-logging-installation.adoc#plan-your-logging-installation[Plan your logging installation]
* xref:../plan/choose-lokistack-storage-backend.adoc#choose-lokistack-storage-backend[Choose a LokiStack storage backend]
* xref:../plan/size-your-lokistack-deployment.adoc#size-your-lokistack-deployment[Size your LokiStack deployment]

[NOTE]
====
Both storage backend selection and LokiStack sizing are required for Scenario 2.
====

*Skip these planning topics:*

* Console UI plugin configuration (not using COO)
* Multi-tenant monitoring setup (not using COO)
