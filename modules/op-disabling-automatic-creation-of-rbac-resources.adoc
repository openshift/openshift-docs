= Disabling automatic creation of RBAC resources

Setting `createRbacResource` to `"false"` in the `TektonConfig` custom resource disables automatic RBAC reconciliation by the {pipelines-title} Operator.

[IMPORTANT]
====
Disabling automatic RBAC resource creation makes the cluster administrator responsible for creating the workload service account and all required RBAC and Security Context Constraints (SCC) bindings.
====

== Administrator responsibilities and SCC configuration

When automatic RBAC creation is disabled, the Operator does not create default workload service accounts or RBAC and SCC bindings. Cluster administrators must manually perform the following tasks:

* Create the workload service account in the target namespace.
* Grant required RBAC permissions to the service account.
* Bind an SCC to the intended workload service account that permits the UID behavior and capabilities requested by the Tasks.

== Workload admission failures and SCC requirements

Without Operator-managed service accounts and SCC/RBAC bindings, pods can fail admission when a Task requests a UID or capability not permitted by the SCC available to its service account.

For example, Buildah or S2I-style Tasks can require specific capabilities such as `SETFCAP` or specific UID behaviors.

To resolve or prevent admission failures:

1. Determine the SCC requirements directly from the Task pod security context.
2. Select or create an SCC that permits the required UIDs and capabilities.
3. Bind only the minimum required SCC to the intended workload service account. Do not grant broad cluster-wide SCCs or blanket privileges such as `anyuid` or `privileged`.

[NOTE]
====
The `createRbacResource` setting operates independently from `createCABundleConfigMaps`.
====
