= Disabling automatic creation of RBAC resources

Setting `createRbacResource` to `"false"` in the `TektonConfig` custom resource disables automatic RBAC reconciliation by the {pipelines-title} Operator.

[WARNING]
====
Before setting `createRbacResource` to `"false"`, prepare replacement RBAC permissions in your workload namespaces. When this parameter is set to `"false"`, the Operator deletes the existing RBAC installer set rather than pausing reconciliation.
====

.Prerequisites

* You have cluster administrator permissions.
* You have created the required workload service account in the workload namespace.
* You have granted the necessary RBAC permissions and bound an appropriate Security Context Constraint (SCC) to the workload service account.

.Procedure

1. Edit the `TektonConfig` custom resource to set `createRbacResource` to `"false"`:
+
[source,yaml]
----
apiVersion: operator.tekton.dev/v1alpha1
kind: TektonConfig
metadata:
  name: config
spec:
  params:
    - name: createRbacResource
      value: "false"
    - name: createCABundleConfigMaps
      value: "true"
----

2. In your pipeline runs or task runs, explicitly specify the workload service account using `TaskRun.spec.serviceAccountName` or `PipelineRun.spec.taskRunTemplate.serviceAccountName` (or a per-task override).
+
[NOTE]
====
If a service account is not explicitly specified, runs default to the `pipeline` service account and fail admission because namespace SCC annotations and automatic RBAC creation are disabled.
====

[NOTE]
====
Although `createRbacResource` and `createCABundleConfigMaps` are independently configurable parameters, omitting `createCABundleConfigMaps` when `createRbacResource` is set to `"false"` causes the Operator to default `createCABundleConfigMaps` to `"false"`. To maintain automatic CA bundle ConfigMap provisioning, explicitly set `createCABundleConfigMaps` to `"true"`.
====
