= Namespace access

[role="_abstract"]

By default, {KialiServer} can read every namespace on the cluster. Limit that access with discovery selectors when the console should see only part of the mesh. {KialiServer} does not reuse the discovery selectors configured on {istio}. If you set selectors on the mesh, set the same selectors here.

A namespace is accessible when {KialiServer} can read it. A namespace is visible when the signed-in user is also allowed to see it. Per-user visibility is described in "Namespace access for each user".

What a user sees is the overlap of two lists: the namespaces {KialiServer} can read, and the namespaces that the user's {ocp-product-title} RBAC allows.

Set `spec.deployment.cluster_wide_access` to `false` and list the namespaces with `spec.deployment.discovery_selectors.default`. Selectors follow the same match-label and match-expression rules as other {ocp-product-title} label selectors. Conditions inside one selector are combined with a logical AND. Separate selectors in the list are combined with a logical OR.

The following example grants {KialiServer} access to every namespace that has the `my-mesh` label:

[source,yaml]
----
spec:
  deployment:
    cluster_wide_access: false
    discovery_selectors:
      default:
      - matchExpressions:
        - key: my-mesh
          operator: Exists
----

{KialiProduct} creates a `Role` for each matching namespace and binds it to the Kiali service account. The server can always read the namespace it is installed in, even when that namespace does not match a selector. If `cluster_wide_access` is `false` and you define no selectors, the server can read only its own namespace.

If `discovery_selectors.default` is unset, `cluster_wide_access` must stay `true`.

For a remote cluster whose namespaces use different labels, add an entry under `spec.deployment.discovery_selectors.overrides`. The entry name is the remote cluster name. When an override exists, the `default` selectors are not used for that cluster.
