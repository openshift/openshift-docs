= Update policy configuration parameters

[role="_abstract"]
You can update Day-2 configuration values on a provisioned cluster by modifying the `policyTemplateParameters` field in the `ProvisioningRequest` custom resource (CR). The O-Cloud Manager propagates the updated values to the cluster policy `ConfigMap` CR, and {rh-rhacm-first} policies re-apply the configuration on the spoke cluster.

[NOTE]
====
Only policy configuration values exposed in the `spec.templateParameters.policyTemplateParameters` field of the associated `ClusterTemplate` CR can be updated through the `ProvisioningRequest` CR.
====

.Prerequisites

* The cluster is fully provisioned with `provisioningPhase: fulfilled` on the `ProvisioningRequest` CR.
* The parameters you want to update are defined in `spec.templateParameters.policyTemplateParameters` field of the associated `ClusterTemplate` CR.

.Procedure

. Edit the `ProvisioningRequest` CR to update the `spec.templateParameters.policyTemplateParameters` field by running the following command:
+
[source,terminal]
----
$ oc edit provisioningrequests.clcm.openshift.io <uuid>
----
+
where:
+
--
`<uuid>`:: Specifies the UUID of the `ProvisioningRequest` CR for the target cluster.
--

. Update the configuration parameters to the desired values:
+
[source,yaml]
----
# ...
spec:
  templateParameters:
    policyTemplateParameters:
      sriov-network-vlan-1: "222"
      sriov-network-pfNames-1: '["ens2f0"]'
# ...
----
+
* `spec.templateParameters.policyTemplateParameters` contains the policy configuration values to update. The O-Cloud Manager writes these values to the cluster-specific `<cluster-name>-pg` ConfigMap resource in the `ztp-<clustertemplate-namespace>` namespace.
* Values specified here take precedence over the defaults defined in the policy `ConfigMap` CR referenced by the `ClusterTemplate` CR.

. Apply the updated `ProvisioningRequest` CR to the hub cluster, or commit it to the GitOps repository for ArgoCD synchronization.
+
The O-Cloud Manager updates the `<cluster-name>-pg` `ConfigMap` CR with the new values. {rhacm} policies referencing these values report a `NonCompliant` status and are re-enforced on the spoke cluster.

.Verification

* Verify that all policies return to `Compliant` status by checking the `ConfigurationApplied` condition by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -o jsonpath='{.status.conditions[?(@.type=="ConfigurationApplied")]}'
----
+
.Example output
[source,terminal]
----
{"lastTransitionTime":"2025-10-07T22:15:32Z","message":"The configuration is up to date","reason":"Completed","status":"True","type":"ConfigurationApplied"}
----
+
A `reason: Completed` with `status: "True"` indicates that all enforce policies are `Compliant` and the configuration change has been applied.
