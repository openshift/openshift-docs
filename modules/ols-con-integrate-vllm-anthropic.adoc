= Integrate {ols-long} with vLLM by using the Anthropic provider

[role="_abstract"]
As an administrator, you can integrate a self-hosted vLLM server as a large language model (LLM) provider for {ols-long} by using the Anthropic provider type and the Anthropic-compatible `/v1/messages` endpoint. Use this pathway for agentic and tool-calling workloads to help ensure that tool calls and structured outputs work reliably. Create a credentials secret that contains your authentication token, configure the `OLSConfig` custom resource (CR) to use the Anthropic provider, and verify the deployment.

// TODO(OLS-4284): SME to confirm the exact OLSConfig provider `type` string for the Anthropic /v1/messages pathway. Existing shipped provider types are openai, rhelai_vllm, rhoai_vllm, azure_openai, watsonx, bedrock, google_vertex, and google_vertex_anthropic. This draft uses `anthropic` as a placeholder.

vLLM (version 0.24 and later, as shipped with {rhelai}) natively supports the Anthropic-compatible `/v1/messages` endpoint. Selecting the Anthropic provider lets {ols-long} use its own two-pass mechanism, which preserves tool calls instead of suppressing them. This two-pass behavior is implemented in {ols-long} rather than in the vLLM endpoint, so using the `/v1/messages` endpoint on its own does not resolve tool call suppression. This behavior improves reliability for agentic workflows, such as integrations that use the Gemma series of models.
