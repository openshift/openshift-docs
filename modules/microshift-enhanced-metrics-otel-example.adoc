= Example: Collecting enhanced metrics with {microshift-short} Observability

[role="_abstract"]
When you install both enhanced metrics RPM packages and the `microshift-observability` RPM, the OpenTelemetry Collector automatically scrapes the enabled exporter endpoints and forwards the metrics to your configured back end.

.Prerequisites
 
* You installed and configured {microshift-short} Observability.
* You installed one or more optional metrics RPM packages and restarted {microshift-short} to deploy the exporters that your monitoring workflow requires.

.Procedure

. Confirm that the OpenTelemetry Collector service is running by entering the following command:
+
[source,terminal]
----
$ sudo systemctl status microshift-observability
----

. Inspect the collector logs to verify that metrics are being scraped by entering the following command:
+
[source,terminal]
----
$ sudo journalctl -u microshift-observability
----
+
When kube-state-metrics is enabled, the logs can include successful scrapes of the `kube-state-metrics` Service endpoints. When node-exporter is enabled, the logs can include successful scrapes of the local node-exporter endpoint.

. Verify that metrics are forwarded to your configured OpenTelemetry Protocol (OTLP) endpoint by checking the back end that receives data from the collector.
