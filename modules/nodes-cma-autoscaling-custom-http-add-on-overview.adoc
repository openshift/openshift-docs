= Understanding the Autoscaling HTTP Add-on

[role="_abstract"]
The HTTP Add-on extends the Custom Metrics Autoscaler Operator to automatically scale HTTP-based applications on incoming request metrics to increase or decrease replicas as needed to meet demand.

During periods of low HTTP traffic, the scaler decreases application scales down to zero replicas or the `maxReplicaCount` value you set. When requests arrive the application gets scaled up from zero up to `maxReplicaCount` value you set.

The HTTP Add-on is a specialized extension that integrates with the Custom Metrics Autoscaler Operator to provide HTTP traffic-based scaling for containerized applications. Unlike traditional horizontal pod autoscaling (HPA) that requires persistent metrics collection, the HTTP Add-on uses an interceptor proxy to observe HTTP traffic in real time and make intelligent scaling decisions.

The HTTP Add-on consists of several Kubernetes resources deployed in the `openshift-keda` namespace:

* Interceptor. The proxy that sits between your traffic source and application, collecting HTTP metrics.

* Scaler. Analyzes interceptor metrics and provides scaling decisions to the Custom Metrics Autoscaler Operator.

* Operator. Manages the lifecycle of interceptor and scaler resources based on your scaling configuration.

* Custom Metrics Adapter. Part of the Custom Metrics Autoscaler Operator; exposes interceptor metrics to the Kubernetes metrics API so the HPA can consume them.

To configure HTTP traffic-based scaling you create two custom resources for each application, in addition to an edge route and service:

* `InterceptorRoute`: Defines how the HTTP Add-on intercepts and collects traffic for your application. The interceptor route specifies routing rules, scaling metrics configuration, and the target application service.

* `ScaledObject`: Defines how the Custom Metrics Autoscaler uses HTTP traffic metrics to scale your application. Understanding trigger parameters helps you configure appropriate activation and scaling thresholds for your workload.

The HTTP Add-on supports the autoscaler activation and scaling phases, where the Cluster Metrics Autoscaler Operator handles scaling between zero and one replica. After the application has at least one replica, the HPA takes control and scales the application based on your configured metrics.

When traffic arrives at your application, the interceptor measures request volume and concurrency. Based on configurable thresholds, the scaler determines whether to scale from zero to one replica or allow the HPA to scale to more replica counts. When traffic drops below the activation threshold, the application scales back to zero, reducing infrastructure costs.

You can set minReplicaCount to 0 in the ScaledObject custom resource so that the application scales to zero replicas after requests stop. Any request causes the Custom Metrics Autoscaler to scale the application from zero to one replica. Set targetValue in the InterceptorRoute custom resource to control when the horizontal pod autoscaler adds more replicas, up to maxReplicaCount in the ScaledObject custom resource.

For example, with `requestRate.targetValue` set to `100` and `maxReplicaCount` set to `10`, the first request starts one pod. The autoscaler adds pods while the rate stays above 100 requests per second per pod, and it stops at 10 pods.

For more information on the HTTP Add-on, you can review the KEDA HTTP Add-on documentation.
