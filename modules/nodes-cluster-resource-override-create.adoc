= Creating a ResourceOverride in a project

[role="_abstract"]
You can create a namespaced `ResourceOverride` object so that new pods in your project use CPU and memory requests that differ from the cluster-wide default.

The new requests are applied to pods in opted-in namespaces that are created or updated after the `ResourceOverride` object exists. Pods that already run are unchanged.

.Prerequisites

* The Cluster Resource Override Operator is installed.
* A `ClusterResourceOverride` object named `cluster` exists.
* You are bound to the `admin` or `edit` role in the target project.
* The target project is not a system namespace, which are namespaces whose name starts with `openshift-`, `kube-`, or `kubernetes-`.
* The namespace has the `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled=true` label.
* Default container limits are specified in a `LimitRange` object for the project, or limits are configured in `Pod` specs, if you set `memoryRequestToLimitPercent`, `cpuRequestToLimitPercent`, or `limitCPUToMemoryPercent`.

.Procedure

. Confirm that the cluster-scoped object named `cluster` still exists, and do not re-create, rename, or relabel that object:
+
[source,terminal]
----
$ oc get clusterresourceoverride cluster -n clusterresourceoverride-operator
----

. Confirm that each application namespace that should receive overrides is still opted in:
+
[source,terminal]
----
$ oc get namespace <namespace> --show-labels
----
+
The output includes `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled=true`.
A `ResourceOverride` object does not bypass this label.
+
.Example output
[source,terminal]
----
NAME   STATUS   AGE   LABELS
aa     Active   39s   clusterresourceoverrides.admission.autoscaling.openshift.io/enabled=true
# ...
----
+
Altermatively, add the opt-in label to the namespace by using the following command:
+
[source,terminal]
----
oc label namespace <namespace_name> clusterresourceoverrides.admission.autoscaling.openshift.io/enabled=true
----
+
where:

`<namespace_name>`:: Specifies the namespace name to use.

. Create a `ResourceOverride` object in an already opted-in application namespace.
To change only some pods, set `spec.podSelector` so that unmatched pods keep the cluster-wide ratios.
+
[IMPORTANT]
====
If you omit `spec.podSelector` or set `podSelector: {}`, the namespaced ratios replace the cluster-wide configuration for every new pod in that namespace.
The webhook does not merge the two objects field by field.
====

.. Create a `ResourceOverride` object YAML file, for example `resourceoverride.yaml`:
+
[source,yaml]
----
apiVersion: autoscaling.openshift.io/v1
kind: ResourceOverride
metadata:
  name: example
  namespace: <namespace>
spec:
  podResourceOverride:
    memoryRequestToLimitPercent: 50
    cpuRequestToLimitPercent: 25
    limitCPUToMemoryPercent: 200
    cpuRequestToRequestPercent: 50
  podSelector:
    matchLabels:
      workload-type: batch
----
+
where:
+
--
`metadata.name`:: Specifies a name for the object in the project.
`metadata.namespace`:: Specifies the project that contains the pods to mutate.
Use the same value in later commands, `<namespace>` in this example.
`spec.podResourceOverride`:: Specifies the override ratios.
Place fields directly under `spec.podResourceOverride`.
Do not nest them under an extra `.spec` key.
`spec.podResourceOverride.memoryRequestToLimitPercent`::  Specifies the percentage to override the container memory limit, if used, between 1 and 100. The default is `50`. This parameter is optional.
`spec.podResourceOverride.spec.cpuRequestToLimitPercent`:: Specifies the percentage to override the container CPU limit, if used, between 1 and 100. The default is `25`. This parameter is optional. 
`spec.podResourceOverride.spec.limitCPUToMemoryPercent`:: Specifies the percentage to override the container memory limit, if used. Scaling 1 Gi of RAM at 100 percent is equal to 1 CPU core. This is processed before overriding the CPU request, if configured. The default is `200`. This parameter is optional.
`spec.podResourceOverride.cpuRequestToRequestPercent`:: Specifies the percentage of the original CPU request to set as the new CPU request, between 1 and 100. Omit this field to disable request-relative CPU override. This parameter is optional and has no default. A CPU limit is not required.
`spec.podSelector.matchLabels`:: Specifies labels that a pod must have to use these requests.
Omit `spec.podSelector`, if every new pod in the namespace should use these requests.
--

.. Create the object:
+
[source,terminal]
----
$ oc create -f resourceoverride.yaml
----

.Verification

. List `ResourceOverride` objects in the project:
+
[source,terminal]
----
$ oc get resourceoverride -n <namespace>
----
+
.Example output
[source,terminal]
----
NAME      AGE
example   15s
----

. Inspect status conditions by running the following command until the `ValidationFailure` and `Ignored` conditions are present:
+
[source,terminal]
----
$ oc get resourceoverride <resource_override> -n <namespace> -o yaml
----
+
Replace `<resource_override>` with the name of your `ResourceOverride` object.
+
.Example status.conditions for a valid object in an opted-in namespace
[source,yaml]
----
status:
  conditions:
  - status: "False"
    type: Ignored
  - status: "False"
    type: ValidationFailure
----
+
For more information on status conditions, see "Resource override API fields".

. Create or roll out a new pod that matches the selector, if you set one, and inspect the admitted requests and limits.
