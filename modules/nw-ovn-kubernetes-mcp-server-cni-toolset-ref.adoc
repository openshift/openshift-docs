= CNI diagnostics toolset reference

[role="_abstract"]
You can call `cni-diagnostics` tools from an MCP client for kernel-level networking diagnostics and packet capture on {product-title} nodes.

The following `cni-diagnostics` tools create ephemeral privileged debug pods on the target node for kernel-level networking diagnostics and packet capture. Pod-level `tcpdump` uses `pods/exec` on an existing pod. You can customize debug-pod images in the MCP server `config.toml` file.

.Kernel-level tools
[cols="25%,75%",options="header"]
|===
|Tool |Key parameters and use

|`get-conntrack`
|Requires `node`. Optional `command` values include `-L`, `-C`, and `-S`.

|`get-iptables`
|Requires `node`. Optional `table` and `command` select the table and list style.

|`get-nft`
|Requires `node` and a `command` such as `list ruleset` or `list tables`.

|`get-ip`
|Requires `node` and `command` for `iproute2` queries.
|===

.Network tools
[cols="25%,75%",options="header"]
|===
|Tool |Key parameters and use

|`tcpdump`
|Set `target_type` to `node` or `pod`, and set `name` to the node or pod name. Optional `bpf_filter` and `packet_count` limit the capture.

|`pwru`
|Requires `node_name`. Optional `bpf_filter` and `output_limit_lines` limit the trace. Requires Linux kernel 4.18 or later with eBPF support.
|===

Packet capture and eBPF tracing can increase CPU use on production nodes. Use BPF filters and limit packet or line counts to the minimum that you need.
