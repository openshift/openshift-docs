= Understanding data sent to LLM providers

[role="_abstract"]
{ols-long} sends a prompt payload directly from the {ols-long} Service pod to your configured large language model (LLM) provider endpoint. The exact fields in that payload depend on which features you enable. Use the following disclosures to evaluate {ols-long} for a regulated environment.

[id="ols-data-standard-query-flow_{context}"]
== Standard query flow

For a standard chat query, {ols-long} sends the following data to the LLM provider:

* The user question that you type into the interface.
* The conversation history for the current session, which provides context for follow-up questions.
* The system prompt. By default, this prompt contains the guardrails that restrict {ols-long} to allowed topics. If you set the `querySystemPrompt` field, {ols-long} sends your custom prompt instead.
* Retrieval-augmented generation (RAG) context snippets that match your question. By default, these snippets come from the Offline Knowledge Portal, which provides {ocp-product-title} documentation and {product-rosa} (ROSA) documentation on ROSA clusters.
* Cluster and environment details that {ols-long} appends to provide context for your environment.

[id="ols-data-agentic-flow_{context}"]
== Agentic flow

When you enable cluster interaction or an agentic feature, {ols-long} sends everything in the standard query flow and the following additional data:

* Tool definitions for the set of tools that query-based filtering selects as relevant to your request.
* Tool call arguments that the model generates when it decides to call a tool.
* Tool execution results that are returned from the Observability MCP server and from any Model Context Protocol (MCP) servers that you configure.

[IMPORTANT]
====
Query filtering and redaction apply only to the user query path. Content that a tool returns is not filtered by `queryFilters` and is visible to the LLM. If a tool returns secrets, personally identifiable information (PII), or credentials, that content reaches the LLM unfiltered. For related protections, see the tool-result safety inspection in xref:#ols-prompt-injection-safeguards_{context}[Prompt injection safeguards].
====

[id="ols-data-byok-rag-flow_{context}"]
== BYOK and RAG flow

When you use the BYO Knowledge tool to add a custom RAG database, {ols-long} sends everything in the standard query flow and the following additional data:

* Content from your custom knowledge base that matches your question, inserted into the prompt as RAG context.

When you use the BYO Knowledge tool, you provide your documents directly to the LLM provider through this RAG context. Do not include content in a BYO Knowledge database that you want to keep private from the LLM.

[id="ols-data-not-sent_{context}"]
== What is not sent

{ols-long} does not send the following data to the LLM provider:

* Cluster credentials, kubeconfig files, bearer tokens, or service account tokens.
* Secrets and role-based access control (RBAC) objects. By default, the built-in cluster introspection MCP server blocks access to secrets and RBAC objects, which prevents the leakage of sensitive infrastructure data.
* Data that matches a query filter pattern that you configure. {ols-long} redacts this data before it sends the query to the LLM.

[NOTE]
====
{ols-long} has a limited ability to filter or hide the data you send to the LLM. Redaction applies only to the regular expression patterns that you define, and only on the user query path. It does not filter tool results, RAG content, or free-form text that does not match a configured pattern. Do not enter any information into the interface that you want to keep private from the LLM.
====

[id="ols-data-per-provider-differences_{context}"]
== Per-provider differences

{ols-long} composes the prompt payload the same way for every supported provider. The fields that {ols-long} sends do not change based on which provider you configure. What differs is each provider's own handling, retention, and training policy for the data that it receives.

{ols-long} communicates directly with the endpoint that you configure, such as OpenAI, {azure-openai}, {watsonx}, {aws-full} Bedrock, Google Vertex AI, or a self-hosted model served by {rhoai} or {rhelai}. When you self-host a model, the prompt payload stays within your own infrastructure and does not reach a third-party provider. For a Software as a Service (SaaS) provider, review that provider's data handling and retention policy to confirm that it meets your compliance requirements.
