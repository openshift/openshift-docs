= About {KMS} encryption

[role="_abstract"]
{KMS} uses external Key Management Services to encrypt etcd data and centralize key management. // cite:1
// cite:1 VERIFIED [90]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L28-L29 - "Extend OpenShift encryption controllers to support external Key Management Services (KMS v2)"

{KMS} provides:

* Customer-managed encryption keys that never leave the external KMS // cite:2
* Centralized key management and auditing
* Regulatory compliance support
// cite:2 VERIFIED [90]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L41-L42 - "encryption keys are stored outside the cluster, protecting against attacks where control plane nodes are compromised"

[id="kms-architecture_{context}"]
== KMS plugin architecture

{product-title} manages KMS plugins as sidecar containers that run alongside the API server pods. An OLM Operator for the KMS provider manages the plugin image lifecycle and configuration through a custom resource. // cite:3
// cite:3 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L139 - "In Tech Preview v2, it runs as a sidecar container alongside with API Servers...managed by the APIServer operators"
// cite:3 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L141 - "KMS plugin OLM operator...manages the plugin image lifecycle"
// cite:3 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L712 - "Tech Preview v2 replaces this with managed sidecar containers running in the same pod as the API server"

The workflow is:

. Install the OLM Operator for your KMS provider.
. Create a provider-specific custom resource with your KMS plugin configuration, such as `VaultKMSConfig` for HashiCorp Vault. // cite:4
. Reference the custom resource from the `APIServer` resource.
// cite:4 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L211-L280 - Steps for enabling KMS v2: install OLM operator, create VaultKMSConfig CR, configure APIServer resource

The OLM Operator reconciles the custom resource and provides a tested, version-compatible plugin image. The encryption controllers deploy the plugin as a sidecar container and manage encryption key secrets. // cite:5
// cite:5 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L232 - "OLM operator reconciles the custom resource...mirrors the spec but also includes the plugin image reference"
// cite:5 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L745 - "Plugin images...embedded in the OLM operator...ensuring that the image is tested and compatible"

[id="kms-preflight-validation_{context}"]
== Pre-flight validation

Before applying any KMS configuration change, {product-title} runs a pre-flight check that deploys a temporary pod with the KMS plugin to verify: // cite:7

* The plugin reports healthy status.
* The plugin can encrypt and decrypt data.

Configuration changes are applied only after pre-flight checks succeed. This prevents deploying a misconfigured plugin that could cause API server failures. // cite:8
// cite:7 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L337 - "keyController runs pre-flight checks by deploying a pod with the KMS plugin to verify status and encrypt/decrypt capability"
// cite:7 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L472-L476 - "Status — polls until healthz=ok; Encrypt — encrypts a random payload; Decrypt — decrypts and verifies round-trip"
// cite:8 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L449 - "Configuration changes are only applied after pre-flight checks succeed. This prevents deadlocks where a misconfigured key...is deployed but non-functional"

[id="kms-health-monitoring-overview_{context}"]
== Health monitoring

A health reporter sidecar runs alongside each API server pod and probes the KMS plugin at regular intervals. The reporter publishes results as conditions on the Operator custom resource. An aggregator controller rolls up per-node conditions into a `KMSPluginsDegraded` condition on the `ClusterOperator` resource. // cite:9
// cite:9 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L800 - "health reporter sidecar runs alongside every API server pod replica...probes the colocated KMS plugin(s) and publishes the outcome"
// cite:9 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L1033 - "Each reporter probes and emits on a fixed interval, default 30 seconds"
// cite:9 VERIFIED [92]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L1041 - "aggregator controller reads the per-node KMSHealthReporter_<nodeName> conditions...emits rollup conditions...first rollup is KMSPluginsDegraded"

You can check KMS plugin health by viewing the `kube-apiserver` cluster Operator status.

[id="kms-encrypted-resources_{context}"]
== Encrypted resources

When you enable KMS encryption, {product-title} encrypts the following sensitive resources in etcd:

* Secrets
* ConfigMaps
* Routes
* OAuth access tokens
* OAuth authorize tokens // cite:10
// cite:10 VERIFIED [97]: https://github.com/openshift/api/blob/9edb1b2/config/v1/types_apiserver.go#L222-L227 - Authoritative list: "1. secrets 2. configmaps 3. routes.route.openshift.io 4. oauthaccesstokens.oauth.openshift.io 5. oauthauthorizetokens.oauth.openshift.io"

[NOTE]
====
Resource types, namespaces, and object names are not encrypted. // cite:11
====
// cite:11 VERIFIED [45]: https://kubernetes.io/docs/tasks/administer-cluster/kms-provider/ - Upstream Kubernetes KMS docs confirm only resource values are encrypted, not metadata
