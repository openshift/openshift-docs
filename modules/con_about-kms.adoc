= About {KMS} encryption

[role="_abstract"]
{KMS} uses an external Key Management Service to encrypt etcd data and centralize key management.

{KMS} provides:

* Customer-managed encryption keys stored in an external KMS
* Centralized key management and auditing
* Regulatory compliance support

[id="kms-architecture_{context}"]
== KMS plugin architecture

The KMS plugin configuration is specified inline in the `APIServer` resource. Encryption controllers deploy the KMS plugin and manage encryption key secrets.

The workflow is:

. Create the credential secret and optional CA bundle in the `openshift-config` namespace.
. Configure the `APIServer` resource with the KMS provider settings and plugin image.
. The encryption controllers deploy the KMS plugin and begin encrypting etcd data.

[NOTE]
====
HashiCorp Vault Enterprise is the only supported KMS provider. Vault Community Edition is not supported. Vault Enterprise must be externally hosted and must not run inside the cluster service network.
====

[id="kms-encrypted-resources_{context}"]
== Encrypted resources

When you enable KMS encryption, {product-title} encrypts the following resources in etcd:

* Secrets
* ConfigMaps
* Routes
* OAuth access tokens
* OAuth authorize tokens

[NOTE]
====
Resource types, namespaces, and object names are not encrypted.
====
