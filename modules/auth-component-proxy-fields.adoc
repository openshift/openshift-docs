= Authentication operator proxy field reference

[role="_abstract"]
The `spec.proxy` object of the `Authentication` operator resource (`operator.openshift.io/v1`) accepts fields for HTTP proxy, HTTPS proxy, proxy bypass, and trusted CA configuration.

.`spec.proxy` fields
[cols="2,1,4",options="header"]
|===
|Field
|Type
|Description

|`httpProxy`
|`string`
|Specifies the proxy URL for HTTP requests. Must use `http` or `https` scheme with a non-empty hostname and no path, query parameters, or fragment. Userinfo is allowed (for example, `\http://user:password@proxy:3128`). Maximum 2048 characters. At least one of `httpProxy` or `httpsProxy` is required.

|`httpsProxy`
|`string`
|Specifies the proxy URL for HTTPS requests. Must use `http` or `https` scheme with a non-empty hostname and no path, query parameters, or fragment. Userinfo is allowed. Maximum 2048 characters. At least one of `httpProxy` or `httpsProxy` is required.

|`noProxy`
|`[]string`
|Specifies hostnames, domains, classless inter-domain routing (CIDR) ranges, or IP addresses that bypass the proxy. Each entry must be 1-253 characters. Maximum 64 entries. Duplicates are not permitted. Cluster-internal defaults (`.cluster.local`, `.svc`, `127.0.0.1`, the Kubernetes API service IP, and `localhost`) are appended automatically.

|`trustedCA.name`
|`string`
|Specifies the name of a config map in the `openshift-config` namespace containing a CA certificate bundle under the key `ca-bundle.crt`. This bundle is appended to the system truststore for proxy Transport Layer Security (TLS) connections. When omitted, only the system truststore is used. Must be a valid Domain Name System (DNS) subdomain name (RFC 1123): at most 253 characters, lowercase alphanumeric characters, hyphens, or periods.
|===

== Behavioral notes

* When `spec.proxy` is set, it completely replaces the cluster-wide proxy for authentication. No fields are inherited.
* The proxy validation controller tests IdP connectivity through the proxy on every configuration change.
* The controller emits warning events when IdP endpoints are unreachable through the proxy.
* Proxy-level failures such as connection refused or TLS handshake errors cause the `Available` condition to report `False`. The `Degraded` condition message includes details from the `ProxyConfigController` sub-controller.
* The operator injects `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY` environment variables into the OAuth server pod specification. Changes to these values trigger a redeployment.
* The `trustedCA` config map is synced from `openshift-config` to `openshift-authentication` by the operator. The OAuth server hot-reloads the mounted CA file on change without redeployment.
