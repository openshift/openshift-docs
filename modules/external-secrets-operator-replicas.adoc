[id="external-secrets-operator-replicas_{context}"]
= Replicas for external-secrets components

[role="_abstract"]
Set the `replicas` field to run more than one pod for each `external-secrets` component in the {external-secrets-operator}. Multiple replicas keep the component available if a pod fails.

The following components support replica settings:

.Components that support replica settings
[cols="1,1",options="header"]
|===
| Component name
| Description

| `ExternalSecretsCoreController`
| Main `external-secrets` controller

| `Webhook`
| `external-secrets` webhook server

| `CertController`
| Certificate controller for webhook Transport Layer Security (TLS) certificates

| `BitwardenSDKServer`
| Bitwarden SDK server plugin

|===

You can add one configuration entry for each component, for a maximum of four entries.

[id="external-secrets-operator-leader-election_{context}"]
== Leader election

Leader election ensures that only one replica of a controller processes changes at a time, even when several replicas are running.

* For `ExternalSecretsCoreController` and `CertController`, the {external-secrets-operator} always sets `--enable-leader-election=true` on the container arguments. Leader election stays enabled when you set `replicas` to 1. During rolling updates, two pods can briefly run, and only one replica processes changes.

* For `Webhook` and `BitwardenSDKServer`, neither component uses leader election, regardless of the `replicas` count.
