== Fixed issues

* Before this update, when you removed failure domains from the infrastructure specification, the vSphere Problem Detector (VPD) logged errors about failure domain labels missing from nodes. As a consequence, VPD logged warnings that were not relevant. With this release, VPD improves processing logic for failure domain changes in the infrastructure specification. As a result, these unnecessary warnings no longer appear. (link:https://issues.redhat.com/browse/OCPBUGS-105280[OCPBUGS-105280])

* Before this update, on dual-stack HostedClusters, ValidateKeyPair compared certificate IP SANs using raw net.IP byte slices. After an X.509 round-trip, IPv4 SANs could be stored as 4-byte values while desired IPs from net.ParseIP were 16-byte IPv4-mapped addresses, so validation falsely reported that IP addresses differed even when the logical set was unchanged. As a consequence, the control-plane operator resigned kas-server-crt on every reconcile, rewriting the kube-apiserver Deployment config-hash and causing generation churn that could prevent HostedCluster installation from completing. With this release, current and desired IP SANs are normalized with net.IP.To16() before comparison. As a result, dual-stack HostedClusters no longer regenerate kas-server-crt when the SAN set is unchanged, and kube-apiserver stops rolling continuously. (link:https://issues.redhat.com/browse/OCPBUGS-112731[OCPBUGS-112731])

* Before this update, when you removed a MachineConfig that required a revert to a MachineOSBuild in a terminal state, the digested image push configuration was not changed. As a consequence, removing a MachineConfig in image mode failed and left the associated MachineConfigPool in an Updating state indefinitely. With this release, terminal builds update correctly when the digested image push configuration changes, enabling image reuse for a new build. As a result, you can successfully delete MachineConfigs in an image mode cluster. (link:https://issues.redhat.com/browse/OCPBUGS-127018[OCPBUGS-127018])

* Before this update, the rendezvous-node IP list was not refreshed after a static IP was added through the agent TUI networking screen. As a consequence, the newly added IP was not shown or available in the Rendezvous node IP selection screen. With this release, the host IP list refreshes whenever the selection screen opens. As a result, newly configured IP addresses appear for selection. (link:https://issues.redhat.com/browse/OCPBUGS-127041[OCPBUGS-127041])

* Before this update, sometimes during startup the default PTP operator config failed to create because the webhook was not yet ready. As a consequence, the linuxptp-daemon was not scheduled. With this release, the operator waits for the webhook to become ready before creating the default PTP operator config. As a result, the default PTP operator config is populated reliably. (link:https://issues.redhat.com/browse/OCPBUGS-128642[OCPBUGS-128642])
