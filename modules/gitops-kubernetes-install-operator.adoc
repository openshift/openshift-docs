= Install {gitops-title} Operator via Helm chart

[role="_abstract"]
You can install the {gitops-title} Operator on non-OpenShift Kubernetes platforms using the official OCI Helm chart published to `registry.redhat.io`.

.Prerequisites

* You have configured registry authentication. For more information, see "Configure registry authentication for {gitops-title} Helm charts".
* You have Helm version 3.8 or later installed with OCI support enabled.
* You have cluster-admin privileges on your Kubernetes cluster.

.Procedure

. Install the {gitops-title} Operator Helm chart:
+
Replace `<chart_version>` with the {gitops-title} version you want to install. The chart version matches the product version, for example, `1.23.0`.
+
[source,terminal,subs="attributes+"]
----
$ helm install openshift-gitops-operator \
  oci://registry.redhat.io/openshift-gitops/openshift-gitops-operator-chart \
  --version <chart_version> \
  --namespace openshift-gitops-operator \
  --set-file pullSecret.dockerConfigJson=/path/to/pull-secret.txt \
  --set "pullSecret.labels.operator\.argoproj\.io/propagate-image-pull-secret=true" \
  --create-namespace \
  --registry-config /path/to/pull-secret.txt
----

. Verify that the Operator pod is running:
+
[source,terminal]
----
$ kubectl get pods -n openshift-gitops-operator
----
+
Example output:
+
----
NAME                                               READY   STATUS    RESTARTS   AGE
gitops-operator-controller-manager-5d7f8c8-xk2lm   2/2     Running   0          2m
----

.Verification

The {gitops-title} Operator is installed and running in the `openshift-gitops-operator` namespace. The operator is now ready to manage Argo CD instances.
