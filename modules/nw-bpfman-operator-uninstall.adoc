= Uninstalling a containerized eBPF program

[role="_abstract"]
To stop an eBPF application and unload its programs from cluster nodes, you can delete the userspace workload and the custom resource that loaded the bytecode. The eBPF Manager Operator then detaches and unloads the programs.

As a cluster administrator, you can uninstall a containerized eBPF application without uninstalling the eBPF Manager Operator. Delete the userspace workload first so that Container Storage Interface (CSI) map volumes unmount. Then delete the `ClusterBpfApplication` or `BpfApplication` custom resource so that the Operator unloads the eBPF programs.

[NOTE]
====
If you deployed the sample application from a YAML file, you can delete all of its resources by running `oc delete -f go-xdp-counter-install-selinux.yaml` instead of deleting each object individually.
====

.Prerequisites

* You have installed the OpenShift CLI (`oc`).
* You have an account with administrator privileges.
* You have installed the eBPF Manager Operator.
* You have deployed a containerized eBPF application.

.Procedure

. Delete the userspace daemon set that mounts the eBPF maps by running the following command:
+
[source,terminal]
----
$ oc delete daemonset <daemonset_name> -n <namespace>
----
+
where:
+
`<daemonset_name>`:: Specifies the name of the daemon set that runs the userspace application, for example `go-xdp-counter-ds`.
`<namespace>`:: Specifies the namespace of the application, for example `go-xdp-counter`.

. Delete the custom resource that loaded the eBPF programs:
+
* For a cluster-scoped application, run the following command:
+
[source,terminal]
----
$ oc delete clusterbpfapplication <application_name>
----
+
* For a namespace-scoped application, run the following command:
+
[source,terminal]
----
$ oc delete bpfapplication <application_name> -n <namespace>
----
+
where:
+
`<application_name>`:: Specifies the name of the `ClusterBpfApplication` or `BpfApplication` object, for example `go-xdp-counter-example`.

. Delete any cluster-scoped resources that you created for the application, such as a `ClusterRoleBinding` object, by running the following command:
+
[source,terminal]
----
$ oc delete clusterrolebinding <clusterrolebinding_name>
----
+
where:
+
`<clusterrolebinding_name>`:: Specifies the name of the cluster role binding, for example `xdp-binding`. Deleting the application namespace does not remove cluster-scoped objects.

. Optional: Delete a `SelinuxProfile` object that you created for the application by running the following command:
+
[source,terminal]
----
$ oc delete selinuxprofile <selinuxprofile_name> -n <namespace>
----
+
where:
+
`<selinuxprofile_name>`:: Specifies the name of the SELinux profile, for example `bpfman-secure`.

. Optional: Delete the application namespace by running the following command:
+
[source,terminal]
----
$ oc delete namespace <namespace>
----

.Verification

. Verify that the application custom resources are removed by running the following command:
+
[source,terminal]
----
$ oc get clusterbpfapplication,bpfapplication -A
----
+
.Example output
[source,text]
----
No resources found
----

. Verify that the per-node state objects that the Operator created for the application are removed by running the following command:
+
[source,terminal]
----
$ oc get clusterbpfapplicationstate,bpfapplicationstate -A
----
+
.Example output
[source,text]
----
No resources found
----
+
The Operator owns the `ClusterBpfApplicationState` and `BpfApplicationState` objects. Do not delete these objects directly. They are removed after the application custom resource is deleted.
