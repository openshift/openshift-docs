= Evaluating HAProxy version changes before a cluster update

[role="_abstract"]
Before you update to {product-title} {product-version}, decide whether your Ingress Controller should keep HAProxy 2.8 or move to HAProxy 3.2. Pinning the HAProxy version reduces the risk that an ingress behavior change will disrupt applications during the cluster update.

{product-title} {product-version} changes the default HAProxy version for Ingress Controllers from 2.8 to 3.2. You can keep HAProxy 2.8 for migration, or pin HAProxy 3.2 so that a later cluster update does not change the version unexpectedly.

If your applications are sensitive to proxy behavior, set `spec.haproxyVersion` to `2.8` on each Ingress Controller that must keep the previous HAProxy version. If you leave `spec.haproxyVersion` unset, Ingress Controller pods use HAProxy 3.2 after the update.

[IMPORTANT]
====
If `spec.haproxyVersion` is set to a value that a target release does not support, a preflight check blocks the cluster update until you change the field to an empty value or to a supported version. HAProxy 2.8 is supported in {product-title} {product-version} for migration and is planned to be removed in a later release.
====
