= Configure Spectrum-X network adapters

[role="_abstract"]
You can configure network interface controller (NIC) firmware and Spectrum-X optimized settings by using the NVIDIA NIC Configuration Operator.

The examples use the BlueField-3 SuperNIC `a2dc` profile and Spectrum-X RA2.1. Resource schemas and configuration profiles can differ between Network Operator releases.

[IMPORTANT]
====
Firmware or NIC configuration changes can interrupt network traffic and can require a node or adapter restart.
====

.Prerequisites

* You have cluster administrator privileges.
* You have installed the NVIDIA Network Operator and NIC Configuration Operator and verified that they are running.
* You have confirmed the adapter type, peripheral component interconnect (PCI) addresses, breakout configuration, firmware bundle, and Spectrum-X reference architecture version for the target nodes.
* You have scheduled a maintenance window.

.Procedure

. Create a file named `nic-interface-name-template.yaml` with the following content to assign consistent names to the physical functions (PFs):
+
[source,yaml]
----
apiVersion: configuration.net.nvidia.com/v1alpha1
kind: NicInterfaceNameTemplate
metadata:
  name: spectrum-x-interface-names
  namespace: nvidia-network-operator
spec:
  nodeSelector:
    node-role.kubernetes.io/worker: ""
  pfsPerNic: 1
  rdmaDevicePrefix: "roce_r%rail_id%"
  netDevicePrefix: "eth_r%rail_id%_p%plane_id%"
  railPciAddresses:
  - ["0000:18:00.0"]
  - ["0000:3a:00.0"]
  - ["0000:4d:00.0"]
----
+
Replace the example PCI addresses with the addresses recorded for the target workers. Use the same naming pattern in the rail policies.
+
Apply the `NicInterfaceNameTemplate` custom resource:
+
[source,terminal]
----
$ oc apply -f nic-interface-name-template.yaml
----

. Create a file named `nic-firmware-source.yaml` with the following content to identify the firmware bundle:
+
[source,yaml]
----
apiVersion: configuration.net.nvidia.com/v1alpha1
kind: NicFirmwareSource
metadata:
  name: spectrum-x-firmware
  namespace: nvidia-network-operator
spec:
  bfbUrlSource: https://content.mellanox.com/BlueField/FW-Bundle/bf-fwbundle-3.3.0-202_26.01-prod.bfb
----
+
The URL identifies the firmware bundle used in the RA2.1 example. Confirm that NVIDIA and the hardware vendor support the bundle for the adapter and platform before applying the `NicFirmwareSource` custom resource:
+
[source,terminal]
----
$ oc apply -f nic-firmware-source.yaml
----

. Create a file named `nic-firmware-template.yaml` with the following content to select the worker adapters:
+
[source,yaml]
----
apiVersion: configuration.net.nvidia.com/v1alpha1
kind: NicFirmwareTemplate
metadata:
  name: spectrum-x-firmware
  namespace: nvidia-network-operator
spec:
  nodeSelector:
    node-role.kubernetes.io/worker: ""
  nicSelector:
    nicType: a2dc
    pciAddresses:
    - "0000:18:00.0"
  template:
    nicFirmwareSourceRef: spectrum-x-firmware
    updatePolicy: Update
----
+
Replace the sample PCI address with the PCI addresses for all target PFs. Confirm with NVIDIA and the hardware vendor that the firmware bundle supports each selected adapter model.
+
Apply the `NicFirmwareTemplate` custom resource and monitor the NIC Configuration Operator and maintenance components until the firmware operation completes:
+
[source,terminal]
----
$ oc apply -f nic-firmware-template.yaml
$ oc get pods -n nvidia-network-operator
----

. Create a file named `nic-configuration-template.yaml` with the following content to enable the Spectrum-X reference architecture:
+
[source,yaml]
----
apiVersion: configuration.net.nvidia.com/v1alpha1
kind: NicConfigurationTemplate
metadata:
  name: spectrum-x-single-plane
  namespace: nvidia-network-operator
spec:
  nicSelector:
    nicType: a2dc
    pciAddresses:
    - "0000:18:00.0"
  nodeSelector:
    node-role.kubernetes.io/worker: ""
  resetToDefault: false
  template:
    linkType: Ethernet
    numVfs: 1
    spectrumXOptimized:
      enabled: true
      overlay: none
      version: RA2.1
----
+
Replace the sample PCI address with the PCI addresses for all adapters that belong to the single plane. Confirm that RA2.1 and the `a2dc` adapter type are supported for the selected Network Operator release before applying the `NicConfigurationTemplate` custom resource:
+
[source,terminal]
----
$ oc apply -f nic-configuration-template.yaml
----

.Verification

* Check the NIC Configuration Operator logs and custom resource status for reconciliation errors.

* Confirm that the expected physical interface names are present on each worker by running the following commands:
+
[source,terminal]
----
$ oc get pods -n nvidia-network-operator
$ oc debug node/<worker_node> -- chroot /host ip -brief link
----
+
Replace `<worker_node>` with the name of the worker node.

* Confirm that each selected adapter has completed its firmware and NIC configuration operations before configuring rails.
