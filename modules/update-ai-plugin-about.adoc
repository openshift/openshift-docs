= AI assessments on the Cluster Update page

[role="_abstract"]
Generating an AI update assessment on the *Cluster Update* page of the web console has several key differences compared to updating a cluster with the *Cluster Settings* page.

Unlike using the *Cluster Settings* page of the web console, where you can only initiate an update after performing your own update preparations, the assessment tool on the *Cluster Update* page directs a user-provided Large Language Model (LLM) to perform a preliminary check for cluster update readiness.
The tool then provides you with the risk of a cluster update to a target version, and you can decide whether or not to initiate the update based on this assessment and your own review of the cluster state.

The assessment tool does not execute an update, it only analyzes the cluster and provides update recommendations.
All cluster state data is processed only by the LLM provider you configured OpenShift Lightspeed Service (OLS) to use.

[id="update-ai-plugin-about-workflow_{context}"]
== AI assessment tool workflow and skills

The assessment tool performs the following workflow when you use it to analyze an update path:

. The assessment tool patches an `AgenticRunApproval` custom resource, which triggers an analysis request.

. An AI agent runs the analysis request inside a read-only sandbox using OLS.

. In the sandbox, the agent uses your configured LLM to execute prechecks on categories such as cluster health, node status, Operator compatibility, conditional update risks, deprecated APIs, and so on.

. The LLM produces an analysis about these categories, as well as an AI risk score and an assessment of whether or not the update is recommended, and the tool renders this assessment for you to review.


During this analysis, the assessment tool uses the following two skills:

* `cluster-update-advisor`: This skill interprets readiness results and cluster conditions such as `ClusterVersion`, `ClusterOperators`, node conditions, and alerts.

* `product-lifecycle`: This skill checks Operator product lifecycle data for lifecycle freshness, and recommends updates for Operators with less than 4 months of remaining lifecycle support.
