= Virtualization dashboards overview

[role="_abstract"]
{VirtProductName} includes Perses-based dashboards that provide visibility into virtual machine (VM) health, resource utilization, and capacity planning across your cluster.

The dashboards are deployed automatically as `PersesDashboard` custom resources by the HyperConverged Cluster Operator (HCO) in the `{CNVNamespace}` namespace.

You can access these dashboards from the web console by navigating to *Observe* -> *Dashboards*.

The dashboards require the Cluster Observability Operator with the monitoring stack enabled.

[id="available-dashboards_{context}"]
== Available dashboards

The following table describes the available {VirtProductName} dashboards:

[cols="1,2",options="header"]
|===
| Dashboard | Description

| *Virtual Machines Inventory*
| Provides a sortable table of all VMs in the cluster, including status, instance type, guest operating system, resource allocation, and operational flags such as live-migratable and evictable. Use this dashboard for fleet management and to find VMs matching specific criteria.

| *Virtual Machines Utilization*
| Shows per-VM resource utilization, including CPU usage, CPU delay, memory usage, swap traffic, storage traffic, storage IOPS, network traffic, and filesystem usage. Use this dashboard for resource monitoring, right-sizing decisions, and cost optimization.

| *Virtual Machines Service Level*
| Tracks VM uptime and downtime over a 24-hour window with planned and unplanned breakdowns. Use this dashboard for service-level agreement (SLA) compliance reporting and to identify VMs that experienced unexpected downtime.

| *Virtual Machines Time in Status*
| Shows how long each VM has been in its current state, with filterable time-in-status thresholds. Use this dashboard to identify stuck or problematic VMs and find long-stopped VMs that can be cleaned up.

| *Top Consumers*
| Ranks the top-N VMs by resource consumption across memory, CPU, storage traffic, storage IOPS, network traffic, vCPU wait time, and memory swap. Use this dashboard for capacity planning and identifying resource contention.

| *Nodes Memory*
| Provides node-level memory utilization, overcommit analysis, memory pressure indicators, and system reservation tracking. Use this dashboard for memory capacity planning and to prevent out-of-memory events.
|===

[id="nodes-memory-dashboard-details_{context}"]
== Nodes Memory dashboard details

The Nodes Memory dashboard is organized into the following sections:

Summary:: Provides a high-level overview of cluster memory health, including the highest and lowest node utilization, cluster-wide utilization trends, and the current system reservation status.

Cluster:: Provides a more detailed view of cluster-wide memory behavior over time, including physical memory utilization split by virtualization and non-virtualization workloads, virtual memory assignment relative to node capacity, and cluster-level memory pressure and swap usage.

Nodes:: Breaks down memory information per node to help identify imbalances, including per-node utilization, pod request fill levels, virtual memory commit ratios, and per-node memory pressure.

System Reserved:: Monitors whether the system (hypervisor) processes stay within their reserved memory budget, including the top nodes by system-reserved memory utilization and the number of nodes exceeding their reservation.

Workloads:: Focuses on individual VM memory behavior, including VM overcommit ratios, guest-reported versus host-side memory usage, and the total number of running VM instances. The Workloads section is collapsed by default.

The dashboard provides two filter variables in the top toolbar:

[cols="3",options="header"]
|===
| Filter | Description | Default
| *Node* | Filters all panels to display information about one or more nodes in the cluster. | *All*
| *role* | Filters all panels to display information about nodes with a specific Kubernetes role, populated from `kube_node_role`. | *worker*
|===

You can also change the time range displayed in the different panels in the top toolbar of the dashboard.

[id="nodes-memory-dashboard-health-states_{context}"]
=== Nodes Memory dashboard health states

Monitor the dashboard indicators in the *Summary* section to identify early warning signs of memory pressure and prevent critical out-of-memory events.

Healthy state:: The *Cluster Utilization* panel gauge is green (below 70%), the *Cluster Virtual Committed* panel gauge is below 120%, the *Node PSI - max* pressure stall information (PSI) values are near zero, and no nodes exceed their system reservation.
Warning signs:: Utilization gauges turn amber (80% to 90%), the virtual commit approaches 150%, or individual nodes diverge significantly from the cluster average, which suggests imbalanced scheduling.
Critical state:: Utilization gauges turn red (above 90%), PSI values exceed 0.5, system reservation is exceeded on any node, or virtual commit ratios per node exceed 200%. These conditions indicate that the cluster is at risk of out-of-memory events and VM eviction.
