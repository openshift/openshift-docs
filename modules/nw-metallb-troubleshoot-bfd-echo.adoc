= If a BFD session stays down with a non-FRR peer

[role="_abstract"]
With a non-FRR peer, such as a Cisco NX-OS router, and `echoMode` set to `false` in the BFD profile, the `Echo receive interval` timer can remain active in the `show bfd peers` output and prevent the BFD session from being established.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the {oc-first}.

.Procedure

. Verify that the `show bfd peers` output shows an active `Echo receive interval` with the `Echo transmission interval: disabled`, as in the following example:
+
[source,text]
----
		Local timers:
			Detect-multiplier: 3
			Receive interval: 300ms
			Transmission interval: 300ms
			Echo receive interval: 50ms
			Echo transmission interval: disabled
----

. As a workaround, disable the echo receive interval for the BFD profile by creating an `FRRConfiguration` custom resource (CR) with a raw FRR configuration. Create a file, such as `frr-echo-disable.yaml`, with content like the following example:
+
[source,yaml]
----
apiVersion: frrk8s.metallb.io/v1beta1
kind: FRRConfiguration
metadata:
  name: disable-echo-receive-interval
  namespace: openshift-frr-k8s
spec:
  nodeSelector:
    matchLabels:
      node-role.kubernetes.io/worker: ''
  raw:
    priority: 10
    rawConfig: |-
      bfd
        profile <bfd_profile_name>
          echo receive-interval disabled
----
+
Replace `<bfd_profile_name>` with the name of the BFD profile used by the BGP peer.

. Apply the CR by running the following command:
+
[source,terminal]
----
$ oc apply -f frr-echo-disable.yaml
----

.Verification

* Run the `show bfd peers` command again and confirm that the `Echo receive interval` field for the local timers shows `disabled` and the session `Status` is `up`.
