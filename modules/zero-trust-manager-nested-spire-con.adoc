= Configuring nested SPIRE for Zero Trust Workload Identity Manager

[role="_abstract"]
You use nested {spiffe-full} Runtime Environment (SPIRE) to join the SPIRE servers on your clusters into one trust domain and one certificate hierarchy. You configure each nested server to obtain its intermediate signing certificate authority (CA) from a parent server. Trust the common root, and you can accept an X.509 workload identity from any cluster in that hierarchy.

You can create the cross-cluster credentials and the trust bundle secret. {zero-trust-full} configures the SPIRE servers and the agent sidecar.

Configure nested SPIRE in the following order:

. Prepare API credentials for each nested cluster.
. Register the nested clusters on the parent server.
. Make the parent gRPC endpoint reachable from each nested cluster.
. Copy the trust bundle to each nested cluster.
. Set `spec.upstreamAuthority.spire` on each nested server.

A mid-tier cluster signs intermediate CAs for other clusters and obtains its own intermediate CA from a parent cluster. Register the lower clusters on the mid-tier server, and configure the mid-tier server to obtain its CA from the parent cluster.
