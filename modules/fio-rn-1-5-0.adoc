= Release notes for OpenShift File Integrity Operator 1.5.0

[role="_abstract"]
OpenShift File Integrity Operator 1.5.0 is now available. The `stable` update channel tracks and receives updates for the File Integrity Operator. For more information, see xref:../../security/file_integrity_operator/file-integrity-operator-updating.adoc#file-integrity-operator-updating[Updating the File Integrity Operator]. The following Red Hat Security Advisory (RHSA) is available:

* link:https://access.redhat.com/errata/RHSA-2026:xxxxx[RHSA-2026:xxxxx - OpenShift File Integrity Operator 1.5.0 bug fix and enhancement update]

[id="file-integrity-operator-1-5-0-new-features-and-enhancements_{context}"]
== New features and enhancements

* With this release, the File Integrity Operator uses the `ubi9/ubi-minimal-pqc` base image. This change enables Post-Quantum Cryptography (PQC) support through OpenSSL and helps TLS endpoints offer ML-KEM during key exchange. (link:https://issues.redhat.com/browse/CMP-4573[CMP-4573], link:https://issues.redhat.com/browse/CMP-4504[CMP-4504])

* With this release, you can set labels and annotations in the `FileIntegrity` custom resource (CR) so the Operator applies them to the DaemonSet pod template. As a result, you can customize how file integrity pods are identified and selected in your environment. (link:https://issues.redhat.com/browse/CMP-4728[CMP-4728])

* With this release, the File Integrity Operator uses the {product-title} API server as the source of truth for TLS configuration. As a result, the Operator applies the same TLS settings as the cluster API. (link:https://issues.redhat.com/browse/CMP-4638[CMP-4638])

* With this release, the File Integrity Operator creates label-scoped `NetworkPolicy` resources for AIDE scanner and re-init operand pods during `FileIntegrity` CR reconciliation. As a result, those operand pods meet required network policy controls. (link:https://issues.redhat.com/browse/CMP-4714[CMP-4714])

* This update includes upgraded dependencies in the underlying base images.
