= Upgrade GitOps components

[role="_abstract"]
Upgrade {gitops-title} Operator and Argo CD instances to receive new features, bug fixes, and security updates. The Operator Lifecycle Manager (OLM) manages the upgrade process automatically or manually, depending on your approval strategy.

.Prerequisites

* You have `cluster-admin` permissions.
* You have reviewed the release notes for the target version.
* You have completed the pre-upgrade checklist.
* You have backed up critical application configurations and Argo CD custom resources.

.Procedure

. Review available updates in the {OCP} web console:
+
.. Navigate to *Operators* -> *Installed Operators*.
.. Select the *openshift-gitops-operator* namespace.
.. Click *{gitops-title}*.
.. Click the *Subscription* tab to view available updates.

. For automatic upgrades (approval strategy: Automatic):
+
The Operator upgrades automatically when a new version is available in the update channel. Monitor the upgrade progress:
+
[source,terminal]
----
$ oc get csv -n openshift-gitops-operator -w
----
+
*Example output:*
[source,terminal]
----
NAME                      DISPLAY              VERSION   REPLACES                  PHASE
openshift-gitops.v1.21.0  Red Hat OpenShift... 1.21.0    openshift-gitops.v1.20.0  Succeeded
----

. For manual upgrades (approval strategy: Manual):
+
.. Check for pending install plans:
+
[source,terminal]
----
$ oc get installplan -n openshift-gitops-operator
----
+
.. Approve the install plan:
+
[source,terminal]
----
$ oc patch installplan <install_plan_name> -n openshift-gitops-operator --type=merge -p '{"spec":{"approved":true}}'
----
+
Or approve through the web console:
+
... Navigate to *Operators* -> *Installed Operators* -> *{gitops-title}* -> *Subscription*.
... Click *Upgrade available*.
... Review the upgrade details and click *Approve*.

. Monitor the Operator upgrade:
+
[source,terminal]
----
$ oc get pods -n openshift-gitops-operator -w
----
+
The Operator pod restarts with the new version.

. Verify the Operator version after upgrade:
+
[source,terminal]
----
$ oc get csv -n openshift-gitops-operator
----
+
*Example output:*
[source,terminal]
----
NAME                      VERSION
openshift-gitops.v1.21.0  1.21.0
----

. Verify Argo CD instances are updated:
+
[source,terminal]
----
$ oc get argocd -A
----
+
Check that the Argo CD version matches the expected version for the Operator release.

. Check component status after upgrade:
+
[source,terminal]
----
$ oc get pods -n openshift-gitops
----
+
All pods should be in `Running` state.

. Verify applications still function correctly:
+
[source,terminal]
----
$ argocd app list
$ argocd app get <application_name>
----

.Verification

. Confirm the Operator version:
+
[source,terminal]
----
$ oc get csv -n openshift-gitops-operator -o jsonpath='{.items[0].spec.version}'
----

. Verify all Argo CD components are healthy:
+
[source,terminal]
----
$ oc get pods -n openshift-gitops
----

. Test application synchronization:
+
[source,terminal]
----
$ argocd app sync <test_application>
----

[IMPORTANT]
====
The Operator manages the Argo CD instance versions automatically. You cannot manually upgrade individual Argo CD instances to versions not supported by the installed Operator version.
====

[NOTE]
====
Some upgrades may include breaking changes or require manual intervention. Always review the release notes and upgrade documentation before proceeding.
====
