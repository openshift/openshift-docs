= About software RAID configuration in {lvms}

[role="_abstract"]
{lvms-first} supports software RAID configuration through the `LVMCluster` custom resource (CR), enabling data redundancy and protection against single disk failures. 

RAID configuration is defined in the `raidConfig` section within a `deviceClass` in the `LVMCluster` CR.

Software RAID in {lvms} provides the following benefits:

* Increases data redundancy across multiple disks on a node
* Protects against data loss from single disk failures
* Provides declarative management of resilient local storage
* Suitable for read-intensive applications (RAID1) or balanced workloads (RAID5)

{lvms} uses LVM RAID to create redundant storage arrays on local devices. When you configure a `deviceClass` with `raidConfig`, the {lvms-first} Operator creates an LVM volume group with RAID levels such as RAID1, RAID5, RAID6, or RAID10 across the specified devices.

After you create a device class with RAID configuration, persistent volume claims (PVCs) created using that device class are automatically backed by the RAID array.

[IMPORTANT]
====
The `raidConfig` fields are immutable after the device class is created. You cannot change the RAID type, number of stripes, or number of mirrors after the initial configuration. Only the `deviceSelector.paths` field can be modified to replace failed disks.
====

You can use software RAID in {lvms} for the following use cases:

Read-heavy databases requiring redundancy:: Use RAID1 for high read performance and protection against single disk failures.

Balanced performance, capacity, and redundancy needs:: Use RAID5 for general-purpose workloads where you need a balance between storage capacity and data protection.

Critical data requiring dual-disk failure protection:: Use RAID6 when you need protection against two simultaneous disk failures.

High-performance I/O intensive workloads:: Use RAID10 for applications that require both high read and write performance with redundancy.

Software RAID is particularly useful in single-node {product-title} and edge computing environments where local storage resilience is critical but external storage arrays are not available.
