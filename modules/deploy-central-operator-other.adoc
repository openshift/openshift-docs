= Deploy Central by using the Operator

[role="_abstract"]
After you install the {product-title-short} Operator, deploy Central by creating a `Central` custom resource.
You deploy Central only once, and you can monitor multiple separate clusters by using the same Central installation.

[IMPORTANT]
====
When you install {product-title} for the first time, you must first install the `Central` custom resource because the `SecuredCluster` custom resource installation is dependent on certificates that Central generates.
====

.Prerequisites

* The {product-title-short} Operator is installed on the cluster. For more information, see "Install the {product-title-short} Operator on other platforms".

.Procedure

. Create the `stackrox` namespace:
+
[source,terminal]
----
$ kubectl create namespace stackrox
----
. Optional: Depending on where you are deploying the image from, create an image pull secret:
* If you are not deploying from the Red Hat image registry, you do not need an image pull secret. You can omit the following steps for generating a token and applying the secret.
* If you are deploying directly from the Red Hat image registry, you must have one of the following:
** A cluster-wide image pull secret
** An image pull secret for the {product-title-short} Operator (that was installed in the `rhacs-operator` namespace) and application component images such as Central, Scanner, and Sensor. You only need one of these secrets for each namespace in which you deploy {product-title-short}. 
.. Generate a registry service account access token by using the Red Hat Customer Portal. For instructions, see "Creating Registry Service Accounts".
.. After you have generated the token, go to the *OpenShift Secret* tab on your *Token Information* page and download a secret suitable for use on Kubernetes clusters. 
.. Apply the secret in the namespace you just created, for example, `stackrox`:
+
[source,terminal]
----
$ kubectl apply -f <path-to-secret/pull-secret.yaml> -n stackrox
----
. Create a YAML file for the `Central` custom resource:
+
[source,yaml,subs="+quotes"]
----
apiVersion: platform.stackrox.io/v1alpha1
kind: Central
metadata:
  name: stackrox-central-services
  namespace: stackrox
spec:
  imagePullSecrets:
    - name: _<pull_secret_name>_
  central:
    exposure:
      loadBalancer:
        enabled: true
----
+
If you have a cluster-wide image pull secret configured, you can omit the `imagePullSecrets` field.
+
[NOTE]
====
The preceding example configures a load balancer for Central access.
You can also use a node port or other exposure method depending on your cluster configuration.
For a full list of configuration options, see "Central configuration options for {product-title-short} by using the Operator".
====

. Apply the custom resource:
+
[source,terminal,subs="+quotes"]
----
$ kubectl apply -f _<central_cr_file>_.yaml
----

.Verification

. Verify the `Central` custom resource status:
+
[source,terminal]
----
$ kubectl get central 
----

. Verify that Central pods are running:
+
[source,terminal]
----
$ kubectl get central -n stackrox
----
+
Confirm that central services has been installed (`AVAILABLE`=`True` and `PROGRESSING`=`False`). 
+
.Example output
----
NAME                        VERSION   ADMINPASSWORD      MESSAGE                                         PROGRESSING   AVAILABLE
stackrox-central-services   4.11.0    central-htpasswd   StackRox Central Services has been installed.   False         True
----
. Retrieve the administrator password:
+
[source,terminal]
----
$ kubectl -n stackrox get secret central-htpasswd -o go-template='{{index .data "password" | base64decode}}'
----
. Retrieve the external IP address of the Central load balancer:
+
[source,terminal]
----
$ kubectl -n stackrox get svc central-loadbalancer
----

. Enter the external IP address and port of the Central load balancer into your browser to access the {product-title-short} portal. 
. Log in with the `admin` user name and the administrator password that you previously retrieved.

.Next steps

* Generate and apply a cluster registration secret or init bundle.
