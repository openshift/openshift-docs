= Secured Cluster services configuration options

[role="_abstract"]
When you create a `SecuredCluster` instance, the Operator exposes the parameters that control how Secured Cluster services connect to Central and how each secured cluster component is deployed and scheduled.

Two parameters are required, and the Operator applies defaults to the rest. You set the remaining parameters only when you want to override a default, for example, to reserve nodes for a component, adjust resource limits, or turn off a component that your environment does not need.

The parameters are grouped into the following categories:

Required configuration settings:: Identify the Central instance to connect to and the name that the secured cluster is registered under.
Admission controller settings:: Control admission control enforcement, scheduling, and webhook behavior.
Scanner configuration settings for the Operator:: Configure the Scanner and Scanner V4 components, including scaling, database storage, and monitoring.
Image configuration:: Specify the image pull secrets that are used to pull component images.
Per node settings:: Configure the components that run on every node, such as Collector and Compliance.
Sensor configuration settings:: Configure scheduling and resources for Sensor.
General and miscellaneous settings:: Configure cluster-wide behavior such as annotations, environment variables, egress mode, network policies, and TLS.
