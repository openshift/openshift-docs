= Project-level resource override parameters

[role="_abstract"]
The `ResourceOverride` custom resource (CR) parameters control how the Cluster Resource Override admission webhook changes container CPU and memory requests for pods in one {product-title} project. An optional pod selector limits the pods in the project that the webhook changes.

[source,yaml]
----
apiVersion: autoscaling.openshift.io/v1
kind: ResourceOverride
metadata:
  name: stateless
  namespace: my-namespace
spec:
  podResourceOverride:
    spec:
      memoryRequestToLimitPercent: 50
      cpuRequestToLimitPercent: 25
      limitCPUToMemoryPercent: 200
      cpuRequestToRequestPercent: 50
  podSelector:
    matchLabels:
      tier: stateless
    matchExpressions:
    - key: app
      operator: In
      values:
        - api
----
where:

--
`apiVersion`:: Specifies `autoscaling.openshift.io/v1`. A `ResourceOverride` object belongs to one project. The cluster-wide profile remains a `ClusterResourceOverride` object with `apiVersion: operator.autoscaling.openshift.io/v1` and `metadata.name: cluster`.
`metadata.name`:: Specifies the name of the object. The name must be unique in the project.
`metadata.namespace`:: Specifies the project for this object. The webhook reads `ResourceOverride` objects in the project of the admitted pod.
`spec.podResourceOverride.spec.memoryRequestToLimitPercent`:: If a container memory limit has been specified or defaulted, the memory request is overridden to this percentage of the limit, from 1 to 100. This parameter is optional.
`spec.podResourceOverride.spec.cpuRequestToLimitPercent`:: If a container CPU limit has been specified or defaulted, the CPU request is overridden to this percentage of the limit, from 1 to 100. This parameter is optional.
`spec.podResourceOverride.spec.limitCPUToMemoryPercent`:: If a container memory limit has been specified or defaulted, the CPU limit is overridden to a percentage of the memory limit. Scaling 1Gi of RAM at 100 percent is equal to 1 CPU core. The webhook processes this parameter before it overrides the CPU request. This parameter is optional.
`spec.podResourceOverride.spec.cpuRequestToRequestPercent`:: If a container CPU request has been specified or defaulted, the CPU request is overridden to this percentage of that request, from 1 to 100. The webhook applies this parameter after the other configured overrides. It calculates the percentage from the CPU request on the original pod and stores that request in the pod annotation `clusterresourceoverrides.admission.autoscaling.openshift.io/original-cpu-request-<container_name>`. If the container has a CPU request and you also set `cpuRequestToLimitPercent`, this parameter replaces the CPU request. If the container has no CPU request, this parameter has no effect. This parameter does not require a CPU limit. This parameter is optional.
`spec.podSelector`:: Optional label selector for pods in the same project. If you omit `podSelector`, or leave `matchLabels` and `matchExpressions` empty, the object matches every pod in the project. If the selector is not a valid label selector, the webhook ignores the object.
`spec.podSelector.matchLabels`:: A map of labels. A pod must include every label in the map to match.
`spec.podSelector.matchExpressions`:: A list of label selector requirements. Each requirement has a `key` field and an `operator` field. Valid values for `operator` are `In`, `NotIn`, `Exists`, and `DoesNotExist`. Set `values` when `operator` is `In` or `NotIn`. A pod must satisfy every requirement. The pod must also match every entry in `matchLabels`.
--

[id="nodes-cluster-resource-override-profiles-conflict_{context}"]
== Resource override conflicts

When more than one `ResourceOverride` object in the project matches a pod, the webhook applies the object whose `metadata.name` comes first in alphabetical order. It records a warning event with the reason `OverrideConflict` on each matching object that it does not apply.

An object with an empty `podSelector` matches every pod in the project. If that object's name comes first in alphabetical order, the webhook applies it to pods that also match an object with a narrower selector.
