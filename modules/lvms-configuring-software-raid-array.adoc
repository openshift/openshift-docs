= Configuring a software RAID array

[role="_abstract"]
You can configure a software RAID array for {lvms} by creating or editing the `LVMCluster` custom resource (CR) with RAID configuration parameters.

.Prerequisites

* The {lvms} Operator is installed on the cluster.
* You have sufficient available, unused block devices on target nodes. The minimum number of devices depends on the RAID level.
* Nodes have physical disks attached and recognized by the system.

.Procedure

. Identify available block devices on the target node:
+
[source,terminal]
----
$ oc debug node/<node_name> -- lsblk
----
+
Note the device paths, such as `/dev/sdb`, `/dev/sdc`, and `/dev/sdd`.

. Create or edit the `LVMCluster` CR with RAID configuration.

.. Navigate to the `deviceClasses` section.
.. Add the `raidConfig` section within a device class.
.. Omit `thinPoolConfig` entirely. RAID configurations require THICK provisioning.
+
[NOTE]
====
The LVMS Operator validates RAID configurations. For example, RAID5 requires at least 3 disks. Configurations that do not meet minimum requirements are rejected.
====
+
.Example RAID1 configuration
[source,yaml]
----
apiVersion: lvm.topolvm.io/v1alpha1
kind: LVMCluster
metadata:
  name: lvmcluster-sample
spec:
  storage:
    deviceClasses:
    - name: raid1-vg
      deviceSelector:
        paths:
        - /dev/sdb
        - /dev/sdc
      raidConfig:
        type: raid1
        mirrors: 1
----
+
.Example RAID5 configuration
[source,yaml]
----
apiVersion: lvm.topolvm.io/v1alpha1
kind: LVMCluster
metadata:
  name: lvmcluster-sample
spec:
  storage:
    deviceClasses:
    - name: raid5-vg
      deviceSelector:
        paths:
        - /dev/sdb
        - /dev/sdc
        - /dev/sdd
      raidConfig:
        type: raid5
        stripes: 2 
----
+
For RAID5, `raidConfig.stripes` equals the number of data disks. With 3 total disks, you have 2 data disks and 1 parity disk.

. Apply the `LVMCluster` CR by running the following command:
+
[source,terminal]
----
$ oc apply -f lvmcluster.yaml
----

. Verify that the device class is ready by running the following command:
+
[source,terminal]
----
$ oc get lvmcluster -o yaml
----
+
The device class status should show as `Ready`.

.Verification

* Verify that the device class appears in the `LVMCluster` status by running the following command:
+
[source,terminal]
----
$ oc get lvmcluster lvmcluster-sample -o jsonpath='{.status.deviceClassStatuses}' | jq
----

* Verify that the storage class is automatically created for the RAID device class by running the following command:
+
[source,terminal]
----
$ oc get storageclass
----

.Next steps

* Create a `StorageClass` referencing the RAID device class if custom parameters are needed.
* Provision persistent volume claims (PVCs) using the RAID-backed storage.
