= Kiali console architecture

[role="_abstract"]

The Kiali console is a front end served by {KialiServer}. {KialiServer} reads {istio} and {ocp-product-title} data and returns it to the browser. The server does not store mesh telemetry.

.Kiali architecture on {ocp-product-title}
image::ossm-kiali-architecture.png[Diagram of the Kiali back end, the Kiali console, {istio}, Prometheus, and the {ocp-product-title} API]

{KialiServer}:: The back end runs on {ocp-product-title}. It talks to {istio}, to Prometheus, and to the {ocp-product-title} API, then exposes that data to the console. When you install Kiali with {KialiProduct}, you configure the server in the `Kiali` custom resource. The server does not need its own database.

Kiali console:: The console is a single-page web application. In a standard deployment, {KialiServer} serves the console, and the console calls the server for every view. Session credentials stay in the browser. They are not shared across browsers or devices.

{istio}:: {istio} provides the mesh. Kiali and {istio} are installed separately, and the console has nothing to show until {istio} is present. {KialiServer} reads {istio} configuration from the {ocp-product-title} API and, when the {istio} API is enabled, from istiod. You can disable communication with istiod by setting `spec.external_services.istio.istio_api_enabled` to `false` in the `Kiali` custom resource. Some proxy-status features are then unavailable.

Prometheus:: Prometheus stores the metrics that {istio} telemetry emits. On {ocp-product-title}, that Prometheus is the in-cluster monitoring stack. {KialiServer} queries Prometheus directly to build the topology, charts, and health. Many console features do not work without those metrics. Keep the default {istio} metrics. You can add aggregations, but do not remove the metrics the console requires.

{ocp-product-title} API:: {KialiServer} uses the {ocp-product-title} API to read namespaces, services, deployments, pods, and the relationships between them. It also reads {istio} objects such as virtual services, destination rules, and gateways from that API.

Tracing:: Tracing is optional. When {TempoName} is configured, the console can show traces for a selected service, workload, or graph edge. Tracing data is available only when distributed tracing is enabled in the mesh.

Grafana:: A Grafana link on the metrics pages is optional. Grafana is not part of the supported {ocp-product-title} or {SMProduct} stack. The console already charts the default {istio} metrics for workloads, applications, and services.
