= Roll back a skip-version upgrade

[role="_abstract"]
If you have issues after a skip-version upgrade, roll back the Istio control plane and workload proxies to the previous version. Revert the `IstioCNI` and `Istio` resources, restart workloads to reconnect to the older control plane, and wait for the newer revision to be removed.

[IMPORTANT]
====
To roll back the Operator itself, uninstall and reinstall it at the previous version.
====

.Prerequisites

* You have cluster-admin credentials for {ocp-product-title}.

* The `istioctl` command-line tool is installed on your local machine.

.Procedure

. Roll back the `IstioCNI` resource to the previous version.

.. Edit the `IstioCNI` resource and set the `spec.version` field to the previous version:
+
[source,terminal]
----
$ oc patch istiocni default -n istio-cni --type=merge -p '{"spec":{"version":"v3.3-latest"}}'
----
+
Replace `v3.3-latest` with the version you are rolling back to.

.. Wait for the `IstioCNI` rollout to complete by running the following command:
+
[source,terminal]
----
$ oc get istiocni default -n istio-cni -w
----
+
Wait until the `READY` column shows `True` and the `VERSION` column shows the previous version.

. Revert the `Istio` control plane to the previous version.

.. Edit the `Istio` resource and set the `spec.version` field to the previous version:
+
[source,terminal]
----
$ oc patch istio default -n istio-system --type=merge -p '{"spec":{"version":"v3.3-latest"}}'
----
+
Replace `v3.3-latest` with the version you are rolling back to.

.. Verify that the older revision becomes the active revision by running the following command:
+
[source,terminal]
----
$ oc get istiorevision -n istio-system
----
+
The output shows the older revision with `IN USE` set to `True`:
+
[source,terminal]
----
NAME           TYPE    READY   STATUS    IN USE   VERSION   AGE
default        Local   True    Healthy   True     v1.28.10   3d
default-v131   Local   True    Healthy   False    v1.31.1   30m
----

. Wait for the `IstioRevisionTag` to point back to the older revision.

.. Monitor the `IstioRevisionTag` resource until it points to the older revision by running the following command:
+
[source,terminal]
----
$ oc get istiorevisiontag default -n istio-system -o jsonpath='{.spec.targetRef.name}'
----
+
The output shows the name of the older revision:
+
[source,terminal]
----
default
----

. Restart workloads to reconnect to the older control plane.

.. Restart all deployments in namespaces that participate in the mesh by running the following command for each namespace:
+
[source,terminal,subs="+quotes"]
----
$ oc rollout restart deployment -n __<namespace>__
----
+
Replace `<namespace>` with the name of each namespace that has the `istio-injection=enabled` or `istio.io/rev=default` label.

.. Verify that all pods are running and use the older proxy version with the following command:
+
[source,terminal]
----
$ istioctl version
----
+
The output shows all proxies running the older `Istio` version:
+
[source,terminal]
----
client version: 1.31.1
control plane version: 1.28.10
data plane version: 1.28.10 (2 proxies)
----

. Wait for the newer revision to be removed.

.. Monitor the `IstioRevision` resources until the newer revision is removed. Run the following command:
+
[source,terminal]
----
$ oc get istiorevision -n istio-system -w
----
+
After the grace period expires, the newer revision is deleted.
The default grace period is controlled by the `inactiveRevisionDeletionGracePeriodSeconds` parameter in the `Istio` resource.

.Verification

* Verify that your applications are functioning correctly with the older Istio version by testing application endpoints and reviewing logs for errors.

* Confirm that only the older `IstioRevision` resource remains by running the following command:
+
[source,terminal]
----
$ oc get istiorevision -n istio-system
----
+
The output shows only the older revision:
+
[source,terminal]
----
NAME      TYPE    READY   STATUS    IN USE   VERSION   AGE
default   Local   True    Healthy   True     v1.28.10   3d
----
