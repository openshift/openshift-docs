== Fixed issues

* Before this update, `node-ca` updated registry CA certificate files in place, so processes reading a certificate during an update could encounter an empty or partially written file. With this update, `node-ca` writes certificates to a temporary file and atomically replaces the destination. As a result, readers no longer observe incomplete certificate updates. (link:https://redhat.atlassian.net/browse/OCPBUGS-63691[OCPBUGS-63691])

* Before this update, when the cloud-event-proxy emitted logs, reading of process logs was blocked, and if `phc2sys` selected the clock instance it synchronizes to during that time, the selection was not logged. As a consequence, the HA profile status metrics were not updated. With this release, log output is monitored during the cloud-event-proxy emit-logs operation. As a result, the HA profile status metrics are updated even if clock selection occurs while the emit-logs operation is underway. (link:https://redhat.atlassian.net/browse/OCPBUGS-104531[OCPBUGS-104531])

* Before this update, the Control Plane Operator could include AWS Local Zone subnets when creating or modifying VPC endpoints for hosted control planes, causing AWS to reject the request and endpoint reconciliation to fail. With this release, when multiple candidate subnets are configured, subnets known to be outside the configured region's standard Availability Zones are excluded before endpoint subnet selection. As a result, endpoint reconciliation can proceed by using eligible standard Availability Zone subnets. (link:https://redhat.atlassian.net/browse/OCPBUGS-132917[OCPBUGS-132917])

* Before this update, the *Impersonate* action was missing from RoleBinding and ClusterRoleBinding details pages when the binding referenced a user or group, even when the action was available in the list view. With this release, the details page uses the first binding subject when no subject index is provided. As a result, authorized users can access the *Impersonate* action from the details page. (link:https://redhat.atlassian.net/browse/OCPBUGS-135131[OCPBUGS-135131])

* Before this update, on a cluster already running version 5.0 with OLMv0 Operators installed that set `olm.maxOpenShiftVersion` to `5.0`, the `Upgradeable=False` message incorrectly claimed that minor version upgrades to 4.23 or major version upgrades to 5.0 were blocked. With this release, the dynamic calculation of the blocked version is restored. As a result, the `Upgradeable=False` message on a 5.0 cluster correctly states that updates from 5.0 to 5.1 are blocked by an Operator that is only compatible through 5.0. (link:https://redhat.atlassian.net/browse/OCPBUGS-135357[OCPBUGS-135357])

* Before this update, after migration to AWS SDK v2, the AWS identity-provider health check used an error-code check that no longer matched credential errors. As a consequence, genuine STS authentication failures were reported as `Unknown`, preventing detection of invalid identity providers. With this release, errors are classified by their underlying AWS error code, distinguishing authentication failures from infrastructure errors, and condition messages are stabilized. As a result, genuine authentication failures report `ValidAWSIdentityProvider=False`, while errors that prevent validation remain `Unknown`. (link:https://redhat.atlassian.net/browse/OCPBUGS-135943[OCPBUGS-135943])

* Before this update, when the hardware configuration restarted a process, `linuxptp-daemon` could attempt to stop the process before the process structure was fully populated. As a consequence, `linuxptp-daemon` could deadlock. With this release, locks were added so that a process cannot be stopped before it has fully started. As a result, processes are closed properly and no longer deadlock `linuxptp-daemon`. (link:https://redhat.atlassian.net/browse/OCPBUGS-138355[OCPBUGS-138355])

* Before this update, the Cluster Autoscaler's Cluster API provider could repeatedly reduce a node group's target size for the same pending Machine, potentially reducing the group to its minimum size. With this update, the provider skips pending Machines already marked for deletion. It also skips stale pending-machine deletion requests for Machines that have since registered as nodes, so that those nodes go through the normal scale-down checks. (link:https://redhat.atlassian.net/browse/OCPBUGS-140545[OCPBUGS-140545])
