[id="ref-dns-group-metrics_{context}"]
= DNS group metrics reference


[role="_abstract"]
The DNS operator exposes Prometheus metrics for monitoring group assignments, active and inactive states, and cleanup activity during DNS failover. These metrics are available when the dns-operator is running and groups are configured.

[id="dns-group-metrics-available_{context}"]
== Available metrics

.DNS group metrics
[%header,cols="2,1,4,2"]
|===
|Metric |Type |Description |Labels

|`dns_record_group_info`
|Gauge
|Reports the group assignment of each `DNSRecord` custom resource (CR). The value is always `1`; the `group` label identifies the assigned group.
|`dns_record_name`, `dns_record_namespace`, `group`

|`dns_record_group_active`
|Gauge
|Reports whether a `DNSRecord` CR belongs to an active group (`1`) or an inactive group (`0`), based on its `Active` status condition. This metric also includes ungrouped records with an empty `group` label. Use the selector `{group!=""}` to exclude ungrouped records.
|`dns_record_name`, `dns_record_namespace`, `group`

|`dns_record_inactive_group_cleanup_total`
|Counter
|Counts cleanup operations that remove DNS records or TXT registry entries belonging to inactive groups. The counter increases each time an active controller performs cleanup for an inactive group.
|`dns_record_name`, `dns_record_namespace`, `group`
|===


[id="dns-group-metrics-queries_{context}"]
== Example PromQL queries

Use the following queries in Prometheus or Grafana to inspect group state and cleanup activity.

.DNS group monitoring queries
[%header,cols="2,3"]
|===
|Purpose |Query

|List all DNSRecords and their group assignments
|`dns_record_group_info`

|Show inactive DNSRecord
|`dns_record_group_active{group!=""} == 0`

|Show active DNSRecords
|`dns_record_group_active{group!=""} == 1`

|Count DNSRecords per group
|`count by (group) (dns_record_group_info)`

|Count active records per group
|`count by (group) (dns_record_group_active{group!=""} == 1)`

|Count inactive records per group
|`count by (group) (dns_record_group_active{group!=""} == 0)`

|Show the average cleanup operations per minute
|`rate(dns_record_inactive_group_cleanup_total[5m]) * 60`

|Identify cleanup counters that increased over the preceding ten minutes
|`increase(dns_record_inactive_group_cleanup_total[10m]) > 0`
|===

[id="dns-group-metrics-alerts_{context}"]
== Example alert for sustained cleanup activity

Sustained cleanup activity may indicate that a group was deactivated unintentionally or an operator is stuck cycling between active and inactive states. Adjust the interval and duration to match your environment:

[source,yaml]
----
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: dns-group-alerts
spec:
  groups:
    - name: dns-groups
      rules:
        - alert: DNSInactiveGroupCleanupSustained
          expr: rate(dns_record_inactive_group_cleanup_total[5m]) > 0
          for: 30m
          labels:
            severity: warning
          annotations:
            summary: "Sustained inactive group cleanup for {{ $labels.dns_record_name }} in group {{ $labels.group }}"
            description: "Continuous cleanup operations for an inactive group over 30 minutes may indicate a misconfigured group or an operator cycling between states."
----
