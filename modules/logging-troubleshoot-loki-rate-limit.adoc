= Troubleshoot ingestion rate limit errors

[role="_abstract"]
Diagnose and resolve situations where LokiStack is discarding logs because the total ingestion rate exceeds the configured global limit.

.Prerequisites

* You have administrator permissions.
* You have installed the OpenShift CLI (`oc`).

.Procedure

. Confirm that ingestion rate limit discards are occurring and identify the affected tenants:
+
[source,terminal]
----
$ oc exec -n openshift-logging -it <distributor_pod> -- sh -c \
  'promtool query instant http://localhost:3100 \
  "sum by (tenant, reason) (rate(loki_discarded_samples_total[2m]))"'
----
+
Alternatively, run the following PromQL in the OpenShift web console under *Observe* -> *Metrics*:
+
[source,promql]
----
sum by (tenant, reason) (rate(loki_discarded_samples_total[2m]))
----
+
A nonzero value with `reason="RateLimit"` confirms ingestion rate limit discards.

. Check distributor pod logs for ingestion rate limit errors:
+
[source,terminal]
----
$ ns="openshift-logging"
$ pod=$(oc -n ${ns} get pod -l app.kubernetes.io/component=distributor \
    -o jsonpath='{.items[0].metadata.name}')
$ oc -n ${ns} logs ${pod} | grep "ingestion rate limit exceeded" | tail -5
----

. Identify which tenants the rate limit affects:
+
[source,terminal]
----
$ oc -n ${ns} logs ${pod} | grep "ingestion rate limit exceeded" | grep -c "org_id=application"
$ oc -n ${ns} logs ${pod} | grep "ingestion rate limit exceeded" | grep -c "org_id=infrastructure"
$ oc -n ${ns} logs ${pod} | grep "ingestion rate limit exceeded" | grep -c "org_id=audit"
----

. Determine whether the rate limiting is temporary or persistent.
+
Expect rate limiting in the following situations, which are temporary and require no action:
+
--
* The collector starts for the first time and reads all available logs.
* The collector recovers after an incident and processes a backlog.
* A sporadic log spike occurs, such as during a cluster upgrade.
--
+
Monitor the discards over time. If the rate decreases and reaches zero, you do not need to change the configuration.

. If rate limiting is persistent, choose one or both of the following actions:

.. *Reduce log volume and size:* Review which workloads are generating the most log data and apply filters or reduce log verbosity. This is always the recommended first step.

.. *Increase the ingestion rate limit:* First, measure the actual ingestion rate to determine an appropriate limit value:
+
[source,promql]
----
sum by (tenant) (rate(loki_distributor_bytes_received_total[5m]))
----
+
Use the baseline value from this query as a reference for setting `ingestionRate`. Then update the `LokiStack` custom resource with the new values. For the configuration steps, see "Configure LokiStack ingestion limits".
