= Troubleshooting permission failures

[role="_abstract"]
If an Operator installation fails due to a lack of permissions, identify which specific permissions are missing.

include::snippets/olmv0-failed-install-cluster-role-bindings.adoc[]

.Procedure

. Review the `status.installPlanRef` field of the `Subscription` object to identify the `InstallPlan` that failed:
+
[source,yaml]
----
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: etcd
  namespace: example-operators
status:
  installPlanRef:
    apiVersion: operators.coreos.com/v1alpha1
    kind: InstallPlan
    name: install-4plp8
    namespace: example-operators
    resourceVersion: "117359"
    uid: 2c1df80e-afea-11e9-bce3-5254009c9c23
----

. Check the status of the `InstallPlan` object for any errors:
+
[source,yaml]
----
apiVersion: operators.coreos.com/v1alpha1
kind: InstallPlan
status:
  conditions:
  - lastTransitionTime: "2019-07-26T21:13:10Z"
    lastUpdateTime: "2019-07-26T21:13:10Z"
    message: 'error creating clusterrole etcdoperator.v0.9.4-clusterwide-dsfx4: clusterroles.rbac.authorization.k8s.io
      is forbidden: User "system:serviceaccount:example-operators:example-installer" cannot create resource
      "clusterroles" in API group "rbac.authorization.k8s.io" at the cluster scope'
    reason: InstallComponentFailed
    status: "False"
    type: Installed
  phase: Failed
----

. Use the error message to identify the following information:
+
* The resource type and API group. In this example, the error identifies `clusterroles` in the `rbac.authorization.k8s.io` API group.
* The resource name.
* The authorization result.
* The user or service account that attempted the operation.
* The scope of the operation.

. If the status does not report every missing permission, resolve the reported error and check the status again.

. Inspect the Operator service account for active role bindings and cluster role bindings.

. Delete the remaining role bindings and cluster role bindings created by the failed installation.

. After you delete a binding, verify that OLM did not re-create it. For more information, see _Failed Operator installation cleanup_.

. Before you retry the installation, review the missing permission.

. Grant the missing permission to the installation service account only if you intend to delegate that permission to the Operator.
