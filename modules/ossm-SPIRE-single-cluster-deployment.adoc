= Single cluster SPIRE deployment

[role="_abstract"]

A single cluster SPIRE deployment provides zero-trust workload identity for applications running on one {ocp-short-name} cluster.
This deployment topology is simpler to configure and manage compared to federated deployments.
It is suitable for environments where all workloads operate within a single cluster boundary.

== Deployment overview

To deploy SPIRE on a single cluster, you complete four high-level steps:

. Install the Zero Trust Workload Identity Manager (ZTWIM) Operator and deploy the SPIRE components (server, agent, CSI driver, and OIDC discovery provider).
. Integrate the {istio} control plane with SPIRE by configuring the {istio} CR to use SPIFFE identities instead of default {istio} certificates.
. Secure traffic within the mesh by deploying test applications and enforcing strict mTLS authentication between workloads.
. Secure traffic entering the mesh by deploying an ingress gateway that obtains SPIFFE identities from SPIRE for mTLS connections to backend services.

== When to use single cluster deployment

Use a single cluster SPIRE deployment when:

* All your workloads run on the same {ocp-short-name} cluster.
* You do not need to establish trust relationships across many clusters.
* You want to implement zero-trust security without the complexity of federation.

For multi-cluster environments where workloads need to communicate across cluster boundaries, use a federated SPIRE deployment instead.
Federated deployments enable workloads on different clusters to verify each other's SPIFFE identities through established trust relationships between SPIRE servers.
