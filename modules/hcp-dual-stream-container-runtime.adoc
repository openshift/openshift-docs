= Container runtime compatibility for {op-system-base} 10 node pools

[role="_abstract"]
Before you migrate workloads to a {op-system-base} 10 `NodePool` resource, verify that no `ContainerRuntimeConfig` resources in the cluster specify `defaultRuntime: runc` for the workloads you intend to migrate.

Workloads that depend on `runc` must remain on {op-system-base} 9 `NodePool` resources and cannot be migrated to {op-system-base} 10.

.Container runtime availability by {op-system} stream
[cols="2,^1,^1", options="header"]
|===
|Container runtime
|{op-system-base} 9 `NodePool` resources
|{op-system-base} 10 `NodePool` resources

|`crun`
|Yes
|Yes

|`runc`
|Yes
|No

|===

If a `NodePool` resource uses a `ContainerRuntimeConfig` resource with `defaultRuntime: runc`, the controller behavior depends on the `spec.osImageStream` setting:

* When `spec.osImageStream` is not set, the controller detects the `runc` requirement and automatically selects `rhel-9` instead of the version-derived default. This fallback applies even on {product-title} 5.0 and later, where the version-derived default would otherwise be `rhel-10`.

* When `spec.osImageStream.name` is set to `rhel-10`, the controller cannot satisfy the `runc` requirement on an {op-system-base} 10 `NodePool` resource. The controller sets the `ValidMachineConfig=False` condition on the `NodePool` resource. The node configuration is not applied until the conflict is resolved.

On a `NodePool` resource that has `spec.osImageStream.name: rhel-10` set, if you see `ValidMachineConfig=False`, take the following steps:

. Identify the `ContainerRuntimeConfig` resources in the cluster by entering the following command:
+
[source,terminal]
----
$ oc get containerruntimeconfig
----

. Review each `ContainerRuntimeConfig` for `defaultRuntime: runc` settings by entering the following command:
+
[source,terminal]
----
$ oc get containerruntimeconfig <config_name> -o yaml
----

. Either remove the `ContainerRuntimeConfig` that specifies `runc`, or move the workloads that require `runc` to a {op-system-base} 9 `NodePool` resource.
