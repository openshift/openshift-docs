= Install the {product-title-short} Operator on other platforms

[role="_abstract"]
You can install the {product-title-short} Operator on non-OpenShift Kubernetes clusters by using the `rhacs-operator` Helm chart.
After the Operator is running, create `Central` and `SecuredCluster` custom resources to deploy {product-title-short} components.

.Prerequisites

* You have Helm version 3.x installed. Migrating a legacy installation requires version 3.18 or later. Users migrating with version 4.x might experience problems.
* You have `kubectl` installed and configured with cluster administrator access to the target Kubernetes cluster.
* You have access to `registry.redhat.io`, or you have mirrored the Operator image to an internal registry.

.Procedure

. Create a namespace for the Operator. `rhacs-operator-system` is recommended:
+
[source,terminal]
----
$ kubectl create namespace rhacs-operator-system
----
. Optional: Depending on where you are deploying the image from, create an image pull secret:
* If you are not deploying from the Red Hat image registry, you do not need an image pull secret. You can omit the following steps for generating a token and applying the secret.
* If you are deploying directly from the Red Hat image registry, you must have one of the following:
** A cluster-wide image pull secret
** An image pull secret for the {product-title-short} application component images such as Central, Scanner, and Sensor for each namespace in which you deploy {product-title-short}. 
.. Generate a registry service account access token by using the Red Hat Customer Portal. For instructions, see "Creating Registry Service Accounts".
.. After you have generated the token, go to the *OpenShift Secret* tab on your *Token Information* page and download a secret suitable for use on Kubernetes clusters. 
.. Apply the secret in the namespace you just created, for example, `rhacs-operator-system`:
+
[source,terminal]
----
$ kubectl apply -f <path-to-secret/pull-secret.yaml> -n rhacs-operator
----
. Add the {product-title-short} Helm chart repository, if it has not been added yet:
+
[source,terminal]
----
$ helm repo add rhacs https://mirror.openshift.com/pub/rhacs/charts/
----
+
If you previously added the repository, update the local cache:
+
[source,terminal]
----
$ helm repo update rhacs
----
. Install the `rhacs-operator` Helm chart:
+
[source,terminal,subs="+quotes"]
----
$ helm install --wait -n rhacs-operator-system rhacs-operator rhacs/rhacs-operator --set 'manager.imagePullSecrets[0].name=_<pull_secret_name>_'
----
+
where <pull_secret_name> is the value of the `metadata.name` of the image pull secret you applied in the previous step. If you have a cluster-wide image pull secret and do not need to specify a pull secret, you can omit the `--set manager.imagePullSecrets` option. The `manager.imagePullSecrets` value configures the image pull secret for the Operator pod itself. This is different from the `spec.imagePullSecrets` field in `Central` or `SecuredCluster` custom resources, which configures image pull secrets for {product-title-short} application component images such as Central, Scanner, and Sensor.
+
. Optional: If you are installing the Operator on a cluster where {product-title-short} was previously installed by using a legacy installation method, add `--take-ownership` after `helm install` to avoid conflicts with existing `SecurityPolicies` custom resource definition (CRD). 
. Optional: If you are using Helm version 4, you might additionally need to add `--force-conflicts` in addition to `--take-ownership` to avoid errors such as the one shown in the following example output.
+
.Example output
[source,terminal]

----
Error: INSTALLATION FAILED: conflict occurred while applying object /securitypolicies.config.stackrox.io apiextensions.k8s.io/v1, Kind=CustomResourceDefinition: Apply failed with 2 conflicts: conflicts with "kubectl-client-side-apply" using apiextensions.k8s.io/v1:
- .metadata.annotations.controller-gen.kubebuilder.io/version
- .spec.versions
----

.Verification

* Verify that the Operator pod is running:
+
[source,terminal]
----
$ kubectl get pods -n rhacs-operator
----
+
.Example output
[source,terminal]
----
NAME                                         READY   STATUS    RESTARTS   AGE
rhacs-operator-controller-manager-<hash>     1/1     Running   0          60s
----
