= Troubleshoot HTTPRoute attachments using status conditions

[role="_abstract"]
When an `HTTPRoute` custom resource (CR) is not routing traffic as expected, you can review its `status` conditions to diagnose attachment failures, unresolved backend references, or partially invalid rules. The controller reports these conditions for each parent gateway that accepted or rejected the route.

.Procedure

. Check the `status` conditions of your `HTTPRoute` CR by running the following command:
+
[source,terminal]
----
$ oc describe httproute <httproute_name> -n <namespace>
----
+
* `<httproute_name>`: Specify the name of your HTTPRoute.
* `<namespace>`: Specify the namespace where the HTTPRoute resides.
+
If the `status.parents` list is empty, the controller has not attached the route to any gateway. Confirm that the `spec.parentRefs` target exists, that the listener allows routes from this namespace, and that the listener hostname intersects with the HTTPRoute hostnames.

. Optional: Query a specific condition without parsing the full resource by running the following command:
+
[source,terminal]
----
$ oc get httproute <httproute_name> -n <namespace> -o jsonpath='{.status.parents[*].conditions[?(@.type=="Accepted")].status}'
----
+
A value of `True` means the parent gateway accepted the route. No output means the controller has not populated parent status yet, which can occur when the parent does not exist or the controller cannot see the route.
+
For details on how to interpret the output and resolve common errors, see xref:httproute-status-conditions_{context}[].
