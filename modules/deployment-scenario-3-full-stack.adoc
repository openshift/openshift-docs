= Scenario 3: Vector + Loki + COO (full stack)

*Choose this scenario if:*

* You want to query logs directly in the OpenShift web console
* You need to correlate logs with metrics and distributed traces
* You manage a multi-tenant cluster with namespace-scoped observability needs
* You prefer browser-based visualization over external dashboards
* You want incident detection with automatic alert grouping

*What you need to plan:*

* Everything from Scenario 2 (object storage, Loki sizing, cluster resources)
* Console UI plugin resources (additional CPU and memory for plugin pods)
* Multi-tenant monitoring stacks (if providing per-namespace observability)
* Korrel8r configuration for signal correlation
* Network policies for UI plugin access
* User permissions for namespace-scoped log queries

*Resource requirements:*

* *Vector + Loki*: Same as Scenario 2
* *COO UI plugins*: Additional ~500m CPU, ~512 MiB memory for console plugins
* *Korrel8r*: ~200m CPU, ~256 MiB memory
* *Per-namespace monitoring stacks* (optional): ~1 vCPU, ~2 GiB memory per stack

*Total for medium deployment*: ~40 vCPUs, ~75 GiB memory (before multi-tenant stacks)

*Estimated installation time:* 2-4 hours (includes all three operators and UI setup)

*Go to these planning topics:*

* xref:../plan/plan-your-logging-installation.adoc#plan-your-logging-installation[Plan your logging installation]
* xref:../plan/choose-lokistack-storage-backend.adoc#choose-lokistack-storage-backend[Choose a LokiStack storage backend]
* xref:../plan/size-your-lokistack-deployment.adoc#size-your-lokistack-deployment[Size your LokiStack deployment]

[NOTE]
====
Both storage backend selection and LokiStack sizing are required for Scenario 3.
