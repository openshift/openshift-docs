= Hardening {op-system-base} hosts and verifying CIS Level 2 compliance

[role="_abstract"]
Harden a {op-system-base} host with the Red{nbsp}Hat Official CIS (Center for Internet Security) Ansible roles, apply the overrides that {microshift-short} requires for IP forwarding, and verify compliance with OpenSCAP.

.Prerequisites

* You have a {op-system-base} {op-system-version-major} or {op-system-base} {op-system-version-major-10} host on `x86_64` or `aarch64`.
* You have root or `sudo` privileges on the host.
* You can install Ansible and the Red Hat Official CIS role for your {op-system-base} major version.
* You can install the `openscap-scanner` and `scap-security-guide` packages.

.Procedure

. Install Ansible and obtain the CIS hardening role for your {op-system-base} major version by running the following commands:
+
[source,terminal,subs="+quotes"]
----
$ sudo dnf install ansible-core -y
$ ansible-galaxy RedHatOfficial.rhel${_<MAJOR_VERSION>_}_cis
$ ansible-galaxy collection install community.general:<10.0.0 ansible.posix
----
+
Replace _<MAJOR_VERSION>_ with the major version of the target operating system.
+
. Create one of the following playbooks that apply CIS Level 2 hardening and override the IP forwarding variables so that the role does not disable forwarding before {microshift-short} starts.
+
.Example playbook for {op-system-base} {op-system-version-major}
[source,yaml]
----
---
- name: Apply CIS Level 2 hardening
  hosts: localhost
  connection: local
  become: true
  roles:
    - role: RedHatOfficial.rhel9_cis
      vars:
        sysctl_net_ipv4_ip_forward: false
        sysctl_net_ipv6_conf_all_forwarding: false
----
+
.Example playbook for {op-system-base} {op-system-version-major-10}
[source,yaml]
----
---
- name: Apply CIS Level 2 hardening
  hosts: localhost
  connection: local
  become: true
  roles:
    - role: RedHatOfficial.rhel10_cis
      vars:
        sysctl_net_ipv4_ip_forward: false
        sysctl_net_ipv4_conf_all_forwarding: false
        sysctl_net_ipv4_conf_default_forwarding: false
        sysctl_net_ipv6_conf_all_forwarding: false
        sysctl_net_ipv6_conf_default_forwarding: false
----
+
Setting each variable to `false` tells the role not to disable forwarding. The setting does not enable forwarding. {microshift-short} enables IP forwarding at startup.

. Validate the playbook definition before executing the playbook by entering the following command:
+
[source,terminal, subs="+quotes"]
----
$ ansible-playbook --check _<path_to_playbook>_.yml
----
+
Replace _<path_to_playbook>_ with the playbook file path.
+
. Harden the system by running the playbook that you created for your {op-system-base} major version against the host by entering the following command:
+
[source,terminal,subs="+quotes"]
----
$ ansible-playbook _<path_to_playbook>_.yml
----
+
Replace _<path_to_playbook>_ with the playbook file path.
+
. Install OpenSCAP scanner packages by entering the following command:
+
[source,terminal]
----
$ sudo dnf install -y openscap-scanner scap-security-guide
----

. Evaluate the host against the CIS profile by entering one of the following commands for your target operating system.
+
* If your target operating system is {op-system-base} {op-system-version-major}, enter the following command:
+
[source,terminal]
----
$ sudo oscap xccdf eval \
  --profile xccdf_org.ssgproject.content_profile_cis \
  --results /tmp/cis-results.xml \
  --report /tmp/cis-report.html \
  /usr/share/xml/scap/ssg/content/ssg-rhel9-ds.xml
----
+
* If your target operating system is {op-system-base} {op-system-version-major-10}, enter the following command:
+
[source,terminal]
----
$ sudo oscap xccdf eval \
  --profile xccdf_org.ssgproject.content_profile_cis \
  --results /tmp/cis-results.xml \
  --report /tmp/cis-report.html \
  /usr/share/xml/scap/ssg/content/ssg-rhel10-ds.xml
----
+
. Review `/tmp/cis-report.html` and remediate unexpected failures before you install {microshift-short}.

.Verification

* The OpenSCAP report uses the `xccdf_org.ssgproject.content_profile_cis` profile.
* Remaining failures match only rules that you expect to address after {microshift-short} installation, or that are documented as unavoidable for container platforms.
