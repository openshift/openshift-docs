= Removing a cluster from a nested SPIRE topology

[role="_abstract"]
Remove nested SPIRE from a downstream cluster and delete that cluster's registration from the upstream cluster. {zero-trust-full} deletes the upstream agent, the upstream CSI driver, and the registration entries that it created for the link.

.Prerequisites

* You have `cluster-admin` permissions on the upstream cluster and the downstream cluster.
* The `UPSTREAM_KUBECONFIG` and `DOWNSTREAM_KUBECONFIG` environment variables are set.

.Procedure

. On the downstream cluster, remove the SPIRE UpstreamAuthority configuration by running the following command:
+
[source,terminal]
----
$ oc patch spireserver cluster --type=json --kubeconfig="${DOWNSTREAM_KUBECONFIG}" -p '[{"op":"remove","path":"/spec/upstreamAuthority"}]'
----
+
{zero-trust-full} deletes the downstream resources it created for nested SPIRE, including `deployment/spire-agent-upstream` and `daemonset/spire-spiffe-csi-driver-upstream`.
+
Existing workload SVIDs remain valid until they expire. After the current intermediate CA expires, the downstream server signs new SVIDs with a self-signed CA. Re-enabling `spec.upstreamAuthority.spire` recreates the nested SPIRE resources. SPIRE joins the shared CA chain again on the next CA rotation.

. On the upstream cluster, delete the matching `downstreamClusters` entry. If this is the only downstream cluster, remove the nested SPIRE configuration by running the following command:
+
[source,terminal]
----
$ oc patch spireserver cluster --type=json --kubeconfig="${UPSTREAM_KUBECONFIG}" -p '[{"op":"remove","path":"/spec/nestedSpire"}]'
----
+
If other downstream clusters remain, edit the CR and delete only the entry for the cluster you are removing:
+
[source,terminal]
----
$ oc edit spireserver cluster --kubeconfig="${UPSTREAM_KUBECONFIG}"
----
+
Removing an entry deletes the `ClusterStaticEntry` objects for that downstream cluster and restarts the upstream SPIRE server. The remaining downstream servers keep their cached intermediate CAs.

. Optional: if no remaining downstream cluster uses the gRPC endpoint, remove it by running the following command:
+
[source,terminal]
----
$ oc patch spireserver cluster --type=json --kubeconfig="${UPSTREAM_KUBECONFIG}" -p '[{"op":"remove","path":"/spec/grpcEndpoint"}]'
----
+
{zero-trust-full} deletes the managed `spire-server-grpc` Route.

.Verification

. Confirm that the upstream agent is gone from the downstream cluster by running the following command:
+
[source,terminal]
----
$ oc get deployment spire-agent-upstream -n zero-trust-workload-identity-manager --kubeconfig="${DOWNSTREAM_KUBECONFIG}"
----
+
The command reports that the deployment is not found.

. Confirm that the upstream registration entry for that cluster is gone by running the following command:
+
[source,terminal]
----
$ oc get clusterstaticentries.spire.spiffe.io --kubeconfig="${UPSTREAM_KUBECONFIG}"
----
+
The list does not include `nested-spire-<downstream_cluster_name>-downstream` or `nested-spire-<downstream_cluster_name>-node-alias`.
