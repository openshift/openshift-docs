= Fine-grained permissions

[role="_abstract"]
Operator Lifecycle Manager (OLM) uses the permissions granted to the service account specified in the Operator group to manage resources during Operator installation and upgrades.

OLM uses this service account except when creating `APIService` and `CustomResourceDefinition` resources, which OLM creates with `cluster-admin` privileges. Selecting a target namespace does not restrict the permissions granted to the Operator to the selected namespace.

Depending on the Operator, OLM might need permissions to manage the following resources:

* `ClusterServiceVersion`
* `Subscription`
* `Secret`
* `ServiceAccount`
* `Service`
* `ClusterRole` and `ClusterRoleBinding`
* `Role` and `RoleBinding`

[NOTE]
====
The following role configuration is a generic example. Review the permissions required to install the Operator. Grant only the permissions that you intend to delegate.
====

[source,yaml]
----
kind: Role
rules:
- apiGroups: ["operators.coreos.com"]
  resources: ["subscriptions", "clusterserviceversions"]
  verbs: ["get", "create", "update", "patch"]
- apiGroups: [""]
  resources: ["services", "serviceaccounts"]
  verbs: ["get", "create", "update", "patch"]
- apiGroups: ["rbac.authorization.k8s.io"]
  resources: ["roles", "rolebindings"]
  verbs: ["get", "create", "update", "patch"]
- apiGroups: ["apps"]
  resources: ["deployments"]
  verbs: ["list", "watch", "get", "create", "update", "patch", "delete"]
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["list", "watch", "get", "create", "update", "patch", "delete"]
----

In the following fields, specify the API groups, resources, and permitted actions:

* `rules.apiGroups`: Specify `apps` for deployments and `""` for pods in the core API group.
* `rules.resources`: Specify `deployments` or `pods` for the corresponding API group.
* `rules.verbs`: Specify the permitted actions, such as `create`.

Some installations require OLM to copy a pull secret from the OLM namespace. For these installations, the service account specified in the Operator group needs the following permissions:

`get`:: Allows the service account to retrieve the pull secret from the OLM namespace.
`create`:: Allows the service account to create a copy in the Operator installation namespace.

The following example grants these permissions to a service account named `example-installer` in a namespace named `example-operators`. The source role limits read access to the named pull secret. Each role binding grants the corresponding permissions to that service account.

[WARNING]
====
Before granting permission to create secrets in the Operator installation namespace, review the following limits and risks:

* Kubernetes RBAC permits secret creation with any name in the namespace. The `resourceNames` field cannot restrict creation to the pull-secret name.
* Permission to create and retrieve service account token secrets can provide access as other service accounts in the namespace. The resulting access depends on the permissions granted to those accounts and can extend across the cluster.
* Review permissions to read secrets, create service account tokens, and create workloads together with the permissions granted to service accounts in the namespace. Grant only the access that you intend to delegate.
====

.Example roles and role bindings for copying a pull secret
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: example-pull-secret-reader
  namespace: <olm_namespace>
rules:
- apiGroups: [""]
  resources: ["secrets"]
  resourceNames: ["<pull_secret_name>"]
  verbs: ["get"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: example-pull-secret-reader
  namespace: <olm_namespace>
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: example-pull-secret-reader
subjects:
- kind: ServiceAccount
  name: example-installer
  namespace: example-operators
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: example-pull-secret-writer
  namespace: example-operators
rules:
- apiGroups: [""]
  resources: ["secrets"]
  verbs: ["create"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: example-pull-secret-writer
  namespace: example-operators
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: example-pull-secret-writer
subjects:
- kind: ServiceAccount
  name: example-installer
  namespace: example-operators
----
where:

`<olm_namespace>`:: Specifies the namespace from which OLM retrieves the pull secret.
`<pull_secret_name>`:: Specifies the name of the pull secret that OLM copies.
