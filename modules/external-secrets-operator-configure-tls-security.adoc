= Configure the Transport Layer Security profile

[role="_abstract"]
Align secure connections with your cluster policy by configuring the Transport Layer Security (TLS) profile for the {external-secrets-operator}. Enable `StrictAllComponents` adherence in the `APIServer` custom resource (CR).

.Prerequisites

* You have access to the cluster with `cluster-admin` privileges.
* You have installed the {oc-first}.
* You have installed `jq`.
* You have installed the {external-secrets-operator}.

.Procedure

. Edit the cluster `APIServer` CR by running the following command:
+
[source,terminal]
----
$ oc edit apiserver cluster
----

. Set the `spec.tlsSecurityProfile` field to the profile you require.
+
The profile can be `Old`, `Intermediate`, `Modern`, or `Custom`. If you omit this field, the platform default is `Intermediate`.

. Set the `spec.tlsAdherence` field to `StrictAllComponents` to apply the cluster TLS security profile to the {external-secrets-operator-short} and the operands. The following example shows the resulting configuration with the `Intermediate` profile and cluster-wide adherence:
+
[source,yaml]
----
apiVersion: config.openshift.io/v1
kind: APIServer
metadata:
  name: cluster
spec:
  tlsSecurityProfile:
    type: Intermediate
    intermediate: {}
  tlsAdherence: StrictAllComponents
----
+
where:

`spec.tlsAdherence`:: If you omit this field or select `LegacyAdheringComponentsOnly`, the {external-secrets-operator-short} and the operands use the default TLS settings.

. Save your changes.

. Exit the editor.

.Verification

. Verify the TLS security profile on the `APIServer` CR by running the following command:
+
[source,terminal]
----
$ oc get apiserver cluster -o jsonpath='{.spec.tlsSecurityProfile}' | jq .
----

. Verify that the {external-secrets-operator-short} pod logged that the cluster TLS profile is in use by running the following command:
+
[source,terminal]
----
$ oc logs -n external-secrets-operator deploy/external-secrets-operator-controller-manager -c manager | grep -i 'cluster TLS'
----

. Verify that the `external-secrets` operand `Deployment` includes the TLS arguments by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="external-secrets")].args}'
----
+
The output includes the `--tls-min-version` argument. If the profile sets a minimum TLS version below 1.3, the output also includes the `--tls-ciphers` argument. The `Modern` profile uses TLS 1.3, so the output omits `--tls-ciphers`.

. Optional: Check the webhook `Deployment` by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets-webhook -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="webhook")].args}'
----
