= Setting up backup and restore for {hcp} on {azure-short}

[role="_abstract"]
Set up your {hcp} on {azure-short} environment to run automated backups.

{oadp-first} 1.6 with the built-in `hypershift` plugin is the supported backup and restore solution for {hcp} on {azure-short}. The `hypershift` plugin is included in {oadp-short} 1.6 by default and does not require a custom plugin image.

The plugin supports two backup modes:

Volume snapshot backup:: Captures persistent volume data by using CSI snapshots. This mode backs up etcd storage volumes and does not require the `HCPEtcdBackup` feature gate. For volume snapshot backup procedures, see "Automated disaster recovery for {hcp} on {azure-short}".

etcd snapshot backup:: Captures a point-in-time etcd snapshot and stores the snapshot URL in the `HostedCluster.status.lastSuccessfulEtcdBackupURL` specification. The {oadp-short} plugin injects this URL automatically at restore time. This mode requires the `HCPEtcdBackup` feature gate and is available as a Technology Preview feature.

.Prerequisites

* You installed {oadp-short} 1.6 on the management cluster. For more information, see xref:../../backup_and_restore/application_backup_and_restore/installing/installing-oadp-azure.adoc#installing-oadp-azure[Configuring {oadp-short} with {azure-short}].
* You created an Azure Blob Storage account and container that are accessible from the management cluster.
* You have a Kubernetes secret containing the Azure credentials. For more information, see step 1 in xref:../../hosted_control_planes/hcp-deploy/hcp-deploy-azure.adoc#hcp-azure-automated-dr-setup_hcp-deploy-azure[Setting up automated disaster recovery for {hcp} on {azure-short}].

.Procedure

* To configure automated backups, enter the `hcp create oadp-schedule` command. The following example shows how to schedule daily backups.
+
[source,terminal]
----
$ hcp create oadp-schedule \
  --hc-name <hosted_cluster_name> \
  --hc-namespace <hosted_cluster_namespace> \
  --storage-location azure-blob \
  --schedule "0 2 * * *"
----
+
where:
+
`<hosted_cluster_name>`:: Specifies the name of the `HostedCluster` resource to back up.
`<hosted_cluster_namespace>`:: Specifies the namespace of the `HostedCluster` resource.

.Verification

. Check the status of the most recent Velero backup by entering the following command:
+
[source,terminal]
----
$ oc get backups.velero.io -n openshift-adp -o wide
----

. Inspect Velero logs for errors by entering the following command:
+
[source,terminal]
----
$ oc logs -n openshift-adp deployment/velero
----

. Verify that the `HostedCluster` resource status reports a successful etcd backup URL by entering the following command:
+
[source,terminal]
----
$ oc get hostedcluster <hosted_cluster_name> -n <hosted_cluster_namespace> \
  -o jsonpath='{.status.lastSuccessfulEtcdBackupURL}'
----
+
A non-empty URL confirms that the etcd snapshot was captured and stored successfully.
