= OVN-Kubernetes and CNI diagnostics toolsets

[role="_abstract"]
The MCP server for Red Hat OpenShift can expose optional toolsets that group related tools, resources, and prompts for OVN-Kubernetes and CNI troubleshooting.

Toolsets extend the default `core` toolset, which provides Kubernetes primitives such as `pods_list` and `pods_exec`. Enable toolsets in the MCP server `config.toml` file after you install the server.

[id="ai-app-mcp-server-ovn-kubernetes-cni-toolsets-about-ovn-kubernetes_{context}"]
== OVN-Kubernetes toolset

The `ovn-kubernetes` toolset provides read-only tools for inspecting OVN-Kubernetes clusters across two layers:

* *OVN layer*: Query OVN Northbound and Southbound databases, list logical flows, and trace packets through the logical network. Tools include `ovn_show`, `ovn_get`, `ovn_lflow_list`, and `ovn_trace`.
* *OVS layer*: Inspect Open vSwitch configuration, OpenFlow tables, and data path state. Tools include `ovs_vsctl`, `ovs_ofctl`, and `ovs_appctl`.

These tools execute OVN and OVS commands inside `ovnkube-node` pods by using `pods/exec`. They do not modify OVN or OVS state.

[id="ai-app-mcp-server-ovn-kubernetes-cni-toolsets-about-cni-diagnostics_{context}"]
== CNI diagnostics toolset

The `cni-diagnostics` toolset provides kernel-level and packet-level networking diagnostics:

* *Kernel tools*: `get-conntrack`, `get-iptables`, `get-nft`, and `get-ip` run in privileged debug pods on nodes.
* *Network tools*: `tcpdump` captures packets on nodes or inside pod network namespaces; `pwru` performs eBPF-based kernel packet tracing.

Use the CNI diagnostics toolset together with the `ovn-kubernetes` toolset when you need both logical OVN/OVS inspection and kernel-level or packet-level evidence.
