= Choosing a provider pathway for vLLM

[role="_abstract"]
When you serve a model with vLLM, you can connect {ols-long} through either the OpenAI-compatible pathway or the Anthropic-compatible pathway. For agentic and tool-calling workloads, use the Anthropic provider pathway.

.vLLM provider pathway comparison
[cols="1,1,1", options="header"]
|===
| Provider pathway | Endpoint | Recommended use

| Anthropic
| `/v1/messages`
| Agentic and tool-calling workloads, for example, integrations that use the Gemma series of models. Preserves tool calls and structured outputs.

| OpenAI-compatible
| `/v1/chat/completions`
| General chat completion workloads that do not depend on reliable tool calling.
|===

[IMPORTANT]
====
When you use the OpenAI provider pathway with vLLM for tool-calling tasks, the `response_format` handling on OpenAI-compatible endpoints can suppress tool calls. This behavior causes structured output failures for agentic workflows. To avoid this issue, use the Anthropic provider pathway and the `/v1/messages` endpoint. Selecting this pathway lets {ols-long} apply its own two-pass mechanism, which preserves tool calls. The two-pass mechanism is implemented in {ols-long}, not in the vLLM endpoint, so the `/v1/messages` endpoint on its own does not resolve tool call suppression.
====
