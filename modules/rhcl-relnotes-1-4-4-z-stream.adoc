== Bug fixes

* Before this update, gateways did not detect unresponsive authorization or rate-limiting pods during restarts or rolling updates. As a result, applications using `AuthPolicy` or `RateLimitPolicy` custom resources (CRs) returned `500` or `503` errors during routine cluster maintenance. With this update, active health checking is added for authorization and rate-limiting connections and Authorino load is distributed evenly across all healthy replicas. Now, `AuthPolicy` and `RateLimitPolicy` CRs remain available during pod restarts and scaling events. (link:https://redhat.atlassian.net/browse/CONNLINK-1732[CONNLINK-1732])

* Before this update, Authorino used fixed resource names that conflicted across namespaces. As a result, deploying independent Authorino instances in more than one namespace on the same cluster failed. With this update, resource names are scoped per namespace. Now, you can deploy Authorino independently in multiple namespaces on a single cluster.

* Before this update, credentials containing special characters in query strings were not decoded correctly before validation, and Open Policy Agent (OPA) policy bundles could stall during download. As a result, affected API clients received unexpected `401 Unauthorized` errors and external policies failed to sync reliably. With this update, query string decoding and OPA context propagation are corrected. Now, credentials with special characters authenticate correctly and external OPA policies remain consistently enforced.

* Before this update, deleting or modifying a `DNSPolicy` object in one namespace could remove DNS records shared with applications in other namespaces. As a result, live applications experienced unexpected DNS outages. With this update, shared DNS targets are retained during policy cleanup. Now, DNS resolution for applications is not affected when a `DNSPolicy` object in a neighboring namespace is updated or deleted.

* Before this update, certain failures in CEL expressions could block further processing by the WASM filter. Rather than proceeding to evaluate the request outcome, the WASM filter stalled during execution and held the HTTP/gRPC connection open. API clients could experience hung connections, timeouts, and resource exhaustion when requests encountered specific CEL evaluation errors. With this release, failure handling is fixed and the filter can proceed and determine the appropriate outcome for the request according to its configuration. Tasks with non-terminal errors no longer block filter evaluation. API requests complete predictably without hanging or timing out and the WASM filter can to process the request and apply the intended authorization and routing logic.
