= RHSA-2026:94538 - {product-title} {product-version}.1 bug fix and security update

Issued: 5 November 2026

[role="_abstract"]

The list of fixed bugs and enhancements that are included in the update is documented in the link:https://access.redhat.com/errata/RHSA-2026:94538[RHSA-2026:94538] advisory. The RPM packages that are included in the update are provided by the link:https://access.redhat.com/errata/RHBA-2026:94536[RHBA-2026:94536] advisory.

== Fixed issues

* Before this update, when generating the Agent-based Installer minimal ISO from the full {op-system-first} ISO, metadata about the modified kernel arguments was not updated. As a consequence, users could not use the `coreos-installer iso kargs` commands to view or manipulate the kernel arguments. With this release, the metadata is updated so that each copy of the kernel arguments in the ISO is consistent. As a result, `coreos-installer` do not treat the kernel arguments as corrupted. (link:https://redhat.atlassian.net/browse/OCPBUGS-43501[OCPBUGS-43501])

* Before this update, selecting *Create MachineAutoscaler* from a `MachineSet` details page in the web console displayed a blank page instead of the creation dialog. With this release, the *Create MachineAutoscaler* dialog opens correctly from the `MachineSet` details page. As a result, you can create a `MachineAutoscaler` from the `MachineSet` details page as expected. (link:https://redhat.atlassian.net/browse/OCPBUGS-86294[OCPBUGS-86294])

* Before this update, the `oc-oidc` exec plugin did not include extra scopes in its token cache key. As a consequence, changing the `--extra-scopes` parameter could return a cached token that lacked claims associated with the newly requested scopes. With this release, the extra scopes are included in the cache key and sorted for deterministic cache lookup. As a result, different requested scope sets use separate cache entries, while changing only the order of the scopes uses the same entry. (link:https://redhat.atlassian.net/browse/OCPBUGS-99757[OCPBUGS-99757])

* Before this update, the `fwupd-refresh.timer` parameter was enabled by default on {op-system-first} 10. As a consequence, firmware scans caused system management interrupts (SMIs) and latency spikes. With this release, the `fwupd-refresh.timer` parameter is disabled when a `PerformanceProfile` parameter is applied. As a result, firmware refresh scans do not introduce latency spikes on performance-tuned nodes. (link:https://redhat.atlassian.net/browse/OCPBUGS-112580[OCPBUGS-112580])

* Before this update, the etcd restore script could fail when additional files remained in the `/var/lib/etcd` directory after the member directory was moved to backup. With this release, remaining files and directories, including hidden entries, are moved into the `extra-data-dir-contents` directory within the restore backup directory before continuing. As a result, these extra entries do not prevent restoration because the etcd data directory is not empty. (link:https://redhat.atlassian.net/browse/OCPBUGS-127425[OCPBUGS-127425])

* Before this update, after a hosted control plane upgrade the `ClusterVersion` `Upgradeable` condition could remain `False` with reason `ResourceDeletesInProgress` even when the listed deployments were ready and had no deletion timestamp. As a consequence, further control plane upgrades could be blocked. With this release, the upgradeable status clears correctly when resource deletions are not in progress. As a result, later upgrades are not blocked by a stale `ResourceDeletesInProgress` condition. (link:https://redhat.atlassian.net/browse/OCPBUGS-133261[OCPBUGS-133261])

* Before this update, revealed values on the *Secret* details page could automatically become hidden when the page refreshed. With this release, the reveal state is preserved so that values remain visible until you click *Hide values*. As a result, secret values do not hide unexpectedly. (link:https://redhat.atlassian.net/browse/OCPBUGS-133720[OCPBUGS-133720])

* Before this update, NetworkPolicy manifests were missing from the `openshift-cluster-machine-approver` namespace. As a consequence, ingress traffic to machine-approver pods was not restricted by a NetworkPolicy. With this release, policies that deny traffic by default, allow all egress traffic, and allow ingress traffic on TCP metrics ports 9192 and 9194 are added. As a result, the namespace restricts ingress while preserving metrics access and outbound connectivity. (link:https://redhat.atlassian.net/browse/OCPBUGS-135091[OCPBUGS-135091])
