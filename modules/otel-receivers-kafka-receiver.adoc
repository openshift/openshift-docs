= Kafka Receiver

[role="_abstract"]
The Kafka Receiver receives traces, metrics, and logs from Kafka in the OTLP format.

The following `OpenTelemetryCollector` custom resource configures the Kafka Receiver:

[source,yaml]
----
# ...
  config:
    receivers:
      kafka:
        brokers: ["localhost:9092"]
        protocol_version: 2.0.0
        logs:
          topics: ["otlp_logs"]
          encoding: raw
        metrics:
          topics: ["otlp_metrics"]
          encoding: otlp_proto
        traces:
          topics: ["otlp_spans"]
          encoding: otlp_proto
        auth:
          sasl:
            username: example
            password: example
            mechanism: PLAIN
        tls:
          ca_file: ca.pem
          cert_file: cert.pem
          key_file: key.pem
          insecure: false
          insecure_skip_verify: false
          reload_interval: 1h
          server_name_override: <name>
          min_version: "1.2"
          max_version: "1.3"
    service:
      pipelines:
        traces:
          receivers: [kafka]
# ...
----
where:

`brokers`:: List of Kafka brokers. The default is `+localhost:9092+`.
`protocol_version`:: Kafka protocol version. For example, `+2.0.0+`. This is a required field.
`logs.topics`, `metrics.topics`, `traces.topics`:: List of Kafka topics to read from for each signal type. The defaults are `+otlp_logs+`, `+otlp_metrics+`, and `+otlp_spans+`, respectively.
`auth.sasl`:: SASL authentication configuration. Requires `username`, `password`, and `mechanism`, which must be one of `PLAIN`, `AWS_MSK_IAM_OAUTHBEARER`, `OAUTHBEARER`, `SCRAM-SHA-256`, or `SCRAM-SHA-512`. If omitted, SASL authentication is disabled.
`auth.kerberos`:: Kerberos authentication configuration. Cannot be combined with `auth.sasl`. If omitted, Kerberos authentication is disabled.
`tls`:: Client-side TLS configuration. Defines paths to the TLS certificates. If omitted, TLS authentication is disabled.
`insecure`:: Disables TLS on the client connection when set to `true`. This setting is ignored if a CA file is also configured. The default is `false`.
`insecure_skip_verify`:: Skips verifying the certificate when set to `true`. The default is `false`.
`reload_interval`:: Specifies the time interval at which the certificate is reloaded. If the value is not set, the certificate is never reloaded. The `reload_interval` field accepts a string containing valid units of time such as `ns`, `us`, `ms`, `s`, `m`, `h`. Set this value to an interval shorter than your certificate lifetime if you use automated certificate rotation.
`server_name_override`:: Overrides the virtual hostname of authority, such as the authority header field in requests. That is, it overrides the server name in the TLS handshake. You can use this for testing or when the connection hostname differs from the server name in the certificate.
`min_version`:: Sets the minimum supported TLS protocol version. This parameter is optional. The default is `1.2`.
`max_version`:: Sets the maximum supported TLS protocol version. This parameter is optional. The default is `1.3`.

[NOTE]
====
The top-level `topic` field and the `auth.plain_text` authentication option have been removed. Configure per-signal topics under `logs.topics`, `metrics.topics`, and `traces.topics`, and use `auth.sasl` with `mechanism: PLAIN` instead of `auth.plain_text`. A configuration that still uses these removed fields fails to start.
====
