= Configuring BGP authentication with MD5 passwords

[role="_abstract"]
To secure BGP sessions with MD5 authentication, configure BGP peers to use password-based authentication. Starting in {product-title} 4.19, you can use the `secretPassthrough` feature to prevent passwords from being exposed in cleartext in the generated `FRRConfiguration` custom resources.

When you enable the `secretPassthrough` field in the MetalLB custom resource (CR), the MetalLB Operator passes BGP password Secret references to the FRR-K8s daemon instead of resolving them to cleartext. This ensures that passwords are never exposed in cleartext in any custom resource.

.Prerequisites

* Install the {oc-first}.
* Log in as a user with `cluster-admin` privileges.
* Configure MetalLB with a BGP advertisement.

.Procedure

. Enable secret passthrough in the MetalLB CR:
+
[source,terminal]
----
$ oc edit metallb metallb -n metallb-system
----

. Add the `secretPassthrough` field under `spec.frrk8sConfig`:
+
[source,yaml]
----
apiVersion: metallb.io/v1beta1
kind: MetalLB
metadata:
  name: metallb
  namespace: metallb-system
spec:
  frrk8sConfig:
    secretPassthrough: true
# ...
----

. Create a Secret of type `kubernetes.io/basic-auth` in the `openshift-frr-k8s` namespace with the BGP password:
+
[source,terminal]
----
$ oc create secret generic bgp-peer-password \
  --type=kubernetes.io/basic-auth \
  --from-literal=password=<your_password> \
  -n openshift-frr-k8s
----
+
Replace `<your_password>` with your BGP MD5 authentication password.

. Create a BGPPeer CR that references the Secret:
+
[source,yaml]
----
apiVersion: metallb.io/v1beta2
kind: BGPPeer
metadata:
  name: doc-example-peer-auth
  namespace: metallb-system
spec:
  peerAddress: 10.0.0.1
  peerASN: 64501
  myASN: 64500
  passwordSecret:
    name: bgp-peer-password <1>
# ...
----
<1> The name of the Secret in the `openshift-frr-k8s` namespace. Do not specify a namespace in the `passwordSecret` field.

. Apply the BGPPeer configuration:
+
[source,terminal]
----
$ oc apply -f bgppeer-auth.yaml
----

.Verification

. Verify that the FRRConfiguration CR contains only a `passwordSecret` reference and no cleartext `password` field:
+
[source,terminal]
----
$ oc get frrconfiguration -n openshift-frr-k8s -o yaml
----
+
The output should show `passwordSecret` but not a `password` field in the neighbors section:
+
[source,yaml]
----
spec:
  bgp:
    routers:
    - asn: 64500
      neighbors:
      - address: 10.0.0.1
        asn: 64501
        passwordSecret:
          name: bgp-peer-password
          namespace: openshift-frr-k8s
# ...
----

. Verify that the BGP session is established:
+
[source,terminal]
----
$ oc get bgppeer -n metallb-system
----
+
The output should show the BGP peer with an `Established` status.

[IMPORTANT]
====
Cross-namespace secret references are not supported by FRR-K8s. The Secret referenced in the BGPPeer CR must reside in the `openshift-frr-k8s` namespace, not in the `metallb-system` namespace.
====
