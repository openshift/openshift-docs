= Configuring BGP password secret passthrough

[role="_abstract"]
Starting in {product-title} 4.19, you can enable the optional `secretPassthrough` field so that a password-backed BGP session passes a Secret reference to FRR-K8s.

Password-backed BGP sessions use the optional `spec.password` or `spec.passwordSecret` field on the BGP peer custom resource. You can use those fields when `spec.frrk8sConfig.secretPassthrough` is unset or set to `false`. In that configuration, the MetalLB Operator extracts the password value into the generated `FRRConfiguration` custom resource. When you use `spec.passwordSecret`, create the Secret in the `metallb-system` namespace. For the peer fields, see "About the BGP peer custom resource".

Secret passthrough stays off until you set `spec.frrk8sConfig.secretPassthrough` to `true` in the MetalLB custom resource (CR). When the field is `true`, the Operator passes the BGP password Secret to the FRR-K8s daemon as a reference. The Secret must reside in the `openshift-frr-k8s` namespace, and the generated `FRRConfiguration` custom resource has a `passwordSecret` field.

.Prerequisites

* Install the {oc-first}.
* Log in as a user with `cluster-admin` privileges.
* Deploy the MetalLB Operator and create a MetalLB custom resource.
* Use a cluster that runs {product-title} 4.19 or later.

.Procedure

. Enable secret passthrough in the MetalLB CR.
+
You can enable `secretPassthrough` using either the CLI or by editing the YAML directly.
+
Run the following command to enable secret passthrough:
+
[source,terminal]
----
$ oc patch metallb metallb -n metallb-system --type=merge \
  -p '{"spec":{"frrk8sConfig":{"secretPassthrough":true}}}'
----
+
Alternatively, edit the MetalLB CR interactively. Run the following command:
+
[source,terminal]
----
$ oc edit metallb metallb -n metallb-system
----
+
Add the `secretPassthrough` field under `spec.frrk8sConfig`:
+
[source,yaml]
----
apiVersion: metallb.io/v1beta1
kind: MetalLB
metadata:
  name: metallb
  namespace: metallb-system
spec:
  frrk8sConfig:
    secretPassthrough: true
# ...
----

. Create a Secret of type `kubernetes.io/basic-auth` in the `openshift-frr-k8s` namespace with the BGP password. Run the following command:
+
[source,terminal]
----
$ oc create secret generic bgp-peer-password \
  --type=kubernetes.io/basic-auth \
  --from-literal=password=<your_password> \
  -n openshift-frr-k8s
----
+
Replace `<your_password>` with your BGP MD5 authentication password.
+
[NOTE]
====
The Cluster Network Operator (CNO) automatically creates the `openshift-frr-k8s` namespace when it deploys the FRR-K8s components. You do not need to create this namespace manually.
====
+
[IMPORTANT]
====
This procedure applies when `secretPassthrough` is `true`. Create the Secret in the `openshift-frr-k8s` namespace. FRR-K8s reads the Secret directly. FRR-K8s does not support cross-namespace Secret references.

When `secretPassthrough` is unset or `false`, create the Secret in the `metallb-system` namespace. The MetalLB Operator extracts the password value into the generated `FRRConfiguration` custom resource. That configuration is the existing password-backed session.
====

. Create a BGPPeer CR that references the Secret:
+
[source,yaml]
----
apiVersion: metallb.io/v1beta2
kind: BGPPeer
metadata:
  name: doc-example-peer-auth
  namespace: metallb-system
spec:
  peerAddress: 10.0.0.1
  peerASN: 64501
  myASN: 64500
  passwordSecret:
    name: bgp-peer-password
# ...
----
+
.BGPPeer CR parameters
[cols="1,3"]
|===
|Parameter |Description

|`spec.peerAddress`
|Replace with your BGP router's IP address.

|`spec.peerASN`
|Replace with your BGP peer's AS number.

|`spec.myASN`
|Replace with your local AS number. This must match the AS number used in your BGPAdvertisement configuration.

|`spec.passwordSecret.name`
|The name of the Secret in the `openshift-frr-k8s` namespace. Do not specify a namespace in the `passwordSecret` field.
|===

. Apply the BGPPeer configuration:
+
[source,terminal]
----
$ oc apply -f bgppeer-auth.yaml
----

.Verification

. Wait for the FRR-K8s daemon to process the BGPPeer configuration:
+
[source,terminal]
----
$ oc wait --for=condition=Ready pod -l app=frr-k8s \
  -n openshift-frr-k8s --timeout=120s
----

. Verify that secret passthrough is in effect. The neighbor object in the `FRRConfiguration` CR has a `passwordSecret` reference:
+
[source,terminal]
----
$ oc get frrconfiguration -n openshift-frr-k8s \
  -o jsonpath='{.items[0].spec.bgp.routers[0].neighbors[0]}' | jq
----
+
The following example output shows the BGP neighbor with a `passwordSecret` reference in the `openshift-frr-k8s` namespace.
+
[source,json]
----
{
  "address": "10.0.0.1",
  "asn": 64501,
  "passwordSecret": {
    "name": "bgp-peer-password",
    "namespace": "openshift-frr-k8s"
  }
}
----
+
[IMPORTANT]
====
A `password` field means secret passthrough is off for this peer. The MetalLB Operator extracted the password value, which is the password-backed session when `spec.frrk8sConfig.secretPassthrough` is unset or `false`.

If you intended to enable secret passthrough, confirm the MetalLB CR:

[source,terminal]
----
$ oc get metallb metallb -n metallb-system \
  -o jsonpath='{.spec.frrk8sConfig.secretPassthrough}'
----

A value of `true` means secret passthrough is on. If the output is empty or `false`, repeat step 1.
====

. Verify that the BGP session is established. Run the following command:
+
[source,terminal]
----
$ oc get bgpsessionstate -n openshift-frr-k8s
----
+
The following example output shows the BGP session in the `Established` state.
+
[source,terminal]
----
NAME                                      STATUS        AGE
doc-example-peer-auth-mysno-sno-...       Established   2m15s
----
+
[NOTE]
====
It might take up to 2 minutes for the BGP session to establish after creating the BGPPeer CR. If the status shows `Connect` or `Active`, the session is still negotiating. Check the FRR-K8s pod logs if the session does not establish within 5 minutes:

[source,terminal]
----
$ oc logs -n openshift-frr-k8s -l app=frr-k8s -c frr --tail=50
----
====

*Troubleshooting*

*BGP session does not establish*

If the BGP session status remains in `Connect` or `Active` state:

. Verify network connectivity between OpenShift nodes and the BGP peer:
+
[source,terminal]
----
$ oc debug node/<node-name> -- chroot /host ping -c 3 <peer-address>
----

. Check the FRR-K8s logs for authentication errors:
+
[source,terminal]
----
$ oc logs -n openshift-frr-k8s -l app=frr-k8s -c frr --tail=50
----

. Verify that the MD5 password in the Secret matches the password configured on your BGP router.

*Secret not found error*

If you see errors about the Secret not being found:

. Verify the Secret exists in the `openshift-frr-k8s` namespace (not `metallb-system`):
+
[source,terminal]
----
$ oc get secret bgp-peer-password -n openshift-frr-k8s
----

[IMPORTANT]
====
Cross-namespace secret references are not supported by FRR-K8s. The Secret referenced in the BGPPeer CR must reside in the `openshift-frr-k8s` namespace, not in the `metallb-system` namespace.
====
