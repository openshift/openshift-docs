= Understand sync, health, and self-healing

[role="_abstract"]
Argo CD continuously monitors your applications and ensures the cluster state matches the desired state defined in Git. Understanding how Argo CD tracks application status helps you troubleshoot deployments and configure automation.

*Sync status*

Sync status indicates whether the application resources on the cluster match the manifests in Git:

* *Synced* - The live state on the cluster matches the desired state in Git. All resources are up to date.
* *OutOfSync* - The live state differs from the desired state. Resources need to be synchronized to match Git.
* *Unknown* - Argo CD cannot determine the sync status, usually due to missing health checks or inaccessible resources.

Applications become OutOfSync when:

* You commit changes to the Git repository containing application manifests
* Someone manually modifies resources on the cluster outside of Argo CD
* Kubernetes controllers or operators modify resources automatically

*Health status*

Health status reflects the operational state of application resources on the cluster:

* *Healthy* - Resources are running normally and passing health checks.
* *Progressing* - Resources are deploying or updating but not yet ready.
* *Degraded* - Resources exist but are not functioning correctly (for example, pods in CrashLoopBackOff).
* *Suspended* - Resources are intentionally paused (for example, a suspended CronJob).
* *Missing* - Expected resources do not exist on the cluster.
* *Unknown* - Argo CD cannot determine the health status.

Argo CD determines health by checking Kubernetes resource conditions, pod status, and custom health checks.

*Self-healing*

Self-healing automatically reverts manual changes to match the Git repository. When enabled, Argo CD detects configuration drift and synchronizes the cluster state back to match Git.

Self-healing behavior:

. Argo CD polls the Git repository every 3 minutes by default (configurable)
. When drift is detected, Argo CD marks the application as OutOfSync
. If self-healing is enabled, Argo CD automatically synchronizes the application
. Resources return to the state defined in Git

Enable self-healing for production applications to prevent configuration drift and maintain consistency. Disable self-healing in development environments where developers may need to test manual changes.

[NOTE]
====
Self-healing only reverts changes that cause the application to become OutOfSync. It does not revert changes to resources that Argo CD does not manage.
====

*Automated vs. manual sync*

Argo CD supports two synchronization modes:

* *Automated sync* - Argo CD automatically synchronizes applications when it detects changes in Git. Combine with self-healing for fully automated GitOps workflows.
* *Manual sync* - Applications require manual synchronization through the UI, CLI, or API. Use for production environments where you want to review changes before deployment.

Configure sync policies when you create the application or update them later in the application settings.
