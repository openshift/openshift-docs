= Configuring OpenShift ingress shards

[role="_abstract"]
Before configuring Knative Serving, you must configure OpenShift ingress shards.

.Procedure

* Use a label selector in the `IngressController` CR to configure {ServerlessProductName} to match specific ingress shards with different domains:
+
.Example `IngressController` CR
[source,yaml]
----
apiVersion: operator.openshift.io/v1
kind: IngressController
metadata:
  name: ingress-dev
  namespace: openshift-ingress-operator
spec:
  routeSelector:
    matchLabels:
      router: dev
  domain: "dev.serverless.cluster.example.com"
  # ...
---
apiVersion: operator.openshift.io/v1
kind: IngressController
metadata:
  name: ingress-prod
  namespace: openshift-ingress-operator
spec:
  routeSelector:
    matchLabels:
      router: prod
  domain: "prod.serverless.cluster.example.com"
  # ...
----
+
--
`metadata.name`:: Name of the first ingress shard.
`spec.routeSelector.matchLabels.router`:: A label selector to match the `ingress-dev` shard.
`spec.domain`:: A custom domain for the `ingress-dev` shard.
`metadata.name (second shard)`:: Name of the second ingress shard.
`spec.routeSelector.matchLabels.router (second shard)`:: A label selector to match the `ingress-prod` shard.
`spec.domain (second shard)`:: A custom domain for the `ingress-prod` shard.
--
