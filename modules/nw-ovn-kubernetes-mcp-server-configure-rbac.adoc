= Configure RBAC for OVN-Kubernetes and CNI diagnostics toolsets

[role="_abstract"]
Apply `ClusterRole` and `ClusterRoleBinding` resources so the MCP server for Red{nbsp}Hat OpenShift can list `ovnkube-node` pods, run OVN and OVS commands in them, and create privileged debug pods with host network access.

[IMPORTANT]
====
The `ovn-kubernetes` tool uses `pods/exec` permissions on privileged `ovnkube-node` pods. The `cni-diagnostics` tool creates privileged debug pods with host network access. Grant these permissions only to trusted users, and monitor Kubernetes audit logs for unexpected tool usage.
====

.Prerequisites

* You have installed and configured the MCP server for Red{nbsp}Hat OpenShift.
* You have configured the MCP server with base RBAC.
* You have cluster administrator permissions.

.Procedure

. Create a `ClusterRole` and `ClusterRoleBinding` resources that grant the MCP server permissions to list `ovnkube-node` pods and execute OVN and OVS commands inside them:
+
.Example of RBAC for the `ovn-kubernetes` toolset
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: ovn-kubernetes-mcp-user
rules:
  - apiGroups: [""]
    resources: ["namespaces"]
    verbs: ["get", "list"]
  - apiGroups: [""]
    resources: ["pods"]
    verbs: ["get", "list"]
  - apiGroups: [""]
    resources: ["pods/exec"]
    verbs: ["create"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: ovn-kubernetes-mcp-user-binding
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: ovn-kubernetes-mcp-user
subjects:
  - kind: ServiceAccount
    name: <mcp_server_service_account>
    namespace: <mcp_server_namespace>
----
+
where:

`<mcp_server_service_account>`:: Specifies the service account name used by the MCP server.
`<mcp_server_namespace>`:: Specifies the namespace where the MCP server service account exists.

. Create a `ClusterRole` and `ClusterRoleBinding` that grant the MCP server permissions for CNI diagnostics:
+
.Example RBAC for the `cni-diagnostics` toolset
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: cni-diagnostics-mcp-user
rules:
  - apiGroups: [""]
    resources: ["nodes"]
    verbs: ["get", "list"]
  - apiGroups: [""]
    resources: ["pods"]
    verbs: ["create", "get", "list", "delete"]
  - apiGroups: [""]
    resources: ["namespaces"]
    verbs: ["get", "list"]
  - apiGroups: [""]
    resources: ["pods/exec"]
    verbs: ["create"]
  - apiGroups: [""]
    resources: ["pods/log"]
    verbs: ["get"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: cni-diagnostics-mcp-user-binding
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: cni-diagnostics-mcp-user
subjects:
  - kind: ServiceAccount
    name: <mcp_server_service_account>
    namespace: <mcp_server_namespace>
----
+
where:

`<mcp_server_service_account>`:: Specifies the service account name used by the MCP server.
`<mcp_server_namespace>`:: Specifies the namespace where the MCP server service account exists.

. Optional: if your MCP server uses OAuth or token exchange, update the `subjects` field in each `ClusterRoleBinding` to reference the user or group that requires access:
+
.Example `ClusterRoleBinding` subjects for OAuth or token exchange mode
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: <binding_name>
subjects:
  - kind: User
    name: <user_name>
    apiGroup: rbac.authorization.k8s.io
----
+
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: <binding_name>
subjects:
  - kind: Group
    name: <group_name>
    apiGroup: rbac.authorization.k8s.io
----
+
where:

`<binding_name>`:: Specifies the name of the `ClusterRoleBinding` resource, for example `ovn-kubernetes-mcp-user-binding`.
`<user_name>`:: Specifies that the `ClusterRole` is bound to an individual user. Replace `<user_name>` with the user's username.
`<group_name>`:: Specifies that the `ClusterRole` is bound to all members of a group. Replace `<group_name>` with the group name.

. Apply the `ovn-kubernetes-mcp-rbac.yaml` manifests:
+
[source,terminal]
----
$ oc apply -f ovn-kubernetes-mcp-rbac.yaml
----

. Apply the `cni-diagnostics-mcp-rbac.yaml` manifests:
+
[source,terminal]
----
$ oc apply -f cni-diagnostics-mcp-rbac.yaml
----
