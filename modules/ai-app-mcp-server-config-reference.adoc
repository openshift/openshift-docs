= Configuration reference

[role="_abstract"]
To configure the MCP server for Red{nbsp}Hat OpenShift, review how the server resolves settings from environment variables and the `config.toml` file, and which configuration options changed in this release.

In the MCP Lifecycle Operator-managed deployment, the server reads configuration from a `config.toml` file that is mounted from a `ConfigMap`. To change the configuration, edit the `ConfigMap`. Whether a change takes effect without a restart depends on whether the option is reloadable, as listed in the configuration option table (see "Configuration Reference"). Reloadable options apply automatically; non-reloadable options require you to restart the server.

The loading precedence for configuration, from highest to lowest, is the environment variable, then the `config.toml` file, and then the default value. Command-line flags are used only for startup (`--config`, `--config-dir`, `--version`), not for runtime configuration.

Startup config logging::
The server logs the effective config (and where each value came from) at startup.

Removed and renamed config options::
Several config options have been removed or renamed in {product-title} 5.0 in comparison with 4.22. For a list of which options are removed or renamed, see the following tables.
+
.Removed CLI flags

|===
|Dropped flag|Replacement

|`--log-level`|`log_level`
|`--log-file`|`log_file`

|`--list-output`|`list_output`
|`--read-only`|`read_only`
|`--disable-destructive`|`disable_destructive`
|`--stateless`|`stateless`

|Hidden OAuth flags (`--require-oauth`, `--authorization-url`, ...)|matching TOML keys
|===

[NOTE]
====
* — means that vector is off. 
* Reload = yes means a SIGHUP that changes the value takes effect.
* Reload = no means a SIGHUP that would change the value is rejected and the process exits.
