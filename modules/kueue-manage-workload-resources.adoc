= Manage workload resources with gang scheduling and readiness timeouts

[role="_abstract"]
To limit how long workloads hold resources while pods wait to reach a ready state, configure cluster-wide readiness timeouts. Set a retry limit to restrict repeated admission attempts.

The following example uses the `ByWorkload` policy with parallel admission.

.Prerequisites

* You have cluster administrator permissions.
* You installed the {kueue-name} Operator on your cluster.
* You created a `Kueue` custom resource (CR) named `cluster`.
* You installed the {oc-first}.

.Procedure

. Update the `Kueue` CR configuration by setting the `spec.config.gangScheduling` field to the following values. Keep the other CR settings.
+
[source,yaml]
----
apiVersion: kueue.openshift.io/v1
kind: Kueue
metadata:
  name: cluster
spec:
  config:
    integrations:
      frameworks:
      - BatchJob
    gangScheduling:
      policy: ByWorkload
      byWorkload:
        admission: Parallel
        timeoutSeconds: 600
        recoveryTimeoutSeconds: 1800
        requeuingStrategy:
          timeReference: Eviction
          retryLimit: 5
          backoffBaseSeconds: 120
          backoffMaxSeconds: 7200
# ...
----
+
For more information, see "Gang scheduling configuration".

. Apply the updated `Kueue` CR to the cluster by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----

.Verification

* Verify the readiness configuration by running the following command:
+
[source,terminal]
----
$ oc get configmap kueue-manager-config \
  -n openshift-kueue-operator \
  -o jsonpath='{.data.controller_manager_config\.yaml}'
----
+
Confirm that the `waitForPodsReady` section has the following values:
+
.Example output
[source,yaml]
----
# ...
waitForPodsReady:
  blockAdmission: false
  recoveryTimeout: 30m0s
  requeuingStrategy:
    backoffBaseSeconds: 120
    backoffLimitCount: 5
    backoffMaxSeconds: 7200
    timestamp: Eviction
  timeout: 10m0s
# ...
----
