= Create a route to the HTTP interceptor

[role="_abstract"]
You can send external HTTP traffic through the interceptor by creating an {product-title} route to the interceptor proxy service. The interceptor then forwards the request to the workload and counts it for scaling.

The route must target `keda-add-ons-http-interceptor-proxy` in the `{cma-namespace}` namespace. A route can select only a service in its own namespace, so create the route in `{cma-namespace}`. The route host must match a host in the `InterceptorRoute` resource.

.Prerequisites

* An `InterceptorRoute` resource exists for the workload.
* You have permission to create routes in the `{cma-namespace}` namespace.
* The OpenShift CLI (`oc`) is installed.

.Procedure

. Confirm the interceptor proxy service port by running the following command:
+
[source,terminal,subs="+attributes"]
----
$ oc get svc keda-add-ons-http-interceptor-proxy -n {cma-namespace}
----
+
Note the service port. The default port is `8080`.

. Create a route to that service. The following example uses edge TLS termination and the default router certificate:
+
.Example route to the interceptor
[source,yaml,subs="+attributes"]
----
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: sample-app
  namespace: {cma-namespace} <1>
spec:
  host: sample-app.example.com <2>
  to:
    kind: Service
    name: keda-add-ons-http-interceptor-proxy <3>
  port:
    targetPort: 8080 <4>
  tls:
    termination: edge <5>
    insecureEdgeTerminationPolicy: Redirect
----
<1> Specifies the namespace where the Custom Metrics Autoscaler Operator and the interceptor service are installed.
<2> Specifies the public host. Use the same host in `spec.rules[].hosts` on the `InterceptorRoute` resource.
<3> Specifies the interceptor proxy service. Do not target the application service. Traffic that bypasses the interceptor is not counted.
<4> Specifies the interceptor proxy service port from the previous step.
<5> Specifies edge TLS termination so that the interceptor receives a plain text HTTP request and can read the host, path, and headers. Use `reencrypt` when the interceptor receives HTTPS. Do not use `passthrough`.

. Create the route by running the following command:
+
[source,terminal]
----
$ oc apply -f route.yaml
----
+
For clients that run inside the cluster, send requests to the interceptor proxy service instead of the application service. Include the host that those clients send in `spec.rules[].hosts`. The in-cluster service host is `keda-add-ons-http-interceptor-proxy.{cma-namespace}.svc`.

.Verification

. Confirm that the route is admitted by running the following command:
+
[source,terminal,subs="+attributes"]
----
$ oc get route sample-app -n {cma-namespace}
----

. Send a request to the route host and confirm that the workload scales by running the following command:
+
[source,terminal]
----
$ oc get deployment sample-app -n my-namespace -w
----
