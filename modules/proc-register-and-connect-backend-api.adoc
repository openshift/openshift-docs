= Register and connect the backend API

[role="_abstract"]
To connect external APIs, you must register your backend hostname so that it becomes routable, configure TLS, then allow the traffic and route it.

.Prerequisites

* You installed {prodname}.
* You are using Istio as the `Gateway` object provider.

.Procedure

. Register your backend hostname so that it becomes routable by using the following example `ServiceEntry` called `backend_api_se.yaml`:
+
.Example ServiceEntry
[source,yaml,subs="+quotes"]
----
apiVersion: networking.istio.io/v1
kind: ServiceEntry
metadata:
  name: _<backend_api_se>_
  namespace: _<gateway_system>_
spec:
  hosts:
    - _<my.api.local>_
  location: MESH_EXTERNAL
  resolution: DNS
  ports:
    - number: 443
      name: https
      protocol: HTTPS
----
+
* Replace the `metadata.name` parameter value for both resources with the name you want to use.
* Replace the `metadata.namespace` parameter value with the namespace where you want to apply your `Gateway` object.
* The `ServiceEntry` provides the `Hostname` backend `kind` to your `Gateway` object and route.
* Replace the `spec.hosts` parameter value with your backend hostname.
+
[IMPORTANT]
====
Your backend hostname domain must be reachable from the cluster.
====

. Apply the `ServiceEntry` CRs by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<backend_api_se>_.yaml
----
+
Replace `_<backend_api_se>_` with your `ServiceEntry` YAML name.

. Configure TLS origination to the external backend by using the following example `DestinationRule` called `backend_api_dr.yaml`:
+
.Example DestinationRule
[source,yaml,subs="+quotes"]
----
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: _<backend_api_dr>_
  namespace: _<gateway_system>_
spec:
  host: _<my.api.local>_
  trafficPolicy:
    tls:
      mode: SIMPLE
      sni: _<my.api.local>_
----
+
* Replace the `metadata.name` parameter value with the name you want to use.
* Replace the `metadata.namespace` parameter value with the namespace where you want to apply your `Gateway` object.
* Replace the `_<my.api.local>_` values with your backend hostname.
+
[IMPORTANT]
====
Your backend hostname domain must be reachable from the cluster.
====

. Apply `DestinationRule` CR by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<backend_api_dr>_.yaml
----
+
Replace `_<backend_api_dr>_` with your `DestinationRule` YAML name.

. To accept traffic on the external hostname, deploy a `Gateway` object by using the following example:
+
.Example Gateway object for external hostname traffic
[source,yaml,subs="+quotes"]
----
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  labels:
    istio: ingress
  name: _<ingress>_
  namespace: _<gateway_system>_
spec:
  gatewayClassName: istio
  listeners:
    - name: _<ingress_http>_
      port: 80
      hostname: _<my.api.com>_
      protocol: HTTP
      allowedRoutes:
        namespaces:
          from: All
----
+
* Replace the `metadata.name` parameter value with the name of your `Gateway` object.
* Replace the `metadata.namespace` parameter value with the namespace where you want to apply your `Gateway` object.
* Replace the `spec.listeners.name` parameter value with the name of your listener.
* Replace the `spec.listeners.hostname` parameter value with your external host.

. Apply the `Gateway` CR by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<ingress_gateway>_.yaml
----
+
Replace `_<ingress_gateway>_` with your `Gateway` YAML name.

. To ensure that the backend receives the correct hostname, create an `HTTPRoute` by using the following example:
+
.Example `HTTPRoute` for external API access
[source,yaml,subs="+quotes"]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: _<httproute_external_host>_
  namespace: _<gateway_system>_
spec:
  parentRefs:
    - name: _<ingress>_
      namespace: _<gateway_system>_
  hostnames:
    - _<my.api.com>_
  rules:
    - backendRefs:
        - name: _<my.api.local>_
          kind: Hostname
          group: networking.istio.io
          port: 443
      filters:
        - type: URLRewrite
          urlRewrite:
            hostname: _<my.api.local>_
----
+
* Replace the `metadata.name` parameter value with the name you want to use.
* Replace the `metadata.namespace` parameter value with the namespace where you applied your `Gateway` object.
* Replace the `spec.hostnames` parameter value with your external host.
* Replace the `spec.parentRefs.metadata.name` parameter value with the name of your `Gateway` object.
* Replace the `spec.parentRefs.metadata.namespace` parameter value with the namespace where you applied your `Gateway` object.
* The `HTTPRoute` bridges the traffic to the backend, rewriting the `Host` header.
* Replace the `_<my.api.local>_` values with your backend hostname.
+
[IMPORTANT]
====
Your backend hostname domain must be reachable from the cluster.
====

. Apply the `HTTPRoute` CR by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<httproute_external_host>_.yaml
----
+
Replace `_<httproute_external_host>_` with your `HTTPRoute` YAML name.

. Wait for the `Gateway` object to become ready by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc get gateway _<ingress>_ -n _<gateway_system>_ -o=jsonpath='{.status.conditions[?(@.type=="Programmed")].status}'
----
+
* Replace `_<ingress>_` with the name of your `Gateway` object.
* Replace `_<gateway_system>_` with the namespace where your `Gateway` object is applied.
+
.Expected output
[source,text]
----
True
----

.Verification

. Fetch and store the IP address of your Gateway object by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ GATEWAY_IP=$(oc get gateway _<ingress>_ -n _<gateway_system>_ -o jsonpath='{.status.addresses[0].value}')
----
+
* Replace `_<ingress>_` with the name of your `Gateway` object.
* Replace `_<gateway_system>_` with the namespace where your `Gateway` object is applied.

. Optional. Confirm that you have a valid IP address in your variable by running the following command:
+
[source,terminal]
----
$ echo $GATEWAY_IP
----

. Make an HTTP request to the `Gateway` IP address while presenting a specific hostname by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ curl -v --resolve <my.api.com>:80:$GATEWAY_IP "http://<my.api.com>/"
----
+
* Replace `_<my.api.com>_` with your external host.
+
.Expected output
[source,text]
----
HTTP/1.1 200 OK
----

.Next steps

* If you want to secure your traffic, create {prodname} policies.
* If the backend also needs egress-level controls such as workload identity, credential injection, and per-workload rate limiting, see "Set up outbound traffic from your cluster".
