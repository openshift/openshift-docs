= {ols-long} version 2.0.1

[role="_abstract"]
{ols-official} 2.0.1 adds access to mutating and write tools through the {ocp-product-title} Model Context Protocol (MCP) server, resolves tool-result inspection regressions with clearer insight into why a result is rejected, and includes CVE fixes across component repositories. This release also improves the autonomous agents log viewing experience in the {ocp-product-title} web console and helps ensure continued support and stability for clusters running {ocp-product-title} 4.16 and later.

[NOTE]
====
The latest Offline Knowledge Portal (OKP) image that includes {ocp-product-title} 5 documentation is not available in {ols-official} 2.0.1. This image is planned for a future release.
====

[id="ols-2-0-1-enhancements_{context}"]
== Enhancements

[role="_abstract"]
{ols-official} 2.0.1 adds access to mutating and write tools through the {ocp-product-title} MCP server and adds log download and raw log viewing controls to the {ols-long} autonomous agents log viewer.

{ols-official} 2.0.1 includes the following enhancements:

//Mutating/write tools via OpenShift MCP server
* With this update, {ols-official} can access mutating and write tools that are exposed through the {ocp-product-title} Model Context Protocol (MCP) server. This capability lets autonomous agents use tools that change cluster state, in addition to read-only tools. Before this update, the built-in {ocp-product-title} MCP server did not expose tools that are marked as destructive. These tools are available when introspection is enabled, and you can control them by using the `disable_destructive` flag. Executing a tool remains subject to the requesting user's Kubernetes permissions and configured controls.

//OLS-4188
* With this update, the per-stage log viewer for `AgenticRun` workflows in the {ocp-product-title} web console provides a *Download* action to save logs as a file and a *View raw logs* action to open the unformatted logs in a new browser tab. These controls appear on the run detail page for the analysis, execution, and verification stages, and they match the log viewing experience in the *Pod* -> *Logs* view.
