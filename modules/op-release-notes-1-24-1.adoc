{pipelines-title} General Availability 1.24.1 is available on {OCP} 4.14 and later supported versions.

[id="breaking-changes-1-24-1_{context}"]
== Breaking changes

.Manual Approval Gate

//SRVKP-12172
Manual Approval Gate controller role binding update::
Before this update, the Manual Approval Gate controller role binding included the `system:authenticated` group. As a result, any authenticated user or service account in the cluster could approve, reject, list, or describe approval tasks across namespaces without requiring specific RBAC permissions. With this update, the `system:authenticated` group is removed from the controller role binding. As a result, users and service accounts require explicit role bindings to manage approval tasks. To grant users approval task access, create a `RoleBinding` to the `manual-approval-gate-approver` ClusterRole in the relevant namespace. This ClusterRole is shipped with Manual Approval Gate and provides the minimum required permissions.
+
link:https://redhat.atlassian.net/browse/SRVKP-12172[SRVKP-12172]

[id="fixed-issues-1-24-1_{context}"]
== Fixed issues

.Manual Approval Gate

//SRVKP-12509
Approval task spec fields are no longer mutable during updates::
Before this update, the Manual Approval Gate webhook did not enforce immutability on task parameters during updates. As a consequence, an approver could modify `spec.numberOfApprovalsRequired` or `spec.description` while submitting an approval, bypassing multi-approver requirements. With this update, the webhook enforces immutability on these fields for existing approval tasks.
+
link:https://redhat.atlassian.net/browse/SRVKP-12509[SRVKP-12509]

//SRVKP-12510
Approvers can no longer inject pre-approved entries into the approver list::
Before this update, the Manual Approval Gate webhook did not validate new entries in `spec.approvers` during task updates. As a consequence, an approver could inject additional approver entries with a pre-approved status during their own approval action. With this update, the webhook rejects attempts to add, remove, or modify approver entries in `spec.approvers` on existing approval tasks.
+
link:https://redhat.atlassian.net/browse/SRVKP-12510[SRVKP-12510]
