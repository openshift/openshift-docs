= Token rate limiting considerations for egress traffic

[role="_abstract"]
Review the following behaviors before you rely on a `TokenRateLimitPolicy` custom resource (CR) to control the artificial intelligence (AI) token consumption of an egress `Gateway` object.

[id="rhcl-egress-token-tls-origination_{context}"]
== TLS origination and access to the response body

When workloads call an external AI service over the internet, the egress `Gateway` object terminates the connection from the workload and originates a new TLS connection to the external service. The response body passes through the gateway unencrypted on the internal side, so the gateway extracts the token count from the response as usual.

[id="rhcl-egress-token-concurrency_{context}"]
== Concurrent requests and limit accuracy

The egress `Gateway` object checks the remaining budget before it forwards a request, and reports the consumed tokens after the response arrives. No capacity is held between these two phases, so concurrent requests that arrive before the first response returns can pass the check and push the total consumption past the configured limit.

Responses from AI services are typically slow enough that this behavior is acceptable for most workloads. If you need strict enforcement under high concurrency, set limits that leave headroom for the number of requests that your workloads send in parallel.

[id="rhcl-egress-token-response-formats_{context}"]
== Supported response formats

Token extraction works with any external service that returns an OpenAI-compatible response body that has a `usage.total_tokens` field. Response formats that place the token count in a different structure are not supported.

[id="rhcl-egress-token-missing-usage_{context}"]
== Responses that omit token usage

If the external AI service omits the `usage.total_tokens` field, or if the gateway cannot parse the field, the report phase fails and no tokens are counted. Both the check service and the report service default to a failure mode of `allow`, so the request succeeds and the counter remains unchanged. The result is that the policy enforces no limit at all.

[IMPORTANT]
====
Verify that your external AI service returns `usage.total_tokens` in every response before you rely on a `TokenRateLimitPolicy` CR for enforcement. For streaming responses, verify that each request sets the `stream_options.include_usage` field to `true`.
====

To reject the requests for which token extraction fails, set the `RATELIMIT_REPORT_SERVICE_FAILURE_MODE` environment variable to `deny` on the {prodname} Operator deployment. The gateway then blocks every response from which it cannot extract token usage. This setting is a blunt control that applies to all `TokenRateLimitPolicy` CRs in the cluster.
