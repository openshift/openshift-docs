= Configuring log rotation for Windows node services

[role="_abstract"]
You can limit the size of log files for Windows services that the Windows Machine Config Operator (WMCO) manages. Set log rotation environment variables on the WMCO subscription.

The Windows Instance Config Daemon (WICD) writes its own logs. The WMCO passes the size limit to WICD as the `--log-file-max-size` parameter. Other managed services, such as the kubelet and kube-proxy, run under `kube-log-runner`, which applies the size, age, and flush settings.

.Prerequisites

* You installed the Windows Machine Config Operator (WMCO) using Operator Lifecycle Manager (OLM).
* You have access to the cluster as a user with the `cluster-admin` role.

.Procedure

. Edit the `windows-machine-config-operator` subscription in the `openshift-windows-machine-config-operator` namespace by running the following command:
+
[source,terminal]
----
$ oc edit subscription windows-machine-config-operator -n openshift-windows-machine-config-operator
----

. Add the log rotation environment variables to the `.spec.config.env` stanza:
+
[source,yaml]
----
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: windows-machine-config-operator
  namespace: openshift-windows-machine-config-operator
# ...
spec:
# ...
  config:
    env:
      - name: SERVICES_LOG_FILE_SIZE
        value: 100M
      - name: SERVICES_LOG_FILE_AGE
        value: 168h
      - name: SERVICES_LOG_FLUSH_INTERVAL
        value: 5s
----
+
where:
+
--
`SERVICES_LOG_FILE_SIZE`:: Specifies the log file size that starts rotation, as a Kubernetes quantity. For example, `100M` rotates a file at 100 megabytes. The WMCO converts this quantity to megabytes and passes it to WICD as `--log-file-max-size`. The same value is passed to `kube-log-runner` for the other managed services. If you omit this variable, WICD uses a maximum file size of 1800 MB. A value of `0` disables size-based rotation, which can fill the disk.
`SERVICES_LOG_FILE_AGE`:: Specifies how long `kube-log-runner` keeps a rotated log file. For example, `168h` keeps rotated files for 168 hours. This setting applies to services that run under `kube-log-runner`.
`SERVICES_LOG_FLUSH_INTERVAL`:: Specifies how often `kube-log-runner` writes buffered log data to disk. For example, `5s` writes buffered data every 5 seconds. This setting applies to services that run under `kube-log-runner`.
--

[NOTE]
====
Saving the subscription restarts the WMCO. The WMCO then reconfigures each Windows node one node at a time. Managed services, such as the kubelet and kube-proxy, can be interrupted briefly on a node while that node is reconfigured.
====

WICD writes log files to `C:\var\log\wicd\`. Services that run under `kube-log-runner` write log files to `C:\var\log\<service>\`. For example, the kubelet log file is `C:\var\log\kubelet\kubelet.log`.

To return the managed services to their default log rotation behavior, remove the environment variables that you added.
