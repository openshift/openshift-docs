= Validations

[role="_abstract"]

The console checks {istio} objects for conflicts and missing targets, using the live state of the mesh. These checks go beyond the static schema validation that {istio} performs when an object is admitted.

Validations run against objects such as destination rules, service entries, virtual services, gateways, and peer authentication policies. A check can compare objects in one namespace or across namespaces. The console marks each object with the highest severity it found and links the message to the configuration that caused it.

Typical findings include a subset that no workload matches, a host that no service owns, or two virtual services that claim the same route. In ambient mode, the console also warns when a Layer 7 object needs a waypoint that is not in place. Fix the object in the YAML editor or with a wizard, then refresh the validation list.

The console evaluates validations when it loads configuration. It does not block `oc apply`. An object can be stored on the cluster and still appear as invalid in the console.

== Disabling validations

On a cluster with a large number of {istio} objects, validations can take time and memory. To turn them off, set the reconcile interval to `0s`:

[source,yaml]
----
spec:
  external_services:
    istio:
      validation_reconcile_interval: "0s"
----

== Ignoring validations

Ignore a check that does not apply to your environment. Ignored checks are still written to the {KialiServer} log, but they are hidden in the console.

To ignore a code for every object, list it in the `Kiali` custom resource:

[source,yaml]
----
spec:
  kiali_feature_flags:
    validations:
      ignore:
      - KIA0106
----

To ignore checks on one object, set the `kiali.io/ignore-validations` annotation. An empty value ignores every check on that object. A comma-separated list ignores only those codes:

[source,yaml]
----
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: backup-policy
  namespace: my-ns
  annotations:
    kiali.io/ignore-validations: "KIA0101,KIA0102"
----

The annotation works on {istio} configuration, Gateway API objects, services, and workloads. Object-level ignores are added to any codes you ignore in the custom resource.
