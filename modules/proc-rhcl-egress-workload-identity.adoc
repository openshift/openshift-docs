= Authenticate workloads with TokenReview

[role="_abstract"]
Identify the workload that is making a request by using a Kubernetes `TokenReview` with an `AuthPolicy` custom resource (CR).

In egress scenarios, the clients are internal workloads. Every pod has a `ServiceAccount` token mounted automatically, so you do not need to distribute API keys.

The workload sends its `ServiceAccount` token in the `Authorization` header. The `AuthPolicy` CR validates the token and displays the identity of the workload, including the namespace and service account name. This allows use by other policies.

.Prerequisites

include::snippets/egress-gateway-prereqs.adoc[]

* A test client pod is available in the `egress-test` namespace.

.Procedure

. Export the egress `Gateway` object IP address by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ export EGRESS_IP=$(oc get gtw _<kuadrant_egressgateway>_ -n _<gateway_system>_ \
    -o jsonpath='{.status.addresses[0].value}')
----
+
Replace `_<kuadrant_egressgateway>_` value with the egress `Gateway` object name.

. Create an `AuthPolicy` CR to authenticate workloads and restrict egress access to specific namespaces by using the following example:
+
[source,yaml,subs="+quotes"]
----
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: _<workload_identity>_
  namespace: _<gateway_system>_
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: httpbin-external
  rules:
    authentication:
      "workload-sa":
        kubernetesTokenReview:
          audiences:
            - "https://kubernetes.default.svc.cluster.local"
    authorization:
      "allowed-namespaces":
        patternMatching:
          patterns:
            - predicate: auth.identity.user.username.startsWith('system:serviceaccount:egress-test:')
    response:
      success:
        filters:
          "identity":
            json:
              properties:
                username:
                  selector: auth.identity.user.username
----
+
* Replace the `metadata.name` parameter value with the name of your workload.
* Replace the `metadata.namespace` parameter value with the namespace where you applied your egress `Gateway` object.
* `authentication.workload-sa` validates the service account token with `TokenReview`. Unauthenticated requests are rejected with a `401` status code.
* `authorization.allowed-namespaces` restricts access to workloads from the `egress-test` namespace. Workloads from other namespaces are rejected with a `403` status code. Add additional patterns with `||` to allow more namespaces.
* `response.success.filters.identity` displays the resolved identity as dynamic metadata. This is required for policies that reference `auth.identity.*` expressions, such as per-workload rate limiting.

. Apply the `AuthPolicy` CR by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<workload_identity>_
----
+
Replace `_<workload_identity>_` with the name of your workload.
