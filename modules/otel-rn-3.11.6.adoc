The {otel} 3.11.6 release resolves the following Common Vulnerabilities and Exposures (CVEs):

Zstd decompression no longer stops the Collector::
Before this update, the Zstandard (zstd) decompression logic in the Go `klauspost/compress` library mishandled an integer value, which left stale internal state in the decoder. As a consequence, a remote attacker could send a crafted zstd-compressed stream to the Collector, causing an out-of-bounds read and an unhandled panic that stopped the Collector. With this update, the library handles the integer value correctly, so the decoder no longer retains stale internal state or performs the out-of-bounds read. As a result, the Collector no longer stops when it decodes a crafted zstd-compressed payload.
