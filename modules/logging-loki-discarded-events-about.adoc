= About Loki discarded log events

[role="_abstract"]
LokiStack enforces ingestion limits that can cause log data to be discarded, requiring you to understand which limit was exceeded to determine if logs are permanently lost.

LokiStack enforces three types of ingestion limits:

Ingestion rate limit (`RateLimit`)::
The total volume of log data (in bytes per second) arriving at the LokiStack exceeds the configured global ingestion rate. Loki enforces this limit globally and distributes it across Loki distributor replicas.

Per-stream rate limit (`StreamRateLimit`)::
A single log stream is sending data faster than the configured per-stream rate limit. A stream is a unique combination of log labels, such as container name, host, namespace, and pod name.

Log line size limit (`LineTooLong`)::
A single log line exceeds the maximum permitted entry size, which defaults to 256 KB.

The following table summarizes the data loss implications of each limit type:

[cols="1,1,2",options="header"]
|===
| Limit type | Metric reason label | Are logs permanently lost?

| `RateLimit`
| `reason="RateLimit"`
| Not immediately. Vector retries the request. If the limit persists, Loki might permanently discard some logs.

| `StreamRateLimit`
| `reason="StreamRateLimit"`
| Not immediately. Vector retries the request. Logs might be lost if the limit persists.

| `LineTooLong`
| `reason="line_too_long"`
| Yes, always. The collector receives a 400 error and drops the request without retrying.
|===

To identify which limit type is triggering discards, run the following PromQL query in the OpenShift web console under *Observe* -> *Metrics*:

[source,promql]
----
sum by (tenant, reason) (rate(loki_discarded_samples_total[2m]))
----

A nonzero value for a tenant and reason indicates active discards for that limit type.
