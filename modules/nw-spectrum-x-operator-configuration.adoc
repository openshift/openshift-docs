= Configure the NVIDIA Network and Maintenance Operators for Spectrum-X

[role="_abstract"]
You can configure the NVIDIA Network and Maintenance Operators to deploy Spectrum-X components and coordinate node maintenance during network interface controller (NIC) configuration and firmware operations.

.Prerequisites

* You have cluster administrator privileges.
* You have prepared the worker nodes for Spectrum-X.
* You have reviewed the NVIDIA Network Operator platform support matrix for the {product-title}, NVIDIA Network Operator, adapter, firmware, and Spectrum-X reference architecture versions that you plan to use.
* You have installed a supported NVIDIA Network Operator version in the `nvidia-network-operator` namespace.
For installation instructions, see link:https://docs.nvidia.com/networking/display/kubernetes2610/openshift/deployment-guide-openshift.html[NVIDIA Network Operator deployment guide for OpenShift].
* You have access to the NVIDIA container registries required by the selected Network Operator release.
* You have identified a supported NVIDIA Maintenance Operator version for coordinated node maintenance during NIC configuration and firmware operations.

.Procedure

. Confirm that the NVIDIA Network Operator controller is running:
+
[source,terminal]
----
$ oc get pods -n nvidia-network-operator
----

. Create the namespace for the NVIDIA Maintenance Operator:
+
[source,terminal]
----
$ oc new-project nvidia-maintenance-operator
----

. Install the NVIDIA Maintenance Operator:
+
.. In the OpenShift web console, select *Ecosystem* -> *Software Catalog*.
.. Search for *NVIDIA Maintenance Operator* and select the NVIDIA-published result.
.. Click *Install*.
.. Select the `nvidia-maintenance-operator` namespace and a channel and version that are compatible with the NVIDIA Network Operator release.
.. Click *Install*.
+
Confirm that the controller pod is running before configuring NIC firmware:
+
[source,terminal]
----
$ oc get pods -n nvidia-maintenance-operator
----

. Configure the NVIDIA Maintenance Operator to process one node maintenance request at a time.
Save the following `MaintenanceOperatorConfig` custom resource as `maintenance-operator-config.yaml`:
+
[source,yaml]
----
apiVersion: maintenance.nvidia.com/v1alpha1
kind: MaintenanceOperatorConfig
metadata:
  name: default
  namespace: nvidia-maintenance-operator
spec:
  logLevel: info
  maxParallelOperations: 1
  maxNodeMaintenanceTimeSeconds: 300
----
+
The example timeout is 300 seconds.
Adjust it to give the firmware operation enough time to finish.
+
Apply the resource and confirm that it exists:
+
[source,terminal]
----
$ oc apply -f maintenance-operator-config.yaml
$ oc get maintenanceoperatorconfig default -n nvidia-maintenance-operator
----

. Create the persistent volume claim for firmware files referenced by the `NicClusterPolicy` example.
Save the resource as `nic-firmware-pvc.yaml`:
+
[source,yaml]
----
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: nic-fw-storage-pvc
  namespace: nvidia-network-operator
spec:
  accessModes:
  - ReadWriteMany
  storageClassName: <RWX_STORAGE_CLASS>
  resources:
    requests:
      storage: 10Gi
----
+
Replace `<RWX_STORAGE_CLASS>` with a storage class available in the cluster.
+
Apply the claim and confirm that the cluster binds it to a volume:
+
[source,terminal]
----
$ oc apply -f nic-firmware-pvc.yaml
$ oc get pvc -n nvidia-network-operator
----

. Create the `NicClusterPolicy` custom resource to deploy the NVIDIA components for a single-plane configuration.
Save the resource as `nic-cluster-policy.yaml`:
+
[source,yaml]
----
apiVersion: mellanox.com/v1alpha1
kind: NicClusterPolicy
metadata:
  name: nic-cluster-policy
spec:
  nicConfigurationOperator:
    configurationDaemon:
      image: nic-configuration-operator-daemon
      repository: nvcr.io/nvidia/mellanox
      version: network-operator-v26.1.0
    nicFirmwareStorage:
      availableStorageSize: 1Gi
      create: false
      pvcName: nic-fw-storage-pvc
    operator:
      image: nic-configuration-operator
      repository: nvcr.io/nvidia/mellanox
      version: network-operator-v26.1.0
  nvIpam:
    enableWebhook: false
    image: nvidia-k8s-ipam
    repository: nvcr.io/nvidia/mellanox
    version: network-operator-v26.1.0
  ofedDriver:
    env:
    - name: UNLOAD_STORAGE_MODULES
      value: "true"
    forcePrecompiled: false
    image: doca-driver
    repository: nvcr.io/nvidia/mellanox
    version: doca3.3.0-26.01-1.0.0.0-0
    upgradePolicy:
      autoUpgrade: true
      drain:
        deleteEmptyDir: true
        enable: true
        force: true
        timeoutSeconds: 300
      maxParallelUpgrades: 1
      safeLoad: false
  secondaryNetwork:
    cniPlugins:
      image: plugins
      repository: nvcr.io/nvidia/mellanox
      version: network-operator-v26.1.0
  spectrumXOperator:
    image: spectrum-x-operator
    repository: nvcr.io/nvidia/mellanox
    version: network-operator-v26.1.0
----
+
The example uses NVIDIA Network Operator 26.1.0 and driver package version 3.3.0.
Change the component versions only as a compatible set confirmed by NVIDIA for the target platform.
+
If the NVIDIA registries require authentication, create and reference image pull secrets as described in the NVIDIA Network Operator documentation. Do not use empty credentials or publish registry credentials in configuration files.

. Apply the resource:
+
[source,terminal]
----
$ oc apply -f nic-cluster-policy.yaml
----

.Verification

* Confirm that the requested components become ready:
+
[source,terminal]
----
$ oc get nicclusterpolicy nic-cluster-policy
$ oc get pods -n nvidia-network-operator -o wide
----
+
Wait for the NVIDIA Network Operator, NIC Configuration Operator, IP address management (IPAM) controller, Spectrum-X Operator, and driver pods to become ready before configuring NIC firmware or creating rail resources.
