= Install the VCF Migration Operator

[role="_abstract"]
You can install the VCF Migration Operator from OperatorHub by using the {product-title} web console or the CLI.
After installation, you must create a secret that holds the credentials for the target vCenter.

.Prerequisites

* You have access to an {product-title} cluster version 4.18 or later that you installed by using installer-provisioned infrastructure on {vmw-full}.
* You have `cluster-admin` privileges.
* The Machine API Operator is healthy and managing node lifecycle on the cluster.
* The target vCenter is accessible from the cluster network.
* The `VSphereMultiVCenterDay2` feature gate is enabled on the cluster.

.Procedure

. Install the VCF Migration Operator by using one of the following methods:

** *Web console*: In the {product-title} web console, go to *Operators* -> *OperatorHub*. Search for *VCF Migration Operator* and click *Install*. On the *Install Operator* page, accept the default *All namespaces on the cluster* installation mode. Select `openshift-vcf-migration` as the installed namespace. Click *Install* and verify that the operator is displayed on the *Installed Operators* page with a status of *Succeeded*.

** *CLI*: Create the following YAML files and apply them with the `oc apply` command.
+
Create the target namespace:
+
[source,yaml]
----
apiVersion: v1
kind: Namespace
metadata:
  name: openshift-vcf-migration
----
+
Create an `OperatorGroup` object:
+
[source,yaml]
----
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: vcf-migration-operator
  namespace: openshift-vcf-migration
spec: {}
----
+
Create a `Subscription` object to install the Operator:
+
[source,yaml]
----
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: vcf-migration-operator
  namespace: openshift-vcf-migration
spec:
  channel: stable
  name: vcf-migration-operator
  source: redhat-operators
  sourceNamespace: openshift-marketplace
----
+
Apply the resources:
+
[source,terminal]
----
$ oc apply -f <namespace_file>.yaml
$ oc apply -f <operatorgroup_file>.yaml
$ oc apply -f <subscription_file>.yaml
----

. Verify that the Operator pod is running:
+
[source,terminal]
----
$ oc get pods -n openshift-vcf-migration
----
+
.Example output
[source,terminal]
----
NAME                                              READY   STATUS    RESTARTS   AGE
vcf-migration-operator-controller-manager-xxxxx   1/1     Running   0          30s
----

. Create a secret that holds the target vCenter credentials.
+
The secret keys must follow the format `<target_vcenter_fqdn>.username` and `<target_vcenter_fqdn>.password`.
+
In the following example, replace `<target_vcenter_fqdn>` with the fully qualified domain name of your target vCenter, and replace `<base64_encoded_username>` and `<base64_encoded_password>` with the Base64-encoded credentials:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: target-vcenter-creds
  namespace: openshift-vcf-migration
type: Opaque
data:
  <target_vcenter_fqdn>.username: <base64_encoded_username>
  <target_vcenter_fqdn>.password: <base64_encoded_password>
----
+
--
`<target_vcenter_fqdn>.username`:: The Base64-encoded username for the target vCenter. The key must include the vCenter FQDN as a prefix.
`<target_vcenter_fqdn>.password`:: The Base64-encoded password for the target vCenter. The key must include the vCenter FQDN as a prefix.
--
+
[NOTE]
====
The target vCenter user must have privileges to create tag categories, create tags, attach tags, and create VM folders.
The user requires `InventoryService.Tagging.CreateCategory`, `InventoryService.Tagging.CreateTag`, `InventoryService.Tagging.AttachTag`, `InventoryService.Tagging.ObjectAttachable`, and `Folder.Create` privileges.
====

. Apply the secret:
+
[source,terminal]
----
$ oc apply -f <secret_file>.yaml
----

.Verification

* Verify that the Operator is installed and the target vCenter secret exists:
+
[source,terminal]
----
$ oc get csv -n openshift-vcf-migration
----
+
[source,terminal]
----
$ oc get secret target-vcenter-creds -n openshift-vcf-migration
----

[NOTE]
====
For disconnected environments, you must mirror the VCF Migration Operator image to a local registry before installation.
Use standard Operator Lifecycle Manager (OLM) mirroring procedures to make the Operator available in your disconnected cluster.
====
