= Create firewall rules for reduced Workload Identity Federation permissions on {gcp-short}

[role="_abstract"]
Some {product-title} on {GCP} clusters use a reduced set of permissions for the Workload Identity Federation (WIF) configuration. To allow the cluster to function properly, you must create firewall rules in your {gcp-short} project that allow traffic between the cluster's control plane and worker nodes. This approach allows your network security team to maintain control over firewall rule management in the shared VPC host project without granting broad firewall creation and deletion privileges to {product-title}-managed service accounts.

[IMPORTANT]
====
If you create firewall rules by using this procedure, you are responsible for managing firewall rules through the lifetime of the cluster. The cluster's Cloud Controller Manager does not create or delete firewall rules automatically. If you expose a new service by using a load balancer or change the ingress configuration, you must create or update the corresponding firewall rules manually.
====

.Prerequisites

* You have configured a {gcp-short} project for {product-title} deployment.
* You have downloaded the latest version of the {cluster-manager} CLI (`ocm`) for your operating system from the link:https://console.redhat.com/openshift/downloads[Downloads] page on {cluster-manager}.
* You have a VPC network created in the project for the cluster to use. For more information, see link:https://cloud.google.com/vpc/docs/create-modify-vpc-networks[Create and manage VPC networks].
* You have created a Workload Identity Federation (WIF) configuration and know the WIF configuration ID. For more information, see _Create a Workload Identity Federation configuration_ in the _Additional resources_ section.

.Procedure

. Create the firewall rules by running the `ocm gcp create firewall-rules` command in `manual` mode only. The command generates a shell script containing the required `gcloud` commands. You must review and run the script yourself.
+
[source,terminal]
----
$ ocm gcp create firewall-rules \
    --mode manual \
    --name <firewall_rule_prefix> \
    --wif-config <wif_config_id> \
    --project-id <host_project_id> \
    --vpc-name <vpc_name> \
    --machine-cidr <machine_cidr> \
    --profile <public|private> \
    --output-file <output_file_path>
----
+
where:

`<firewall_rule_prefix>`:: A prefix for the firewall rule names. The command applies this prefix to all nine firewall rules created in the project. Use the cluster name or another identifier to distinguish these rules from other firewall rules in the project.
`<wif_config_id>`:: The ID of the Workload Identity Federation (WIF) configuration to use. The command retrieves the worker and control plane service account emails from the WIF configuration and assigns the firewall rules to those service accounts.
`<host_project_id>`:: The ID of the {gcp-short} project where the firewall rules will be created. For shared VPC deployments, this is the host project.
`<vpc_name>`:: The name of the VPC network for the cluster.
`<machine_cidr>`:: The CIDR range of the machine network, for example `10.0.0.0/16`.
`public|private`:: The firewall rule profile. Specify `public` for clusters with public API endpoints, or `private` for private clusters that use Private Service Connect. The `private` profile restricts source ranges to internal endpoints, while the `public` profile allows access from public endpoints for certain rules.
`<output_file_path>`:: Manual mode only. The path to the file where the command saves the generated script.

. Review the generated script and run it:
+
[source,terminal]
----
$ chmod +x <output_file_path>
$ ./<output_file_path>
----

.Verification

* Verify that the firewall rules were created successfully:
+
[source,terminal]
----
$ gcloud compute firewall-rules list \
  --project=<host_project_id> \
  --filter="network=<vpc_name>" \
  --format="table(name, direction, allowed, sourceRanges.list():label=SRC_RANGES, targetServiceAccounts.list():label=TARGET_SA)"
----
