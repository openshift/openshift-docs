= Compute machines without {vmw-short} integration

[role="_abstract"]
Provision physical or virtual compute machines manually and install {op-system-first} with your {product-title} cluster's worker configuration. These nodes join the cluster without {vmw-short} integration.

The target cluster is the existing {product-title} cluster on {vmw-short} that the new compute machines join. Run the {oc-first} commands in this workflow against the target cluster.

For a virtual machine (VM), use a virtualization environment other than {vmw-short}, such as {VirtProductName}. That environment supplies the processor, memory, virtual disks, and network interfaces. Create the VM in that environment, and then install {op-system} inside the VM by using the ISO procedure. The VM needs network access to the target cluster and its worker Ignition configuration.

For VMs hosted on {vmw-short}, use the procedures for adding {vmw-short} compute machines.

The ISO procedure uses `coreos-installer install` with `--platform=metal` for both physical machines and VMs. The `metal` value selects the Ignition platform for the new worker; the target cluster retains its {vmw-short} platform configuration.

You must provision and replace the added machines manually. The Machine API, compute machine sets, and cluster autoscaler do not provision or replace these machines. The Machine Config Operator (MCO) manages node configuration and operating system updates through machine config pools (MCPs).

If the added workers require configuration changes that differ from the existing workers, use a custom MCP to target those changes. The custom pool must inherit the worker configuration.

The requirement to disable the native {vmw-short} Container Storage Interface (CSI) driver applies to workload storage in the target cluster. Storage for a VM's virtual disks is configured in its virtualization environment.
