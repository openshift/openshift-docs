= Monitoring KMS encryption status

[role="_abstract"]
You can monitor KMS encryption status by checking cluster Operator conditions, health reporter output, and API server logs.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.

.Procedure

. Check the `kube-apiserver` cluster Operator for KMS-related degraded conditions by entering the following command:
+
[source,terminal]
----
$ oc get co kube-apiserver -o jsonpath='{range .status.conditions[*]}{.type}: {.status} - {.message}{"\n"}{end}'
----
+
A `KMSPluginsDegraded` condition with a status of `True` indicates a KMS plugin health issue on one or more nodes. // cite:1
// cite:1 VERIFIED [90]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L1041-L1043 - KMSPluginsDegraded _Degraded suffix routes to ClusterOperator Degraded via StatusSyncer; "admin-facing signal" surfaces through oc get co kube-apiserver

. View per-node KMS plugin health by entering the following command: // cite:2
+
[source,terminal]
----
$ oc get kubeapiserver cluster -o json | jq -r '.status.conditions[] | select(.type | startswith("KMSHealthReporter")) | "\(.type): \(.message)"'
----
+
Each condition shows the health status and remote key ID for each KMS plugin on that node. // cite:3
// cite:2 VERIFIED [90]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L842 - Condition type: KMSHealthReporter_<nodeName>, written by each per-pod reporter
// cite:2 VERIFIED [90]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L970 - "KMSHealthReporter_<nodeName>" confirmed as condition type pattern
// cite:3 VERIFIED [90]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L822-L824 - Each probe produces PluginHealthCondition with health status and key_id per plugin

. Check the kube-apiserver Operator logs for KMS-related events by entering the following command:
+
[source,terminal]
----
$ oc logs -n openshift-kube-apiserver-operator deploy/kube-apiserver-operator | grep -i kms
----

. View API server logs for KMS-related events by entering the following command:
+
[source,terminal]
----
$ oc logs -n openshift-kube-apiserver -l apiserver=true --tail=100 | grep -i kms
----

. Verify the KMS encryption configuration by entering the following command:
+
[source,terminal]
----
$ oc get apiserver cluster -o jsonpath='{.spec.encryption}' | jq
----
