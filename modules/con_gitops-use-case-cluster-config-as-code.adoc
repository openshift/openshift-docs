= Cluster configuration as code

[role="_abstract"]
Cluster configuration as code uses GitOps to manage {OCP} cluster settings and infrastructure components declaratively. Instead of manually configuring clusters through the web console or CLI, you define all configurations in Git and let Argo CD apply them automatically.

With this approach, you store cluster-scoped resources in Git repositories, including:

* Namespace definitions and resource quotas
* Custom resource definitions (CRDs)
* Role-based access control (RBAC) policies and cluster roles
* Network policies and security policies
* Operators and their configurations
* Infrastructure monitoring and logging configurations

This practice brings infrastructure management into the same workflow as application delivery:

* *Reproducibility* - Create identical clusters from the same Git repository, ensuring consistency across environments.
* *Disaster recovery* - Quickly rebuild clusters from Git if infrastructure fails.
* *Change tracking* - All cluster configuration changes are tracked in Git with commit history and approval workflows.
* *Compliance* - Enforce policy-as-code by requiring all changes to go through Git pull requests and review processes.

Cluster configuration as code is particularly valuable for managing multiple clusters, meeting compliance requirements, and implementing infrastructure as code practices.

*Example configurations managed as code:*

* Deploy and configure the OpenShift logging and monitoring stacks
* Provision persistent storage configurations
* Configure cluster autoscaling policies
* Deploy compliance and security scanning tools
* Set up custom authentication providers
