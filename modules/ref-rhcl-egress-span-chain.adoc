= Span hierarchy for an outbound request

[role="_abstract"]
A request that passes through an egress `Gateway` object that carries an `AuthPolicy` custom resource (CR) and a `RateLimitPolicy` CR produces the following spans. The `wasm-shim` module creates a root span and a child span for each policy evaluation, and propagates the trace context to Authorino and Limitador through gRPC metadata.

.Example span hierarchy of the {prodname} filter trace
[source,text]
----
[kuadrant-filter] kuadrant_filter
├─ [kuadrant-filter] grpc (action=ratelimit)
│  ├─ [kuadrant-filter] grpc_request (ShouldRateLimit)
│  │  └─ [limitador] should_rate_limit
│  │     └─ [limitador] check_and_update
│  └─ [kuadrant-filter] grpc_response
├─ [kuadrant-filter] grpc (action=auth)
│  ├─ [kuadrant-filter] grpc_request (Check)
│  │  └─ [authorino] envoy.service.auth.v3.Authorization/Check
│  │     └─ [authorino] Check
│  └─ [kuadrant-filter] grpc_response
└─ [kuadrant-filter] headers (HttpResponseHeaders)
----

The gateway trace of the same request holds the proxy spans for the route to the external service.

.Span attributes for troubleshooting
[cols="1,1,2",options="header"]
|===
| Attribute | Span | Description

| `request_id`
| `kuadrant_filter`
| Correlates the trace with the access logs and the gateway trace

| `action`
| `grpc`
| Type of policy that the gateway evaluated, such as `auth` or `ratelimit`

| `sources`
| `grpc`
| Policy resource that triggered the action

| `grpc_service`
| `grpc_request`
| Upstream service that the gateway called

| `grpc_method`
| `grpc_request`
| gRPC method that the gateway called, such as `Check` or `ShouldRateLimit`
|===
