= Troubleshooting authentication proxy connectivity

[role="_abstract"]
You can diagnose and resolve issues with the component-scoped proxy for authentication by reviewing operator conditions, events, and pod environment variables.

Proxy validation warning events::
+
The proxy validation controller emits warning events when IdP endpoints are unreachable through the proxy. Check events by running the following command:
+
[source,terminal]
----
$ oc get events -n openshift-authentication-operator --field-selector reason=IdPEndpointUnreachable
----
+
Verify that the proxy URL is correct, the proxy server is running, and the cluster nodes can reach the proxy.

Authentication operator reports proxy errors::
+
A proxy-level failure such as connection refused, Domain Name System (DNS) resolution failure, or a Transport Layer Security (TLS) handshake error causes the `AVAILABLE` column to show `False`. The `Degraded` condition message also reports the proxy error details from the `ProxyConfigController` sub-controller. Check the operator status by running the following command:
+
[source,terminal]
----
$ oc get clusteroperator authentication -o jsonpath='{.status.conditions}' | jq .
----
+
.Example output
[source,json]
----
[
  {
    "type": "Available",
    "status": "False",
    "reason": "OAuthServerRouteEndpointAccessibleController_EndpointUnavailable",
    "message": "...proxyconnect tcp: dial tcp: lookup proxy.example.com: no such host"
  },
  {
    "type": "Progressing",
    "status": "True",
    "reason": "OAuthServerDeployment_PodsUpdating",
    "message": "deployment/oauth-openshift: 3/3 pods have been updated and 1/3 are available"
  },
  {
    "type": "Degraded",
    "status": "False",
    "reason": "AsExpected",
    "message": "ProxyConfigControllerDegraded: failed to append CA certificates to cert pool for proxy trustedCA..."
  }
]
----
+
Verify that the proxy server is running, the proxy URL and port are correct, and the `trustedCA` config map contains valid Privacy-Enhanced Mail (PEM)-encoded certificates.

All users locked out after proxy misconfiguration::
+
A misconfigured proxy can prevent the OAuth server from reaching the identity provider, locking out all OAuth-authenticated users. To recover access:
+
.. Log in by using `kubeadmin` credentials or client certificate authentication, both of which bypass OAuth.
.. Correct the proxy configuration:
+
[source,terminal]
----
$ oc edit authentication.operator.openshift.io cluster
----
.. Verify that the authentication operator returns to a healthy state:
+
[source,terminal]
----
$ oc get clusteroperator authentication
----
+
.Example output
[source,terminal]
----
NAME             VERSION   AVAILABLE   PROGRESSING   DEGRADED   SINCE   MESSAGE
authentication   5.0.0     True        False         False      10m
----

CA bundle not trusted by OAuth server::
+
If the OAuth server cannot verify the proxy TLS certificate, check the following:
+
* The config map exists in `openshift-config` with valid PEM-encoded certificates under the key `ca-bundle.crt`.
* The `spec.proxy.trustedCA.name` value matches the actual config map name.
* The CA certificate chain is complete, including intermediate certificates.
+
The operator syncs the config map from `openshift-config` to `openshift-authentication` automatically.

Brief authentication outage on single-node {product-title}::
+
Changing the proxy URL triggers an OAuth server redeployment. On single-node deployments, this causes a brief outage because only one replica is available. Make proxy URL changes during a maintenance window. Updates to `trustedCA` config map content are hot-reloaded without redeployment.

LDAP group sync failing through proxy::
+
LDAP group sync `CronJob` resources are not managed by the authentication operator. Setting `spec.proxy` does not configure proxy settings for LDAP group sync. Configure proxy environment variables on the `CronJob` pod specification independently. For example:
+
[source,yaml]
----
apiVersion: batch/v1
kind: CronJob
metadata:
  name: ldap-group-sync
spec:
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: sync
            env:
            - name: HTTPS_PROXY
              value: "http://proxy.example.com:3128"
----

Cluster-wide proxy and component-scoped proxy both configured::
+
The component-scoped proxy takes full precedence for authentication components. No fields are inherited from the cluster-wide proxy. To verify which proxy is active, inspect the OAuth server pod environment variables by running the following command:
+
[source,terminal]
----
$ oc get deployment oauth-openshift -n openshift-authentication -o jsonpath='{.spec.template.spec.containers[0].env}' | jq .
----
+
.Example output
[source,json]
----
[
  {
    "name": "HTTP_PROXY",
    "value": "http://proxy.example.com:3128"
  },
  {
    "name": "HTTPS_PROXY",
    "value": "http://proxy.example.com:3128"
  },
  {
    "name": "NO_PROXY",
    "value": ".example.com,.cluster.local,.svc,127.0.0.1,172.30.0.1,localhost"
  }
]
----
+
The `NO_PROXY` value includes your configured entries and automatically appended cluster-internal defaults.
