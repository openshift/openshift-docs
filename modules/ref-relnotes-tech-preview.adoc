= Technology Preview features

[role="_abstract"]
You can try the Technology Preview features that are available with {product-title} {version}.

[IMPORTANT]
====
Technology Preview features are not supported with Red Hat production service level agreements (SLAs). These features might not be functionally complete. {rh} does not recommend using them in production.

Technology Preview features give you early access to upcoming product features. You can use these features to test new tools early and share your feedback. For more information, see https://access.redhat.com/support/offerings/techpreview[{rh} Technology Preview Features - Scope of Support].
====

Egress Gateway management::

With this release of {prodname}, you can configure, secure, and monitor outbound traffic leaving your cluster as a Technology Preview feature. You must use {service-mesh} to use an egress gateway. With this enhancement, you can complete the following tasks:

* Enforce request limits on egress traffic by to protect against third-party API quota exhaustion.
* Verify internal workloads making outbound calls.
* Securely fetch API credentials from external secret stores and inject them into outbound headers.
* Gain visibility into outbound service health and network traffic by using metrics and access logs.

For more information, see xref:../configure/egress_gateway/rhcl-egress-gateway.adoc#rhcl-egress-gateway[Set up outbound traffic from your cluster].

Extension SDK now available::

With this update, extension SDK is available as a Technology Preview. You can build, package, and deploy custom policy extensions on your own release cadence without modifying core {prodname} Operator logic. Running as independent workloads, gRPC-based extensions dynamically adapt to cluster topology changes, such as `Gateway` object listeners, and shape per-request data plane behavior by using CEL expressions, HTTP request and response actions, and custom gRPC service callouts.

DNS failover with groups::

With this release, DNS groups let you shift traffic to a standby cluster during a planned migration or outage as a Technology Preview. Update the active-groups TXT record to activate the standby group, and use Prometheus metrics to monitor group status and cleanup. For more information, see xref:../configure/dns-failover.adoc#rhcl-dns-failover[Configure DNS failover with groups].
