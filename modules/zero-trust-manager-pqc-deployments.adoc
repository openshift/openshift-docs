= Supported deployments for post-quantum key exchange

[role="_abstract"]
Hybrid key exchange is available on clusters where you already install {zero-trust-full}. It uses the existing operator installation, including the same images in a restricted network, and it has no topology-specific setting.

This behavior applies to the following deployments:

* Self-managed and managed {product-title} clusters where {zero-trust-full} is installed.
* Multi-node clusters, {3no}, and {sno-caps}, where {zero-trust-full} is already supported.
* Connected clusters and restricted-network clusters. Mirror the same operator and operand images that you mirror for {zero-trust-full}. Hybrid Module-Lattice-Based Key-Encapsulation Mechanism (ML-KEM) uses those images and does not add a payload.

On managed clusters, the cluster TLS security profile might be set by the service owner. The operands still follow `spec.tlsSecurityProfile` on `apiserver.config.openshift.io/cluster`.
