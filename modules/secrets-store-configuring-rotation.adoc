= Configuring secret rotation for the Secrets Store CSI Driver

[role="_abstract"]
You can configure secret rotation intervals to control how often mounted secrets are refreshed from external stores, or disable rotation for static secrets based on your specific security and operational requirements.

By default, secret rotation is enabled. When rotation is enabled, the {secrets-store-operator} polls the external secret store at a configurable interval to check for secret updates. This process ensures that updates in the external store are automatically reflected in your pods and secrets. By default, polling interval is 2 minutes. 

If you enabled synchronization of mounted content as Kubernetes secrets, the Kubernetes secrets are also rotated when the external secrets are updated.

Applications consuming the secret data must watch for file system changes to detect updated secrets. The {secrets-store-operator} updates the content of the mounted volume, and applications should reload the secrets when changes are detected.

.Prerequisites

* The {secrets-store-operator} is installed on the cluster.
* You have access to the cluster with `cluster-admin` privileges.

.Procedure

. Edit the `ClusterCSIDriver` custom resource for the {secrets-store-operator}:
+
[source,terminal]
----
$ oc edit clustercsidrivers.operator.openshift.io secrets-store.csi.k8s.io
----

. Locate or add the `secretRotation` section under `spec.driverConfig.secretsStore`. To enable secret rotation with a custom polling interval, set the type to `Custom` and configure the `minimumRefreshAge` field:
+
[source,yaml]
----
apiVersion: operator.openshift.io/v1
kind: ClusterCSIDriver
metadata:
  name: secrets-store.csi.k8s.io
spec:
  driverConfig:
    driverType: SecretsStore
    secretsStore:
      secretRotation:
        type: Custom
        custom:
          minimumRefreshAge: 300
----
+
where:

`spec.driverConfig.secretsStore.secretRotation.type`:: Specify the secret rotation mode. Set to `Custom` to enable secret rotation with a custom interval, or `None` to disable rotation. When rotation is disabled, secrets are fetched only at initial pod mount time.

`spec.driverConfig.secretsStore.secretRotation.custom.minimumRefreshAge`:: Specify the minimum number of seconds between rotation attempts. Valid range is 1 to 31,560,000 seconds (approximately 1 year). If omitted when `type` is `Custom`, the platform applies a default of 120 seconds.
+
[TIP]
====
Choose a refresh interval based on your security and cost requirements:

* For secrets that change frequently and require quick updates, use shorter intervals such as `60` (60 seconds) or `120` (2 minutes).
* For secrets that change infrequently, use longer intervals such as `600` (10 minutes) or `3600` (1 hour) to reduce transaction costs and performance overhead.
====

. To disable secret rotation completely, set the `type` field to `None`:
+
[source,yaml]
----
apiVersion: operator.openshift.io/v1
kind: ClusterCSIDriver
metadata:
  name: secrets-store.csi.k8s.io
spec:
  driverConfig:
    driverType: SecretsStore
    secretsStore:
      secretRotation:
        type: None
----
+
When rotation is disabled, secrets are fetched only at initial pod mount time and are not updated thereafter, even if the values change in the external secret store.

. Save and apply the changes to the custom resource.

.Verification

. Verify that the {secrets-store-operator} driver pods are updated with the new configuration:
+
[source,terminal]
----
$ oc get pods -n openshift-cluster-csi-drivers | grep secrets-store
----
+
.Example output
[source,terminal]
----
secrets-store-csi-driver-node-bhp2d                  3/3     Running   0          45s
secrets-store-csi-driver-node-xyz12                  3/3     Running   0          45s
secrets-store-csi-driver-operator-74696fc7bc-qjrl8   1/1     Running   0          7m40s
----

. Check the `ClusterCSIDriver` configuration to confirm the rotation settings:
+
[source,terminal]
----
$ oc get clustercsidrivers.operator.openshift.io secrets-store.csi.k8s.io -o jsonpath='{.spec.driverConfig.secretsStore.secretRotation}' | jq
----
+
.Example output
[source,terminal]
----
{
  "custom": {
    "minimumRefreshAge": 300
  },
  "type": "Custom"
}
----

. For pods that mount secrets from the external store, monitor the file system to verify that the CSI driver rotates secrets according to the configured interval.
