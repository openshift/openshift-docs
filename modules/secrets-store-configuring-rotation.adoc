= Configuring secret rotation for the Secrets Store CSI Driver

[role="_abstract"]
You can configure secret rotation settings for the {secrets-store-operator} to control how frequently the operator polls external secret stores for updates. This enables you to balance security requirements with operational efficiency.

.Prerequisites

* The {secrets-store-operator} is installed on the cluster.
* You have access to the cluster with `cluster-admin` privileges.

.Procedure

. Edit the `Driver` custom resource for the {secrets-store-operator}:
+
[source,terminal]
----
$ oc edit driver.csidriver.openshift.io/secrets-store.csi.k8s.io
----

. Locate or add the `rotation` section in the `spec` field. To enable secret rotation with a custom polling interval, configure the `enabled` and `pollingInterval` fields:
+
[source,yaml]
----
apiVersion: csidriver.openshift.io/v1
kind: Driver
metadata:
  name: secrets-store.csi.k8s.io
spec:
  rotation:
    enabled: true <1>
    pollingInterval: "5m" <2>
----
<1> Set to `true` to enable secret rotation, or `false` to disable rotation. When rotation is disabled, the `RequiresRepublish` flag is set to `false`, preventing unnecessary kubelet calls.
<2> Specify the interval for checking external secret stores for updates. Valid values are duration strings, such as `30s` (30 seconds), `2m` (2 minutes), `1h` (1 hour). The default value is `2m`.
+
[TIP]
====
Choose a polling interval based on your security and cost requirements:

* For secrets that change frequently and require quick updates, use shorter intervals such as `30s` or `1m`.
* For secrets that change infrequently, use longer intervals such as `10m` or `1h` to reduce transaction costs and performance overhead.
* For static secrets that never change, consider disabling rotation entirely by setting `enabled: false`.
====

. To disable secret rotation completely, set the `enabled` field to `false`:
+
[source,yaml]
----
apiVersion: csidriver.openshift.io/v1
kind: Driver
metadata:
  name: secrets-store.csi.k8s.io
spec:
  rotation:
    enabled: false
----
+
When rotation is disabled, secrets are mounted only when pods start and are not updated thereafter, even if the values change in the external secret store.

. Save and apply the changes to the custom resource.

.Verification

. Verify that the {secrets-store-operator} driver pods have been updated with the new configuration:
+
[source,terminal]
----
$ oc get pods -n openshift-cluster-csi-drivers -l app=secrets-store-csi-driver
----
+
.Example output
[source,terminal]
----
NAME                                    READY   STATUS    RESTARTS   AGE
secrets-store-csi-driver-node-4x2xq     3/3     Running   0          2m
secrets-store-csi-driver-node-7s8vz     3/3     Running   0          2m
secrets-store-csi-driver-operator-...   1/1     Running   0          5m
----

. Check the driver configuration to confirm the rotation settings:
+
[source,terminal]
----
$ oc get driver.csidriver.openshift.io/secrets-store.csi.k8s.io -o jsonpath='{.spec.rotation}' | jq
----
+
.Example output
[source,terminal]
----
{
  "enabled": true,
  "pollingInterval": "5m"
}
----

. For pods that mount secrets from the external store, monitor the logs to verify that secrets are being rotated according to the configured interval:
+
[source,terminal]
----
$ oc logs -n openshift-cluster-csi-drivers <secrets-store-csi-driver-node-pod> -c secrets-store
----
