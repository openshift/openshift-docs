= Hybrid ML-KEM key exchange

[role="_abstract"]
The `Old`, `Intermediate`, and `Modern` TLS security profiles include hybrid post-quantum key-exchange groups. In a TLS 1.3 handshake, the server selects one of these groups when the client supports it. No component adds a separate post-quantum setting for this handshake.

The hybrid groups are `X25519MLKEM768`, `SecP256r1MLKEM768`, and `SecP384r1MLKEM1024`. Each group combines a Module-Lattice-Based Key-Encapsulation Mechanism (ML-KEM) with a classical elliptic curve: `X25519`, `secp256r1`, or `secp384r1`. The server offers these hybrid groups together with the classical groups in the same profile. The handshake uses a hybrid group when the client supports one. The handshake uses a classical group when the client supports only classical groups.

A default cluster uses the `Intermediate` profile. The `Intermediate` profile requires TLS 1.2 or later and allows TLS 1.3, so the server negotiates hybrid ML-KEM with a client that supports a hybrid group.

Hybrid groups keep a classical algorithm in the key exchange. {product-title} does not support pure ML-KEM, which uses ML-KEM without a classical curve in the same group. The TLS security profile excludes post-quantum signature algorithms.

[NOTE]
====
The hybrid ML-KEM groups are not FIPS-approved. In FIPS mode, components exclude these groups from the key exchange.
====

The cluster `APIServer` custom resource (CR), `apiserver.config.openshift.io/cluster`, holds the control plane TLS security profile. The `IngressController` CR overrides that profile in `spec.tlsSecurityProfile`. The `KubeletConfig` CR holds the kubelet TLS security profile.

{zero-trust-full} does not include a custom resource field to enable or require hybrid ML-KEM. During a TLS 1.3 key exchange, a {spire-full} (SPIRE) server listener offers `X25519MLKEM768`, `SecP256r1MLKEM768`, and `SecP384r1MLKEM1024` together with the classical groups. For workload-to-workload mutual TLS, {zero-trust-full} issues the {spiffe-full} identity, and the TLS stack of each workload selects the key-exchange group.
