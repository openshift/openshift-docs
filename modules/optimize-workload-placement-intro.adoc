= Optimize workload placement

[role="_abstract"]
Optimize how {product-title} places pods on nodes to achieve your performance, availability, and resource utilization goals.

Pod placement affects application performance, high availability, and resource utilization. {product-title} provides multiple mechanisms to control where pods run, including the default scheduler, scheduler profiles, node constraints, the descheduler, and secondary schedulers.

You can optimize workload placement for different goals:

* *High availability:* Spread pods across nodes and zones to ensure application resilience
* *Performance:* Group related pods together or place them on specific nodes to reduce latency
* *Resource utilization:* Balance workloads across the cluster and adjust node density
* *Specialized scheduling:* Use custom secondary schedulers for complex placement requirements that the default scheduler does not support

The default scheduler automatically places pods on nodes based on configured profiles and policies. You can customize scheduler behavior through profiles, node affinity, pod affinity and anti-affinity, taints and tolerations, and other constraints. The descheduler can rebalance pods after initial placement, and secondary schedulers provide additional flexibility for specialized workloads.
