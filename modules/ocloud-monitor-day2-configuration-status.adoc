= Monitor Day-2 configuration status

[role="_abstract"]
You can monitor the progress of Day-2 configuration changes by watching the `ProvisioningRequest` custom resource status conditions. The O-Cloud Manager reports the state of policy configuration and hardware configuration separately through dedicated status conditions.

.Prerequisites

* A Day-2 configuration change has been applied to the `ProvisioningRequest` CR.

.Procedure

. Check the policy configuration status by viewing the `ConfigurationApplied` condition by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -o jsonpath='{.status.conditions[?(@.type=="ConfigurationApplied")]}'
----
+
where:
+
--
`<uuid>`:: Specifies the UUID of the `ProvisioningRequest` CR for the target cluster.
--
+
[cols="1,1,2",options="header"]
|===
|Status |Reason |Description

|`False`
|`InProgress`
|The configuration is still being applied. One or more policies are `NonCompliant`.

|`True`
|`Completed`
|The configuration is up to date. All enforce policies are `Compliant`.
|===

. Check the hardware configuration status by viewing the `HardwareConfigured` condition by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -o jsonpath='{.status.conditions[?(@.type=="HardwareConfigured")]}'
----
+
[cols="1,1,2",options="header"]
|===
|Status |Reason |Description

|`False`
|`InProgress`
|Firmware or BIOS update is in progress.

|`True`
|`Completed`
|All nodes have been updated and validated.

|`False`
|`TimedOut`
|The update exceeded the configured timeout.

|`False`
|`Failed`
|The update failed on one or more nodes.
|===

. View per-policy compliance details by checking the `status.extensions.policies` field by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -o jsonpath='{.status.extensions.policies}' | jq .
----
+
.Example output
[source,json]
----
[
  {"compliant": "Compliant", "policyName": "v1-perf-configuration-policy", "policyNamespace": "ztp-sno-ran-du-v4-Y-Z", "remediationAction": "enforce"},
  {"compliant": "NonCompliant", "policyName": "v1-sriov-configuration-policy", "policyNamespace": "ztp-sno-ran-du-v4-Y-Z", "remediationAction": "enforce"}
]
----
+
* The `nonCompliantAt` timestamp in `status.extensions.clusterDetails` records when a policy first became `NonCompliant`.
* Once all policies return to `Compliant`, the `nonCompliantAt` value is removed and the `ConfigurationApplied` condition is updated.

. For hardware firmware updates on multi-node clusters, check per-node progress by viewing `AllocatedNode` CRs by running the following command:
+
[source,terminal]
----
$ oc get allocatednodes.clcm.openshift.io -A -o json | \
  jq -r '["NAME","CURRENTPROFILE","REASON","DETAILS"],
         (.items[] | [.metadata.name, .status.hwProfile,
           (.status.conditions[]? | select(.type=="Configured") | .reason),
           (.status.conditions[]? | select(.type=="Configured") | .message)]) | @tsv' | \
  column -t -s $'\t'
----
+
When a node `status.hwProfile` matches `spec.hwProfile`, the update for that node is complete.
