= Discover and evaluate the platform

[role="_abstract"]
Understand the capabilities and architecture of {VirtProductName}, and how it compares to hypervisor-based virtualization, so you can decide whether it fits your environment and learn what a deployment would require.

{VirtProductName} runs virtual machines (VMs) as Kubernetes workloads on the same cluster, scheduler, and storage as your containers. The VM lifecycle stays the same. The layer underneath changes: {product-title}, not a separate virtualization platform. Evaluate whether that change works for the workloads you run.

Start with what the platform can do, then compare it against what you run today. If you are coming from {vmw-full}, a concept-by-concept comparison shows which of your workflows carry over unchanged, which have a close equivalent, and which have none at all. Focus on the workflows with no equivalent.

Confirm that your environment qualifies before you plan any further. Cluster version and topology both limit what you can deploy, and a single-node cluster differs enough to check early.

Compute, storage, networking, and scaling each come from a separate Operator, all deployed and managed through the `HyperConverged` custom resource. Learning which Operator owns which capability makes configuration and troubleshooting easier later.

When you would rather see the platform running than read about it, the guided tour and the quick starts walk you through the web console on a live cluster.
