= HTTPRoute hostnames and parentRefs configuration

[role="_abstract"]
To attach an `HTTPRoute` custom resource (CR) to a gateway and select which HTTP Host headers it handles, you configure `spec.parentRefs` and `spec.hostnames`. Parent references bind the route to a `Gateway` CR. Hostnames match requests before the route rules are evaluated.

== HTTPRoute parentRefs

`parentRefs` lists the parent resources, usually `Gateway` CRs, that the route wants to attach to. You can specify a maximum of 32 parent references. Attachment succeeds only when the parent allows routes of this kind from the `HTTPRoute` namespace. On {product-title}, parent references typically target a `Gateway` CR whose `GatewayClass` uses the `openshift.io/gateway-controller/v1` controller.

{product-title} provisions a load balancer `Service` and data-plane workload for each `Gateway` CR. You cannot manually deploy the gateway data plane, and you cannot merge listeners from separate gateways onto a shared service. Point each `parentRef` at a distinct `Gateway` CR.

You can customize parent references using the following fields:

`parentRefs.name`::
Specifies the name of the parent `Gateway` CR. This field is required.

`parentRefs.namespace`::
Specifies the namespace of the parent `Gateway` CR. If you omit this field, the controller looks for the gateway in the same namespace as the `HTTPRoute` CR. When the gateway is in `openshift-ingress` and the route is in an application namespace, set this field to `openshift-ingress`. The gateway listener must allow routes from the `HTTPRoute` namespace.

`parentRefs.sectionName`::
Binds the route to a single named listener on the parent gateway. If you omit this field, the route can attach to any listener that allows it. If at least one listener accepts the route, the attachment is successful. If the parent gateway has more than one listener, set `sectionName` so the route attaches to the intended protocol and port.

`parentRefs.port`::
Binds the route to every listener on that port that supports this route kind and selects this route. Use `port` only when the route must apply to a specific port rather than to a named listener.
+
[NOTE]
====
The `port` field in `parentRefs` is classified as an extended feature (`Support: Extended`) according to Gateway API conventions.
====

`parentRefs.kind` and `parentRefs.group`::
Identify the parent resource type. When unspecified, `kind` defaults to `Gateway` and `group` defaults to `gateway.networking.k8s.io`.

[NOTE]
====
Parent references must be distinct. Two entries cannot select the same gateway with the same optional fields.

* If they select different objects, the combination of `group`, `kind`, `namespace`, and `name` must be unique.
* If they select the same gateway, set the same combination of optional fields on every entry, and give each entry a different value. If one `parentRef` sets `sectionName`, every `parentRef` to that gateway must set `sectionName`. If one sets `port`, every `parentRef` to that gateway must set `port`. If one sets both `sectionName` and `port`, every `parentRef` to that gateway must set both.
====

== Example: Attach to a named listener in another namespace

The following example attaches an `HTTPRoute` CR in an application namespace to the `https` listener of a gateway in `openshift-ingress`:

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: <example_route>
  namespace: <example_application>
spec:
  parentRefs:
  - name: <example_gateway>
    namespace: openshift-ingress
    sectionName: https
  hostnames:
  - app.<example_domain.tld>
  rules:
  - backendRefs:
    - name: <example_service>
      port: 8080
----
* `name` identifies the parent `Gateway` CR.
* `namespace` is required when the gateway is not in the same namespace as the route.
* `sectionName` must match a listener `name` on the parent `Gateway` CR.

== HTTPRoute hostnames

`hostnames` lists fully qualified domain names that must match the HTTP Host header before the controller evaluates route rules. You can specify a maximum of 16 hostnames. Implementations ignore any port in the Host header. Hostnames cannot be IP addresses. You can prefix a hostname with a wildcard label (`*.`) as the first label only. For example, `*.example.com` is valid, but `*foo.example.com` is not. A wildcard hostname is a suffix match. For example, `*.example.com` matches `shop.example.com` and `foo.shop.example.com`, but does not match `example.com`.

The Ingress Operator installs a `ValidatingAdmissionPolicy` that validates `HTTPRoute` hostnames against cluster security policies.

The Ingress Operator creates `DNSRecord` CRs for listener hostnames when the `Gateway` CR is in the `openshift-ingress` namespace and the hostname matches the cluster base domain. The Operator does not create DNS records for hostnames that you set only on an `HTTPRoute` CR. Set HTTPRoute hostnames that match, or are subdomains of, the attached listener hostnames. For more information, see xref:../../../networking/ingress_load_balancing/configuring_gateway_api/assigning-network-addresses-gateways.adoc#assigning-network-addresses-gateways[Assign network addresses to gateways].

Hostname matching between a listener and an `HTTPRoute` CR is an intersection used for routing, not a permission check:

* If both the listener and the route set hostnames, at least one hostname must intersect or the route is not accepted. The controller sets the `Accepted` condition to `False` on that parent, typically with the `NoMatchingListenerHostname` reason.
* If both set hostnames and some route hostnames do not intersect, the controller ignores the non-intersecting hostnames and uses only the intersection.
* If the route omits hostnames, it inherits the listener hostname.
* If the listener omits hostnames, any attaching route can claim hostnames. Always set a listener hostname unless you are defining a catch-all route.

When multiple `HTTPRoute` CRs specify intersecting hostnames, the controller prefers the route whose matching non-wildcard hostname has the most characters, then the matching hostname with the most characters.

== Example: Wildcard listener with precise route hostnames

The following example shows an `HTTPRoute` CR whose hostnames must fall under the parent listener hostname `*.<example_domain.tld>`:

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: <example_route>
  namespace: <example_application>
spec:
  parentRefs:
  - name: <example_gateway>
    namespace: openshift-ingress
    sectionName: https
  hostnames:
  - app1.<example_domain.tld>
  - app2.<example_domain.tld>
  rules:
  - backendRefs:
    - name: <example_service>
      port: 8080
----
* Incoming requests are matched against `hostnames` before `rules` are evaluated.
* A listener hostname of `*.<example_domain.tld>` accepts these hostnames. Hostnames outside that suffix, such as `app.other.tld`, do not intersect and are not accepted.
