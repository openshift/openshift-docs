= Creating execution RBAC for the agentic Operator

[role="_abstract"]
Create the execution role-based access control (RBAC) that the agentic Operator requires to run the execution step of an `AgenticRun`.

[NOTE]
====
The OLM-granted `ClusterRole` for the agentic Operator only covers core resources, agentic CRDs, and RBAC. When the execution step creates a per-run `Role` granting the sandbox access to deployments, jobs, and similar resources, Kubernetes RBAC escalation prevention blocks it because the Operator service account does not have those permissions itself. The quickstart sidesteps this by granting `cluster-admin`. The following `ClusterRole` is a scoped alternative.
====

.Prerequisites

* You have installed the {ols-long} Operator.

* You have `cluster-admin` access to the cluster.

.Procedure

* Create the execution `ClusterRole` and `ClusterRoleBinding` by running the following command:
+
[source,terminal]
----
$ oc apply -f - <<'EOF'
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: agentic-operator-escalation
rules:
- apiGroups: ["", "apps", "batch", "networking.k8s.io"]
  resources: ["*"]
  verbs: ["get", "list", "watch", "create", "update", "patch", "delete"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: agentic-operator-escalation-binding
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: agentic-operator-escalation
subjects:
- kind: ServiceAccount
  name: lightspeed-agentic-operator-controller-manager
  namespace: openshift-lightspeed
EOF
----
