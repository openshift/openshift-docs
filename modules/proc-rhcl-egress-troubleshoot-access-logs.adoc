= Diagnose failed outbound requests

[role="_abstract"]
Find the cause of a failed outbound request by reading the access logs of your egress `Gateway` object and then inspecting the connection statistics of the external service.

.Prerequisites

include::snippets/egress-gateway-prereqs.adoc[]

* You enabled access logs on your egress `Gateway` object.

.Procedure

. Read the access logs of your egress `Gateway` object by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc logs -n _<gateway_system>_ -l gateway.networking.k8s.io/gateway-name=_<kuadrant_egressgateway>_ -f
----
+
* Replace `_<gateway_system>_` with the namespace where you applied your egress `Gateway` object.
* Replace `_<kuadrant_egressgateway>_` with the name of your egress `Gateway` object.

. Find the entry for the failed request, and note the response code, the response flags, and the response code details. For an explanation of each field, see "Access log fields for egress traffic".

. Store the name of the egress gateway pod in a variable by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ export EGRESS_POD=$(oc get pods -n _<gateway_system>_ \
    -l gateway.networking.k8s.io/gateway-name=_<kuadrant_egressgateway>_ \
    -o jsonpath='{.items[0].metadata.name}')
----

. Read the connection statistics for the external service from the administration endpoint of the gateway by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc exec -n _<gateway_system>_ ${EGRESS_POD} -- \
    pilot-agent request GET /clusters | grep "outbound|443||_<api.example.com>_::" | \
    grep -E "(cx_total|cx_connect_fail|rq_total|rq_error|rq_success|rq_timeout|health_flags)"
----
+
Replace `_<api.example.com>_` with the hostname of your external service.
+
.Example output
[source,text]
----
outbound|443||api.example.com::198.51.100.155:443::cx_total::1
outbound|443||api.example.com::198.51.100.155:443::cx_connect_fail::0
outbound|443||api.example.com::198.51.100.155:443::rq_total::1
outbound|443||api.example.com::198.51.100.155:443::rq_error::1
outbound|443||api.example.com::198.51.100.155:443::rq_success::0
outbound|443||api.example.com::198.51.100.155:443::health_flags::healthy
----

. Interpret the statistics for each resolved address of the external service:
+
* The `cx_total` and `cx_connect_fail` counters show how many connections the gateway opened and how many of those failed.
* The `rq_total`, `rq_success`, and `rq_error` counters show how many requests the gateway sent and how many of those failed.
* A `cx_connect_fail` value of `0` with an `rq_error` value above `0` means that the gateway reached the external service and the external service returned the errors.

. Confirm the source of the failure in the access log entry. An HTTP error code with a `-` response flag means that the external service returned the error. A `UF` or `UT` response flag means that the failure occurred at the proxy level.
