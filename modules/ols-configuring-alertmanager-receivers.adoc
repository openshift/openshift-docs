= Configure Alertmanager receivers

[role="_abstract"]
Before you configure `allowedReceivers`, review your cluster's Alertmanager configuration to identify the receiver names you can authorize. Alertmanager configuration for core platform monitoring is stored in the `alertmanager-main` secret in the `openshift-monitoring` project.

.Procedure

. Inspect the current configuration:
+
[source,terminal]
----
$ oc get secret alertmanager-main -n openshift-monitoring -o jsonpath='{.data.alertmanager\.yaml}' | base64 -d
----
+
The following example shows a default configuration. Your configuration might differ.
+
[source,yaml]
----
# [some parts omitted for simplicity]
receivers:
  - name: Default
  - name: Watchdog
  - name: Critical
route:
  receiver: Default
  group_by:
    - namespace
  routes:
    - receiver: Watchdog
      matchers:
        - alertname = "Watchdog"
    - receiver: Critical
      matchers:
        - severity = "critical"
----

. In this configuration, note the two elements that control filtering:
+
--
* The `receivers` section defines the available receiver names. In this example, the receivers are `Default`, `Watchdog`, and `Critical`. These are the names you can list under `allowedReceivers`.
* The `route` section defines the routing rules that assign each firing alert to a receiver based on its labels. In this example, alerts with the `severity = "critical"` label are routed to the `Critical` receiver, and any alert that matches no other route falls through to the `Default` receiver.
--

. To investigate alerts for a different severity or alert label, define a new receiver and route. The following example adds a `Warning` receiver for alerts with the `severity = "warning"` label:
+
[source,yaml]
----
receivers:
  - name: Warning
route:
  routes:
    - receiver: Warning
      matchers:
        - severity = "warning"
----
