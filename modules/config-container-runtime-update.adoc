= Changing the container runtime to crun for updated clusters

[role="_abstract"]
You can override the default runC container runtime to crun on clusters that used specific versions of {product-title} 4.17.z by deleting specific `MachineConfig` objects. 

Starting in {product-title} 4.18, crun is the default container runtime for new installations. However, if your cluster used {product-title} 4.17.11 or a later 4.17.z release, whether it was installed on 4.17 or updated to it, after you updated the cluster to 4.18, the container runtime remained as runC. 

This is because the Machine Config Operator created two `MachineConfig` objects, `00-override-master-generated-crio-default-container-runtime` and `00-override-worker-generated-crio-default-container-runtime`, that kept runC as the default container runtime on control plane and worker nodes respectively. Custom machine config pools retained runC through the worker object. 

You can migrate the cluster runtime on these clusters, on a schedule of your choosing, by removing either or both of the override `MachineConfig` objects.

[IMPORTANT]
====
Removing one of the override `MachineConfig` objects drains and reboots every node in the affected machine config pools. After the reboot, all workloads on those nodes use the new container runtime.
====

To check whether your cluster has these objects, you can run the following command:

[source,terminal]
----
$ oc get machineconfig -o name | grep generated-crio-default-container-runtime
----

These machine config objects remain after updates to 4.18 and later releases, including 5.0. 

.Procedure

* Migrate your worker nodes to crun by running the following command to delete the worker override `MachineConfig` object:
+
[source,terminal]
----
$ oc delete machineconfig 00-override-worker-generated-crio-default-container-runtime
----

* Migrate your control plane nodes to crun by running the following command to delete the control plane override `MachineConfig` object:
+
[source,terminal]
----
$ oc delete machineconfig 00-override-master-generated-crio-default-container-runtime
----

.Verification

* After the nodes return to a ready state, check the default container runtime on a node by running the following command:
+
[source,terminal]
----
$ oc debug node/<node_name> -- chroot /host crio status config | grep default_runtime
----
+
.Example output
[source,terminal]
----
    default_runtime = "crun"
----
+
The `default_runtime` parameter specifies the container runtime that {product-title} uses for new workloads on this node.
