= Changing the container runtime to crun for updated clusters

[role="_abstract"]
If your cluster used {product-title} 4.17.11 or a later 4.17.z release, whether it was installed on 4.17 or updated to it, the container runtime remains as runc after updating to 4.18 or later. You can update the cluster to use crun by deleting two specific `MachineConfig` objects.

In these clusters, the Machine Config Operator created two `MachineConfig` objects, `00-override-master-generated-crio-default-container-runtime` and `00-override-worker-generated-crio-default-container-runtime`, that keep runC as the default container runtime on control plane and worker nodes respectively. Custom machine config pools use runC through the worker object. These machine config objects remain after updates to 4.18 and later releases, including 5.0. You can migrate the container runtime to crun, on a schedule of your choosing, by removing either or both of the `MachineConfig` objects. 

Removing one of the override `MachineConfig` objects drains and reboots every node in the affected machine config pools. After the reboot, all workloads on those nodes use the new container runtime.

To check whether your cluster has these objects, you can run the following command:

[source,terminal]
----
$ oc get machineconfig -o name | grep generated-crio-default-container-runtime
----
