= Configuring ImageDigestMirrorSet with multiple mirrors for fallback

[role="_abstract"]
You can configure an ImageDigestMirrorSet custom resource with multiple mirrors to enable automatic fallback when a primary mirror encounters transient errors. This configuration allows OpenShift to pull image layers from secondary or tertiary mirrors without requiring manual intervention or marking the primary mirror as completely unavailable.

.Prerequisites
* You have cluster administrator access to the cluster.
* You have `kubectl` installed and configured to access the cluster.
* You understand the image digest reference format (SHA256 digest-based image references).
* Multiple mirror registries are deployed and contain the images you want to pull.
* You have verified network connectivity from the cluster to all configured mirrors.

.Procedure

. Determine the source registry and mirror repositories for your IDMS configuration.
+
For each source image registry you want to mirror (for example, `registry.redhat.io`), you need:
+
* The source registry URL
* A prioritized list of mirror registry URLs (primary, secondary, tertiary)
* The desired `mirrorSourcePolicy` value (`AllowContactingSource` for hybrid deployments or `NeverContactSource` for air-gapped clusters)

. Create an IDMS custom resource YAML file with multiple mirrors in fallback order.
+
[source,yaml]
----
apiVersion: config.openshift.io/v1
kind: ImageDigestMirrorSet
metadata:
  name: registry-mirror
spec:
  imageDigestMirrors:
  - source: registry.redhat.io
    mirrors:
    - quay.example.com                        <1>
    - mirror-backup.example.com               <2>
    - mirror.disaster-recovery.example.com    <3>
    mirrorSourcePolicy: AllowContactingSource <4>
  - source: quay.io
    mirrors:
    - local-quay.example.com
    - quay-backup.example.com
    mirrorSourcePolicy: NeverContactSource    <5>
----
+
<1> Primary mirror — attempted first for each layer
<2> Secondary mirror — attempted if primary fails with a transient error
<3> Tertiary mirror — attempted if secondary fails
<4> Allows fallback to the source registry (`registry.redhat.io`) after all mirrors fail; use for hybrid deployments
<5> Prevents fallback to the source registry (`quay.io`); required for air-gapped clusters

. Configure the mirrors to match your deployment architecture.
+
For a disconnected cluster with local primary mirror and remote backup:
+
[source,yaml]
----
apiVersion: config.openshift.io/v1
kind: ImageDigestMirrorSet
metadata:
  name: disconnected-mirrors
spec:
  imageDigestMirrors:
  - source: registry.redhat.io
    mirrors:
    - local-quay.cluster.local              # Primary: same cluster, low latency
    - quay-backup.us-east.example.com       # Secondary: remote data center
    - quay-dr.eu-west.example.com           # Tertiary: disaster recovery region
    mirrorSourcePolicy: NeverContactSource  # Enforce network isolation
----

. Apply the IDMS custom resource to your cluster.
+
[source,terminal]
----
$ kubectl apply -f /path/to/idms-config.yaml
----
+
The cluster acknowledges the resource:
+
[source,terminal]
----
imagedigestmirrorset.config.openshift.io/registry-mirror created
----

. Verify that the IDMS resource is accepted and active.
+
[source,terminal]
----
$ kubectl get imagedigestmirrorset registry-mirror
----
+
The output should show:
+
[source,terminal]
----
NAME              AGE
registry-mirror   2m
----

. Verify that the mirrors are applied to the cluster nodes by checking the registries configuration.
+
On each worker node, the mirror configuration is written to `/etc/containers/registries.conf`. To verify this on a specific node:
+
[source,terminal]
----
$ oc debug node/<node-name>
sh-4.4# cat /etc/containers/registries.conf | grep -A 10 "registry.redhat.io"
----
+
The output should show all configured mirrors in the correct order:
+
[source,terminal]
----
[[registry]]
location = "registry.redhat.io"
mirror-by-digest-only = true
[registry.mirror]
location = "quay.example.com"
[registry.mirror]
location = "mirror-backup.example.com"
[registry.mirror]
location = "mirror.disaster-recovery.example.com"
----

. (Optional) Configure authentication for mirrors if they require credentials.
+
If a mirror requires authentication (username and password or authentication token), create a pull secret:
+
[source,terminal]
----
$ oc create secret docker-registry <secret-name> \
  --docker-server=<mirror-registry> \
  --docker-username=<username> \
  --docker-password=<password> \
  -n openshift-config
----
+
Then link the secret to the service account used for image pulls (this is cluster-wide configuration handled by the ImagePullSecrets API).

. Test the IDMS configuration by creating a test pod that pulls an image from a configured source registry.
+
[source,yaml]
----
apiVersion: v1
kind: Pod
metadata:
  name: test-mirror-fallback
spec:
  containers:
  - name: test
    image: registry.redhat.io/ubi9/ubi-minimal:latest
  restartPolicy: Never
----
+
[source,terminal]
----
$ kubectl apply -f test-pod.yaml
$ kubectl get pod test-mirror-fallback -o wide
----

. (Optional) Simulate primary mirror failure to verify fallback behavior works correctly.
+
To safely test fallback without production impact, temporarily make the primary mirror unreachable on a single node:
+
[source,terminal]
----
$ oc debug node/<test-node-name>
sh-4.4# mount -o remount,rw /
sh-4.4# iptables -I OUTPUT -d quay.example.com -j DROP
----
+
Trigger an image pull on the node:
+
[source,terminal]
----
sh-4.4# crictl pull registry.redhat.io/ubi9/ubi-minimal:latest
----
+
Monitor the CRI-O logs to verify fallback behavior:
+
[source,terminal]
----
sh-4.4# journalctl -u crio -n 50 | grep "Trying to access"
----
+
You should see entries showing attempts from multiple mirrors. When done testing, restore connectivity:
+
[source,terminal]
----
sh-4.4# iptables -D OUTPUT -d quay.example.com -j DROP
----

. Verify cluster events and pod pull events to confirm fallback is working in production.
+
After deployment, monitor image pull events in your cluster:
+
[source,terminal]
----
$ oc get events -A --sort-by='.lastTimestamp' | grep -i "pull"
----
+
When fallback occurs, pod events show attempts from multiple mirrors:
+
[source,terminal]
----
REASON          MESSAGE
BackOff         Back-off pulling image...
Failed          Failed to pull image <source>: rpc error from multiple mirrors...
Pulled          Successfully pulled image <digest> from <mirror>
----

.Next steps
* Verify that mirror fallback functions correctly using the verification procedure in the xref:images-verify-mirror-fallback_{context}[Verifying mirror fallback functionality] guide.
* Troubleshoot mirror fallback issues using the procedures in the xref:images-troubleshoot-mirror-fallback-logs_{context}[Troubleshooting mirror fallback using CRI-O logs] guide.
* For air-gapped clusters, ensure that `mirrorSourcePolicy: NeverContactSource` is configured for all mirrors to enforce network isolation policies.
