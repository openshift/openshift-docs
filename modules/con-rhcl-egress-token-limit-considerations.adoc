= Token rate limiting considerations for egress traffic

[role="_abstract"]
Review the following behaviors before using a `TokenRateLimitPolicy` custom resource (CR) to control the artificial intelligence (AI) token consumption of an egress `Gateway` object.

TLS origination and access to the response body::

When workloads call an external AI service over the internet, the egress `Gateway` object terminates the connection from the workload and originates a new TLS connection to the external service. The response body passes through the `Gateway` object unencrypted on the internal side, so the `Gateway` object extracts the token count from the response as usual.

Concurrent requests and limit accuracy::

A limit tracks the configured budget closely only when it holds capacity for the requests that are in flight, which requires the `spec.limits._<limit_name>_.reservation.amount` field.
+
That field defaults to `0`. By default, concurrent requests that arrive before the first response returns can push the total consumption past the configured limit.
+
Responses from AI services are typically slow enough that an occasional overshoot is acceptable for most workloads. If you need strict enforcement under high concurrency, set a reservation amount on the limit. Otherwise, set limits that leave headroom for the number of requests that your workloads send in parallel.

Supported response formats::

Token extraction works with any external service that returns an OpenAI-compatible response body that has a `usage.total_tokens` field. Response formats that place the token count in a different structure are not supported.

Responses that omit token usage::

If the external AI service omits the `usage.total_tokens` field, or if the `Gateway` object cannot parse the field, the report phase fails. No tokens are counted. Both the check service and the report service default to a failure mode of `allow`, so the request succeeds and the counter remains unchanged. The result is that the policy does not enforce a limit.
+
[IMPORTANT]
====
Verify that your external AI service returns `usage.total_tokens` in every response before you rely on a `TokenRateLimitPolicy` CR for enforcement. For streaming responses, verify that each request sets the `stream_options.include_usage` field to `true`.
====
+
To reject the requests for which token extraction fails, set the `RATELIMIT_REPORT_SERVICE_FAILURE_MODE` environment variable to `deny` on the {prodname} Operator deployment. The `Gateway` object then blocks every response from which it cannot extract token usage. This setting applies to all `TokenRateLimitPolicy` CRs in the cluster.
