= Declarative cluster configuration with Argo CD

[role="_abstract"]
{gitops-title} uses Git repositories as the source of truth for your {OCP} cluster configuration, enabling declarative management of infrastructure and application settings through Argo CD.

Declarative cluster configuration provides the following benefits:

* *Version control and auditability*: Configuration changes committed to Git provide a complete history of modifications for auditing, compliance, and accountability.
* *Single source of truth*: Git defines the desired state of your {OCP} cluster, and Argo CD continuously reconciles the live cluster to match.
* *Disaster recovery*: Argo CD can point to a previous commit or tag with a known-good state, reducing downtime during recovery.
* *Scalability*: {gitops-shortname} standardizes deployment and operations workflows across multiple clusters and environments.

To manage your cluster configuration declaratively, you work with the following areas:

* *Default Argo CD instance*: Analyze, access, and configure the default Argo CD instance, including RBAC and permission settings.
* *Cluster configuration with applications*: Use a cluster-scoped Argo CD instance to deploy applications that define cluster-wide configurations, synchronize application state with Git repositories, and manage OLM Operators.
* *Permissions customization*: Customize Argo CD permissions for cluster-scoped instances by using user-defined cluster roles or aggregated cluster roles.
