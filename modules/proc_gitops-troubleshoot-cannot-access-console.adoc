= Cannot access Argo CD web console

[role="_abstract"]
Troubleshoot issues preventing access to the Argo CD web console, including route problems, certificate errors, and authentication failures.

.Prerequisites

* You have installed the {gitops-title} Operator.
* You have `cluster-admin` or sufficient permissions to view routes and deployments.

.Procedure

. Verify the Argo CD server pod is running:
+
[source,terminal]
----
$ oc get pods -n openshift-gitops -l app.kubernetes.io/name=openshift-gitops-server
----
+
*Example output:*
[source,terminal]
----
NAME                                      READY   STATUS    RESTARTS   AGE
openshift-gitops-server-7b5d8f6c4-xyz12   1/1     Running   0          10m
----
+
If the pod is not running, check pod events and logs:
+
[source,terminal]
----
$ oc describe pod <pod_name> -n openshift-gitops
$ oc logs <pod_name> -n openshift-gitops
----

. Verify the route exists and is accessible:
+
[source,terminal]
----
$ oc get route openshift-gitops-server -n openshift-gitops
----
+
*Example output:*
[source,terminal]
----
NAME                      HOST/PORT                                         PATH   SERVICES                  PORT    TERMINATION     WILDCARD
openshift-gitops-server   openshift-gitops-server-openshift-gitops.apps...        openshift-gitops-server   https   reencrypt/None   None
----
+
If the route does not exist, the Argo CD CR may be misconfigured. Check the Argo CD custom resource:
+
[source,terminal]
----
$ oc get argocd openshift-gitops -n openshift-gitops -o yaml | grep -A10 server
----

. Test route accessibility:
+
[source,terminal]
----
$ curl -I https://$(oc get route openshift-gitops-server -n openshift-gitops -o jsonpath='{.status.ingress[0].host}')
----
+
If the request times out or returns errors, check:
+
** *Firewall or network policies:*
+
[source,terminal]
----
$ oc get networkpolicy -n openshift-gitops
----
+
** *Ingress controller status:*
+
[source,terminal]
----
$ oc get pods -n openshift-ingress
----

. If you receive certificate errors in the browser:
+
** *For self-signed certificates:*
+
... Accept the certificate warning in your browser.
... Or add the certificate to your browser's trusted certificates.
+
** *For invalid certificates:*
+
... Check the route TLS configuration:
+
[source,terminal]
----
$ oc get route openshift-gitops-server -n openshift-gitops -o yaml | grep -A5 tls
----
+
... Verify the certificate is valid:
+
[source,terminal]
----
$ echo | openssl s_client -connect $(oc get route openshift-gitops-server -n openshift-gitops -o jsonpath='{.status.ingress[0].host}'):443 2>/dev/null | openssl x509 -noout -dates
----

. If the console loads but login fails, see xref:#gitops-troubleshoot-authentication-login-failures_{context}[Authentication and login failures].

. Check the Argo CD server service:
+
[source,terminal]
----
$ oc get svc openshift-gitops-server -n openshift-gitops
$ oc describe svc openshift-gitops-server -n openshift-gitops
----
+
Verify the service has endpoints:
+
[source,terminal]
----
$ oc get endpoints openshift-gitops-server -n openshift-gitops
----

.Verification

Access the Argo CD web console URL in your browser. The login page should load without certificate or connection errors.

[TIP]
====
Use port-forwarding to access the Argo CD server directly, bypassing the route:

[source,terminal]
----
$ oc port-forward svc/openshift-gitops-server -n openshift-gitops 8080:443
----

Then navigate to `https://localhost:8080` in your browser.
====
