= Multi-cluster fleet management

[role="_abstract"]
Multi-cluster fleet management uses GitOps to manage applications and configurations across multiple {OCP} clusters simultaneously. This enables you to maintain consistency across development, staging, and production environments.

In a multi-cluster setup, you can use a single Argo CD instance on a hub cluster to deploy applications to multiple spoke clusters. Alternatively, you can use the Argo CD Agent architecture to distribute the control plane and improve scalability.

Key capabilities of multi-cluster fleet management:

* *Centralized control* - Manage all clusters from a single control plane with unified policies.
* *Environment promotion* - Promote applications from development through staging to production clusters using Git workflows.
* *Configuration variants* - Use overlays and templates to customize applications for different environments while maintaining a common base.
* *Compliance and governance* - Enforce consistent security policies, resource quotas, and access controls across all clusters.

Multi-cluster management is essential for organizations with multiple environments, geographic regions, or edge deployments. It reduces operational overhead and ensures configuration consistency across your entire infrastructure.

*Example use cases:*

* Deploy the same application to development, staging, and production clusters with environment-specific configurations
* Manage edge clusters in different geographic regions from a central location
* Maintain consistent baseline configurations across a fleet of clusters
* Roll out updates progressively across clusters to minimize risk
