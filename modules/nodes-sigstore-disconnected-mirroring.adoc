= Verifying signature mirroring in disconnected environments

[role="_abstract"]
When you use the oc-mirror plugin v2 to mirror images for a disconnected environment, signatures are mirrored automatically. You can verify that signatures were mirrored correctly before enabling signature verification on your cluster.

The oc-mirror plugin v2 mirrors sigstore tag-based signatures by default for all images defined in your `ImageSetConfiguration` file. No additional configuration is required to enable signature mirroring.

[id="nodes-sigstore-disconnected-mirroring-verify_{context}"]
== Verifying that signatures were mirrored

After mirroring completes, verify that signature data is present in your local registry:

. Check that signatures exist for a mirrored image by running the following command:
+
[source,terminal]
----
$ skopeo list-tags docker://<local_registry>/<repository>/<image_name> | grep sig
----
+
Sigstore signatures are stored as separate image tags with a `.sig` suffix. For example, if you mirrored an image with the digest `sha256:abc123...`, the signature tag is `sha256-abc123....sig`.

. Check the oc-mirror log for signature mirroring activity:
+
[source,terminal]
----
$ grep -i "signature" oc-mirror.log
----

A successful response indicates that signatures were mirrored. An error or empty response indicates that signatures were not mirrored and signature verification will fail.

[id="nodes-sigstore-disconnected-mirroring-third-party_{context}"]
== Third-party and community catalogs

Certified, marketplace, and community operator catalogs contain third-party content. Red{nbsp}Hat does not guarantee the availability or validity of signatures for images in these catalogs. If you include third-party catalogs in your `ImageSetConfiguration` file and signature verification is required, verify that the source images have valid sigstore signatures before mirroring.
