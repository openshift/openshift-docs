= Connect an {azure-openai} provider to Agentic {ols-long}

[role="_abstract"]
To use {azure-openai} as the large language model (LLM) provider for Agentic {ols-long}, create a credentials secret, an `LLMProvider` custom resource (CR) with the `AzureOpenAI` type, and an `Agent` CR that uses that provider.

.Prerequisites

* You have installed the {ols-long} Operator.
* You have logged in to the cluster as a user with the `cluster-admin` role, or with permission to create cluster-scoped custom resources.
* You have an {azure-openai} resource endpoint and either an API key or Microsoft Entra ID credentials (`client_id`, `tenant_id`, and `client_secret`).

.Procedure

. Create a credentials secret in the `openshift-lightspeed` namespace. {azure-openai} supports two authentication methods. Create the secret by using one of the following methods:
+
--
* To authenticate with an API key, create the secret with the `AZURE_OPENAI_API_KEY` key by running the following command:
+
[source,terminal]
----
$ oc create secret generic llm-credentials \
  --from-literal=AZURE_OPENAI_API_KEY=<api_key> \
  -n openshift-lightspeed
----
* To authenticate with Microsoft Entra ID, create the secret with the `client_id`, `tenant_id`, and `client_secret` keys by running the following command:
+
[source,terminal]
----
$ oc create secret generic llm-credentials \
  --from-literal=client_id=<client_id> \
  --from-literal=tenant_id=<tenant_id> \
  --from-literal=client_secret=<client_secret> \
  -n openshift-lightspeed
----
+
When the secret contains Entra ID keys, Agentic {ols-long} uses them for authentication. If the Entra ID keys are not present, Agentic {ols-long} falls back to the `AZURE_OPENAI_API_KEY` key.
--

. Create an `LLMProvider` CR that uses the `AzureOpenAI` type:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: LLMProvider
metadata:
  name: azure-openai
spec:
  type: AzureOpenAI
  azureOpenAI:
    credentialsSecret:
      name: llm-credentials # <1>
    endpoint: <azure_resource_endpoint> # <2>
    apiVersion: <api_version> # <3>
----
<1> The name of the credentials secret that contains either the `AZURE_OPENAI_API_KEY` key or the Entra ID keys in the `openshift-lightspeed` namespace.
<2> The {azure-openai} resource endpoint, for example, `https://my-resource.openai.azure.com`.
<3> Optional: The {azure-openai} API version in `YYYY-MM-DD` format, with an optional `-preview` suffix, for example, `2024-08-01-preview`. When omitted, the value defaults to `2024-08-01-preview`.

. Create an `Agent` CR that references the `LLMProvider` and specifies the model to use:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: Agent
metadata:
  name: default # <1>
spec:
  llmProvider:
    name: azure-openai # <2>
  model: <model_id> # <3>
  maxTurns: 200
----
<1> The `default` agent must exist. The deployment uses it when a workflow step does not specify an agent.
<2> The name of the `LLMProvider` CR that you created.
<3> The identifier of the deployed model to use.

. Apply the custom resources by running the following command:
+
[source,terminal]
----
$ oc apply -f <cr_filename>.yaml
----

.Verification

* Confirm that the resources exist by running the following commands:
+
[source,terminal]
----
$ oc get llmprovider azure-openai
----
+
[source,terminal]
----
$ oc get agent default
----
