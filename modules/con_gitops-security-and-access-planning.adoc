= Security and access planning considerations

[role="_abstract"]
Plan your security and access control strategy before deploying {gitops-title}. Consider authentication methods, authorization models, and how to implement least-privilege access for your teams.

*Authentication planning*

Choose an authentication method based on your organization's identity management:

* *OpenShift OAuth* - Integrate with {OCP} authentication for unified access control across platform and GitOps.
* *Dex connector* - Connect to external identity providers including LDAP, SAML, OIDC, and OAuth 2.0 providers.
* *Local users* - Create Argo CD-specific user accounts for testing or specialized service accounts.

For production environments, integrate with your existing identity provider instead of managing separate credentials.

*Authorization models*

Plan how teams and individuals access applications and clusters:

* *Cluster-based permissions* - Control which clusters users can deploy to.
* *Namespace-based permissions* - Restrict users to specific namespaces within clusters.
* *Application-based permissions* - Grant access to specific applications or application groups.
* *Repository-based permissions* - Control which Git repositories users can deploy from.

Argo CD uses role-based access control (RBAC) policies to enforce these permissions.

*Least privilege access*

Implement least-privilege access principles:

* Grant developers access only to their team's applications and namespaces
* Limit cluster-admin access to platform administrators
* Use AppProjects to group related applications and apply consistent policies
* Configure separate Argo CD instances for different security zones or compliance requirements

*Secrets management*

Plan how to handle sensitive data:

* *Git repository credentials* - Store credentials for accessing private repositories.
* *Cluster credentials* - Manage credentials for remote clusters in multi-cluster deployments.
* *Application secrets* - Use external secret management solutions instead of storing secrets in Git.

Consider integrating with HashiCorp Vault, {OCP} External Secrets Operator, or sealed secrets for production environments.

*Network and firewall planning*

Plan network access requirements:

* Argo CD needs outbound access to Git repositories (HTTPS port 443 or SSH port 22)
* For multi-cluster deployments, the control plane needs network access to managed clusters
* Consider firewall rules, proxy configurations, and corporate network policies
* Plan for accessing the Argo CD web console and API from authorized networks
