== Fixed issues

The following issues are fixed for this release:

* Before this update, the kube-apiserver Operator deployment disabled automatic service account token mounting and explicitly defined a `kube-api-access` projected volume. As a consequence, the Operator maintained a redundant custom configuration alongside default bound service account token volume injection. With this release, the explicit volume and mount are removed and automatic token mounting is no longer disabled. As a result, the Operator uses the automatically injected service account volume instead of maintaining a separate manual projection. (link:https://issues.redhat.com/browse/OCPBUGS-60496[OCPBUGS-60496])

* Before this update, when reconciling virtual machines (VMs) on Azure, a creation operation could fail and leave a virtual NIC attached to a load balancer without a corresponding VM. As a consequence, the load balancer could not be used until the orphaned NIC was removed. With this release, the reconciler cleans up orphaned NICs when VM creation fails. As a result, load balancers are not blocked by orphaned NICs after failed VM creation. (link:https://issues.redhat.com/browse/OCPBUGS-133111[OCPBUGS-133111])

* Before this update, an infinite boot loop occurred during Lenovo SR645 V3 hardware provisioning. As a consequence, the host stalled on a boot option restoration screen and could not complete the provisioning. With this release, the `ironic` resource skips setting the boot device. As a result, NVRAM loss does not occur, and provisioning succeeds. (link:https://issues.redhat.com/browse/OCPBUGS-134139[OCPBUGS-134139])

* Before this update, the `AWSMachine` controller queued machine instances again before confirming the presence of tags. As a consequence, duplicate {aws-first} EC2 instances were created. With this release, the `AWSMachine` controller verifies tags before it queues instances again. As a result, duplicate EC2 instances are not created. (link:https://issues.redhat.com/browse/OCPBUGS-134665[OCPBUGS-134665])
