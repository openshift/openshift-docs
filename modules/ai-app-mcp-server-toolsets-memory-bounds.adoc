= Set tool memory bounds

[role="_abstract"]
Set a maximum response size for tool calls to keep the MCP server for Red{nbsp}Hat OpenShift stable when tools return large amounts of data, such as extensive pod logs or event lists. 

Responses that exceed the limit are truncated and marked with a `[TRUNCATED]` indicator, which prevents the server pod from running out of memory.

The following table lists the tool memory boundary fields.

.Tool memory boundary fields
[cols="1,1,1,1,3",options="header"]
|===
|Name |Type|Default value|Description|Truncation behavior
|`max_backend_response_bytes`
|Integer
|4194304
|Maximum bytes read from one Kubernetes API, Kiali, or Prometheus response. 
|`pods_exec` counts stdout and stderr together. An exact fit is allowed. The next byte closes the body and the call returns an error. 0 disables the cap. HTTP 101 upgrades are not capped. The schema fetch skips the cap so that the aggregated spec can be parsed whole. Every other request stays capped. `pods_exec` keeps the bytes already stored and appends a truncation notice even if the exec library returns a stream error after the cap. A stream error before the cap drops that output.
|`max_result_bytes`
|Integer
|16777216
|Maximum bytes of one tool, prompt, or resource result.
|A tool counts `Content` plus the JSON size of `StructuredContent` when that field is set. When `ContentBlocks` is set, those block bytes replace `Content`, including image data. A tool error counts the error text. A prompt counts message text. A resource counts its text or blob. Log and event assembly stops at the cap and appends a truncation notice. The notice might make the result longer than the cap by the length of that notice. A result larger than the cap plus that notice is rejected and is not sent.
|`max_in_flight`
|Integer
|64
|Maximum number of` tools/call`, `prompts/get`, and `resources/read` requests running at once in this process. 
|When every slot is in use, another of those requests is rejected with JSON-RPC error -32030 (`max_in_flight` limit exceeded). Other methods are not counted. Every session shares one pool.
|===

.Prerequisites
* The MCP server for Red{nbsp}Hat OpenShift is installed.

.Procedure
* In the `config.toml ConfigMap`, change the fields listed in "Tool memory boundary fields" table similar to the following:
+
[source,toml]
----
# Memory bounds
max_backend_response_bytes = 4194304
max_result_bytes = 16777216
max_in_flight = 64
----
