= Troubleshooting backup and restore for {hcp} on {azure-short}

[role="_abstract"]
If you experience issues during the backup and restore process for {hcp} on {azure-short}, review the likely causes to find a resolution.

[cols="2,2,3", options="header"]
|===
|Symptom |Likely cause |Resolution

|An XML error in `etcd-init` logs
|The Azure shared access signature (SAS) token in the snapshot URL expired.
|Regenerate the SAS token and run a new backup. Use the new backup name with the `hcp create oadp-restore` command.

|A `curl 404` error in `etcd-init` logs
|The blob URL in the snapshot is wrong or the blob was deleted.
|Verify the backup snapshot URL by entering the following command: `oc get hostedcluster <name> -n <namespace> -o jsonpath='{.status.lastSuccessfulEtcdBackupURL}'`. Confirm that the blob exists in the Azure Storage container.

|`not empty` error; etcd restore does not start
|Existing etcd persistent volume claim (PVC) data is present from the previous cluster.
|Delete the `HostedCluster` resource and confirm that all PVCs in the hosted cluster namespace are removed before you run the restore command.

|Velero restore stuck; `Restore` custom resource (CR) does not progress
|The Velero controller is not processing the `Restore` CR.
|Check Velero pod logs by entering the following command: `oc logs -n openshift-adp deployment/velero`. Verify that the `DataProtectionApplication` (DPA) configuration is correct and the `BackupStorageLocation` is available.
|===
