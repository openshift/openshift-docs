= Opt out of `virt-platform-autopilot` controller-managed configurations

[role="_abstract"]
You can opt out of specific `virt-platform-autopilot` controller-managed configurations by disabling management of a resource or by ignoring specific fields that you customize.

.Prerequisites

* You have installed the {oc-first}.
* You have logged in to the cluster as a user with `cluster-admin` privileges.
* The `virt-platform-autopilot` controller is enabled on the cluster.

.Procedure

. To fully opt out of `virt-platform-autopilot` controller management for a specific resource, set the `platform.kubevirt.io/mode` annotation to `unmanaged`.
+
For example, to stop the `virt-platform-autopilot` controller from managing the descheduler configuration, run the following command:
+
[source,terminal]
----
$ oc annotate kubedescheduler cluster \
  platform.kubevirt.io/mode=unmanaged \
  -n openshift-kube-descheduler-operator
----
+
When a resource is set to `unmanaged`, the `virt-platform-autopilot` controller stops reconciling it.
You can then change the resource freely without the `virt-platform-autopilot` controller reverting your changes.

. Optional: To keep a resource managed by the `virt-platform-autopilot` controller while customizing specific fields, add the `platform.kubevirt.io/ignore-fields` annotation with a comma-separated list of JSON pointer paths.
+
For example, to prevent the `virt-platform-autopilot` controller from overriding a custom descheduler profile configuration, run the following command:
+
[source,terminal]
----
$ oc annotate kubedescheduler cluster \
  platform.kubevirt.io/ignore-fields="/spec/profileCustomizations" \
  -n openshift-kube-descheduler-operator
----
+
The `virt-platform-autopilot` controller continues to manage all other fields on the resource but skips the specified paths.

. Optional: To customize specific values in a managed resource, add the `platform.kubevirt.io/patch` annotation with a JSON Patch document.
+
For example, to override a systemd unit in a managed `MachineConfig` resource, run the following command:
+
[source,terminal]
----
$ oc annotate machineconfig 90-worker-swap-online \
  platform.kubevirt.io/patch='[{"op": "replace", "path": "/spec/config/systemd/units/0/contents", "value": "..."}]'
----
+
The `virt-platform-autopilot` controller applies your patch on top of the managed configuration during each reconciliation.

. Optional: To restore `virt-platform-autopilot` controller management for a resource that was set to unmanaged, remove the `mode` annotation by running the following command:
+
[source,terminal]
----
$ oc annotate kubedescheduler cluster \
  platform.kubevirt.io/mode- \
  -n openshift-kube-descheduler-operator
----

.Verification

* Verify that the annotation is set on the managed resource by running the following command and observing the output:
+
[source,terminal]
----
$ oc get kubedescheduler cluster \
  -n openshift-kube-descheduler-operator \
  -o jsonpath='{.metadata.annotations}' | jq .
----
+
For a resource set to `unmanaged`, the output includes the following annotation:
+
[source,json]
----
{
  "platform.kubevirt.io/mode": "unmanaged"
}
----

* Verify that the `virt-platform-autopilot` controller is not managing the resource by checking that the `platform.kubevirt.io/managed-by` label is absent:
+
[source,terminal]
----
$ oc get kubedescheduler cluster \
  -n openshift-kube-descheduler-operator \
  -o jsonpath='{.metadata.labels.platform\.kubevirt\.io/managed-by}'
----
+
An unmanaged resource does not return a value.
