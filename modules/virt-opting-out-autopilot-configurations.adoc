= Opt out of `virt-platform-autopilot` controller-managed configurations

[role="_abstract"]
You can opt out of specific `virt-platform-autopilot` controller-managed configurations by disabling management of a resource or by ignoring specific fields that you customize.

.Prerequisites

* You have installed the {oc-first}.
* You have logged in to the cluster as a user with `cluster-admin` privileges.
* The `virt-platform-autopilot` controller is enabled on the cluster.

.Procedure

. To fully opt out of `virt-platform-autopilot` controller management for a specific resource, annotate the managed resource with the `platform.kubevirt.io/management-state` annotation set to `Unmanaged`.
+
For example, to stop the `virt-platform-autopilot` controller from managing the descheduler configuration, run the following command:
+
[source,terminal]
----
$ oc annotate kubedescheduler cluster \
  platform.kubevirt.io/management-state=Unmanaged \
  -n openshift-kube-descheduler-operator
----
+
When a resource is set to `Unmanaged`, the `virt-platform-autopilot` controller stops reconciling it.
You can then modify the resource freely without the `virt-platform-autopilot` controller reverting your changes.

. Optional: To keep a resource managed by the `virt-platform-autopilot` controller while customizing specific fields, annotate the resource with the `platform.kubevirt.io/ignore-fields` annotation.
+
Specify the JSON paths of the fields that you want the `virt-platform-autopilot` controller to ignore during reconciliation.
For example, to prevent the `virt-platform-autopilot` controller from overriding a custom descheduler profile configuration, run the following command:
+
[source,terminal]
----
$ oc annotate kubedescheduler cluster \
  platform.kubevirt.io/ignore-fields='["/spec/profileCustomizations"]' \
  -n openshift-kube-descheduler-operator
----
+
The `virt-platform-autopilot` controller continues to manage all other fields on the resource but skips the specified paths.

. Optional: To restore `virt-platform-autopilot` controller management for a resource that was previously set to unmanaged, remove the `management-state` annotation by running the following command:
+
[source,terminal]
----
$ oc annotate kubedescheduler cluster \
  platform.kubevirt.io/management-state- \
  -n openshift-kube-descheduler-operator
----

.Verification

* Verify that the annotation is set on the managed resource by running the following command and observing the output:
+
[source,terminal]
----
$ oc get kubedescheduler cluster \
  -n openshift-kube-descheduler-operator \
  -o jsonpath='{.metadata.annotations}' | jq .
----
+
For a resource set to `Unmanaged`, the output includes the following annotation:
+
[source,json]
----
{
  "platform.kubevirt.io/management-state": "Unmanaged"
}
----

* Verify that the `virt-platform-autopilot` controller is not reconciling the unmanaged resource by checking the `kubevirt_vpa_compliance_status` metric in the {product-title} web console under *Observe* > *Metrics*.
An unmanaged resource does not appear in the compliance status.
