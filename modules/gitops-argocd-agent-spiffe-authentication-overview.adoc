= SPIFFE/SPIRE authentication overview

:FeatureName: SPIFFE/SPIRE authentication for Argo CD Agent
include::snippets/technology-preview.adoc[]

As an alternative to the standard mTLS and JWT authentication setup, the principal and agent components can authenticate using SPIFFE identities issued by a SPIRE deployment through the SPIFFE CSI driver.

SPIFFE (Secure Production Identity Framework for Everyone) provides a standard way to identify workloads in dynamic environments. SPIRE (SPIFFE Runtime Environment) is the production-ready implementation that issues and manages SPIFFE identities.

When you configure SPIFFE authentication, it takes precedence over any legacy TLS and credentials configuration. However, the `principal.auth` field is not automatically overridden by SPIFFE settings. A non-empty `principal.auth` value always takes precedence over the SPIFFE-inferred pattern. You can leave it unset to allow the controller to infer the correct pattern automatically, or set it to a value that matches your SPIFFE identity format.

*Benefits of SPIFFE/SPIRE authentication*

Identity-based authentication:: SPIFFE provides cryptographic identities to workloads without requiring manual certificate management.

Federation support:: JWT-SVIDs enable authentication across federated SPIRE deployments, supporting multi-cluster or multi-cloud scenarios.

Centralized trust:: SPIRE manages the trust relationship between workloads, eliminating the need to distribute and rotate certificates manually.

Automatic rotation:: SPIRE automatically rotates SPIFFE Verifiable Identity Documents (SVIDs), reducing the operational burden of certificate lifecycle management.
