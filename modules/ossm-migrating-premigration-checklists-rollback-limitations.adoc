= Rollback limitations

[role="_abstract"]

Understand the limitations of rolling back a {SMProduct} 3.1 migration before you begin migrating your workloads from {SMProduct} {SMv2Version} to {SMProduct} 3.1.

[IMPORTANT]
====
Rolling back from {SMProduct} 3.1 to {SMProduct} {SMv2Version} is not recommended. If you encounter problems during the migration, the recommended approach is to fix the problems and continue forward with the migration.
====

After the {SMProduct} 3 Operator is installed, all Istio custom resource definitions (CRDs) on the cluster are updated. It is not possible to revert the Istio CRDs to the {SMProduct} {SMv2Version} versions without reinstalling {SMProduct} {SMv2Version} from scratch.

If you must roll back workloads that were already migrated to the {SMProduct} 3.1 control plane, complete the following steps.

[IMPORTANT]
====
At any given time, exactly one control plane version must inject side cars into workloads. The 2.6 and 3.1 control planes must never inject side cars into workloads at the same time.
====

.Procedure

. In the namespace of an already migrated workload, remove the sidecar injection labels for the 3.1 control plane, remove the `maistra.io/ignore-namespace: "true"` label, and re-apply the sidecar injection label for the {SMProduct} {SMv2Version} control plane. You must apply all of these label changes at the same time by running a single command.

. Restart the workloads in the namespace so that the {SMProduct} {SMv2Version} control plane injects the side cars.

. Repeat steps 1-2 for all other already migrated workloads.

. After all workloads are managed by the {SMProduct} {SMv2Version} control plane, remove the {SMProduct} 3.x control plane.
