= vLLM Anthropic provider requirements

[role="_abstract"]
{ols-long} supports a self-hosted vLLM server as an Anthropic-compatible LLM provider. Before you configure this pathway, ensure that your environment meets the version, endpoint, and authentication requirements.

The {ols-long} Service does not provide the LLM for you, so you must configure the LLM before you install the {ols-long} Operator.

[NOTE]
====
Red{nbsp}Hat does not provide support for any specific models or make suggestions or support statements pertaining to models.
====

To integrate vLLM through the Anthropic provider, your environment must meet the following requirements:

Supported vLLM version::
vLLM version 0.24, the version currently supported with {rhelai}. The Anthropic-compatible `/v1/messages` endpoint is available in this version.

API endpoint::
The vLLM server must expose the Anthropic-compatible `/v1/messages` endpoint.

Authentication::
The Anthropic provider passes a standard authentication (AUTH) token with each request. You store this token in a {k8s} Secret that the `OLSConfig` CR references. If your vLLM endpoint does not require a token, you must still set the token value to any valid string so that the request authenticates.

Network access::
Because the vLLM server runs in a different environment than the {ols-long} deployment, the model deployment must allow access over a secure connection.

Tested models::
The Gemma series of models has been tested with this pathway. Model quality affects agentic and tool-calling outcomes, so results can vary by model.
