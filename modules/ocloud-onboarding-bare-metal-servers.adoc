= Onboard bare-metal servers to resource pools

[role="_abstract"]
You can register bare-metal servers with the O-Cloud Manager by defining an infrastructure hierarchy and creating `BareMetalHost` custom resources (CRs) with resource selector labels. Onboarded servers become available for allocation when a `ProvisioningRequest` CR references a `ClusterTemplate` CR with matching resource selectors.

.Prerequisites

* The O-Cloud Manager Operator is installed on the hub cluster.
* You have Baseboard Management Controller (BMC) credentials for each server.

.Procedure

. Create the infrastructure hierarchy by defining `Location`, `OCloudSite`, and `ResourcePool` CRs:
+
[source,yaml]
----
apiVersion: ocloud.openshift.io/v1alpha1
# A geographic place. Specify at least one of address, coordinate, or civicAddress.
kind: Location
metadata:
  name: dc1
  namespace: <server_namespace>
spec:
  description: "Data Center 1"
  address: "123 Example Street"
---
apiVersion: ocloud.openshift.io/v1alpha1
# A logical site at a Location. References the parent Location by name.
kind: OCloudSite
metadata:
  name: site-rack-a
  namespace: <server_namespace>
spec:
  description: "Rack A at Data Center 1"
  globalLocationName: dc1
---
apiVersion: ocloud.openshift.io/v1alpha1
# A group of bare-metal resources at a site. References the parent OCloudSite by name.
kind: ResourcePool 
metadata:
  name: <resource_pool_name>
  namespace: <server_namespace>
spec:
  description: "<resource_pool_description>"
  oCloudSiteName: site-rack-a
----
+
where:
+
`<server_namespace>`:: Specifies the namespace where server and infrastructure resources are stored. The recommended convention is one namespace per resource pool.
`<resource_pool_name>`:: Specifies a descriptive name for the resource pool, for example `compute-pool-1`.
`<resource_pool_description>`:: Describes the purpose or hardware type of the resource pool.

. Create a `Secret` CR containing the BMC credentials for the server, for example:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: <bmc_secret_name>
  namespace: <server_namespace>
type: Opaque
data:
  username: <base64_encoded_username>
  password: <base64_encoded_password>
----
+
where:
+
`<bmc_secret_name>`:: Specifies the name of the secret. This name is referenced by the `BareMetalHost` resource.
`<base64_encoded_username>`:: Specifies the Base64-encoded BMC username.
`<base64_encoded_password>`:: Specifies the Base64-encoded BMC password.

. Create a `BareMetalHost` CR with the required labels to associate the server with a resource pool:
+
[source,yaml]
----
apiVersion: metal3.io/v1alpha1
kind: BareMetalHost
metadata:
  name: <server_name>
  namespace: <server_namespace>
  labels:
    resources.clcm.openshift.io/resourcePoolName: <resource_pool_name>
    interfacelabel.clcm.openshift.io/boot-interface: <boot_interface_name>
    resourceselector.clcm.openshift.io/server-type: <server_type>
  annotations:
    bmac.agent-install.openshift.io/allow-provisioned-host-management: ""
spec:
  online: false
  bmc:
    address: redfish-virtualmedia+https://192.168.1.100/redfish/v1/Systems/System.Embedded.1
    credentialsName: server1-bmc-credentials
    disableCertificateVerification: true
----
+
where:
+
`<server_name>`:: Specifies a unique name for the `BareMetalHost` resource.
`<server_namespace>`:: Specifies the namespace where server resources are stored. The recommended convention is one namespace per resource pool.
`resources.clcm.openshift.io/resourcePoolName`:: Required. Must match an existing `ResourcePool` resource's `metadata.name`. Links this server to the infrastructure hierarchy. Without this label, the server does not appear in the O-Cloud Manager inventory.
`interfacelabel.clcm.openshift.io/boot-interface`:: Required if `spec.bootMACAddress` is not set. Specifies the physical NIC name used for booting, for example `ens3f0`. The O-Cloud Manager uses this label to resolve the boot MAC address from hardware inventory data.
`resourceselector.clcm.openshift.io/server-type`:: Optional. A user-defined label identifying the server hardware class. These labels are matched against the `resourceSelector` criteria in the `ClusterTemplate` CR.
`bmac.agent-install.openshift.io/allow-provisioned-host-management`:: Optional. Allows the O-Cloud Manager to manage a host that is already in a provisioned state. The O-Cloud Manager sets this annotation automatically during node allocation if not already present.
`spec.online: false`:: Prevents the server from being powered on before provisioning. The O-Cloud Manager manages power state during provisioning.
`spec.bmc.address`:: Specifies the BMC connection URL in the format `<protocol>+https://<bmc_ip>/redfish/v1/Systems/<system_id>`. Use `redfish-virtualmedia` for generic Redfish or `idrac-virtualmedia` for Dell iDRAC.
`spec.bmc.credentialsName`:: Specifies the name of the `Secret` resource containing the BMC credentials created in the previous step.


. Apply the CRs to the hub cluster by running the following commands:
+
[source,terminal]
----
$ oc apply -f <infrastructure_hierarchy_filename>.yaml
$ oc apply -f <bmc_secret_filename>.yaml
$ oc apply -f <baremetalhost_filename>.yaml
----
+
* Replace `<infrastructure_hierarchy_filename>.yaml`, `<bmc_secret_filename>.yaml`, and `<baremetalhost_filename>.yaml` with the names of the files.
+
After the `BareMetalHost` CR is created, the Bare Metal Operator connects to the BMC, inspects the physical hardware, and populates a `HardwareData` CR with CPU, memory, NIC, and storage details. This data is used for hardware data filtering during resource selection.

.Verification

. Verify that the infrastructure hierarchy resources are created by running the following commands:
+
[source,terminal]
----
$ oc get locations.ocloud.openshift.io
$ oc get ocloudsites.ocloud.openshift.io
$ oc get resourcepools.ocloud.openshift.io
----

. Verify that the `BareMetalHost` CR is registered and inspection is complete by running the following command:
+
[source,terminal]
----
$ oc get bmh -A
----
+
The server should show a provisioning state of `available` after inspection completes, indicating it is ready for allocation.
