= Connect an OpenAI provider to Agentic {ols-long}

[role="_abstract"]
To use {openai} or an OpenAI-compatible endpoint as the large language model (LLM) provider for Agentic {ols-long}, create a credentials secret, an `LLMProvider` custom resource (CR) with the `OpenAI` type, and an `Agent` CR that uses that provider.

[IMPORTANT]
====
For agentic and tool-calling workloads that use a self-hosted vLLM server, use the Anthropic provider pathway instead of the OpenAI-compatible pathway. The OpenAI provider pathway can suppress tool calls on vLLM. For more information, see "Choose an LLM provider pathway for Agentic {ols-long}".
====

.Prerequisites

* You have installed the {ols-long} Operator.
* You have logged in to the cluster as a user with the `cluster-admin` role, or with permission to create cluster-scoped custom resources.
* You have an {openai} API key, or a key for an OpenAI-compatible endpoint.

.Procedure

. Create a credentials secret in the `openshift-lightspeed` namespace by running the following command:
+
[source,terminal]
----
$ oc create secret generic llm-credentials \
  --from-literal=OPENAI_API_KEY=<api_key> \
  -n openshift-lightspeed
----

. Create an `LLMProvider` CR that uses the `OpenAI` type:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: LLMProvider
metadata:
  name: openai
spec:
  type: OpenAI
  openAI:
    credentialsSecret:
      name: llm-credentials # <1>
    url: <api_endpoint_url> # <2>
----
<1> The name of the credentials secret that contains the `OPENAI_API_KEY` key in the `openshift-lightspeed` namespace.
<2> Optional: An override for the OpenAI API endpoint. Set this value for an OpenAI-compatible endpoint, such as a self-hosted service. Omit it to use the default {openai} endpoint.

. Create an `Agent` CR that references the `LLMProvider` and specifies the model to use:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: Agent
metadata:
  name: default # <1>
spec:
  llmProvider:
    name: openai # <2>
  model: <model_id> # <3>
  maxTurns: 200
----
<1> The `default` agent must exist. The deployment uses it when a workflow step does not specify an agent.
<2> The name of the `LLMProvider` CR that you created.
<3> The identifier of the model to use. The model must support function calling to participate in agentic workflows.

. Apply the custom resources by running the following command:
+
[source,terminal]
----
$ oc apply -f <cr_filename>.yaml
----

.Verification

* Confirm that the resources exist by running the following commands:
+
[source,terminal]
----
$ oc get llmprovider openai
----
+
[source,terminal]
----
$ oc get agent default
----
