= Router audit log fields

[role="_abstract"]
Each router audit log entry has the following fields. You can use the `audit` field to filter audit entries from other `Info`-level log messages.

.Router audit log fields
[cols="1,3", options="header"]
|===
|Field
|Description

|`audit`
|Always `true`. Filters audit entries from other `Info`-level logs.

|`user`
|Decoded JWT `sub` claim from the `Authorization` header. The router does not validate this token. Empty when it cannot extract a nonempty subject. See "The user field and authentication".

|`tool`
|Unprefixed upstream tool name after successful rewriting. If a failure occurs before rewriting, the field can retain the client-supplied name, including its prefix.

|`server`
|`namespace/name` of the selected `MCPServerRegistration` object. Empty when no upstream server was recorded, for example, after session validation fails or no route matches. An empty value does not identify a unique failure cause.

|`status`
|HTTP response status code, not the MCP or tool outcome. An MCP error can be returned with HTTP `200`.

|`request_id`
|Envoy-generated request UUID from the `x-request-id` header.

|`session`
|Log-safe session identifier: `jti:<uuid>` or `sha256:<prefix>`. Never a raw JSON web token (JWT).
|===

[id="con-mcp-gateway-router-audit-user-field_{context}"]
== The user field and authentication

The router decodes the `user` field from the JWT `sub` claim in the `Authorization` header without validating the token signature. Do not use `x-mcp-verified-sub` as proof of authentication; it is a router-set internal header.

Protect both broker and back-end route sets with token-validating `AuthPolicy` CRs or equivalent authentication. In the sample configuration, these route sets use the `mcp` and `mcps` listeners. Protecting only one listener does not establish authenticated identity for requests routed through the other.

Even with both policies configured, the router can emit an audit entry for a rejection before authentication completes. Treat the `user` value in these entries as unverified. The presence of a `user` value or an HTTP `200` status does not prove authentication or a successful tool call.
