= Get details on tool requests with structured audit logs

[role="_abstract"]
You can use the router structured audit log in {mcpg} to capture who called a specific tool, on which MCP server the call was made, in which session, and whether the call succeeded. The router emits a structured `level=INFO` log entry for every `tools/call` request without requiring additional infrastructure.

An `audit=true` entry is displayed at the following two points in the request lifecycle:

Response headers phase example::
A call reached the backend and received a response.
+
[source,text]
----
level=INFO msg="tool call" audit=true user=alice tool=echo server=mcp-test/my-server status=200 request_id=<uuid> session=jti:...
----

Request body phase example::
The router returned an error before forwarding, for example, an expired session or an unknown server.
+
[source,text]
----
level=INFO msg="tool call" audit=true user=alice tool=echo server="" status=401 request_id=<uuid> session=sha256:...
----

Events not logged::
When a tool identity is not available, or the tools are not the responsibility of the router, the following events are not logged:

* `AuthPolicy` denials: Envoy rejects the request before the external processing filter, `ext_proc`, runs.
* Invalid JSON-RPC (Remote Procedure Call) or a body that cannot be parsed: The router rejects the request before populating `mcpRequest`.
* Non-`tools/call` methods, for example `tools/list` and `initialize`.
