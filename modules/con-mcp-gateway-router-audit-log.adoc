= Get details on tool requests with structured audit logs

[role="_abstract"]
You can use the router structured audit log in {mcpg} to inspect the reported caller subject, tool, selected MCP server, log-safe session identifier, and HTTP response status.

The router emits structured `level=INFO` audit entries for parsed `tools/call` requests at the response headers phase or when routing returns an error. This does not require additional logging infrastructure.

An `audit=true` entry is emitted at either of the following points in the request lifecycle. The `user` field is a decoded, not router-validated, JWT subject, and `status` describes HTTP only. An MCP or tool error can have HTTP status `200`.

Response headers phase example::
The request reached response header processing. After successful tool-name rewriting, the logged tool name is the unprefixed upstream name.
+
[source,text]
----
level=INFO msg="tool call" audit=true user=alice tool=echo server=mcp-test/my-server status=200 request_id=<uuid> session=jti:...
----

Request body phase example::
The router returned an error before forwarding, for example, an expired session or an unknown tool. These entries can precede authentication, and the tool name can retain the client prefix if rewriting has not occurred. An empty `server` field means that no upstream was recorded, not that a route lookup necessarily failed.
+
[source,text]
----
level=INFO msg="tool call" audit=true user="" tool=test1_echo server="" status=401 request_id=<uuid> session=sha256:...
----

Events not logged::
Router audit logs are not a complete record of all requests. The following events do not produce a router audit entry:

* Authentication denials that stop processing before a router audit point. Use authentication and Envoy access logs to investigate these denials; do not assume that router audit logs include every denial.
* Invalid JSON-RPC (Remote Procedure Call) or a body that cannot be parsed: The router rejects the request before reaching an audit log emission point.
* Non-`tools/call` methods, for example `tools/list` and `initialize`.
