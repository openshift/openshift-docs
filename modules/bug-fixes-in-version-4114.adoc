= Bug fixes and security updates in version 4.11.4

[role="_abstract"]
This release includes the following bug fixes:

//ROX-36824
* Before this update, the diagnostic bundle included unredacted values from the `openshift.io/token-secret.value` annotation for `dockercfg` secrets, exposing sensitive secret data. With this release, Red{nbsp}Hat redacts these annotation values before including resources in the diagnostic bundle. As a result, sensitive secret values are no longer exposed in diagnostic bundles.
//should this level of detail be included? (should we make more general for security purposes?)

//ROX-36660
* Before this update, the security policy criterion "CVE is not yet fixable" did not generate violations for deployments with unfixable CVEs. With this release, Red{nbsp}Hat fixed the policy matching logic. As a result, you can now create policies that detect deployments with unfixable CVEs.

//ROX-36628
* Before this update, {product-title-short} Scanner incorrectly flagged the PyPI package `langsmith` as vulnerable to CVE-2026-45134 when scanning versions where the fix version comparison failed. With this release, Red{nbsp}Hat corrected the ecosystem-specific version matching logic. As a result, Scanner accurately reports vulnerability status for language-ecosystem packages.

//ROX-36405
* Before this update, when you applied a security policy by using a SecurityPolicy custom resource (CR) with `clusterlabel` or `namespacelabel` scope fields, the scope filters were ignored due to a field name mismatch between the YAML export format and the CR definition. With this release, Red{nbsp}Hat aligned the field naming. As a result, cluster and namespace label scopes now work correctly in Policy-as-Code deployments.

//ROX-36393
* Before this update, the Policy Management filter bar did not display available policy categories when you attempted to filter by category. With this release, Red{nbsp}Hat restored the category suggestions. As a result, you can now filter policies by category through the {product-title-short} portal.

//ROX-36237
* Before this update, the `stackrox` `ValidatingWebhookConfiguration` used an incorrect namespace label selector (`namespace.metadata.stackrox.io/name`) that does not exist on standard Kubernetes namespaces. This caused the admission controller to incorrectly process system namespaces such as `kube-system` and `kube-public` instead of excluding them. With this release, Red{nbsp}Hat updated the namespace selector to use the standard `kubernetes.io/metadata.name` label. As a result, system namespaces are now correctly excluded from admission control evaluation.

//ROX-35908
* Before this update, you could not download compliance reports for node profiles on Hosted Control Plane (HCP) clusters. The report generation job would wait indefinitely and eventually fail. With this release, Red{nbsp}Hat fixed the report generation logic for HCP clusters. As a result, compliance reports for node profiles on HCP clusters now download successfully.
