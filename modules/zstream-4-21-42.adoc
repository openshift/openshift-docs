== Fixed issues

The following issues are fixed for this release:

* Before this update, field-level CEL immutability rules on `HostedCluster` `spec.infraID` and `spec.clusterID` could be bypassed by a JSON merge patch that removed those fields. As a consequence, the controller could auto-generate a new `infraID` and re-provision infrastructure, orphaning existing cloud resources. With this release, parent-level CEL validation rules prevent removal of `infraID` and `clusterID` after they are set. As a result, API requests that attempt to clear these fields are rejected with a validation error. (link:https://issues.redhat.com/browse/OCPBUGS-129443[OCPBUGS-129443])

* Before this update, when reconciling virtual machines (VMs) on Azure, a creation operation could fail and leave a virtual NIC attached to a load balancer without a corresponding VM. As a consequence, the load balancer could not be used until the orphaned NIC was removed. With this release, the reconciler cleans up orphaned NICs when VM creation fails. As a result, load balancers are not blocked by orphaned NICs after failed VM creation. (link:https://issues.redhat.com/browse/OCPBUGS-133099[OCPBUGS-133099])

* Before this update, an infinite boot loop occurred during Lenovo SR645 V3 hardware provisioning. As a consequence, the host stalled on a boot option restoration screen and could not complete the provisioning. With this release, the `ironic` resource skips setting the boot device. As a result, NVRAM loss does not occur, and provisioning succeeds. (link:https://issues.redhat.com/browse/OCPBUGS-134138[OCPBUGS-134138])
