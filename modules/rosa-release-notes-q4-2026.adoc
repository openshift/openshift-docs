= Q4 2026

[role="_abstract"]
The following items were added during the fourth quarter of 2026.

ifdef::openshift-rosa-hcp[]
AWS resource tagging improvements::
+
You can include spaces in AWS tag keys and values. In addition, when the same AWS tag key is defined at both the cluster and machine pool levels, the machine pool tag value takes precedence over the cluster tag value. For more information, see link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws/4/html/cluster_administration/managing-compute-nodes-using-machine-pools#rosa-adding-tags_rosa-managing-worker-nodes[Adding tags to a machine pool].

BGP routing for OpenShift Virtualization on AWS::
+
Border Gateway Protocol (BGP) Cloud Connector integrates {product-title} with {aws-short} Route Server allowing direct, routed connectivity to {VirtProductName} virtual machines (VMs) on {aws-short}. For more information, see the following documentation:

* link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws/4/html-single/advanced_networking/index#about-bgp-routing[About BGP routing for {product-title}]
endif::openshift-rosa-hcp[]

{hcp-capital} is the default in interactive cluster creation::
+
With {rosa-cli} 1.2.66 and later, when you run the `rosa create cluster` command in interactive mode without specifying the `--hosted-cp` option, the `Deploy cluster with Hosted Control Plane` prompt defaults to `Yes`. To create a {rosa-classic-title} cluster interactively, answer `No` at this prompt or specify the `--hosted-cp=false` option.
+
Non-interactive cluster creation is unchanged.
ifdef::openshift-rosa[]
+
For more information, see link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws_classic_architecture/4/html-single/install_rosa_classic_clusters/index#rosa-sts-interactive-mode-reference[Interactive cluster creation mode reference].
endif::openshift-rosa[]

ifdef::openshift-rosa[]
The {rosa-cli} uses AWS STS by default without prompting::
+
With {rosa-cli} 1.2.66 and later, the `--sts` option for the `rosa create cluster` command defaults to `true`, and the interactive `Deploy cluster using AWS STS` prompt is removed. To create a cluster that uses IAM user credentials instead, you must explicitly specify the `--non-sts` or `--mint-mode` option.
endif::openshift-rosa[]

ifdef::openshift-rosa[]
AWS EC2 IMDSv2 is required by default::
+
New {product-title} clusters default to requiring AWS EC2 Instance Metadata Service Version 2 (IMDSv2), whether you create them by using {cluster-manager}, the {rosa-cli}, Terraform, or the API. You can configure this setting at cluster creation. Existing clusters are unaffected. For more information, see link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws_classic_architecture/4/html-single/install_rosa_classic_clusters/index#rosa-sts-overview-of-the-default-cluster-specifications_rosa-sts-creating-a-cluster-quickly[Default cluster specifications].
endif::openshift-rosa[]

ifdef::openshift-rosa-hcp[]
AWS EC2 IMDSv2 is required by default::
+
New {product-title} clusters and machine pools default to requiring AWS EC2 Instance Metadata Service Version 2 (IMDSv2), whether you create them by using {cluster-manager}, the {rosa-cli}, Terraform, or the API. You can configure this setting at cluster creation or when creating machine pools. Existing clusters and machine pools are unaffected. For more information, see link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws/4/html/install_clusters/rosa-hcp-sts-creating-a-cluster-quickly#rosa-sts-overview-of-the-default-cluster-specifications_rosa-hcp-sts-creating-a-cluster-quickly[Default cluster specifications].
endif::openshift-rosa-hcp[]

Configure cluster notification contacts by using the {rosa-cli} or Terraform::
+
With {rosa-cli} 1.2.66 and later, you can specify additional {cluster-manager} account usernames or email addresses to receive cluster notification emails by using the `--notification-contacts` option. This feature is also available in version 1.7.10 and later of the Red{nbsp}Hat Cloud Services Terraform provider. For more information, see
ifdef::openshift-rosa[]
link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws_classic_architecture/4/html/cluster_administration/rosa-cluster-notifications#rosa-manage-notification-contacts-cli_rosa-cluster-notifications[Manage notification contacts by using the {rosa-cli-title}]
endif::openshift-rosa[]
ifdef::openshift-rosa-hcp[]
link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws/4/html/cluster_administration/rosa-cluster-notifications#rosa-manage-notification-contacts-cli_rosa-cluster-notifications[Manage notification contacts by using the {rosa-cli-title}]
endif::openshift-rosa-hcp[]
and link:https://registry.terraform.io/providers/terraform-redhat/rhcs/latest/docs/resources/cluster_notification_contacts[rhcs_cluster_notification_contacts] in the Terraform Registry.
