= Q4 2026

[role="_abstract"]
The following items were added during the fourth quarter of 2026.

ifdef::openshift-rosa-hcp[]
BGP routing for OpenShift Virtualization on AWS::
+
Border Gateway Protocol (BGP) Cloud Connector integrates {product-title} with {aws-short} Route Server allowing direct, routed connectivity to {VirtProductName} virtual machines (VMs) on {aws-short}. For more information, see the following documentation:

* link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws/4/html-single/advanced_networking/index#about-bgp-routing[About BGP routing for {product-title}]
endif::openshift-rosa-hcp[]

{hcp-title} is the default in interactive cluster creation::
+
With {rosa-cli} 1.2.66 and later, when you run the `rosa create cluster` command in interactive mode without specifying the `--hosted-cp` option, the `Deploy cluster with Hosted Control Plane` prompt defaults to `Yes`. To create a {rosa-classic-short} cluster interactively, answer `No` at this prompt or specify the `--hosted-cp=false` option.
+
If you specify options that are only compatible with {rosa-classic-short} clusters, such as `--disable-workload-monitoring`, the prompt is skipped. The {rosa-cli} displays an informational message that lists the incompatible options and continues with the classic architecture.
+
Non-interactive cluster creation is unchanged.
ifdef::openshift-rosa[]
+
For more information, see link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws_classic_architecture/4/html-single/install_rosa_classic_clusters/index#rosa-sts-interactive-mode-reference[Interactive cluster creation mode reference].
endif::openshift-rosa[]

ifdef::openshift-rosa-hcp[]
Default compute machine type for clusters with {hcp}::
+
With {rosa-cli} 1.2.66 and later, if you create a cluster and do not specify the `--compute-machine-type` option, the service default instance type is now used. The current service default is `m7i.xlarge`, and it can vary by region.
endif::openshift-rosa-hcp[]

ifdef::openshift-rosa[]
AWS STS is used by default without prompting::
+
With {rosa-cli} 1.2.66 and later, the `--sts` option for the `rosa create cluster` command defaults to `true`, and the interactive `Deploy cluster using AWS STS` prompt is removed. To create a cluster that uses IAM user credentials instead, you must explicitly specify the `--non-sts` or `--mint-mode` option.
endif::openshift-rosa[]

ifdef::openshift-rosa[]
IMDSv2 required by default::
+
New {product-title} clusters now default to requiring Amazon EC2 Instance Metadata Service Version 2 (IMDSv2). The IMDS setting is configured at cluster creation and applies to machine pools in the cluster. Existing clusters are unaffected, and the IMDS setting cannot be changed after the cluster is created. For more information regarding IMDS, see link:https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-metadata.html[Instance metadata and user data] in the AWS documentation.
endif::openshift-rosa[]

ifdef::openshift-rosa-hcp[]
IMDSv2 required by default::
+
New {product-title} clusters now default to requiring Amazon EC2 Instance Metadata Service Version 2 (IMDSv2). You can configure the IMDS setting at cluster creation, and you can also set it for an individual machine pool by specifying the `--ec2-metadata-http-tokens` option when you create the machine pool. Existing clusters and machine pools are unaffected, and the IMDS setting cannot be changed after the cluster or machine pool is created. For more information regarding IMDS, see link:https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-metadata.html[Instance metadata and user data] in the AWS documentation.
endif::openshift-rosa-hcp[]
