= Q4 2026

[role="_abstract"]
The following items were added during the fourth quarter of 2026.

ifdef::openshift-rosa-hcp[]
AWS resource tagging improvements::
+
You can include spaces in AWS tag keys and values. In addition, when the same AWS tag key is defined at both the cluster and machine pool levels, the machine pool tag value now takes precedence over the cluster tag value. For more information, see link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws/4/html/cluster_administration/managing-compute-nodes-using-machine-pools#rosa-adding-tags_rosa-managing-worker-nodes[Adding tags to a machine pool].

BGP routing for OpenShift Virtualization on AWS::
+
Border Gateway Protocol (BGP) Cloud Connector integrates {product-title} with {aws-short} Route Server allowing direct, routed connectivity to {VirtProductName} virtual machines (VMs) on {aws-short}. For more information, see the following documentation:

* link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws/4/html-single/advanced_networking/index#about-bgp-routing[About BGP routing for {product-title}]
endif::openshift-rosa-hcp[]

{hcp-capital} is the default in interactive cluster creation::
+
With {rosa-cli} 1.2.66 and later, when you run the `rosa create cluster` command in interactive mode without specifying the `--hosted-cp` option, the `Deploy cluster with Hosted Control Plane` prompt defaults to `Yes`. To create a {rosa-classic-short} cluster interactively, answer `No` at this prompt or specify the `--hosted-cp=false` option.
+
If you specify options that are only compatible with {rosa-classic-short} clusters, such as `--disable-workload-monitoring`, the prompt is skipped. The {rosa-cli} displays an informational message that lists the incompatible options and continues with the classic architecture.
+
Non-interactive cluster creation is unchanged.
ifdef::openshift-rosa[]
+
For more information, see link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_on_aws_classic_architecture/4/html-single/install_rosa_classic_clusters/index#rosa-sts-interactive-mode-reference[Interactive cluster creation mode reference].
endif::openshift-rosa[]

ifdef::openshift-rosa[]
AWS STS is used by default without prompting::
+
With {rosa-cli} 1.2.66 and later, the `--sts` option for the `rosa create cluster` command defaults to `true`, and the interactive `Deploy cluster using AWS STS` prompt is removed. To create a cluster that uses IAM user credentials instead, you must explicitly specify the `--non-sts` or `--mint-mode` option.
endif::openshift-rosa[]

ifdef::openshift-rosa[]
AWS EC2 Instance Metadata Service Version 2 (IMDSv2) is now required by default::
+
New {product-title} clusters now default to requiring IMDSv2, whether you create them by using {cluster-manager}, the {rosa-cli}, Terraform, or the API. The IMDS setting is configured at cluster creation and applies to machine pools in the cluster. Existing clusters are unaffected, and the IMDS setting cannot be changed after the cluster is created.
endif::openshift-rosa[]

ifdef::openshift-rosa-hcp[]
AWS EC2 Instance Metadata Service Version 2 (IMDSv2) is now required by default::
+
New {product-title} clusters and machine pools now default to requiring IMDSv2, whether you create them by using {cluster-manager}, the {rosa-cli}, Terraform, or the API. You can configure the IMDS setting at cluster creation, and you can also set it for an individual machine pool by specifying the `--ec2-metadata-http-tokens` option when you create the machine pool. Existing clusters and machine pools are unaffected. To change the IMDS setting for an existing machine pool, create a new machine pool with the new IMDS setting, migrate your workloads to the new machine pool, and then delete the original machine pool.
endif::openshift-rosa-hcp[]

Configure cluster notification contacts by using the {rosa-cli} or Terraform::
+
With {rosa-cli} 1.2.66 and later, you can specify additional {cluster-manager} account usernames or email addresses to receive cluster notification emails. Use the `--notification-contacts` option with the `rosa create cluster` command to set contacts when you create a cluster, or with the `rosa edit cluster` command to add, change, or remove contacts on an existing cluster. All contacts must belong to the same Red{nbsp}Hat organization as the cluster. The `rosa describe cluster` command displays the configured notification contacts.
+
You can also manage notification contacts by using the `rhcs_cluster_notification_contacts` resource in version 1.7.10 or later of the Red{nbsp}Hat Cloud Services Terraform provider. The resource accepts only {cluster-manager} account usernames and manages the complete set of notification contacts for the cluster, so contacts that you add outside of Terraform are removed the next time you apply your configuration. For more information, see link:https://registry.terraform.io/providers/terraform-redhat/rhcs/latest/docs/resources/cluster_notification_contacts[rhcs_cluster_notification_contacts] in the Terraform Registry.
