= CustomRule platform checks with CEL

[role="_abstract"]
When standard profiles omit checks your environment needs, CEL expressions evaluate Kubernetes API objects and surface `PASS` or `FAIL` results during a compliance scan.

`CustomRule` resources run platform-level checks against Kubernetes and {product-title} API objects, such as pods, roles, and cluster configurations. They do not scan cluster nodes or host filesystems. For host-level checks, such as file permissions or running processes on nodes, use the node `Rule` resources in profiles that the Compliance Operator ships.

Common Expression Language (CEL) is a lightweight policy language used in Kubernetes, including validating admission policies.

A `CustomRule` object works like a `Rule` object in the Compliance Operator, but the Compliance Operator evaluates it with the CEL scanner instead of the checks in shipped profiles. Use `CustomRule` resources to automate organization-specific controls that standard benchmarks, such as CIS or PCI-DSS, do not include.

`CustomRule` resources are not scanned directly. To run a custom check, add the `CustomRule` to a `TailoredProfile`, and link that profile to a `ScanSetting` with a `ScanSettingBinding`.

This example shows how to use a platform `CustomRule` to check `ClusterLogForwarder` resources so that log data is transmitted securely.

`ClusterLogForwarder` resources define where cluster logs are forwarded. Using insecure protocols (HTTP, TCP, UDP) exposes sensitive log data to security risks including Man-in-the-Middle (MitM) attacks, data tampering, and credential exposure. The following example checks rules for handling logs and provides output `FAIL` if the rule is violated and output `PASS` if the rule is obeyed.

This example `CustomRule` validates that all `ClusterLogForwarder` outputs use secure protocols.

* HTTP/Elasticsearch/Loki/Splunk/OTLP must use `https://`
* AzureMonitor, GoogleCloudLogging, LokiStack: no URL fields to validate
* Kafka must use `tls://` (not `tcp://`)
* Syslog must use `tls://` (not `tcp://` or `udp://`)
* S3 and CloudWatch custom endpoints must use `https://`
* TLS certificate verification must not be disabled (`insecureSkipVerify`)

[NOTE]
====
The `kind` must be `CustomRule` and the `scannerType` must be `CEL`.
====

[IMPORTANT]
====
A single `TailoredProfile` cannot contain both standard `Rule` resources and `CustomRule` resources. Use separate `TailoredProfile` definitions for each type.
====


== Common issues and fixes

. HTTP instead of HTTPS:
+
[source,yaml]
----
# Insecure
outputs:
  - name: my-loki
    type: loki
    loki:
      url: http://loki.example.com

# Secure
outputs:
  - name: my-loki
    type: loki
    loki:
      url: https://loki.example.com
----

. Kafka using TCP instead of TLS:
+
[source,yaml]
----
# Insecure
kafka:
  url: tcp://kafka.example.com:9092

# Secure
kafka:
  url: tls://kafka.example.com:9093
----

. TLS verification disabled:
+
[source,yaml]
----
# Insecure
tls:
  insecureSkipVerify: true

# Secure
tls:
  insecureSkipVerify: false
----
