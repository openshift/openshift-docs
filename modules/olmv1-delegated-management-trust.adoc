= Trust boundaries for delegated extension management

[role="_abstract"]
Delegated extension management for {product-title} expands the trust boundary of the cluster by allowing users to request installations through a privileged controller. The approved extensions, their configuration, and the access you grant determine the scope of that expanded trust.

{olmv1-first} installs extension resources with `cluster-admin` permissions. To delegate management of these privileged installations, use the following controls:

* Role-based access control (RBAC) limits who can access the `ClusterExtension` API.
* A validating admission policy limits the packages, versions, catalogs, and installation namespaces that authorized users can specify.

An extension uses the service accounts and runtime permissions defined by its bundle and supported configuration. Admission restrictions on installation requests do not limit those runtime permissions.

Also, selecting an installation namespace does not restrict all extension resources or actions to that namespace.

Extensions differ in the resources they create, the permissions they require, and the configuration they support. A new bundle version can change these resources, permissions, and configuration. You must perform a new security review before approving a new bundle version.
