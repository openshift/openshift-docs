= Dual-stream {op-system} support for {hcp} node pools

[role="_abstract"]
{hcp-capital} supports running {op-system-base} 9 and {op-system-base} 10 boot images simultaneously within a single hosted cluster by assigning each `NodePool` resource to a specific {op-system-first} major version.

You control the operating system stream for each `NodePool` resource by using the `spec.osImageStream` API field, which accepts the `rhel-9` and `rhel-10` values. This capability is unique to {hcp} and is not available in standalone {product-title}, where all nodes in a cluster must share the same {op-system} version.

[id="hcp-dual-stream-hcp-vs-standalone_{context}"]
== How dual-stream differs from standalone {product-title}

In standalone {product-title}, all nodes in a cluster always run the same {op-system} major version. You cannot mix {op-system-base} 9 and {op-system-base} 10 nodes within a single cluster.

In {hcp}, each `NodePool` resource has its own {op-system} boot image selection. Many `NodePool` resources within the same `HostedCluster` resource can run different {op-system} major versions simultaneously. With this architecture, you can complete the following tasks:

* Migrate workloads incrementally from {op-system-base} 9 to {op-system-base} 10 by running both versions in parallel.
* Pin workloads with {op-system-base} 9 dependencies (such as `runc`) to {op-system-base} 9 `NodePool` resources while moving other workloads to {op-system-base} 10.
* Test {op-system-base} 10 compatibility on a subset of nodes without replacing the entire cluster.

[id="hcp-dual-stream-active-stream_{context}"]
== Observing the active stream

The `status.osImageStream` field on a `NodePool` resource reports the {op-system} stream that is currently active across the pool's nodes. The controller determines the observed stream by majority consensus across the `NodeInfo.OSImage` values reported by Cluster API Machine objects in the pool:

* {op-system} versions in the 4.xx series (for example, `4.22.x`) indicate `rhel-9`.
* {op-system} versions in the 5.xx series (for example, `5.0.x`) indicate `rhel-10`.

[NOTE]
====
This version series mapping is enforced by the stream detection logic of the {hcp} controller, not derived by users.
====

The majority-consensus rule means that `status.osImageStream` reflects the stream of the majority of nodes. During a rolling node replacement, the status field might temporarily show the old stream until most nodes have been replaced.
