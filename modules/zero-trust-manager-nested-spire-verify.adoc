= Verifying nested SPIRE

[role="_abstract"]
Confirm that the downstream SPIRE server is signing workload identities with the upstream CA.

.Prerequisites

* You configured the upstream cluster and the downstream cluster.
* The `UPSTREAM_KUBECONFIG` and `DOWNSTREAM_KUBECONFIG` environment variables are set.

.Procedure

. Check the nested SPIRE conditions on the upstream cluster by running the following command:
+
[source,terminal]
----
$ oc get spireserver cluster --kubeconfig="${UPSTREAM_KUBECONFIG}" -o jsonpath='{range .status.conditions[*]}{.type}{" "}{.status}{" "}{.reason}{"\n"}{end}'
----
+
`GRPCEndpointAvailable` is `True` with reason `RouteCreated`. `DownstreamClustersValid` is `True` with reason `Ready`.

. Check the nested SPIRE conditions on the downstream cluster by running the following command:
+
[source,terminal]
----
$ oc get spireserver cluster --kubeconfig="${DOWNSTREAM_KUBECONFIG}" -o jsonpath='{range .status.conditions[*]}{.type}{" "}{.status}{" "}{.reason}{"\n"}{end}'
----
+
`UpstreamAgentAvailable` and `UpstreamCSIDriverAvailable` are `True` with reason `Ready`.

. Confirm that the downstream server prepared an upstream-signed CA by running the following command:
+
[source,terminal]
----
$ oc logs spire-server-0 -c spire-server -n zero-trust-workload-identity-manager --kubeconfig="${DOWNSTREAM_KUBECONFIG}" | grep "X509 CA"
----
+
A healthy downstream server logs `X509 CA prepared` with `self_signed=false` and a non-empty `upstream_authority_id`. Repeat this check on every tier.
+
If the log shows `self_signed=true`, the server is still using a CA that does not chain to the shared root. For more information, see xref:#zero-trust-manager-nested-spire-troubleshooting_{context}[Troubleshooting nested SPIRE].
