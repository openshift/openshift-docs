= Troubleshooting toolsets

[role="_abstract"]
Diagnose and resolve common problems that can occur when you enable and configure toolsets in MCP server for Red{nbsp}Hat OpenShift.

Use the following table to troubleshoot the `ossm` toolset.

.Troubleshooting the `ossm` toolset
[cols="1,3",options="header"]
|===
|Issue|Resolution
|Missing Kiali configuration when the `ossm` toolset is enabled.
|Set `[toolset_configs.kiali].url` in `config.toml`.
|Invalid URL. 
|Ensure `[toolset_configs.kiali].url` is a valid `http(s)://host` URL.
|TLS certificate validation.
|* If `[toolset_configs.kiali].url` uses HTTPS and `[toolset_configs.kiali].insecure` is false, you must set `[toolset_configs.kiali].certificate_authority` with the path to the CA certificate file. Relative paths are resolved relative to the directory containing the config file.

* For non-production environments you can set `[toolset_configs.kiali].insecure = true` to skip certificate verification.
|The server does not start after you enable `ossm|Set `[toolset_configs.kiali].url`.
|The URL is rejected.|Use an `http://` or `https://` URL that includes a host.
|HTTPS fails certificate verification.|Set `certificate_authority` to the CA file, or, outside production, set `insecure = true`.
|A tool returns no data or an authorization error.|The token presented to Kiali cannot read that namespace or resource. Bind the identity to `kiali-viewer` or `kiali`.
|`ossm_manage_istio_config` is not offered.|The server is running with `read_only = true`.
|===
