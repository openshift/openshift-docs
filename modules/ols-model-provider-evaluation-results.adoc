[role="_abstract"]
Red{nbsp}Hat evaluates supported large language model (LLM) provider and model combinations by using open source evaluation harnesses. The following tables summarize the most recent evaluation harness scores for classic chat and Agentic {ols-long}. You can run the same harnesses yourself against any supported provider with the models of your choosing.

[NOTE]
====
Red{nbsp}Hat does not provide support for any specific models or make suggestions or support statements pertaining to models. The following results are provided for guidance only. Model quality can change between model versions, and your results can vary depending on your workloads, prompts, and configuration.
====

[id="ols-evaluation-results-classic-chat_{context}"]
== Classic chat evaluation results

The classic chat evaluation harness runs a question-and-answer dataset against a running {ols-long} Service and uses a judge LLM to score each response. The evaluation harness score is the aggregate pass rate across the configured quality metrics, where the default metric is answer correctness measured against an expected answer with a pass threshold of `0.7`.

[id="ols-evaluation-results-run-your-own_{context}"]
== Running the evaluations yourself

You can run the same evaluation harnesses against any supported provider by using the models of your choosing. The harnesses are open source.

* Classic chat evaluation harness: the evaluation datasets and configurations are in the link:https://github.com/openshift/lightspeed-service/tree/main/eval[`eval` directory of the `lightspeed-service` repository], and the scoring tool is the link:https://github.com/lightspeed-core/lightspeed-evaluation[`lightspeed-evaluation` project]. Follow the instructions in the `eval` directory to run an evaluation against your own provider and model.

* Agentic evaluation harness: the end-to-end evaluation scenarios are in the link:https://github.com/openshift/lightspeed-agentic-sandbox[`lightspeed-agentic-sandbox` repository]. Follow the repository instructions to run the scenarios against your own provider and model.
