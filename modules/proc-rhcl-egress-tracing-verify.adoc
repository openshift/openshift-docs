= Verify traces from an egress gateway

[role="_abstract"]
Confirm that your egress `Gateway` object produces both the gateway trace and the {prodname} filter trace, and correlate the two traces for a single outbound request.

.Prerequisites

include::snippets/egress-gateway-prereqs.adoc[]

* You configured data plane tracing in the `Kuadrant` custom resource (CR) and in {service-mesh}.
* You applied at least one policy to the egress `Gateway` object or to one of its routes.
* You installed {TempoName}, or another tracing back end, and you can reach its UI.

.Procedure

. Confirm that the {prodname} Operator created the tracing `EnvoyFilter` object by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc get envoyfilter -n _<gateway_system>_ -l kuadrant.io/tracing=true
----
+
.Example output
[source,text]
----
NAME                                      AGE
kuadrant-tracing-kuadrant-egressgateway   10s
----

. Send a request through the egress `Gateway` object with a known request identifier by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc exec -n egress-test test-client -- \
    curl -sS -o /dev/null -w '%{http_code}' \
    "http://${EGRESS_IP}/get" -H "Host: _<api.example.com>_" \
    -H "x-request-id: egress-trace-test" --max-time 10
----
+
* Replace `_<api.example.com>_` with the hostname of your external service.
* The `x-request-id` header value identifies the request in both traces.

.Verification

. In the {TempoShortName} UI, select the `kuadrant-filter` service and search for the tag `request_id=egress-trace-test`. The trace includes the policy evaluation spans of the `wasm-shim` module, Authorino, and Limitador.

. Select the service of your egress gateway proxy, which has the form `_<kuadrant_egressgateway>_-istio._<gateway_system>_`, and search for the tag `guid:x-request-id=egress-trace-test`. The trace includes the proxy spans for the same request.
