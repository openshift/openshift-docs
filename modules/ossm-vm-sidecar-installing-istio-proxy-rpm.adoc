= Installing the istio-proxy RPM on the virtual machine

[role="_abstract"]

Install the `istio-proxy` RPM on the virtual machine, place the generated configuration files in the locations that the proxy reads, and start the service. After the service starts, the virtual machine registers itself with the control plane and joins the mesh.

.Prerequisites

* The virtual machine runs Red Hat Enterprise Linux (RHEL) 9 and is registered with Red Hat Subscription Management.

* You have transferred the contents of the `vm-files` directory to the virtual machine.

* You have root access on the virtual machine.

.Procedure

. Enable the {SMProductName} repository by running the following command on the virtual machine:
+
[source,terminal]
----
$ sudo subscription-manager repos --enable ossm-3-for-rhel-9-x86_64-rpms
----

. Install the `istio-proxy` package by running the following command:
+
[source,terminal]
----
$ sudo dnf install -y istio-proxy
----

. Create the directory for the service account token by running the following command:
+
[source,terminal]
----
$ sudo mkdir -p /var/run/secrets/tokens
----

. Place the generated files in the locations listed in the following table:
+
.Destination of each generated file
[options="header"]
[cols="1,2"]
|===
|Generated file |Destination on the virtual machine

|`root-cert.pem`
|`/etc/certs/root-cert.pem`

|`istio-token`
|`/var/run/secrets/tokens/istio-token`

|`cluster.env`
|`/var/lib/istio/envoy/cluster.env`

|`mesh.yaml`
|`/etc/istio/config/mesh`
|===
+
[NOTE]
====
The `mesh.yaml` file is renamed to `mesh` at its destination.
====

. Grant the `istio-proxy` user access to the configuration directories by running the following command:
+
[source,terminal]
----
$ sudo chown -R istio-proxy /var/lib/istio /etc/certs /etc/istio/proxy /etc/istio/config /var/run/secrets
----

. Start the service and enable it to start at boot by running the following command:
+
[source,terminal]
----
$ sudo systemctl enable --now istio-proxy
----

.Verification

. Verify that the service is active by running the following command on the virtual machine:
+
[source,terminal]
----
$ sudo systemctl status istio-proxy
----

. Verify that the virtual machine registered itself with the control plane by running the following command on the cluster:
+
[source,terminal]
----
$ oc get workloadentries -n external-vm
----
+
*Example output:*
+
[source,terminal]
----
NAME                  AGE   ADDRESS
vm-app-10.0.2.2-vm-network   30s   10.0.2.2
----
