= Go runtime tuning for the Application Controller

The {gitops-title} Operator automatically tunes the Go runtime of the Argo CD Application Controller based on the resource limits configured in the `ArgoCD` custom resource (CR). When you configure resource limits on the Application Controller, the Operator computes and injects the `GOMEMLIMIT` and `GOMAXPROCS` environment variables into the Application Controller StatefulSet. These settings help align the Go garbage collector and scheduler with the container's CPU and memory limits.

Tuning automatically activates for all Argo CD instances that define resource limits on the Application Controller.

*Benefits of Go runtime tuning*

Improved memory management:: The `GOMEMLIMIT` setting establishes a soft memory limit for the Go runtime, helping the garbage collector manage memory more efficiently. This can reduce the risk of out-of-memory (OOM) kills, though it does not guarantee that the container will never be OOM-killed.

Optimized CPU use:: The `GOMAXPROCS` setting controls the maximum number of CPUs that can run Go code simultaneously. The Operator calculates this value based on the configured CPU limit, helping align Go application concurrency with the available CPU resources.

Automatic configuration:: The Operator automatically calculates appropriate values based on your resource limits, eliminating the need to manually tune these environment variables.

*How the Operator computes runtime values*

The Operator computes the Go runtime environment variables as follows:

`GOMEMLIMIT`:: The Operator derives this value from the Application Controller memory limit (`.spec.controller.resources.limits.memory`), multiplied by the configured `memoryLimitPercent` value. The default percentage is `80`. The remaining headroom provides space for memory allocations outside the Go runtime's managed memory and for garbage collection operations.

`GOMAXPROCS`:: The Operator derives this value from the CPU limit (`.spec.controller.resources.limits.cpu`) at 100% of the limit, rounding down to whole cores. For CPU limits below one core, such as `250m`, the Operator sets the value to `1` because `GOMAXPROCS=0` is invalid.

The Operator injects `GOMEMLIMIT` only when you configure the Application Controller memory limit. The Operator injects `GOMAXPROCS` only when you configure the Application Controller CPU limit.

[NOTE]
====
If you do not set the corresponding resource limit, the Operator does not inject that environment variable.
====
