The {otel} 3.11.1 release fixes this issue:

TargetAllocator endpoint uses FQDN to work behind HTTP proxy::
Before this update, the Collector used a bare service name (`+http://<name>-targetallocator:80+`) to contact the Target Allocator. When the cluster was behind a corporate HTTP proxy, the bare hostname did not match the standard `NO_PROXY=.svc` entry, causing the request to route through the proxy instead of reaching the service directly. As a consequence, the proxy returned an HTML authentication page instead of the expected JSON response, breaking the metrics scraping pipeline. With this release, the Target Allocator endpoint uses the fully qualified domain name (FQDN) (`+http://<name>-targetallocator.<namespace>.svc:80+`). As a result, the endpoint matches the standard `NO_PROXY=.svc` pattern, and the Collector reaches the Target Allocator directly without routing through the proxy.
