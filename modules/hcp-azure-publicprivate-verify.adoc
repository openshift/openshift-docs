= Verifying endpoint accessibility for a PublicAndPrivate hosted cluster

[role="_abstract"]
After you create a hosted cluster on {azure-short} with `PublicAndPrivate` topology, you must verify that the Kubernetes API Server endpoint is reachable from both the public internet and the private Azure VNet.

Successful verification confirms that the control plane is healthy, private connectivity resources are provisioned, and DNS is resolving correctly. Verification is crucial, as topology misconfiguration is partially irreversible.

.Prerequisites

* You have a running hosted cluster on {azure-short} with `PublicAndPrivate` or `Private` topology.
* The `oc` CLI is installed and authenticated to the cluster management plane.
* For private VNet verification, you have access to a jumpbox VM or other host inside the guest {azure-short} VNet, or the ability to use port-forwarding from inside the VNet.

.Procedure

. Check the HostedCluster `Available` condition to confirm the control plane is running by entering the following command:
+
[source,terminal]
----
$ oc get hostedcluster <cluster_name> -n clusters \
  -o jsonpath='{.status.conditions[?(@.type=="Available")]}'
----
+
Replace `<cluster_name>` with the name of your hosted cluster.
+
Verify that `"status":"True"` is displayed in the output.

. Retrieve the `AzurePrivateLinkService` CR conditions to verify that the private link chain is fully provisioned by entering the following command:
+
[source,terminal]
----
$ oc get azureprivatelinkservices -n clusters-<cluster_name> -o yaml
----
+
Verify that all five conditions are `True`:
+
* `AzureInternalLoadBalancerAvailable`
* `AzurePLSCreated`
* `AzurePrivateEndpointAvailable`
* `AzurePrivateDNSAvailable`
* `AzurePrivateLinkServiceAvailable`
+
If any condition is `False`, see "AzurePrivateLinkService conditions reference" for diagnosis guidance.

. Verify DNS resolution of the private API hostname from inside the guest VNet.
+
From a host inside the guest {azure-short} VNet, resolve the private API hostname by entering the following command:
+
[source,terminal]
----
$ nslookup api.<cluster_name>.<base_domain>
----
+
Replace `<base_domain>` with the base domain configured at cluster creation.
+
The hostname must resolve to the Private Endpoint IP address, not a public IP address. If the hostname resolves to a public IP, verify that the Private DNS zone is correctly linked to the guest VNet.

. Confirm API reachability from the public internet by using the hosted cluster `kubeconfig` by entering the following command:
+
[source,terminal]
----
$ oc get nodes --kubeconfig <path_to_hosted_cluster_kubeconfig>
----
+
Replace `<path_to_hosted_cluster_kubeconfig>` with the path to the hosted cluster kubeconfig file.
+
A successful node listing confirms that the public Kubernetes API Server endpoint is reachable.

. Confirm API reachability from inside the private {azure-short} VNet.
+
From a jumpbox VM or other host inside the private {azure-short} VNet, run the following command:
+
[source,terminal]
----
$ oc get nodes --kubeconfig <path_to_hosted_cluster_kubeconfig>
----
+
A successful node listing confirms that the private Kubernetes API Server endpoint is reachable from within the VNet.
+
[IMPORTANT]
====
By default, private DNS zones are linked only to the hosted cluster's VNet. If you require DNS resolution from peered VNets, manually link the Private DNS zone to each peered VNet after cluster creation. Failure to link peered VNets results in DNS resolution failures from those networks.
====
