= Supported bonding modes for OVS bridges

[role="_abstract"]
You can run VM traffic over a bonded interface to increase resiliency. The following bonding modes are supported when you configure an OVS bridge for a localnet network.

[NOTE]
====
If you use the default machine network as the uplink connection, see "Creating a customized `br-ex` bridge" in the Additional resources section for Day 1 configuration.
====

Source load balancing (`balance-slb`):: This mode balances traffic from different VMs across the physical links based on the source MAC address and VLAN. It works without needing special switch support, making it useful when the physical switch is not configured for Link Aggregation Control Protocol (LACP).
+
.Example `NodeNetworkConfigurationPolicy` manifest with `balance-slb` bonding
[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: network-config
spec:
  desiredState:
    interfaces:
    # ...
    - name: br1
      type: ovs-bridge
      state: up
      bridge:
        # ...
        port:
        - name: bond1
          link-aggregation:
            mode: balance-slb
            port:
              - name: eno1np0
              - name: eno2np1
----

Active-backup (mode 1):: This mode is only partially supported. It creates a highly available network link where one physical interface is active and others are on standby. In the event of failure, a backup interface takes over, providing fault tolerance without increased bandwidth.
+
.Example `NodeNetworkConfigurationPolicy` manifest with `active-backup` bonding
[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: network-config
spec:
  desiredState:
    interfaces:
    # ...
    - name: bond1
      type: bond
      state: up
      link-aggregation:
        mode: active-backup
        port:
        - eno1np0
        - eno2np1
----

LACP (mode 4 / IEEE 802.3ad):: Also known as Link Aggregation Control Protocol (LACP), this mode creates a single logical link from multiple physical interfaces for increased bandwidth and redundancy. This mode requires compatible switch configuration.
+
.Example `NodeNetworkConfigurationPolicy` manifest with `802.3ad` bonding
[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: network-config
spec:
  desiredState:
    interfaces:
    # ...
    - name: bond1
      type: bond
      state: up
      link-aggregation:
        mode: 802.3ad
        port:
        - eno1np0
        - eno2np1
----

XOR (mode 2 / `balance-xor`):: This mode uses an XOR hash of source and destination MAC addresses to select a physical interface for traffic, providing both load balancing and fault tolerance across active links. Other `xmit_hash_policy` options are available. For more information, see "Which bonding modes work when used with a bridge that virtual machine guests or containers connect to?" in the Additional resources section.
+
.Example `NodeNetworkConfigurationPolicy` manifest with `balance-xor` bonding
[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: network-config
spec:
  desiredState:
    interfaces:
    # ...
    - name: bond1
      type: bond
      state: up
      link-aggregation:
        mode: balance-xor
        options:
          xmit_hash_policy: layer2+3
        port:
        - eno1np0
        - eno2np1
----

[IMPORTANT]
====
{VirtProductName} does not support bridge bonding modes 0, 5, and 6. Mode 1 is only partially supported. For more information, see "Which bonding modes work when used with a bridge that virtual machine guests or containers connect to?" in the _Additional resources_ section.
====
