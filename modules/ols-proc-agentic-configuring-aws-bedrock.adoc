= Connect an {aws-first} Bedrock provider to Agentic {ols-long}

[role="_abstract"]
To use {aws-short} Bedrock as the large language model (LLM) provider for Agentic {ols-long}, create a credentials secret that contains your {aws-short} access keys, an `LLMProvider` custom resource (CR) with the `AWSBedrock` type, and an `Agent` CR that uses that provider.

.Prerequisites

* You have installed the {ols-long} Operator.
* You have logged in to the cluster as a user with the `cluster-admin` role, or with permission to create cluster-scoped custom resources.
* You have {aws-short} credentials with permission to call {aws-short} Bedrock, including an access key ID and a secret access key.

.Procedure

. Create a credentials secret in the `openshift-lightspeed` namespace by running the following command:
+
[source,terminal]
----
$ oc create secret generic llm-credentials \
  --from-literal=AWS_ACCESS_KEY_ID=<access_key_id> \
  --from-literal=AWS_SECRET_ACCESS_KEY=<secret_access_key> \
  -n openshift-lightspeed
----

. Create an `LLMProvider` CR that uses the `AWSBedrock` type:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: LLMProvider
metadata:
  name: aws-bedrock
spec:
  type: AWSBedrock
  awsBedrock:
    credentialsSecret:
      name: llm-credentials # <1>
    region: <aws_region> # <2>
    url: <api_endpoint_url> # <3>
----
<1> The name of the credentials secret that contains the `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` keys in the `openshift-lightspeed` namespace.
<2> The {aws-short} region for the Bedrock endpoint, for example, `us-east-1`.
<3> Optional: An override for the {aws-short} Bedrock API endpoint. Set this value only for custom deployments or API proxies.

. Create an `Agent` CR that references the `LLMProvider` and specifies the model to use:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: Agent
metadata:
  name: default # <1>
spec:
  llmProvider:
    name: aws-bedrock # <2>
  model: <model_id> # <3>
  maxTurns: 200
----
<1> The `default` agent must exist. The deployment uses it when a workflow step does not specify an agent.
<2> The name of the `LLMProvider` CR that you created.
<3> The {aws-short} Bedrock model or inference-profile identifier to use.

. Apply the custom resources by running the following command:
+
[source,terminal]
----
$ oc apply -f <cr_filename>.yaml
----

.Verification

* Confirm that the resources exist by running the following commands:
+
[source,terminal]
----
$ oc get llmprovider aws-bedrock
----
+
[source,terminal]
----
$ oc get agent default
----
