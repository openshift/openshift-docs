= HTTP Add-on autoscaling general workflow

[role="_abstract"]
You can use the following steps to understand the general workflow of the HTP Add-on process. 

. Create a namespace for the example application.

. Create a sample HTTP application deployment. For more information, see

. Create a service to expose the application. For more information, see

. Create a route to expose the application externally. For more information, see

. Create an interceptor route to intercept traffic. For more information, see "About configuring an interceptor route custom resource" in this section.

. Create a scaled object to configure autoscaling. For more information, see "About configuring an HTTP Add-on scaled object trigger" in this section.

. Update the route to point to the interceptor service. For more information, see

. Verify the autoscaling configuration is active:
* Use the `keda-sample-app-scaler -n <namespace_name>` command to check that an HPA was created by the scaled object.
* Use the `oc get deployment <app-name> -n <namespace_name>` command to verify that the deployment currently has zero replicas (because there is no traffic)

. Generate traffic to observe autoscaling behavior. 

. Use the `oc get deployment <app-name> -n <namespace_name> -w` command to watch the deployment scale up in response to traffic. You should see the `READY` and `AVAILABLE` change.

. Use the oc describe hpa keda-<scaled-object-name> -n <namespace_name>

. Stop the load generator and observe scale-to-zero:
* Use the `oc delete pod load-generator -n <namespace_name>` command to delete the load generation pod.
* Wait for the cooldown period.
* Use the `oc get deployment <app-name> -n <namespace_name> -w` command to watch the deployment scale down to zero replicas.
