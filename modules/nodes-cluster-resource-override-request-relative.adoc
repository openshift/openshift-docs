= Scaling CPU requests relative to existing requests

[role="_abstract"]
You can use the `RequestRelative` CPU override strategy to reduce CPU requests as a percentage of the existing request value, independent of whether a CPU limit is set. This is useful for Helm charts that define CPU requests without corresponding limits, or for architecture-specific optimization.

== When to use RequestRelative

The traditional `LimitRelative` strategy computes the new CPU request as a percentage of the CPU limit. However, this approach has limitations:

* Helm charts often define CPU requests without CPU limits
* Containers without CPU limits are not affected by `LimitRelative` overrides
* Different architectures may require different request scaling

The `RequestRelative` strategy overcomes these limitations by scaling the request value itself.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the Cluster Resource Override Operator.

.Procedure

. Create a `ClusterResourceOverride` profile using `RequestRelative` strategy:
+
[source,yaml]
----
apiVersion: operator.autoscaling.openshift.io/v1
kind: ClusterResourceOverride
metadata:
  name: helm-chart-optimized
spec:
  podResourceOverride:
    spec:
      cpuRequestOverride:
        type: RequestRelative
        requestRelative:
          percent: 50
      memoryRequestToLimitPercent: 25
----
+
where:
+
--
`cpuRequestOverride.type`:: Set to `RequestRelative` to use request-based scaling.
`requestRelative.percent`:: Specifies the percentage of the existing CPU request to use as the new request. For example, 50 means the request is halved, 75 means it is reduced to 75% of the original.
--

. Create a binding to apply this profile to namespaces using Helm charts:
+
[source,yaml]
----
apiVersion: operator.autoscaling.openshift.io/v1
kind: ClusterResourceOverrideBinding
metadata:
  name: helm-optimization
spec:
  overrideRef: helm-chart-optimized
  namespaceSelector:
    matchLabels:
      helm-optimization: "true"
----

. Label the namespaces where you want to apply request-relative scaling:
+
[source,terminal]
----
$ oc label namespace <namespace> helm-optimization=true
----

. Verify the override is applied by checking a pod's resources:
+
[source,terminal]
----
$ oc get pod <pod-name> -n <namespace> -o jsonpath='{.spec.containers[0].resources.requests.cpu}'
----
+
The output should show the CPU request reduced according to the `percent` value.

== Example: Architecture-specific optimization

For clusters running on non-x86 architectures, you can use `RequestRelative` to optimize CPU requests calibrated for x86:

[source,yaml]
----
apiVersion: operator.autoscaling.openshift.io/v1
kind: ClusterResourceOverride
metadata:
  name: arm64-optimized
spec:
  podResourceOverride:
    spec:
      cpuRequestOverride:
        type: RequestRelative
        requestRelative:
          percent: 25
      memoryRequestToLimitPercent: 80
---
apiVersion: operator.autoscaling.openshift.io/v1
kind: ClusterResourceOverrideBinding
metadata:
  name: arm64-binding
spec:
  overrideRef: arm64-optimized
  namespaceSelector:
    matchLabels:
      architecture: arm64
----

In this example, pods in ARM64 namespaces have their CPU requests reduced to 25% of the original values, allowing for better density without overcommitting resources.
