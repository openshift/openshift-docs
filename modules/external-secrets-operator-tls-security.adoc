= Transport Layer Security profile support

[role="_abstract"]
Align secure connections with your cluster policy by applying the Transport Layer Security (TLS) profile to the {external-secrets-operator}. Enable profile adherence with the StrictAllComponents setting.

The cluster defines the profile in the `apiserver.config.openshift.io/cluster` `APIServer` custom resource (CR). When the profile is in effect, the {external-secrets-operator-short} applies it to the following components:

* The secure serving endpoints of the {external-secrets-operator-short} for metrics and the webhook
* The `external-secrets`, `external-secrets-webhook`, and `external-secrets-cert-controller` operand `Deployment` objects
* The `bitwarden-sdk-server` operand `Deployment`, when you enable it

The {external-secrets-operator-short} injects the following operand container arguments, derived from the cluster TLS security profile:

* `--tls-min-version=<version>`
* `--tls-ciphers=<cipher_list>`

When the minimum TLS version is 1.3, such as with the `Modern` profile, the {external-secrets-operator-short} omits the `--tls-ciphers` argument.

[id="external-secrets-operator-tls-adherence_{context}"]
== Transport Layer Security adherence

To apply the cluster TLS security profile to the {external-secrets-operator-short}, set the `spec.tlsAdherence` field to `StrictAllComponents` in the `APIServer` CR. This setting requires cluster-wide adherence.

If you leave the `spec.tlsAdherence` field unset or select `LegacyAdheringComponentsOnly`, the {external-secrets-operator-short} and the operands retain their default TLS settings.

When the TLS security profile or the adherence policy changes, the {external-secrets-operator-short} restarts. The restart reloads the new settings and reconciles operand `Deployment` objects.
