= Improved Central rollout downtimes

// JIRA: ROX-33759

[role="_abstract"]
{product-title-short} can now reduce Central downtime during upgrades and configuration changes by optionally using a `RollingUpdate` rollout strategy.

When enabled, the existing Central pod keeps serving until the new pod is ready. Long-running database work such as index creation and table backfills can continue in the background after the upgrade, so those operations no longer block Central from becoming ready.

For more information, see the "central.rolloutStrategy" field in "Central configuration options using the Operator".
