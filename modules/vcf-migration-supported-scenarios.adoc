= Supported VCF migration scenarios and limitations

[role="_abstract"]
Before you migrate your {product-title} cluster, verify that your source and target environments are in a supported migration path.
The VCF Migration Operator supports specific combinations of source and target vCenter versions.

.Supported migration paths
[cols="1,1", options="header"]
|===
|Source environment
|Target environment

|{vmw-short} 7.x
|{vmw-short} 8.x

|{vmw-short} 8.x
|{vmw-short} 8.x (later version)

|VCF 4.x
|VCF 5.x

|VCF 5.x
|VCF 5.x (later version)

|Any supported source ({vmw-short} 7.x, {vmw-short} 8.x, VCF 4.x, or VCF 5.x)
|VCF9 or VVF9
|===

.Cluster requirements
[cols="1,2", options="header"]
|===
|Requirement
|Description

|{product-title} version
|4.18 or later.

|Installation method
|Installer-provisioned infrastructure with Machine API when using the Recreate migration engine. Clusters that use user-provisioned infrastructure can use `VMotion`.

|Machine API
|The Machine API Operator must be healthy and managing node lifecycle. Verify that `Machine` and `MachineSet` objects exist and are in a `Running` phase.

|Target vCenter
|The target vCenter must be accessible from the cluster network. All failure domain topology elements (data center, compute cluster, datastore, networks) must exist on the target.

|Feature gate
|The `VSphereMultiVCenterDay2` feature gate must be enabled on the cluster.

|Cluster health
|All cluster operators must be healthy. No cluster upgrade can be in progress.
|===

.Features not supported in this release
[cols="1,2", options="header"]
|===
|Exclusion
|Details

|{vmw-short} CSI persistent volumes
|Automated migration of persistent volumes that use the `csi.vsphere.vmware.com` driver is not supported. You must remove the {vmw-short} CSI driver and delete all CSI-backed persistent volumes before starting migration. Automated persistent volume migration is planned for a future release.

|Third-party CSI drivers
|Persistent volumes that use third-party CSI drivers are not validated for migration. Verify compatibility with your storage vendor before proceeding.

|Automated rollback
|The operator does not provide automated rollback. If the migration fails partway through, you must follow the manual recovery steps in the troubleshooting section.

|`MachineHealthCheck` resources
|User-defined `MachineHealthCheck` resources must be removed before migration. The platform-managed `machine-api-termination-handler` `MachineHealthCheck` is allowed.

|Cluster autoscalers
|`ClusterAutoscaler` and `MachineAutoscaler` resources must be removed before migration to prevent interference with the migration workflow.
|===

If your cluster uses NSX networking, verify that NSX network segments are configured on the target vCenter before starting the migration.
The VCF Migration Operator migrates the cluster infrastructure but does not configure NSX networking on the target.
