= Override scheduling, arguments, and resources for external-secrets components

[role="_abstract"]
Customize an `external-secrets` component deployment to meet your scheduling and resource requirements or to change its container arguments. Set the `advancedOverrides` field for the relevant component in the `componentConfigs` list of the `ExternalSecretsConfig` custom resource (CR).

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the {oc-first}.
* You have installed `jq`.
* You have created the `ExternalSecretsConfig` CR.

.Procedure

. Edit the `ExternalSecretsConfig` CR by running the following command:
+
[source,terminal]
----
$ oc edit externalsecretsconfigs.operator.openshift.io cluster
----

. Add the `componentConfigs` field under the `spec.controllerConfig`. Include only the overrides that you need, as in the following example:
+
[source,yaml]
----
apiVersion: operator.openshift.io/v1alpha1
kind: ExternalSecretsConfig
metadata:
  name: cluster
spec:
  controllerConfig:
    componentConfigs:
      - componentName: ExternalSecretsCoreController
        advancedOverrides:
          spec:
            template:
              spec:
                affinity:
                  podAntiAffinity:
                    preferredDuringSchedulingIgnoredDuringExecution:
                      - weight: 100
                        podAffinityTerm:
                          topologyKey: kubernetes.io/hostname
                          labelSelector:
                            matchLabels:
                              app: external-secrets
                topologySpreadConstraints:
                  - maxSkew: 1
                    topologyKey: topology.kubernetes.io/zone
                    whenUnsatisfiable: ScheduleAnyway
                containers:
                  - name: external-secrets
                    args:
                      - --concurrent=20
                      - --client-burst=200
                      - --client-qps=100
                    resources:
                      requests:
                        cpu: 200m
                        memory: 256Mi
                      limits:
                        cpu: "1"
                        memory: 512Mi
----
+
where:

`spec.controllerConfig.componentConfigs.componentName`:: Specifies the component to override, such as `ExternalSecretsCoreController`, `Webhook`, `CertController`, or `BitwardenSDKServer`.

`spec.controllerConfig.componentConfigs.advancedOverrides`:: Specifies the changes to apply to the `Deployment` of the component. Include only the allowed `Deployment` field paths. You can omit `containers[].name`. If you set `containers[].name`, the name must match the component container name.

. Save the file.

.Verification

. Verify that the `ExternalSecretsConfig` CR is ready by running the following command:
+
[source,terminal]
----
$ oc get externalsecretsconfigs.operator.openshift.io cluster -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}'
----
+
The output is `True`.

. Verify that the `Deployment` uses the `affinity` override by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.affinity}' | jq .
----
+
.Example output
[source,json]
----
{
  "podAntiAffinity": {
    "preferredDuringSchedulingIgnoredDuringExecution": [
      {
        "podAffinityTerm": {
          "labelSelector": {
            "matchLabels": {
              "app": "external-secrets"
            }
          },
          "topologyKey": "kubernetes.io/hostname"
        },
        "weight": 100
      }
    ]
  }
}
----

. Verify that the `Deployment` uses the `topologySpreadConstraints` override by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.topologySpreadConstraints}' | jq .
----
+
.Example output
[source,json]
----
[
  {
    "maxSkew": 1,
    "topologyKey": "topology.kubernetes.io/zone",
    "whenUnsatisfiable": "ScheduleAnyway"
  }
]
----

. Verify that the `Deployment` uses the container `resources` override by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="external-secrets")].resources}' | jq .
----
+
.Example output
[source,json]
----
{
  "limits": {
    "cpu": "1",
    "memory": "512Mi"
  },
  "requests": {
    "cpu": "200m",
    "memory": "256Mi"
  }
}
----

. Verify that the {external-secrets-operator-short} merges the `args` overrides with the default flags by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="external-secrets")].args}' | jq .
----
+
.Example output
[source,json]
----
[
  "--concurrent=20",
  "--metrics-addr=:8080",
  "--loglevel=warn",
  "--zap-time-encoding=epoch",
  "--enable-leader-election=true",
  "--enable-push-secret-reconciler=true",
  "--enable-cluster-store-reconciler=true",
  "--enable-cluster-external-secret-reconciler=true",
  "--client-burst=200",
  "--client-qps=100"
]
----
