= Configure advancedOverrides for external-secrets components

[role="_abstract"]
Set the `advancedOverrides` field to adjust scheduling, container arguments, and container resources of an `external-secrets` component. The {external-secrets-operator} applies your settings as a strategic merge patch on the generated `Deployment`.

.Prerequisites

* You have access to the cluster with `cluster-admin` privileges.
* You have created the `ExternalSecretsConfig` custom resource (CR).

.Procedure

. Edit the `ExternalSecretsConfig` CR by running the following command:
+
[source,terminal]
----
$ oc edit externalsecretsconfigs.operator.openshift.io cluster
----

. Add the `componentConfigs` field under the `spec.controllerConfig` field as follows:
+
[source,yaml]
----
apiVersion: operator.openshift.io/v1alpha1
kind: ExternalSecretsConfig
metadata:
  name: cluster
spec:
  controllerConfig:
    componentConfigs:
      - componentName: ExternalSecretsCoreController
        advancedOverrides:
          spec:
            template:
              spec:
                affinity:
                  podAntiAffinity:
                    preferredDuringSchedulingIgnoredDuringExecution:
                      - weight: 100
                        podAffinityTerm:
                          topologyKey: kubernetes.io/hostname
                          labelSelector:
                            matchLabels:
                              app: external-secrets
                topologySpreadConstraints:
                  - maxSkew: 1
                    topologyKey: topology.kubernetes.io/zone
                    whenUnsatisfiable: ScheduleAnyway
                containers:
                  - name: external-secrets
                    args:
                      - --concurrent=20
                      - --client-burst=200
                      - --client-qps=100
                    resources:
                      requests:
                        cpu: 200m
                        memory: 256Mi
                      limits:
                        cpu: "1"
                        memory: 512Mi
----
+
where:

`spec.controllerConfig.componentConfigs.componentName.advancedOverrides`:: Specifies the strategic merge patch that the {external-secrets-operator-short} applies to the generated `Deployment` for the named component. The {external-secrets-operator-short} accepts only the allowed `Deployment` field paths. If you omit `containers[].name`, the {external-secrets-operator-short} injects the correct container name for the component. If you set `containers[].name`, it must match the component container name.

.Verification

. Verify that the `ExternalSecretsConfig` CR is ready by running the following command:
+
[source,terminal]
----
$ oc get externalsecretsconfigs.operator.openshift.io cluster -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}'
----
+
The output is `True`. If you set a field outside the allowed `Deployment` field paths, the status is `Degraded` instead.

. Verify that the `Deployment` uses the `affinity` override by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.affinity}' | jq .
----

. Verify that the `Deployment` uses the `topologySpreadConstraints` override by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.topologySpreadConstraints}' | jq .
----

. Verify that the `Deployment` uses the container `resources` override by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="external-secrets")].resources}' | jq .
----

. Verify that the {external-secrets-operator-short} merges the `args` overrides with the default flags by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="external-secrets")].args}'
----
+
The output lists your overridden flags, such as `--concurrent=20`, and the default flags that you did not change, such as `--enable-leader-election=true`.
