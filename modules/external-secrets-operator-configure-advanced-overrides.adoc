= Override scheduling and resources for external-secrets components

[role="_abstract"]
Control where an `external-secrets` pod runs, which arguments the container starts with, and how many resources the container uses. Set the `advancedOverrides` field in the `ExternalSecretsConfig` custom resource (CR) of the {external-secrets-operator-short}.

.Prerequisites

* You have access to the cluster with `cluster-admin` privileges.
* You have installed the {oc-first}.
* You have installed the `jq` command-line JSON processor.
* You have created the `ExternalSecretsConfig` CR.

.Procedure

. Edit the `ExternalSecretsConfig` CR by running the following command:
+
[source,terminal]
----
$ oc edit externalsecretsconfigs.operator.openshift.io cluster
----

. Add the `componentConfigs` field under the `spec.controllerConfig` field. Include only the overrides that you need, as in the following example:
+
[source,yaml]
----
apiVersion: operator.openshift.io/v1alpha1
kind: ExternalSecretsConfig
metadata:
  name: cluster
spec:
  controllerConfig:
    componentConfigs:
      - componentName: ExternalSecretsCoreController
        advancedOverrides:
          spec:
            template:
              spec:
                affinity:
                  podAntiAffinity:
                    preferredDuringSchedulingIgnoredDuringExecution:
                      - weight: 100
                        podAffinityTerm:
                          topologyKey: kubernetes.io/hostname
                          labelSelector:
                            matchLabels:
                              app: external-secrets
                topologySpreadConstraints:
                  - maxSkew: 1
                    topologyKey: topology.kubernetes.io/zone
                    whenUnsatisfiable: ScheduleAnyway
                containers:
                  - name: external-secrets
                    args:
                      - --concurrent=20
                      - --client-burst=200
                      - --client-qps=100
                    resources:
                      requests:
                        cpu: 200m
                        memory: 256Mi
                      limits:
                        cpu: "1"
                        memory: 512Mi
----
+
where:

`spec.controllerConfig.componentConfigs.componentName`:: Specifies the component to override, such as `ExternalSecretsCoreController`, `Webhook`, `CertController`, or `BitwardenSDKServer`.

`spec.controllerConfig.componentConfigs.advancedOverrides`:: Specifies the changes to apply to the `Deployment` of the component. Include only the allowed `Deployment` field paths. You can omit `containers[].name`. If you set `containers[].name`, the name must match the component container name.

. Save the file.

. Exit the editor.

.Verification

. Verify that the `ExternalSecretsConfig` CR is ready by running the following command:
+
[source,terminal]
----
$ oc get externalsecretsconfigs.operator.openshift.io cluster -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}'
----
+
The output is `True`.

. Verify that the `Deployment` uses the `affinity` override by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.affinity}' | jq .
----

. Verify that the `Deployment` uses the `topologySpreadConstraints` override by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.topologySpreadConstraints}' | jq .
----

. Verify that the `Deployment` uses the container `resources` override by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="external-secrets")].resources}' | jq .
----

. Verify that the {external-secrets-operator-short} merges the `args` overrides with the default flags by running the following command:
+
[source,terminal]
----
$ oc get deployment external-secrets -n external-secrets -o jsonpath='{.spec.template.spec.containers[?(@.name=="external-secrets")].args}'
----
+
The output lists your overridden flags, such as `--concurrent=20`, and the default flags that you did not change.
