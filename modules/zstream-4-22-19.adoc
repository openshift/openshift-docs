= RHSA-2026:83541 - {product-title} {product-version}.19 bug fix and security update

Issued: 20 October 2026

[role="_abstract"]
{product-title} release {product-version}.19 is now available. The list of fixed issues that are included in the update is documented in the link:https://access.redhat.com/errata/RHSA-2026:83541[RHSA-2026:83541] advisory. The RPM packages that are included in the update are provided by the link:https://access.redhat.com/errata/RHBA-2026:83539[RHBA-2026:83539] advisory.

== Fixed issues

* Before this update, when the Ingress capability was disabled on a HyperShift hosted cluster, the console operator still attempted to reconcile unavailable ingress resources and run route health checks. As a consequence, the console operator reported degraded or progressing conditions. With this release, the operator skips route and health-check controllers and ingress-dependent reconciliation when Ingress is disabled, and resumes normal operation if Ingress is later enabled. As a result, the console operator no longer reports those conditions when Ingress is disabled. (link:https://issues.redhat.com/browse/OCPBUGS-113612[OCPBUGS-113612])

* Before this update, selecting a specific project in the project selector caused the Namespace column to be hidden in the Pods tab on the Node Details page, even when Namespace was enabled under Manage Columns. As a consequence, users could not determine which namespace each pod belonged to, even though the tab displayed pods from multiple namespaces. With this release, the Namespace column is displayed correctly in the Node Details Pods tab regardless of the selected project. As a result, users can identify the namespace of each pod when viewing the Pods tab on a node. (link:https://issues.redhat.com/browse/OCPBUGS-123201[OCPBUGS-123201])

* Before this update, the boot image controller required an exact match between a `MachineSet` providerSpec workspace and an `Infrastructure` failure domain on all five fields. As a consequence, `MachineSet` resources on clusters without failure domains or with a datastore not listed in any failure domain were silently skipped for boot image management, and boot image skew could grow over time. With this release, matching logic is improved so eligible `MachineSet` resources are not skipped in those cases. As a result, boot images stay managed for `MachineSet` resources that before had no matching failure domain. (link:https://issues.redhat.com/browse/OCPBUGS-129268[OCPBUGS-129268])

* Before this update, when 4.21 clusters that used the multi-arch payload upgraded to 4.22.15 or later, nodes could fail to update in place because of an `rpm-ostree` defect that omitted Open vSwitch binaries from the RHCOS image. As a consequence, affected nodes could become unrecoverable during the update. With this release, the Machine Config Daemon works around that `rpm-ostree` defect so that nodes update properly across this transition. As a result, multi-arch payload clusters can complete the update; clusters that use a single-arch payload were not affected. (link:https://issues.redhat.com/browse/OCPBUGS-129375[OCPBUGS-129375])

* Before this update, vSphere machine reconciliation made repeated vCenter API calls for the same virtual machine state and attached tags, and could repeat operations when task references were missing or status updates failed. As a consequence, reconciliation generated unnecessary vCenter API load, could submit duplicate virtual machine operations, and slowed machine provisioning in large clusters. With this release, VM power state and tag lookups are cached, attached-tag queries are batched, redundant property calls are skipped, and clone task references are retained across reconciles. As a result, new machines provision more reliably and with less vCenter load in large vSphere-backed clusters. (link:https://issues.redhat.com/browse/OCPBUGS-129423[OCPBUGS-129423])
