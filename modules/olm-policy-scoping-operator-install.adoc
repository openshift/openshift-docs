= Scoping Operator installations

[role="_abstract"]
To provide scoping rules to Operator installations and upgrades on Operator Lifecycle Manager (OLM), associate a service account with an Operator group.

The following example provides a template for configuring an Operator group to use a service account with role-based access control (RBAC) permissions within a designated namespace. Replace the placeholders with values for the Operator installation before running the commands.

include::snippets/olmv0-failed-install-cluster-role-bindings.adoc[]

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the OpenShift CLI (`oc`).
* You have identified the API groups, resources, and verbs required to install the Operator.

.Procedure

. Create a new namespace:
+
.Example command that creates a `Namespace` object
[source,terminal]
----
$ cat <<EOF | oc create -f -
apiVersion: v1
kind: Namespace
metadata:
  name: scoped
EOF
----

. Configure a service account, role, and role binding in the designated namespace with the permissions approved for delegated installation:

.. Create a service account by running the following command:
+
.Example command that creates a `ServiceAccount` object
[source,terminal]
----
$ cat <<EOF | oc create -f -
apiVersion: v1
kind: ServiceAccount
metadata:
  name: scoped
  namespace: scoped
EOF
----

.. Create a secret by running the following command:
+
.Example command that creates a long-lived API token `Secret` object
[source,terminal]
----
$ cat <<EOF | oc create -f -
apiVersion: v1
kind: Secret
type: kubernetes.io/service-account-token
metadata:
  name: scoped
  namespace: scoped
  annotations:
    kubernetes.io/service-account.name: scoped
EOF
----
+
The secret must be a long-lived API token, which is used by the service account.

.. Create a role and role binding by using the following template. Grant only the permissions that you intend to delegate. Use separate rules when different resources require different verbs. For more information, see "Fine-grained permissions".
+
.Example command that creates `Role` and `RoleBinding` objects
[source,terminal]
----
$ cat <<EOF | oc create -f -
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: scoped
  namespace: scoped
rules:
- apiGroups: ["<api_group>"]
  resources: ["<resource>"]
  verbs: ["<verb>"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: scoped-bindings
  namespace: scoped
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: scoped
subjects:
- kind: ServiceAccount
  name: scoped
  namespace: scoped
EOF
----
+
where:

`<api_group>`:: Specifies the API group for the resource. For resources in the core API group, replace `<api_group>` with an empty string so the field reads `apiGroups: [""]`.
`<resource>`:: Specifies the resource to grant access to, using the plural resource name.
`<verb>`:: Specifies an operation approved for the resource.

. Create an `OperatorGroup` object in the designated namespace by running the following command. Use RBAC permissions granted to the service account specified in `spec.serviceAccountName` to limit the installation permissions available to OLM. The `spec.targetNamespaces` field selects the namespaces that the Operator watches and does not impose a permission boundary. OLM creates `APIService` and `CustomResourceDefinition` resources with `cluster-admin` privileges.
+
.Example command that creates an `OperatorGroup` object
[source,terminal]
----
$ cat <<EOF | oc create -f -
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: scoped
  namespace: scoped
spec:
  serviceAccountName: scoped
  targetNamespaces:
  - scoped
EOF
----
+
Specify the service account created in the previous step. Any Operator installed in the designated namespace is tied to this Operator group and therefore to the service account specified.

. Create a `Subscription` object in the designated namespace to install an Operator:
+
.Example command that creates a `Subscription` object
[source,terminal]
----
$ cat <<EOF | oc create -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: <subscription_name>
  namespace: scoped
spec:
  channel: <channel_name>
  name: <operator_package_name>
  source: <catalog_source_name>
  sourceNamespace: <catalog_source_namespace>
EOF
----
where:

`<subscription_name>`:: Specifies the name of the subscription.
`<channel_name>`:: Specifies an update channel available for the Operator package in the selected catalog source.
`<operator_package_name>`:: Specifies the Operator package to install from the selected catalog source.
`<catalog_source_name>`:: Specifies a catalog source that already exists in the designated namespace or one that is in the global catalog namespace, for example `redhat-operators`.
`<catalog_source_namespace>`:: Specifies a namespace where the catalog source was created, for example `openshift-marketplace` for the `redhat-operators` catalog.
+
If OLM cannot create a required resource with the permissions granted to the specified service account, the installation fails.
