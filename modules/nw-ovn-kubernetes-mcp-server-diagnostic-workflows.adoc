= Example diagnostic workflows for OVN-Kubernetes MCP toolsets

[role="_abstract"]
You can combine `ovn-kubernetes` and `cni-diagnostics` tools in MCP client prompts to investigate common OVN-Kubernetes connectivity problems across logical and kernel layers.

Ask your MCP client in natural language to run these workflows. Replace placeholders such as pod names, MAC addresses, and IP addresses with values from your cluster. Keep the `core` toolset enabled so that the client can discover `ovnkube-node` pods.

.Inspect logical network topology
====
* Use `pods_list` with `app=ovnkube-node` to find an `ovnkube-node` pod.
* Use `ovn_show` with `database=nbdb` for the Northbound topology overview.
* Use `ovn_get` with `table=Logical_Switch` and `table=Logical_Router` to list logical switches and routers.
====

.Debug pod-to-pod connectivity with OVN
====
* Use `ovn_show` with `database=sbdb` to review chassis and port bindings.
* Use `ovn_get` with `table=Port_Binding` and a pattern that matches the source pod to locate the logical port.
* Use `ovn_trace` with the logical switch data path and a microflow that includes the inport, Ethernet source, and IPv4 source and destination addresses.
* Use `ovn_lflow_list` for the same data path to inspect related logical flows.
====

.Verify network policy translation to OVN ACLs
====
* Use `ovn_get` with `table=ACL` to list Northbound ACLs.
* Filter with a pattern such as `action=drop` to focus on deny rules.
* Use `ovn_get` with `table=Port_Group` to review port groups that network policies create.
====

.Verify OVS configuration on a node
====
* Locate the `ovnkube-node` pod for the node.
* Use `ovs_vsctl` with `action=show` for an OVS overview.
* Use `ovs_vsctl` with `action=list-ports` and `bridge=br-int` to list ports on the integration bridge.
====

.Trace packet forwarding toward a Service
====
* Use `ovs_appctl` with `action=ofproto/trace`, `bridge=br-int`, and a flow that includes the pod source IP and Service cluster IP.
* Use `ovs_ofctl` with `action=dump-flows` and `bridge=br-int` to inspect matching OpenFlow entries.
====

.Diagnose pod egress with CNI diagnostics
====
* Use `get-ip` on the worker node to review routes toward the destination.
* Use `get-conntrack` with filters for the pod IP and destination IP.
* Use `get-nft` with `list ruleset` to review host packet filtering.
* Use `tcpdump` with `target_type=node` and a BPF filter that matches the pod and destination hosts.
====

.Diagnose inter-pod drops with kernel tracing
====
* Use `get-ip` and `get-conntrack` on the source node for routes and connection state.
* Use `pwru` with a BPF filter that matches both pod IPs to trace the kernel path.
* Use `get-nft` if the trace stops at a filter hook.
====

[NOTE]
====
If tools return Forbidden errors, confirm that the MCP server service account has permission to list and exec into `ovnkube-node` pods and to create privileged debug pods. If OVN tools report a missing container, confirm that you selected an `ovnkube-node` pod. If OVS tools report a missing bridge, use `ovs_vsctl` with `action=list-br` to list bridges on that node.
====
