== Fixed issues

Argo Rollouts controller outputs clean semantic version information::
Before this update, running `rollouts-controller --version` could output malformed version tags. With this update, the Argo Rollouts controller correctly outputs clean semantic version information. As a result, version queries return properly formatted semantic versions.
+
link:https://redhat.atlassian.net/browse/GITOPS-10775[GITOPS-10775]

Image Updater writes only resolved image values to Helm targets::
Before this update, the Image Updater could rewrite unresolved images when tracking multiple images in one application and writing back to a Helm values file. Any image the updater could not resolve during a reconcile cycle was rewritten from the image running in the cluster. This occurred when a registry error, no tag matching the constraint, or a failed signature check prevented resolution. As a consequence, a commit triggered by a different image could add a registry prefix to a repository stored in short form. The commit could also drop the tag from a `manifestTargets.helm.spec` key or revert a tag that was already committed but not yet rolled out. These edits persisted because subsequent cycles treated the rewritten value as the file's original state.
+
With this update, the updater writes only values it resolved during the current cycle. The updater falls back to the running image only to create keys the target file does not have yet. Entries for unresolved images are left unchanged. As a result, Helm values files remain stable across reconcile cycles.
+
link:https://redhat.atlassian.net/browse/GITOPS-11708[GITOPS-11708]

Partially configured Helm targets write only specified parameters::
Before this update, setting only `manifestTargets.helm.tag` caused the image name parameter to default to `image.name`. Setting only `manifestTargets.helm.name` defaulted the tag to `image.tag`. As a consequence, every image configured this way pointed at the same default path. The images overwrote each other and none of the intended names were written. A single stray `image.name` key belonging to whichever image was processed last was left behind in the Helm values file. This key also appeared in the `.argocd-source-<app>.yaml` override file and in the Application spec for the `argocd` write-back method.
+
With this update, the defaults apply only when `manifestTargets.helm` is omitted entirely. A partially configured image writes only the parameter it specifies. As a result, multiple images can coexist without conflicts in the Helm values file.
+
link:https://redhat.atlassian.net/browse/GITOPS-11922[GITOPS-11922]
