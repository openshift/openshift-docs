= Private cluster requirement on Google Cloud Dedicated

[role="_abstract"]
All clusters installed on Google Cloud Dedicated must be private clusters.
Unlike standard {gcp-short} where private clusters are an optional configuration, the physically isolated Google Cloud Dedicated infrastructure does not support public-facing endpoints.

On standard {gcp-short}, you can choose to install either a public or private cluster.
On Google Cloud Dedicated, the isolated infrastructure enforces this constraint at the infrastructure level.
Google Cloud Dedicated does not support public DNS zones or the global load balancer types that {product-title} uses for public-facing endpoints.
The `compute.disableGlobalLoadBalancing` organization policy is in effect on Google Cloud Dedicated, which prevents creation of global load balancers.

This constraint has the following implications for your cluster:

* Set `publish: Internal` in your `install-config.yaml` file. The installation program does not reject `publish: External` for sovereign projects, but the installation fails during infrastructure provisioning because public DNS zones and global load balancers are not available.
* The cluster API server and application Ingress endpoints are accessible only through internal network paths.
* You must configure VPN or Cloud Interconnect connectivity to access the cluster API and applications running on the cluster.
* Only regional internal load balancers are available for cluster services. Global load balancers are not supported.

[NOTE]
====
On standard {gcp-short}, private clusters are an optional configuration.
For more information about how private clusters work on standard {gcp-short}, see xref:../../installing/installing_gcp/installing-gcp-private.adoc#installing-gcp-private[Installing a private cluster on {gcp-short}].
