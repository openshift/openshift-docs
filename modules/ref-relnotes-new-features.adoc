= New features and enhancements

[role="_abstract"]
You can use the new features and enhancements that are available with {product-title} {version}.

Disconnected installation is now Generally Available::
Installing {prodname} in a disconnected environment is now Generally Available. You can apply cloud-like traffic management within your private, secure network. For more information, see xref:../install_rhcl/rhcl-install-disconnected.adoc#con-rhcl-install-disconnected_rhcl-install-disconnected[Install {prodname} in a disconnected environment].

Support for `GRPCRoute` policy attachment is Generally Available::
With this Connectivity Link release, `GRPCRoute` policy attachment support is a Generally Available feature. You can attach `AuthPolicy` and `RateLimitPolicy` custom resources (CRs) to `GRPCRoute` CRs, enabling authentication and rate-limiting controls for gRPC services with native service and method matching. For more information, see xref:../administer/connect-apis-services.adoc#con-about-grpc-support_connect-secure-apis-services[GRPCRoute policy attachment support].

Support for {ibm-power} and {ibm-390} is Generally Available::
With this release, you can install and run {prodname} on {ocp} clusters that use the {ibm-power} and {ibm-390}, architecture. For more information, see xref:../plan/plan-rhcl-install.adoc#rhcl-supported-configs_plan-rhcl-install[Supported configurations].

{rhdh} plugin is Generally Available::
The {rhdh} plugin for {prodname} is Generally Available. With a {rhdh} subscription, you can create a self-service API catalog that makes API consumption easier and enables teams to work together more effectively. For more information, see xref:../develop/rhdh-plugin-installation.adoc#rhdh-plugin-on-ocp_rhdh-plugin-installation[Manage APIs through Red Hat Developer Hub].

Token-based rate limiting enhancements::
`TokenRateLimitPolicy` now supports token usage extraction from OpenAI, Google Gemini, and AWS Bedrock response formats. You can configure JSON Pointers for other formats and reserve token capacity for requests in progress to help prevent concurrent requests from exceeding a limit. For more information, see xref:../configure/deployment.adoc#con-about-token-based-rate-limiting_rhcl-config-deploy-gateway-policies[Token-based rate limiting with TokenRateLimitPolicy].

*{mcpg}*: {mcpg} is now Generally Available::
The {mcpg} is now Generally Available. Gather your Model Context Protocol (MCP) servers behind a single endpoint. Grow your agentic AI applications at scale without building in connectivity. Manage access to and the security of AI tools and MCP servers. For more information, see xref:../mcp_gateway_discover/mcp-gateway-introduction.adoc#con-about-mcp-gateway_mcp-gateway-introduction[Introduction to the {mcpg}].

*{mcpg}*: {mcpg} adds new protocol support::
With this release, the {mcpg} adds support for the `2026-07-28` stateless Model Context Protocol (MCP) protocol version. This enhancement means that MCP servers can operate like standard HTTP services in cloud-native environments. Every request is now self-describing and independent, meaning that you can scale your MCP servers while reducing costs. For more information, see xref:../mcp_gateway_config/mcp-gateway-multi-protocol-support.adoc#con-mcp-gateway-multi-protocol-support_mcp-gateway-multi-protocol-support[Multi-protocol support for the {mcpg}].

*{mcpg}*: Audit trail documentation is updated::
The {mcpg} documentation is updated with simplified configuration instructions for creating an audit trail. Use audit trails for compliance and accountability. Capture caller identity, tool names, and system status. For more information, see xref:../observe/mcp-gateway-audit-trail-router-log.adoc#con-mcp-gateway-router-audit-log_mcp-gateway-audit-trail-router-log[Audit MCP tool calls].

*{mcpg}*: NeMo Guardrails support::
With this release, you can inspect tool call traffic in the {mcpg} with NeMo Guardrails. Configured guardrails can block unsafe tool calls and mask sensitive information. When guardrails are enabled, every tools call request is routed through the gateway and is checked against the guardrails path. For more information, see xref:../secure/mcp-gateway-guardrails.adoc#con-mcp-gateway-understand-guardrails_mcp-gateway-guardrails[Enable guardrails on the {mcpg}].
