= Use an audit trail without authentication

[role="_abstract"]
Without authentication, routing metadata can help you investigate requests, but user-related fields do not identify a verified caller.

Without a token-validating `AuthPolicy` that sets `x-auth-identity`, do not trust the Envoy `mcp_user_id` field. It is empty if the header is absent, but a supplied header is not proof of identity. Router audit logs similarly decode the JWT subject without validating the token. Depending on the request processing stage, access logs can show the following details:

* Which tool was requested
* Which server was selected
* At what time the call took place
* How long the interaction lasted

Use `request_id` and `traceparent` for request correlation and the router audit `session` field for a log-safe session identifier. Do not add the raw `Mcp-Session-Id` header to Envoy access logs.

When you enable authentication, protect both broker and back-end route sets, such as the `mcp` and `mcps` listeners. Add an `x-auth-identity` success-response header to the existing `AuthPolicy` CR for each route set. Choose a claim from your identity provider:

* {keycloak}: `auth.identity.preferred_username` or `auth.identity.email`.
* Generic OIDC: `auth.identity.sub`, the subject claim.
* Custom claims: `auth.identity._<claim_name>_` for a claim supplied by your identity provider.

[IMPORTANT]
====
If you change the header name, also update the `mcp_user_id` field in your `MeshConfig` extension provider to match the `%REQ(_<header_name>_)%` format.
====

Add the following fragment under `spec.defaults.rules` or `spec.rules`, matching the structure of each existing policy. Preserve token validation, authorization rules, and other response settings.

.Generic OIDC identity header fragment
[source,yaml,subs="+quotes"]
----
response:
  success:
    headers:
      "x-auth-identity":
        plain:
          selector: auth.identity.sub
----
