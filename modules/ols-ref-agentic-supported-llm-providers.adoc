= Supported LLM providers for Agentic {ols-long}

[role="_abstract"]
Agentic {ols-long} supports several large language model (LLM) provider backends. You select a backend by setting the `spec.type` field on the `LLMProvider` custom resource (CR). Each provider type requires a matching per-provider configuration block and a credentials secret that contains specific keys.

The {ols-long} Service does not provide the LLM for you, so you must configure access to an LLM provider before you deploy Agentic {ols-long}.

.Supported Agentic {ols-long} LLM providers
[cols="1,1,2", options="header"]
|===
| Provider | `spec.type` value | Required credentials secret keys

| Anthropic
| `Anthropic`
| `ANTHROPIC_API_KEY`. For Anthropic-compatible endpoints that use bearer token authentication, such as vLLM, also set `ANTHROPIC_AUTH_TOKEN`.

| OpenAI
| `OpenAI`
| `OPENAI_API_KEY`.

| Google Cloud Vertex AI
| `GoogleCloudVertex`
| `GOOGLE_APPLICATION_CREDENTIALS`, which contains a Google Cloud service account JSON key.

| {aws-first} Bedrock
| `AWSBedrock`
| `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.

| {azure-openai}
| `AzureOpenAI`
| `AZURE_OPENAI_API_KEY`.
|===

For vLLM or {rhelai} deployments, use the `Anthropic` provider type with the Anthropic-compatible `/v1/messages` endpoint for agentic and tool-calling workloads. For more information, see "Connect a vLLM server through the Anthropic provider" and "Choose an LLM provider pathway for Agentic {ols-long}".

[NOTE]
====
The credentials secret must exist in the `openshift-lightspeed` operator namespace, and the `LLMProvider` CR references it by name.
====
