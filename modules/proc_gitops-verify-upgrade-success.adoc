= Verify upgrade success

[role="_abstract"]
Verify that the {gitops-title} upgrade completed successfully by checking component versions, pod status, application health, and operational functionality.

.Prerequisites

* You have upgraded the {gitops-title} Operator.
* You have `cluster-admin` or sufficient permissions to view resources in the `openshift-gitops` namespace.

.Procedure

. Verify the Operator version:
+
[source,terminal]
----
$ oc get csv -n openshift-gitops-operator
----
+
*Example output:*
[source,terminal]
----
NAME                      DISPLAY                    VERSION   REPLACES                  PHASE
openshift-gitops.v1.21.0  Red Hat OpenShift GitOps   1.21.0    openshift-gitops.v1.20.0  Succeeded
----
+
Confirm the `PHASE` is `Succeeded` and the `VERSION` matches your target version.

. Check all Argo CD pods are running:
+
[source,terminal]
----
$ oc get pods -n openshift-gitops
----
+
*Example output:*
[source,terminal]
----
NAME                                                READY   STATUS    RESTARTS   AGE
openshift-gitops-application-controller-0           1/1     Running   0          5m
openshift-gitops-applicationset-controller-...      1/1     Running   0          5m
openshift-gitops-dex-server-...                     1/1     Running   0          5m
openshift-gitops-redis-...                          1/1     Running   0          5m
openshift-gitops-repo-server-...                    1/1     Running   0          5m
openshift-gitops-server-...                         1/1     Running   0          5m
----
+
All pods should show `READY 1/1` and `STATUS Running`.

. Verify the Argo CD version:
+
[source,terminal]
----
$ argocd version --server <server_url> --insecure
----
+
Or check through the web console:
+
.. Log in to the Argo CD web console.
.. Click *User Info* in the top right.
.. Verify the Argo CD version matches the expected version.

. Check application status:
+
[source,terminal]
----
$ argocd app list
----
+
Verify all applications show expected sync and health status.

. Test application synchronization:
+
[source,terminal]
----
$ argocd app get <application_name> --refresh
$ argocd app sync <application_name>
----
+
Confirm the sync operation completes successfully.

. Verify repository connections:
+
[source,terminal]
----
$ argocd repo list
----
+
All repositories should show `SUCCESSFUL` connection status.

. Check cluster connections (for multi-cluster setups):
+
[source,terminal]
----
$ argocd cluster list
----
+
All clusters should show `Successful` connection status.

. Review component logs for errors:
+
[source,terminal]
----
$ oc logs deployment/openshift-gitops-server -n openshift-gitops --tail=50
$ oc logs statefulset/openshift-gitops-application-controller -n openshift-gitops --tail=50
$ oc logs deployment/openshift-gitops-repo-server -n openshift-gitops --tail=50
----
+
Look for any error or warning messages related to the upgrade.

. Verify custom configurations persisted:
+
.. Check RBAC policies:
+
[source,terminal]
----
$ oc get cm argocd-rbac-cm -n openshift-gitops -o yaml
----
+
.. Check SSO configuration:
+
[source,terminal]
----
$ oc get cm argocd-cm -n openshift-gitops -o yaml | grep -A10 dex.config
----
+
.. Verify custom resource requests and limits:
+
[source,terminal]
----
$ oc get argocd openshift-gitops -n openshift-gitops -o yaml | grep -A10 resources
----

. Test critical application workflows:
+
* Deploy a test application
* Modify a manifest in Git and verify automatic sync (if enabled)
* Test manual sync and rollback operations
* Verify webhooks trigger synchronizations correctly

. Check monitoring and metrics:
+
[source,terminal]
----
$ oc get servicemonitor -n openshift-gitops
$ curl -k https://$(oc get route openshift-gitops-server -n openshift-gitops -o jsonpath='{.status.ingress[0].host}')/metrics
----
+
Verify metrics endpoints are accessible.

. Review Prometheus alerts for Argo CD:
+
[source,terminal]
----
$ oc get prometheusrule -n openshift-gitops
----
+
Check for any firing alerts related to Argo CD components.

.Verification

The upgrade is successful if:

* Operator CSV shows `Succeeded` phase
* All pods are in `Running` state with `READY 1/1`
* Component versions match the expected release
* Applications sync successfully
* No critical errors appear in logs
* Custom configurations are preserved
* Repository and cluster connections are healthy

[NOTE]
====
Monitor applications and Argo CD components for 24-48 hours after upgrade to identify any delayed issues or performance degradation.
====

[TIP]
====
If verification fails, review the troubleshooting section or check the {gitops-title} release notes for known issues with your target version.
====
