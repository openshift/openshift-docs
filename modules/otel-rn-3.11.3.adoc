The {otel} 3.11.3 release resolves these Common Vulnerabilities and Exposures (CVEs):

Apache Thrift Go services are no longer vulnerable to DoS via empty network frames::
Before this update, Apache Thrift Go services were vulnerable to a denial of service (DoS) attack when processing specially crafted network frames with zero payload bytes. When the transport received these empty frames, it recursively called its read function rather than iterating in a loop, which exhausted the execution stack. As a consequence, this stack exhaustion caused an unrecoverable error that terminated the entire process. With this update, Apache Thrift handles empty frame payloads correctly. As a result, Go services are no longer vulnerable to DoS attacks via specially crafted network frames.
+
link:https://access.redhat.com/security/cve/cve-2026-83663/[CVE-2026-83663]
+
link:https://redhat.atlassian.net/browse/TRACING-6873[TRACING-6873]

Apache Thrift Go library is no longer vulnerable to DoS via malformed compressed data::
Before this update, the Apache Thrift Go library incorrectly handled decompression when a remote attacker sent specially crafted, highly compressed data to an affected service. As a consequence, the data amplification exhausted system resources and caused the service to become unavailable. With this update, Apache Thrift correctly handles decompression of compressed data. As a result, the Go library is no longer vulnerable to denial of service (DoS) attacks via malformed compressed frames.
+
link:https://access.redhat.com/security/cve/cve-2026-94637/[CVE-2026-94637]
+
link:https://redhat.atlassian.net/browse/TRACING-6879[TRACING-6879]
