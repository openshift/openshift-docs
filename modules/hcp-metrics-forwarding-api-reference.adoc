= Per-cluster metrics forwarding API reference

[role="_abstract"]
The `spec.monitoring` field on `HostedCluster` and `HostedControlPlane` (v1beta1) provides a
structured, admission-validated API for configuring control plane metrics forwarding per hosted cluster.
Use this reference to understand the fields, allowed values, and their relationships.

== MonitoringSpec

The `MonitoringSpec` type is set in `spec.monitoring` on a `HostedCluster` or `HostedControlPlane` object.
Cluster administrators interact directly with the `HostedCluster` object;
the `HostedControlPlane` object is managed by the HyperShift Operator and is not a surface that operators interact with directly.
The HyperShift Operator propagates `spec.monitoring` settings from the `HostedCluster` to the corresponding `HostedControlPlane`.

[cols="2,2,3", options="header"]
|===
|Field |Type |Description

|`metricsForwarding`
|`MetricsForwardingSpec`
|Configures forwarding of control plane metrics into the hosted cluster's monitoring stack.
When omitted, metrics forwarding behavior is determined by the
`hypershift.openshift.io/enable-metrics-forwarding` annotation for backward compatibility.
If neither is set, metrics forwarding is disabled.

|`metricsSet`
|`MetricsSet`
|Cluster-level default for which metrics set to collect and forward.
Overrides the global `METRICS_SET` environment variable on the HyperShift Operator deployment.
When not specified, the global `METRICS_SET` value is used, which defaults to `Telemetry`.
|===

[NOTE]
====
At least one field must be set when `spec.monitoring` is present.
Setting `spec.monitoring: {}` with no sub-fields is rejected by the API server.
====

== MetricsForwardingSpec

The `MetricsForwardingSpec` type is set in `spec.monitoring.metricsForwarding` on a `HostedCluster` object.

[cols="2,2,1,3", options="header"]
|===
|Field |Type |Required |Description

|`mode`
|`MetricsForwardingMode`
|Yes
|Controls whether metrics forwarding is active for this hosted cluster.

|`metricsSet`
|`MetricsSet`
|No
|Forwarding-path override for which metrics set to forward.
Takes precedence over `spec.monitoring.metricsSet` and the global `METRICS_SET` operator environment variable.
When not specified, the value from `spec.monitoring.metricsSet` is used.
|===

== MetricsForwardingMode enum

The `mode` field in `MetricsForwardingSpec` accepts the following values:

[cols="1,3", options="header"]
|===
|Value |Description

|`Forward`
|Metrics forwarding is active.
The HyperShift Operator deploys `metrics-proxy` and `endpoint-resolver` in the hosted control plane namespace
and a `control-plane-metrics-forwarder` in the hosted cluster's `openshift-monitoring` namespace.

|`None`
|Metrics forwarding is inactive.
No forwarding components are deployed.
This is the effective default when no `spec.monitoring` field is set.
|===

== MetricsSet enum

The `MetricsSet` type is used in both `spec.monitoring.metricsSet` and `spec.monitoring.metricsForwarding.metricsSet`.

[cols="1,3", options="header"]
|===
|Value |Description

|`Telemetry`
|Collects only the minimal set of metrics required for OpenShift Telemetry.
This is the default when no metrics set is configured anywhere in the precedence chain.

|`SRE`
|Collects the Telemetry set plus additional metrics defined in the `sre-metric-set` `ConfigMap`.
Required for SRE monitoring dashboards and alerts.

|`All`
|Collects all metrics from control plane components without filtering.
Produces significantly higher metrics volume than `Telemetry` or `SRE`.
|===

== Metrics set precedence

When determining which metrics set to use for the forwarding path,
the following precedence applies, from highest to lowest:

[cols="1,3", options="header"]
|===
|Precedence |Source

|1 (highest)
|`spec.monitoring.metricsForwarding.metricsSet` on the `HostedCluster` object

|2
|`spec.monitoring.metricsSet` on the `HostedCluster` object

|3 (lowest)
|`METRICS_SET` environment variable on the HyperShift Operator deployment (defaults to `Telemetry`)
|===
