= advancedOverrides for external-secrets components

[role="_abstract"]
The `advancedOverrides` field applies a strategic merge patch to the `Deployment` that the {external-secrets-operator} generates for each `external-secrets` component. Use this field only when first-class fields such as `deploymentConfigs` or `overrideEnv` are not sufficient.

[IMPORTANT]
====
Do not use the `advancedOverrides` field unless you understand the impact. Setting fields outside the `allowlist` causes validation to fail and puts the `ExternalSecretsConfig` custom resource (CR) into a `Degraded` condition.
====

The following components support the `advancedOverrides` field:

.Components that support the `advancedOverrides` field
[cols="1,1",options="header"]
|===
| Component name
| Description

| `ExternalSecretsCoreController`
| Main `external-secrets` controller

| `Webhook`
| `external-secrets` webhook server

| `CertController`
| Certificate controller for webhook Transport Layer Security (TLS) certificates

| `BitwardenSDKServer`
| Bitwarden SDK server plugin

|===

Each component can have only one configuration entry. You can add a maximum of four component configuration entries, one for each component.

You can use only the following `Deployment` field paths in the `advancedOverrides` field:

* `spec.template.spec.affinity`
* `spec.template.spec.tolerations`
* `spec.template.spec.nodeSelector`
* `spec.template.spec.topologySpreadConstraints`
* `spec.template.spec.containers[*].args`
* `spec.template.spec.containers[*].resources`

If an allowed field overlaps a first-class setting in the `ExternalSecretsConfig` CR, the value in the `advancedOverrides` field takes precedence. For example, the `affinity`, `nodeSelector`, and `tolerations` fields in `spec.appConfig` can overlap.

Use first-class fields instead of the `advancedOverrides` field for the following values:

* `deploymentConfigs.replicas`
* `deploymentConfigs.revisionHistoryLimit`
* `overrideEnv`

The {external-secrets-operator} merges container `args` overrides with the managed arguments by flag name. You need to specify only the flags that you want to change or add. The other default flags remain. For the `ExternalSecretsCoreController` and `CertController` components, `--enable-leader-election=true` remains unless you explicitly override that flag.
