= Schedule and resource overrides for external-secrets components

[role="_abstract"]
Control where `external-secrets` pods run, which arguments the containers start with, and how many resources the containers use. Set the `advancedOverrides` field in the {external-secrets-operator-short} only when dedicated fields such as `deploymentConfigs` or `overrideEnv` do not meet your need.

[IMPORTANT]
====
Do not set the `advancedOverrides` field unless you must. A field outside the allowed paths fails validation and sets the `ExternalSecretsConfig` custom resource (CR) to the `Degraded` condition.
====

The following components support the `advancedOverrides` field:

.Components that support the `advancedOverrides` field
[cols="1,1",options="header"]
|===
| Component name
| Description

| `ExternalSecretsCoreController`
| Main `external-secrets` controller

| `Webhook`
| `external-secrets` webhook server

| `CertController`
| Certificate controller for webhook Transport Layer Security (TLS) certificates

| `BitwardenSDKServer`
| Bitwarden SDK server plugin

|===

You can add one configuration entry for each component, for a maximum of four entries.

You can use only the following `Deployment` field paths in the `advancedOverrides` field:

`spec.template.spec.affinity`:: Controls the rules that place the pods on specific nodes, or keep the pods on different nodes from other pods.

`spec.template.spec.tolerations`:: Controls whether the pods can run on nodes that have matching taints.

`spec.template.spec.nodeSelector`:: Controls which nodes the pods can run on, based on node labels.

`spec.template.spec.topologySpreadConstraints`:: Controls how the pods spread across zones or nodes.

`spec.template.spec.containers[*].args`:: Controls the command-line flags that the containers start with.

`spec.template.spec.containers[*].resources`:: Controls the CPU and memory requests and limits for the containers.

If you set the same field in `advancedOverrides` and in a dedicated field such as `spec.appConfig.affinity`, the `advancedOverrides` value applies.

Set the following values in their dedicated fields, not in the `advancedOverrides` field:

* `deploymentConfigs.replicas`
* `deploymentConfigs.revisionHistoryLimit`
* `overrideEnv`

The {external-secrets-operator-short} merges container `args` overrides with the managed arguments by flag name. Specify only the flags that you want to change or add. The {external-secrets-operator-short} keeps the other default flags. For the `ExternalSecretsCoreController` and `CertController` components, `--enable-leader-election=true` stays unless you override that flag.
