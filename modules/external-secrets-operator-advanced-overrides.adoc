= Advanced overrides for external-secrets component deployments

[role="_abstract"]
You can customize pod placement, container arguments, and resource settings for {external-secrets-operator-short} components. Advanced overrides let you change deployment settings when dedicated configuration fields do not provide the options you need.

[WARNING]
====
Do not set the `advancedOverrides` field unless necessary. A field outside the allowed paths fails validation and sets the `ExternalSecretsConfig` custom resource (CR) to the `Degraded` condition.
====

The following components support the `advancedOverrides` field:

.Components that support the `advancedOverrides` field
[cols="1,1",options="header"]
|===
| Component name
| Description

| `ExternalSecretsCoreController`
| Main `external-secrets` controller

| `Webhook`
| `external-secrets` webhook server

| `CertController`
| Certificate controller for the webhook Transport Layer Security certificates

| `BitwardenSDKServer`
| Bitwarden SDK server plugin

|===

You can add one configuration entry per component, up to four entries.

Set the `advancedOverrides` field in the relevant entry of the `spec.controllerConfig.componentConfigs` list in the `ExternalSecretsConfig` CR.

You can use only the following `Deployment` field paths in the `advancedOverrides` field:

`spec.template.spec.affinity`:: Specifies the rules that place the pods on specific nodes or keep them apart from other pods.

`spec.template.spec.tolerations`:: Specifies the taints that the pods can tolerate when scheduled on nodes.

`spec.template.spec.nodeSelector`:: Specifies the node labels that a node must have for the pods to run on it.

`spec.template.spec.topologySpreadConstraints`:: Specifies how the pods spread across zones or nodes.

`spec.template.spec.containers[*].args`:: Specifies the command-line flags that the containers use at startup.

`spec.template.spec.containers[*].resources`:: Specifies the CPU and memory requests and limits for the containers.

If you configure the same deployment setting through both the `advancedOverrides` field and a dedicated field, such as `spec.appConfig.affinity`, the `advancedOverrides` value applies.

Set the following fields in the relevant `componentConfigs` entry, not in its `advancedOverrides` field:

* `deploymentConfigs.replicas`
* `deploymentConfigs.revisionHistoryLimit`
* `overrideEnv`

The {external-secrets-operator-short} merges overrides from the `args` field with the managed arguments by flag name. The {external-secrets-operator-short} keeps the other default flags. Specify only the flags that you want to change or add. For the `ExternalSecretsCoreController` and `CertController` components, `--enable-leader-election=true` remains enabled unless you override it.
