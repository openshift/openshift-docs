= Topology

[role="_abstract"]

The topology views combine live traffic, health, and {istio} configuration so you can see how applications, services, and workloads communicate on {ocp-product-title}.

.Kiali overview of mesh health
image::ossm-kiali-overview.png[Kiali overview page showing mesh health]

== Overview

The landing page summarizes clusters, control planes, data planes, and configuration. It groups applications by health and lists services with the highest error rates and the highest tail latency.

== Namespaces

From Kiali 2.23, the Namespaces page filters and sorts the namespaces you can access. You can run namespace actions there or open a more detailed view.

== Graph

.Bookinfo traffic in the Kiali graph
image::ossm-kiali-graph-bookinfo.png[Kiali graph of the bookinfo application]

The graph draws real-time request traffic on top of {istio} configuration. Node shape is the object type: application, service, or workload. Node and edge color is health. Badges call out virtual services, service entries, fault injection, circuit breakers, and mutual TLS problems.

The graph has four layouts:

* The workload graph shows traffic between workloads.
* The app graph groups workloads that share an application label.
* The versioned app graph groups by application and still shows each version.
* The service graph aggregates traffic for each service.

=== Health

Orange nodes and edges are degraded traffic. Red nodes and edges are failing traffic. The edge color is the health of the requests between the two ends. The shape of a node is its type, not its health. The graph refreshes on the interval you set. You can pause it or replay an earlier interval.

=== Side panel

Select a node, edge, or box to open the side panel. The panel shows traffic and response-time charts, health, response codes, hosts, and traces for the selection. It also links to the full detail page.

=== Node detail

Double-click a node to open the detail graph for traffic reported by that node's {istio} proxy. Double-click another node to switch the detail graph, or return to the main graph.

=== Traffic animation

For HTTP, the animation uses circles for successful requests and red diamonds for errors. Denser shapes mean a higher request rate, and faster motion means a shorter response time. TCP traffic uses offset circles whose speed follows the throughput.

=== Ranking

You can rank nodes by a criterion such as the number of inbound edges. Rank 1 is the highest. Combined with find and hide, ranking highlights the workloads, services, and applications that matter most.

=== Replay

You can pause the graph or replay a past time range. The graph URL includes the replay window, so you can share a view.

=== Operation nodes

When {istio} request classification is configured, enable *Operation nodes* to show those aggregates as pentagons. Operation nodes are not drawn on the service graph, because that graph is already an aggregate. Response time is not shown on edges into or out of an operation node. Select the edge to read response time in the side panel.
