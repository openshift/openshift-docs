= Start a migration to the target vCenter

[role="_abstract"]
To migrate with the {vcf-migration-operator}, create a secret for the target vCenter and a `VmwareCloudFoundationMigration` custom resource (CR). Set the CR to `Running` when you are ready to start the migration.

.Prerequisites

* You have installed the {vcf-migration-operator} and prepared the cluster for migration.
* You have installed the {oc-first} and logged in with `cluster-admin` privileges.
* You have the target vCenter credentials and inventory details.

.Procedure

. Create a `target-vcenter-creds.yaml` file with the following content. Replace `vcenter-target.example.com` in both keys with the target vCenter FQDN:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: target-vcenter-creds
  namespace: openshift-vcf-migration
type: Opaque
stringData:
  vcenter-target.example.com.username: "<vcenter_username>"
  vcenter-target.example.com.password: "<vcenter_password>"
----
+
where:
+
`<vcenter_username>`:: The username for the target vCenter account with the required privileges.
`<vcenter_password>`:: The password for that account. Enter both credentials as single-line strings without trailing newline characters.

. Create the secret by running the following command:
+
[source,terminal]
----
$ oc create -f target-vcenter-creds.yaml
----

. Create a `migration.yaml` file with the following content. Replace the example failure domain values and inventory paths with values from your target vCenter. Keep the CR name as `cluster` and its state as `Pending` while you review the configuration. Preflight checks run after you change the state to `Running`:
+
[source,yaml]
----
apiVersion: migration.openshift.io/v1alpha1
kind: VmwareCloudFoundationMigration
metadata:
  name: cluster
  namespace: openshift-vcf-migration
spec:
  state: Pending
  targetVCenterCredentialsSecret:
    name: target-vcenter-creds
    namespace: openshift-vcf-migration
  failureDomains:
  - name: target-fd
    region: target-region
    zone: target-zone
    server: vcenter-target.example.com
    topology:
      datacenter: TargetDC
      computeCluster: /TargetDC/host/TargetCluster
      datastore: /TargetDC/datastore/TargetDatastore
      networks:
      - "VM Network"
      template: /TargetDC/vm/rhcos-template
----
+
where:
+
`failureDomains[].name`:: A unique name for the target failure domain. Add an entry for each target failure domain.
`failureDomains[].region` and `failureDomains[].zone`:: The topology tag values for the target data center and compute cluster. If those objects already have tags in the `openshift-region` and `openshift-zone` categories, use the existing tag values.
`failureDomains[].server`:: The target vCenter FQDN. This value must match the FQDN in the credentials secret keys.
`failureDomains[].topology`:: Inventory names and paths from the {vmw-short} Client. This example uses the compute cluster's default resource pool and a VM folder created by the Operator.
`failureDomains[].topology.networks`:: The target network name, such as `VM Network`.
`failureDomains[].topology.template`:: The inventory path of the existing {op-system} template on the target vCenter.

. Create the migration CR by running the following command:
+
[source,terminal]
----
$ oc create -f migration.yaml
----

. Start the migration by running the following command:
+
[source,terminal]
----
$ oc patch vcfm cluster -n openshift-vcf-migration --type=merge -p '{"spec":{"state":"Running"}}'
----

.Verification

* Check the migration status by running the following command:
+
[source,terminal]
----
$ oc describe vcfm cluster -n openshift-vcf-migration
----
+
The `InfrastructurePrepared` condition reports preflight progress or the requirement that blocks migration. After preflight succeeds, the Operator continues with destination setup and machine replacement.
