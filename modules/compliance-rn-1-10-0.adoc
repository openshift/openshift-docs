= Release notes for OpenShift Compliance Operator 1.10.0

[role="_abstract"]
OpenShift Compliance Operator 1.10.0 is now available. The `stable` update channel tracks and receives updates for the Compliance Operator. For more information, see xref:../../security/compliance_operator/co-management/compliance-operator-updating.adoc#compliance-operator-updating[Updating the Compliance Operator]. The following Red Hat Security Advisory (RHSA) is available:

* link:https://access.redhat.com/errata/RHSA-2026:TBD[RHSA-2026:TBD - OpenShift Compliance Operator 1.10.0 bug fix and enhancement update]

[id="compliance-operator-1-10-0-new-features-and-enhancements_{context}"]
== New features and enhancements

* With this release, CEL-based `CustomRule` and `Rule` objects are generally available. You can define custom platform checks with CEL expressions, enable them in `TailoredProfile` objects, and run scans that produce `ComplianceCheckResult` output. CEL does not replace existing Extensible Configuration Checklist Description Format (XCCDF) profiles but extends the ability to enforce custom security policies on {product-title} resources. For more information, see xref:../../security/compliance_operator/co-cel/compliance-operator-cel-overview.adoc#compliance-operator-cel-overview[Understanding Compliance Operator CEL profiles] and (link:https://redhat.atlassian.net/browse/CMP-4574[CMP-4574]).

* With this release, the Compliance Operator profile parser can ingest CEL content from a `ProfileBundle` object when `spec.celContentFile` references a bundled YAML file in the content image. The parser creates CEL `Rule` and `Profile` objects that you can bind directly to scans. For more information, see xref:../../security/compliance_operator/co-cel/compliance-operator-cel-overview.adoc#compliance-operator-cel-profilebundle_compliance-operator-cel-overview[CEL rules in ProfileBundles] and (link:https://redhat.atlassian.net/browse/CMP-4134[CMP-4134]).
