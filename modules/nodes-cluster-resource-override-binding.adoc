= Understanding ClusterResourceOverrideBinding

[role="_abstract"]
The `ClusterResourceOverrideBinding` custom resource allows you to assign different `ClusterResourceOverride` profiles to specific namespaces and pods. This enables multi-tenant clusters where different workloads can have different overcommit ratios based on their resource guarantees.

== Purpose of ClusterResourceOverrideBinding

In the default single-profile mode, all namespaces labeled with `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled: "true"` share the same overcommit ratios defined in the `cluster` profile. This is limiting for multi-tenant environments where:

* Production namespaces need conservative overcommit to maintain SLAs
* Development and batch namespaces can use aggressive overcommit to maximize density
* Different teams require different resource policies

The `ClusterResourceOverrideBinding` CRD separates the definition of override ratios (the profile) from where those ratios are applied (the binding). This allows cluster administrators to:

* Create multiple named `ClusterResourceOverride` profiles with different ratios
* Assign each profile to specific namespaces using label selectors
* Filter which pods receive the override using optional pod label selectors
* Avoid conflicts by using hierarchical label-matching rules

== Binding structure

A `ClusterResourceOverrideBinding` consists of:

`spec.overrideRef`:: The name of the `ClusterResourceOverride` profile to apply (required).
`spec.namespaceSelector`:: A label selector that matches the namespaces where this binding applies (required).
`spec.podSelector`:: An optional label selector that matches specific pods within those namespaces. When omitted, all pods in matching namespaces are mutated.

== Conflict resolution

If a namespace matches multiple bindings, the most specific binding wins (the binding that matches the smallest set of namespaces). If the specificity is equal, the alphabetically first binding name is applied. A warning event is logged when conflicts are detected.

== Backward compatibility

Namespaces labeled with `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled: "true"` implicitly use an internal default binding that applies the `cluster` profile. You can continue using this legacy approach, or migrate to explicit `ClusterResourceOverrideBinding` objects for more control.
