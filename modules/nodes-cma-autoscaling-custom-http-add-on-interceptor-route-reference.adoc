= About configuring an interceptor route custom resource

[role="_abstract"]
The `InterceptorRoute` custom resource defines how the HTTP Add-on intercepts and metrics-collects traffic for your application. It specifies routing rules, scaling metrics configuration, and the target application service.

The `InterceptorRoute` custom resource is part of the `http.keda.sh` API group and defines the traffic interception and metrics collection configuration for a single application or route.

[source,yaml]
----
apiVersion: http.keda.sh/v1alpha1
kind: InterceptorRoute
metadata:
  name: my-app-interceptor
  namespace: default
spec:
  hosts:
  - "my-app.example.com"
  targetService:
    name: my-app-service
    port: 8080
    protocol: https
  scalingMetrics:
    concurrency:
      threshold: 100
    rps:
      threshold: 1000
----
where:

`metadata.name`:: Specifies the name of the interceptor route resource. This name is referenced by ScaledObject triggers.
`metadata.namespace`:: Specifies the namespace where the interceptor route is created. Typically, the same namespace as your application deployment.
`spec.hosts`:: Specifies which hostnames or DNS names trigger this interceptor route, for example  `"my-app.example.com"` or `"api.internal.svc.cluster.local"`. Incoming HTTP requests matching these hostnames are intercepted and have metrics collected.
`spec.targetService.name`:: Specifies the service name where intercepted traffic should be forwarded after metrics collection. The service must exist in the same namespace as the interceptor route. 
`spec.targetService.port`:: Specifies the port number on the target service. Typically `8080` for HTTP or `443` for HTTPS applications.
`spec.targetService.protocol`:: Specifies the protocol to use when communicating with the target Service. Valid values are `http` or `https`.
`spec.targetService.scalingMetrics`:: Specifies which metrics the interceptor collects and provides to the scaler. This value is typically overridden by the ScaledObject trigger configuration. Specify either `rps` or `concurrency`
+
--
* `rps`. The `rps` metric measures incoming requests averaged over a measurement window. The baseline RPS value is used as the scaling reference. 
* `concurrency`. The `concurrency` metric measures in-flight HTTP requests. The baseline concurrency value is used as the scaling reference.
