= Modifying application creation

[role="_abstract"]
You can customize how `oc new-app` creates applications by setting names, labels, environment variables, target projects, and other options. Use these flags to control the objects the command generates before you deploy.

.`new-app` output objects
[cols="2,8",options="header"]
|===

|Object |Description

|`BuildConfig`
|A `BuildConfig` object is created for each source repository that is specified in the command line. The `BuildConfig` object specifies the strategy to use, the source location, and the build output location.

|`ImageStreams`
|For the `BuildConfig` object, two image streams are usually created. One represents the input image. With source builds, this is the builder image.
ifndef::openshift-online[]
With `Docker` builds, this is the *FROM* image.
endif::[]
The second one represents the output image. If a container image was specified as input to `new-app`, then an image stream is created for that image as well.

|`DeploymentConfig`
|A `DeploymentConfig` object is created either to deploy the output of a build, or a specified image. The `new-app` command creates `emptyDir` volumes for all Docker volumes that are specified in containers included in the resulting `DeploymentConfig` object .

|`Service`
|The `new-app` command attempts to detect exposed ports in input images. It uses the lowest numeric exposed port to generate a service that exposes that port. To expose a different port, after `new-app` has completed, use the `oc expose` command to generate additional services.

|Other
|Other objects can be generated when creating applications from templates, according to the template.

|===

.Procedure

. Pass environment variables to the application container at run time when you create an application from a template, source, or image:
+
.. Pass environment variables inline by running the following command:
+
[source,terminal]
----
$ oc new-app openshift/postgresql-92-centos7 \
    -e POSTGRESQL_USER=user \
    -e POSTGRESQL_DATABASE=db \
    -e POSTGRESQL_PASSWORD=password
----
+
.. Store environment variables in a file by creating a file such as `postgresql.env` with the following content:
+
[source,terminal]
----
POSTGRESQL_USER=user
POSTGRESQL_DATABASE=db
POSTGRESQL_PASSWORD=password
----
+
.. Create an application by using an environment variable file by running the following command:
+
[source,terminal]
----
$ oc new-app openshift/postgresql-92-centos7 --env-file=postgresql.env
----
+
.. Read environment variables from standard input by running the following command:
+
[source,terminal]
----
$ cat postgresql.env | oc new-app openshift/postgresql-92-centos7 --env-file=-
----
+
[NOTE]
====
Any `BuildConfig` objects created as part of `new-app` processing are not updated with environment variables passed with the `-e|--env` or `--env-file` argument.
====

. Pass environment variables to the build container at run time when you create an application from a template, source, or image:
+
.. Pass build environment variables inline by running the following command:
+
[source,terminal]
----
$ oc new-app openshift/ruby-23-centos7 \
    --build-env HTTP_PROXY=http://myproxy.net:1337/ \
    --build-env GEM_HOME=~/.gem
----
+
.. Store build environment variables in a file by creating a file such as `ruby.env` with the following content:
+
[source,terminal]
----
HTTP_PROXY=http://myproxy.net:1337/
GEM_HOME=~/.gem
----
+
.. Create an application by using a build environment variable file by running the following command:
+
[source,terminal]
----
$ oc new-app openshift/ruby-23-centos7 --build-env-file=ruby.env
----
+
.. Read build environment variables from standard input by running the following command:
+
[source,terminal]
----
$ cat ruby.env | oc new-app openshift/ruby-23-centos7 --build-env-file=-
----

. Add labels to objects created by `new-app` by running the following command:
+
[source,terminal]
----
$ oc new-app https://github.com/openshift/ruby-hello-world -l name=hello-world
----

. Preview `new-app` output without creating objects on the cluster:
+
.. Write `new-app` output to a file by running the following command:
+
[source,terminal]
----
$ oc new-app https://github.com/openshift/ruby-hello-world \
    -o yaml > myapp.yaml
----
+
.. Edit `myapp.yaml` as needed, then create the application from the file by running the following command:
+
[source,terminal]
----
$ oc create -f myapp.yaml
----

. Set the name of objects created by `new-app` by running the following command:
+
[source,terminal]
----
$ oc new-app https://github.com/openshift/ruby-hello-world --name=myapp
----

. Create objects in a different project by running the following command:
+
[source,terminal]
----
$ oc new-app https://github.com/openshift/ruby-hello-world -n myproject
----

. Create multiple applications in one command by running the following command:
+
[source,terminal]
----
$ oc new-app https://github.com/openshift/ruby-hello-world mysql
----
+
[NOTE]
====
If a source code repository and a builder image are specified as separate arguments, `new-app` uses the builder image as the builder for the source code repository. If this is not the intent, specify the required builder image for the source using the `~` separator.
====

. Deploy multiple images together in a single pod:
+
.. Group images by using the `+` separator by running the following command:
+
[source,terminal]
----
$ oc new-app ruby+mysql
----
+
.. Group an image built from source with an external image by running the following command:
+
[source,terminal]
----
$ oc new-app \
    ruby~https://github.com/openshift/ruby-hello-world \
    mysql \
    --group=ruby+mysql
----

. Search for images, templates, and other inputs for `oc new-app` by running the following command:
+
[source,terminal]
----
$ oc new-app --search php
----

. Set the import mode when you use `oc new-app`:
+
.. Create image streams by using the `Legacy` import mode by running the following command:
+
[source,terminal]
----
$ oc new-app --image=registry.redhat.io/ubi8/httpd-24:latest  --import-mode=Legacy --name=test
----
+
.. Create image streams by using the `PreserveOriginal` import mode by running the following command:
+
[source,terminal]
----
$ oc new-app --image=registry.redhat.io/ubi8/httpd-24:latest  --import-mode=PreserveOriginal --name=test
----
