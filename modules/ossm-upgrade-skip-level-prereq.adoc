= Prerequisites for a skip-version upgrade

[role="_abstract"]
Before upgrading {SMProductShortName} by skipping a version, verify that your environment meets the required conditions and that you have the necessary access credentials and tools installed.

[#access_{context}]
== Access requirements

* You have logged in to OpenShift Container Platform as a user with the `cluster-admin` role.

* You have installed the `istioctl` command-line tool on your local machine.

[#configuration-requirements_{context}]
== Configuration requirements

* Your mesh uses sidecar mode.

* The `Istio` resource specifies the `RevisionBased` update strategy:
+
[source,yaml]
----
spec:
  updateStrategy:
    type: RevisionBased
----

* The `IstioCNI` resource version matches the current `Istio` resource version.

* An `IstioRevisionTag` resource named `default` references the `Istio` resource, rather than individual `IstioRevision` objects. You create this resource, for example:
+
[source,yaml]
----
apiVersion: sailoperator.io/v1
kind: IstioRevisionTag
metadata:
  name: default
spec:
  targetRef:
    kind: Istio
    name: default
----
+
[NOTE]
====
With `targetRef.kind: Istio`, the tag automatically updates when the `Istio` resource updates. To manually control when the tag switches revisions, point `targetRef` to a specific `IstioRevision` instead. For details, see link:https://docs.redhat.com/en/documentation/red_hat_openshift_service_mesh/3.5/html-single/about/index#istiorevisiontag-resource_ossm-about-concepts[IstioRevisionTag resource].
====

* All workload namespaces that participate in the mesh have the appropriate injection label: `istio-injection=enabled` or `istio.io/rev=default`.
