= Release notes for Red Hat Windows Machine Config Operator 10.20.2

Issued: DD September 2026

[role="_abstract"]
You can review the following release notes to learn about the bug fixes provided in this release of the Windows Machine Config Operator (WMCO). 

The components of the Red Hat Windows Machine Config Operator (WMCO) 10.20.2 were released in link:https://access.redhat.com/errata/TBD[TBD].

[id="wmco-10-20-2-bug-fixes_{context}"]
== Bug fixes

* Before this update, when running the WMCO on a FIPS-enabled {product-title} cluster with FIPS-compliant SSH keys, such as RSA 4096, the Operator would crash due to an internal error in the crypto library's Curve25519 implementation. Because of this, the Operator would panic with the _panic: curve25519: internal error: scalarBaseMult was not 32 bytes_ error, preventing proper Windows node provisioning and management on the cluster. With this release, the `golang.org/x/crypto` package is updated to version 0.47.0, which resolves the Curve25519 internal error handling in FIPS mode. As a result, the Operator no longer crashes with the _scalarBaseMult_ panic error on FIPS-enabled clusters. Windows nodes can now be provisioned successfully. (link:https://issues.redhat.com/browse/OCPBUGS-74381[OCPBUGS-74381])
+
[NOTE]
====
Users might observe the _ssh: handshake failed: curve25519: crypto/ecdh: use of X25519 is not allowed in FIPS 140-only mode_ error in the logs, which is expected behavior in FIPS mode and is tracked separately in link:https://issues.redhat.com/browse/OCPBUGS-74382[OCPBUGS-74382].
====

* Before this update, the `hybridOverlay` service was not using the trusted CA bundle when connecting to Kubernetes, because the `--k8s-cacert` option was missing from the service command. Because of this, users could encounter trust issues or failures when the `hybridOverlay` service attempted to communicate securely with Kubernetes clusters by using custom or internal CAs. With this release, the `hybridOverlay` service command now includes the `--k8s-cacert flag` pointing to the trusted CA bundle. As a result, the `hybridOverlay` service uses the trusted CA bundle for secure communication, preventing trust issues and ensuring compatibility with the cluster. (link:https://issues.redhat.com/browse/OCPBUGS-66266[OCPBUGS-66266]) (link:https://issues.redhat.com/browse/OCPBUGS-65856[OCPBUGS-65856])
