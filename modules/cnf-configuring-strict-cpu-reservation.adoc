= Configure strict CPU reservation for the kubelet

[role="_abstract"]
Configure the `kubelet` CPU Manager `strict-cpu-reservation` policy option on nodes where you plan to use `spec.cpu.ovsDpdk` in a performance profile. This policy option prevents `Burstable` and `BestEffort` pods from running on reserved CPUs, which is required for OVS-DPDK CPU isolation when workload partitioning is not enabled.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the OpenShift CLI (`oc`).
* Workload partitioning is not enabled on the target nodes. If workload partitioning is already enabled, you do not need this procedure.

.Procedure

. Create a `KubeletConfig` CR that enables the `strict-cpu-reservation` policy option on the target nodes:
+
[source,yaml]
----
apiVersion: machineconfiguration.openshift.io/v1
kind: KubeletConfig
metadata:
  name: strict-cpu-reservation
spec:
  machineConfigPoolSelector:
    matchLabels:
      pools.operator.machineconfiguration.openshift.io/worker: ""
  kubeletConfig:
    cpuManagerPolicy: "static"
    cpuManagerPolicyOptions:
      strict-cpu-reservation: "true"
----

. Apply the `KubeletConfig` CR:
+
[source,terminal]
----
$ oc apply -f strict-cpu-reservation.yaml
----

. Wait for the Machine Config Operator to apply the configuration and for the target nodes to reboot:
+
[source,terminal]
----
$ oc get mcp -w
----
+
The pool that matches your `machineConfigPoolSelector` must show `UPDATED=True` and `UPDATING=False`. Press Ctrl+C to stop watching.

.Verification

* Verify that the `kubelet` configuration includes the `strict-cpu-reservation` policy option:
+
[source,terminal]
----
$ oc debug node/<node_name> -- chroot /host cat /etc/kubernetes/kubelet.conf | grep -A 2 cpuManagerPolicyOptions
----
+
.Example output
[source,yaml]
----
cpuManagerPolicyOptions:
  strict-cpu-reservation: "true"
----
