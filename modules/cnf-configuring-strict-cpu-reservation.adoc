= Strict CPU reservation prerequisite for OVS-DPDK

[role="_abstract"]
The Node Tuning Operator requires either workload partitioning or the `kubelet` CPU Manager `strict-cpu-reservation` policy option to be configured before you can reserve CPUs for OVS-DPDK using `spec.cpu.ovsDpdk` in a performance profile. This policy option prevents `Burstable` and `BestEffort` pods from running on reserved CPUs, which is required for OVS-DPDK CPU isolation.

== Configuration methods

Choose one of the following methods to satisfy this prerequisite:

Workload partitioning (recommended):: Enable workload partitioning at cluster install time by setting `cpuPartitioning: AllNodes` in the install configuration. Workload partitioning provides comprehensive CPU isolation for platform services and is the recommended approach for production clusters. For more information, see "Workload partitioning" in _Additional resources_.

Performance profile annotation:: If workload partitioning is not enabled, configure the `strict-cpu-reservation` policy option using the `kubeletconfig.experimental` annotation in your OVS-DPDK performance profile. This annotation ensures that the Node Tuning Operator recognizes the setting when validating the performance profile.
+
[IMPORTANT]
====
Do not configure `strict-cpu-reservation` using a standalone `KubeletConfig` custom resource. The Node Tuning Operator validates prerequisites by checking the performance profile-generated `KubeletConfig`, not standalone `KubeletConfig` resources. A standalone configuration causes the performance profile to enter a `Degraded` state with reason `OvsDpdkCPUsPrerequisiteNotMet`.
====

For the procedure to configure `strict-cpu-reservation` in a performance profile, see "Reserve OVS-DPDK CPUs with a performance profile".
