= Troubleshoot HTTP scaling

[role="_abstract"]
You can trace an HTTP scaling problem from the route to the `InterceptorRoute` resource and the scaled object. Traffic that never reaches the interceptor cannot change the replica count.

.Common HTTP scaling symptoms
[cols="2,2,3",options="header"]
|===
|Symptom
|Likely cause
|What to do

|The application receives requests, and the replica count stays at the minimum.
|The route targets the application service instead of the interceptor.
|Point the route at `keda-add-ons-http-interceptor-proxy` in the `{cma-namespace}` namespace.

|The workload does not scale on HTTP traffic, and the horizontal pod autoscaler uses CPU.
|The scaled object was created before the `InterceptorRoute` resource was ready.
|Delete the scaled object, wait until the interceptor route is `Ready`, and create the scaled object again.

|The client receives HTTP `504` during a scale-up from zero.
|The readiness or request timeout expired.
|Increase `spec.timeouts.readiness` or `spec.timeouts.request`, or configure a cold-start fallback service.

|The interceptor does not forward the request to the expected workload.
|The request host, path, or headers do not match `spec.rules`.
|Set the route host to the same host as `spec.rules[].hosts`.

|Requests fail before the interceptor can route them, or path-based rules never match.
|The route uses passthrough TLS termination.
|Use `edge` or `reencrypt` termination.
|===

.Prerequisites

* The HTTP add-on is enabled.
* An `InterceptorRoute` resource and a scaled object exist for the workload.
* The OpenShift CLI (`oc`) is installed.

.Procedure

. Confirm that the HTTP add-on is installed by running the following command:
+
[source,terminal,subs="+attributes"]
----
$ oc get kedacontroller keda -n {cma-namespace} -o yaml
----
+
`status.httpAddon.phase` must be `Installation Succeeded`. If it is not, see "Enable the HTTP add-on".

. Confirm that the interceptor route is ready by running the following command:
+
[source,terminal]
----
$ oc get interceptorroute -n my-namespace
----
+
The `READY` column must be `True`.

. Confirm that the scaled object trigger points at the HTTP add-on scaler by running the following command:
+
[source,terminal]
----
$ oc get scaledobject sample-app -n my-namespace -o yaml
----
+
`spec.triggers[].metadata.interceptorRoute` must match the `InterceptorRoute` name. `spec.triggers[].metadata.scalerAddress` must be `keda-add-ons-http-external-scaler.{cma-namespace}.svc:9090`.

. Confirm that the route targets the interceptor by running the following command:
+
[source,terminal,subs="+attributes"]
----
$ oc get route sample-app -n {cma-namespace} -o yaml
----
+
`spec.to.name` must be `keda-add-ons-http-interceptor-proxy`, and `spec.host` must match a host on the interceptor route. `spec.tls.termination` must be `edge` or `reencrypt`.

. Inspect the interceptor logs. List the pods by running the following command:
+
[source,terminal,subs="+attributes"]
----
$ oc get pods -n {cma-namespace}
----

. Read the logs for an interceptor pod by running the following command:
+
[source,terminal,subs="+attributes"]
----
$ oc logs -n {cma-namespace} <pod_name>
----
