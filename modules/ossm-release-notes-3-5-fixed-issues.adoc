= {SMProductName} version 3.5 fixed issues

[role="_abstract"]

OpenShift Service Mesh inherits fixes for Common Vulnerabilities and Exposures (CVEs) and bugs from upstream Istio and related projects.

Information about CVEs::
See link:https://access.redhat.com/errata-search/?q=&p=1&sort=portal_update_date+desc&rows=10&portal_product=Red%5C+Hat%5C+OpenShift%5C+Service%5C+Mesh&portal_advisory_type=Security+Advisory[OpenShift Service Mesh Security Advisories].

Upstream fixed issues in {SMProduct} 3.5::
** `DestinationRule` and backend policy precedence: When both a `DestinationRule` and a Gateway API backend policy (`BackendTLSPolicy` or `XBackendTrafficPolicy`) target the same host, `DestinationRule` fields take precedence. This fix ensures the backend policy only fills in fields that the `DestinationRule` leaves unset, regardless of which resource was created first.
+
** Consistent hash load balancing: `DestinationRule` configurations that use `consistentHash` properly send traffic to new endpoints after scaling. 
+
** Subset TLS configuration: When a `DestinationRule` subset does not specify a TLS mode for a port, it correctly falls back to the top-level traffic policy TLS setting. This fix ensures endpoint mTLS mode is properly inherited.
+
** Zone-aware routing configuration: Setting `zoneAwareLbSetting.enabled: false` properly disables Envoy zone-aware routing. This fix prevents uneven traffic distribution during gradual rollouts when some pods have self-discovery enabled and others do not.

For complete details, see the upstream Istio release documentation: link:https://istio.io/latest/news/releases/1.31.x/announcing-1.31/change-notes[Istio 1.31 change notes]
