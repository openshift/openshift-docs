= Console without istiod access

[role="_abstract"]

{KialiServer} calls the istiod debug API for control-plane status and proxy status. If that API is disabled, blocked, or unreachable, the console still runs with a smaller set of features. Tell the server that the API is unavailable. Otherwise it keeps trying to call istiod.

.Console behavior when istiod is unreachable
image::ossm-kiali-no-istiod.png[Kiali message when the istiod API is disabled]

[source,yaml]
----
spec:
  external_services:
    istio:
      istio_api_enabled: false
----

The default is `true`. With the API off:

* Control-plane metrics are hidden.
* Workload pages do not show proxy status.
* Control-plane health uses the namespace status instead of the {istio} component status.
* {istio} objects are still listed and can still be edited, because those objects come from the {ocp-product-title} API.

From Kiali 2.23, Kiali validations still run when the istiod API is off. Earlier versions hide those validations too. Objects you save are not checked by the istiod validating webhook when istiod cannot be reached. If the webhook is still registered, creates and updates fail. List the webhooks with:

[source,terminal]
----
$ oc get validatingwebhookconfiguration
----

Remove the {istio} validating webhook only when istiod is intentionally unreachable and you still need to save {istio} objects from the console.
