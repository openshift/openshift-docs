= Isolation mechanisms in hybrid architecture

In a hybrid architecture, two reconciliation models operate in a single Argo CD instance. To prevent the application controller and the Argo CD Agent components from acting on the same resources, {gitops-title} uses the following isolation mechanisms.

Label selectors::
You configure label selectors in the `ArgoCD` custom resource (CR) to restrict which resources the principal and agent process. Resources without the matching label remain invisible to the Argo CD Agent components, and the hub's application controller continues to reconcile them.
+
Configure the same selector on both components:
+
* `spec.argoCDAgent.principal.labelSelector` on the control plane cluster.
* `spec.argoCDAgent.agent.labelSelector` on each workload cluster.
+
Use a standard Kubernetes label selector expression, for example `argocd-agent=true`. Apply this label to every resource (Applications, AppProjects, Repository secrets) that you want the Argo CD Agent to manage.
+
[IMPORTANT]
====
Always set a label selector in a hybrid architecture. Without one, the principal processes all Argo CD resources in the namespaces that it watches, including your existing applications.
====

The skip-reconcile annotation::
The cluster secret that represents an agent carries the `argocd.argoproj.io/skip-reconcile: "true"` annotation. This prevents the hub's application controller from reconciling managed applications whose destination is that cluster. The `argocd-agentctl agent create` command adds this annotation automatically.

[NOTE]
====
Destination-based mapping routes applications to agents based on `spec.destination.name` rather than the application's namespace. This allows applications to remain in their current namespaces during migration instead of requiring you to move them to agent-specific namespaces. Enable this in both the principal and agent configurations for hybrid setups.
====
