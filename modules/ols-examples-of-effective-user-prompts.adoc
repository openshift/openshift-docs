= Examples of effective user prompts

[role="_abstract"]
You can enter natural language prompts in the {ols-long} chat interface to investigate cluster issues. Troubleshooting can begin from an active alert or from any observed issue, event, or anomaly across the cluster.

In {ocp-product-title} 5.0 and later, {ols-long} leverages expanded OpenShift Model Context Protocol (MCP) server integrations, including Network Observability, Service Mesh, and Distributed Tracing, to analyze complex cluster behaviors.

.Example prompts for common troubleshooting scenarios
[cols="1,1,2", options="header"]
|===
| Scenario | Goal | Example prompt

| Cluster status or alert fatigue
| Summarize multiple firing alerts or cluster issues into a unified context.
| Summarize all active alerts and workload issues in the production namespace and identify the most critical issue.

| Root cause analysis
| Identify why an application or workload is failing.
| Investigate the current status of the payment application and identify why the pod is restarting.

| Context refinement
| Narrow the search scope to a specific namespace or resource.
| Focus on the payments namespace only. Show me the logs for the pod that restarted most recently.

| Historical baseline comparison
| Compare current resource usage against historical metrics.
| Show container memory usage versus limit for this deployment today compared to last week.

| Networking
| Diagnose network connectivity or throughput degradation.
| Investigate connectivity drops in the payment namespace and check for related network errors.

| Red herring identification
| Filter out unrelated errors during broader system degradation.
| Investigate the API error in the payments namespace and state whether the active `CrashLoopBackOff` alert is related or a red herring.

| Cross-namespace correlation
| Identify if a failure in one namespace is caused by a dependency in another.
| Why is the payments-api degrading? Check for related database alerts in the shared-services namespace.

| Network observability
| Track traffic flows and identify packet drops across node interfaces.
| Analyze flow logs for the payments service and identify top sources of dropped packets over the last 30 minutes.

| Service Mesh
| Diagnose microservice communication failures, latency spikes, or mutual TLS (mTLS) errors.
| Analyze traffic routing between ingress-gateway and payments-api to find the source of 5xx HTTP errors.

| Distributed tracing
| Trace end-to-end request paths to pinpoint latency bottlenecks in distributed calls.
| Show trace spans with high latency for checkout transaction paths across all connected microservices.
|===
