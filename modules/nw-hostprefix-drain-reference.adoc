= Node drain options for hostPrefix changes

[role="_abstract"]
To drain nodes when increasing `hostPrefix`, you must drain each node during maintenance. You can use the `oc adm drain` command as a starting point and customize it for your environment.

The following command is a common starting point, but you must validate each option against your workloads before production use.

[source,terminal]
----
$ oc adm drain <node> --force --delete-emptydir-data --ignore-daemonsets --disable-eviction
----

where:

`<node>`:: Specifies the node name to drain.

The command options have the following effects:

`--force`:: Allows drain to continue for pods that are not managed by a controller. This can interrupt unmanaged workloads.
`--delete-emptydir-data`:: Deletes pods using `emptyDir` volumes. Data stored in `emptyDir` is lost when those pods are removed.
`--ignore-daemonsets`:: Continues drain without evicting DaemonSet-managed pods. DaemonSet pods remain and can affect full node evacuation expectations.
`--disable-eviction`:: Uses delete operations instead of eviction API behavior. This bypasses pod disruption budget protections and can cause greater disruption.

Use caution when workloads include:

* Stateful applications that depend on local data.
* Strict pod disruption budgets.
* Long startup times or strict availability objectives.
* Workloads that are sensitive to forced deletion behavior.

If these conditions apply, customize drain behavior for your environment and validate the command in non-production before production use.
