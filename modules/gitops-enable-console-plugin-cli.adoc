= Enable the GitOps Console plugin using the CLI

If you disable the GitOps Console plugin after installing the {gitops-title} Operator, you can enable it manually using the OpenShift CLI.

.Prerequisites

* You have installed the {gitops-title} Operator.
* You have access to the cluster with `cluster-admin` permissions.
* You have installed the OpenShift CLI (`oc`).

.Procedure

The console loads plugins listed in `spec.plugins` on `console.operator.openshift.io/cluster`.

. Check which plugins are enabled:
+
[source,terminal]
----
$ oc get console.operator.openshift.io cluster -o jsonpath='{.spec.plugins}{"\n"}'
----

. To enable *gitops-plugin*:
+
--
* If step 1 printed a JSON array, for example `["monitoring-plugin"]`, append *gitops-plugin*:
+
[source,terminal]
----
PLUGIN_PATCH='[{"op":"add","path":"/spec/plugins/-","value":"gitops-plugin"}]'
oc patch console.operator.openshift.io cluster --type=json -p "${PLUGIN_PATCH}"
----

* If step 1 printed nothing or only `null`, `spec.plugins` is missing. Create the list:
+
[source,terminal]
----
PLUGIN_PATCH='[{"op":"add","path":"/spec/plugins","value":["gitops-plugin"]}]'
oc patch console.operator.openshift.io cluster --type=json -p "${PLUGIN_PATCH}"
----
+
Skip this step if `gitops-plugin` is already in the list from the previous command.
--

. Refresh the browser after the change. The *GitOps* entry appears in the navigation menu when the plugin is enabled.

.Verification

* Navigate to *GitOps* in the navigation menu and verify that you can access Applications, ApplicationSets, AppProjects, ImageUpdaters, and Rollouts pages.

.Disabling the plugin

To disable *gitops-plugin*, edit the Console operator and remove `gitops-plugin` from `spec.plugins`:

[source,terminal]
----
$ oc edit console.operator.openshift.io cluster
----

.Example
[source,yaml]
----
spec:
  plugins:
    - monitoring-plugin
    # remove: - gitops-plugin
----

After saving the change, refresh the browser. The *GitOps* entry disappears from the navigation when the plugin is disabled.
