= Verify per-identity credential isolation

[role="_abstract"]
Different workload identities automatically get different credentials from Vault. The `urlExpression` in the `AuthPolicy` constructs the Vault path from the namespace and service account name of the workload. You can verify this behavior by storing a different credential for another namespace and testing.

.Prerequisites

* You deployed an egress `Gateway` object.
* A credential injection `AuthPolicy` object is applied.
* You deployed HashiCorp Vault with the Kubernetes `auth` method configured.

.Procedure

. Export the egress gateway address by running the following command:
+
[source,terminal]
----
$ export EGRESS_IP=$(oc get gtw _<kuadrant_egressgateway>_ -n _<gateway_system>_ \
    -o jsonpath='{.status.addresses[0].value}')
----
+
Replace `_<kuadrant_egressgateway>_` value with the egress `Gateway` object name.

. Add the new namespace to the Vault role by running the following command:
+
[source,terminal]
----
$ oc exec vault-0 -n vault -- vault write auth/kubernetes/role/egress-workload \
    bound_service_account_names=default \
    bound_service_account_namespaces=egress-test,workload-b \
    policies=egress-read \
    ttl=1h
----

. Store a different credential for the new namespace by running the following command:
+
[source,terminal]
----
$ oc exec vault-0 -n vault -- vault kv put secret/egress/workload-b/default \
    api_key=sk-different-key-for-workload-b
----

. Create a new namespace for the workload by running the following command:
+
[source,terminal]
----
$ oc create namespace workload-b
----

. Deploy a workload in the new namespace by using the following example by using the following example:
+
[source,yaml]
----
apiVersion: v1
kind: Pod
metadata:
  name: test-client-b
  namespace: workload-b
spec:
  containers:
    - name: curl
      image: curlimages/curl:latest
      command: ["sleep", "infinity"]
  restartPolicy: Never
----

. Apply the CR by running the following command:
+
[source,terminal]
----
$ oc apply -f test-client-b
----

. Wait for the pod to be ready by running the following command:
+
[source,terminal]
----
$ oc wait --for=condition=Ready pod/test-client-b -n workload-b --timeout=60s
----

.Verification

. Verify that the original workload receives its credential by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc exec test-client -n egress-test -- sh -c '
curl -s -H "Host: _<httpbin.org>_" \
    -H "Authorization: Bearer $(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
    http://'"${EGRESS_IP}"'/get
'
----
+
** Replace `_<httpbin.org>_` with your external target service.
** The response displays, `Authorization: Bearer sk-test-openai-key-for-egress`.

. Verify that the new workload receives a different credential by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc exec test-client-b -n workload-b -- sh -c '
curl -s -H "Host: _<httpbin.org>_" \
    -H "Authorization: Bearer $(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
    http://'"${EGRESS_IP}"'/get
'
----
+
** Replace `_<httpbin.org>_` with your external target service.
** The response displays, `Authorization: Bearer sk-different-key-for-workload-b`.
