= Nested SPIRE configuration reference

[role="_abstract"]
Use this reference when you set nested SPIRE fields on the `SpireServer` CR. Nested SPIRE adds optional fields to the existing cluster-scoped `SpireServer` CR. It does not add a new custom resource.

You can set only one UpstreamAuthority plugin. The `SpireServer` CR rejects a spec that sets more than one of `certManager`, `vault`, and `spire`.

[id="zero-trust-manager-nested-spire-downstream-fields_{context}"]
== Downstream cluster fields

Set these fields on the downstream `SpireServer` CR under `spec.upstreamAuthority.spire`.

[cols="2,1,1,1,3",options="header"]
|===
| Field | Type | Required | Default | Description

| `upstreamAuthority.spire.serverAddress`
| string
| Yes
| N/A
| DNS hostname of the upstream SPIRE server gRPC endpoint. Do not include a URL scheme, a port, or a path. Maximum length is 253 characters. The value must match the upstream Route host.

| `upstreamAuthority.spire.serverPort`
| integer
| No
| `443`
| TCP port of the upstream gRPC endpoint. Valid values are `1` through `65535`.

| `upstreamAuthority.spire.trustBundleSecret`
| string
| Yes
| N/A
| Name of a Secret in the `zero-trust-workload-identity-manager` namespace. The Secret data key `bundle.crt` contains PEM-encoded X.509 root certificates for the upstream trust domain.
|===

[id="zero-trust-manager-nested-spire-upstream-fields_{context}"]
== Upstream cluster fields

`spec.nestedSpire` requires `spec.grpcEndpoint`.

[cols="2,1,1,1,3",options="header"]
|===
| Field | Type | Required | Default | Description

| `grpcEndpoint.managedRoute`
| string
| No
| `"true"`
| `"true"` creates a passthrough Route named `spire-server-grpc`. `"false"` means you create the Route. Valid values are `"true"` and `"false"`.

| `nestedSpire.downstreamClusters`
| array
| No
| empty
| Downstream clusters whose SPIRE servers chain to this server. The array is a map keyed by `name`.

| `nestedSpire.downstreamClusters[].name`
| string
| Yes
| N/A
| Downstream cluster identifier. Must match that cluster's `ZeroTrustWorkloadIdentityManager.spec.clusterName`. Immutable. DNS-1123 subdomain of 1 to 63 characters.

| `nestedSpire.downstreamClusters[].kubeConfigSecret`
| string
| Yes
| N/A
| Name of a Secret in the `zero-trust-workload-identity-manager` namespace. The Secret data key `kubeconfig` contains a kubeconfig for the downstream cluster API server.
|===

When `managedRoute` is `"true"`, the Route host is `grpc.<clusterName>.<trustDomain>`. `<clusterName>` is the upstream cluster's `spec.clusterName`. The Route uses passthrough TLS and targets the `grpc` port of the `spire-server` Service. Passthrough TLS is required so that clients see the SPIRE server certificate.

[id="zero-trust-manager-nested-spire-conditions_{context}"]
== Status conditions

Downstream `SpireServer` CR::

`UpstreamAgentAvailable`:: The upstream agent deployment has an available replica and the trust bundle Secret exists. Reasons: `Ready`, `DeploymentNotReady`, `TrustBundleMissing`.
`UpstreamCSIDriverAvailable`:: The upstream CSI DaemonSet is ready. Reasons: `Ready`, `DaemonSetNotReady`.

Upstream `SpireServer` CR::

`GRPCEndpointAvailable`:: The gRPC Route matches the expected spec. Reasons: `RouteCreated`, `RouteCreationFailed`, `RouteDisabled`.
`DownstreamClustersValid`:: For each downstream cluster, the kubeconfig Secret exists and both generated `ClusterStaticEntry` objects are rendered and not masked. Reasons: `Ready`, `KubeConfigMissing`, `EntryNotApplied`, `EntryMasked`.

[id="zero-trust-manager-nested-spire-resources_{context}"]
== Resources created by the operator

On the downstream cluster, {zero-trust-full} creates the following objects in the `zero-trust-workload-identity-manager` namespace:

* `Deployment` `spire-agent-upstream`
* `DaemonSet` `spire-spiffe-csi-driver-upstream`
* `ServiceAccount` `spire-agent-upstream`

{zero-trust-full} also creates the cluster-scoped `SecurityContextConstraints` object `spire-agent-upstream` and the `CSIDriver` object `upstream.csi.spiffe.io`.

On the upstream cluster, {zero-trust-full} creates the following objects for each downstream cluster:

* `Route` `spire-server-grpc` in the `zero-trust-workload-identity-manager` namespace, when `managedRoute` is `"true"`
* `ClusterStaticEntry` `nested-spire-<downstream_cluster_name>-node-alias`
* `ClusterStaticEntry` `nested-spire-<downstream_cluster_name>-downstream`

The downstream entry sets `downstream: true`, which authorizes that cluster's SPIRE server to request an intermediate CA. {zero-trust-full} recreates these objects if they are deleted. CA issuance pauses until the entries are restored. Workload issuance continues from the cached intermediate CA.
