= {mcpg} router spans for observability

[role="_abstract"]
When you enable tracing, the Model Context Protocol (MCP) router, `ext_proc`, emits trace spans for every request and exports structured logs through {OTELName}.

Spans give you a continuous timeline of traffic events across different pods and services. The {mcpg} supports dual-protocol routing, both legacy `2025-11-25` stateful transport and current `2026-07-28` stateless transport specifications. The specific sequence of generated spans depends on the protocol version negotiated by the client.

.MCP router spans by protocol version
[cols="1,1,2", options="header"]
|===
|Span |Protocol |Description

|`mcp-router.process`
|Both 2025 and 2026
|Root span. Starts when request headers arrive, ends after response headers are processed.

|`mcp-router.route-decision`
|Both 2025 and 2026
|Determines request type (`tool-call`, `async-task`, or broker pass-through).

|`mcp-router.broker-passthrough`
|Both 2025 and 2026
|Direct pass-through for non-tool requests (such as `server/discover`, `tools/list`, and `notifications`).

|`mcp-router.tool-call`
|Both 2025 and 2026
|Handles tool invocation (`tools/call`).

|`mcp-router.broker.get-server-info`
|Both 2025 and 2026
|Queries the broker to resolve which backend MCP server owns the requested tool.

|`mcp-router.session-cache.get`
|2025 stateful only
|Queries the session cache to look up an existing backend connection session.

|`mcp-router.session-init`
|2025 stateful only
|Cache miss handler. Executes a hairpin `initialize` request to establish a stateful backend session.

|`mcp-router.session-cache.store`
|2025 stateful only
|Persists a new backend session in the session cache.

|`mcp-router.async-task`
|2026 stateless only
|Handles multi-round-trip background execution flows: `tasks/call`.
|===

[NOTE]
====
In the `2026-07-28` MCP specification release, session-management spans such as `session-cache.*` and `session-init` are bypassed entirely due to the protocol stateless core.
====

The attributes attached to spans use link:https://opentelemetry.io/docs/specs/semconv/gen-ai/mcp/#server[OpenTelemetry MCP Semantic Conventions].

.MCP router root span (`mcp-router.process`) attributes
[cols="1,1,1,2", options="header"]
|===
|Attribute |2025 MCP spec |2026 MCP spec |Description

|`http.request.method`
|`http.method`
|`http.request.method`
|HTTP method (`POST`).

|`url.path`
|`http.path`
|`url.path`
|Request URI path (`/mcp`).

|`http.request_id`
|`http.request_id`
|`http.request_id`
|Envoy request correlation ID (`x-request-id`).

|`mcp.method`
|`mcp.method.name`
|`mcp.method`
|MCP method, such as `tools/call`, `server/discover`, `tools/list`. Extracted directly from the `MCP-Method` HTTP header in 2026.

|`mcp.name`
|`gen_ai.tool.name`
|`mcp.name`
|Tool or operation target name. Extracted directly from the `MCP-Name` HTTP header in 2026.

|`mcp.protocol.version`
|`jsonrpc.protocol.version`
|`mcp.protocol.version`
|Protocol `spec` version string, such as `2025-11-25` or `2026-07-28`.

|`mcp.session.id`
|`mcp-session-id` header
|*Removed*
|Gateway session ID. Emitted for 2025 stateful connections only.

|`client.address`
|`x-forwarded-for`
|`client.address`
|Client IP address derived from proxy headers.

|`http.response.status_code`
|`http.status_code`
|`http.response.status_code`
|HTTP status code returned by the router.
|===

.MCP route decision span (`mcp-router.route-decision`) attributes
[cols="1,2", options="header"]
|===
|Attribute |Description

|`mcp.method`
|Extracted MCP method.

|`mcp.route`
|Routing decision: `tool-call`, `broker`, `async-task`, or `elicitation-response`.
|===

.MCP tool call span (`mcp-router.tool-call`) attributes
[cols="1,2", options="header"]
|===
|Attribute |Description

|`mcp.name`
|Name of the target tool being executed.

|`mcp.server`
|Resolved backend MCP server identifier.

|`mcp.server.hostname`
|Resolved backend server network hostname.

|`mcp.session.id`
|Gateway session ID. Emitted for 2025 stateful connections only.
|===

.MCP error attributes
[cols="1,2", options="header"]
|===
|Attribute |Description

|`error.type`
|Error classification, such as `tool_not_found`, `missing_tool_name`, `path_parse_error`, `session_init_error`.

|`error_source`
|Component that generated the error, such as `ext-proc` or `broker`.

|`http.response.status_code`
|HTTP status code associated with the error response.
|===
