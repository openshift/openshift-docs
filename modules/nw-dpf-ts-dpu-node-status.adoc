= DPU nodes remain in NotReady state

[role="_abstract"]
If DPU nodes appear in the hosted cluster but remain in a `NotReady` state, verify DPU provisioning completion, network configuration, and kubelet status.

Check DPU provisioning status::
Verify that DPU provisioning has completed successfully on the management cluster:
+
[source,terminal]
----
$ oc get dpu -n dpf-operator-system
----
+
Ensure that all DPU objects show a `Ready` status.

Verify DPU node status in hosted cluster::
Switch to the hosted cluster context and check the node status:
+
[source,terminal]
----
$ export KUBECONFIG=<path_to_hosted_cluster_kubeconfig>
$ oc get nodes
----
+
Check the node conditions for specific error messages:
+
[source,terminal]
----
$ oc describe node <dpu-node-name>
----

Check kubelet status on DPU::
Access the worker node and verify kubelet status:
+
[source,terminal]
----
$ oc debug node/<worker-node-name>
----
+
[source,terminal]
----
sh-4.4# chroot /host
sh-4.4# journalctl -u kubelet -f
----
+
Look for kubelet authentication or networking errors.

Verify DPU network connectivity::
Ensure that the DPU can communicate with the hosted cluster control plane:
+
[source,terminal]
----
sh-4.4# ping <hosted-cluster-api-vip>
----
+
Check that the DPU has correct network configuration and routing.

Check CNI configuration::
Verify that the Container Network Interface (CNI) is properly configured on the DPU:
+
[source,terminal]
----
$ export KUBECONFIG=<path_to_hosted_cluster_kubeconfig>
$ oc get pods -n openshift-ovn-kubernetes
----
+
Ensure that OVN-Kubernetes pods are running on the DPU ARM cores.

Verify DPU system resources::
Check if the DPU has sufficient resources:
+
[source,terminal]
----
sh-4.4# free -h
sh-4.4# df -h
----
+
Ensure adequate memory and disk space for kubelet operation.
