= Agent custom resource configuration

[role="_abstract"]
The `Agent` custom resource (CR) is a cluster-scoped resource in the `agentic.openshift.io/v1alpha1` API group that pairs an `LLMProvider` with a model and runtime settings. The `metadata.name` field is the agent tier identifier. An `Agent` named `default` must exist, because the deployment uses it when a workflow step does not specify an agent.

.Agent spec fields
[cols="1,1,2", options="header"]
|===
| Field | Required | Description

| `spec.llmProvider.name`
| Yes
| The name of the cluster-scoped `LLMProvider` CR that supplies the LLM backend for this agent.

| `spec.model`
| Yes
| The model identifier as recognized by the provider, for example, `claude-haiku-4-5` or `gpt-4o`. The model must match the provider backend and, for Vertex AI, the configured model family.

| `spec.maxTurns`
| No
| The maximum number of tool-use turns the agent can take during a single workflow step, which prevents runaway loops. The value must be between 1 and 500. When omitted, the deployment uses the default value of 200.

| `spec.timeouts`
| No
| Per-step timeout limits in seconds. Supported fields are `analysisSeconds`, `executionSeconds`, `verificationSeconds`, and `escalationSeconds`. Each value must be between 1 and 3600. When a field is omitted, the deployment uses the built-in default: 600 seconds for `analysisSeconds`, `executionSeconds`, and `escalationSeconds`, and 1800 seconds for `verificationSeconds`.

| `spec.reasoningConfig`
| No
| A map of provider-specific and model-specific reasoning parameters. The supported keys and values depend on the provider and model; consult the provider SDK documentation for the parameters that it supports. For example, Claude models use `thinking` and `budget_tokens`, Gemini models use `thinking_budget` and `thinking_level`, and OpenAI models use `reasoning.effort` and `reasoning.summary`. When omitted, the deployment uses SDK defaults.

| `spec.instructions`
| No
| Optional per-step system and user instructions for the `analysis`, `execution`, `verification`, and `escalation` steps. When a field is set, it replaces the built-in instructions for that step.
|===

You can define multiple agent tiers that share one `LLMProvider` with different models. For example, you can define a `smart` tier that uses a high-capability model and a `fast` tier that uses a cost-efficient model, in addition to the required `default` tier.
