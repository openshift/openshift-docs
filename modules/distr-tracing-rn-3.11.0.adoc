= Release notes for {dt} 3.11.0

[role="_abstract"]
{Dit} 3.11.0 is provided through the link:https://catalog.redhat.com/software/containers/rhosdt/tempo-operator-bundle/642c3e0eacf1b5bdbba7654a[{TempoOperator} 0.22.0] and is based on the open source link:https://grafana.com/oss/tempo/[Grafana Tempo] 2.10.8.

[NOTE]
====
You can access some linked Jira tickets only with Red{nbsp}Hat credentials.
====

The {dt} 3.11.0 release adds these features and enhancements:

High availability defaults for `TempoStack` deployment sizes::
Before this update, only the ingester component was scaled for high availability while all other components defaulted to a single replica, leaving the overall ingest and query paths vulnerable to single points of failure. With this update, when you set a non-demo deployment size (`1x.pico`, `1x.extra-small`, `1x.small`, or `1x.medium`) in the `spec.size` field of the `TempoStack` custom resource, the Operator defaults each component to at least 2 replicas, and scales throughput-bound components at larger sizes. Explicit per-component replicas values always take precedence.
+
[WARNING]
====
Watch your resource consumption, as running more replicas per component increases the total CPU and memory consumed by the deployment.
====
+
link:https://redhat.atlassian.net/browse/TRACING-6169[TRACING-6169]

High availability for `TempoStack` deployments::
You can use the `spec.replicationZones` field in the `TempoStack` custom resource to define zone-aware replication. By using this feature, you can deploy `TempoStack` instances with higher resilience by spreading replicas across topology zones and ensuring minimum pod availability during disruptions.
+
link:https://redhat.atlassian.net/browse/TRACING-6167[TRACING-6167]

Service name and namespace auto-complete with query RBAC enabled::
When you enable query Role-Based Access Control (RBAC) in a multi-tenant `TempoStack` deployment, the Tempo gateway supports auto-complete for non-sensitive attributes such as the service name and namespace. Before this update, all tag value API endpoints were blocked when query RBAC was enabled, which prevented the *Service Name* drop-down filter in the {dt} console plugin from displaying results. With this update, the gateway allows the search tags API for non-sensitive attributes while still protecting sensitive span data. As a result, the *Service Name* filter and other non-sensitive attribute drop-down list items work correctly in multi-tenant RBAC mode.
+
link:https://redhat.atlassian.net/browse/TRACING-6485[TRACING-6485]

The {dt} 3.11.0 release fixes these issues:

`TempoStack` and `TempoMonolithic` status conditions accurately reflect pod readiness::
Before this update, the status field of the `TempoStack` or `TempoMonolithic` custom resource might show `Ready=false` even when all pods were ready, or vice versa. With this update, the Operator watches Deployment and StatefulSet status changes, and the status conditions accurately reflect actual pod readiness. Deleted pods are removed from the pod status map. As a result, the status field reliably indicates the current state of the deployment.
+
link:https://redhat.atlassian.net/browse/TRACING-6453[TRACING-6453]

Gateway redirect URL respects custom ingress hostname::
Before this update, setting a custom hostname with the `spec.template.gateway.ingress.host` field in the `TempoStack` custom resource did not update the OpenShift OAuth redirect URL. This caused authentication redirects to point to an incorrect URL. With this update, the Operator uses the custom hostname when generating the redirect URL, and gateway authentication works correctly with custom ingress hostnames.
+
link:https://redhat.atlassian.net/browse/TRACING-6435[TRACING-6435]

Gateway starts on clusters that use external OIDC authentication::
Before this update, on clusters using external OpenID Connect (OIDC) authentication instead of the built-in OpenShift OAuth server, the gateway container failed to start because it could not auto-discover the necessary authentication endpoints. With this update, the gateway handles external OIDC authentication and starts correctly.
+
link:https://redhat.atlassian.net/browse/TRACING-6646[TRACING-6646]

Deadlock vulnerability in TLS 1.3 connections fixed in Go `crypto/tls` package::
Before this update, a flaw in the `crypto/tls` package of the Go standard library allowed remote attackers to send multiple key update messages within a single record after completing a TLS 1.3 handshake. Consequently, this caused the connection to deadlock, leading to uncontrolled resource consumption and a denial of service (DoS). With this update, the `crypto/tls` package correctly handles key update messages in TLS 1.3 connections, preventing deadlocks and resource exhaustion.
+
link:https://access.redhat.com/security/cve/CVE-2026-32283[CVE-2026-32283]

Denial of service vulnerability fixed in Apache Thrift::
Before this update, Apache Thrift improperly handled highly compressed data, leading to a data amplification flaw. Consequently, a remote attacker could send specially crafted, highly compressed data, causing the component to fail during data expansion, which resulted in resource exhaustion and a denial of service (DoS). With this update, Apache Thrift properly manages data expansion for compressed payloads, preventing resource exhaustion and maintaining system availability.
+
link:https://access.redhat.com/security/cve/CVE-2026-48586[CVE-2026-48586]

Denial of service vulnerability fixed in Apache Thrift language bindings::
Before this update, an integer overflow or wraparound vulnerability existed in Apache Thrift bindings for C++, `c_glib`, Go, `netstd`, Delphi, and Haxe. Consequently, a remote attacker could send specially crafted input to trigger the flaw, causing affected services to become unavailable and impacting system reliability. With this update, Apache Thrift language bindings correctly handle input values to prevent integer overflows and wraparound conditions, ensuring service availability and system stability.
+
link:https://access.redhat.com/security/cve/CVE-2026-55969[CVE-2026-55969]

Cross-site scripting vulnerability fixed in Go `html` package::
Before this update, a flaw in the `golang.org/x/net/html` package improperly parsed specially crafted HTML input, altering how the HTML was processed and rendered. Consequently, this allowed an attacker to create an unexpected document structure, leading to potential Cross-Site Scripting (XSS) attacks that could compromise user data or sessions. With this update, the `golang.org/x/net/html` package correctly parses and renders HTML structures, preventing unauthorized script execution and preserving session integrity.
+
link:https://access.redhat.com/security/cve/CVE-2026-42502[CVE-2026-42502]
