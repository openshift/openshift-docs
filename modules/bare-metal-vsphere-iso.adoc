= Create compute machines from an ISO image

[role="_abstract"]
Install {op-system-first} on physical machines or virtual machines (VMs) by using an ISO image and the worker Ignition configuration from your {product-title} cluster on {vmw-short}. The machines join as workers without {vmw-short} integration.

.Prerequisites

* You have prepared the machines, network, and storage for adding compute machines without {vmw-short} integration.
* You have added any new machine subnets to the target cluster's infrastructure configuration.
* You have a Hypertext Transfer Protocol (HTTP) server that the new machines can access to download the Ignition configuration.
* You have installed the {oc-first} and `jq` on your workstation.
* You are logged in to the target cluster as a user with the `cluster-admin` role.

.Procedure

. From your workstation, obtain the ISO download URL from the target cluster by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc -n openshift-machine-config-operator get configmap/coreos-bootimages -o jsonpath='{.data.stream}' | jq -r '.architectures["<architecture>"].artifacts.metal.formats.iso.disk.location'
----
+
Replace `<architecture>` with the processor architecture of the new machines, for example, `x86_64`. The architecture must be supported by the target cluster.

. Download the ISO image from the returned URL.

. Extract the worker Ignition configuration from the target cluster by running the following command:
+
[source,terminal]
----
$ oc extract -n openshift-machine-api secret/worker-user-data-managed --keys=userData --to=- > worker.ign
----

. Upload the `worker.ign` file to your HTTP server. Record its URL.

. Boot the new machine from the ISO image:
+
** For a physical machine, use local installation media or remote ISO redirection.
** For a VM, attach the ISO image to the VM's virtual optical drive and configure the VM to boot from it.

. From the live installation console, configure networking if Dynamic Host Configuration Protocol (DHCP) does not provide the required settings. You can use `nmcli` or `nmtui` to configure a static address or other network settings.

. From the live installation console, verify that the machine can retrieve its Ignition configuration by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ curl --fail http://<http_server>/worker.ign
----
+
Replace `<http_server>` with the address of your HTTP server. Include the path to `worker.ign` if you placed it in a subdirectory. The command must return the Ignition configuration.

. Identify the destination disk by running the following command:
+
[source,terminal]
----
$ lsblk
----

. Install {op-system} on that disk by running the following command:
+
If you configured networking in the live environment, add `--copy-network` to the command to copy the connection profiles in `/etc/NetworkManager/system-connections` to the installed system. This option does not copy the system hostname. Use the documented hostname configuration for your network.
+
[source,terminal,subs="+quotes"]
----
$ sudo coreos-installer install <installation_disk> \
    --ignition-url=http://<http_server>/worker.ign \
    --insecure-ignition \
    --platform=metal
----
+
where:
+
`<installation_disk>`:: Specifies the disk on which to install {op-system}, for example, `/dev/sda` on a physical machine or `/dev/vda` on a VM. Installation overwrites the contents of this disk.
`<http_server>`:: Specifies the HTTP server and any directory path used in the Ignition URL.

. After installation completes, remove or detach the ISO media, or change the boot order so that the machine boots from the installed disk. Reboot the machine by running the following command:
+
[source,terminal]
----
$ sudo reboot
----

. Monitor the console as the machine boots from disk. It attempts to join the target cluster and generates certificate signing requests (CSRs).

.Verification

* From your workstation, verify that the new machine has generated CSRs in the target cluster by running the following command:
+
[source,terminal]
----
$ oc get csr
----
+
Continue by reviewing and approving the CSRs for the machines that you added.
