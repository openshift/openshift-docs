= Common console features

The {gitops-shortname} Console plugin provides consistent features across all GitOps resource list and details pages.

.Project selector

Use the *Project* dropdown on list pages to filter resources by namespace. Select a specific project to view resources in that namespace, or select all projects to view resources across all namespaces. A project represents an {OCP} namespace.

.YAML editor

The *YAML* tab on details pages provides a live editor for viewing and modifying resource manifests. The editor includes:

* A *Schema* side panel that documents resource fields
* A *Download* button to save the YAML file locally
* Syntax highlighting and validation

.Create resources from YAML templates

Click the *Create* button on any list page to open the YAML editor with a starter template. The template includes placeholders for common fields such as name, namespace, repository URL, and destination. Edit the YAML for your configuration, then create the resource.

The console does not provide form-based wizards for creating GitOps resources. All resource creation uses the YAML editor.

.Row actions

Each row in a resource list table includes a kebab menu with these actions:

* *Edit labels*
* *Edit annotations*
* *Edit [Resource]* to open the YAML editor
* *Delete [Resource]*

The available actions depend on your {OCP} RBAC permissions for that resource type.

.Pagination controls

List pages and details page tables support pagination. The console displays results in pages to improve usability and browser performance for large lists.

* *Page size*: Choose *10*, *20*, *50*, or *100* items per page. The default is *50*. There is no *All* option.
* *Controls*: Pagination appears above and below the table when the list contains at least one row.
* *URL state*: The current page number and page size are stored in the URL (`page` and `perPage`) so you can refresh or share the view.
* *Reset behavior*: Changing filters, search terms, or the selected project returns you to page 1. Changing the page size or sorting does not reset the page; if the list shrinks, the page is clamped to the last valid page.
* *Client-side operation*: Pagination runs in the browser on the already loaded and filtered list. It does not use Kubernetes API `limit` or `continue` tokens.

When you apply search or filters, pagination applies only to the matching resources.

.Events tab

The *Events* tab on resource details pages shows Kubernetes events for that resource object, using the standard console event stream. Events help diagnose resource state changes, controller actions, and errors.

.Favorites

You can mark Applications as favorites by using the console favorites control on the list and details pages. Favorites follow your console user settings across browser sessions.
