= TLS termination and certificate management in Gateway API

[role="_abstract"]
When configuring secure HTTPS traffic by using the Gateway API, TLS certificates and private keys are configured at the `Gateway` listener level rather than on individual `HTTPRoute` resources. The Gateway API does not automatically generate self-signed certificates for encrypted routes.

As a cluster administrator, you must create Secret resources that contain valid TLS certificate pairs and attach them to specific listeners on the `Gateway`. A developer can then attach their `HTTPRoute` resources to the designated `Gateway` and listener.

[NOTE]
====
Unlike legacy `Route` objects where developers could supply custom TLS certificates within the route spec, `HTTPRoute` objects delegate TLS configuration entirely to the parent `Gateway` object.
====

Wildcard domain listener configuration::
+
In a multi-tenant cluster environment, cluster administrators typically configure a `Gateway` with a wildcard domain listener, such as `*.example.com`. This workflow aligns with standard {product-title} `IngressController` and `Route` behavior. This means that developers can create routes under the shared domain without managing individual certificates.
+
.Example `Gateway` CR with a wildcard TLS listener
[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: wildcard-gateway
  namespace: openshift-ingress
spec:
  gatewayClassName: openshift-gateway-manager
  listeners:
  - name: https-wildcard
    hostname: "*.example.com"
    port: 443
    protocol: HTTPS
    tls:
      mode: Terminate
      certificateRefs:
      - kind: Secret
        name: wildcard-example-com-tls
    allowedRoutes:
      namespaces:
        from: All
----

.Example `HTTPRoute` CR referencing a wildcard `Gateway` listener
[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: app-route
  namespace: my-app
spec:
  parentRefs:
  - name: wildcard-gateway
    namespace: openshift-ingress
    sectionName: https-wildcard
  hostnames:
  - "app.example.com"
  rules:
  - backendRefs:
    - name: my-app-service
      port: 8080
----

Explicit non-wildcard listener configuration::
+
For dedicated services or strict hostname-matching policies, cluster administrators can configure a `Gateway` listener with an explicit, non-wildcard hostname. The attached `HTTPRoute` must specify the matching domain.
+
.Example `Gateway` CR with an explicit non-wildcard TLS listener
[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: dedicated-gateway
  namespace: openshift-ingress
spec:
  gatewayClassName: openshift-gateway-manager
  listeners:
  - name: https-api
    hostname: "api.example.com"
    port: 443
    protocol: HTTPS
    tls:
      mode: Terminate
      certificateRefs:
      - kind: Secret
        name: api-example-com-tls
    allowedRoutes:
      namespaces:
        from: Selector
        selector:
          matchLabels:
            expose-api: "true"
----
+
.Example `HTTPRoute` CR referencing an explicit hostname listener
[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: api-route
  namespace: api-service
spec:
  parentRefs:
  - name: dedicated-gateway
    namespace: openshift-ingress
    sectionName: https-api
  hostnames:
  - "api.example.com"
  rules:
  - backendRefs:
    - name: api-backend-service
      port: 8080
----
