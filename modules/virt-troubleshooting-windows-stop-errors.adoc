= Troubleshooting Windows stop errors

[role="_abstract"]
Before you investigate a Windows stop error, also known as a BSOD, on a Windows virtual machine (VM), determine whether the cause is related to the hypervisor or to the Windows guest operating system. This determination helps you contact the correct vendor for diagnosis and resolution.

{VirtProductName} supports the components used to virtualize Windows guests, including the `virtio-win` drivers and the QEMU guest agent. For issues related to the Windows operating system, its configuration, or its components, you might need to contact Microsoft support.

Use the following circumstances as a guide for which vendor to contact first. Some issues require collaboration between both vendors to resolve.

Contact Red{nbsp}Hat support first::
* The VM does not boot immediately after you migrate it from VMware to {VirtProductName}.
* The stop error occurs after you update the `virtio-win` drivers.
* The stop error occurs after you upgrade {VirtProductName} or the cluster.

Contact Microsoft support first::
* The stop error is a one-off or random occurrence with no related changes to the VM or environment.
* The VM ran without issues for an extended period before the stop error occurred.
* The stop error occurs after a configuration change or update to Windows.

Before you contact Red{nbsp}Hat support, configure the Windows guest to generate a complete memory dump, and collect the crash dump and relevant event logs. This information helps identify the stop error's root cause.
