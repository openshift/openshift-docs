= Use node selectors to control pod placement

[role="_abstract"]
You can use node selectors on pods and labels on nodes to control where the pod is scheduled. With node selectors, {product-title} schedules the pods on nodes that contain matching labels.

You add labels to a node, a compute machine set, or a machine config. Adding the label to the compute machine set ensures that if the node or machine goes down, new nodes have the label. Labels added to a node or machine config do not persist if the node or machine goes down.

To add node selectors to an existing pod, add a node selector to the controlling object for that pod, such as a `ReplicaSet` object, `DaemonSet` object, `StatefulSet` object, `Deployment` object, or `DeploymentConfig` object.
Any existing pods under that controlling object are recreated on a node with a matching label. If you are creating a new pod, you can add the node selector directly to the pod spec. If the pod does not have a controlling object, you must delete the pod, edit the pod spec, and recreate the pod.

[NOTE]
====
You cannot add a node selector directly to an existing scheduled pod.
====

.Prerequisites

To add a node selector to existing pods, determine the controlling object for that pod.
For example, the `router-default-66d5cf9464-m2g75` pod is controlled by the `router-default-66d5cf9464`
replica set:

[source,terminal]
----
$ oc describe pod router-default-66d5cf9464-7pwkc
----

The output appears similar to the following example:

[source,terminal]
----
kind: Pod
apiVersion: v1
metadata:
# ...
Name:               router-default-66d5cf9464-7pwkc
Namespace:          openshift-ingress
# ...
Controlled By:      ReplicaSet/router-default-66d5cf9464
# ...
----

The web console lists the controlling object under `ownerReferences` in the pod YAML:

[source,terminal]
----
apiVersion: v1
kind: Pod
metadata:
  name: router-default-66d5cf9464-7pwkc
# ...
  ownerReferences:
    - apiVersion: apps/v1
      kind: ReplicaSet
      name: router-default-66d5cf9464
      uid: d81dd094-da26-11e9-a48a-128e7edf0312
      controller: true
      blockOwnerDeletion: true
# ...
----

.Procedure

. [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#{empty}# Add labels to a node by using a compute machine set or editing the node directly:

* [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#{empty}# Use a `MachineSet` object to add labels to nodes managed by the compute machine set when a node is created:

.. [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#{empty}# Run the following command to add labels to a `MachineSet` object:
+
[source,terminal,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
----
$ oc patch MachineSet <name> --type='json' -p='[{"op":"add","path":"/spec/template/spec/metadata/labels", "value":{"<key>"="<value>","<key>"="<value>"}}]'  -n openshift-machine-api
----
+
[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
For example:
+
[source,terminal,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
----
$ oc patch MachineSet abc612-msrtw-worker-us-east-1c  --type='json' -p='[{"op":"add","path":"/spec/template/spec/metadata/labels", "value":{"type":"user-node","region":"east"}}]'  -n openshift-machine-api
----
+
[TIP,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
====
You can alternatively apply the following YAML to add labels to a compute machine set:

[source,yaml]
----
apiVersion: machine.openshift.io/v1beta1
kind: MachineSet
metadata:
  name: xf2bd-infra-us-east-2a
  namespace: openshift-machine-api
spec:
  template:
    spec:
      metadata:
        labels:
          region: "east"
          type: "user-node"
# ...
----
====

.. [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#{empty}# Verify that the labels are added to the `MachineSet` object by using the `oc edit` command:
+
[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
For example:
+
[source,terminal,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
----
$ oc edit MachineSet abc612-msrtw-worker-us-east-1c -n openshift-machine-api
----
+
[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
The output appears similar to the following example:
+
[source,yaml,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
----
apiVersion: machine.openshift.io/v1beta1
kind: MachineSet

# ...

# ...
  template:
    metadata:
# ...

        labels:
          region: east
          type: user-node
# ...
----

* [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#{empty}# Add labels directly to a node:

.. [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#{empty}# Edit the `Node` object for the node:
+
[source,terminal,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
----
$ oc label nodes <name> <key>=<value>
----
+
[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
For example, to label a node:
+
[source,terminal,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
----
$ oc label nodes ip-10-0-142-25.ec2.internal type=user-node region=east
----
+
[TIP,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
====
You can alternatively apply the following YAML to add labels to a node:

[source,yaml]
----
kind: Node
apiVersion: v1
metadata:
  name: hello-node-6fbccf8d9
  labels:
    type: "user-node"
    region: "east"
# ...
----
====

.. [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#{empty}# Verify that the labels are added to the node:
+
[source,terminal,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
----
$ oc get nodes -l type=user-node,region=east
----
+
[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
.Example output
[source,terminal,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
----

. [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#{empty}# Add the matching node selector to a pod:
+
* [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#{empty}# To add a node selector to existing and future pods, add a node selector to the controlling object for the pods:
+
[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
.Example `ReplicaSet` object with labels
[source,yaml,role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
----
kind: ReplicaSet
apiVersion: apps/v1
metadata:
  name: hello-node-6fbccf8d9
# ...
spec:
# ...
  template:
    metadata:
      creationTimestamp: null
      labels:
        ingresscontroller.operator.openshift.io/deployment-ingresscontroller: default
        pod-template-hash: 66d5cf9464
    spec:
      nodeSelector:
        kubernetes.io/os: linux
        node-role.kubernetes.io/worker: ''
        type: user-node
# ...
----
+
[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
where:

[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
`spec.template.spec.nodeSelector`:: Specifies the node selectors .

[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
