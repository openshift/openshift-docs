= Predefined metrics

[role="_abstract"]
When you enable a configurable metric category, you can select one or more predefined metrics to expose on the `/metrics` path of the Central API endpoint. Each predefined metric is a gauge whose value is the total number of matching items aggregated by the metric labels. For example, `rox_central_image_vuln_deployment_severity` reports the number of image vulnerabilities for each combination of cluster, namespace, deployment, platform workload status, fixability, and severity.

Predefined metric names use the following pattern, where the prefix identifies the metric category:

* `rox_central_image_vuln_<metric>` for image vulnerabilities
* `rox_central_node_vuln_<metric>` for node vulnerabilities
* `rox_central_policy_violation_<metric>` for policy violations
* `rox_central_admin_event_<metric>` for administrative events

The following tables list the predefined metrics for each category, what each metric measures, and the labels that are collected by default.

You cannot change the labels or filters of an existing metric. To use a different set of labels or filters, delete the metric and create a new one. If you use the configuration API to create a metric with a name that matches a predefined metric but with a different set of labels or filters, your custom metric hides the matching predefined metric.

.Image vulnerability metrics
[cols="3,4,3",options="header"]
|===
| Metric name | What it measures | Default labels

| `rox_central_image_vuln_namespace_severity`
| The number of image vulnerabilities in each namespace, grouped by severity and fixability.
| `Cluster`, `Namespace`, `IsPlatformWorkload`, `IsFixable`, `Severity`

| `rox_central_image_vuln_deployment_severity`
| The number of image vulnerabilities in each deployment, grouped by severity and fixability.
| `Cluster`, `Namespace`, `Deployment`, `IsPlatformWorkload`, `IsFixable`, `Severity`

| `rox_central_image_vuln_cve_severity`
| The number of image vulnerabilities for each CVE, grouped by severity and fixability.
| `Cluster`, `CVE`, `IsPlatformWorkload`, `IsFixable`, `Severity`

|===

.Node vulnerability metrics
[cols="3,4,3",options="header"]
|===
| Metric name | What it measures | Default labels

| `rox_central_node_vuln_node_severity`
| The number of node vulnerabilities on each node, grouped by severity and fixability.
| `Cluster`, `Node`, `IsFixable`, `Severity`

| `rox_central_node_vuln_component_severity`
| The number of node vulnerabilities in each node component, such as an operating system package, grouped by severity and fixability.
| `Cluster`, `Node`, `Component`, `IsFixable`, `Severity`

| `rox_central_node_vuln_cve_severity`
| The number of node vulnerabilities for each CVE, grouped by severity and fixability.
| `Cluster`, `CVE`, `IsFixable`, `Severity`

|===

.Policy violation metrics
[cols="3,4,3",options="header"]
|===
| Metric name | What it measures | Default labels

| `rox_central_policy_violation_namespace_severity`
| The number of active policy violations in each namespace, grouped by policy severity and enforcement action.
| `Cluster`, `Namespace`, `IsPlatformComponent`, `Action`, `Severity`

| `rox_central_policy_violation_deployment_severity`
| The number of active policy violations in each deployment, grouped by policy severity and enforcement action.
| `Cluster`, `Namespace`, `Deployment`, `IsPlatformComponent`, `Action`, `Severity`

|===

[NOTE]
====
The policy violation metrics count only active violations by using a default include filter of `ACTIVE` on the `State` label. The `State` label is used for filtering and is not exposed as a metric label.
====

.Administrative event metrics
[cols="3,4,3",options="header"]
|===
| Metric name | What it measures | Default labels

| `rox_central_admin_event_domain_occurrences`
| The number of administrative event occurrences in each domain, grouped by event type and level.
| `Type`, `Level`, `Domain`

| `rox_central_admin_event_resource_occurrences`
| The number of administrative event occurrences for each resource, grouped by event type, level, and domain.
| `Type`, `Level`, `Domain`, `ResourceType`, `ResourceName`

|===

Some labels use a fixed set of values. The following table lists the possible values for these labels:

.Label values
[cols="2,3,5",options="header"]
|===
| Label | Applies to | Possible values

| `Severity`
| Image and node vulnerability metrics
| `UNKNOWN_VULNERABILITY_SEVERITY`, `LOW_VULNERABILITY_SEVERITY`, `MODERATE_VULNERABILITY_SEVERITY`, `IMPORTANT_VULNERABILITY_SEVERITY`, `CRITICAL_VULNERABILITY_SEVERITY`

| `Severity`
| Policy violation metrics
| `UNSET_SEVERITY`, `LOW_SEVERITY`, `MEDIUM_SEVERITY`, `HIGH_SEVERITY`, `CRITICAL_SEVERITY`

| `Action`
| Policy violation metrics
| `UNSET_ENFORCEMENT`, `SCALE_TO_ZERO_ENFORCEMENT`, `UNSATISFIABLE_NODE_CONSTRAINT_ENFORCEMENT`, `KILL_POD_ENFORCEMENT`, `FAIL_BUILD_ENFORCEMENT`, `FAIL_KUBE_REQUEST_ENFORCEMENT`, `FAIL_DEPLOYMENT_CREATE_ENFORCEMENT`, `FAIL_DEPLOYMENT_UPDATE_ENFORCEMENT`

| `Type`
| Administrative event metrics
| `ADMINISTRATION_EVENT_TYPE_UNKNOWN`, `ADMINISTRATION_EVENT_TYPE_GENERIC`, `ADMINISTRATION_EVENT_TYPE_LOG_MESSAGE`

| `Level`
| Administrative event metrics
| `ADMINISTRATION_EVENT_LEVEL_UNKNOWN`, `ADMINISTRATION_EVENT_LEVEL_INFO`, `ADMINISTRATION_EVENT_LEVEL_SUCCESS`, `ADMINISTRATION_EVENT_LEVEL_WARNING`, `ADMINISTRATION_EVENT_LEVEL_ERROR`

| `IsFixable`, `IsPlatformWorkload`, `IsPlatformComponent`
| Metrics that include these labels
| `true`, `false`

|===

[IMPORTANT]
====
The `Severity` label uses different values for vulnerability metrics than for policy violation metrics.
====

For administrative event metrics, the `Domain` label is a free-form string. Current values include `Authentication`, `General`, `Image Scanning`, and `Integrations`. The `ResourceType` and `ResourceName` labels are also free-form strings that are derived from the event resource.

The following examples show how to query predefined metrics by using PromQL:

* To count the fixable critical image vulnerabilities in each namespace, use the following query:
+
----
sum(rox_central_image_vuln_namespace_severity{Severity="CRITICAL_VULNERABILITY_SEVERITY", IsFixable="true"}) by (Cluster, Namespace)
----

* To count the critical vulnerabilities on each node, use the following query:
+
----
sum(rox_central_node_vuln_node_severity{Severity="CRITICAL_VULNERABILITY_SEVERITY"}) by (Node)
----

* To count the active policy violations that have an enforcement action in each deployment, use the following query:
+
----
sum(rox_central_policy_violation_deployment_severity{Action!="UNSET_ENFORCEMENT"}) by (Cluster, Namespace, Deployment)
----

* To count the administrative event occurrences of each level in each domain, use the following query:
+
----
sum(rox_central_admin_event_domain_occurrences) by (Domain, Level)
----
