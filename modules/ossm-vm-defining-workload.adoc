= Defining the virtual machine workload in the mesh

[role="_abstract"]

A `WorkloadGroup` resource describes the identity, labels, and network of the virtual machines that join the mesh. It is the equivalent of a `Deployment` resource for workloads that do not run as pods. The control plane uses it to issue certificates to the proxy running on a virtual machine and to include the workload in service discovery.

The following examples use the `external-vm` namespace and a workload named `vm-app`. Substitute names that suit your environment.

.Procedure

. Create a namespace for the virtual machine workload by running the following command:
+
[source,terminal]
----
$ oc create namespace external-vm
----

. Create a service account that represents the identity of the virtual machine by running the following command:
+
[source,terminal]
----
$ oc create serviceaccount vm-app -n external-vm
----

. Create a `WorkloadGroup` resource named `workloadgroup.yaml` similar to the following example:
+
[source,yaml]
----
apiVersion: networking.istio.io/v1
kind: WorkloadGroup
metadata:
  name: vm-app
  namespace: external-vm
spec:
  metadata:
    labels:
      app: vm-app # <1>
  template:
    serviceAccount: vm-app # <2>
    network: vm-network # <3>
----
<1> The labels that identify the workload running on the virtual machine. Services and policies select the workload through these labels, in the same way that they select workloads running in pods.
<2> The service account whose identity the virtual machine assumes. The control plane issues certificates for this identity.
<3> The network that the virtual machine belongs to. This value must differ from the `spec.values.global.network` value in the `Istio` resource so that traffic between the virtual machine and in-cluster workloads passes through the east-west gateway.

. Apply the `WorkloadGroup` resource by running the following command:
+
[source,terminal]
----
$ oc apply -f workloadgroup.yaml
----

.Verification

. Verify that the workload group exists by running the following command:
+
[source,terminal]
----
$ oc get workloadgroup vm-app -n external-vm
----
