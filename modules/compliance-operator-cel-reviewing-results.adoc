= Reviewing CEL scan output

[role="_abstract"]
Monitor a CEL compliance scan and review `ComplianceCheckResult` objects to determine whether each `CustomRule` passed or failed.

.Prerequisites

* You have created a `ScanSettingBinding` object that references a CEL `TailoredProfile` object.

.Procedure

. List compliance scans in the `openshift-compliance` namespace by running the following command:
+
[source,terminal]
----
$ oc get compliancescan -n openshift-compliance
----
+
Wait until the scan `PHASE` is `DONE`.

. Review the overall scan result by running the following command:
+
[source,terminal]
----
$ oc get compliancescan <scan_name> -n openshift-compliance
----
+
The `RESULT` column shows `COMPLIANT` or `NON-COMPLIANT`.

. List `ComplianceCheckResult` objects for the scan by running the following command:
+
[source,terminal]
----
$ oc get compliancecheckresults -n openshift-compliance
----
+
Each row shows the `PASS` or `FAIL` status for a `CustomRule` expression.

. Inspect a single result, including the rule title and severity, by running the following command:
+
[source,terminal]
----
$ oc describe compliancecheckresult <result_name> -n openshift-compliance
----

. To filter results by status, run the following command:
+
[source,terminal]
----
$ oc get compliancecheckresults -n openshift-compliance \
  --field-selector status=FAIL
----

. After you fix non-compliant resources, trigger a new scan by deleting and reapplying the `ScanSettingBinding` object:
+
[source,terminal]
----
$ oc delete scansettingbinding custom-cel-scan -n openshift-compliance
$ oc apply -f scan-setting-binding.yaml
----

.Verification

* Confirm that `ComplianceCheckResult` objects exist for each `CustomRule` enabled in the tailored profile.
* Confirm that updated resources produce `PASS` results after you rerun the scan.
