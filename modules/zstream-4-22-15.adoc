== Fixed issues

* Before this update, in {aws-first}, the installation program created a security group rule that applied to cluster nodes and allowed ports 6441 and 6442. However, these ports are not needed or used anywhere. With this update, this security group rule is removed.(link:https://redhat.atlassian.net/browse/OCPBUGS-95072[OCPBUGS-95072])

* Before this update, the `AWSMachine` controller was requeuing machine instances before confirming the presence of tags. As a consequence, duplicate {aws-first} EC2 instances were created. With this release, the `AWSMachine` controller verifies tags before requeuing instances. As a result, duplicate EC2 instances are not created. (link:https://redhat.atlassian.net/browse/OCPBUGS-112305[OCPBUGS-112305])

* Before this update, the Machine Config Operator (MCO) boot image controller on vSphere incorrectly joined the failure domain network path onto the compute cluster inventory path using the `path.Join` parameter. When the network was specified as an absolute path, for example, `<datacenter>/network/<portgroup>`, the `path.Join` parameter concatenated the two paths, which created a doubled, invalid inventory path. As a consequence, when a `MachineSet` workspace matched a failure domain, the boot image controller failed to resolve the network, which caused a `failed to find network` error and degraded the MCO. With this update, the network name is passed directly to the vSphere finder library without manually constructing the path. The finder handles all network identifier formats, for example, absolute, relative, or UUID, natively. As a result, the boot image controller correctly resolves the vSphere failure domain networks regardless of path format, and the MCO is no longer degraded. (link:https://redhat.atlassian.net/browse/OCPBUGS-121849[OCPBUGS-121849])
