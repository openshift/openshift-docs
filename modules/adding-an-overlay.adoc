= Adding an overlay

[role="_abstract"]
Add an overlay to the `Central` or `SecuredCluster` custom resource (CR) to patch a Kubernetes resource that the CR does not expose as a parameter. You can edit the CR by using the OpenShift CLI (`oc`) or the {ocp} web console.

.Prerequisites

* You have installed the {product-title-short} Operator.
* You have administrator access to the cluster.

.Procedure

. Open the CR that you want to customize for editing by running one of the following commands:
+
--
* For Central:
+
[source,terminal]
----
$ oc edit central -n stackrox
----

* For Secured Cluster services:
+
[source,terminal]
----
$ oc edit securedcluster -n stackrox
----
--
+
Alternatively, in the {ocp} web console, go to *Operators* -> *Installed Operators*, select the {product-title-short} Operator, and then edit the CR on the *Central* or *Secured Cluster* tab.

. In the editor, add an `overlays` field under `spec` and list the patches that you want to apply. The following example injects an environment variable into the `central` deployment:
+
[source,yaml]
----
apiVersion: platform.stackrox.io/v1alpha1
kind: Central
metadata:
  name: stackrox-central-services
  namespace: stackrox
spec:
  # ...
  overlays:
  - apiVersion: apps/v1
    kind: Deployment
    name: central
    patches:
    - path: spec.template.spec.containers[name:central].env[-1]
      value: |
        name: MY_ENV_VAR
        value: value
----

. Save the changes and close the editor.
+
The Operator applies the patches to the affected Kubernetes resources and redeploys the affected components.

.Verification

. To confirm that the patch is present on the target resource, inspect that resource. For example, to list the environment variables on the `central` deployment, run the following command:
+
[source,terminal]
----
$ oc get deployment central -n stackrox -o jsonpath='{.spec.template.spec.containers[?(@.name=="central")].env}'
----

. If the overlay does not take effect as expected, check the {product-title-short} Operator logs for syntax errors or other logged issues by running the following command:
+
[source,terminal]
----
$ oc logs -n rhacs-operator deployment/rhacs-operator-controller-manager
----
