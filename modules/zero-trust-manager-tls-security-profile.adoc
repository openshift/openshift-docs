= TLS configuration for {zero-trust-full}

[role="_abstract"]
{zero-trust-full} does not include a custom resource field for the TLS version, cipher suites, or post-quantum key exchange. During a TLS 1.3 key exchange, a {spire-full} (SPIRE) server listener offers the hybrid Module-Lattice-Based Key-Encapsulation Mechanism (ML-KEM) groups `X25519MLKEM768`, `SecP256r1MLKEM768`, and `SecP384r1MLKEM1024` together with the classical groups. A peer that supports only classical groups uses a classical group. The `ZeroTrustWorkloadIdentityManager`, `SpireServer`, and `SpireAgent` custom resources (CRs) stay unchanged.

A default cluster uses the `Intermediate` profile. The `Intermediate` profile requires TLS 1.2 or later and allows TLS 1.3. A peer that supports hybrid ML-KEM negotiates a hybrid group on a default cluster.

For workload-to-workload mutual TLS, SPIRE issues the {spiffe-full} identity. The TLS implementation of each workload selects the key-exchange group.

[NOTE]
====
Hybrid ML-KEM groups are not FIPS-approved. In FIPS mode, {zero-trust-full} uses the OpenSSL backend. This backend excludes hybrid ML-KEM groups.
====
