= TLS configuration for {zero-trust-full}

[role="_abstract"]
{zero-trust-full} inherits the TLS security profile from `spec.tlsSecurityProfile` in the cluster `APIServer` custom resource (CR), `apiserver.config.openshift.io/cluster`. During a TLS 1.3 key exchange, a {spire-full} (SPIRE) server listener offers the hybrid Module-Lattice-Based Key-Encapsulation Mechanism (ML-KEM) groups `X25519MLKEM768`, `SecP256r1MLKEM768`, and `SecP384r1MLKEM1024` together with the classical groups. A peer that supports only classical groups uses a classical group.

The `Modern` profile is recommended for {zero-trust-full}. It requires a minimum TLS version of 1.3.

The `Intermediate` profile is the default. It requires a minimum TLS version of 1.2 and can still negotiate hybrid ML-KEM when the server offers a hybrid group. The server and the client agree on the highest TLS version that both support.

For workload-to-workload mutual TLS, SPIRE issues the {spiffe-full} identity. The TLS implementation of each workload selects the key-exchange group.

[NOTE]
====
Hybrid ML-KEM groups are not FIPS-approved. In FIPS mode, {zero-trust-full} uses the OpenSSL backend. This backend excludes hybrid ML-KEM groups.
====
