= TLS configuration for {zero-trust-full}

[role="_abstract"]
{zero-trust-full} inherits its Transport Layer Security (TLS) security profile from the cluster `APIServer` custom resource (CR). Set the `spec.tlsSecurityProfile` field in the `apiserver.config.openshift.io/cluster` CR.

Select the `Modern` profile for {zero-trust-full}. This profile requires a minimum TLS version of 1.3.

The `Intermediate` profile is the default. It requires a minimum TLS version of 1.2. You can still use this profile to negotiate a hybrid Module-Lattice-Based Key-Encapsulation Mechanism (ML-KEM) group when the server offers that group. The server and the client use the highest TLS version that both support.

During a TLS 1.3 key exchange, a {spiffe-full} Runtime Environment (SPIRE) server listener offers the hybrid ML-KEM groups with the classical groups. The hybrid groups are `X25519MLKEM768`, `SecP256r1MLKEM768`, and `SecP384r1MLKEM1024`. If a peer supports only classical groups, the handshake uses a classical group.

For workload-to-workload mutual TLS, SPIRE issues the SPIFFE identity. The TLS stack of each workload selects the key-exchange group.

[NOTE]
====
Because hybrid ML-KEM groups are not Federal Information Processing Standards (FIPS)-approved, {zero-trust-full} uses the OpenSSL backend in FIPS mode. The OpenSSL backend excludes the hybrid ML-KEM groups.
====
