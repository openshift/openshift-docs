= Configure notification alerts

[role="_abstract"]
Configure Argo CD notifications to send alerts about application sync status, health changes, and deployment events to Slack, email, webhooks, or other notification services.

.Prerequisites

* You have installed the {gitops-title} Operator.
* You have access to configure the Argo CD instance.
* You have credentials for your notification service (for example, Slack webhook URL or SMTP credentials).

.Procedure

. Create a secret containing notification service credentials:
+
** *For Slack:*
+
[source,terminal]
----
$ oc create secret generic argocd-notifications-secret \
  -n openshift-gitops \
  --from-literal=slack-token=<slack_webhook_url>
----
+
** *For email:*
+
[source,terminal]
----
$ oc create secret generic argocd-notifications-secret \
  -n openshift-gitops \
  --from-literal=email-username=<smtp_username> \
  --from-literal=email-password=<smtp_password>
----

. Configure notification services in a ConfigMap:
+
[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: argocd-notifications-cm
  namespace: openshift-gitops
data:
  service.slack: |
    token: $slack-token
  service.email.gmail: |
    username: $email-username
    password: $email-password
    host: smtp.gmail.com
    port: 465
----

. Apply the ConfigMap:
+
[source,terminal]
----
$ oc apply -f argocd-notifications-cm.yaml
----

. Define notification templates:
+
[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: argocd-notifications-cm
  namespace: openshift-gitops
data:
  template.app-sync-succeeded: |
    message: |
      Application {{.app.metadata.name}} sync succeeded.
      Revision: {{.app.status.sync.revision}}
    slack:
      attachments: |
        [{
          "title": "{{ .app.metadata.name}}",
          "title_link":"{{.context.argocdUrl}}/applications/{{.app.metadata.name}}",
          "color": "good",
          "fields": [
            {"title": "Sync Status", "value": "{{.app.status.sync.status}}", "short": true},
            {"title": "Repository", "value": "{{.app.spec.source.repoURL}}", "short": true}
          ]
        }]
  template.app-sync-failed: |
    message: |
      Application {{.app.metadata.name}} sync failed.
      Error: {{.app.status.operationState.message}}
    slack:
      attachments: |
        [{
          "title": "{{ .app.metadata.name}}",
          "title_link":"{{.context.argocdUrl}}/applications/{{.app.metadata.name}}",
          "color": "danger",
          "fields": [
            {"title": "Sync Status", "value": "{{.app.status.sync.status}}", "short": true},
            {"title": "Repository", "value": "{{.app.spec.source.repoURL}}", "short": true}
          ]
        }]
----

. Configure notification triggers:
+
[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: argocd-notifications-cm
  namespace: openshift-gitops
data:
  trigger.on-sync-succeeded: |
    - when: app.status.operationState.phase in ['Succeeded']
      send: [app-sync-succeeded]
  trigger.on-sync-failed: |
    - when: app.status.operationState.phase in ['Failed', 'Error']
      send: [app-sync-failed]
  trigger.on-health-degraded: |
    - when: app.status.health.status == 'Degraded'
      send: [app-health-degraded]
----

. Subscribe applications to notifications by adding annotations:
+
[source,yaml]
----
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  annotations:
    notifications.argoproj.io/subscribe.on-sync-succeeded.slack: my-channel
    notifications.argoproj.io/subscribe.on-sync-failed.slack: my-channel
spec:
  # ... application spec
----

. Apply the application with notification annotations:
+
[source,terminal]
----
$ oc apply -f application.yaml
----

.Verification

. Trigger a sync operation on the application.
. Check your notification service (Slack channel or email inbox) for the notification message.
. Review notification controller logs for troubleshooting:
+
[source,terminal]
----
$ oc logs -n openshift-gitops deployment/openshift-gitops-notifications-controller
----

[TIP]
====
Configure notifications at the AppProject level to apply them to all applications in the project automatically. This reduces the need to annotate individual applications.
====
