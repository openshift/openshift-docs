= Template reuse strategies

[role="_abstract"]
Every `ClusterTemplate` CR defines base hardware requirements in its `hwMgmtDefaults` section, including node groups, roles, and resource selectors that the O-Cloud Manager uses to automatically select hosts from the available pool. When you deploy the same template across multiple sites, you have three options for handling hardware variation.

Define hardware selection in the template::
Use the `hwMgmtDefaults` section of the `ClusterTemplate` CR to specify node groups and resource selectors. This is the base configuration that applies to all clusters provisioned with this template. You can use label selectors, `hardwaredata/` selectors, or both to match hosts. For details, see "Select hosts by hardware specifications" and "Define a multi-node template with distinct node groups".

Override template defaults per site::
Use this approach when deployments share the same cluster topology, {product-title} release version, and Day-2 configuration policies but differ in hardware at each site, such as server model, firmware profile, or rack location. The `ProvisioningRequest` CR supplies site-specific values in `hwMgmtParameters` that override the `ClusterTemplate` CR's `hwMgmtDefaults` at provisioning time. This avoids creating a separate template for every site. For details, see _Override hardware profiles per deployment site_.

Create a new `ClusterTemplate` CR::
Use this approach when deployments differ in cluster topology (single-node versus multi-node), node count, {product-title} release version, or Day-2 policy configuration. These structural differences require a separate template because they affect installation flow, `ConfigMap` defaults, or policy rendering beyond what hardware overrides can address.
