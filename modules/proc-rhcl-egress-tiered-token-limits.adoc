= Apply tiered token limits to egress traffic

[role="_abstract"]
Assign different artificial intelligence (AI) token budgets to different groups of workloads by combining `when` predicates with per-identity counters in a single `TokenRateLimitPolicy` custom resource (CR).

Each named limit in the policy applies only to the requests that match its predicates. A counter expression inside each limit keeps the budget of each workload separate from the budgets of the other workloads in the same tier.

.Prerequisites

include::snippets/egress-gateway-prereqs.adoc[]

include::snippets/egress-ai-service-prereqs.adoc[]

* You applied an `AuthPolicy` CR that resolves workload identity on the route of your external AI service.
* You created a second test client pod that uses a different service account, such as `team-gold` in the `egress-test` namespace.

.Procedure

. Export the egress `Gateway` object IP address by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ export EGRESS_IP=$(oc get gtw _<kuadrant_egressgateway>_ -n _<gateway_system>_ \
    -o jsonpath='{.status.addresses[0].value}')
----
+
* Replace `_<kuadrant_egressgateway>_` with the name of your egress `Gateway` object.
* Replace `_<gateway_system>_` with the namespace where your `Gateway` object is applied.

. Create a `TokenRateLimitPolicy` CR that defines one limit for each tier by using the following example:
+
[source,yaml,subs="+quotes"]
----
apiVersion: kuadrant.io/v1alpha1
kind: TokenRateLimitPolicy
metadata:
  name: _<ai_per_tier>_
  namespace: _<gateway_system>_
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: _<ai_external>_
  limits:
    default-tier:
      rates:
        - limit: 100
          window: 1m
      when:
        - predicate: auth.identity.username == 'system:serviceaccount:egress-test:default'
      counters:
        - expression: auth.identity.username
    gold-tier:
      rates:
        - limit: 500
          window: 1m
      when:
        - predicate: auth.identity.username == 'system:serviceaccount:egress-test:team-gold'
      counters:
        - expression: auth.identity.username
----
+
* Replace the `metadata.name` parameter value with the name of your `TokenRateLimitPolicy` CR that defines each tier.
* Replace the `metadata.namespace` parameter value with the namespace where your `Gateway` object is applied.
* Replace the `spec.targetRef.name` value with the name of the `HTTPRoute` object of your external AI service.
* The `default-tier` limit applies to workloads that run under the `default` service account and caps them at 100 tokens per minute.
* The `gold-tier` limit applies to workloads that run under the `team-gold` service account and caps them at 500 tokens per minute.
* Each tier keeps a separate counter for each service account. Workloads in the same tier do not share a budget.

. Apply the `TokenRateLimitPolicy` CR by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<ai_per_tier>_
----
+
Replace `_<ai_per_tier>_` with the name of your token rate limit policy YAML.

.Verification

. Count how many requests each tier accepts before the `Gateway` object rejects them by running the following command for the `test-client` pod and then for the `team-gold` pod:
+
[source,terminal,subs="+quotes"]
----
$ for i in $(seq 1 40); do
    CODE=$(oc exec _<test_client>_ -n egress-test -- sh -c '
        curl -s -o /dev/null -w "%{http_code}" \
            -H "Host: _<api.example.com>_" \
            -H "Content-Type: application/json" \
            -H "Authorization: Bearer $(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
            -X POST http://'"${EGRESS_IP}"'/v1/chat/completions \
            -d "{\"model\": \"_<model_name>_\", \"messages\": [{\"role\": \"user\", \"content\": \"Hello\"}], \"max_tokens\": 100, \"stream\": false, \"usage\": true}"
    ')
    echo "request $i: HTTP $CODE"
    [ "$CODE" = "429" ] && break
  done
----
+
* Replace `_<test_client>_` with the name of the test client pod of the tier that you are measuring.
* Replace `_<api.example.com>_` with the hostname of your external AI service.
* Replace `_<model_name>_` with a model that your external AI service provides.
* Wait for the one-minute window to pass between the two runs, so that the second tier starts from a full budget.

. Compare the two request counts. The gold tier accepts about 5 times as many requests as the default tier before it receives a `429` status code, because its limit is 500 tokens per minute rather than 100. The exact counts depend on how many tokens each response reports.
