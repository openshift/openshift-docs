= Troubleshooting DOCA Platform Framework

[role="_abstract"]
You can diagnose and resolve common issues with DPF installation, DPU provisioning, and cluster operations by checking component status, reviewing logs, and verifying resource configurations.

== DPU provisioning issues

If DPU provisioning does not start immediately after adding worker nodes to the cluster, use the following diagnostic steps.

Verify that worker CSRs are approved::
Run the following command to list the CSR status on the management cluster:
+
[source,terminal]
----
$ oc get csr
----
+
Ensure that all CSRs for the worker nodes show an `Approved,Issued` status. To approve a pending CSR, run the following command, replacing `<csr-name>` with the name of the CSR:
+
[source,terminal]
----
$ oc adm certificate approve <csr-name>
----

Verify that DPF Controller pods are running::
Run the following command to check the status of the DPF Operator pods:
+
[source,terminal]
----
$ oc get pod -n dpf-operator-system
----
+
Ensure that all `controller-manager` pods are in a `Running` state. If any pods are not running, retrieve the logs by running the following command:
+
[source,terminal]
----
$ oc logs -n dpf-operator-system deployment/dpf-operator-controller-manager
----

Verify that worker nodes are labeled for DPU by NFD::
Run the following command to confirm that the `dpu-enabled` label is present on the worker nodes:
+
[source,terminal]
----
$ oc get nodes -l feature.node.kubernetes.io/dpu-enabled=""
----
+
The output lists the worker nodes that Node Feature Discovery (NFD) has labeled for DPU provisioning. For example:
+
[source,terminal]
----
NAME                           STATUS     ROLES    AGE   VERSION
host-worker1.example.com   NotReady   worker   62s   v1.35.0
host-worker2.example.com   NotReady   worker   66s   v1.35.0
----
+
If no nodes are returned, verify that NFD is running.

Check the BFB object status::
Run the following command to verify that the BlueField Bootstream File (BFB) image is downloaded and ready:
+
[source,terminal]
----
$ oc describe bfb -n dpf-operator-system bf-bundle
----
+
Verify that the `Ready` condition is `True` and that the BFB image URL is accessible.

Check the `DPUDeployment` status::
Inspect the `DPUDeployment` object for status conditions. Run the following command to view the full status:
+
[source,terminal]
----
$ oc get dpudeployments -n dpf-operator-system dpudeployment -o yaml
----
+
Alternatively, run the following `dpfctl` command for a summarized view:
+
[source,terminal]
----
$ oc -n dpf-operator-system exec deploy/dpf-operator-controller-manager -- /dpfctl describe dpudeployments
----

== DPU object state issues

If DPU objects remain in a `DPU Cluster Config` state and do not progress, the issue is typically caused by pending CSRs in the hosted cluster.

Switch to the hosted cluster context::
Set the `KUBECONFIG` environment variable to point to the hosted cluster:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/hosted-cluster.kubeconfig
----

Check for pending CSRs::
Run the following command to list CSRs in the hosted cluster:
+
[source,terminal]
----
$ oc get csr -A
----
+
Review the output and identify any CSRs with a `Pending` status. For example:
+
[source,terminal]
----
NAME        AGE   SIGNERNAME                         REQUESTOR                  CONDITION
csr-abc12   30s   kubernetes.io/kubelet-serving      system:node:dpu-worker1    Pending
----

Approve pending CSRs::
Run the following command to approve a pending CSR, replacing `<csr-name>` with the name of the CSR:
+
[source,terminal]
----
$ oc adm certificate approve <csr-name>
----
+
[NOTE]
====
The DPF HCP Provisioner includes automatic CSR approval. If CSRs remain in a `Pending` state, verify that the provisioner is running correctly.
====

Verify that DPU workers join the hosted cluster::
Run the following command to confirm that DPU worker nodes appear in the hosted cluster:
+
[source,terminal]
----
$ oc get nodes
----

Return to the management cluster context::
Set the `KUBECONFIG` environment variable to point to the management cluster:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/management-cluster.kubeconfig
----

== Management cluster node readiness issues

If management cluster nodes do not become `Ready` after DPU provisioning, the issue is typically caused by an OVN-Kubernetes CNI configuration problem.

Verify the management cluster context::
Set the `KUBECONFIG` environment variable to point to the management cluster:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/management-cluster.kubeconfig
----

Check OVN-Kubernetes pods on the management cluster::
Run the following command to verify that OVN-Kubernetes pods are running on the management cluster:
+
[source,terminal]
----
$ oc get pods -n openshift-ovn-kubernetes -o wide
----
+
Ensure that all `ovnkube` pods are in a `Running` state.

Check OVN-Kubernetes pods on the hosted cluster::
Switch to the hosted cluster context and run the following command to verify that OVN-Kubernetes pods are running on the DPU ARM cores:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/hosted-cluster.kubeconfig
----
+
[source,terminal]
----
$ oc get pods -n openshift-ovn-kubernetes -o wide
----
+
If OVN-Kubernetes pods are not starting on the hosted cluster, investigate the following common causes:
+
--
* MTU misconfigurations: verify that the `OVN_MTU` value matches your environment.
* Network connectivity: DPUs must be able to communicate with the management control plane.
* Resource constraints: verify that DPUs have sufficient resources to run the required pods.
--

Check OVN-Kubernetes logs::
Run the following command to retrieve logs from an OVN-Kubernetes pod, replacing `<pod-name>` with the pod name:
+
[source,terminal]
----
$ oc logs -n openshift-ovn-kubernetes <pod-name>
----

== Common diagnostic commands

Use the following commands to gather diagnostic information about DPF components.

*List all DPF resources in the operator namespace*

[source,terminal]
----
$ oc get dpudeployment,dpuservicetemplate,dpuserviceconfiguration,bfb -n dpf-operator-system
----

*List nodes with DPU labels*

[source,terminal]
----
$ oc get nodes -o custom-columns=NAME:.metadata.name,LABELS:.metadata.labels | grep dpu
----

*Retrieve DPF Operator logs*

[source,terminal]
----
$ oc logs -n dpf-operator-system -l app.kubernetes.io/name=dpf-operator --tail=100
----

*Retrieve DPF HCP Provisioner Operator logs*

[source,terminal]
----
$ oc logs -n dpf-operator-system -l app.kubernetes.io/name=dpfhcp-provisioner-operator --tail=100
----

*Check node conditions*

[source,terminal]
----
$ oc describe node <node-name> | grep -A 10 "Conditions:"
----
