= Single-cluster application delivery

[role="_abstract"]
Single-cluster application delivery uses GitOps to automate application deployments to a single {OCP} cluster. This is the most common starting point for teams adopting GitOps practices.

In this scenario, you store application manifests in a Git repository and configure Argo CD to monitor that repository. When you commit changes to the repository, Argo CD detects the changes and synchronizes the application state on the cluster to match the desired state in Git.

This approach provides several benefits:

* *Version control* - All application configurations are versioned in Git, providing a complete audit trail of changes.
* *Automated deployments* - Commits to the Git repository trigger automatic deployments without manual intervention.
* *Consistency* - The cluster state always matches the configuration in Git, preventing configuration drift.
* *Easy rollbacks* - You can revert to any previous version by reverting the Git commit.

Single-cluster deployment is ideal for development and testing environments, proof-of-concept projects, and teams new to GitOps. Once you master single-cluster workflows, you can expand to multi-cluster deployments.

*Example workflow:*

. Developer commits application manifests to a Git repository
. Argo CD detects the change and compares it with the current cluster state
. Argo CD synchronizes the application to match the Git repository
. The application deploys or updates on the cluster automatically
