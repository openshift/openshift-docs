= Deploy a service across multiple clusters

[role="_abstract"]
After you configure C2CC between clusters, you can deploy an application on one cluster and access it from a client pod on a different cluster by using cross-cluster DNS.

Use the two-cluster setup from the configuration procedure. Use the `cluster-a.remote` domain for Host A and use the `cluster-b.remote` domain for Host B.

Cluster-to-cluster communication (C2CC) for {microshift-short} is a Technology Preview feature only.

include::snippets/technology-preview.adoc[leveloffset=+1]

.Prerequisites

* C2CC is configured and verified between the clusters. Each `RemoteCluster` resource reports `status.state: Healthy`.
* You installed the `oc` CLI on each cluster.
* You have access to both clusters.

.Procedure

. On **Host B**, deploy a sample application and expose it as a Service by running the following commands:
+
[source,terminal]
----
$ oc create namespace demo
$ oc -n demo create deployment hello --image=registry.access.redhat.com/ubi9/httpd-24
$ oc -n demo expose deployment hello --port=8080
----

. On **Host A**, deploy a client pod by running the following command:
+
[source,terminal]
----
$ oc run curl-client --image=registry.access.redhat.com/ubi9/ubi-minimal --restart=Never -- sleep infinity
----

. From the client pod on Host A, resolve and reach the Service on Host B by using cross-cluster DNS:
+
[source,terminal]
----
$ oc exec curl-client -- curl -s http://hello.demo.svc.cluster-b.remote:8080
----
+
The DNS name format is `<_service_>.<_namespace_>.svc.<_domain_>`, where `<_domain_>` is the `domain` value configured for the remote cluster.

. Verify pod-to-pod connectivity by resolving a headless Service or using the remote pod IP directly by running the following command:
+
[source,terminal]
----
$ oc exec curl-client -- curl -s http://<_remote-pod-ip_>:8080
----

.Verification

* The client pod on Host A successfully connects to the Service on Host B.
* Cross-cluster DNS resolves `hello.demo.svc.cluster-b.remote` to the remote service IP.
+
[NOTE]
====
C2CC does not create `NetworkPolicy` resources. Namespaces with default-deny ingress must explicitly allow the remote pod classless inter-domain routings (CIDRs). `ipBlock` selectors work because original pod source IPs are preserved.
====
