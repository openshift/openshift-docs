= Metric label values on an egress gateway

[role="_abstract"]
The metrics of an egress `Gateway` object carry the same labels as the metrics of a gateway that handles incoming traffic. Several labels hold different values, because the destination is outside the cluster.

.Label values on egress metrics
[cols="1,1,2",options="header"]
|===
| Label | Value on egress | Description

| `destination_service`
| External hostname, such as `api.example.com`
| Taken from the `ServiceEntry` object

| `destination_service_name`
| External hostname, such as `api.example.com`
| The same as `destination_service`

| `destination_service_namespace`
| Namespace of the egress `Gateway` object
| Namespace that holds the `ServiceEntry` object

| `destination_workload`
| `unknown`
| External services have no workload identity in the cluster

| `source_workload`
| Name of the egress gateway deployment
| The egress `Gateway` object, not the workload that sent the request

| `source_workload_namespace`
| Namespace of the egress `Gateway` object
| Namespace that holds the egress gateway deployment

| `reporter`
| `source`
| Always `source`, because no proxy exists on the destination side

| `response_code`
| HTTP status code
| Same meaning as on incoming traffic

| `response_flags`
| Envoy response flags
| Primary signal for diagnosing egress failures

| `connection_security_policy`
| `unknown`
| Describes the connection from the workload to the gateway
|===
