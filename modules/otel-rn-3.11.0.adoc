= Release notes for the {otel} 3.11.0

[role="_abstract"]
The {otel} 3.11.0 is available through the link:https://catalog.redhat.com/software/containers/rhosdt/opentelemetry-operator-bundle/615618406feffc5384e84400[{OTelOperator} 0.???.0] and is based on the open source link:https://opentelemetry.io/docs/collector/[OpenTelemetry] release 0.???.0.

The {otel} 3.11.0 release adds these features and enhancements:

High availability for the Operator webhooks::
This update introduces high availability support for the {OTelOperator} webhooks. The webhooks run in a separate deployment from the main Operator deployment.

The {otel} 3.11.0 release adds these Technology Preview features:

OBI Receiver (Technology Preview)::
The OpenTelemetry eBPF Instrumentation (OBI) Receiver captures zero-code network and kernel-level telemetry from Kubernetes workloads. It does this without modifying application source code or container images by running as a daemon set alongside the Collector. This receiver is a Technology Preview feature.

Prometheus Remote Write Receiver (Technology Preview)::
The Prometheus Remote Write Receiver accepts Prometheus remote write requests and converts them to OpenTelemetry metrics. This receiver is a Technology Preview feature.
+
link:https://redhat.atlassian.net/browse/TRACING-6500[TRACING-6500]

Redaction Processor (Technology Preview)::
The Redaction Processor removes sensitive data from telemetry data before it is exported. This processor is a Technology Preview feature.
+
link:https://redhat.atlassian.net/browse/TRACING-6502[TRACING-6502]

Headers Setter Extension (Technology Preview)::
The Headers Setter Extension sets headers on outgoing HTTP requests made by exporters. This extension is a Technology Preview feature.
+
link:https://redhat.atlassian.net/browse/TRACING-6504[TRACING-6504]

Kubernetes Leader Elector Extension (Technology Preview)::
The Kubernetes Leader Elector Extension enables high availability for Collector components that must run as singletons in a Kubernetes cluster. This extension uses Kubernetes Lease objects to elect a single active leader among multiple Collector replicas. All other replicas remain on standby and automatically promote to leader if the current leader becomes unavailable. This extension supports metrics and logs. This extension is a Technology Preview feature.
+
link:https://redhat.atlassian.net/browse/TRACING-6478[TRACING-6478]

The {otel} 3.11.0 release fixes these issues:

`Instrumentation` CR status fields are updated automatically::
Previously, when creating or updating an `Instrumentation` custom resource (CR), the `.status.observedGeneration` and `.status.conditions` fields were not updated because the {OTelOperator} lacked a reconciliation controller for `Instrumentation` CRs. In this release, the Operator continuously reconciles `Instrumentation` CRs and populates these status fields upon creation or update without requiring an Operator restart.
+
link:https://issues.redhat.com/browse/TRACING-6412[TRACING-6412]

Automatic RBAC of the Operator includes `PersistentVolume` and `PersistentVolumeClaim` resources::
Before this update, the automatic Role-Based Access Control (RBAC) feature of the {OTelOperator} did not include the required permissions for `PersistentVolume` and `PersistentVolumeClaim` resources. As a consequence, the Kubernetes Cluster Receiver failed with RBAC errors. With this update, the Operator automatically grants the required permissions for these resources. As a result, the Kubernetes Cluster Receiver works correctly with the automatic RBAC feature.
+
link:https://redhat.atlassian.net/browse/TRACING-6381[TRACING-6381]
