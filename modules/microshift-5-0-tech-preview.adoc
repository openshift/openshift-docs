= Technology Preview features

[role="_abstract"]
Some features in this release are currently in Technology Preview. These experimental features are not intended for production use. Note the following scope of support on the Red{nbsp}Hat Customer Portal for these features:

link:https://access.redhat.com/support/offerings/techpreview[Technology Preview Features Support Scope]

[id="microshift-5-0-trust-manager-tp_{context}"]
== Support for the trust-manager operand

With this release, you can use the trust-manager operand with cert-manager on {microshift-short} as a Technology Preview feature. The operand distributes certificate authority (CA) certificates across the node so that edge applications can verify TLS connections to local host hardware endpoints. You can consolidate certificates from multiple sources into a synchronized trust bundle and automatically update target objects when source certificates change. 

[id="microshift-5-0-c2cc-tp_{context}"]
== Cluster-to-cluster communication on L3

With this release, you can enable cluster-to-cluster communication (C2CC) on {microshift-short} as a Technology Preview feature. C2CC provides direct pod-to-pod and pod-to-service communication between independent {microshift-short} clusters over Layer 3 (L3) networks. You enable the feature in the {microshift-short} configuration file by adding remote cluster entries; no separate interconnect service is required. Cross-cluster traffic is routed over IP with no tunnel or encryption by default. You can use host-level IPsec when you need encrypted communication.
