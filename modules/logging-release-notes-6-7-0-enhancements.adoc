= New features and enhancements

[role="_abstract"]
This section describes new features and enhancements in {LoggingProductName} 6.7.0.

*Log collection*

* With this release, {LoggingProductName} components apply the cluster-wide TLS profile to their endpoints, ensuring consistent TLS configuration when `tlsAdherence` is set to `strict`. The {clo} metrics endpoint now uses the cluster TLS profile, including cipher suites, minimum TLS version, and curve groups. The operator also watches for TLS profile changes and restarts automatically to apply updated settings. The `LogFileMetricExporter` applies the same TLS profile to its metrics endpoint. (https://issues.redhat.com/browse/LOG-8944[LOG-8944])

* With this release, the `ClusterLogForwarder` Elasticsearch output supports a list of endpoints. You can configure multiple endpoints for failover and load balancing when forwarding logs to Elasticsearch. (https://issues.redhat.com/browse/OBSDA-1368[OBSDA-1368])

*Log storage*

* With this release, the Loki Operator validates private VPC endpoint URLs for {aws-short} S3 storage. You can configure a VPC endpoint URL in the format `\https://bucket.vpce-id.s3.region.vpce.amazonaws.com` to enable secure, private access to S3 buckets without routing traffic over the public internet. (https://issues.redhat.com/browse/RFE-8590[RFE-8590])

* With this release, the Loki Operator certificate rotation behavior aligns with OpenShift cluster-wide certificate expiration alert thresholds. Certificates are now rotated when 35 days of validity remain, ensuring rotation occurs before OpenShift generates alerts for certificates with fewer than 30 days until expiration. (https://issues.redhat.com/browse/RFE-8485[RFE-8485])

* With this release, the Loki Operator upgrades to Loki 4.0, which removes the BoltDB storage backend. `LokiStack` resources that reference BoltDB-based schemas (v11 or v12) are not reconciled by the {loki-op} after you upgrade to {LoggingProductName} 6.7. You must complete the TSDB schema (v13) migration before upgrading to avoid a degraded `LokiStack`. (https://issues.redhat.com/browse/LOG-9510[LOG-9510])

* With this release, the `spec.storage.schemas` field is required in the v1 `LokiStack` API. You must explicitly configure this field in your `LokiStack` resources. (https://issues.redhat.com/browse/LOG-9351[LOG-9351])

* With this release, the `LokiStorageSlowWrite` and `LokiStorageSlowRead` Prometheus alerts have been removed. These alerts relied on BoltDB Shipper metrics that no longer exist in Loki 4.0. (https://issues.redhat.com/browse/LOG-9666[LOG-9666])

*Observability*

* With this release, you can deploy the logging stack by using the {coo-full} `ObservabilityInstaller` custom resource definition (CRD). This provides a unified installation experience for the logging stack alongside other observability components. (https://issues.redhat.com/browse/OBSDA-1364[OBSDA-1364])
