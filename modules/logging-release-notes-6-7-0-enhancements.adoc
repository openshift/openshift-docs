= New features and enhancements

[role="_abstract"]
{LoggingProductName} 6.7.0 includes enhancements to log collection TLS configuration, Elasticsearch output failover, Loki Operator VPC endpoint validation, certificate rotation alignment, and observability stack installation.

*Log collection*

* With this release, {LoggingProductName} components apply the cluster-wide TLS profile to their endpoints, ensuring consistent TLS configuration when `tlsAdherence` is set to `strict`. The {clo} metrics endpoint uses the cluster TLS profile, including cipher suites, minimum TLS version, and curve groups. The {clo} also watches for TLS profile changes and restarts automatically to apply updated settings. The `LogFileMetricExporter` applies the same TLS profile to its metrics endpoint.
+
https://issues.redhat.com/browse/LOG-8944[LOG-8944]

* With this release, the `ClusterLogForwarder` Elasticsearch output supports a list of endpoints. You can configure multiple endpoints for failover and load balancing when forwarding logs to Elasticsearch.
+
https://issues.redhat.com/browse/OBSDA-1368[OBSDA-1368]

*Log storage*

* With this release, the Loki Operator validates virtual private cloud (VPC) endpoint URLs for {aws-short} S3 storage. You can configure a VPC endpoint URL in the format `\https://bucket.vpce-id.s3.region.vpce.amazonaws.com` to enable secure, private access to S3 buckets without routing traffic over the public internet.
+
https://issues.redhat.com/browse/RFE-8590[RFE-8590]

* With this release, the Loki Operator certificate rotation behavior aligns with OpenShift cluster-wide certificate expiration alert thresholds. Certificates are rotated when 35 days of validity remain, ensuring rotation occurs before OpenShift generates alerts for certificates with fewer than 30 days of validity remaining.
+
https://issues.redhat.com/browse/RFE-8485[RFE-8485]

* With this release, the Loki Operator prepares for Loki 4.0 compatibility by removing support for the BoltDB storage backend. `LokiStack` resources that reference BoltDB-based schemas (v11 or v12) are not reconciled by the {loki-op} after you upgrade to {LoggingProductName} 6.7. For upgrade requirements, see xref:logging-release-notes-6-7-0-upgrade-notes_{context}[Required actions before upgrading].
+
https://issues.redhat.com/browse/LOG-9510[LOG-9510]

*Observability*

* With this release, you can deploy the logging stack by using the {coo-full} `ObservabilityInstaller` custom resource definition (CRD). This provides a unified installation experience for the logging stack alongside other observability components.
+
https://issues.redhat.com/browse/OBSDA-1364[OBSDA-1364]
