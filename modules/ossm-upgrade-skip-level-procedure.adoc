= Upgrade your mesh with the skip-version method

[role="_abstract"]
Upgrade {SMProductShortName} from version n-2 to version n by updating the Operator subscription channel, the {istio} control plane, workloads, and the `IstioCNI` resource.

.Prerequisites

* You meet all the requirements detailed in "Prerequisites for a skip-version upgrade".

.Procedure

. Update the {SMProductName} Operator subscription to the target version channel.

.. In the {ocp-product-title} web console, navigate to *Operators* > *Installed Operators*.

.. Click the {SMProductName} Operator.

.. Click the *Subscription* tab.

.. In the *Update channel* field, select the target version channel.
For example, to upgrade from version 3.3 to version 3.5, select `stable-3.5`.

.. If the approval strategy is set to `Manual`, navigate to *Operators* -> *Installed Operators* -> *{SMProductName}* -> *Subscription* -> *Upgrade Status* and approve the install plan.

.. Verify that the operator upgrade completed successfully by running the following command:
+
[source,terminal]
----
$ oc get csv -n openshift-operators | grep sail
----
+
The output should show the new operator version in the `PHASE` column:
+
[source,terminal]
----
NAME                     DISPLAY                        VERSION   REPLACES   PHASE
sailoperator.v3.5.0      Red Hat OpenShift Service Mesh 3.5.0                Succeeded
----

. Update the {istio} control plane to the target version.

.. Edit the {istio} resource and set the `spec.version` field to the target version:
+
[source,terminal]
----
$ oc edit istio default -n istio-system
----
+
Change the `spec.version` field to the target version.
For example, to upgrade to version 3.5:
+
[source,yaml]
----
spec:
  version: v3.5-latest
----

.. Verify that both the old and new {istio} revisions are healthy by running the following command:
+
[source,terminal]
----
$ oc get istiorevision -n istio-system
----
+
The output should show both revisions with a `Healthy` status:
+
[source,terminal]
----
NAME       TYPE    READY   STATUS    IN USE   VERSION   AGE
default    Local   True    Healthy   True     v1.24.4   3d
default-v125   Local   True    Healthy   False    v1.25.0   2m
----

.. Verify that the `default` IstioRevisionTag points to the new revision by running the following command:
+
[source,terminal]
----
$ oc get istiorevisiontag default -n istio-system -o jsonpath='{.spec.targetRef.name}'
----
+
The output should show the name of the new revision:
+
[source,terminal]
----
default-v125
----

. Restart workloads to inject the new proxy version.

.. Restart all deployments in namespaces that participate in the mesh by running the following command for each namespace:
+
[source,terminal]
----
$ oc rollout restart deployment -n <namespace>
----
+
Replace `<namespace>` with the name of each namespace that has the `istio-injection=enabled` or `istio.io/rev=default` label.

.. Verify that all pods are running and using the new proxy version by running the following command:
+
[source,terminal]
----
$ istioctl version
----
+
The output should show all proxies running the new {istio} version:
+
[source,terminal]
----
client version: 1.25.0
control plane version: 1.25.0
data plane version: 1.25.0 (2 proxies)
----

. Update the IstioCNI resource to match the {istio} version.

.. Edit the IstioCNI resource and set the `spec.version` field to match the {istio} version:
+
[source,terminal]
----
$ oc edit istiocni default -n istio-cni
----
+
Change the `spec.version` field to match the {istio} version.
For example:
+
[source,yaml]
----
spec:
  version: v3.5-latest
----

.. Verify that the IstioCNI resource is ready by running the following command:
+
[source,terminal]
----
$ oc get istiocni default -n istio-cni
----
+
The output should show a `Ready` status:
+
[source,terminal]
----
NAME      TYPE    READY   STATUS    VERSION     AGE
default   Local   True    Healthy   v1.25.0     5m
----

.Verification

* Verify that your applications are functioning correctly with the new {istio} version by testing application endpoints and reviewing logs for errors.

* Monitor the mesh for any issues by using the {ocp-product-title} web console or the {SMPlugin}.
