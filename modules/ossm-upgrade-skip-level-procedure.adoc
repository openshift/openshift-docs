= Upgrade your mesh with the skip-version method

[role="_abstract"]

Upgrade {SMProductShortName} from version _n_ to version _n+2_ in a single process that requires only one workload restart.

.Prerequisites

* You meet all the requirements detailed in "Prerequisites for a skip-version upgrade".

.Procedure

. Update the {SMProductName} Operator subscription to the target version channel.

.. For example, to upgrade from Service Mesh 3.2 to 3.4, run the following command: 
+
[source,terminal]
----
$ oc patch subscription servicemeshoperator3 -n openshift-operators --type='merge' -p '{"spec":{"channel":"stable-3.4"}}'
----
+
If your subscription uses the `Manual` approval strategy, approve the resulting install plan.

.. Verify that the Operator upgrade completed successfully by running the following command:
+
[source,terminal]
----
$ oc get csv -n openshift-operators
----
+
The output shows `PHASE` as `Succeeded`:
+
[source,terminal]
----
NAME                          DISPLAY                            VERSION   REPLACES   PHASE
servicemeshoperator3.v3.4.4   Red Hat OpenShift Service Mesh 3   3.4.4                Succeeded
----

. Update the control plane to the latest version of Istio available with the new Operator.

.. Run the following command to display the Istio versions supported by the new Operator:
+
[source,terminal]
----
$ oc explain istio.spec.version
----

.. Set `spec.version` of the `Istio` resource to the latest version from the list that you generated in the previous step. The following example uses version 1.30.5:
+
[source,terminal]
----
$ oc patch istio default --type='merge' -p '{"spec":{"version":"v1.30.5"}}'
----
+
[NOTE]
====
Instead of specifying a patch version, you can use a version alias such as `v1.30-latest`, but be aware of the impact post-upgrade. When you use an alias with `RevisionBased`, the Operator creates a new revision whenever a new patch release becomes available. You must restart workloads to move to the revision.
====

.. Verify that both the old and new `Istio` revisions are healthy by running the following command:
+
[source,terminal]
----
$ oc get istiorevisions
----
+
The output must show both revisions with a `Healthy` status:
+
[source,terminal]
----
NAME              TYPE    READY   STATUS    IN USE   VERSION   AGE
default-v1-27-9   Local   True    Healthy   True     v1.27.9   35m
default-v1-30-5   Local   True    Healthy   True     v1.30.5   50s
----

.. Confirm that the `IstioRevisionTag` resource points to the new revision by running the following command:
+
[source,terminal]
----
$ oc get istiorevisiontags
----
+
The output shows the new revision:
+
[source,terminal]
----
NAME      STATUS    IN USE   REVISION          AGE
default   Healthy   True     default-v1-30-5   35m
----

. Restart workloads and gateways to inject the new proxy version and connect the proxies to the new control plane.

.. Run the following command for each namespace. This example uses the sample application bookinfo:
+
[source,terminal]
----
$ oc rollout restart deployment -n bookinfo
----

.. Confirm that the workloads are running with the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc get pods -n bookinfo
----

.. Verify that the proxies are connected to the new control plane: 
+
[source,terminal]
----
$ istioctl proxy-status
----
+
In the output, the `Version` column must show the new version for all proxies. For example:  
+
[source,terminal]
----
NAME                                       CLUSTER        CDS              LDS              EDS              RDS              ECDS        ISTIOD                                     VERSION
details-v1-766844796b-2w7hv.bookinfo       Kubernetes     SYNCED (11s)     SYNCED (11s)     SYNCED (11s)     SYNCED (11s)     IGNORED     istiod-default-v1-30-5-5c8f7d6b49-qk4zt    1.30.5
productpage-v1-54bb874995-9xnvd.bookinfo   Kubernetes     SYNCED (14s)     SYNCED (14s)     SYNCED (14s)     SYNCED (14s)     IGNORED     istiod-default-v1-30-5-5c8f7d6b49-qk4zt    1.30.5
ratings-v1-5dc79b6bcd-7jr4c.bookinfo       Kubernetes     SYNCED (13s)     SYNCED (13s)     SYNCED (13s)     SYNCED (13s)     IGNORED     istiod-default-v1-30-5-5c8f7d6b49-qk4zt    1.30.5
reviews-v1-598b896c9d-pk8mn.bookinfo       Kubernetes     SYNCED (12s)     SYNCED (12s)     SYNCED (12s)     SYNCED (12s)     IGNORED     istiod-default-v1-30-5-5c8f7d6b49-qk4zt    1.30.5

----
+
[NOTE]
====
Newer versions of istioctl might require the revision to be named explicitly when more than one control plane is running. If the output is empty or shows an incomplete list of proxies, repeat the command for each revision:

[source,terminal]
----
$ istioctl proxy-status --istioNamespace istio-system --revision default-v1-30-5
----
====

.. Confirm that no proxies use the old revision after the grace period defined by `spec.updateStrategy.inactiveRevisionDeletionGracePeriodSeconds` expires. (The default grace period is 30 seconds.) Run the command:
+
[source,terminal]
----
$ oc get istiorevisions
----
+
The output shows only the new revision:
+
[source,terminal]
----
NAME              TYPE    READY   STATUS    IN USE   VERSION   AGE
default-v1-30-5   Local   True    Healthy   True     v1.30.5   6m
----

. Update the `IstioCNI` resource.

.. Set the `spec.version` field of `IstioCNI` to match the version of the `Istio` resource. For example:
+
[source,yaml]
----
$ oc patch istiocni default -n istio-cni --type='merge' -p '{"spec":{"version":"v1.30.5"}}'
----

.. Verify that the `IstioCNI` resource is ready by running the following command:
+
[source,terminal]
----
$ oc get istiocni default
----
+
The output shows a `Ready` status:
+
[source,terminal]
----
NAME      READY   STATUS    VERSION   AGE
default   True    Healthy   v1.30.5   38m
----
