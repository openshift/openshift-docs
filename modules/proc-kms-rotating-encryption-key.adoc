= Rotating the Vault encryption key

[role="_abstract"]
You can rotate your Vault Transit encryption key to generate a new key version while maintaining access to data encrypted with earlier versions.

[WARNING]
====
After rotating the Vault encryption key, {product-title} does not automatically re-encrypt existing etcd data with the new key version. Existing data remains encrypted with the previous key version. Automatic migration to the new key version is planned for a future release. The Vault-side rotation steps documented here are safe to perform because Vault retains all previous key versions for decryption.
====

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have access to your Vault instance with permissions to rotate keys.
* {KMS} encryption is enabled and functioning.

.Procedure

. Rotate the Vault encryption key by entering the following command:
+
[source,terminal]
----
$ vault write -f transit/keys/kms-key/rotate
----
+
Replace `kms-key` with your Vault Transit key name. Vault creates a new key version while retaining earlier versions for decryption.

. Verify the new key version by entering the following command:
+
[source,terminal]
----
$ vault read transit/keys/kms-key
----
+
The `latest_version` field shows the current key version number.

.Verification

* Verify that existing secrets remain accessible by entering the following command:
+
[source,terminal]
----
$ oc get secret -A
----
+
All secrets should be readable without errors. Vault maintains all key versions and automatically uses the appropriate version for decryption.
