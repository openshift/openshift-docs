= Prerequisites for deploying federated SPIRE

[role="_abstract"]
Before deploying a federated SPIRE configuration across clusters, ensure you have the required access, software versions, and environment configuration.

== Cluster requirements

* Two or more {ocp-short-name} clusters running version 4.20 or later.
* Cluster administrator access on all clusters involved in the federation.
* Network connectivity between clusters to allow SPIRE servers to exchange federation bundles.

== Environment variables

Configure the following environment variables before beginning the deployment.
These variables are referenced throughout the federated deployment procedures.

.Environment variables for Cluster A
[cols="1,2", options="header"]
|===
|Variable
|Description

|`CLUSTER_A_KUBECONFIG`
|Path to the kubeconfig file for Cluster A

|`TRUST_DOMAIN_A`
|SPIFFE trust domain for Cluster A (for example, `cluster-a.example.com`)

|`ZTWIM_NS`
|Namespace for the Zero Trust Workload Identity Manager (typically `zero-trust-workload-identity-manager`)

|`OSSM_NS`
|Namespace for the {istio} control plane (typically `istio-system`)

|`OSSM_CNI`
|Namespace for the {istio} CNI component (typically `istio-cni`)
|===

.Environment variables for Cluster B
[cols="1,2", options="header"]
|===
|Variable
|Description

|`CLUSTER_B_KUBECONFIG`
|Path to the kubeconfig file for Cluster B

|`TRUST_DOMAIN_B`
|SPIFFE trust domain for Cluster B (for example, `cluster-b.example.com`)

|`ZTWIM_NS`
|Namespace for the Zero Trust Workload Identity Manager (typically `zero-trust-workload-identity-manager`)

|`OSSM_NS`
|Namespace for the {istio} control plane (typically `istio-system`)

|`OSSM_CNI`
|Namespace for the {istio} CNI component (typically `istio-cni`)
|===

== Additional tools for deployment

* `kubectl` or `oc` CLI configured to access both clusters
* `jq` command-line JSON processor for parsing API responses
* Helm CLI version 3.x for deploying gateway components
