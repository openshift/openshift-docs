= KMS encryption for storage buckets on Google Cloud

[role="_abstract"]
You can encrypt cluster storage buckets with customer-managed encryption keys (CMEK) by specifying a KMS key in your `install-config.yaml` file.
In {product-title} {product-version}, the `encryptionKey.kmsKey` field automatically encrypts both the bootstrap ignition bucket and the internal image registry bucket, in addition to OS disks.

On Google Cloud Dedicated sovereign cloud environments, organization policies commonly require CMEK for all storage resources.
Configuring the KMS key in the `install-config.yaml` file ensures that all installer-created storage meets this requirement without additional manual steps.

[discrete]
== How KMS bucket encryption works

When you specify a KMS key in the `defaultMachinePlatform.osDisk.encryptionKey.kmsKey` section of your `install-config.yaml` file, the installation program performs the following actions:

. Retrieves the KMS key reference from `defaultMachinePlatform.osDisk.encryptionKey.kmsKey`.
. Grants `roles/cloudkms.cryptoKeyEncrypterDecrypter` to the Cloud Storage service account, Compute Engine service account, and master node service account.
. Applies the KMS key to the bootstrap ignition storage bucket during cluster creation.
. Applies the KMS key to the internal image registry storage bucket configuration.

No additional user configuration is needed beyond specifying the KMS key fields.

[discrete]
== Required IAM permissions

To enable automatic KMS encryption of storage buckets, the installation program service account must have the following additional IAM permissions:

* `cloudkms.cryptoKeys.getIamPolicy`
* `cloudkms.cryptoKeys.setIamPolicy`

These permissions allow the installer to automatically grant encryption access to the service accounts that access the storage buckets.

[discrete]
== KMS key location

The KMS key ring location should match the cluster region.
If you do not specify a location in the `kmsKey` configuration, the installation program defaults to the cluster region.
If you do not specify a project ID for the KMS key, the installation program defaults to the cluster project ID.
The installation program validates that the KMS key ring exists but does not enforce that its location matches the cluster region.
A location mismatch might cause failures at the GCP API level or result in suboptimal performance.

[discrete]
== Optional KMS service account field

The `kmsKeyServiceAccount` field is optional.
If you do not specify a service account, the Compute Engine default service account is used for KMS operations.
The installation program automatically provisions the required IAM bindings, so you typically do not need to specify a separate service account.
