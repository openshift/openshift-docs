= Access log fields for egress traffic

[role="_abstract"]
Each access log entry of an egress `Gateway` object describes both connections of the outbound path. The first connection runs from the workload to the gateway, and the second connection runs from the gateway to the external service.

The default Envoy log format produces an entry similar to the following example:

.Example access log entry
[source,text]
----
[2026-07-07T14:33:57.697Z] "GET /get HTTP/1.1" 200 - via_upstream - "-" 0 1172 1879 1879
  "192.0.2.18" "curl/8.21.0" "4fe1434d-fd3b-4c68-92ac-c15700dfccc7" "api.example.com"
  "198.51.100.143:443" outbound|443||api.example.com 192.0.2.17:40974 192.0.2.17:80
  192.0.2.18:43722 - gateway-system.api-external.0
----

[id="rhcl-egress-access-log-fields_{context}"]
== Fields that are relevant to outbound traffic

.Access log fields for egress traffic
[cols="1,1,1,2",options="header"]
|===
| Field | Format variable | Example value | Use on egress

| Response code
| `%RESPONSE_CODE%`
| `200`
| Status that the external service returned

| Response flags
| `%RESPONSE_FLAGS%`
| `-`
| Error indicators from Envoy

| Response code details
| `%RESPONSE_CODE_DETAILS%`
| `via_upstream`
| Origin of the response

| Duration
| `%DURATION%`
| `1879`
| Total request time in milliseconds, including the external service

| Upstream service time
| `%RESP(X-ENVOY-UPSTREAM-SERVICE-TIME)%`
| `1879`
| Response time of the external service in milliseconds

| Forwarded client address
| `%REQ(X-FORWARDED-FOR)%`
| `192.0.2.18`
| Address of the calling workload

| Request ID
| `%REQ(X-REQUEST-ID)%`
| `4fe1434d-fd3b-4c68-92ac-c15700dfccc7`
| Correlates the entry with traces and other components

| Authority
| `%REQ(:AUTHORITY)%`
| `api.example.com`
| Destination hostname after the gateway rewrites it

| Upstream host
| `%UPSTREAM_HOST%`
| `198.51.100.143:443`
| Resolved address of the external service

| Upstream cluster
| `%UPSTREAM_CLUSTER_RAW%`
| See the preceding example
| Envoy cluster that the gateway routed to

| Downstream remote address
| `%DOWNSTREAM_REMOTE_ADDRESS%`
| `192.0.2.18:43722`
| Address and port of the pod that made the call

| Route name
| `%ROUTE_NAME%`
| `gateway-system.api-external.0`
| `HTTPRoute` object that matched the request
|===

[id="rhcl-egress-response-flags_{context}"]
== Response flags

Response flags show where and why a request failed. The following flags are the most relevant to outbound traffic:

.Response flags on egress traffic
[cols="1,1,2",options="header"]
|===
| Flag | Meaning | Interpretation on egress

| `-`
| No flags
| The request completed, either successfully or with an error from the external service

| `NR`
| No route found
| No `HTTPRoute` object matches the destination hostname

| `UH`
| No healthy upstream
| DNS resolution succeeded, but no healthy endpoint is available

| `UF`
| Upstream connection failure
| The gateway could not connect to the external service

| `UT`
| Upstream request timeout
| The external service did not respond within the configured timeout

| `DC`
| Downstream connection termination
| The calling workload disconnected before the response arrived

| `URX`
| Upstream retry limit exceeded
| Every retry to the external service failed

| `UPE`
| Upstream protocol error
| The protocol of the external service does not match the expected protocol
|===

The distinction between `-` and the other flags is important. A `503` status code with the `-` flag means that the external service returned the error. A `503` status code with the `UF` flag means that the gateway never reached the external service.

[id="rhcl-egress-access-log-json_{context}"]
== Fields for structured access logs

If you send access logs to a log aggregation system, configure the mesh-wide access log format to emit JSON. The following format includes the fields that are most useful for outbound traffic:

.Example JSON access log format
[source,json]
----
{
  "start_time": "%START_TIME%",
  "method": "%REQ(:METHOD)%",
  "path": "%REQ(X-ENVOY-ORIGINAL-PATH?:PATH)%",
  "protocol": "%PROTOCOL%",
  "response_code": "%RESPONSE_CODE%",
  "response_flags": "%RESPONSE_FLAGS%",
  "response_code_details": "%RESPONSE_CODE_DETAILS%",
  "bytes_received": "%BYTES_RECEIVED%",
  "bytes_sent": "%BYTES_SENT%",
  "duration": "%DURATION%",
  "upstream_service_time": "%RESP(X-ENVOY-UPSTREAM-SERVICE-TIME)%",
  "downstream_remote_address": "%DOWNSTREAM_REMOTE_ADDRESS%",
  "request_id": "%REQ(X-REQUEST-ID)%",
  "authority": "%REQ(:AUTHORITY)%",
  "upstream_host": "%UPSTREAM_HOST%",
  "upstream_cluster": "%UPSTREAM_CLUSTER_RAW%",
  "route_name": "%ROUTE_NAME%"
}
----
