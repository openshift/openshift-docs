= HTTP Add-on architecture deep dive

[role="_abstract"]
The KEDA HTTP Add-on architecture combines an interceptor proxy with the Custom Metrics Autoscaler to provide intelligent HTTP traffic-based scaling. Understanding its design helps you evaluate whether it meets your requirements compared to serverless platforms such as Knative or native Kubernetes HPA.

The KEDA HTTP Add-on uses a layered architecture where the interceptor proxy captures metrics and the scaler makes decisions based on those metrics.

When a request arrives at your application:

. The request enters the interceptor proxy, which is configured as the primary traffic receiver for your service. The interceptor records metadata about the request (concurrency, request rate, latency).

. The interceptor forwards the request to your application with minimal latency impact.

. The scaler continuously monitors the interceptor's collected metrics through an internal API.

. The scaler calculates whether the current replica count matches your configured thresholds (activation threshold during zero-replica state, or scaling thresholds for active applications).

. The scaler communicates with the Custom Metrics Autoscaler Operator, which provides metrics to the HPA through the Kubernetes metrics server.

. The HPA makes scaling decisions and instructs the API server to adjust the deployment's replica count.

. If the metric falls below the activation threshold for a configured duration, the scaler scales the deployment to zero replicas.

The HTTP Add-on consists of several interdependent components:

* **Interceptor**: A reverse proxy (typically an Envoy-based gateway) deployed as a separate pod or sidecar. Routes traffic and collects metrics without modifying your application code.

* **Scaler**: A service that polls the interceptor for metrics and translates them into scaling decisions for the Custom Metrics Autoscaler.

* **Operator**: Manages the deployment and configuration of interceptor and scaler resources based on your custom resource definitions.

* **Custom Metrics Adapter**: Part of the Custom Metrics Autoscaler Operator; exposes interceptor metrics to the Kubernetes metrics API so the HPA can consume them.

* **InterceptorRoute**: A custom resource that defines scaling configuration for a specific route (your application's traffic endpoint). Specifies activation and scaling thresholds, concurrency limits, and other behavior.

* **ScaledObject**: References an interceptor route and a deployment, linking your scaling configuration to the application being scaled.
