= Custom labels on data plane metrics

[role="_abstract"]
The `istio_*` metrics of an egress `Gateway` object cannot identify the workload that made an outbound call. A `TelemetryPolicy` custom resource (CR) closes that gap by adding labels, derived from Common Expression Language (CEL) expressions, to the metrics that the {prodname} data plane emits.

A `TelemetryPolicy` CR has no egress-specific fields. A policy that you write for an egress `Gateway` object is the same as a policy that you write for a gateway that handles incoming traffic.

[id="rhcl-egress-telemetry-labeled-metrics_{context}"]
== Metrics that carry custom labels

A `TelemetryPolicy` CR labels the Limitador counters, not the `istio_*` metrics. Adding a `TelemetryPolicy` CR leaves the `istio_*` metrics unchanged, because the two are separate metric streams.

.Metrics that carry custom labels
[cols="1,2",options="header"]
|===
| Metric | Description

| `authorized_calls`
| Requests that a rate limit check allowed

| `limited_calls`
| Requests that a rate limit check rejected

| `authorized_hits`
| Hits counted against a limit, which for a `TokenRateLimitPolicy` CR is the token consumption

| `report_calls`
| Calls to the Limitador `Report` method, which a `TokenRateLimitPolicy` CR uses to report token usage after the response
|===

Each series also carries the `limitador_namespace` label, which identifies the targeted route in the form `_<route_namespace>_/_<route_name>_`.

[id="rhcl-egress-telemetry-requirements_{context}"]
== Requirements for emitting labels

Neither of the following requirements is specific to egress, but both are often overlooked when the target is an egress `Gateway` object:

* A rate limit policy must be in effect on the route. Custom labels are attached to the descriptor that the `wasm-shim` module sends to Limitador, so a route that carries neither a `RateLimitPolicy` CR nor a `TokenRateLimitPolicy` CR produces no Limitador metrics and therefore no labels. A `TelemetryPolicy` CR that targets a gateway whose routes are not rate limited reports that it is accepted and enforced, but emits nothing.
* The `spec.targetRef` field must reference a `Gateway` object. The API rejects every other kind, so you cannot scope a `TelemetryPolicy` CR to an individual `HTTPRoute` object. The labels apply to every rate limited route on the gateway.

Labels that reference the `auth.identity.*` attributes also require an `AuthPolicy` CR that resolves workload identity on the route.
