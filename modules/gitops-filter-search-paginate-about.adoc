= About filtering, searching, and pagination in the GitOps Console

The {gitops-shortname} Console plugin provides search, filters, and client-side pagination on resource list pages. These features improve usability and browser performance for large lists.

*Search*

The search field lets you match resources by *Name* or *Label*. Search is separate from filters, so you can combine search with filters to narrow results further.

*Filters*

Available filters vary by resource type:

* *Applications*: Health status (Healthy, Progressing, Suspended, Degraded, Missing, Unknown) and sync status (Synced, OutOfSync, Unknown)
* *ApplicationSets*: Health status (Healthy, Error, Unknown)
* *AppProjects*: Description, Applications, Project Type, Source Repositories, and Destinations
* *ImageUpdaters*: Apps and Ready status
* *Rollouts*: Rollout status (Healthy, Paused, Progressing, Degraded)

You can combine multiple filters to narrow results further. Search and filters work together.

*Pagination*

Pagination keeps large result sets usable and improves browser performance. The console shows one page of rows at a time so long lists are easier to scan and the browser does not render every row at once.

Pagination is available on all {gitops-shortname} list pages (Applications, ApplicationSets, AppProjects, ImageUpdaters, and Rollouts) and on nested tables in details pages:

* The *Applications* tab on ApplicationSet and AppProject details pages
* Application details: *Resources* (list view), *Sources*, *Sync Status* (resources last synced), and *History*
* AppProject details: *Roles* and *Sync Windows*
* ImageUpdater details: *Recent Updates*
* Rollout details: *Pods*

Pagination behavior:

* *Page size*: Choose *10*, *20*, *50*, or *100* items per page. The default is *50*.
* *Controls*: Pagination appears above and below the table when the filtered list contains at least one row.
* *URL state*: The current page and page size are stored in the URL (`page` and `perPage`) so you can refresh or share the view.
* *Reset*: Changing filters, name or label search, or the selected project returns you to page 1. Changing the page size or sorting does not reset the page by itself.
* *Client-side only*: Pagination runs in the browser on the already loaded and filtered list. It does not use Kubernetes API `limit` or `continue` tokens.
