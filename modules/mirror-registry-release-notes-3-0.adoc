== Mirror registry for Red{nbsp}Hat OpenShift 3.0.0 (Technology Preview)

Issued: TBA September 2026

_Mirror registry for Red{nbsp}Hat OpenShift_ 3.0 is now available with Red{nbsp}Hat Quay TBD.

The following advisory is available for the _mirror registry for Red{nbsp}Hat OpenShift_:

* link:https://access.redhat.com/errata/RHBA-2026:TBA[RHBA-2026:TBA - mirror registry for Red{nbsp}Hat OpenShift 3.0.0]

The following new features are available with _mirror registry for Red{nbsp}Hat OpenShift_ 3.0:

* With this release, the _mirror registry for Red{nbsp}Hat OpenShift_ is distributed as a single, self-contained Go binary (`mirror-registry`) that requires no external dependencies beyond Podman. The Ansible-based installation tooling used in version 2.0.x has been removed.

* With this release, the `mirror-registry install` command performs fresh installations only. Running `install` on a host where a registry is already installed exits with an error and points to `mirror-registry upgrade`. This prevents unintended reconfiguration of a running registry.

* A new `mirror-registry upgrade` command has been added. The `upgrade` command replaces the container image of an existing installation in place while preserving the data directory, credentials, TLS certificates, hostname, and port. It exits with an error if no existing installation is found. For more information, see link:https://github.com/quay/quay/pull/7251[quay/quay#7251].

* With this release, the registry runs as a Podman container managed by systemd using a Quadlet `.container` unit file (`quay.service`). The separate `quay-app`, `quay-redis`, and `quay-pod` services used in version 2.0.x have been replaced by this single unit.

* With this release, the _mirror registry for Red{nbsp}Hat OpenShift_ uses SQLite exclusively as its internal database for new installations. PostgreSQL is supported only as a migration source from version 2.0.x. The `quay-redis` container dependency has been removed.

* A new `mirror-registry migrate` command has been added to migrate existing version 2.0.x installations to version 3.0. Both SQLite and PostgreSQL source databases are supported. The command auto-detects the existing installation and copies all data, certificates, and credentials to the new data directory. For PostgreSQL sources, the migration converts the database to SQLite before deploying the new registry.

* With this release, the _mirror registry for Red{nbsp}Hat OpenShift_ installs only on the local host. Remote host installation, which previously required SSH keys and the `--targetHostname` flag, is no longer supported.

* With this release, repositories are created automatically on the first image push. Manual repository creation through the {quay} web console, which was required in version 2.0.x, is no longer necessary. The web console and {quay} UI have been removed from the _mirror registry for Red{nbsp}Hat OpenShift_; all management is performed through the CLI or the registry API.

* All registry data, including the SQLite database, TLS certificates, credentials, and image blob storage, is stored under a single configurable data directory (default: `/var/lib/quay`). The separate Podman volumes (`quay-storage`, `sqlite-storage`) used in version 2.0.x are no longer used for new installations.
