= Gang scheduling for workloads

[role="_abstract"]
Configure gang scheduling when you want _all-or-nothing_ admission for a group, or gang, of pods that must run together. Gang scheduling can improve resource use, help resolve deadlocks, and reduce costs.

A deadlock can occur when workloads compete for limited resources and not all required pods can reach a ready state. Pods from each workload might start and hold some resources. The remaining pods cannot start because the competing workloads hold the resources they need.

For example, a distributed training job can require several GPU workers to exchange data. If some workers cannot start, the running workers can hold GPUs while waiting. The readiness timeout limits how long they hold those GPUs.
