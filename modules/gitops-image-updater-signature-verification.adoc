= Container image signature verification

[role="_abstract"]
You can configure the Argo CD Image Updater controller to verify cosign-based image signatures before updating container images. When signature verification is enabled, the controller updates an image only if its candidate image has a valid cryptographic signature from the configured public key. The controller skips images that fail verification and logs an error. Other images in the same ImageUpdater CR continue to be processed normally.

The controller first attempts to locate signatures through the OCI Referrers API, which is part of the OCI Distribution Spec v1.1 and uses the sigstore bundle format. If the registry does not support the Referrers API, the controller automatically uses the tag-based signature storage supported by older cosign versions. It first checks the `sha256-<digest>` tag, which is used by cosign 3.x, and then the `sha256-<digest>.sig` tag, which is used by cosign 2.5.x and earlier.

You can configure the `imagesVerification` field at the following levels, from least specific to most specific:

* *Global* (`spec.imagesVerification`): Applies to all images in the CR unless overridden.
* *Application group* (`spec.applicationRefs[].imagesVerification`): Applies to all images in a specific `applicationRef` entry unless overridden.
* *Per-image* (`spec.applicationRefs[].images[].imagesVerification`): Applies to a single image and takes precedence over the global and application-group settings.

When you use annotation-based image configuration (`useAnnotations: true`), the global `spec.imagesVerification` field is not used. You must configure verification at the `applicationRef` level.

[NOTE]
====
Only cosign key-based verification is supported. Keyless verification through Fulcio and OIDC is not supported in the GitOps 1.22 release.
====
