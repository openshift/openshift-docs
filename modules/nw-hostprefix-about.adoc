= About increasing the cluster network hostPrefix

[role="_abstract"]
By changing `hostPrefix` to a smaller prefix length, you can allocate a larger per-node pod subnet from the same cluster network classless inter-domain routing (CIDR).

Changing the `hostPrefix` value removes pod IP address exhaustion as a bottleneck for some workloads; however, it does not guarantee a higher supported pod density per node.

[IMPORTANT]
====
* This operation supports increasing the per-node subnet size only. Decreasing the per-node subnet size is not supported.

* This operation applies to the cluster network only. Changing the service network is not supported as part of this workflow.

* This operation requires sequential node maintenance to apply the updated per-node subnet size.
====

The `hostPrefix` value determines the subnet size assigned to each node from the `spec.clusterNetwork[].cidr` range. For example, with a cluster network CIDR of `172.28.0.0/16`, changing `hostPrefix` from `23` to `20` changes each node allocation from a `/23` subnet to a `/20` subnet. The `/20` subnet provides a larger per-node subnet than the `/23` subnet, and therefore provides more pod IP addresses per node.

By default, a `/23` per-node subnet provides 512 addresses, with approximately 510 pod IP addresses available per node. Increasing the subnet size can provide more addresses per node; however, node-level pod density remains dependent on cluster scalability limits, node resources, workload behavior, and operational constraints.
