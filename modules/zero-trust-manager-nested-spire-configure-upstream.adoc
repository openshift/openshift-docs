= Registering nested clusters

[role="_abstract"]
You register each nested cluster on the parent `SpireServer` custom resource (CR) so that the parent can attest it and sign its intermediate certificate authority (CA). Optionally, you let {zero-trust-full} publish a passthrough route for the parent gRPC endpoint. That route lets nested clusters reach the {spiffe-full} Runtime Environment (SPIRE) server.

The route host is `grpc.<cluster_name>.<trust_domain>`. The parent `ZeroTrustWorkloadIdentityManager` CR provides `<cluster_name>` and `<trust_domain>`. Nested servers use the host as `spec.upstreamAuthority.spire.serverAddress`.

.Prerequisites

* You are logged in to the parent cluster with the `cluster-admin` role.
* You created a `kubeconfig` secret named `nested-spire-<cluster_name>-kubeconfig` in the Operator namespace for each nested cluster.
* You set each nested cluster name to a DNS subdomain that differs from the parent `spec.clusterName`.

.Procedure

. Export the current `SpireServer` CR by running the following command:
+
[source,terminal]
----
$ oc get spireserver cluster -o yaml > SpireServer-parent.yaml
----

. Add `spec.managedRoute` and `spec.nodeAttestor.externalK8sPSAT` to the exported file.
+
Keep the existing `spec` fields. The following example registers a nested cluster named `cluster01` and creates the route:
+
[source,yaml]
----
apiVersion: operator.openshift.io/v1alpha1
kind: SpireServer
metadata:
  name: cluster
spec:
  # ...
  managedRoute: "true"
  nodeAttestor:
    externalK8sPSAT:
      clusters:
      - name: cluster01
----
+
where:
+
`spec.managedRoute`:: Specifies whether {zero-trust-full} creates a passthrough route. The value is `"true"` or `"false"`. The default is `"false"`.
`spec.nodeAttestor.externalK8sPSAT.clusters[].name`:: Specifies `spec.clusterName` of the nested cluster.
+
[NOTE]
====
You must set `managedRoute` to `"false"` when you expose the gRPC endpoint and use passthrough TLS for the endpoint. Edge or re-encrypt termination presents the router certificate, which has no SPIFFE URI Subject Alternative Name (SAN). You must set `serverAddress` on the nested server to the hostname that clients use. Do not include a scheme, a port, or a path.
====

. Apply the updated CR by running the following command:
+
[source,terminal]
----
$ oc apply -f SpireServer-parent.yaml
----
+
Adding or removing a cluster restarts the parent SPIRE server. Nested servers that already have an intermediate CA keep issuing certificates until that CA expires.

. If you set `managedRoute` to `"true"`, publish DNS for the route host so that it resolves to the parent cluster ingress.

.Verification

. Confirm the registration condition is `DownstreamClustersValid=True Ready` by running the following command:
+
[source,terminal]
----
$ oc get spireserver cluster -o jsonpath='{range .status.conditions[*]}{.type}={.status} {.reason}{"\n"}{end}'
----
+
The `DownstreamClustersValid=True Ready` condition does not prove that SPIRE has issued a CA.

. If you set `managedRoute` to `"true"`, confirm the route value by running the following command:
+
[source,terminal]
----
$ oc get route spire-server-grpc -n zero-trust-workload-identity-manager -o jsonpath='{.spec.host}{"\n"}{.spec.tls.termination}{"\n"}'
----
+
.Example output
[source,terminal]
----
grpc.cluster-root.example.com
passthrough
----

. Record the route host. You enter it as `serverAddress` on each nested `SpireServer` CR.
