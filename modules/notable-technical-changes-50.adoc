= Notable technical changes

[role="_abstract"]
This release includes notable technical changes.

// JIRA: ROX-32329

StackRox Scanner (Scanner V2) removal::

Scanner V4 is now the default and only vulnerability scanner in {product-title-short}. The StackRox Scanner, also known as Scanner V2, has been removed in this release. This change impacts installation, upgrades, and scanning workflows.
+
Key impacts:
+
* Scanner V4 is installed by default on all new installations and upgrades.
* StackRox Scanner settings and configurations do not migrate to Scanner V4.
* Certain features available in the StackRox Scanner might not yet be implemented in Scanner V4.
* Manifest-based installations require manual cleanup of StackRox Scanner resources.
* Kubernetes node scanning now requires Scanner V4.

// JIRA: ROX-33377

Scanner V4 vulnerability data per source::

Scanner V4 now loads vulnerability data per source, providing better visibility into vulnerability data freshness and source reliability. This enables per-updater scheduling and improved error isolation.

// JIRA: ROX-34935

Red Hat VEX feed migration::

{product-title-short} now uses the new Red Hat VEX feed for vulnerability data. This provides more accurate vulnerability information for Red Hat images.

// JIRA: ROX-31457

Platform-aligned Operator for {product-title} 5.0::

Beginning with this release, {product-title-short} aligns with Red Hat {ocp}, adopting platform-aligned versioning and lifecycle policies. Previously, with a shorter {product-title-short} support lifecycle, Red Hat supported secured clusters running any version of {product-title-short} connecting to {product-title-short} Central running any version, if both versions did not reach end of life. Due to the increased support lifecycle duration now, Red Hat limits support for {product-title-short} secured clusters when the secured cluster version is too new or too old as compared to the {product-title-short} Central version.

Red{nbsp}Hat now provides clear guidance on which versions of Sensor are supported for the associated secured cluster. Sensor can diverge up to 3 major versions away from Central if all versions are not at the end of life. For example, {product-title-short} secured cluster versions compatible with {product-title-short} Central 5.0 are 4.9, 4.10, 4.11, 5.0, 5.1, 5.2, and 5.3. Note that supported versions must not be at the end of life and future version numbers (at the time of this release, 5.1, 5.2, and 5.3) might differ.

To help you plan for upgrades, the *Platform Configuration* -> *Clusters* page in the {product-title-short} portal now includes information about the compatibility between Central and a cluster. You can also generate compatibility reports by using the API directly. 

Refer to the product documentation and support matrix for more information.
