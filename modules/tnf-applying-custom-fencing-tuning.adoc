= Applying custom fencing tuning values

[role="_abstract"]
If your scenario does not match a preset, you can edit individual parameter values in the `apply-fencing-tuning.sh` script. Change only the parameters that address your observed symptom.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have the `oc` CLI tool installed.
* Both control plane nodes are in the `Ready` state and all Pacemaker resources are started.

.Procedure

. Save the `apply-fencing-tuning.sh` script to a local file.

. Open the script in a text editor and modify the values in the `DEFAULT VALUES` section at the top of the script. For example, to increase the Corosync token to 6000 ms and the etcd stop timeout to 120 seconds:
+
.Example
[source,bash]
----
COROSYNC_TOKEN=6000

ETCD_OP_STOP_TIMEOUT=120s
----
+
For valid ranges and fencing risk for each parameter, see "Fencing tuning parameter reference"

. Run the script by running the following command:
+
[source,terminal]
----
$ ./apply-fencing-tuning.sh
----

. Wait for the Machine Config Operator (MCO) to roll out the change to both control plane nodes:
+
[source,terminal]
----
$ oc get mcp master -w
----
+
Wait until `UPDATED` is `True` and `UPDATING` is `False`.

.Verification

. Verify the Corosync token value by running the following command:
+
[source,terminal]
----
$ oc debug node/<master-node> -- chroot /host pcs cluster config show | grep token
----

. Verify the resource agent timeouts for kubelet by running the following command:
+
[source,terminal]For valid ranges and fencing 
----
$ oc debug node/<master-node> -- chroot /host pcs resource config kubelet
----

. Verify the resource agent timeouts for etcd by running the following command:
+
[source,terminal]
----
$ oc debug node/<master-node> -- chroot /host pcs resource config etcd
----

. Verify the fence agent timeouts by running the following command:
+
[source,terminal]
----
$ oc debug node/<master-node> -- chroot /host pcs stonith config
----

. To change values after the initial application, edit the script with new values and run it again. The MCO detects the change and rolls out a new update.
