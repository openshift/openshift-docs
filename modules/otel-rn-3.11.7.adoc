The Red Hat build of OpenTelemetry 3.11.7 release resolves the following Common Vulnerabilities and Exposures (CVEs):

HTTP/2 trailer headers can no longer cause a denial of service through memory exhaustion::
Before this update, the HTTP/2 server implementation in the Go `net/http` package allocated memory for every field that a `Trailer` header declared. It did not count those fields against the `MaxHeaderValueCount` and `MaxHeaderBytes` limits. As a consequence, a malicious client could send a `Trailer` header that declared a large number of fields, exhaust memory, and cause a denial of service. With this update, the package limits the memory allocated for trailer fields. As a result, a malicious trailer header no longer exhausts memory.
+
link:https://access.redhat.com/security/cve/cve-2026-78659[CVE-2026-78659]

HTTP response smuggling through malformed HTTP/2 framing headers is no longer possible::
Before this update, the HTTP/2 implementation in the Go `net/http` package accepted malformed framing-related headers in responses that were forwarded to an HTTP/1 client through a reverse proxy. As a consequence, an attacker could exploit a client that does not validate responses strictly and cause HTTP response smuggling. With this update, the package rejects malformed framing headers. As a result, responses no longer contain the malformed headers and response smuggling does not occur.
+
link:https://access.redhat.com/security/cve/cve-2026-78660[CVE-2026-78660]
