= Understand multi-protocol support

[role="_abstract"]
The {mcpg} can serve both the `2025-11-25`, stateful, and `2026-07-28`, stateless, Model Context Protocol (MCP) protocol versions from a single instance.

The new stateless protocol has the following cloud-native pattern:

* Round-robin load balancing: Because any container instance can handle any incoming request, you can horizontally scale your stateless MCP servers behind a plain round-robin load balancer.
* Serverless deployment: You can now run MCP servers as serverless functions on cloud platforms because there is no need for a persistent connection.
* Transparent failover: If a container crashes, the load balancer routes the next request to a healthy peer with zero session disruption.
* No Redis sessions: Because persistency and sticky sessions are no longer needed, you can remove Redis session storage. Database writes and reads on every single call are not required.

Clients negotiate their preferred version automatically.

[id="con-mcp-gateway-multi-protocol-version-detection_{context}"]
== How version detection works

When a standard MCP client connects, the {mcpg} detects the MCP protocol version by using the following sequence:

* Client request: Sends a `server/discover` request specifying version `2026-07-28`.
* Gateway response: Returns the combined list of all supported upstream versions.
* Version match: The client connects using a version that both sides support.
* Older clients: If the client does not send a `server/discover` request, the {mcpg} falls back to the `initialize` handshake with `2025-11-25`.

[id="con-mcp-gateway-multi-protocol-tool-visibility_{context}"]
== Tool filtering by protocol version

The `tools/list` response returns only tools from the following protocol-compatible backends:

* 2026-07-28 clients: Use tools from servers that negotiated `2026-07-28`, without `meta-tools`.

* 2025-11-25 clients: Use tools from servers that negotiated `2025-11-25`, plus the `discover_tools`,`select_tools`, and `meta-tools`.

`UserSpecificList` MCP servers follow the same filtering. Per-user tools are only displayed from backends that match the client protocol version.

[NOTE]
====
When upstream MCP servers support both protocol types, the {mcpg} displays the correct set of tools based on what the connected client supports.
====
