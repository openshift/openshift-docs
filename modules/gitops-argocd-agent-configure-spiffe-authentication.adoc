= Configure SPIFFE/SPIRE authentication

Configure the principal and agent components to use SPIFFE/SPIRE authentication instead of the standard mTLS and JWT setup.

.Prerequisites

* You have a SPIRE deployment with both SPIRE server and SPIRE agent components installed and accessible from the clusters running the principal and agent.
* You have installed the SPIFFE CSI driver so that workloads can access the SPIRE Agent Workload API socket.
* SPIFFE IDs are issued to the principal and agent workloads that match the expected SVID format. For example, `spiffe://<trust_domain>/ns/<namespace>/argocd/agent/<agent_name>` for the default JWT authentication method.

.Procedure

. Configure SPIFFE authentication on the principal component by adding a `spiffe` block to the `ArgoCD` custom resource (CR):
+
[source,yaml]
----
apiVersion: argoproj.io/v1beta1
kind: ArgoCD
metadata:
  name: argocd-principal
  namespace: argocd
spec:
  argoCDAgent:
    principal:
      enabled: true
      spiffe:
        enabled: true
        authMethod: "jwt"
        csiDriverName: "csi.spiffe.io"
----
+
where:
+
`spiffe.enabled`:: Set to `true` to activate SPIFFE authentication for the principal component.
+
`spiffe.authMethod`:: Specifies the SPIFFE authentication method. Use `jwt` for JWT-SVIDs with federated SPIRE deployments, or `mtls` for X.509-SVIDs with centralized SPIRE deployments. The default value is `jwt`.
+
`spiffe.csiDriverName`:: Specifies the name of the CSI driver that mounts the SPIFFE Workload API socket. The default value is `csi.spiffe.io`.

. Configure SPIFFE authentication on the agent component by adding a `spiffe` block to the `Argo CD` CR on the workload cluster:
+
[source,yaml]
----
apiVersion: argoproj.io/v1beta1
kind: ArgoCD
metadata:
  name: argocd-agent
  namespace: agent-managed
spec:
  argoCDAgent:
    agent:
      enabled: true
      spiffe:
        enabled: true
        authMethod: "jwt"
        csiDriverName: "csi.spiffe.io"
----
+
[IMPORTANT]
====
You must enable SPIFFE on both the principal and agent components for the authentication handshake to succeed. The `authMethod` values on both sides must match because they negotiate the same SPIFFE authentication method.
====

. Optional: If your SPIRE deployment uses a different SVID format than the default pattern, set the `principal.auth` field explicitly:
+
[source,yaml]
----
apiVersion: argoproj.io/v1beta1
kind: ArgoCD
metadata:
  name: argocd-principal
  namespace: argocd
spec:
  argoCDAgent:
    principal:
      enabled: true
      auth: "spiffe-jwt:spiffe://<trust_domain>/ns/<namespace>/argocd/agent/(.+)"
      spiffe:
        enabled: true
        authMethod: "jwt"
----
+
Replace `<trust_domain>` and `<namespace>` with your actual SPIRE trust domain and namespace values.

.Verification

. Verify that your SPIFFE ID format works with the default regex pattern:
+
[source,terminal]
----
$ SPIFFE_ID="spiffe://example.org/ns/agent-managed/argocd/agent/agent-managed"
----
+
[source,terminal]
----
$ AGENT_NAME=$(echo "$SPIFFE_ID" | sed -E 's|^spiffe://[^/]+/ns/[^/]+/argocd/agent/(.+)$|\1|')
----
+
[source,terminal]
----
$ echo $AGENT_NAME
----
+
The output shows the extracted agent name. If the extraction succeeds, your SPIFFE ID format is compatible with the default pattern.

. Check the principal and agent pod logs to verify successful SPIFFE authentication:
+
[source,terminal]
----
$ oc logs -n argocd deployment/argocd-agent-principal | grep -i spiffe
----
