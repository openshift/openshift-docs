= When to use a virtualized control plane

[role="_abstract"]
You can use virtualized control planes to address infrastructure challenges where physical hardware constraints, compliance requirements, or provisioning timelines limit how you deploy and manage clusters.

Regulatory isolation::
You must meet compliance mandates that require hypervisor-level isolation for control plane components.
A virtualized control plane runs each control plane node as a separate VM, providing stronger isolation boundaries than container-based alternatives.

Infrastructure consolidation::
You want to reduce hardware costs by hosting multiple cluster control planes on shared infrastructure.
A single hosting cluster can run control plane VMs for multiple target clusters in separate namespaces, reducing the number of physical servers you need to maintain.

Faster cluster provisioning::
You need to deploy new clusters faster than physical bare-metal provisioning allows.
Provisioning control plane VMs on an existing hosting cluster reduces the lead times associated with physical hardware provisioning.

You can deploy virtualized control planes by using standard installation workflows such as Agent-based Installer or {ztp-first}.
These workflows treat the VMs the same as physical servers with baseboard management controllers (BMCs), so your existing deployment processes work without modification.
