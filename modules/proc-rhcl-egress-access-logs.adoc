= Enable access logs on an egress gateway

[role="_abstract"]
Record one log entry for each outbound request by enabling {service-mesh} access logs on the pods of your egress `Gateway` object.

A selector scopes the configuration to the pods of the egress `Gateway` object. The selector prevents a conflict with the other `Telemetry` objects in the same namespace, such as the configuration of a gateway that handles incoming traffic.

.Prerequisites

include::snippets/egress-gateway-prereqs.adoc[]

.Procedure

. Create a `Telemetry` object that enables access logs on the pods of your egress `Gateway` object by using the following example:
+
[source,yaml,subs="+quotes"]
----
apiVersion: telemetry.istio.io/v1
kind: Telemetry
metadata:
  name: _<egress_access_logs>_
  namespace: _<gateway_system>_
spec:
  selector:
    matchLabels:
      gateway.networking.k8s.io/gateway-name: _<kuadrant_egressgateway>_
  accessLogging:
    - providers:
      - name: envoy
----
+
* Replace the `metadata.namespace` value with the namespace where you applied your egress `Gateway` object.
* Replace the `spec.selector.matchLabels` value with the name of your egress `Gateway` object.

. Apply the `Telemetry` object by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<egress_access_logs>_
----
+
Replace `_<egress_access_logs>_` with the name of the file that holds your telemetry configuration.

. Optional: To reduce the volume of logs, add a filter that records only the requests that fail by using the following example:
+
[source,yaml,subs="+quotes"]
----
apiVersion: telemetry.istio.io/v1
kind: Telemetry
metadata:
  name: _<egress_access_logs>_
  namespace: _<gateway_system>_
spec:
  selector:
    matchLabels:
      gateway.networking.k8s.io/gateway-name: _<kuadrant_egressgateway>_
  accessLogging:
    - providers:
      - name: envoy
      filter:
        expression: "!has(response.code) || response.code >= 400"
----
+
The `!has(response.code)` condition also records the connection failures for which the gateway generates no HTTP status code, such as a failure to connect to the external service or a timeout.

.Verification

* Read the access logs from the pods of your egress `Gateway` object by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc logs -n _<gateway_system>_ -l gateway.networking.k8s.io/gateway-name=_<kuadrant_egressgateway>_ -f
----
+
Each outbound request produces one entry.
