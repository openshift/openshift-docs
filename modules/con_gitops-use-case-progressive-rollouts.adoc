= Progressive rollouts with zero downtime

[role="_abstract"]
Progressive rollouts use GitOps to deploy application updates gradually, minimizing risk and enabling zero-downtime deployments. {gitops-title} supports progressive delivery through Argo Rollouts, which provides advanced deployment strategies beyond standard Kubernetes rolling updates.

With progressive rollouts, you can:

* Deploy new versions to a small percentage of users first, then gradually increase traffic
* Run both old and new versions simultaneously during the rollout
* Automatically roll back if metrics indicate problems with the new version
* Perform A/B testing by routing specific user segments to different versions

Key progressive deployment strategies:

* *Canary deployments* - Deploy the new version to a small subset of users, monitor metrics, then gradually shift traffic if successful.
* *Blue-green deployments* - Deploy the new version alongside the old version, then switch all traffic at once after validation.
* *Analysis-driven rollouts* - Use metrics from Prometheus, Datadog, or other monitoring systems to automatically determine rollout success.

Progressive rollouts are critical for production environments where you need to minimize the impact of failed deployments. They enable continuous delivery with confidence, allowing you to release updates frequently while maintaining high availability.

*Example workflow:*

. Commit a new application version to Git
. Argo CD deploys the new version alongside the existing version
. Argo Rollouts gradually shifts 10% of traffic to the new version
. Analysis runs to check error rates and latency metrics
. If metrics are healthy, traffic shifts to 50%, then 100%
. If metrics degrade, the rollout automatically aborts and traffic returns to the previous version
