= Troubleshooting NIDS issues with an AI agent

[role="_abstract"]
You can use the `netedge` toolset in the MCP server for Red Hat OpenShift to diagnose Ingress and DNS issues by describing symptoms to a connected LLM client in natural language.

.Prerequisites

* You have installed the MCP server for Red Hat OpenShift and enabled the `netedge` toolset.
* You have connected an MCP-compliant client to the MCP server.

.Procedure

. In your connected client, describe the issue that you want to troubleshoot. For example, to investigate a router problem, enter a prompt similar to the following:
+
[source,terminal]
----
Why is the route for my application unreachable? Check the router configuration and active sessions.
----

. Review the tools that the LLM selects and invokes to diagnose the issue.
+
* For router or Ingress issues, the LLM might use the following tools:
+
** `get_router_config`: Retrieves the current HAProxy configuration of the router.
** `get_router_info`: Retrieves HAProxy runtime information from the router.
** `get_router_sessions`: Retrieves all active sessions from the router.
+
* For DNS resolution issues, the LLM might use the `get_coredns_config` tool to retrieve the current CoreDNS configuration.

. Review the structured output that the MCP server returns and the root-cause diagnosis that the LLM provides based on that output.

.Verification

* Confirm the diagnosis by retrieving the same resource directly. For example, to cross-check a router diagnosis, run the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-ingress
----

* To cross-check a DNS diagnosis, run the following command:
+
[source,terminal]
----
$ oc get configmap dns-default -n openshift-dns -o yaml
----
