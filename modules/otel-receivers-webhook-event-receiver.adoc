= Webhook Event Receiver

[role="_abstract"]
The Webhook Event Receiver listens for HTTP requests that a webhook sends and turns them into log records. With this receiver, you can collect events from systems that can send a webhook but cannot send OTLP data, such as CI/CD pipelines, source code platforms, and SaaS applications.

:FeatureName: The Webhook Event Receiver
include::snippets/technology-preview.adoc[]
:!FeatureName:

The receiver supports logs only. By default, it creates one log record for each request and uses the request body as the body of the log record. The receiver does not parse the request body. Use the Transform Processor to parse it.

The following `OpenTelemetryCollector` custom resource configures the Webhook Event Receiver:

[source,yaml]
----
# ...
  env:
    - name: WEBHOOK_TOKEN
      valueFrom:
        secretKeyRef:
          name: webhook-token
          key: token
  config:
    receivers:
      webhook_event:
        endpoint: 0.0.0.0:8088
        path: /events
        health_path: /health_check
        read_timeout: 500ms
        write_timeout: 500ms
        split_logs_at_newline: true
        header_attribute_regex: "^X-Custom-.*"
        required_header:
          key: X-Webhook-Token
          value: ${env:WEBHOOK_TOKEN}
    service:
      pipelines:
        logs:
          receivers: [webhook_event]
# ...
----
where:

`endpoint`:: Address and port that the receiver listens on. You must set this option, and there is no default. The Operator creates a Service port for the port of the endpoint.
`path`:: URL path that receives events. The path must start with `/`. The default is `/events`.
`health_path`:: URL path that returns the status of the receiver. A `GET` request to this path returns `200`. The path must start with `/`. The default is `/health_check`.
`read_timeout`:: Maximum time to read a request. The value can be at most `10s`. The default is `500ms`.
`write_timeout`:: Maximum time to write a response. The value can be at most `10s`. The default is `500ms`.
`split_logs_at_newline`:: If `true`, the receiver creates one log record for each line of the request body. Use this setting for bodies in the newline-delimited JSON (NDJSON) format. The default is `false`. You cannot use it together with `split_logs_at_json_boundary`.
`header_attribute_regex`:: Optional: Regular expression. The receiver adds the request headers whose names match the expression to the log record as attributes. The attribute names start with `header.`, for example `header.X-Custom-Id`.
`required_header`:: Optional: Header that every request must contain. The `key` and the `value` are both required. The receiver compares the value of the header as plain text. It rejects requests without the header or with a different value with the HTTP status code `401`. This setting does not check a signature. To check a signature, use `hmac_signature`.

The following `OpenTelemetryCollector` custom resource verifies the signature of the requests in the format that GitHub uses:

[source,yaml]
----
# ...
  env:
    - name: WEBHOOK_SECRET
      valueFrom:
        secretKeyRef:
          name: github-webhook
          key: secret
  config:
    receivers:
      webhook_event:
        endpoint: 0.0.0.0:8088
        path: /github/webhooks
        hmac_signature:
          secret: ${env:WEBHOOK_SECRET}
          header: X-Hub-Signature-256
          prefix: "sha256="
# ...
----
where:

`hmac_signature`:: Optional: Verifies the HMAC-SHA256 signature of the request body. The receiver rejects requests with a missing or invalid signature with the HTTP status code `401`. You must set `secret`, `header`, and `prefix` together.
`secret`:: Shared secret that the webhook uses to sign the requests. Store the secret in a Kubernetes secret, as the example shows, and not in the custom resource.
`header`:: Name of the request header that contains the signature.
`prefix`:: Text that comes before the hexadecimal digest in the value of the header, for example `sha256=` for GitHub.

The receiver also supports the following settings:

`split_logs_at_json_boundary`:: If `true`, the receiver parses the request body as JSON and creates one log record for each JSON object. Use this setting when the objects in the body are not separated by new lines. The default is `false`.
`max_request_body_size`:: Maximum size of a request body in bytes. The receiver rejects larger requests. If you do not set this option, the default of the HTTP server settings applies.

[WARNING]
====
If the `path` or the `health_path` does not start with `/`, or is empty, the Collector fails with a panic after it has bound the port. As a result, the Collector cannot restart cleanly. This is a known issue of the upstream receiver. Always start these paths with `/`.
====

[NOTE]
====
* The name `webhookevent` is deprecated. The receiver still accepts it and logs a deprecation warning. Use `webhook_event`.
* An HTTP endpoint that does not use TLS sends the request headers, including the secret in a `required_header`, in plain text. Send webhooks to an endpoint that is protected by TLS, for example through an OpenShift route.
====
