= Webhook Event Receiver

[role="_abstract"]
The Webhook Event Receiver listens for HTTP requests to a webhook and turns them into log records. With this receiver, you can collect events from systems that can send HTTP `POST` requests to a webhook but cannot send OpenTelemetry Protocol (OTLP) data. Examples include CI/CD pipelines, SaaS applications, and source code platforms.

:FeatureName: The Webhook Event Receiver
include::snippets/technology-preview.adoc[]
:!FeatureName:

The receiver supports only logs and accepts only `POST` requests. By default, it creates one log record for each request and fills it with the request body. The receiver does not parse the request body. Use the Transform Processor to parse it.

The following `OpenTelemetryCollector` custom resource configures the Webhook Event Receiver:

[source,yaml]
----
# ...
  env:
    - name: WEBHOOK_TOKEN
      valueFrom:
        secretKeyRef:
          name: webhook-token
          key: token
  config:
    receivers:
      webhook_event:
        endpoint: 0.0.0.0:8088
        path: /events
        health_path: /health_check
        read_timeout: 500ms
        write_timeout: 500ms
        split_logs_at_newline: true
        header_attribute_regex: "^X-Custom-.*"
        required_header:
          key: X-Webhook-Token
          value: ${env:WEBHOOK_TOKEN}
    service:
      pipelines:
        logs:
          receivers: [webhook_event]
# ...
----
where:

`endpoint`:: Address and port that the receiver listens on over HTTP. This setting is required and has no default. The Operator creates a Service port for this endpoint port. To keep the request headers from traveling in plain text, set the `tls.cert_file` and `tls.key_file` settings of the receiver, or expose the receiver through a TLS-protected route.
`path`:: URL path that receives events. The default is `/events`. The path must start with `/`.
`health_path`:: URL path that reports the health of the receiver. A `GET` request to this path returns the HTTP status code `200`. The default is `/health_check`. The path must start with `/`.
`read_timeout`:: Maximum time to read the headers of a request. The maximum value is `10s`. The default is `500ms`.
`write_timeout`:: Maximum time to write a response. The maximum value is `10s`. The default is `500ms`.
`split_logs_at_newline`:: If set to `true`, the receiver creates one log record for each line of the request body. Use this setting for bodies in the newline-delimited JSON (NDJSON) format. The default is `false`. You cannot use this setting together with `split_logs_at_json_boundary`.
`header_attribute_regex`:: Optional: A regular expression. The receiver adds the request headers whose names match the expression to the log record as attributes. The receiver matches the canonical form of the header name, for example `X-Github-Event` for the `X-GitHub-Event` header. To ignore case, start the expression with `(?i)`. The attribute names start with `header.`, for example `header.X-Custom-Id`. Do not match headers that contain credentials, such as the header that you set in `required_header`, because the receiver writes the matched values to the log records.
`required_header`:: Optional: Header that every request must contain. Both the `key` and the `value` are required. This value must be present in the header of every request, and the receiver compares it for an exact, case-sensitive match. The receiver rejects requests without the header or with a different value, and returns the HTTP status code `401`. This setting does not check a signature. To check a signature, use `hmac_signature`.

The following `OpenTelemetryCollector` custom resource verifies the signature of the requests in the format that GitHub uses:

[source,yaml]
----
# ...
  env:
    - name: WEBHOOK_SECRET
      valueFrom:
        secretKeyRef:
          name: github-webhook
          key: secret
  config:
    receivers:
      webhook_event:
        endpoint: 0.0.0.0:8088
        path: /github/webhooks
        hmac_signature:
          secret: ${env:WEBHOOK_SECRET}
          header: X-Hub-Signature-256
          prefix: "sha256="
# ...
----
where:

`endpoint`:: Address and port that the receiver listens on over HTTP. This setting is required and has no default. The Operator creates a Service port for this endpoint port. To keep the request headers from traveling in plain text, set the `tls.cert_file` and `tls.key_file` settings of the receiver, or expose the receiver through a TLS-protected route.
`path`:: URL path that receives events. The default is `/events`. The path must start with `/`.
`hmac_signature`:: Optional: Verifies the HMAC-SHA256 signature of the request body. The receiver rejects requests that have a missing or invalid signature, and returns the HTTP status code `401`. You must set `secret`, `header`, and `prefix` together.
`secret`:: Shared secret that the source system uses to sign the requests. The source system sends only the signature, not the secret, and the receiver uses the secret to verify it. Store the secret in a Kubernetes secret, as the example shows, and not in the custom resource.
`header`:: Name of the request header that contains the signature.
`prefix`:: Text that comes before the hexadecimal digest in the header value, for example `sha256=` for GitHub.

The receiver also supports the following settings:

`split_logs_at_json_boundary`:: If set to `true`, the receiver parses the request body as JSON and creates one log record for each JSON object. Use this setting when the objects in the body are not separated by newlines. The default is `false`.
`max_request_body_size`:: Maximum size of a request body in bytes. The default is `102400` (100 KiB). The receiver rejects larger requests with the HTTP status code `400`.
