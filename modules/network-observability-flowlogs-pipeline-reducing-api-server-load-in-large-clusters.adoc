= Reduce API server load in large clusters

[role="_abstract"]
To reduce Kubernetes API server load and optimize resource consumption in large clusters, enable the `flowlogs-pipeline` shared cache. The shared cache is recommended for clusters with more than 3 `flowlogs-pipeline` replicas, especially when API server load becomes a performance concern.

.Prerequisites

* The Network Observability Operator is installed.
* Access to the cluster as a user with the `cluster-admin` role.

.Procedure

. In the {product-title} web console, navigate to *Operators* → *Installed Operators*.
. Select the *Network Observability Operator*, and then click the *`FlowCollector`* tab.
. Click the `cluster` instance, and then click the *YAML* tab.
. In the `spec.processor` section, set the `informerCacheProxy` configuration to enable the shared cache:
+
[source,yaml]
----
apiVersion: flows.netobserv.io/v1beta2
kind: FlowCollector
metadata:
  name: cluster
spec:
  processor:
    informerCacheProxy:
      enabled: true
      replicas: 2
----
+
where:

`spec.processor.informerCacheProxy.enabled`:: Set to `true` to enable the informer cache proxy. The default value is `false`.
`spec.processor.informerCacheProxy.replicas`:: Specifies the number of replicas. For high availability in production environments, the minimum is `2`. The Operator enforces this requirement with leader election to prevent a single point of failure.

. Click *Save*.

.Verification

. Navigate to *Workloads* → *Pods*.
. Ensure that the pods beginning with `flowlogs-pipeline-informers` are in the *Running* state.
. Verify that one pod shows as the active leader by checking the pod logs for leader election messages.
. Confirm that the `flowlogs-pipeline` pods remain *Running* and show decreased CPU and memory use in the *Metrics* tab.
