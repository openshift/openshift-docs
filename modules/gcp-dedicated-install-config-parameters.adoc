= Google Cloud Dedicated install-config.yaml parameters

[role="_abstract"]
When you install {product-title} on Google Cloud Dedicated, several `install-config.yaml` parameters have requirements, defaults, or constraints specific to Google Cloud Dedicated.
Use this reference to configure your `install-config.yaml` file correctly for a Google Cloud Dedicated installation.

.Google Cloud Dedicated install-config.yaml fields
[cols="2,1,1,3",options="header"]
|===
|Parameter
|Required
|Default
|Description

|`platform.gcp.projectID`
|Yes
|None
|The domain-scoped project ID for your Google Cloud Dedicated project. Uses the format `<prefix>:<project-id>`, for example `eu0:my-project` for German sovereign regions.

|`platform.gcp.region`
|Yes
|None
|The sovereign region where the cluster is deployed. Only regions provisioned in the Google Cloud Dedicated universe are available. The installation program validates the region against the GCP Compute API for the sovereign project.

|`platform.gcp.defaultMachinePlatform.osImage.name`
|Yes
|None
|The name of the custom {op-system} image. On Google Cloud Dedicated, you must provide a custom {op-system} image because the standard {op-system} images hosted on public {gcp-short} are not accessible from the sovereign universe.

|`platform.gcp.defaultMachinePlatform.osImage.project`
|Yes
|None
|The project containing the custom {op-system} image. On Google Cloud Dedicated, you must specify both `name` and `project` fields for the `osImage`. The installation program rejects configurations where `osImage.name` is specified without `osImage.project`.

|`publish`
|Yes
|`External`
|Set to `Internal` on Google Cloud Dedicated. Google Cloud Dedicated infrastructure does not support public DNS zones or global load balancers, so installations with `publish: External` fail during infrastructure provisioning. The installation program does not validate this field for sovereign projects.

|`platform.gcp.defaultMachinePlatform.osDisk.encryptionKey.kmsKey`
|No
|None
|The Cloud KMS key used to encrypt operating system disks, the bootstrap ignition storage bucket, and the internal image registry storage bucket. The KMS key ring location should match the cluster region. If you do not specify a location, the installation program defaults to the cluster region.

|===

[discrete]
== Sovereign regions

The following regions are available for Google Cloud Dedicated installations.
The available regions are determined by the Google Cloud Dedicated universe infrastructure.

.Google Cloud Dedicated sovereign regions

|`europe-west4`

|Thales / Google Cloud Germany

|`u-france-east1`
|France

[NOTE]
====
Region availability depends on the Google Cloud Dedicated universe infrastructure.
Verify that your target region is accessible by confirming it appears in the GCP Compute API response for your sovereign project.
====

[discrete]
== Default values on Google Cloud Dedicated

When the installation program detects a Google Cloud Dedicated sovereign cloud environment from the domain-scoped project ID, it automatically applies the following defaults:

* **Default disk type**: `hyperdisk-balanced` (instead of `pd-ssd` on standard {gcp-short})
* **Default instance type**: Determined by the instance family. Instance types from the c3 family (such as `c3-standard-4`) default to `hyperdisk-balanced` disk types on Google Cloud Dedicated.

[discrete]
== Validation behavior

The installation program performs the following validation specific to Google Cloud Dedicated:

* **Sovereign environment detection**: The installation program detects the sovereign cloud environment from the project ID prefix. Known sovereign prefixes (such as `eu0`) trigger sovereign-specific defaults and validation.
* **Region validation**: Regions are validated dynamically by querying the GCP Compute API. Only regions provisioned in the Google Cloud Dedicated universe are returned by the API and accepted by the installation program.
* **Operating system image validation**: The `osImage.project` field is required when `osImage.name` is specified. The installation program rejects configurations where the `project` field is missing.
