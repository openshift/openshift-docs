= Configure {microshift-short} with a custom CoreDNS Corefile

[role="_abstract"]
You can replace the built-in CoreDNS configuration by placing a custom Corefile on the host and pointing the `dns.configFile` parameter to that file. {microshift-short} copies the file contents into the `dns-default` config map in the `openshift-dns` namespace.

.Prerequisites

* You installed the {oc-first}.
* You have root access to the node.
* You created a {microshift-short} `config.yaml` file in the `/etc/microshift/` directory.
* The `dns.hosts.status` parameter is not set to `Enabled`.

.Procedure

. Create the directory for the custom Corefile by running the following command:
+
[source,terminal]
----
$ sudo mkdir -p /etc/microshift/dns
----

. Create a custom Corefile. Use the following example as a starting point, then add the forwarding rules or zone stanzas that your environment requires:
+
.Example starter Corefile
[source,text]
----
.:5353 {
    bufsize 1232
    errors
    log . {
        class error
    }
    health {
        lameduck 20s
    }
    ready
    kubernetes cluster.local in-addr.arpa ip6.arpa {
        pods insecure
        fallthrough in-addr.arpa ip6.arpa
    }
    prometheus 127.0.0.1:9153
    forward . /etc/resolv.conf {
        policy sequential
    }
    cache 900 {
        denial 9984 30
    }
    reload
}
hostname.bind:5353 {
    chaos
}
----
+
Save the file as `/etc/microshift/dns/Corefile`.
+
[IMPORTANT]
====
Keep the `reload` plugin in the custom Corefile so that CoreDNS applies config map updates. An invalid Corefile can break DNS resolution or cause {microshift-short} to fail to start.
====

. Optional: To forward queries to a specific upstream resolver, replace the `forward` stanza in the Corefile with values for your environment:
+
.Example custom forwarding stanza
[source,text]
----
    forward . 192.0.2.53 {
        policy sequential
    }
----

. Edit the `/etc/microshift/config.yaml` file and set the `dns.configFile` parameter to the absolute path of the custom Corefile:
+
.Example custom Corefile configuration
[source,yaml]
----
apiServer:
# ...
dns:
  configFile: /etc/microshift/dns/Corefile
# ...
----
+
where:
+
--
`dns.configFile`:: Specifies the absolute path to the custom Corefile on the host. The path must exist, be readable, and not exceed 1 MiB. This parameter is mutually exclusive with `dns.hosts.status: Enabled`.
--
+
[NOTE]
====
You can set the same parameter in a configuration snippet in the `/etc/microshift/config.d/` directory instead of editing `config.yaml`.
====

. Save the configuration file.

. Restart the {microshift-short} service by running the following command:
+
[source,terminal]
----
$ sudo systemctl restart microshift
----
+
After this initial restart, {microshift-short} monitors the custom Corefile for content changes. You do not restart the {microshift-short} service to apply edits to that file. If you change the `dns.configFile` path in the configuration YAML file, restart the {microshift-short} service again.

.Verification

. Confirm that the `dns-default` config map contains the custom Corefile by running the following command:
+
[source,terminal]
----
$ oc get configmap dns-default -n openshift-dns -o jsonpath='{.data.Corefile}{"\n"}'
----
+
The output matches the contents of `/etc/microshift/dns/Corefile`.

. Confirm that the config map annotation points to your custom Corefile by running the following command:
+
[source,terminal]
----
$ oc get configmap dns-default -n openshift-dns -o jsonpath='{.metadata.annotations.microshift\.io/dns-config-file}{"\n"}'
----
+
.Example output
[source,text]
----
/etc/microshift/dns/Corefile
----

. Confirm that the DNS pods are running by running the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-dns
----
+
.Example output
[source,text]
----
NAME                  READY   STATUS    RESTARTS   AGE
dns-default-xxxxx     2/2     Running   0          1m
node-resolver-xxxxx   1/1     Running   0          1m
----
