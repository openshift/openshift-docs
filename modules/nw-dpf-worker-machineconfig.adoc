= Configure worker nodes for DPU operation

[role="_abstract"]
You must create a `MachineConfigPool` resource and deploy the `dpu-worker-config` Helm chart to configure worker nodes with DPUs before adding those nodes to the management cluster.
The `MachineConfigPool` groups DPU-equipped worker nodes so that the Machine Config Operator can apply DPU-specific configurations to them.
The `dpu-worker-config` Helm chart creates the `dpu-worker-configuration` MachineConfig resource that configures the bridge, OVS services, and IP routing on worker nodes.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the OpenShift CLI (`oc`).
* The Helm CLI (`helm`) is installed on your workstation.

.Procedure

. Deploy the `dpu-worker-config` Helm chart to create the worker node MachineConfig:
+
[source,terminal]
----
$ helm upgrade --install dpu-worker-config \
    oci://quay.io/redhat-user-workloads/dpu-kit-for-nvidia-operator-tenant/dpu-worker-config-chart \
    --namespace dpf-hcp-provisioner-system \
    --create-namespace \
    --disable-openapi-validation
----
+
[NOTE]
====
If your network uses jumbo frames, set the MTU by adding `--set networkMTU=9000` to the command.
====

. Create a file named `worker-dpu-mcp.yaml` with the following `MachineConfigPool` definition:
+
[source,yaml]
----
apiVersion: machineconfiguration.openshift.io/v1
kind: MachineConfigPool
metadata:
  name: worker-dpu
spec:
  machineConfigSelector:
    matchExpressions:
      - {key: machineconfiguration.openshift.io/role, operator: In, values: [worker, worker-dpu]}
  maxUnavailable: 1
  nodeSelector:
    matchLabels:
      node-role.kubernetes.io/worker-dpu: ""
  paused: false
----

. Apply the `MachineConfigPool`:
+
[source,terminal]
----
$ oc apply -f worker-dpu-mcp.yaml
----

.Verification

* Verify that the `dpu-worker-config` Helm release is deployed:
+
[source,terminal]
----
$ helm list -n dpf-hcp-provisioner-system
----

* Verify that the `dpu-worker-configuration` MachineConfig is created:
+
[source,terminal]
----
$ oc get machineconfig dpu-worker-configuration
----

* Verify that the `MachineConfigPool` exists:
+
[source,terminal]
----
$ oc get machineconfigpool worker-dpu
----
+
.Example output
[source,terminal]
----
NAME         CONFIG   UPDATED   UPDATING   DEGRADED   MACHINECOUNT   READYMACHINECOUNT
worker-dpu            True      False      False      0              0
----

[NOTE]
====
The Machine Config Operator automatically reboots worker nodes to apply DPU-specific configurations after nodes with the `worker-dpu` label are added to the cluster.
====
