= Notable technical changes

[role="_abstract"]
This section includes several technical changes for {product-title} {product-version}.

The NUMA Resources Operator validates the secondary scheduler image::
+
--
Before this update, the NUMA Resources Operator did not validate the image that you set in the `spec.imageSpec` field of the `NUMAResourcesScheduler` custom resource (CR).
Because this CR is cluster-scoped and the scheduler runs with high privileges, a user with write access to the CR could run an arbitrary container image with scheduler privileges.

With this release, the NUMA Resources Operator validates the scheduler image by default.
The Operator accepts only digest-based image references, such as `registry.redhat.io/openshift4/noderesourcetopology-scheduler-rhel9@sha256:<digest>`, and the digest must match one of the trusted scheduler images that are embedded in the Operator for the current or previous release stream.
If you specify an image that does not meet these requirements, the `NUMAResourcesScheduler` resource enters a `Degraded` state with the reason `InvalidSchedulerImage`.

[IMPORTANT]
====
If you set a custom image in the `spec.imageSpec` field of the `NUMAResourcesScheduler` CR, for example, a tag-based reference, the resource enters a `Degraded` state after you upgrade to this release. To restore the scheduler, perform one of the following actions:

* Update the `spec.imageSpec` field to reference the scheduler image by its `sha256` digest instead of a tag, and make sure that the image you are using is in the current production stream.
* Add the digest of your custom image to the trusted list by setting the `SCHEDULER_IMAGE_DIGESTS` environment variable in the Operator subscription.
* Disable validation by setting the `SCHEDULER_IMAGE_VALIDATION` environment variable to `false` in the Operator subscription. Disabling validation removes this security protection, so avoid it unless necessary.
====

For more information about the NUMA Resources Operator and the `NUMAResourcesScheduler` CR, see xref:../scalability_and_performance/cnf-numa-aware-scheduling.adoc#cnf-numa-aware-scheduling[Scheduling NUMA-aware workloads]. (link:https://issues.redhat.com/browse/OCPBUGS-94176[OCPBUGS-94176])
--

The NUMA Resources Operator validates the Resource Topology Exporter image::
+
--
Before this update, the NUMA Resources Operator did not validate the Resource Topology Exporter (RTE) image that you set in the `spec.imageSpec` field of the `NUMAResourcesOperator` custom resource (CR).
Because the RTE runs as a daemon set on worker nodes with elevated read privileges, a user with write access to the CR could run an arbitrary container image with those privileges.

With this release, the NUMA Resources Operator does not allow a custom RTE image by default.
If you set the exporter image in the `spec.imageSpec` field of the `NUMAResourcesOperator` CR, the resource enters a `Degraded` state with the reason `CustomUserImage` and the Operator does not reconcile the resource.
Leave the `spec.imageSpec` field unset so that the Operator uses the default RTE image for your {product-title} release.
In a disconnected environment, the image mirroring configuration for the Operator container redirects the default image to your internal registry.

[IMPORTANT]
====
If you set a custom image in the `spec.imageSpec` field of the `NUMAResourcesOperator` CR, the resource enters a `Degraded` state after you upgrade to this release. To restore the deployment, perform one of the following actions:

* Remove the `spec.imageSpec` field from the `NUMAResourcesOperator` CR so that the Operator uses the default RTE image.
* Disable validation by setting the `EXPORTER_IMAGE_RESTRICTION` environment variable to `false` in the Operator subscription. Disabling validation removes this security protection, so avoid it unless necessary.
====

For more information about the NUMA Resources Operator and the `NUMAResourcesOperator` CR, see xref:../scalability_and_performance/cnf-numa-aware-scheduling.adoc#cnf-numa-aware-scheduling[Scheduling NUMA-aware workloads]. (link:https://issues.redhat.com/browse/OCPBUGS-94176[OCPBUGS-94176])
--
