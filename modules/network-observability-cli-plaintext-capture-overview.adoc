= Plain text capture for encrypted network traffic

[role="_abstract"]
The Network Observability CLI provides visibility into the unencrypted content of TLS-encrypted network traffic through eBPF-based plain text capture.
This feature correlates decrypted payload data with network packets so you can debug encrypted connections when payload inspection is essential but encryption makes the data unreadable.

The eBPF agent captures plain text data by intercepting TLS operations before encryption and after decryption, supporting OpenSSL, Go TLS, and kernel TLS (kTLS) implementations.
The agent collects the data and the Network Observability CLI displays and correlates it with corresponding network packets, providing visibility into the actual content flowing through encrypted connections.

This capability is particularly valuable for:

* Debugging application-level protocol issues in encrypted traffic
* Verifying API request and response payloads
* Analyzing encrypted traffic patterns without disabling TLS
* Troubleshooting encrypted connections to system services

The plain text capture workflow consists of:

. The eBPF agent intercepts TLS operations in your cluster workloads.
. The agent captures plain text data before encryption and after decryption.
. The Network Observability CLI retrieves and displays the captured data.
. The CLI correlates plain text content with the corresponding network packets.

[NOTE]
====
Plain text capture requires kernel support for eBPF features and appropriate permissions for the eBPF agent to attach to TLS library functions.
====

[id="supported-tls-implementations_{context}"]
== Supported TLS implementations

The Network Observability plain text capture feature supports the following TLS implementations:

OpenSSL:: The OpenSSL library used by many applications and services for TLS encryption.
Go TLS:: The native TLS implementation in Go applications, including many Kubernetes components.
kernel TLS (kTLS):: The Linux kernel's native TLS implementation that offloads encryption to the kernel, improving performance for high-throughput applications.

Each implementation can be enabled or disabled independently in the `FlowCollector` custom resource so you can focus on specific workloads or reduce noise from system processes.

[id="key-considerations_{context}"]
== Key considerations

When using plain text capture, consider the following:

kernel requirements:: kTLS support requires specific kernel versions and configuration. Verify kernel compatibility before enabling kTLS plain text capture.
Privileged access:: The eBPF agent requires elevated permissions to attach to TLS library functions. Ensure the agent has the necessary security context and capabilities.
Noise from system processes:: Cluster components such as the API server and etcd generate significant encrypted traffic. Use process exclusion filters to reduce noise and focus on application traffic.
Performance impact:: Plain text capture requires additional resources. Monitor resource usage when enabling this feature in production environments.
Security and compliance:: Captured plain text data can contain sensitive information. Ensure appropriate access controls and retention policies are in place.
