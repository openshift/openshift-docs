= Metrics and tracing

[role="_abstract"]

The console reads mesh metrics from Prometheus and, when you configure it, distributed traces from {TempoName}. Both are cluster services on {ocp-product-title}. This page does not cover installing Kiali.

Prometheus is required. {KialiServer} uses {istio} metrics to draw the graph, calculate health, and chart traffic. On {ocp-product-title}, point Kiali at the in-cluster monitoring stack instead of a separate Prometheus instance. The procedure is described in "Configuring OpenShift Monitoring with Kiali".

Tracing is optional. After you configure {TempoName} for the mesh, the console adds trace lists on the detail pages and on the graph side panel. Users only see traces in namespaces they can access. If distributed tracing is disabled in the mesh, those views stay empty.

Set the service URLs under `spec.external_services` in the `Kiali` custom resource. Use the in-cluster service URL. You do not expose Prometheus or Tempo on a route for {KialiServer} to read them.

If Prometheus is not the default `prometheus` service in the {istio} namespace, set `spec.external_services.prometheus.url`. {KialiServer} caches some Prometheus queries that it uses for health. Delays in the console are uncommon. Change the cache only when you have measured a delay.

For {TempoName} on {ocp-product-title}, set `provider` to `tempo` and `url_format` to `openshift` so *View in tracing* opens the {ocp-short-name} console plugin:

[source,yaml]
----
spec:
  external_services:
    tracing:
      enabled: true
      provider: tempo
      use_grpc: false
      internal_url: https://tempo-sample-gateway.tempo.svc.cluster.local:8080/
      external_url: https://console-openshift-console.apps.example.com
      tempo_config:
        name: sample
        namespace: tempo
        tenant: default
        url_format: openshift
----

`use_grpc` must be `false` for the Tempo HTTP API. If `internal_url` has no path and `tenant` is set, {KialiServer} appends `/api/traces/v1/<tenant>/tempo`.

Grafana and Perses links on the metrics pages are optional. Neither is a supported part of {ocp-product-title} or {SMProduct}. The console still charts the default {istio} metrics without them.

For the monitoring and tracing procedures that apply to {SMProduct}, see "Using metrics with Service Mesh" and "Configuring distributed tracing with Service Mesh".
