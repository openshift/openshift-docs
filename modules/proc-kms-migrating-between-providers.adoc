= Migrating between KMS providers

[role="_abstract"]
You can migrate between KMS providers without an intermediate local encryption step. During migration, {product-title} runs both KMS plugins concurrently until re-encryption completes.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* KMS encryption is enabled and functioning with the current provider.
* You have created the credential secret and optional CA bundle config map for the new provider in the `openshift-config` namespace.
* You have the fully qualified OCI image pull spec with SHA256 digest for the new KMS plugin image.

[IMPORTANT]
====
Create an etcd backup before migrating between KMS providers.
====

.Procedure

. Edit the `APIServer` custom resource by entering the following command:
+
[source,terminal]
----
$ oc edit apiserver cluster
----

. Update the `kms.vault` configuration with the new provider settings:
+
[source,yaml]
----
apiVersion: config.openshift.io/v1
kind: APIServer
metadata:
  name: cluster
spec:
  encryption:
    type: KMS
    kms:
      type: Vault
      vault:
        kmsPluginImage: <new_registry>/<new_repository>@sha256:<new_digest>
        vaultAddress: https://new-vault.example.com:8200
        vaultKeyPath: transit/keys/new-kms-key
        authentication:
          type: AppRole
          appRole:
            secret:
              name: new-vault-approle-secret
----

. Save and exit.
+
After configuration validation succeeds, the new provider handles encryption while the old provider decrypts existing data.

. Monitor migration progress by entering the following command:
+
[source,terminal]
----
$ oc get kubeapiserver cluster -o jsonpath='{.status.conditions[?(@.type=="Encrypted")]}' | jq .
----
+
Wait for `reason` to show `EncryptionCompleted`.

.Verification

. Verify that the OpenShift API server has completed migration by entering the following command:
+
[source,terminal]
----
$ oc get openshiftapiserver -o jsonpath='{range .items[0].status.conditions[?(@.type=="Encrypted")]}{.reason}{"\n"}{end}'
----
+
The output shows `EncryptionCompleted`.

. Verify that the Kubernetes API server has completed migration by entering the following command:
+
[source,terminal]
----
$ oc get kubeapiserver -o jsonpath='{range .items[0].status.conditions[?(@.type=="Encrypted")]}{.reason}{"\n"}{end}'
----
+
The output shows `EncryptionCompleted`.

. Verify that the authentication Operator has completed migration by entering the following command:
+
[source,terminal]
----
$ oc get authentication.operator.openshift.io -o jsonpath='{range .items[0].status.conditions[?(@.type=="Encrypted")]}{.reason}{"\n"}{end}'
----
+
The output shows `EncryptionCompleted`.

. After migration completes, clean up the old provider resources:
+
[NOTE]
====
The platform does not remove KMS credentials and CA bundles from the `openshift-config` namespace. You must delete these resources after migration completes.
====
+
--
.. Delete the old credential secret by entering the following command:
+
[source,terminal]
----
$ oc delete secret old-vault-approle-secret -n openshift-config
----

.. Optional: Delete the old CA bundle config map by entering the following command:
+
[source,terminal]
----
$ oc delete configmap old-vault-ca-bundle -n openshift-config
----

.. After your backup retention period passes, decommission the old KMS key.
--

[NOTE]
====
Do not decommission the old KMS key until migration completes and all backups encrypted with the old key have expired.
====
