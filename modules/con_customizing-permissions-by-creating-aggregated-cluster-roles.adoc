= Customize permissions with aggregated cluster roles

[role="_abstract"]
The default cluster role for the Argo CD Application Controller has hard-coded permissions managed by the {gitops-title} Operator. You can customize the permissions by using either of the following methods:

* xref:../deploy/customize-cluster-permissions.adoc#customizing-permissions-by-creating-user-defined-cluster-roles-for-cluster-scoped-instances_customize-cluster-permissions[Customize permissions with user-defined cluster roles]
* xref:../deploy/customize-cluster-permissions.adoc#gitops-creating-aggregated-cluster-roles_customize-cluster-permissions[Creating aggregated cluster roles]

[id="aggregated-cluster-roles_{context}"]
== Aggregated cluster roles

By using aggregated cluster roles, you do not have to define permissions by creating new cluster roles from scratch. Instead, you can combine several cluster roles into a single one. 

With {gitops-title} 1.14 and later, as a cluster administrator, you can use aggregated cluster roles so that users can add user-defined permissions for Argo CD Application Controller.

[IMPORTANT]
====
* The aggregated cluster roles functionality is optional and disabled by default. You can create aggregated cluster roles only for the Argo CD Application Controller component of a cluster-scoped Argo CD instance.
* Deleting the `aggregatedClusterRoles` field from the Argo CD custom resource (CR) does not delete the user-defined cluster role. You must manually delete the user-defined cluster role using the CLI or UI.
====
