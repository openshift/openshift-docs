= Access to VM pod networks from external networks

The {aws-short} Route Server advertises the virtual machine (VM) pod network routes only into the route tables of the VPC that hosts your cluster.
The Route Server does not advertise these routes to networks outside the VPC, such as an on-premises network connected over {aws-short} Direct Connect or a VPN, or a peered VPC.

To allow a host on an external network to reach a VM at its pod network IP address, the external network must be able to route traffic for the pod network CIDR into the VPC. 
After the traffic reaches the VPC, the VPC route tables directs the traffic to the correct compute node Elastic Network Interface (ENI).

Configure external connectivity so that both of the following conditions are met:

* The external network has a route for the VM `<pod_network_cidr>` whose next hop lands the traffic inside the VPC.
For example, through the virtual private gateway (VGW) or transit gateway (TGW) that attaches the external network to the VPC.
You can add this route statically or by propagating the route through your dynamic routing configuration.
* No NAT device is placed in the path between the external host and the VM, because the VM must be reachable at its pod network IP address.
