= Access to VM pod networks from external networks

[role="_abstract"]
The {aws-short} Route Server advertises the virtual machine (VM) pod network routes only into the route tables of the virtual private cloud (VPC) that hosts your cluster. The Route Server does not advertise these routes to networks outside the VPC, such as an on-premises network connected over {aws-short} Direct Connect or a VPN, or a peered VPC.

The recommended architecture is to set static routes in external networks that point pod network the next-hops of Classless Inter-Domain Routings (CIDRs) into the VPC. The VPC can then use the routes injected by the Route Server to forward the traffic to compute nodes.

[IMPORTANT]
====
Red{nbsp}Hat does not recommended to use the BGP Cloud Connector to directly peer with routers in other networks or with services other than the Route Server. The reason for this recommendation is that when using `platform: manual`, the list of peers do not get updates as compute nodes join or leave the cluster.
====

Configure external connectivity so that both of the following conditions are met:

* The external network has a route for the VM `<pod_network_cidr>` whose next hop lands the traffic inside the VPC. For example, if the external network is a VPC joined to the VPC of the cluster through a Transit Gateway, the external network should have a route whose CIDR block matches a `BGPRouting.spec.network.subnets` entry and whose target is the Transit Gateway. You can add this route statically or by propagating the route through your dynamic routing configuration.
* No NAT device is placed in the path between the external host and the VM, because the VM must be reachable at its pod network IP address.
