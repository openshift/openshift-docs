= Protocol behavior differences

[role="_abstract"]
The stateful and stateless Model Context Protocol (MCP) protocol versions differ in how the {mcpg} handles routing, sessions, backend initialization, and response handling.

.Behavior differences between protocol versions
[cols="1,1,1",options="header"]
|===
|Behavior
|2025-11-25, stateful
|2026-07-28, stateless

|Routing
|Initialize handshake and `Mcp-Session-Id` required. Sticky sessions or a shared session database required. Parsing focuses strictly on the valid execution of the `JSON-RPC` JSON body.
|`Gateway` objects inspect the headers that mirror body the fields, `MCP-Protocol-Version`, `Mcp-Method`, and `Mcp-Name`, for instant classification.

|Client context
|Sent once and cached in server-side memory.
|Passed inside a `_meta` field embedded on every individual request.

|Sessions
|JWT-based `Mcp-session-Id`
|None

|Backend initialization
|Hairpin initialization through the {mcpg}
|`server/discover`

|Response handling
|Session ID rewriting, elicitation ID rewriting
|Pass-through

|Header-body validation
|Not applicable
|Rejects mismatches between the `Mcp-Name` header and the body `params.name`

|Meta-tools
|`discover_tools`, `select_tools` available
|Not available

|Gateway visibility
|Opaque traffic. Load balancers cannot see the operation being performed without inspecting the payload.
|Transparent traffic. Standard network infrastructure can read routing context directly from HTTP headers.
|===
