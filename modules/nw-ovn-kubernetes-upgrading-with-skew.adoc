= Upgrading the control plane with data-plane version skew

[role="_abstract"]
You can upgrade the OVN-Kubernetes control plane even when some compute nodes cannot update their data-plane agents.
The Cluster Network Operator (CNO) allows the control-plane upgrade to proceed independently of the data plane.

.Prerequisites

* You have access to the cluster with `cluster-admin` privileges.
* You have installed the {oc-first}.
* The cluster is running a version of {product-title} that supports relaxed OVN-Kubernetes version skew policies.
* You understand that nodes with older data-plane agents experience best-effort networking.

.Procedure

. Verify that the cluster is healthy by entering the following commands:
+
[source,terminal]
----
$ oc get hostedcluster <hosted_cluster_name> -n <hosted_cluster_namespace>
----
+
[source,terminal]
----
$ oc get nodes -o wide
----
+
[source,terminal]
----
$ oc get pods -n <hosted_cluster_namespace>-<hosted_cluster_name> -l app=ovnkube-control-plane
----
+
Confirm that the hosted cluster shows `AVAILABLE` as `True`, all nodes report `Ready` status, and OVN-Kubernetes control-plane pods are `Running` with `3/3` containers ready.

. Verify the current `NodePool` state by entering the following command:
+
[source,terminal]
----
$ oc get nodepool -n <hosted_cluster_namespace>
----
+
Confirm that each `NodePool` shows the current version and `UPDATING` is `False`.

. Upgrade the control plane to the target version by entering the following command:
+
[source,terminal]
----
$ oc patch hostedcluster <hosted_cluster_name> -n <hosted_cluster_namespace> --type merge \
    -p '{"spec":{"release":{"image":"<target_release_image>"}}}'
----
+
Replace `<target_release_image>` with the pull specification of the target release image.

. Monitor the control-plane upgrade by entering the following command:
+
[source,terminal]
----
$ oc get hostedcluster <hosted_cluster_name> -n <hosted_cluster_namespace>
----
+
Wait until `AVAILABLE` shows `True` and `PROGRESSING` shows `False`.

. Verify that version skew exists between the control plane and data plane by entering the following commands:
+
[source,terminal]
----
$ oc get pods -n <hosted_cluster_namespace>-<hosted_cluster_name> -l app=ovnkube-control-plane -o jsonpath='{.items[0].spec.containers[?(@.name=="ovnkube-cluster-manager")].image}'
----
+
[source,terminal]
----
$ oc get daemonset ovnkube-node -n openshift-ovn-kubernetes -o jsonpath='{.spec.template.spec.containers[?(@.name=="ovn-controller")].image}'
----
+
Confirm that the image SHA values differ between the control plane and data plane.

. Upgrade the compute nodes to match the control-plane version by patching each `NodePool`:
+
[source,terminal]
----
$ oc patch nodepool <nodepool_name> -n <hosted_cluster_namespace> --type merge \
    -p '{"spec":{"release":{"image":"<target_release_image>"}}}'
----
+
Repeat this command for each `NodePool`. Replace `<nodepool_name>` with the name of each `NodePool` object and `<target_release_image>` with the same pull specification used for the control-plane upgrade.
+
[NOTE]
====
The `NodePool` upgrade uses a rolling replacement strategy.
Existing nodes are cordoned, drained, and deleted, and replacement nodes are provisioned with the target version.
====

. Monitor the `NodePool` upgrade status by entering the following command:
+
[source,terminal]
----
$ oc get nodepool -n <hosted_cluster_namespace>
----
+
Wait until each `NodePool` reports the target version with `READY` as `True` and `UPDATING` as `False`.

.Verification

* Confirm that all compute nodes match the target release by running the following command:
+
[source,terminal]
----
$ oc get nodes -o wide
----

* Confirm that the OVN-Kubernetes node pods were recreated and are ready by running the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-ovn-kubernetes -l app=ovnkube-node
----

* Verify that the control plane and data plane are running the same version by running the following commands:
+
[source,terminal]
----
$ oc get pods -n <hosted_cluster_namespace>-<hosted_cluster_name> -l app=ovnkube-control-plane -o jsonpath='{.items[0].spec.containers[?(@.name=="ovnkube-cluster-manager")].image}' | sed 's/.*@//'
----
+
[source,terminal]
----
$ oc get daemonset ovnkube-node -n openshift-ovn-kubernetes -o jsonpath='{.spec.template.spec.containers[?(@.name=="ovn-controller")].image}' | sed 's/.*@//'
----
+
Confirm that both commands show the same image SHA.
