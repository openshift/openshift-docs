= Debug Argo CD applications

[role="_abstract"]
Debug Argo CD applications by examining sync errors, health status, resource events, and manifest rendering issues. Use diagnostic commands and logs to identify and resolve deployment problems.

.Prerequisites

* You have the {gitops-shortname} `argocd` CLI installed.
* You have access to the Argo CD web console.
* You have permissions to view application details and logs.

.Procedure

. Get detailed application status:
+
[source,terminal]
----
$ argocd app get <application_name> --show-params --show-operation
----
+
This displays:
+
* Current sync and health status
* Last sync operation details
* Application parameters
* Sync errors and warnings

. View the difference between Git and live state:
+
[source,terminal]
----
$ argocd app diff <application_name>
----
+
Review the diff output to identify configuration drift or unexpected changes.

. Check manifest rendering:
+
[source,terminal]
----
$ argocd app manifests <application_name>
----
+
This shows the rendered Kubernetes manifests that Argo CD generates from your Git repository.
+
Common rendering issues:
+
* Invalid Helm values or missing parameters
* Kustomize overlay errors
* Template syntax errors

. View application resource tree:
+
[source,terminal]
----
$ argocd app get <application_name> --show-tree
----
+
This displays all Kubernetes resources managed by the application and their health status.

. Check individual resource details:
+
[source,terminal]
----
$ argocd app get <application_name> --resource <kind>:<name>
----
+
Replace `<kind>:<name>` with the specific resource (for example, `Deployment:my-app`).

. View resource events:
+
[source,terminal]
----
$ oc get events -n <namespace> --field-selector involvedObject.name=<resource_name> --sort-by='.lastTimestamp'
----

. Enable debug logging for the application:
+
.. Add the `argocd.argoproj.io/sync-options: Debug=true` annotation:
+
[source,yaml]
----
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  annotations:
    argocd.argoproj.io/sync-options: Debug=true
----
+
.. Sync the application and check the operation logs:
+
[source,terminal]
----
$ argocd app sync <application_name>
$ argocd app logs <application_name>
----

. For sync hook failures:
+
.. List all hooks:
+
[source,terminal]
----
$ argocd app get <application_name> | grep -A5 Hook
----
+
.. Check hook job logs:
+
[source,terminal]
----
$ oc logs job/<hook_job_name> -n <namespace>
----
+
.. Delete stuck or failed hooks:
+
[source,terminal]
----
$ oc delete job <hook_job_name> -n <namespace>
----

. Check the Argo CD application controller logs for reconciliation errors:
+
[source,terminal]
----
$ oc logs -n openshift-gitops statefulset/openshift-gitops-application-controller | grep <application_name>
----

. For repository access issues:
+
.. Test repository connectivity:
+
[source,terminal]
----
$ argocd repo get <repo_url>
----
+
.. Check repository server logs:
+
[source,terminal]
----
$ oc logs -n openshift-gitops deployment/openshift-gitops-repo-server | grep <repo_url>
----

. Use the web console for visual debugging:
+
.. Navigate to the application in the Argo CD UI.
.. Click on failing resources to see error details.
.. Use the *APP DIFF* view to compare desired vs. live state.
.. Check the *EVENTS* tab for resource-level events.

.Verification

After resolving issues, verify the application syncs successfully and reaches Healthy status:

[source,terminal]
----
$ argocd app sync <application_name>
$ argocd app wait <application_name> --health
----

[TIP]
====
Create a diagnostic bundle for complex issues:

[source,terminal]
----
$ argocd app get <application_name> --output yaml > app-debug.yaml
$ argocd app manifests <application_name> > app-manifests.yaml
$ argocd app logs <application_name> > app-logs.txt
----

This bundle contains all information needed for troubleshooting or support requests.
====
