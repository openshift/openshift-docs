= Managing and updating pinned images

[role="_abstract"]
You update pinned images by changing the digest list in one or more `PinnedImageSet` objects. The Machine Config Operator (MCO) reconciles those objects onto the matching machine config pools. You do not create or edit `MachineConfigNode` objects to select pools or to control rollout strategy; those objects report per-node status for pinned image sets.

== Organizing images across pools

Use separate `PinnedImageSet` objects for shared and workload-specific content:

* A base set for images that many pools need.
* Pool-specific sets for worker, control plane, or custom pools such as `infra`.

Label each set with `machineconfiguration.openshift.io/role` so that the MCO applies it only to the intended machine config pool. This pattern helps air-gapped and edge clusters pin only what each site requires.

== Updating pinned image digests

To change pinned images:

. Resolve the new image digests.
. Edit the existing `PinnedImageSet` or create a replacement object that contains the new digests.
. Apply the updated manifest with `oc apply`.
. Watch the `MachineConfigNode` status for each affected node until `currentGeneration` matches `desiredGeneration` and `PinnedImageSetsDegraded` is not reported.

For gradual rollouts, place subsets of nodes in a custom machine config pool and apply the updated `PinnedImageSet` to that custom pool first. After you validate the custom pool, apply the same digests to the broader worker or control plane pools.

== GitOps and declarative management

Store `PinnedImageSet` manifests in a Git repository and sync them to clusters with your preferred GitOps tool, such as {gitops-title} or a continuous delivery pipeline. Recommended practice:

* Keep production and non-production overlays in separate directories or branches.
* Require digest-only image references in CI validation.
* Apply and validate changes in a non-production cluster before production.
* Record the generating source of the image list, for example a script output commit, so that updates are reproducible.

[NOTE]
====
Pinned image updates pull new layers onto nodes. Schedule large digest changes during a maintenance window on low-bandwidth or disconnected sites.
====
