The distributed tracing 3.11.2 release resolves these Common Vulnerabilities and Exposures (CVEs):

`klauspost/compress` package no longer causes application failure::
Before this update, a flaw in the `klauspost/compress` Go package allowed an integer overflow to be triggered by a specially crafted compression dictionary with an excessively large repeat value. When a malicious compression dictionary was processed, the integer overflow caused out-of-bounds memory access, causing the application to fail. With this update, the integer overflow is resolved. As a result, the `klauspost/compress` package safely processes untrusted S2 compression dictionaries.
+
link:https://access.redhat.com/security/cve/CVE-2026-63209[CVE-2026-63209]
+
link:https://redhat.atlassian.net/browse/TRACING-6868[TRACING-6868]

Apache Thrift DoS vulnerability in Go services is fixed::
Before this update, Apache Thrift Go services were vulnerable to a denial of service (DoS) attack when processing specially crafted network frames with zero payload bytes. When receiving these empty frames, the transport recursively called its read function rather than iterating in a loop, which exhausted the execution stack. As a consequence, this stack exhaustion caused an unrecoverable fatal error that terminated the entire process. With this update, Apache Thrift handles empty frame payloads correctly. As a result, Go services no longer experience DoS attacks from specially crafted network frames.

gRPC-Go servers no longer fail when receiving malformed RPC requests::
Before this update, servers created with the `xds.NewGRPCServer()` constructor could be exploited by a remote client sending a malformed remote procedure call (RPC) request lacking required headers. As a consequence, this caused an index-out-of-bounds panic that terminated the entire server process, resulting in a denial of service (DoS). In some deployments, unauthenticated clients could trigger this attack. With this update, gRPC-Go, the Go implementation of gRPC, properly validates headers in RPC requests. As a result, servers no longer fail when receiving malformed RPC requests.

Apache Thrift Go library no longer experiences DoS from malformed compressed data::
Before this update, the Apache Thrift Go library improperly handled decompression when a remote attacker sent specially crafted, highly compressed data to an affected service. As a consequence, the data amplification exhausted system resources and caused the service to become unavailable. With this update, Apache Thrift properly handles decompression of compressed data. As a result, the Go library no longer experiences denial of service (DoS) attacks from malformed compressed frames.
