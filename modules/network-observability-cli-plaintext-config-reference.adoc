= Plain text capture configuration parameters

[role="_abstract"]
Configure plain text capture behavior for the Network Observability eBPF agent by setting parameters in the `FlowCollector` custom resource.

The following table describes the configuration parameters available for plain text capture in the `agent.ebpf.plaintextCapture` section of the `FlowCollector` custom resource:

.Plain text capture configuration parameters
[cols="1,2,1,1", options="header"]
|===
|Parameter
|Description
|Type
|Default

|`enable`
|Enables or disables plain text capture globally. When set to `false`, all TLS implementation-specific settings are ignored.
|Boolean
|`false`

|`openssl.enable`
|Enables or disables plain text capture for OpenSSL-encrypted connections. The eBPF agent attaches probes to OpenSSL library functions to intercept plain text data before encryption and after decryption.
|Boolean
|`false`

|`goTLS.enable`
|Enables or disables plain text capture for Go TLS-encrypted connections. The eBPF agent attaches probes to Go runtime TLS functions to intercept plain text data.
|Boolean
|`false`

|`kernelTLS.enable`
|Enables or disables plain text capture for kernel TLS (kTLS) connections. kTLS offloads TLS encryption to the Linux kernel. This option requires kernel version 4.17 or later.
|Boolean
|`false`

|`kernelTLS.cGroupPath`
|Specifies the root path for cgroups to identify kTLS processes. This path determines which processes use kTLS and are monitored for plain text capture.
|String
|`/sys/fs/cgroup`

|`processExclusions`
|Specifies a list of processes to exclude from plain text capture. Each exclusion includes a process name and optional namespace. Use this to reduce noise from high-traffic system processes.
|Array
|`[]`

|`processExclusions[].name`
|The name of the process to exclude from plain text capture. Must match the process name in `/proc/<pid>/comm`.
|String
|N/A

|`processExclusions[].namespace`
|The Kubernetes namespace where the excluded process runs. If specified, only processes in this namespace with the matching name are excluded. If omitted, processes with the matching name in all namespaces are excluded.
|String
|N/A

|===

[id="configuration-examples_{context}"]
== Configuration examples

The following examples show common plain text capture configurations.

.Example: Enable plain text capture for OpenSSL only
[source,yaml]
----
spec:
  agent:
    type: eBPF
    ebpf:
      plaintextCapture:
        enable: true
        openssl:
          enable: true
        goTLS:
          enable: false
        kernelTLS:
          enable: false
----

.Example: Enable all TLS implementations with process exclusions
[source,yaml]
----
spec:
  agent:
    type: eBPF
    ebpf:
      plaintextCapture:
        enable: true
        openssl:
          enable: true
        goTLS:
          enable: true
        kernelTLS:
          enable: true
          cGroupPath: /sys/fs/cgroup
        processExclusions:
          - name: kube-apiserver
            namespace: openshift-kube-apiserver
          - name: etcd
            namespace: openshift-etcd
----

.Example: Exclude all etcd processes across namespaces
[source,yaml]
----
spec:
  agent:
    type: eBPF
    ebpf:
      plaintextCapture:
        enable: true
        openssl:
          enable: true
        processExclusions:
          - name: etcd
----

[id="performance-and-resource-considerations_{context}"]
== Performance and resource considerations

Enabling plain text capture requires additional resources for the eBPF agent:

* **CPU usage**: The eBPF agent uses additional CPU resources to attach probes to TLS library functions and process intercepted data.
* **Memory usage**: Captured plain text data is buffered in memory before the collector receives it, increasing memory consumption.
* **Network bandwidth**: Plain text data flows from the agent to the collector, increasing network traffic within the cluster.

To minimize performance impact:

* Enable only the TLS implementations you need to monitor.
* Use `processExclusions` to filter out high-traffic system processes.
* Monitor agent resource usage and adjust configurations as needed.
* Test plain text capture in non-production environments before enabling it in production.
