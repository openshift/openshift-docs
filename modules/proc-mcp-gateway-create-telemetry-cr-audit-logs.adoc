= Enable the access log on the Gateway pods workload

[role="_abstract"]
Enable optional Envoy access logs by configuring a `Telemetry` custom resource (CR) in the namespace of your `Gateway` object.

The resource created in this example scopes the access log to the `_<mcp_gateway>_` `Gateway` pods only. Other workloads in the mesh are not affected.

.Prerequisites

* You installed the {mcpg}.
* You installed {prodname}.
* You created a `Gateway` object.
* You set up an identity provider.
* You configured Istio as the Gateway API provider.
* You configured authentication for both the broker and back-end route sets, such as the `mcp` and `mcps` listeners, and configured the `x-auth-identity` response header in both `AuthPolicy` CRs.
* You added your custom log provider.

.Procedure

. Add `accessLogging` to the existing `Telemetry` CR that selects the same `Gateway` workload. Preserve its tracing, metrics, and other access logging settings. If no matching CR exists, create one by using the following example. Do not create multiple selector-based `Telemetry` CRs that match the same workload.
+
.Example Telemetry CR for audit logs
[source,yaml,subs="+quotes"]
----
apiVersion: telemetry.istio.io/v1
kind: Telemetry
metadata:
  name: _<mcp_audit_logging>_
  namespace: _<gateway_namespace>_
spec:
  selector:
    matchLabels:
      gateway.networking.k8s.io/gateway-name: _<mcp_gateway>_
  accessLogging:
    - providers:
        - name: mcp-json-access-log
----
+
* Replace `_<mcp_audit_logging>_` with the name of the existing matching `Telemetry` CR, or a new name if none exists.
* Replace `_<gateway_namespace>_` with the namespace where you applied your `Gateway` object.
* Replace `_<mcp_gateway>_` with the `metadata.name` of your `Gateway` object, not the name of the {mcpg} broker deployment.

. Apply the `Telemetry` CR by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<mcp_audit_logging.yaml>_
----
+
Replace `_<mcp_audit_logging.yaml>_` with the name of your audit logging YAML.

.Verification

. Verify that your `Telemetry` CR is applied by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc get telemetry -n _<gateway_namespace>_
----
+
Replace `_<gateway_namespace>_` with the namespace where you applied your `Gateway` object.
