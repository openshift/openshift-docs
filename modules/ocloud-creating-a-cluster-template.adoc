= Create a ClusterTemplate CR for single-node cluster provisioning

[role="_abstract"]
You can define a `ClusterTemplate` custom resource (CR) that serves as a reusable blueprint for provisioning clusters. The template specifies the cluster topology, hardware requirements, and default configuration. It also defines a validation schema for the site-specific parameters that site engineers provide in a `ProvisioningRequest` resource.

A `ClusterTemplate` CR references `ConfigMap` resources that contain defaults for cluster installation and Day-2 policy configuration. The cluster installation defaults ConfigMap defines the common configuration across all clusters provisioned with a template, including cluster-level settings and the shared node configuration for each node group. When a site engineer creates a `ProvisioningRequest` resource, the O-Cloud Manager merges the site-specific parameters from the request with these defaults to produce the final cluster and policy definitions.

[NOTE]
====
For multi-node clusters with distinct hardware requirements for each node role, see "Create a ClusterTemplate CR for multi-node cluster provisioning". For advanced hardware selection using hardware data selectors and site-specific overrides, see "Configure advanced hardware management".
====

.Prerequisites

* The O-Cloud Manager Operator is installed on the hub cluster.
* The GitOps repository is configured and synchronized with ArgoCD.
* Bare-metal servers are onboarded to resource pools with appropriate resource selector labels.
* If firmware or BIOS management is required, `HardwareProfile` resources are defined.

.Procedure

. Create a namespace for the `ClusterTemplate` and its associated resources by running the following command:
+
[source,terminal]
----
$ oc create namespace <template_namespace>
----
+
where:
+
`<template_namespace>`:: Specifies the target namespace for the `ClusterTemplate` resource and associated `ConfigMap` resources.

. Create a `ConfigMap` CR containing default values for cluster installation parameters, such as the following example for a {sno} cluster:
+
[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: clusterinstance-defaults-v1
  namespace: <template_namespace>
data:
  clusterinstance-defaults: |
    baseDomain: example.com
    extraLabels:
      ManagedCluster:
        cluster-version: "v4-Y-Z"
        sno-ran-du-policy: "v1"
    clusterImageSetNameRef: "4.Y.Z"
    pullSecretRef:
      name: pull-secret
    networkType: OVNKubernetes
    clusterNetwork:
      - cidr: 203.0.113.0/24
        hostPrefix: 23
    machineNetwork:
      - cidr: 192.0.2.0/24
    serviceNetwork:
      - cidr: 233.252.0.0/24
    # sshPublicKey: "ssh-rsa AAAA..."
    additionalNTPSources:
      - 1.pool.ntp.org
    templateRefs:
      - name: ai-cluster-templates-v1
        namespace: open-cluster-management
    # Restricts the cluster to a minimal capability set for resource-constrained deployments
    # installConfigOverrides: '{"capabilities": {"baselineCapabilitySet": "None", "additionalEnabledCapabilities": ["NodeTuning", "OperatorLifecycleManager", "Ingress"]}}'
    # Ignition configuration override applied during cluster installation
    # ignitionConfigOverride: '{"ignition": {"version": "3.2.0"}, "storage": {"files": [...]}}'
    cpuPartitioningMode: AllNodes
    extraManifestsRefs:
      - name: sno-ran-du-extra-manifest-v1
    nodeGroups:
      - name: master
        role: master
        bootMode: UEFI
        ironicInspect: "disabled"
        automatedCleaningMode: disabled
        rootDeviceHints:
          deviceName: /dev/disk/by-path/pci-0000:01:00.0-nvme-1
        nodeNetwork:
          interfaces:
            - name: ens3f0
              label: boot-interface
            - name: ens3f1
              label: data-interface
          config:
            routes:
              config:
                - destination: 0.0.0.0/0
                  next-hop-interface: ens3f0
                  table-id: 254
            interfaces:
              - ipv6:
                  enabled: false
                ipv4:
                  enabled: true
                name: ens3f0
                state: up
                type: ethernet
        templateRefs:
          - name: ai-node-templates-v1
            namespace: open-cluster-management
----
+
`extraLabels.ManagedCluster`:: The `cluster-version` label is mandatory. This label, along with any additional custom labels such as `sno-ran-du-policy`, is used to bind {rh-rhacm-first} policies for cluster configuration rendered from the PolicyGenerator manifest.
`nodeGroups[].name`:: Must match `hwMgmtDefaults.nodeGroupData[].name` defined in the `ClusterTemplate` CR, which also correspond to the `MachineConfigPool` name on the managed cluster.
* The `boot-interface` label on a network interface is required. Using this label, the O-Cloud Manager resolves the boot NIC's MAC address from hardware inventory data.
+
[NOTE]
====
For image-based installation (IBI) provisioning, replace the `templateRefs` values with `ibi-cluster-templates-v1` and `ibi-node-templates-v1`. These templates instruct the installation program to use the seed image on the preinstalled host instead of performing a full installation. The Image Based Install (IBI) Operator must be enabled in the `MultiClusterEngine` resource, and servers must be preinstalled with the seed image using the live installation ISO before provisioning.
====

. Create a `ConfigMap` CR containing default values for Day-2 configuration policy parameters, such as the following example:
+
[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: policytemplates-defaults-v1
  namespace: <template_namespace>
data:
  policytemplate-defaults: |
    sriov-network-vlan-1: "140"
    sriov-network-pfNames-1: '["ens2f0"]'
    cpu-isolated: "0-1,64-65"
    cpu-reserved: "2-10"
    hugepages-default: "1G"
    hugepages-size: "1G"
    hugepages-count: "32"
    install-plan-approval: "Automatic"
----
+
The `ConfigMap` resource must contain a `policytemplate-defaults` key. The value is a YAML string defining the default policy parameters. Site-specific values from the `ProvisioningRequest` resource take precedence over these defaults when both specify the same parameter. All parameters referenced as placeholders in the PolicyGenerator manifest must be declared here or supplied through the `ProvisioningRequest` CR.

. Create an {rh-rhacm} `PolicyGenerator` manifest that defines the Day-2 configuration policies for clusters provisioned with this `ClusterTemplate`:
+
[NOTE]
====
The PolicyGenerator is the mechanism that turns policy defaults into enforceable policies on managed clusters. When a `ProvisioningRequest` is created, the O-Cloud Manager creates a `ConfigMap` CR named `<cluster-name>-pg` on the hub cluster, populated by merging the values from the policy defaults ConfigMap with any overrides from the `ProvisioningRequest` CR. The PolicyGenerator uses templating expressions (`{{hub ... hub}}`) as placeholders that {rh-rhacm} resolves at runtime by reading values from this `<cluster-name>-pg` ConfigMap. The result is `Policy` CRs that {rh-rhacm} enforces on the managed cluster.
====
+
[source,yaml]
----
apiVersion: policy.open-cluster-management.io/v1
kind: PolicyGenerator
metadata:
  name: sno-ran-du-pg-v4-Y-Z-v1
policyDefaults:
  namespace: ztp-<template_namespace>
  placement:
    labelSelector:
      cluster-version: "v4-Y-Z"
      sno-ran-du-policy: "v1"
  policyAnnotations:
    clustertemplates.clcm.openshift.io/templates: "sno-ran-du.v4-Y-Z-1"
  remediationAction: enforce
policies:
- name: v1-subscriptions-policy
  manifests:
    - path: source-crs/cluster-logging/ClusterLogSubscription.yaml
      patches:
      - spec:
          source: redhat-operators
          installPlanApproval:
            '{{hub $configMap:=(lookup "v1" "ConfigMap" "" (printf "%s-pg" .ManagedClusterName)) hub}}{{hub dig "data" "install-plan-approval" "Manual" $configMap hub}}'
- name: v1-perf-configuration-policy
  manifests:
    - path: source-crs/node-tuning-operator/PerformanceProfile-SetSelector.yaml
      patches:
      - spec:
          cpu:
            isolated: '{{hub fromConfigMap "" (printf "%s-pg" .ManagedClusterName) "cpu-isolated" hub}}'
            reserved: '{{hub fromConfigMap "" (printf "%s-pg" .ManagedClusterName) "cpu-reserved" hub}}'
          hugepages:
            defaultHugepagesSize: '{{hub fromConfigMap "" (printf "%s-pg" .ManagedClusterName) "hugepages-default" hub}}'
----
+
`policyDefaults.namespace`:: Must follow the naming convention `ztp-<clustertemplate-namespace>`. The O-Cloud Manager uses this convention to locate policies associated with a `ClusterTemplate` namespace.
`policyDefaults.placement.labelSelector`:: Must match the `extraLabels.ManagedCluster` labels defined in the `clusterinstance-defaults` `ConfigMap` CR. These labels bind the policies to the correct managed clusters.
`policyAnnotations.clustertemplates.clcm.openshift.io/templates`:: A comma-separated list of `ClusterTemplate` CRs, populated using the `metadata.name` field, that this `PolicyGenerator` CR is associated with. This enables the O-Cloud Manager to track policy compliance for provisioning status reporting.
`source-crs/`:: Contains the base manifests for Day-2 configuration resources such as `PerformanceProfile` CRs, `SriovNetworkNodePolicy` CRs, and Operator subscriptions. These CRs must match the target {product-title} release version.
+
[NOTE]
====
All parameters referenced as placeholders, such as `cpu-isolated` and `install-plan-approval`, must be declared in the `templateParameterSchema.policyTemplateParameters` section of the `ClusterTemplate` CR and supplied either through the policy defaults `ConfigMap` CR or the `ProvisioningRequest` CR.
====

. Create the `ClusterTemplate` CR, such as the following example:
+
[source,yaml]
----
apiVersion: clcm.openshift.io/v1alpha1
kind: ClusterTemplate
metadata:
  name: sno-ran-du.v4-Y-Z-1
  namespace: <template_namespace>
spec:
  name: sno-ran-du
  version: v4-Y-Z-1
  release: 4.Y.Z
  templateDefaults:
    hwMgmtDefaults:
      hardwareProvisioningTimeout: "90m"
      nodeGroupData:
        - name: master
          role: master
          resourceSelector:
            server-type: <server_type>
    clusterInstanceDefaults: clusterinstance-defaults-v1
    policyTemplateDefaults: policytemplates-defaults-v1
  templateParameterSchema:
    properties:
      nodeClusterName:
        type: string
      oCloudSiteId:
        type: string
      hwMgmtParameters:
        properties:
          hardwareProvisioningTimeout:
            type: string
          nodeGroupData:
            type: array
            items:
              type: object
              required:
                - name
              properties:
                name:
                  type: string
                  minLength: 1
                role:
                  type: string
                  enum:
                    - master
                    - worker
                hwProfile:
                  type: string
                resourcePoolId:
                  type: string
                resourceSelector:
                  type: object
                  additionalProperties:
                    type: string
        type: object
      policyTemplateParameters:
        properties:
          sriov-network-vlan-1:
            type: string
          sriov-network-vlan-2:
            type: string
          sriov-network-pfNames-1:
            type: string
          sriov-network-pfNames-2:
            type: string
          cpu-isolated:
            type: string
          cpu-reserved:
            type: string
          hugepages-default:
            type: string
          hugepages-size:
            type: string
          hugepages-count:
            type: string
          install-plan-approval:
            type: string
        type: object
      clusterInstanceParameters:
        properties:
          additionalNTPSources:
            items:
              type: string
            type: array
          apiVIPs:
            items:
              type: string
            maxItems: 2
            type: array
          baseDomain:
            type: string
          clusterName:
            type: string
          extraAnnotations:
            additionalProperties:
              additionalProperties:
                type: string
              type: object
            type: object
          extraLabels:
            additionalProperties:
              additionalProperties:
                type: string
              type: object
            type: object
          ingressVIPs:
            items:
              type: string
            maxItems: 2
            type: array
          machineNetwork:
            items:
              properties:
                cidr:
                  type: string
              required:
                - cidr
              type: object
            type: array
          nodeGroups:
            items:
              properties:
                name:
                  type: string
                  minLength: 1
                extraAnnotations:
                  additionalProperties:
                    additionalProperties:
                      type: string
                    type: object
                  type: object
                extraLabels:
                  additionalProperties:
                    additionalProperties:
                      type: string
                    type: object
                  type: object
                nodeLabels:
                  additionalProperties:
                    type: string
                  type: object
                nodeNetwork:
                  properties:
                    config:
                      type: object
                      x-kubernetes-preserve-unknown-fields: true
                  type: object
                nodes:
                  items:
                    properties:
                      hostName:
                        type: string
                      extraAnnotations:
                        additionalProperties:
                          additionalProperties:
                            type: string
                          type: object
                        type: object
                      extraLabels:
                        additionalProperties:
                          additionalProperties:
                            type: string
                          type: object
                        type: object
                      nodeLabels:
                        additionalProperties:
                          type: string
                        type: object
                      nodeNetwork:
                        properties:
                          interfaces:
                            minItems: 1
                            items:
                              properties:
                                name:
                                  type: string
                                  minLength: 1
                                addresses:
                                  properties:
                                    ipv4:
                                      items:
                                        type: string
                                        minLength: 1
                                      minItems: 1
                                      type: array
                                    ipv6:
                                      items:
                                        type: string
                                        minLength: 1
                                      minItems: 1
                                      type: array
                                  minProperties: 1
                                  type: object
                              required:
                                - name
                                - addresses
                              type: object
                            type: array
                        required:
                          - interfaces
                        type: object
                    required:
                      - hostName
                      - nodeNetwork
                    type: object
                  type: array
              required:
                - name
                - nodes
              type: object
            type: array
          serviceNetwork:
            items:
              properties:
                cidr:
                  type: string
              required:
                - cidr
              type: object
            type: array
          sshPublicKey:
            type: string
        required:
          - clusterName
          - nodeGroups
        type: object
    required:
      - nodeClusterName
      - oCloudSiteId
      - policyTemplateParameters
      - clusterInstanceParameters
    type: object
----
+
where:
+
`metadata.name`:: Must follow the format `<name>.<version>` and must be unique across all namespaces.
`<template_namespace>`:: Specifies the namespace where the `ClusterTemplate` CR and its associated `ConfigMap` CRs are stored.
`spec.name`:: Specifies the base name of the template. Combined with `spec.version` to form the `metadata.name` value.
`spec.version`:: Specifies the version of the template.
`spec.release`:: Specifies the {product-title} release version to install. Must match the `clusterImageSetNameRef` value in the `clusterinstance-defaults` `ConfigMap` resource.
`spec.templateDefaults.hwMgmtDefaults`:: Defines hardware management settings for provisioning, including node groups and a hardware provisioning timeout. This example shows a minimal configuration with a single node group and a simple label selector. For advanced hardware selection using hardware data selectors and site-specific overrides, see "Configure advanced hardware management".
`spec.templateDefaults.hwMgmtDefaults.nodeGroupData[].name`:: Must match the target `MachineConfigPool` name on the managed cluster, for example, `master` or `worker`. This name must also match `nodeGroups[].name` in the `clusterinstance-defaults` `ConfigMap` resource.
`<server_type>`:: Specifies the resource selector label value used to match bare-metal hosts during provisioning. This must match a `resourceselector.clcm.openshift.io/` label on onboarded `BareMetalHost` CRs.
`spec.templateDefaults.clusterInstanceDefaults`:: References the name of the `ConfigMap` resource that contains default cluster installation parameters. These defaults are merged with the site-specific values from the `ProvisioningRequest` CR to produce the final `ClusterInstance` resource.
`spec.templateDefaults.policyTemplateDefaults`:: References the name of the `ConfigMap` resource that contains default Day-2 configuration policy parameters. Site-specific values from the `ProvisioningRequest` CR take precedence over these defaults.
`spec.templateParameterSchema`:: Defines the OpenAPI v3 schema that validates parameters supplied in a `ProvisioningRequest` CR. The schema must include `nodeClusterName`, `oCloudSiteId`, `policyTemplateParameters`, and `clusterInstanceParameters`. The `hwMgmtParameters` section is optional and enables per-site hardware overrides.

. Apply the resources to the hub cluster, or commit them to the GitOps repository for ArgoCD synchronization.

.Verification

. Verify that the `ClusterTemplate` CR is validated by running the following command:
+
[source,terminal]
----
$ oc get clustertemplates.clcm.openshift.io -A
----
+
.Example output
[source,terminal]
----
NAMESPACE          NAME                   AGE   STATE       DETAILS
ocloud-templates   sno-ran-du.v4-Y-Z-1   18s   Completed   The cluster template validation succeeded
----
+
A `STATE` of `Completed` with a `ClusterTemplateValidated` condition of `True` indicates that the template passed validation and is ready for use. After successful validation, the `ClusterTemplate` CR and its referenced `ConfigMap` CRs become immutable.
