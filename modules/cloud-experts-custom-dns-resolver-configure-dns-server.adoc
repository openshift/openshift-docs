= Configure your DNS server

[role="_abstract product:rosa"]
Configure your Domain Name System (DNS) server to forward the private hosted zones to your Amazon Route 53 Inbound Resolver so the {product-title} cluster can resolve internal DNS names after creation.

[role="product:rosa"]
--
The following private hosted zones must be forwarded:

* `<cluster-name>.hypershift.local`
* `rosa.<domain-prefix>.<unique-ID>.p3.openshiftapps.com`

These Amazon Route 53 private hosted zones are created during cluster creation. The `cluster-name` and `domain-prefix` are customer-specified values, but the `unique-ID` is randomly generated during cluster creation and cannot be preselected. As such, you must wait for the cluster creation process to begin before configuring forwarding for the `p3.openshiftapps.com` private hosted zone.
--

[role="_abstract product:rosa-classic"]
Configure your Domain Name System (DNS) server to forward the private hosted zone to your Amazon Route 53 Inbound Resolver so the {product-title} cluster can resolve internal DNS names after creation.

[role="product:rosa-classic"]
--
The following private hosted zone must be forwarded:

* `<domain-prefix>.<unique-ID>.p1.openshiftapps.com`

This Amazon Route 53 private hosted zone is created during cluster creation. The `domain-prefix` is a customer-specified value, but the `unique-ID` is randomly generated during cluster creation and cannot be preselected. As such, you must wait for the cluster creation process to begin before configuring forwarding for the `p1.openshiftapps.com` private hosted zone.
--

.Procedure
. [.product:rosa]#{empty}# Before the cluster is created, configure your DNS server to forward all DNS requests for `<cluster-name>.hypershift.local` to your Amazon Route 53 Inbound Resolver endpoints.
+
If you use a BIND DNS server, add a new zone to the `/etc/named.conf` file using the following example:
+
[source,terminal]
----
zone "<cluster-name>.hypershift.local" {
  type forward;
  forward only;
  forwarders {
    10.0.45.253;
    10.0.23.131;
    10.0.148.159;
  };
};
----
+
--
* Replace `<cluster-name>` with your {product-title} cluster name.
* Replace with the IP addresses of your inbound resolver endpoints collected above, ensuring that following each IP address there is a `;`.
--

. Create your cluster.

. After your cluster has begun the creation process, locate the newly created private hosted zone:
+
[source,terminal]
----
$ aws route53 list-hosted-zones-by-vpc \
  --vpc-id ${VPC_ID} \
  --vpc-region ${REGION} \
  --query 'HostedZoneSummaries[*].Name' \
  --output table
----
+
.Example output
[source,text,role="product:rosa"]
----
--------------------------------------------------
|             ListHostedZonesByVPC               |
+------------------------------------------------+
|  rosa.domain-prefix.lkmb.p3.openshiftapps.com. |
|  cluster-name.hypershift.local.                |
+------------------------------------------------+
----
[source,text,role="product:rosa-classic"]
----
----------------------------------------------
|           ListHostedZonesByVPC             |
+--------------------------------------------+
|  domain-prefix.agls.p1.openshiftapps.com.  |
+--------------------------------------------+
----
+
[NOTE]
====
[.product:rosa]#It may take a few minutes for the cluster creation process to create the private hosted zones in Route 53. If you do not see a `p3.openshiftapps.com` domain, wait a few minutes and run the command again.#
[.product:rosa-classic]#It may take a few minutes for the cluster creation process to create the private hosted zones in Route 53. If you do not see a `p1.openshiftapps.com` domain, wait a few minutes and run the command again.#
====

If you use a BIND DNS server, add a new zone to the `/etc/named.conf` file using the following example:

[source,terminal]
----
zone "rosa.<domain-prefix>.<unique-ID>.p3.openshiftapps.com" {
  type forward;
  forward only;
  forwarders {
    10.0.45.253;
    10.0.23.131;
    10.0.148.159;
  };

----
