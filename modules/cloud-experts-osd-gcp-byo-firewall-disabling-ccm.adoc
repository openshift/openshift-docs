= Disabling CCM firewall management

[role="_abstract"]
With BYO firewall rules, the customer owns all firewall rules. The Cloud Controller Manager (CCM) must be told not to create or delete firewall rules when `LoadBalancer` services are created or deleted. CCM continues to manage the load balancer resources such as forwarding rules and target pools; only its firewall operations are disabled.

The CCM reads its cloud config from the `cloud-conf` config map in the `openshift-cloud-controller-manager` namespace. This config map is managed by a sync controller. Patching it directly will be reverted within seconds.

The correct approach is to patch the source config map. Changes propagate automatically through a three-stage sync chain:

. `openshift-config/cloud-provider-config` (key: `config`)
. `openshift-config-managed/kube-cloud-config` (key: `cloud.conf`)
. `openshift-cloud-controller-manager/cloud-conf` (key: `cloud.conf`)

.Procedure
. Read the current cloud config, set `firewall-rules-management` to `Disabled`, and patch it back:
+
[source,terminal]
----
$ CURRENT_CONFIG=$(oc get configmap cloud-provider-config -n openshift-config \
  -o jsonpath='{.data.config}')
$ if echo "$CURRENT_CONFIG" | grep -q 'firewall-rules-management'; then
    NEW_CONFIG=$(echo "$CURRENT_CONFIG" | \
      sed 's/firewall-rules-management = Enabled/firewall-rules-management = Disabled/')
  else
    NEW_CONFIG="${CURRENT_CONFIG}
  firewall-rules-management = Disabled"
  fi
$ oc patch configmap cloud-provider-config -n openshift-config \
  --type merge \
  --patch "$(jq -n --arg config "$NEW_CONFIG" '{data: {config: $config}}')"
----

. Wait approximately 30 seconds for the sync controllers to propagate the change.

. Restart the CCM pods to pick up the new config:
+
[source,terminal]
----
$ oc delete pods -n openshift-cloud-controller-manager \
  -l k8s-app=gcp-cloud-controller-manager
----

.Verification
. Verify the flag propagated to the source config map:
+
[source,terminal]
----
$ oc get cm cloud-provider-config -n openshift-config \
  -o jsonpath='{.data.config}' | grep firewall
----

. Verify the flag propagated to the intermediate config map:
+
[source,terminal]
----
$ oc get cm kube-cloud-config -n openshift-config-managed \
  -o jsonpath='{.data.cloud\.conf}' | grep firewall
----

. Verify the flag propagated to the CCM config map:
+
[source,terminal]
----
$ oc get cm cloud-conf -n openshift-cloud-controller-manager \
  -o jsonpath='{.data.cloud\.conf}' | grep firewall
----
+
All three commands should output `firewall-rules-management = Disabled`.

. Check the CCM logs for the disabled flag:
+
[source,terminal]
----
$ oc logs -n openshift-cloud-controller-manager \
  -l k8s-app=gcp-cloud-controller-manager --tail=50 | grep -i firewall
----
+
The logs should contain entries with `firewall rules are unmanaged`, confirming that firewall operations are being skipped. The exact function names and message format may vary across {product-title} versions.
