= Configure hardware profiles for bare-metal nodes

[role="_abstract"]
You can optionally define a `HardwareProfile` custom resource (CR) to specify the desired firmware levels and BIOS settings for a class of bare-metal servers. The O-Cloud Manager applies the hardware profile during provisioning to ensure servers meet the required hardware state before cluster installation begins.

[NOTE]
====
Hardware profiles are optional. If you do not specify a hardware profile, the O-Cloud Manager skips firmware and BIOS configuration during provisioning and uses the server in its current hardware state.
====

.Prerequisites

* The O-Cloud Manager Operator is installed on the hub cluster.
* You know the target firmware versions and BIOS settings for your server hardware.

.Procedure

. Create a `HardwareProfile` CR that defines the desired hardware state, such as the following example:
+
[source,yaml]
----
apiVersion: clcm.openshift.io/v1alpha1
kind: HardwareProfile
metadata:
  name: <hardware_profile_name>
  namespace: oran-o2ims
spec:
  bios:
    attributes:
      BootMode: Uefi
      <bios_attribute_name>: <bios_attribute_value>
  bmcFirmware:
    version: "<bmc_firmware_version>"
    url: "<bmc_firmware_url>"
  biosFirmware:
    version: "<bios_firmware_version>"
    url: "<bios_firmware_url>"
  nicFirmware:
    - version: "<nic_firmware_version>"
      url: "<nic_firmware_url>"
----
+
where:
+
`<hardware_profile_name>`:: Specifies a descriptive name for the hardware profile, for example `server-type-bios-settings`.
The `HardwareProfile` CR must be created in the O-Cloud Manager Operator namespace, `oran-o2ims`, regardless of the namespace where the `ClusterTemplate` CR is stored.
`spec.bios.attributes`:: Defines the desired BIOS settings as key-value pairs.
`spec.bmcFirmware`:: Defines the target BMC controller firmware. Configure a `version` and an optional `url` pointing to the firmware binary.
`spec.biosFirmware`:: Defines the target BIOS firmware. Configure a `version` and an optional `url` pointing to the firmware binary.
`spec.nicFirmware`:: Defines the target NIC firmware as a list, allowing you to specify firmware for multiple NICs. Each entry configures a `version` and an optional `url` pointing to the firmware binary.
+
[NOTE]
====
All firmware fields are optional. Specify only the components you need to manage. For example, you can define only `spec.bios.attributes` without any firmware fields if firmware management is not required.
====

. Apply the `HardwareProfile` resource to the hub cluster, or commit it to the `hardwareprofiles/` directory in the GitOps repository for ArgoCD synchronization.

.Verification

* Verify that the `HardwareProfile` resource exists on the hub cluster:
+
[source,terminal]
----
$ oc get hardwareprofiles.clcm.openshift.io -A
----
