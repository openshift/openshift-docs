= Workload identity and post-quantum key exchange

[role="_abstract"]
SPIRE issues X.509 and JWT {svid-full} credentials that workloads present during mutual Transport Layer Security (mTLS). The workload TLS stack negotiates the key-exchange group for that connection.

Two workloads whose TLS stacks implement hybrid Module-Lattice-Based Key-Encapsulation Mechanism (ML-KEM) can negotiate a hybrid group over TLS 1.3 by using SPIRE-issued identities. A workload whose TLS stack implements only classical key exchange continues to use a classical group.

In a service mesh, the mesh data plane selects the mTLS key-exchange group. The SPIFFE identity from SPIRE identifies the workload. The mesh keeps its own TLS negotiation.

The following behavior stays in place with this capability:

* X.509 and JWT SVID signatures use the signature algorithms configured for SPIRE, such as RSA or ECDSA. Post-quantum signatures, such as Module-Lattice-Based Digital Signature Algorithm (ML-DSA), are a separate capability.
* TLS for the {product-title} control plane, including the Kubernetes API server and etcd, follows the cluster control-plane configuration.
* Workload mTLS uses the key-exchange group negotiated by each workload TLS stack.
