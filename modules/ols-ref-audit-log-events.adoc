= Audit log event types

[role="_abstract"]
Reference information for the audit events emitted by {ols-long} and agentic {ols-long} when audit logging is enabled.

== Common fields

Every audit log entry contains the following fields, regardless of the event type or component that emits it:

[cols="2,1,4",options="header"]
|===
| Field | Type | Description

| `event`
| string
| Event type identifier. See the event tables in this topic for valid values.

| `trace_id`
| string
| Correlation identifier for the interaction. For {ols-long}: derived from the `conversation_id` with hyphens removed. For agentic {ols-long}: derived from the `AgenticRun` `metadata.uid` with hyphens removed. Doubles as the OTEL trace ID.

| `timestamp`
| string (ISO 8601)
| Time at which the event occurred, in UTC.

| `user_id`
| string
| Identifier of the user who initiated the interaction.

| `component`
| string
| Name of the component that emitted the event, for example `lightspeed-service` or `lightspeed-agentic-operator`.

|===

== {ols-long} events

The following events are emitted by the `lightspeed-service` component for Q&A and troubleshooting interactions:

[cols="2,4",options="header"]
|===
| Event | Description

| `query.received`
| A user query was received by the service. Marks the start of an auditable interaction.

| `response.sent`
| The LLM response was returned to the user. Marks the end of the interaction.

| `tool.call.started`
| An MCP tool call was initiated as part of processing the query.

| `tool.call.completed`
| An MCP tool call completed successfully.

| `tool.call.failed`
| An MCP tool call returned an error.

|===

== Agentic {ols-long} events

The following events are emitted by the `lightspeed-agentic-operator` and `lightspeed-agentic-sandbox` components for autonomous operations:

[cols="2,4",options="header"]
|===
| Event | Description

| `proposal.created`
| The AI generated an `AgenticRun` resource describing a set of proposed cluster operations.

| `proposal.approval.requested`
| A human approval gate was triggered. The system is waiting for an authorized approver.

| `proposal.approved`
| An authorized user approved the proposal. The `approver_id` field is present on this event.

| `proposal.rejected`
| An authorized user rejected the proposal. The `approver_id` field is present on this event.

| `proposal.executed`
| The approved operations were executed against the cluster.

| `proposal.failed`
| Execution of the approved operations failed.

| `tool.call.started`
| A specific MCP tool call was initiated by the agentic sandbox.

| `tool.call.completed`
| A tool call completed successfully. Includes the tool name and a result summary.

| `tool.call.failed`
| A tool call returned an error. Includes the tool name and the error detail.

|===

== Additional fields for approval events

Events with type `proposal.approved` or `proposal.rejected` include the following additional field:

[cols="2,1,4",options="header"]
|===
| Field | Type | Description

| `approver_id`
| string
| Identity of the user who approved or rejected the proposal, as injected by the mutating webhook on the `AgenticRun` `PATCH` request. This field is present regardless of the approval path used: console, `kubectl`, or API.

|===
