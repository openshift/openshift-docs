The {otel} 3.11.2 release resolves these Common Vulnerabilities and Exposures (CVEs):

`golang.org/x/mod/sumdb` verifies module content against the transparency log::
Before this update, `golang.org/x/mod/sumdb`, the Go module checksum verification package, could be compromised when a malicious Go checksum database (GOSUMDB) served module content not recorded in the transparency log. As a consequence, a coordinated Go proxy (GOPROXY) and GOSUMDB could deliver malicious module content to clients without detection, potentially enabling a supply chain compromise. With this update, the package verifies module content against the transparency log. As a result, clients can detect and reject malicious content served by a coordinated proxy and GOSUMDB.
+
link:https://access.redhat.com/security/cve/cve-2026-56864[CVE-2026-56864]
+
link:https://redhat.atlassian.net/browse/TRACING-6792[TRACING-6792]

`golang.org/x/mod/sumdb/tlog` validates sumdb tiles::
Before this update, `golang.org/x/mod/sumdb/tlog`, the Go module transparency log package, could not detect forged sumdb tiles. As a consequence, a malicious Go proxy (GOPROXY) could forge tiles and bypass integrity checks. This could serve malicious module content to the local Go module cache without detection. Users could unknowingly incorporate compromised modules. With this update, the package validates sumdb tiles. As a result, forged tiles are detected and rejected, preventing malicious content from reaching the module cache.
+
link:https://access.redhat.com/security/cve/cve-2026-56865[CVE-2026-56865]
+
link:https://redhat.atlassian.net/browse/TRACING-6793[TRACING-6793]

gRPC-Go servers no longer fail when receiving fragmented HTTP/2 DATA frames::
Before this update, an unauthenticated remote attacker could exhaust process memory by sending millions of fragmented HTTP/2 DATA frames. As a consequence, each fragmented frame was stored as a separate message, consuming disproportionate heap memory and leading to a runtime panic or out-of-memory termination, which caused a denial of service (DoS). With this update, the gRPC-Go library properly handles fragmented HTTP/2 frames. As a result, servers no longer exhaust memory or crash when receiving fragmented DATA frames.
+
link:https://access.redhat.com/security/cve/cve-2026-84304[CVE-2026-84304]
+
link:https://redhat.atlassian.net/browse/TRACING-6883[TRACING-6883]
+
link:https://redhat.atlassian.net/browse/TRACING-6884[TRACING-6884]

gRPC-Go servers no longer fail when receiving malformed RPC requests::
Before this update, servers created with the `xds.NewGRPCServer()` constructor could be exploited by a remote client sending a malformed remote procedure call (RPC) request lacking required headers. As a consequence, this caused an index-out-of-bounds panic that terminated the entire server process, resulting in a denial of service (DoS). In some deployments, unauthenticated clients could trigger this attack. With this update, gRPC-Go, the Go implementation of gRPC, validates headers in RPC requests. As a result, servers no longer fail when receiving malformed RPC requests.
+
link:https://access.redhat.com/security/cve/cve-2026-84445[CVE-2026-84445]
