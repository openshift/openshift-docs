= Syslog Exporter

[role="_abstract"]
The Syslog Exporter sends logs to a syslog server in the RFC 5424 or RFC 3164 format. With this exporter, you can forward logs to security information and event management (SIEM) systems and to compliance archives that consume syslog.

:FeatureName: The Syslog Exporter
include::snippets/technology-preview.adoc[]
:!FeatureName:

The exporter supports logs only. It does not use the log body. Copy the log body to the `message` attribute, and set the other syslog fields as log attributes, for example with the Transform Processor.

The following `OpenTelemetryCollector` custom resource configures the Syslog Exporter:

[source,yaml]
----
# ...
  volumeMounts:
    - name: syslog-ca
      mountPath: /etc/syslog-ca
  volumes:
    - name: syslog-ca
      secret:
        secretName: syslog-ca
  config:
    processors:
      transform:
        log_statements:
          - context: log
            statements:
              - set(log.attributes["message"], log.body.string)
              - set(log.attributes["appname"], "otel-collector")
    exporters:
      syslog:
        endpoint: siem.example.com
        port: 6514
        network: tcp
        protocol: rfc5424
        enable_octet_counting: true
        tls:
          ca_file: /etc/syslog-ca/ca.crt
        sending_queue:
          enabled: true
        retry_on_failure:
          enabled: true
    service:
      pipelines:
        logs:
          receivers: [otlp]
          processors: [transform]
          exporters: [syslog]
# ...
----
where:

`endpoint`:: Hostname or IP address of the syslog server, without a port number. When `network` is `unix`, the path to the UNIX socket. You must set this option.
`port`:: Port of the syslog server, in the range `1` to `65535`. The default is `514`. The exporter connects to the address `<endpoint>:<port>`, so do not add a port number to `endpoint`. This setting is not used with `unix`.
`network`:: Transport for the connection. The supported values are `tcp`, `udp`, and `unix`. The default is `tcp`.
`protocol`:: Format of the syslog messages. The supported values are `rfc5424` and `rfc3164`. The default is `rfc5424`.
`enable_octet_counting`:: Frames each message with its length, as defined in RFC 6587. This setting is supported only with `protocol: rfc5424`. The default is `false`.
`tls`:: TLS settings of the connection, for example `ca_file`, `cert_file`, and `key_file`. TLS applies to the `tcp` network only and is on by default. To connect to a server without TLS, set `tls.insecure: true`.
`sending_queue`:: Optional: Queue that buffers the messages before they are sent. The queue is off unless you configure it. When enabled, it uses 10 consumers and a queue size of `1000` requests by default.
`retry_on_failure`:: Optional: Retry settings for messages that cannot be sent. Retries are on by default, with an initial interval of `5s`, a maximum interval of `30s`, and a maximum elapsed time of `5m`.
`timeout`:: Time limit for the connection to the syslog server. The default is `5s`.

The exporter reads the following log attributes to build a syslog message:

[options="header"]
[cols="a,a,a"]
|===
|Attribute |Syslog field |Default value

|`priority`
|PRI. The value is an integer, `facility * 8 + severity`. The exporter does not derive it from the severity of the log.
|`165`

|`version`
|VERSION (`rfc5424` only)
|`1`

|`hostname`
|HOSTNAME
|`-`

|`appname`
|APP-NAME
|`-`

|`proc_id`
|PROCID (`rfc5424` only)
|`-`

|`msg_id`
|MSGID (`rfc5424` only)
|`-`

|`structured_data`
|STRUCTURED-DATA (`rfc5424` only). The value must be a map of maps with string values, for example `{"sd-id": {"param": "value"}}`. The exporter ignores other values.
|`-`

|`message`
|MSG
|Empty. The exporter does not use the log body.

|===

[WARNING]
====
Attribute values that contain line breaks can forge additional syslog messages. When you use `network: tcp` without `enable_octet_counting`, or `protocol: rfc3164`, the receiving server treats a line break as the end of a message. As a result, someone who controls the content of a log attribute, such as the message, can inject messages that the SIEM system records as genuine. This is a known issue of the upstream exporter.

To avoid this problem, use `protocol: rfc5424` with `enable_octet_counting: true`, or remove line breaks from the attributes before you export them. For example, add the following statement to the Transform Processor:

[source,yaml]
----
- replace_pattern(log.attributes["message"], "[\r\n]+", " ")
----
====

== Comparison with the syslog output of {logging-uc}

If you already forward logs over syslog with {logging-uc}, the following table shows which Syslog Exporter setting corresponds to which setting of the syslog output in the `ClusterLogForwarder` custom resource.

[options="header"]
[cols="a,a"]
|===
|{logging-uc} setting |Syslog Exporter equivalent

|`url` with the `tcp`, `tls`, or `udp` scheme
|`endpoint` and `port`, `network` (`tcp` or `udp`), and `tls`

|`rfc`
|`protocol`

|`appName`
|`appname` attribute

|`procId`
|`proc_id` attribute

|`msgId`
|`msg_id` attribute

|`payloadKey`
|`message` attribute. Copy the field with the Transform Processor.

|`facility` and `severity`
|`priority` attribute. Calculate `facility * 8 + severity` with the Transform Processor.

|`enrichment`
|Add the Kubernetes data to the message with the Kubernetes Attributes Processor and the Transform Processor.

|`tuning.deliveryMode`
|`sending_queue` and `retry_on_failure`
|===

For more information about forwarding logs over syslog with {logging-uc}, see the link:https://docs.redhat.com/en/documentation/red_hat_openshift_logging/latest/html-single/configure/index#cluster-logging-collector-log-forward-syslog_configuring-log-forwarding[syslog forwarding section] of the {logging-uc} documentation.
