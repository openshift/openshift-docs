= How automated postinstallation configuration works

[role="_abstract"]
The `virt-platform-autopilot` controller replaces manual postinstallation steps by applying opinionated defaults that optimize virtual machine (VM) performance, availability, and resource usage.

[id="virt-about-platform-autopilot-managed-configurations_{context}"]
== Managed configurations

After you install {VirtProductName}, the `virt-platform-autopilot` controller evaluates the cluster state and applies configurations that optimize virtual machine (VM) performance.
The `virt-platform-autopilot` controller continuously reconciles managed resources to keep the expected state and correct configuration drift.

The `virt-platform-autopilot` controller manages the following configurations:

Descheduler:: Configures the {descheduler-operator} to evict and rebalance VM workloads across nodes.
This improves resource distribution and reduces the risk of hotspots.

Node health checks:: Deploys `NodeHealthCheck` resources through medik8s to automate node remediation.
When a node becomes unhealthy, the system recovers VM workloads to available nodes.

Memory overcommit and SWAP:: Enables kernel same-page merging (KSM) and SWAP support to increase VM density per node.
These settings allow more VMs to run on each node by optimizing memory usage.

PSI metrics:: Enables pressure stall information (PSI) metrics collection through `MachineConfig` resources.
PSI metrics show CPU, memory, and I/O pressure at the node level to help you identify resource bottlenecks.

Multipath:: Configures device-mapper multipath through `MachineConfig` resources for reliable storage access across several paths.

Logging:: Aggregates virtualization-related logs when explicitly enabled.
Unlike other managed configurations, logging is not enabled by default and requires explicit opt-in.

[id="virt-about-platform-autopilot-opt-in-and-opt-out-behavior_{context}"]
== Opt-in and opt-out behavior

The `virt-platform-autopilot` controller enables most managed configurations by default.
You can opt out of any individual configuration by setting the corresponding managed resource to unmanaged mode.
When you set a resource to unmanaged mode, the `virt-platform-autopilot` controller stops reconciling it.
You can then apply your own configuration without the `virt-platform-autopilot` controller reverting your changes.

Logging is the exception to the default-enabled model and requires explicit opt-in.

[id="virt-about-platform-autopilot-pre-flight-validation_{context}"]
== Pre-flight validation

Before applying configurations, the `virt-platform-autopilot` controller validates the cluster state to check that the required resources and Operators are available.
If a required Operator or resource is missing, the `virt-platform-autopilot` controller skips that configuration and logs a warning.
This prevents the `virt-platform-autopilot` controller from applying partial or broken configurations.

[id="virt-about-platform-autopilot-reconciliation-and-anti-thrashing-behavior_{context}"]
== Reconciliation and anti-thrashing behavior

The `virt-platform-autopilot` controller continuously reconciles managed resources to keep the expected state.
If an external process changes a managed resource, the `virt-platform-autopilot` controller detects the drift and restores the expected state.

To prevent thrashing, the `virt-platform-autopilot` controller monitors the rate of changes to managed resources.
If the `virt-platform-autopilot` controller detects rapid or repeated changes, it pauses reconciliation for the affected resources.
This prevents a loop where the `virt-platform-autopilot` controller and another controller repeatedly overwrite each other's changes.
You can monitor paused resources by using the `kubevirt_vpa_paused_resources` metric.
