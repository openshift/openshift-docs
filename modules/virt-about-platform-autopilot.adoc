= How automated postinstallation configuration works

[role="_abstract"]
The `virt-platform-autopilot` controller continuously reconciles managed resources to keep the expected state and correct configuration drift.
It also configures optional components such as the {descheduler-operator} and the {coo-full} if they are installed.

[id="virt-about-platform-autopilot-managed-configurations_{context}"]
== Managed configurations

After you install {VirtProductName}, the `virt-platform-autopilot` controller evaluates the cluster state and applies configurations to the virtualization platform.
It also configures optional components such as the {descheduler-operator} and the {coo-full} if they are installed.
The `virt-platform-autopilot` controller continuously reconciles managed resources to keep the expected state and correct configuration drift.

The `virt-platform-autopilot` controller manages the following configurations:

In-flight operations:: Coordinates safe concurrent operations on virtual machines by using `OperationRuleSet` resources.

kubelet performance:: Applies optimized kubelet settings for virtualization workloads.

Load-aware descheduler:: Configures the {descheduler-operator} to balance VM workloads across nodes based on CPU and memory use.
Requires the {descheduler-operator} to be installed.

Observability:: Enables Prometheus metrics, alerting rules, and dashboards for virtualization workloads.
Requires the {coo-full} to be installed.

SWAP:: Enables swap support on worker nodes to increase VM density.

[id="virt-about-platform-autopilot-opt-in-and-opt-out-behavior_{context}"]
== Opt-in and opt-out behavior

The `virt-platform-autopilot` controller enables most managed configurations by default.
You can customize or opt out of managed configurations by using the following levels of control:

JSON Patch Override:: Customize specific values in a managed resource while keeping the resource managed.
Add a `platform.kubevirt.io/patch` annotation with a JSON Patch document.

Field masking:: Exclude specific fields from management so that the `virt-platform-autopilot` controller ignores them during reconciliation.
Add a `platform.kubevirt.io/ignore-fields` annotation with a comma-separated list of JSON pointer paths.

Full opt-out:: Stop managing a resource entirely.
Set the `platform.kubevirt.io/mode` annotation to `unmanaged`.
The `virt-platform-autopilot` controller stops reconciling the resource and you can modify it freely.

All three levels use declarative annotations that are compatible with GitOps workflows.

[id="virt-about-platform-autopilot-soft-dependency-model_{context}"]
== Soft dependency model

The `virt-platform-autopilot` controller does not install optional components.
It configures components that are already installed on the cluster.
If an optional component is not installed, the `virt-platform-autopilot` controller skips that configuration and continues without error.

When you install an optional component later, the `virt-platform-autopilot` controller detects it on the next reconciliation cycle and applies the relevant configuration automatically.

[id="virt-about-platform-autopilot-reconciliation-and-anti-thrashing-behavior_{context}"]
== Reconciliation and anti-thrashing behavior

The `virt-platform-autopilot` controller continuously reconciles managed resources to keep the expected state.
If an external process changes a managed resource, the `virt-platform-autopilot` controller detects the drift and restores the expected state.

To prevent thrashing, the `virt-platform-autopilot` controller monitors the rate of changes to managed resources.
If the `virt-platform-autopilot` controller detects rapid or repeated changes, it pauses reconciliation for the affected resources.
This prevents a loop where the `virt-platform-autopilot` controller and another controller repeatedly overwrite each other's changes.
You can monitor paused resources by using the `kubevirt_autopilot_paused_resources` metric.
