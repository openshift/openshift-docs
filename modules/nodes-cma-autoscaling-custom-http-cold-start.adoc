= Configure HTTP cold-start behavior

[role="_abstract"]
You can control what clients receive while a workload scales up from zero replicas. By default, the interceptor holds the request until a pod is ready. You can return a placeholder response immediately, send later requests to a fallback service after the readiness timeout, or do both.

Cold-start handling applies when `minReplicaCount` on the scaled object is `0` and the workload has no ready pods. The readiness limit is `spec.timeouts.readiness` on the `InterceptorRoute` resource.

.Prerequisites

* An `InterceptorRoute` resource exists for the workload.
* The scaled object sets `minReplicaCount` to `0`.

.Procedure

. Choose how the interceptor responds while the workload scales up from zero replicas.
+
To return a static response while the workload starts, and still count the request so that scaling proceeds, set `spec.coldStart.placeholder`:
+
.Example cold-start placeholder
[source,yaml]
----
spec:
  coldStart:
    placeholder:
      response:
        body: Starting <1>
        headers:
          Content-Type: text/plain
          Refresh: "5" <2>
        statusCode: 503 <3>
----
<1> Specifies the response body.
<2> Optional: Asks the client to retry after five seconds.
<3> Specifies the HTTP status code.
+
To send requests to another service after the readiness timeout, set `spec.coldStart.fallback`. The fallback service must be in the same namespace as the `InterceptorRoute` resource:
+
.Example cold-start fallback service
[source,yaml]
----
spec:
  coldStart:
    fallback:
      service:
        name: fallback-app <1>
        port: 8080 <2>
  timeouts:
    readiness: 5s <3>
----
<1> Specifies the fallback service name.
<2> Specifies the fallback service port.
<3> Specifies how long the interceptor waits for the target workload before using the fallback service. If you omit the fallback service, the interceptor returns HTTP `504` when this timeout expires.
+
When you set both `placeholder` and `fallback`, the interceptor returns the placeholder immediately. If the workload is still not ready when the readiness timeout expires, later requests go to the fallback service.

. Apply the updated resource by running the following command:
+
[source,terminal]
----
$ oc apply -f interceptorroute.yaml
----
