= Configure secure communications between the agent and the FlowLogs Pipeline

[role="_abstract"]
You can configure Transport Layer Security (TLS) or mutual TLS (mTLS) to secure communications between the eBPF agents and the FlowLogs Pipeline (FLP). By default, communications are secured automatically using OpenShift service CA annotations with zero configuration required.

.Prerequisites

* You have installed the Network Observability Operator.
* You have cluster administrator permissions.

.Procedure

. In the web console, go to *Ecosystem* -> *Installed Operators* page.
. Under the *Provided APIs* heading for *Network Observability*, select *Flow Collector*.
. Select *cluster* then select the *YAML* tab.
. Configure the `FlowCollector` CR for agent TLS settings. A sample configuration is as follows:
+
[id="network-observability-flowcollector-agent-tls_{context}"]
.Example `FlowCollector` CR for agent TLS configuration
[source, yaml]
----
apiVersion: flows.netobserv.io/v1beta2
kind: FlowCollector
metadata:
  name: cluster
spec:
  agent:
    ebpf:
      flowFilter:
        enable: true
      tls:
        type: AUTO
        caCert:
          type: certManager
          certManager:
            name: my-ca-cert
        userCert:
          type: secret
          secret:
            name: my-user-cert
            namespace: netobserv
# ...
----
+
where:

`spec.agent.ebpf.tls.type`:: Specifies the TLS configuration mode:
+
--
* `AUTO` (default): Communications are automatically secured by using OpenShift service CA annotations. This provides TLS encryption with zero configuration.
* `DISABLED`: TLS is disabled. Communications between agents and FLP are not encrypted. Use this option only in development or testing environments.
* `PROVIDED`: You provide your own certificates for TLS or mutual TLS. This option requires additional configuration by using the `caCert` and `userCert` fields.
--

`spec.agent.ebpf.tls.caCert.type`:: When using `PROVIDED` type, specifies how the Certificate Authority (CA) certificate is provided. Valid values are `certManager` or `secret`.

`spec.agent.ebpf.tls.caCert.certManager.name`:: When using `certManager` type, specifies the name of the cert-manager certificate.

`spec.agent.ebpf.tls.userCert.type`:: When using `PROVIDED` type and mutual TLS, specifies how the user certificate is provided. Valid value is `secret`.

`spec.agent.ebpf.tls.userCert.secret.name`:: The name of the secret containing the user certificate for mutual TLS.

`spec.agent.ebpf.tls.userCert.secret.namespace`:: The namespace where the user certificate secret is located.

.Verification

. After configuring TLS, verify that the agents are communicating securely with FLP:
+
[source,terminal]
----
$ oc logs -n netobserv deployment/netobserv-plugin | grep -i tls
----
+
.Example output
[source,terminal]
----
TLS enabled for agent-to-FLP communication
----
+
[NOTE]
====
Using the `AUTO` mode provides the best balance of security and ease of use for most deployments. Consider using `PROVIDED` mode only if you have specific certificate requirements or are integrating with an existing Public Key Infrastructure (PKI).

When using mutual TLS (mTLS) with the `PROVIDED` mode, both the CA certificate and user certificate must be configured. The FLP verifies the agent certificate, and the agent verifies the FLP certificate.
====
