= Check a disconnected {prodname} installation

[role="_abstract"]
If the Kuadrant Operator or its managed components are not ready after a disconnected installation, check the mirrored catalog, Operator installation, and component pods to find the cause.

.Prerequisites

* You completed a disconnected installation of {prodname}.

.Procedure

. Verify that the {prodname} Operator package is available in the mirrored catalog by running the following command:
+
[source,terminal]
----
$ oc get packagemanifest rhcl-operator -n openshift-marketplace
----
+
If the package is missing, check that the mirrored catalog is ready and that the `ImageSetConfiguration` includes the `rhcl-operator` package.

. Check the {prodname} Operator `Subscription` and `ClusterServiceVersion` (CSV) by running the following commands:
+
[source,terminal,subs="+quotes"]
----
$ oc get subscription rhcl-operator -n _<kuadrant_system>_
$ oc get csv -n _<kuadrant_system>_
----
+
Replace `_<kuadrant_system>_` with the namespace in which you installed {prodname}. The {prodname} Operator CSV should show `Succeeded`. If it does not, inspect the `InstallPlan` in the same namespace for errors.

. If the Operator is installed but its managed components are not ready, check the `Kuadrant` custom resource (CR) and pods by running the following commands:
+
[source,terminal,subs="+quotes"]
----
$ oc describe kuadrant kuadrant -n _<kuadrant_system>_
$ oc get pods -n _<kuadrant_system>_
$ oc get events -n _<kuadrant_system>_ --field-selector reason=Failed
----
+
Replace `_<kuadrant_system>_` with the namespace in which you installed {prodname}. Check the `Kuadrant` CR conditions and pod status for errors. If events show image pull failures, verify that the required images were mirrored and that the cluster image mirror configuration points to your registry. The Kuadrant Operator manages the included components through Helm charts; they do not require separate OLM packages.
