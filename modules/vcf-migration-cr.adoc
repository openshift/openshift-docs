= VmwareCloudFoundationMigration custom resource reference

[role="_abstract"]
The `VmwareCloudFoundationMigration` custom resource (CR) defines the desired state of a cluster migration.
You create one CR named `cluster` in the `openshift-vcf-migration` namespace to configure and control the migration workflow.

The CR uses the API group `migration.openshift.io/v1alpha1` and has the short name `vcfm`.

== Spec fields

.`VmwareCloudFoundationMigrationSpec` fields
[cols="2,1,1,1,3", options="header"]
|===
|Field
|Type
|Required
|Default
|Description

|`spec.state`
|`string`
|No
|`Pending`
|Controls the migration workflow. Valid values are `Pending`, `Running`, and `Paused`. The operator only acts when the state is `Running`. Set to `Paused` to pause the migration at any point. The migration resumes from where it left off when set back to `Running`.

|`spec.targetVCenterCredentialsSecret`
|`object`
|Yes
|
|References the secret that contains the target vCenter credentials. The secret must contain keys in the format `<vcenter_fqdn>.username` and `<vcenter_fqdn>.password`.

|`spec.targetVCenterCredentialsSecret.name`
|`string`
|Yes
|
|The name of the secret.

|`spec.targetVCenterCredentialsSecret.namespace`
|`string`
|No
|Migration CR namespace
|The namespace of the secret. When omitted, defaults to the namespace of the `VmwareCloudFoundationMigration` object.

|`spec.failureDomains`
|`array`
|Yes (minimum 1)
|
|One or more target failure domains. Each element uses the OpenShift `VSpherePlatformFailureDomainSpec` type from the `config.openshift.io/v1` API. Failure domain names must be unique.

|`spec.image`
|`object`
|No
|
|Controls RHCOS OVA resolution and import. When set (even as an empty object `{}`), the operator downloads the OVA and imports it as a VM template for each failure domain. When omitted, you must set `topology.template` manually in each failure domain.

|`spec.image.ovaUrl`
|`string`
|No
|Auto-resolved
|A direct `https://` URL to the RHCOS OVA file. The URL must end in `.ova` (an optional query string is allowed). When set, the operator downloads from this URL instead of resolving from the `coreos-bootimages` ConfigMap. Required for air-gapped environments: point to an internal HTTPS mirror.

|`spec.image.diskProvisioning`
|`string`
|No
|OVF descriptor default
|The VMDK disk provisioning type when importing the OVA. Valid values are `thin`, `thick`, and `eagerZeroedThick`.

|`spec.nodeMigration`
|`object`
|No
|
|Controls how nodes move to the target vCenter. When omitted, the operator uses the MachineSet and ControlPlaneMachineSet replacement path (Recreate). When set, both `workers` and `controlPlane` fields are required.

|`spec.nodeMigration.workers`
|`object`
|Yes (when `nodeMigration` is set)
|
|Migration engine and rolling limits for worker nodes.

|`spec.nodeMigration.controlPlane`
|`object`
|Yes (when `nodeMigration` is set)
|
|Migration engine and rolling limits for control plane nodes. The `maxUnavailable` value is validated to `1` for this role.

|`spec.nodeMigration.<role>.type`
|`string`
|No
|`Recreate`
|The migration engine for this role. Valid values are `VMotion` (relocate existing VMs) and `Recreate` (replace VMs by using `MachineSets` or `ControlPlaneMachineSet`). When omitted, defaults to `Recreate`.

|`spec.nodeMigration.<role>.vmotion`
|`object`
|Conditional
|
|VMotion-specific behavior. Required when `type` is `VMotion`. Forbidden when `type` is `Recreate`.

|`spec.nodeMigration.<role>.vmotion.mode`
|`string`
|No
|`Auto`
|The relocation mode. Valid values are `Auto` (try hot, fall back to cold), `Hot` (live relocation), and `Cold` (powered-off relocation).

|`spec.nodeMigration.<role>.maxUnavailable`
|`int` or `string`
|No
|`1`
|The maximum number of nodes in this role that can migrate simultaneously. Can be an integer (for example, `1`) or a percentage (for example, `"25%"`). Control plane is validated to `1`.
|===

== Failure domain topology fields

Each entry in `spec.failureDomains` specifies the target vCenter topology.

.Failure domain fields
[cols="2,1,1,3", options="header"]
|===
|Field
|Type
|Required
|Description

|`name`
|`string`
|Yes
|A unique name for the failure domain (1-256 characters).

|`region`
|`string`
|Yes
|The region tag name, using the `openshift-region` tag category (1-80 characters).

|`zone`
|`string`
|Yes
|The zone tag name, using the `openshift-zone` tag category (1-80 characters).

|`server`
|`string`
|Yes
|The fully qualified domain name of the target vCenter (1-255 characters).

|`topology.datacenter`
|`string`
|Yes
|The data center name on the target vCenter (maximum 80 characters).

|`topology.computeCluster`
|`string`
|Yes
|The path to the compute cluster, in the format `/<data_center>/host/<cluster>`.

|`topology.datastore`
|`string`
|Yes
|The path to the datastore, in the format `/<data_center>/datastore/<datastore>`.

|`topology.networks`
|`array`
|Yes (minimum 1)
|One or more port group network names.

|`topology.resourcePool`
|`string`
|No
|The path to the resource pool, in the format `/<data_center>/host/<cluster>/Resources/<pool>`.

|`topology.folder`
|`string`
|No
|The path to the VM folder, in the format `/<data_center>/vm/<folder>`.

|`topology.template`
|`string`
|Conditional
|The path to the VM template. Required when `spec.image` is not set. When `spec.image` is set, the operator imports the OVA and populates this field automatically.
|===

== Status conditions

The operator updates status conditions as the migration progresses.
Each condition transitions from `False` (progressing) to `True` (completed) in order.

.Migration status conditions
[cols="2,3", options="header"]
|===
|Condition type
|Description

|`Accepted`
|Admission gate. `True` for the singleton instance named `cluster`. `False` with reason `UnsupportedName` for any other object name.

|`InfrastructurePrepared`
|Preflight checks passed, including cluster health, vCenter connectivity, target topology validation, privilege verification, and storage management state.

|`DestinationInitialized`
|Target vCenter VM folders and topology tags (`openshift-region`, `openshift-zone`) created.

|`DestinationImageImported`
|RHCOS OVA imported as a VM template on the target vCenter. Immediately `True` when `spec.image` is not set.

|`MultiSiteConfigured`
|Cluster recognizes both the source and target vCenters. Secrets, the `Infrastructure` custom resource, and cloud provider configuration are updated.

|`WorkloadMigrated`
|Workers created on the target vCenter, control plane rolled out, source `MachineSets` scaled to zero and deleted.

|`SourceCleaned`
|Source vCenter fully detached from the cluster configuration.

|`Ready`
|Migration is complete. All cluster operators are healthy, `MachineConfigPools` are stable, and only the target vCenter remains in the `Infrastructure` custom resource.
|===

.Condition reasons
[cols="1,2", options="header"]
|===
|Reason
|Description

|`Progressing`
|The phase is in progress.

|`Completed`
|The phase completed successfully.

|`Failed`
|The phase encountered a terminal failure.

|`Paused`
|The migration is paused because `spec.state` is set to `Paused`.

|`Retrying`
|The operator hit a transient condition and will automatically retry. This is not a terminal state.

|`UnsupportedName`
|The CR name is not `cluster`, so the operator ignores it.
|===

== Node migration status

When `spec.nodeMigration` is set, the status includes per-node progress information.
Each node progresses through the following phases:

.Node migration phases
[cols="1,2", options="header"]
|===
|Phase
|Description

|`Pending`
|The node is discovered but has not started migration.

|`Preparing`
|For cold VMotion, the node is being drained and cordoned. For hot VMotion, live-compatibility checks are running.

|`Migrating`
|The `RelocateVM` task is running on vCenter.

|`WaitingForNode`
|The VM is on the target vCenter, but the kubelet is not yet reporting `Ready`.

|`Succeeded`
|The node is `Ready` on the target vCenter.

|`Failed`
|The node migration failed. Check the `message` field for details.
|===

== Example CR

The following example shows a minimal `VmwareCloudFoundationMigration` CR with automatic image import:

[source,yaml]
----
apiVersion: migration.openshift.io/v1alpha1
kind: VmwareCloudFoundationMigration
metadata:
  name: cluster
  namespace: openshift-vcf-migration
spec:
  state: Pending
  targetVCenterCredentialsSecret:
    name: target-vcenter-creds
  image: {}
  failureDomains:
    - name: target-fd-1
      region: target-region
      zone: target-zone-1
      server: vcenter-target.example.com
      topology:
        datacenter: TargetDC
        computeCluster: /TargetDC/host/TargetCluster
        datastore: /TargetDC/datastore/TargetDatastore
        networks:
          - "VM Network"
        resourcePool: /TargetDC/host/TargetCluster/Resources
        folder: /TargetDC/vm/my-cluster-infra-id
----

The following example shows a CR that uses VMotion for both worker and control plane nodes:

[source,yaml]
----
apiVersion: migration.openshift.io/v1alpha1
kind: VmwareCloudFoundationMigration
metadata:
  name: cluster
  namespace: openshift-vcf-migration
spec:
  state: Pending
  targetVCenterCredentialsSecret:
    name: target-vcenter-creds
  nodeMigration:
    workers:
      type: VMotion
      vmotion:
        mode: Auto
      maxUnavailable: "25%"
    controlPlane:
      type: VMotion
      vmotion:
        mode: Hot
      maxUnavailable: 1
  failureDomains:
    - name: target-fd-1
      region: target-region
      zone: target-zone-1
      server: vcenter-target.example.com
      topology:
        datacenter: TargetDC
        computeCluster: /TargetDC/host/TargetCluster
        datastore: /TargetDC/datastore/TargetDatastore
        networks:
          - "VM Network"
        resourcePool: /TargetDC/host/TargetCluster/Resources
        folder: /TargetDC/vm/my-cluster-infra-id
        template: /TargetDC/vm/my-cluster-infra-id/rhcos-vmware.x86_64
----
+
[NOTE]
====
When `spec.image` is not set, each failure domain must include a `topology.template` value that references an existing RHCOS VM template on the target vCenter.
The operator uses this template as a fallback for the Recreate migration path.
====
