= How {ols-long} autonomous agents configuration works

[role="_abstract"]
{ols-long} autonomous agents extends {ols-long} with autonomous, tool-calling workflows that can analyze, remediate, and verify changes in your {ocp-product-title} cluster. You configure {ols-long} autonomous agents by using a chain of cluster-scoped custom resources (CRs).

[NOTE]
====
{ols-long} autonomous agents uses the agentic deployment custom resources in the `agentic.openshift.io/v1alpha1` API group. The `OLSConfig` provider list used by the {ols-long} intelligent assistant and the `apitoken` credentials secret key do not apply to this configuration.
====

{ols-long} autonomous agents uses the following custom resources:

`LLMProvider`::
A cluster-scoped CR that defines the connection to a large language model (LLM) provider, including the provider type, credentials, and endpoint. The `LLMProvider` CR does not specify a model; it defines the provider connection only. You typically create one `LLMProvider` CR for each provider backend.

`Agent`::
A cluster-scoped CR that pairs an `LLMProvider` with a specific model and runtime settings, such as timeouts and reasoning configuration. Because the model is defined on the `Agent` CR, multiple agents can share one `LLMProvider` with different models. You must create an `Agent` named `default`. When a workflow step does not name a specific agent, the deployment falls back to the `default` agent, so the deployment cannot run workflows without it.

`AgenticRun`::
A namespaced CR that requests an autonomous workflow and references agents by name for each step. You create `AgenticRun` resources to run workflows after you configure the `LLMProvider` and `Agent` resources.

`AgenticOLSConfig`::
An optional cluster-scoped singleton CR that controls system-wide autonomous behavior. The CR must be named `cluster`. It governs cluster-wide suspension only, through the `spec.suspended` field, and does not configure providers or models. When `spec.suspended` is `true`, all non-terminal autonomous runs are stopped and no new workflow steps start. When no `AgenticOLSConfig` CR exists, the system behaves as though `spec.suspended` is `false`, so the CR is not required for normal operation.

The resources form a chain: an `AgenticRun` references an `Agent`, and an `Agent` references an `LLMProvider`. To configure a working deployment, you create the credentials secret, the `LLMProvider` CR, and at least the `default` `Agent` CR.

[NOTE]
====
Red{nbsp}Hat does not provide support for any specific models or make suggestions or support statements pertaining to models. Model quality affects autonomous and tool-calling outcomes, so results can vary by model.
====
