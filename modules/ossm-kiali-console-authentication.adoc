= Authentication on {ocp-product-title}

[role="_abstract"]

On {ocp-product-title}, the Kiali console uses {ocp-short-name} authentication by default. A user signs in with the {ocp-product-title} login page, and the console shows only the namespaces that user can access.

{KialiProduct} creates the {ocp-short-name} OAuth client that the console needs. You do not have to set an authentication strategy unless you want to make the choice explicit:

[source,yaml]
----
spec:
  auth:
    strategy: openshift
----

The `openshift` strategy supports namespace access control and both single-cluster and multi-cluster meshes.

== Multi-cluster login

{ocp-short-name} OAuth does not provide single sign-on across clusters. A user logs in to the cluster where {KialiServer} runs, then uses the user menu in the console to log in to each remote cluster.

Deploy Kiali with the same namespace and the same instance name on every cluster that runs a Kiali server. The default namespace is `istio-system` and the default instance name is `kiali`. Set them with `spec.deployment.namespace` and `spec.deployment.instance_name` in the `Kiali` custom resource.

The `OAuthClient` object on every cluster must be named `<instance_name>-<namespace>`. For the defaults, that name is `kiali-istio-system`. If the names differ, login fails.

On a remote cluster that does not run {KialiServer}, install {KialiProduct} and set `spec.deployment.remote_cluster_resources_only` to `true`. Also set `spec.auth.openshift.redirect_uris` to the callback URL of the Kiali route on the home cluster, including the remote cluster name:

[source,yaml]
----
spec:
  auth:
    openshift:
      redirect_uris:
        - https://kiali-istio-system.apps.east.example.com/api/auth/callback/west
  deployment:
    remote_cluster_resources_only: true
----

Replace the host with the Kiali route on the cluster where {KialiServer} runs, and replace `west` with the {istio} cluster name of the remote cluster. The callback path must end with that cluster name. The path `/api/auth/callback` without the cluster name fails with a missing-cookie error.

To read the route host on the home cluster, run:

[source,terminal]
----
$ oc get route -l app.kubernetes.io/name=kiali -n istio-system -o jsonpath='{..spec.host}'
----
