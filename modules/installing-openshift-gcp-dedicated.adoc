= Install {product-title} on Google Cloud Dedicated

[role="_abstract"]
You can install {product-title} on Google Cloud Dedicated by using installer-provisioned infrastructure.
This procedure guides you through configuring the `install-config.yaml` file with parameters specific to Google Cloud Dedicated and running the installation.

.Prerequisites

* You have a Google Cloud Dedicated project with a domain-scoped project ID, for example `eu0:my-project`. The installation program detects sovereign environments from known project ID prefixes such as `eu0`.
* You have obtained service account credentials from the sovereign universe with adequate permissions to create cluster resources.
* You have prepared a custom {op-system} image accessible within your Google Cloud Dedicated project, with both the image name and project identified.
* You have configured network connectivity to the Google Cloud Dedicated environment through VPN or Cloud Interconnect, because only private clusters are supported on Google Cloud Dedicated.
* If you are using KMS encryption, you have created a Cloud KMS key ring in the same region where you are deploying the cluster.
* You have downloaded the {product-title} installation program.

.Procedure

. Create a directory to store the installation files:
+
[source,terminal]
----
$ mkdir <installation_directory>
----

. Generate the `install-config.yaml` file:
+
[source,terminal]
----
$ openshift-install create install-config --dir <installation_directory>
----

. Edit the `install-config.yaml` file to configure the parameters specific to Google Cloud Dedicated.
+
The following example shows a minimal `install-config.yaml` file for a Google Cloud Dedicated installation in a German sovereign region:
+
[source,yaml]
----
apiVersion: v1
baseDomain: example.com
metadata:
  name: my-gcd-cluster
publish: Internal
pullSecret: '{"auths": ...}'
sshKey: 'ssh-ed25519 AAAA...'
controlPlane:
  name: master
  replicas: 3
compute:
- name: worker
  replicas: 3
platform:
  gcp:
    projectID: eu0:my-project <1>
    region: europe-west3 <2>
    defaultMachinePlatform:
      osImage: <3>
        name: my-rhcos-image
        project: eu0:my-image-project
----
+
--
Where:

`eu0:my-project`:: The domain-scoped project ID for your Google Cloud Dedicated project. Replace with your actual Google Cloud Dedicated project ID.
`europe-west3`:: The sovereign region where you want to deploy the cluster. Valid Google Cloud Dedicated regions include `europe-west3`, `europe-west4`, and `u-france-east1`.
`osImage`:: The custom {op-system} image. On Google Cloud Dedicated, you must specify both `name` and `project` because standard {op-system} images on public {gcp-short} are not accessible from the sovereign universe.
--

. Optional: To encrypt cluster storage with a customer-managed KMS key, add the following section under `defaultMachinePlatform`:
+
[source,yaml]
----
    defaultMachinePlatform:
      osDisk:
        encryptionKey:
          kmsKey:
            name: my-encryption-key
            keyRing: my-key-ring
            location: europe-west3
            projectID: eu0:my-project
----
+
The KMS key encrypts operating system disks, the bootstrap ignition storage bucket, and the internal image registry storage bucket.

. Create the cluster:
+
[source,terminal]
----
$ openshift-install create cluster --dir <installation_directory>
----
+
The installation program detects the Google Cloud Dedicated sovereign cloud environment from the domain-scoped project ID and automatically configures sovereign-specific defaults, including `hyperdisk-balanced` disk types.

.Verification

. After the installation completes, verify that you can access the cluster API through your private network connection:
+
[source,terminal]
----
$ export KUBECONFIG=<installation_directory>/auth/kubeconfig
$ oc get nodes
----

. Verify that the default storage class uses `hyperdisk-balanced`:
+
[source,terminal]
----
$ oc get storageclass
----
+
The default storage class should show `pd.csi.storage.gke.io` as the provisioner with `hyperdisk-balanced` as the type parameter.
If the default storage class does not show `hyperdisk-balanced`, you might need to create a `StorageClass` manually.

. Verify that all cluster operators are available:
+
[source,terminal]
----
$ oc get clusteroperators
----
+
All Operators should show `Available: True` and `Degraded: False`.

. If you configured KMS encryption, verify that the cluster infrastructure reflects your KMS configuration:
+
[source,terminal]
----
$ oc get infrastructure cluster -o jsonpath='{.status.platformStatus.gcp}' | jq .
----
+
You can also verify KMS encryption on storage buckets directly in the GCP console by navigating to the Cloud Storage bucket details and confirming the encryption type shows your customer-managed key.

[NOTE]
====
If the installation fails, check `<installation_directory>/.openshift_install.log` for details.
Common failure causes specific to Google Cloud Dedicated include network connectivity issues to sovereign APIs, insufficient KMS permissions, inaccessible custom operating system images, or setting `publish: External` (which fails because Google Cloud Dedicated lacks public DNS zones and global load balancers).
====
