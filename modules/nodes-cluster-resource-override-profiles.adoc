= Project-level resource overrides

[role="_abstract"]
You can use a `ResourceOverride` custom resource (CR) to set CPU and memory override ratios for pods in one {product-title} project. Use a project override when pods in that project need ratios that differ from the cluster-wide `ClusterResourceOverride` object.

The Cluster Resource Override admission webhook changes pods only in projects that have the `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled: "true"` label. For more information about the label, see xref:#nodes-cluster-resource-override_{context}[Cluster-level overcommit].

If a pod in a project with this label matches a `ResourceOverride` object in that project, the webhook applies the ratios in the `ResourceOverride` object. If no `ResourceOverride` object matches the pod, the webhook applies ratios in the `ClusterResourceOverride` object named `cluster`.

When you omit `spec.podSelector`, or leave it empty, a `ResourceOverride` object applies to every pod in its project. If that object’s name comes first in alphabetical order, the webhook applies it to pods that also match an object with a narrower selector. The `spec.podSelector` field limits the object to pods with matching labels, such as stateless application pods.

[NOTE]
====
If more than one `ResourceOverride` object in the project matches a pod, the webhook applies the object whose `metadata.name` parameter comes first in alphabetical order. It records an `OverrideConflict` warning event on each matching object that it does not apply.
====

Users with the `admin` or `edit` role on the project can create, update, and delete `ResourceOverride` objects. Users with the `view` role can read them.

For steps to create an object, see Create a project-level resource override.
