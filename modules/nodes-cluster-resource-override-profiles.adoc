= Project-level resource overrides

[role="_abstract"]
You can use a `ResourceOverride` custom resource (CR) to set CPU and memory override ratios for pods in a specific {product-title} project. Use a project override when pods in that project need ratios that differ from the cluster-wide `ClusterResourceOverride` object.

The Cluster Resource Override admission webhook changes pods only in projects that have the `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled: "true"` label. For more information about the label, see "Cluster-level overcommit using the Cluster Resource Override Operator" in this section.

If a pod in a project with this label matches the `spec.podSelector` parameter in a `ResourceOverride` object in that project, the webhook applies the ratios in the `ResourceOverride` object. For pods that do not match the `ResourceOverride` pod selector, the webhook applies ratios in the `ClusterResourceOverride` object named `cluster`. If you omit the pod selector or leave the parameter value empty, the webhook applies the `ResourceOverride` ratios to every pod in the project.

[NOTE]
====
If more than one `ResourceOverride` object in the project matches a pod, the webhook applies the object whose `metadata.name` parameter comes first in alphabetical order. Any other matching objects are not used. The webhook records an `OverrideConflict` warning event on each matching object that it does not apply.
====

Users with the `admin` or `edit` role on the project can create, update, and delete `ResourceOverride` objects. Users with the `view` role can read them.

For steps to create an object, see Create a project-level resource override.
