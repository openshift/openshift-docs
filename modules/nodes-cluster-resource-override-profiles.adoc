= Project-level resource overrides

[role="_abstract"]
You can use a `ResourceOverride` custom resource (CR) to set CPU and memory override ratios for pods in one {product-title} project. Use a project override when pods in that project need ratios that differ from the cluster-wide `ClusterResourceOverride` object.

The Cluster Resource Override admission webhook changes pods only in projects that have the `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled: "true"` label. Projects must have the label for the cluster profile and for project overrides. For more information about the label, see xref:#nodes-cluster-resource-override_{context}[Cluster-level overcommit].

If a pod in a project with this label matches a `ResourceOverride` object in that project, the webhook applies that object's ratios. If no `ResourceOverride` object matches the pod, the webhook applies the `ClusterResourceOverride` object named `cluster`.

When you omit `spec.podSelector`, or leave it empty, a `ResourceOverride` object applies to every pod in its project. The `spec.podSelector` field limits the object to pods with matching labels, such as stateless application pods.

[NOTE]
====
If more than one `ResourceOverride` object matches a pod, the webhook applies one object and records an `OverrideConflict` warning on the others. For the selection rule, see xref:#nodes-cluster-resource-override-profiles-conflict_{context}[Resource override conflicts].
====

Users with the `admin` or `edit` role on the project can create, update, and delete `ResourceOverride` objects. Users with the `view` role can read them. A cluster administrator creates the `ClusterResourceOverride` object that installs the webhook.

For steps to create an object, see xref:#nodes-cluster-resource-override-profiles-creating_{context}[Create a project-level resource override].
