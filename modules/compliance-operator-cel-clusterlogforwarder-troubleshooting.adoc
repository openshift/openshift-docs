= Troubleshooting ClusterLogForwarder CEL checks

[role="_abstract"]
Resolve common issues when you run the ClusterLogForwarder secure-endpoints CEL example.

If the scan stays in the `RUNNING` phase, check the scanner pod logs by running the following commands:
+
[source,terminal]
----
$ oc get pods -n openshift-compliance -l compliance-scan=logging-security-checks
$ oc logs -n openshift-compliance <scanner_pod_name>
----

If all resources show `PASS` but you expect failures, verify that the `kubernetesInputSpec` API version matches your logging Operator version by running the following command:
+
[source,terminal]
----
$ oc api-resources | grep clusterlogforwarder
----
+
If your cluster uses `logging.openshift.io/v1`, update the `kubernetesInputSpec` in the `CustomRule` object.

To remove the example resources, run the following commands:
+
[source,terminal]
----
$ oc delete scansettingbinding logging-security-scan -n openshift-compliance
$ oc delete tailoredprofile logging-security-checks -n openshift-compliance
$ oc delete customrule clusterlogforwarder-secure-endpoints -n openshift-compliance
----
