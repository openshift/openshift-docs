= Understanding Operator installation policy

[role="_abstract"]
Operator authors specify the permissions requested by an Operator in the cluster service version (CSV). By default, Operator Lifecycle Manager (OLM) uses `cluster-admin` privileges to grant those permissions.

Before delegating Operator installation privileges, complete the following checks:

* Review the permissions requested by the Operator.
* Identify namespaces with an Operator group that does not specify a service account.
* In each identified namespace, identify non-administrator users or groups that can create subscriptions. Check whether the same users or groups can also create service account tokens or pods.

If a user or group can create subscriptions and also create service account tokens or pods in an identified namespace, take one of the following actions:

* Configure the Operator group to use a service account with only the permissions approved for installation.
* Restrict the permissions granted to the user or group.

To limit the permissions used during Operator installation and upgrades, associate the Operator group with a service account that has the minimum required role-based access control (RBAC) permissions. OLM uses the permissions granted to the associated service account during installation and upgrades, except when creating `APIService` and `CustomResourceDefinition` resources.

include::snippets/olmv0-cluster-scoped-rbac-warning.adoc[]

[NOTE]
====
Users with permission to create `Subscription` objects can start Operator installations in a namespace that has an Operator group, even if those users cannot create `OperatorGroup` objects. Before creating an Operator group, review who can create subscriptions in the namespace and configure the permissions that OLM can use for installation.
====

Keep the following points in mind when associating an Operator group with a service account:

* The `APIService` and `CustomResourceDefinition` resources are always created by OLM using the `cluster-admin` role. Do not grant the service account associated with the Operator group permissions to write these resources.

* If OLM cannot create a required resource with the permissions granted to the specified service account, the installation fails. A failed installation does not automatically remove permissions already created. Inspect the service account used by the failed Operator for active cluster role bindings. Delete the remaining `ClusterRoleBinding` objects created by the failed installation.
