= Mesh infrastructure status

[role="_abstract"]

The console watches the {istio} control plane and the observability services that the mesh depends on. If a component is missing or unhealthy, the masthead shows a status indicator. The color is the severity. Hover over the indicator to read which component failed.

A component status is one of the following:

* `Not found`: {KialiServer} cannot find the deployment.
* `Not ready`: No pods are running.
* `Unreachable`: {KialiServer} cannot reach the service, such as Prometheus or tracing.
* `Not healthy`: The deployment does not have the requested number of replicas.
* `Healthy`: The component is omitted from the problem list.

Core components are errors and appear in red. Add-on components are warnings and appear in orange. By default, the core set is istiod, ingress, and egress in the control plane namespace. The add-on set is Prometheus and the tracing service you configure. On {ocp-product-title}, Prometheus is the in-cluster monitoring stack, and tracing is {TempoName} when you enable it.

== Mesh page

The Mesh page is a topology of those components and the connections among them. Select a node to open the side panel. With no selection, the panel lists status, version, and cluster for every component. A red dotted edge means {KialiServer} cannot reach that component.

{KialiServer}:: Version, health, and the values from the `Kiali` custom resource.

{istio} control plane:: Version, mTLS status, outbound traffic policy, CPU and memory, and the control plane configuration.

Control plane namespace:: How many namespaces each control plane revision manages. Use this view when you move workloads between revisions.

Data plane:: Health, configuration, and inbound and outbound traffic for the namespaces in that data plane, similar to the Overview page.

Observability services:: Health and connection status for Prometheus and, when configured, {TempoName}.
