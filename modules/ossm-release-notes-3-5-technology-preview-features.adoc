= {SMProductName} version 3.5 Technology Preview features

[role="_abstract"]

This release includes some features that are currently in Technology Preview. These experimental features are not intended for production use.

For more information about the support scope of Red Hat Technology Preview features, see link:https://access.redhat.com/support/offerings/techpreview/[Technology Preview Features Support Scope].

External VM workload integration (Technology Preview)::
You can include external RHEL virtual machine workloads in {SMProduct}, whether they are managed by Red Hat OpenShift Virtualization or running as standalone VMs.
+
A Red Hat-built RPM package installs the Istio proxy on the external VM, so that the VM joins the mesh. The Istio control plane manages the VM workload. As a result, the VM workload benefits from standard mesh capabilities, such as mutual TLS, observability, traffic management, and authorization policies.
+
Mesh management of external VM workloads is a Technology Preview feature.
+
link:https://redhat.atlassian.net/browse/OSSM-12577[OSSM-12577]

New Kiali perspective for monitoring service meshes on RHACM-managed clusters (Technology Preview)::
If you run meshes on clusters managed by Red Hat Advanced Cluster Management for Kubernetes (RHACM), the OpenShift Service Mesh Console offers a new perspective: the Fleet Service Mesh perspective. It provides a hub-wide inventory of Istio meshes and control planes across the RHACM fleet.
+
The Fleet Service Mesh perspective is a Technology Preview feature.
+
For more information, see link:https://github.com/kiali/openshift-servicemesh-plugin/blob/main/docs/fleet-mesh/TECH-PREVIEW-GUIDE.md[OSSMC Fleet Service Mesh Technical Preview].
+
link:https://redhat.atlassian.net/browse/OSSM-15976[OSSM-15976]

Automated metric scraping configuration for Istio telemetry (Technology Preview)::
Metric scraping for the Istio control plane and sidecar proxies can be automatically configured, enabling you to view mesh metrics in Prometheus, Kiali, and the OpenShift web console without manually creating monitoring resources.
+
To enable automated metric scraping, add the `sailoperator.io/monitoring: enabled` annotation to an `Istio` custom resource. The Sail Operator reconciles `ServiceMonitor` and `PodMonitor` resources with default metrics scraping configuration for each mesh. Existing `ServiceMonitor` and `PodMonitor` resources that you created manually are not overwritten.
+
Automated metric scraping configuration is a Technology Preview feature.
+
link:https://redhat.atlassian.net/browse/OSSM-8471[OSSM-8471]

Weighted waypoint canaries (Technology Preview)::
In Istio ambient mode, you can safely test configuration and version updates to waypoint proxies before rolling them out across your mesh. Use this feature to run a canary waypoint alongside your primary waypoint and shift a configurable percentage of traffic to verify changes under real conditions. Services and namespaces reference the canary proxy by using the `istio.io/use-waypoint-canary` and `istio.io/use-waypoint-canary-namespace` labels, with the traffic split controlled by the `istio.io/use-waypoint-canary-weight` annotation.
+
Weighted waypoint canary proxies are a Technology Preview feature.
+
For more information, see the upstream Istio release documentation: link:https://istio.io/latest/news/releases/1.31.x/announcing-1.31/change-notes[Istio 1.31 change notes].
