= Skip-version upgrades with the RevisionBased strategy

[role="_abstract"]
For more efficient upgrades that minimize workload disruption, you can upgrade sidecar mode deployments two versions at a time with the `RevisionBased` update strategy.

[#how-skipping-a-version-works_{context}]
== How skipping a version works

You skip one Operator minor version and upgrade directly from _n_ to _n+2_. For example, you can upgrade directly from {SMProductShortName} 3.3 to 3.5, which requires only one workload restart instead of multiple restarts at each intermediate version.

During the upgrade process, both the old and new control plane versions operate concurrently.
Existing proxies remain attached to the old version until you restart the workloads.

[#requirements-and-considerations_{context}]
== Supported configurations and guidelines

Review the supported configurations and operational guidelines before upgrading with the skip-version method:     

* *Sidecar mode required.* Ambient mode still requires sequential minor version upgrades.

* *`RevisionBased` strategy required.* The `InPlace` update strategy still requires upgrading one minor version at a time.

* *No workload changes during upgrade.* Wait until the upgrade is complete before modifying the mesh topology.

* *Single version skip only.* You can skip only one minor version at a time. To skip more versions, repeat the complete upgrade procedure for each version skip.

* *Best practice: Longer grace period for validation.* Consider increasing the `inactiveRevisionDeletionGracePeriodSeconds` parameter in the {istio} resource to validate the new version before the process removes the old revision. The default grace period for deleting inactive revisions might not provide enough time for extended validation.

* *Release notes for the skipped version.* Read the release notes for the skipped version to understand the full range of changes and features resulting from the upgrade.
