= Prevent automatic network observability installation during upgrades

[role="_abstract"]
You can configure the Network custom resource (CR) to prevent the Cluster Network Operator (CNO) from automatically installing network observability during a cluster upgrade.

[NOTE]
====
Since automatic network observability installation is a Technology Preview feature in {product-title} 5.0, network observability is not installed automatically during upgrades unless you enable the `NetworkObservabilityInstall` feature gate. If the feature gate is disabled, network observability is not installed, and this procedure is not needed.
====

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* The {ocp-first} is installed.

.Procedure

. Before upgrading your cluster, configure the Network CR to prevent automatic network observability installation. Choose one of the following methods:
+
* Use the `oc patch` command:
+
[source,terminal]
----
$ oc patch network.config.openshift.io cluster --type=merge -p '
spec:
  networkObservability:
    installationPolicy: NoAction
'
----
+
* Alternatively, edit the Network CR manually:
+
[source,terminal]
----
$ oc edit network.config.openshift.io cluster
----
+
Add the `NoAction` installation policy to the `spec` section:
+
[source,yaml]
----
apiVersion: config.openshift.io/v1
kind: Network
metadata:
  name: cluster
spec:
  networkObservability:
    installationPolicy: NoAction
# ...
----
+
Save and close the file to apply the changes.

. Proceed with the cluster upgrade. The CNO skips the network observability installation during and after the upgrade process.
