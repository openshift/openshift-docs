= Troubleshoot DPU provisioning failures

[role="_abstract"]
Use this procedure to diagnose and resolve DPU provisioning issues, including BFB download failures, hardware detection problems, and provisioning timeouts.

.Prerequisites

* You have access to the management cluster as a user with the `cluster-admin` role.
* DPU-equipped worker nodes have been added to the cluster.

.Procedure

. Verify that the BFB image is accessible and downloaded:
+
[source,terminal]
----
$ oc get bfb -n dpf-operator-system bf-bundle -o yaml
----
+
Check the `status.conditions` field for download progress and any error messages.

. If the BFB download fails, verify the image URL:
+
[source,terminal]
----
$ curl -I $BFB_URL
----
+
Ensure that the URL returns a `200 OK` status and that the cluster can access the external registry.

. Check the DPU detection by the Node Feature Discovery (NFD) Operator:
+
[source,terminal]
----
$ oc get nodes -o json | jq -r '.items[] | select(.metadata.labels."feature.node.kubernetes.io/dpu-enabled") | .metadata.name'
----
+
If no nodes are returned:
+
.. Verify that the NFD Operator is installed and running:
+
[source,terminal]
----
$ oc get pods -n openshift-nfd
----
+
.. Check the NFD configuration for DPU detection rules:
+
[source,terminal]
----
$ oc get nodefeaturerule -n openshift-nfd
----

. Monitor DPU provisioning progress:
+
[source,terminal]
----
$ oc get dpu -n dpf-operator-system -w
----
+
Wait for DPU objects to progress through the following phases:
+
* `Pending`
* `Provisioning`
* `Ready`

. If provisioning fails or times out, check the provisioning logs:
+
[source,terminal]
----
$ oc logs -n dpf-operator-system -l app.kubernetes.io/name=dpf-operator -c manager --tail=50
----
+
Look for error messages related to:
+
* BFB image extraction failures
* Network connectivity issues
* Hardware compatibility problems
* Timeout errors

. Verify the DPU hardware state by accessing the worker node directly:
+
[source,terminal]
----
$ oc debug node/<worker-node-name>
----
+
[source,terminal]
----
sh-4.4# chroot /host
sh-4.4# lspci | grep -i mellanox
----
+
Confirm that the BlueField DPU is detected by the system.

. Check the DPU firmware version and compatibility:
+
[source,terminal]
----
sh-4.4# mlxfwmanager --query
----
+
Ensure that the firmware version is compatible with the DOCA Platform Framework.

.Troubleshooting tips

**BFB download issues:**::
* Verify network connectivity to the image registry
* Check firewall rules and proxy configurations
* Ensure sufficient disk space on worker nodes

**Hardware detection failures:**::
* Verify that the BlueField DPU is properly seated
* Check BIOS settings for PCIe configuration
* Ensure that the DPU is not disabled in hardware

**Provisioning timeouts:**::
* Increase timeout values in the DPF operator configuration
* Verify that the DPU has sufficient power and cooling
* Check for hardware errors in system logs

**Network configuration issues:**::
* Verify VLAN and network segmentation settings
* Ensure that required ports are open between nodes
* Check MTU settings across the network path
