= Configure cluster-wide token rate limit reservations

[role="_abstract"]
As a platform engineer, you can configure how {prodname} reserves token capacity for requests to LLM APIs. You can select the cluster-wide token rate limiting mode and set the maximum amount and duration of each reservation.

.Prerequisites

* You installed {prodname} on the {ocp} cluster you are working with.
* You have permissions to update the `Kuadrant` and `Limitador` custom resources (CRs).

.Procedure

. Update the existing `spec.tokenRateLimiting.mode` parameter in the `Kuadrant` CR:
+
[source,yaml]
----
spec:
  tokenRateLimiting:
    mode: Reservation
----
+
* `Reservation` is the default. Requests reserve estimated token capacity before being forwarded. Actual usage is committed when the response completes.
* `CheckReport` checks capacity before forwarding requests and records actual usage afterward, without reserving capacity for requests in progress.
+
The selected mode applies to all `TokenRateLimitPolicy` resources managed by this Kuadrant installation.

. Optional: Configure reservation safeguards in the existing `Limitador` CR:
+
[source,yaml]
----
spec:
  reservations:
    enabled: true
    maxFraction: 0.5
    maxTtl: 60s
----
+
* The `enabled` parameter enables reservation support. The default is `true`.
* The `maxFraction` parameter sets the maximum for each reservation as a fraction of the token limit. The default is set to `0.5`. For example, a 10,000 token limit permits a single reservation of up to 5,000 tokens.
* The `maxTtl` parameter sets the maximum for how long a reservation can hold capacity. The default is set to `60s`.
+
These safeguards limit reserved capacity. Actual token usage is recorded when the request completes, even if it exceeds the reserved amount.

.Verification

* Confirm that the resources contain the configured mode and reservation settings.
* With a `TokenRateLimitPolicy` applied, send concurrent requests to the protected API.
* Confirm that completed requests release their reservations and record actual token usage.
