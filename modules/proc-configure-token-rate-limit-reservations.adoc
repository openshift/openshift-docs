= Configure cluster-wide token rate limit reservations

[role="_abstract"]
As a platform engineer, you can ensure that {prodname} uses reservation mode for token-based rate limiting of requests to LLM APIs.

When several requests are in progress at once, checking only recorded token usage can allow them all through before their usage is counted. Reservations hold estimated token capacity while each request is in progress, helping prevent concurrent requests from exceeding the limit.

The `reservation.amount` parameter defaults to `0` for each limit. If the `reservation` block or its `amount` parameter is omitted, no capacity is held for requests in progress, even when the cluster-wide mode is `Reservation`.

.Prerequisites

* You installed {prodname} on the {ocp} cluster you are working with.
* You have permissions to view the `Kuadrant` custom resource (CR).

.Procedure

* Confirm that `spec.tokenRateLimiting.mode` in the `Kuadrant` CR is either unset or set to `Reservation`.
+
** `Reservation` is the default. Requests reserve estimated token capacity before being forwarded when the matching limit specifies a nonzero `reservation.amount`. Actual usage is committed when the response completes.
** `Optimistic` checks capacity before forwarding requests and records actual usage afterward, without reserving capacity for requests in progress.
+
The selected mode applies to all `TokenRateLimitPolicy` resources managed by this Kuadrant installation.

.Verification

* With `Reservation` mode active and a nonzero `reservation.amount` configured for the matching limit, send concurrent requests to the protected API.
* Confirm that completed requests release their reservations and record actual token usage.
