== Fixed issues

New warning message for resource tracking method changes during upgrade::
Starting with {gitops-title} 1.19, the {gitops-title} Operator uses annotation-based tracking instead of label-based tracking as the default resource tracking method. When upgrading from an earlier version that does not explicitly set `.spec.resourceTrackingMethod`, resources that are managed by controllers other than Argo CD, such as Namespaces, Subscriptions, and Secrets, might show a difference in their labels, and the Application status changes to `OutOfSync`. For Secret resources specifically, syncing the application deletes the labels that other controllers manage or add. This behavior occurs even when `ignoreDifferences` is added to the Application.
+
With this update, the {gitops-title} Operator now logs a warning message during the upgrade, when the resource tracking method changes, so that users can identify and address the issue before syncing their applications:
+
[source,terminal]
----
WARNING: resource tracking method in argocd-cm is changing from 'label' to the default 'annotation' because .spec.resourceTrackingMethod is not set. Managed resources will re-sync to apply the new tracking method and may report OutOfSync; a sync can remove controller-managed labels from Secrets. Set .spec.resourceTrackingMethod to 'label' to keep the current behaviour.
----
+
To avoid these issues, users should explicitly configure `.spec.resourceTrackingMethod` in the Argo CD CR before starting the upgrade to continue using label-based tracking:
+
[source,yaml]
----
apiVersion: argoproj.io/v1beta1
kind: ArgoCD
metadata:
  name: example-argocd
spec:
  resourceTrackingMethod: label
----
