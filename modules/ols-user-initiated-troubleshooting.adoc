= User-initiated troubleshooting in {ols-long}

[role="_abstract"]
When a cluster alert triggers, you need reliable data to respond effectively. The {ols-long} troubleshooting workflow automatically investigates alerts and compiles evidence, helping you determine how best to incorporate it into your incident response strategy.

{ols-long} integrates with the {ocp-short-name} Model Context Protocol (MCP) server to automate alert investigation and telemetry analysis. You can use this capability to correlate metrics, logs, and events into a single causal chain without parsing raw telemetry data.

{ols-long} includes the following capabilities:

* *OpenShift MCP integration*: Queries real-time metrics, status reasons, and restart counts directly from Prometheus. The agent can also run Prometheus range queries to fetch historical data for baseline comparisons.

* *Visual chart rendering*: Displays dynamic, real-time Perses charts that the {ols-long} Service generates in the chat interface to support hypotheses and historical overlays, instead of outputting raw JSON.
+
For more information, see xref:ols-generating-perses-dashboards.adoc#ols-generating-perses-dashboards[Generating Perses dashboards using {ols-long}].

* *Evidence generation*: Synthesizes telemetry into a Root Cause Analysis (RCA) evidence summary that maps the source, signal, and finding to establish a clear causal chain.

* *Read-only operation*: Formulates read-only hypotheses and recommended next steps. The assistant does not run cluster changes without explicit user approval.

* *Cross-namespace correlation*: Identifies and connects failures across different namespaces. For example, the agent can correlate an application failure or API degradation in one namespace to a database dependency issue in a completely separate namespace.

* *Noise reduction and red herring identification*: Filters out distracting, independent cluster issues during an alert storm, allowing you to ignore unrelated alerts such as an isolated `KubePodImagePullError` or `CrashLoopBackOff` event.
