= Upgrade a single-node cluster with image-based upgrade

[role="_abstract"]
You can upgrade a single-node {product-title} cluster by updating the `ProvisioningRequest` custom resource to reference a new `ClusterTemplate` CR version configured for image-based upgrade (IBU). The O-Cloud Manager creates an `ImageBasedGroupUpgrade` (IBGU) CR that orchestrates the upgrade using a seed image containing the pre-installed target version.

.Prerequisites

* The OpenShift API for Data Protection (OADP) Operator and the Lifecycle Agent (LCA) Operator are installed on the spoke cluster, deployed through {rh-rhacm-first} policies in the `PolicyGenerator`.
* A compatible seed image for the target {product-title} version has been created, and both the target cluster and the seed image have a shared container partition configured for IBU.
* The spoke cluster is fully provisioned with `provisioningPhase: fulfilled` on the `ProvisioningRequest` CR.
* A new `ClusterTemplate` CR version is prepared for the target release with `upgradeDefaults.imageBasedGroupUpgrade` configured.

.Procedure

. Update the `ProvisioningRequest` CR to reference the new `ClusterTemplate` version by running the following command:
+
[source,terminal]
----
$ oc patch provisioningrequests.clcm.openshift.io <uuid> --type merge \
  -p '{"spec":{"templateName":"<template_name>","templateVersion":"<new_version>"}}'
----
+
where:
+
--
`<uuid>`:: Specifies the UUID of the `ProvisioningRequest` CR for the target cluster.
`<template_name>`:: Specifies the template name, such as `sno-ran-du`.
`<new_version>`:: Specifies the new `ClusterTemplate` version for the target release, such as `v4-Y-Z+1-1`.
--
+
The O-Cloud Manager detects the version change and creates an `ImageBasedGroupUpgrade` CR to orchestrate the upgrade. The IBGU plan executes the following stages:
+
* *Prep* - Downloads the seed image and prepares the node for upgrade.
* *AbortOnFailure* - Checks for failures and triggers automatic rollback if the Prep stage failed.
* *Upgrade* - Pivots the node to the new version.
* *AbortOnFailure* - Checks for failures and triggers rollback if the Upgrade stage failed.
* *FinalizeUpgrade* - Completes the upgrade and cleans up old state.
+
[NOTE]
====
The `upgradeDefaults` in the `ClusterTemplate` CR define default IBGU parameters including the seed image, OADP content references, rollback timeout, and per-stage rollout strategy. The `autoRollbackOnFailure.initMonitorTimeoutSeconds` configures how long to wait before triggering automatic rollback.
====

.Verification

* Monitor the upgrade progress by checking the `UpgradeCompleted` condition by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> \
  -o jsonpath='{.status.conditions[?(@.type=="UpgradeCompleted")]}'
----
+
.Example output on successful completion
[source,terminal]
----
{"lastTransitionTime":"2025-10-07T23:00:00Z","message":"Upgrade is completed","reason":"Completed","status":"True","type":"UpgradeCompleted"}
----
+
On successful completion, the `ProvisioningRequest` `provisioningPhase` returns to `fulfilled`.
