= RHSA-2026:102917 - {product-title} {product-version}.44 bug fix and security update

Issued: 1 December 2026

[role="_abstract"]
{product-title} release {product-version}.44 is now available. The list of fixed bugs that are included in the update is documented in the link:https://access.redhat.com/errata/RHSA-2026:102917[RHSA-2026:102917] advisory. The RPM packages that are included in the update are provided by the link:https://access.redhat.com/errata/RHBA-2026:102910[RHBA-2026:102910] advisory.

== Fixed issues

The following issues are fixed for this release:

* Before this update, the pod terminal in the console did not show the shell prompt until the browser window was resized. As a consequence, the terminal appeared blank or non-functional until users manually resized the window or toggled fullscreen. With this release, the terminal correctly calculates dimensions and displays the prompt on initial load. As a result, the shell prompt is visible immediately when opening the pod terminal. (link:https://issues.redhat.com/browse/OCPBUGS-100328[OCPBUGS-100328])

* Before this update, a security fix for a server-side request forgery (SSRF) vulnerability blocked access to Helm chart repositories, chart archives, and Open Container Initiative (OCI) registries on private networks. As a consequence, ProjectHelmChartRepository resources that pointed to internal Helm registries, such as registries on private IPv4 networks (RFC 1918), failed validation in the web console. With this release, the SSRF protection permits requests to private network addresses and in-cluster service names, but still blocks requests to localhost, loopback addresses, unspecified addresses, cloud metadata addresses, and Kubernetes API service names. As a result, you can use Helm chart repositories and registries on private networks. A chart URL must use an OCI scheme, or an HTTP or HTTPS scheme with a path that ends in .tgz or .tar.gz. A repository index URL must have a path that ends in /index.yaml. (link:https://redhat.atlassian.net/browse/OCPBUGS-128587[OCPBUGS-128587])

* Before this update, during startup the default PTP Operator configuration sometimes failed to be created because the webhook was not yet ready. As a consequence, the `linuxptp-daemon` service was not scheduled. With this release, the Operator waits for the webhook to become ready before creating the default PTP Operator configuration. As a result, the default PTP Operator configuration is populated reliably. (link:https://issues.redhat.com/browse/OCPBUGS-129459[OCPBUGS-129459])

* Before this update, large numbers of firing alerts could make the {product-title} web console slow or unresponsive. With this update, the notification drawer displays up to 50 alerts per group, and dashboards display up to 50 alerts per list. As a result, responsiveness is improved while preserving full counts and links to all alerts. (link:https://issues.redhat.com/browse/OCPBUGS-133333[OCPBUGS-133333])

* Before this update, during etcd encryption key rotation, data in namespaces deleted with remaining etcd content was skipped. As a consequence, premature key retirement and API server failures occurred. With this release, this type of data is automatically rewritten with the current encryption key before retiring older keys. As a result, the API server remains available.  (link:https://redhat.atlassian.net/browse/OCPBUGS-135096[OCPBUGS-135096])

* Before this update, revealed values on the *Secret* details page could automatically become hidden when the page refreshed. With this release, the reveal state is preserved so that values remain visible until you click *Hide values*. As a result, secret values are not unexpectedly hidden. (link:https://issues.redhat.com/browse/OCPBUGS-135259[OCPBUGS-135259])

* Before this update, when the `current-machine-os-build` annotation on a `MachineOSConfig` pointed to a build that no longer existed, the Machine Config Controller repeatedly logged errors and failed to update the machine config pool. As a consequence, machine config pools remained stuck at `0 machines configured` when using Image Mode. With this release, the Machine Config Controller correctly handles missing build references and creates new builds as needed. As a result, machine config pools update successfully in Image Mode. (link:https://issues.redhat.com/browse/OCPBUGS-135360[OCPBUGS-135360])

* Before this update, the Cluster Autoscaler's Cluster API provider could repeatedly reduce a node group's target size for the same pending Machine, potentially reducing the group to its minimum size. With this update, the provider skips pending Machines already marked for deletion. It also skips stale pending-machine deletion requests for Machines that have since registered as nodes, so those nodes go through the normal scale-down checks. (link:https://issues.redhat.com/browse/OCPBUGS-140547[OCPBUGS-140547])
