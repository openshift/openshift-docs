== Updates to monitoring stack components and dependencies

This release includes the following version updates for monitoring stack components and dependencies:

* Alertmanager to 0.33.1
* Prometheus to 3.13.2
* Prometheus Operator to 0.93.1
* Metrics Server to 0.9.0
* Thanos to 0.42.4
* kube-state-metrics agent to 2.19.1
* monitoring-plugin to 1.0.0
* node-exporter agent to 1.12.1
* prom-label-proxy to 0.14.0

== New features and enhancements

The monitoring stack for this release includes the following new features and enhancements:

`dmmultipath` collector is enabled by default in node-exporter::
With this update, the `node-exporter` agent ships with the `dmmultipath` collector enabled by default. This collector exposes Device Mapper multipath device and path metrics from `/sys/block/dm-*`. As a result, you can monitor the health of multipath block storage without additional configuration. To disable the collector, set the `nodeExporter.collectors.dmMultipath.enabled` field to `false` in the `cluster-monitoring-config` config map.
+
link:https://issues.redhat.com/browse/MON-4613[MON-4613]

`nvmesubsystem` collector is enabled by default in node-exporter::
With this update, the {cmo-first} enables the `nvmesubsystem` collector in the `node-exporter` agent by default. This collector exposes NVMe over Fabrics (NVMe-oF) subsystem metrics from `/sys/class/nvme-subsystem/`, including controller metadata, per-path state, and subsystem topology. As a result, alerts that depend on these metrics, such as `CSIVolumeNVMePathDegraded` and `CSIVolumeNVMePathLost`, can fire. To disable the collector, set the `nodeExporter.collectors.nvmeSubsystem.enabled` field to `false` in the `cluster-monitoring-config` config map.
+
link:https://issues.redhat.com/browse/MON-4621[MON-4621]

Prometheus Remote Write 2.0 support::
With this update, you can configure the {cmo-first} to send metrics by using version 2.0 of the Prometheus remote write protocol. To do so, set the `messageVersion` field in the `remoteWrite` section of the `cluster-monitoring-config` config map to `V2.0`. The default value remains `V1.0`. As a result, you can forward metrics to third-party receivers that support only remote write 2.0.
+
link:https://issues.redhat.com/browse/MON-4390[MON-4390]
