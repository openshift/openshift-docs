= Google Cloud Dedicated networking limitations

[role="_abstract"]
Google Cloud Dedicated imposes networking limitations that differ from standard {gcp-short} environments.
You must plan your network architecture around these constraints when deploying {product-title} on Google Cloud Dedicated.

.Google Cloud Dedicated networking limitations
[cols="1,2",options="header"]
|===
|Limitation
|Description

|No public DNS zones
|Google Cloud Dedicated does not support public DNS zones. The installation program creates only private DNS zones for the cluster.

|No global load balancers
|The `compute.disableGlobalLoadBalancing` organization policy prevents creation of global load balancers. Only regional internal load balancers are available.

|Regional internal load balancers only
|Cluster services use regional internal load balancers. External load balancers are not supported.

|No PSC endpoint overrides
|Private Service Connect (PSC) endpoint overrides are not supported on Google Cloud Dedicated. PSC DNS zones are hard-coded for `googleapis.com` and are incompatible with the Google Cloud Dedicated universe domain.
|===

.Supported access patterns
[cols="1,2",options="header"]
|===
|Access method
|Description

|VPN
|You can access the cluster API and application endpoints through a VPN connection to the Google Cloud Dedicated network.

|Cloud Interconnect
|You can use Cloud Interconnect to establish a dedicated, high-bandwidth connection to the Google Cloud Dedicated network for accessing cluster services.
|===

[NOTE]
====
These limitations are enforced by the Google Cloud Dedicated infrastructure, not by {product-title}.
On standard {gcp-short}, private clusters are optional and some of these capabilities (such as public DNS zones and global load balancers) are available.
====
