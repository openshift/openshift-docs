= Forward logs to an external Elasticsearch cluster

[role="_abstract"]
To configure log forwarding to an external Elasticsearch cluster, you create a `ClusterLogForwarder` custom resource (CR) with an `elasticsearch` output and a pipeline that references that output. You can specify a single cluster URL, multiple cluster endpoints, or both.

.Prerequisites

* You have administrator access to {ocp-product-title}.
* You have installed the {clo}.
* You have access to an external Elasticsearch cluster (version 6.x, 7.x, or 8.x).
* If using Mutual Transport Layer Security (mTLS) or authentication, you have created a Kubernetes `Secret` object in the `openshift-logging` namespace containing the required certificates or credentials.

.Procedure

. Create or edit a `ClusterLogForwarder` custom resource (CR) YAML file:
+
[source,yaml]
----
apiVersion: observability.openshift.io/v1
kind: ClusterLogForwarder
metadata:
  name: <log_forwarder_name>
  namespace: openshift-logging
spec:
  serviceAccount:
    name: <service_account_name>
  outputs:
    - name: external-es
      type: elasticsearch
      elasticsearch:
        url: <elasticsearch_url_1>
        endpoints:
          - <elasticsearch_endpoint_url_2>
          - <elasticsearch_endpoint_url_3>
        version: 8
        index: '{.log_type||"undefined"}'
        authentication:
          username:
            key: username
            secretName: es-secret
          password:
            key: password
            secretName: es-secret
      tls:
        ca:
          key: ca-bundle.crt
          secretName: es-secret
        certificate:
          key: tls.crt
          secretName: es-secret
        key:
          key: tls.key
          secretName: es-secret
  pipelines:
    - name: my-logs
      inputRefs:
        - application
        - infrastructure
      outputRefs:
        - external-es
----
+
where:

`url`:: Optional when you specify `endpoints`. Specifies the URL of a single Elasticsearch cluster node or external load balancer.
`endpoints`:: Optional when you specify `url`. Specifies a list of URLs for Elasticsearch cluster nodes. The collector distributes log records across endpoints by using Power of Two Choices (P2C) load balancing and provides automatic failover if a node becomes unavailable.
`version`:: Required for external Elasticsearch version 8.x or greater. Specify the Elasticsearch major version.
`index`:: Specifies the target index. The value can be static or dynamic using field paths (for example, `{.log_type||"undefined"}`).
`authentication`:: Optional: Specifies the username and password secret for Basic authentication.
`tls`:: Optional: Configures TLS or Mutual Transport Layer Security (mTLS) between the collector and Elasticsearch.
+
You can configure Elasticsearch destinations by using one of the following patterns:
+
--
* **Single endpoint**: Specify a single Elasticsearch URL or external load balancer by using the `url` field:
+
[source,yaml]
----
      elasticsearch:
        url: <elasticsearch_url>
        version: 8
        index: '{.log_type||"undefined"}'
----

* **Multiple endpoints**: Specify a list of Elasticsearch cluster nodes by using the `endpoints` field:
+
[source,yaml]
----
      elasticsearch:
        endpoints:
          - <elasticsearch_endpoint_url_1>
          - <elasticsearch_endpoint_url_2>
          - <elasticsearch_endpoint_url_3>
        version: 8
        index: '{.log_type||"undefined"}'
----

* **Combined URL and endpoints**: Specify both `url` and `endpoints`. The collector prepends the value of `url` to the `endpoints` list:
+
[source,yaml]
----
      elasticsearch:
        url: <elasticsearch_url_1>
        endpoints:
          - <elasticsearch_endpoint_url_2>
          - <elasticsearch_endpoint_url_3>
        version: 8
        index: '{.log_type||"undefined"}'
----
+
In this configuration, the collector distributes log records across the node defined in `url` and all nodes in `endpoints`.
--
+
[NOTE]
====
* **Load balancing and failover**: When you specify more than one endpoint, the collector distributes log records across active endpoints by using Power of Two Choices (P2C) load balancing. If an endpoint becomes unresponsive or fails health checks, the collector fails over to remaining healthy endpoints.
* **Connection security**: Endpoints can use either the `http` or `https` protocol scheme. You can mix `http` and `https` schemes within the same endpoint list if necessary. For `https` endpoints, the collector applies the certificates and keys defined in the `tls` configuration block. For `http` endpoints, the collector establishes unencrypted connections without applying the TLS configuration. The {clo} validates TLS settings against all endpoints specified in both `url` and `endpoints`.
====

. Apply the `ClusterLogForwarder` CR by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----
