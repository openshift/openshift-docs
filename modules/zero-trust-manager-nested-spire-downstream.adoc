= Configuring the downstream cluster

[role="_abstract"]
Configure the downstream SPIRE server to obtain its signing CA from the upstream server. {zero-trust-full} deploys the upstream agent, connects that agent to the downstream server, and restarts the downstream server.

.Prerequisites

* You copied the upstream trust bundle to the `spire-upstream-bundle` Secret on the downstream cluster.
* The downstream `SpireServer` CR does not set `spec.upstreamAuthority.certManager` or `spec.upstreamAuthority.vault`. You can set only one UpstreamAuthority plugin.
* The upstream Route host is admitted, and DNS for that host resolves to the upstream cluster ingress.
* The `DOWNSTREAM_KUBECONFIG` environment variable is set.
* You know the upstream cluster name and the shared trust domain.

[IMPORTANT]
====
Enable nested SPIRE before the downstream SPIRE server issues workload SVIDs. A server that already holds a self-signed CA keeps that CA until the next CA rotation. While that CA is in use, workload SVIDs do not chain to the shared root. To switch immediately, re-initialize the SPIRE server datastore during a maintenance window. For more information, see xref:#zero-trust-manager-nested-spire-troubleshooting_{context}[Troubleshooting nested SPIRE].
====

.Procedure

. Create a file named `downstream-nested-spire.yaml` with the following contents:
+
[source,yaml]
----
spec:
  upstreamAuthority:
    spire:
      serverAddress: grpc.<upstream_cluster_name>.<trust_domain>
      serverPort: 443
      trustBundleSecret: spire-upstream-bundle
----
+
where:

`spec.upstreamAuthority.spire.serverAddress`:: Specifies the DNS hostname of the upstream gRPC Route. Do not include a URL scheme, a port, or a path. The hostname must match the upstream Route host. Maximum length is 253 characters.
`spec.upstreamAuthority.spire.serverPort`:: Specifies the upstream gRPC port. The default is `443`. Valid values are `1` through `65535`.
`spec.upstreamAuthority.spire.trustBundleSecret`:: Specifies the Secret in the `zero-trust-workload-identity-manager` namespace that contains the upstream trust bundle. The Secret data key is `bundle.crt`.

. Apply the configuration by running the following command:
+
[source,terminal]
----
$ oc patch spireserver cluster --type=merge --patch-file=downstream-nested-spire.yaml --kubeconfig="${DOWNSTREAM_KUBECONFIG}"
----

. Wait for the downstream SPIRE server to roll out by running the following command:
+
[source,terminal]
----
$ oc rollout status statefulset/spire-server -n zero-trust-workload-identity-manager --kubeconfig="${DOWNSTREAM_KUBECONFIG}" --timeout=300s
----
+
[NOTE]
====
On a mid-tier cluster, complete this procedure for the tier above, and then complete xref:#zero-trust-manager-nested-spire-upstream_{context}[Configuring the upstream cluster] so that the next tier can chain to this cluster.
====

.Verification

* Confirm that the upstream agent and the upstream CSI driver are available by running the following commands:
+
[source,terminal]
----
$ oc rollout status deployment/spire-agent-upstream -n zero-trust-workload-identity-manager --kubeconfig="${DOWNSTREAM_KUBECONFIG}" --timeout=300s
----
+
[source,terminal]
----
$ oc rollout status daemonset/spire-spiffe-csi-driver-upstream -n zero-trust-workload-identity-manager --kubeconfig="${DOWNSTREAM_KUBECONFIG}" --timeout=300s
----
+
The `UpstreamAgentAvailable` and `UpstreamCSIDriverAvailable` conditions on the downstream `SpireServer` CR are `True` with reason `Ready`.
