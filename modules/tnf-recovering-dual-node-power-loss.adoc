= Recovering from dual node power loss in a TNF cluster

[role="_abstract"]
When both control plane nodes of a two-node {product-title} cluster with fencing (TNF) lose power and both can be restarted, recovery is automatic: Pacemaker reestablishes corosync quorum and starts the cluster services on its own once both nodes are online. Use this procedure to verify the automatic recovery and to diagnose a recovery that stalls.

[IMPORTANT]
====
This procedure applies only when both control plane nodes lost power and both can be restarted. If only one node can be restarted, do not use this procedure; see xref:../installing_tnf/install-post-tnf.adoc#tnf-restoring-c-quorum-manual_install-post-tnf[Manually restoring corosync quorum after dual node power loss].
====

.Prerequisites

* You have administrative access to the control plane nodes.
* You can connect to the nodes by using SSH.

.Procedure

. Power on both control plane nodes.
+
Pacemaker starts automatically and begins the recovery operation when it detects that both nodes are online.

. Verify that corosync membership containing both nodes has formed and that the cluster holds quorum by running the following commands:
+
[source,terminal]
----
$ sudo pcs status corosync
----
+
[source,terminal]
----
$ sudo pcs quorum status
----
+
The `pcs quorum status` output reports `Quorate: Yes`.

. If resources do not start, reset their failure state and instruct Pacemaker to attempt to start them again by running the following command:
+
[source,terminal]
----
$ sudo pcs resource cleanup
----

. Check the resource start order by running the following command:
+
[source,terminal]
----
$ sudo pcs status --full
----

. If kubelet fails to start, inspect the service journals by running the following commands:
+
[source,terminal]
----
$ sudo journalctl -u pacemaker
----
+
[source,terminal]
----
$ sudo journalctl -u kubelet
----

. If one node has a more up-to-date etcd data set than its peer, Pacemaker fences the lagging node and starts it as a learning member. If this process stalls, verify that the Redfish fencing endpoint is reachable and that the fencing credentials are correct by running the following command:
+
[source,terminal]
----
$ sudo pcs stonith config
----
+
If the fencing credentials are wrong or outdated, repair them as described in xref:../installing_tnf/install-post-tnf.adoc#tnf-updating-fencing-credentials-manually_install-post-tnf[Manually updating fencing credentials] or xref:../installing_tnf/install-post-tnf.adoc#updating-fencing-credentials-script_install-post-tnf[Updating fencing credentials by using the script].

.Verification

* Verify that etcd and kubelet are running on both nodes by running the following command:
+
[source,terminal]
----
$ sudo pcs status --full
----

* For information about verifying etcd health, see "Verifying etcd health in a two-node {product-title} cluster with fencing".
