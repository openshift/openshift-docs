= Manual security review for delegated extension management

[role="_abstract"]
Manually review extension permissions, configuration, and user access before delegating extension management in {product-title}.

[IMPORTANT]
====
Use the following configuration and resources as only a starting point for your security review.

Before delegating management of an extension, review and verify its supported configuration, permissions, and resources.
====

The cluster environment can also introduce additional review requirements. For example, existing role-based access control (RBAC) permissions and any feature gates enabled on the cluster require additional review.

Review the extension and its configuration:

* Before delegating extension management
* Before updating the extension
* Before changing cluster configuration that affects the permissions or behavior of the extension

Review the following configuration and resources:

Bundle content and permissions:: Review the resources, service accounts, and permission grants in the selected bundle. Before approving another version, compare the permissions and behavior of the new version with the version you last approved.

Extension configuration:: Identify settings that change workloads, credentials, permissions, or the resources an extension manages. When enabled features expose additional configuration, extend and test admission restrictions before granting access to those settings.

Installation namespace:: Review who can change extension workloads, create workloads, or obtain service account credentials in the installation namespace. Users with these permissions might gain access through an extension service account. Selecting a namespace does not isolate an extension from the rest of the cluster.

Existing user and group access:: Review all RBAC permissions assigned to delegated users and their groups. Adding a role binding does not remove existing access. Keep write access to cluster object sets, catalogs, and admission policies restricted to administrators.

Admission policy coverage:: Verify that the policy and its binding cover the intended identities, operations, and fields. Match the group in the policy to the group receiving RBAC permissions. Verify both accepted and rejected requests. A successful test covers the tested request, not every possible request or extension action.

Catalogs and updates:: Review the catalog and verify who can change its content. If you allow automatic updates within a version range or channel, new bundles can install without another review. Use an exact approved version when each bundle requires review, and reassess the bundle before changing that version.
