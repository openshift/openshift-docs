= Apply rate limiting to egress traffic

[role="_abstract"]
Limit the rate of outbound requests to external services by applying a `RateLimitPolicy` to an egress `Gateway` object or `HTTPRoute` custom resource (CR). Most rate-limiting approaches that you use for incoming traffic work the same way for outgoing traffic.

Rate limiting on egress uses the same attachment model as ingress. A gateway-level policy sets defaults for all routes. A route-level policy can override those defaults for a specific route. The following example attaches a rate limit to an `HTTPRoute` CR.

[TIP]
====
Use workload identity with `auth.identity.username` for per-workload limiting. You cannot use the `source.address` counter expression for egress rate limiting. Egress rate limiting includes the ephemeral port, which means that each connection has its own bucket.
====

.Prerequisites

include::snippets/egress-gateway-prereqs.adoc[]

* You created a test client pod in the `egress-test` namespace.

.Procedure

. Export the egress `Gateway` object IP address by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ export EGRESS_IP=$(oc get gtw _<kuadrant_egressgateway>_ -n _<gateway_system>_ \
    -o jsonpath='{.status.addresses[0].value}')
----
+
Replace `_<kuadrant_egressgateway>_` value with the egress `Gateway` object name.

. Apply a `RateLimitPolicy` custom resource (CR) to the egress `HTTPRoute` CR by using the following example:
+
[source,yaml,subs="+quotes"]
----
apiVersion: kuadrant.io/v1
kind: RateLimitPolicy
metadata:
  name: _<egress_ratelimit>_
  namespace: _<gateway_system>_ # must this be the same as the egress gateway namespace?
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: _<httpbin_external>_
  limits:
    global:
      rates:
        - limit: 5
          window: 10s
----
+
* Replace the `spec.targetRef.name` parameter value with the name of your external service.
* The setting in `spec.limits.global.rates` limits all traffic through the `_<httpbin_external>_` route to 5 requests every 10 seconds, regardless of which workload is sending.

. Apply the rate limit policy CR by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<egress_ratelimit>_
----
+
Replace `_<egress_ratelimit>_` with the name of your egress rate limit policy object.

.Verification

* Send requests in a loop and observe the rate limit enforcement by running the following command:
+
[source,terminal]
----
$ for i in $(seq 1 10); do
    oc exec test-client -n egress-test -- \
        curl -s -o /dev/null -w "%{http_code}" -H "Host: httpbin.org" http://${EGRESS_IP}/get
    sleep 0.5
  done
----
+
** Replace `_<httpbin.org>_` with your external target service.
** The first 5 requests return `200`. Additional requests return `429` until the 10-second window resets.
