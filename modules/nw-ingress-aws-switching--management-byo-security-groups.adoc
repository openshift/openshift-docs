= Switching the management service for security groups

[role="_abstract"]
You can switch an existing NLB from a CCM-managed security group to a BYO security group.
Alternatively, you an revert from a BYO security group back to a CCM-managed security group.

.Prerequisties

* Before switching from a CCM-managed security group to a BYO security group, you provisioned security groups for your service NLB.

.Procedure

* To switch from a CCM-managed security group to a BYO security group, complete the following steps.
+
** Create your BYO security group in the same VPC as the cluster and configure the appropriate ingress rules.
+
.. Add the annotation `service.beta.kubernetes.io/aws-load-balancer-security-groups` with one or more security group IDs to the service manifest by entering the following command:
+
[source,terminal]
----
$ oc annotate svc <your_nlb_service> \
  service.beta.kubernetes.io/aws-load-balancer-security-groups=<security_group_ID>
----
+
Replace `<your_nlb_service>` with the name of your service.
Replace `<security_group_ID>` with your security group ID.
+
[NOTE]
====
After you complete the switch operation, the CCM completes the following tasks:

* Detects the annotation change and updates the NLB security group configuration associating it with the requested BYO security group.
* Automatically deletes the old managed security group. This happens because the security group is cluster-owned and is no longer needed.
====

* To revert from a BYO security group to a CCM-managed security group, complete the following steps.
+
** Remove the annotation from your service by entering the following command:
+
[source,terminal]
----
$ oc annotate svc <your_nlb_service> \
  service.beta.kubernetes.io/aws-load-balancer-security-groups-
----
+
Replace `<your_nlb_service>` with the name of your service.
+
[NOTE]
====
After you complete the revert operation, the CCM completes the following tasks:

* Creates a new managed security group with the appropriate rules and attaches the rules to the NLB.
Detects the annotation change and updates the NLB security group configuration associating it with the requested BYO security group.
* Detaches the BYO security group from the NLB. The CCM does not delete the security group from your {aws-short} customer account as the group is not a cluster-owned resource. You must manually delete the security group.
====
