= Mirroring images with signatures for a disconnected environment

[role="_abstract"]
Before you can enable signature verification in a disconnected environment, you must mirror the container images along with their sigstore signatures to your local registry. Use the oc-mirror plugin v2 to mirror both images and signatures. If you do not mirror the signatures, signature verification fails and pods cannot start.

By default, the oc-mirror plugin v2 mirrors sigstore tag-based signatures for all images. You must ensure that your `ImageSetConfiguration` file includes the required platform images, operator images, and any additional images that your workloads require.

.Prerequisites

* You have installed the oc-mirror plugin v2.
* You have created a container image registry credentials file. For instructions, see _Configuring credentials that allow images to be mirrored_.
* You have access to the Red{nbsp}Hat registries with your Red{nbsp}Hat subscription credentials.
* You have a local registry available to store the mirrored images and signatures.

.Procedure

. Create an `ImageSetConfiguration` YAML file that includes the platform and operator images you need to mirror.
+
The following example mirrors {product-title} release images, selected operators, and support images required for debugging and troubleshooting:
+
[source,yaml]
----
kind: ImageSetConfiguration
apiVersion: mirror.openshift.io/v2alpha1
mirror:
  platform:
    channels:
    - name: stable-{product-version}
      minVersion: {product-version}.0
      maxVersion: {product-version}.0
    graph: true
  operators:
    - catalog: registry.redhat.io/redhat/redhat-operator-index:v{product-version}
      packages:
       - name: cluster-logging
       - name: elasticsearch-operator
       - name: local-storage-operator
       - name: metallb-operator
  additionalImages:
   - name: registry.redhat.io/openshift4/ose-must-gather:v{product-version}
   - name: registry.redhat.io/openshift4/ose-tools-rhel9:v{product-version}
   - name: registry.redhat.io/openshift4/ose-cli:v{product-version}
----
+
[NOTE]
====
Include the `ose-must-gather`, `ose-tools-rhel9`, and `ose-cli` images if you need to use the `oc debug`, `oc adm must-gather`, or toolbox commands in your disconnected environment.
====

. Run the oc-mirror command to mirror the images and signatures to your local registry:
+
[source,terminal]
----
$ oc mirror --config=imageset-config.yaml docker://<local_registry>/<repository>
----
+
where:
+
* `<local_registry>` -- Specifies the hostname and port of your local registry.
* `<repository>` -- Specifies the repository path in your local registry.
+
The oc-mirror plugin automatically mirrors the sigstore signatures for all images. Signature mirroring is enabled by default.

. Verify that the signatures were mirrored by checking the registry for signature tags.
+
Sigstore signatures are stored as separate image tags with a `.sig` suffix. For example, if you mirrored an image with the digest `sha256:abc123...`, the signature tag is `sha256-abc123....sig`.
+
[source,terminal]
----
$ skopeo list-tags docker://<local_registry>/<repository>/<image_name> | grep sig
----

. Apply the generated manifests to your cluster to configure the mirror registry settings:
+
[source,terminal]
----
$ oc apply -f oc-mirror-workspace/results-<timestamp>/
----

.Verification

* After mirroring completes, verify that signature data is present:

.. Check that signatures exist for a platform image:
+
[source,terminal]
----
$ skopeo inspect --raw docker://<local_registry>/<repository>/openshift-release-dev/ocp-release:sha256-<digest>.sig
----
+
A successful response returns the signature manifest content. An error indicates that signatures were not mirrored.

.. Check the oc-mirror log for signature mirroring activity:
+
[source,terminal]
----
$ grep -i "signature" oc-mirror.log
----

.Next steps

* Configure a `ClusterImagePolicy` object to enforce signature verification on the cluster. See _Creating a cluster image policy CR_.
* If you need to mirror signatures for images from third-party catalogs, verify that the source registry contains sigstore signatures. Certified, marketplace, and community catalogs contain third-party content, and Red{nbsp}Hat does not guarantee the availability or validity of their signatures.
