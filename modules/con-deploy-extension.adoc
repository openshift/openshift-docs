= Requirements to deploy an extension

[role="_abstract"]
You can deploy extensions on your own release cadence and extract live data-plane details without modifying core {prodname} Operator logic by using the Extension software development kit (SDK).

The Extension SDK automatically handles gRPC dialing, startup handshakes, and token authentication. You must ensure the following before deploying an extension:

* Permission to register the policy `Kind`. Which `Kind` an extension can manage is an authorization decision. The extension's `ServiceAccount` requires RBAC permissions to register its claimed policy `Kind` alongside standard controller permissions to watch and reconcile its custom resources.

* Ordinary controller RBAC. Your extension does not inherit the {prodname} permissions, so it needs its own. The extension requires its own CRD and status, plus anything that it creates, such as `AuthPolicy` or `HTTPRoute` objects. The extension does not need read access to `Gateway` or route objects if it only reaches them through topology queries.

* The endpoint and a token. The extension reads both from the environment. The token is a projected `ServiceAccount` token scoped to the `kuadrant-extensions` audience, which the `kubelet` rotates for you.

* Network reachability. The {prodname} namespace has a `default-deny` ingress `NetworkPolicy`. You need a `NetworkPolicy` that permits your extension pods to reach the {prodname} Operator on port `50052`.
