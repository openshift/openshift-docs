= Overriding Operator conditions

[role="_abstract"]
Administrators can override Operator conditions to handle situations where an Operator is incorrectly reporting a state to Operator Lifecycle Manager (OLM).

[.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#As a cluster administrator,#
[.pr:openshift-dedicated .pr:openshift-rosa .pr:openshift-rosa-hcp]#As an administrator with the `dedicated-admin` role,#
you might want to ignore a supported Operator condition reported by an Operator. When present, Operator conditions in the `Spec.Overrides` array override the conditions in the `Spec.Conditions` array, allowing
[.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#cluster administrators#
[.pr:openshift-dedicated .pr:openshift-rosa .pr:openshift-rosa-hcp]#`dedicated-admin` administrators#
to deal with situations where an Operator is incorrectly reporting a state to Operator Lifecycle Manager (OLM).

[NOTE]
====
By default, the `Spec.Overrides` array is not present in an `OperatorCondition` object until it is added by
[.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#a cluster administrator#
[.pr:openshift-dedicated .pr:openshift-rosa .pr:openshift-rosa-hcp]#an administrator with the `dedicated-admin` role#
. The `Spec.Conditions` array is also not present until it is either added by a user or as a result of custom Operator logic.
====

For example, consider a known version of an Operator that always communicates that it is not upgradeable. In this instance, you might want to upgrade the Operator despite the Operator communicating that it is not upgradeable. This could be accomplished by overriding the Operator condition by adding the condition `type` and `status` to the `Spec.Overrides` array in the `OperatorCondition` object.

.Prerequisites

* [.pr:openshift-enterprise .pr:openshift-origin .pr:microshift]#You have access to the cluster as a user with the `cluster-admin` role.#
* [.pr:openshift-dedicated .pr:openshift-rosa .pr:openshift-rosa-hcp]#You have access to the cluster as a user with the `dedicated-admin` role.#
* An Operator with an `OperatorCondition` object, installed using OLM.

.Procedure

. Edit the `OperatorCondition` object for the Operator:
+
[source,terminal]
----
$ oc edit operatorcondition <name>
----

. Add a `Spec.Overrides` array to the object:
+
.Example Operator condition override
[source,yaml]
----
apiVersion: operators.coreos.com/v2
kind: OperatorCondition
metadata:
  name: my-operator
  namespace: operators
spec:
  overrides:
  - type: Upgradeable
    status: "True"
    reason: "upgradeIsSafe"
    message: "This is a known issue with the Operator where it always reports that it cannot be upgraded."
  conditions:
  - type: Upgradeable
    status: "False"
    reason: "migration"
    message: "The operator is performing a migration."
    lastTransitionTime: "2020-08-24T23:15:55Z"
----
+
[role="pr:openshift-enterprise pr:openshift-origin pr:microshift"]
Setting the 'type' field to `Upgradeable` allows the cluster administrator to change the upgrade readiness to `True`.
+
[role="pr:openshift-dedicated pr:openshift-rosa pr:openshift-rosa-hcp"]
Setting the 'type' field to `Upgradeable` allows the `dedicated-admin` user to change the upgrade readiness to `True`.
