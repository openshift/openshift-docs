== Fixed issues

* Before this update, when using Agent-based installation, the IP collision validation sent Address Resolution Protocol (ARP) requests from all network interfaces to verify IP address availability. As a consequence, if proxy ARP was enabled on VLAN interfaces configured as gateways for cluster management and storage networks, the validation incorrectly interpreted the proxy ARP responses as IP address collisions, causing the cluster installation to fail. With this release, the validation correctly handles proxy ARP scenarios. As a result, cluster installations succeed when proxy ARP is configured on the gateway interfaces. (link:https://issues.redhat.com/browse/OCPBUGS-61058[OCPBUGS-61058])

* Before this update, the Operator used the `reflect.DeepEqual` parameter for node label comparison which required an exact label match instead of Kubernetes label selector semantics. As a consequence, the `IngressNodeFirewallNodeState` objects were not created for nodes added after the Operator startup. With this release, the `reflect.DeepEqual` parameter is replaced with the `labels.SelectorFromSet().Matches()` parameter for correct Kubernetes label selector matching. As a result, the Operator correctly creates the `IngressNodeFirewallNodeState` object for dynamically added nodes and label changes. (link:https://issues.redhat.com/browse/OCPBUGS-106121[OCPBUGS-106121])
