= Disabling KMS encryption

[role="_abstract"]
You can disable external KMS encryption and migrate to local encryption to simplify operations or resolve KMS connectivity issues. // cite:1
// cite:1 VERIFIED [88]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L396-L399 - Disabling KMS: user sets encryption mode to identity, keyController creates identity key secret, EncryptionConfiguration contains identity as write + KMS as read until migration completes

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have created an etcd backup.

[WARNING]
====
Re-encryption of all etcd data occurs when you change the encryption type.
====

.Procedure

. Edit the `APIServer` custom resource by entering the following command:
+
[source,terminal]
----
$ oc edit apiserver cluster
----

. Change the encryption configuration:
+
[source,yaml]
----
apiVersion: config.openshift.io/v1
kind: APIServer
metadata:
  name: cluster
spec:
  encryption:
    type: <encryption>
----
+
Replace `<encryption>` with `aescbc`, `aesgcm`, or `identity`. // cite:2
// cite:2 VERIFIED [95]: https://github.com/openshift/api/blob/9edb1b2/config/v1/types_apiserver.go#L247-L268 - EncryptionType enum: identity, aescbc, aesgcm, KMS

. Save and exit.
+
{product-title} automatically migrates etcd data. Migration time depends on etcd size and secret count. The KMS plugin sidecars remain running as read-only providers until migration completes. // cite:3
// cite:3 VERIFIED [88]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L398-L399 - KMS plugin remains as read provider until migration completes
// cite:3 VERIFIED [88]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L400 - Unused KMS plugin removal out of scope in TP v2; stale providers remain in EncryptionConfiguration

. Monitor the migration progress by entering the following command:
+
[source,terminal]
----
$ oc get openshiftapiserver -o=jsonpath='{range .items[0].status.conditions[?(@.type=="Encrypted")]}{.reason}{"\n"}{.message}{"\n"}{end}'
----
+
Wait until the output shows `EncryptionCompleted`.

. Verify that the `kube-apiserver` pods have rolled out by entering the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-kube-apiserver -l app=openshift-kube-apiserver
----

// Verify: Confirm whether V2 requires manual VaultKMSConfig CR and OLM operator cleanup after disabling, or if the platform handles this automatically
. Optional: After migration completes, clean up the KMS provider resources: // cite:4
// cite:4 INFERRED [35]: Enhancement L400 states "removal mechanism is out of scope in TP v2" — implies manual cleanup required. Enhancement does not specify auto-cleanup of VaultKMSConfig CR or credentials
+
--
.. Delete the `VaultKMSConfig` custom resource by entering the following command:
+
[source,terminal]
----
$ oc delete vaultkmsconfig my-vault-kms
----

.. Delete the credential secret by entering the following command:
+
[source,terminal]
----
$ oc delete secret vault-approle-secret -n openshift-config
----

.. Optional: Delete the CA bundle config map by entering the following command:
+
[source,terminal]
----
$ oc delete configmap vault-ca-bundle -n openshift-config
----

.. After your backup retention period passes, decommission the KMS key.
--

.Verification

. Verify the encryption type by entering the following command:
+
[source,terminal]
----
$ oc get apiserver cluster -o jsonpath='{.spec.encryption.type}'
----

. Verify that a test secret uses the new encryption type:
+
--
.. Create a test secret by entering the following command:
+
[source,terminal]
----
$ oc create secret generic encryption-test --from-literal=key=value -n default
----

.. Get an etcd pod name by entering the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-etcd -l app=etcd -o name | head -1
----

.. Check the encryption prefix by entering the following command:
+
[source,terminal]
----
$ oc exec -n openshift-etcd <etcd_pod_name> -- etcdctl get /kubernetes.io/secrets/default/encryption-test --print-value-only | hexdump -C | head -1
----
+
The output begins with `k8s:enc:aescbc:v1:`, `k8s:enc:aesgcm:v1:`, or shows readable JSON for `identity`. // cite:5
// cite:5 VERIFIED [50]: https://kubernetes.io/docs/tasks/administer-cluster/encrypt-data/ - Kubernetes encryption at rest prefixes (k8s:enc:<provider>:v1:)

.. Delete the test secret by entering the following command:
+
[source,terminal]
----
$ oc delete secret encryption-test -n default
----
--

[NOTE]
====
Do not delete the KMS key until migration completes successfully. // cite:6
// cite:6 VERIFIED [88]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L400 - Backups encrypted with previous KMS plugin not restorable without access to that plugin
// cite:6 VERIFIED [88]: https://github.com/openshift/enhancements/blob/66c24fe/enhancements/kube-apiserver/kms-encryption-foundations.md#L409 - KMS plugin must remain accessible during migration
====
