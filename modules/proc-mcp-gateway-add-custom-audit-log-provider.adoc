= Add a custom audit log provider

[role="_abstract"]
Define the JSON format for optional Envoy access logs by adding a custom provider to the Istio `MeshConfig` configuration. Keep request and trace identifiers for correlation without logging raw session credentials.

[IMPORTANT]
====
The approach used in the following procedures only works if you are using {service-mesh}. If you are using the {ocp} default Ingress Operator to manage `Istio` objects, changes are reconciled back to the previous settings.
====

.Prerequisites

* You installed the {mcpg}.
* You installed {prodname}.
* You created a `Gateway` object.
* You set up an identity provider.
* You configured Istio as the Gateway API provider.
* You configured authentication for both the broker and back-end route sets, such as the `mcp` and `mcps` listeners, and configured the `x-auth-identity` response header in both `AuthPolicy` CRs.

.Procedure

* Edit the existing cluster-scoped `Istio` object. Add the access log provider under `spec.values.meshConfig.extensionProviders` without removing existing providers or other settings:
+
.Example Istio custom access log provider
[source,yaml,subs="+quotes"]
----
apiVersion: sailoperator.io/v1
kind: Istio
metadata:
  name: _<istio_name>_
spec:
  namespace: _<control_plane_namespace>_
  values:
    meshConfig:
      extensionProviders:
        - envoyFileAccessLog:
            logFormat:
              labels:
                bytes_received: '%BYTES_RECEIVED%'
                bytes_sent: '%BYTES_SENT%'
                duration_ms: '%DURATION%'
                mcp_method: '%REQ(X-MCP-METHOD)%'
                mcp_server_name: '%REQ(X-MCP-SERVERNAME)%'
                mcp_tool_name: '%REQ(X-MCP-TOOLNAME)%'
                mcp_user_id: '%REQ(X-AUTH-IDENTITY)%'
                method: '%REQ(:METHOD)%'
                path: '%REQ(:PATH)%'
                request_id: '%REQ(X-REQUEST-ID)%'
                response_code: '%RESPONSE_CODE%'
                timestamp: '%START_TIME%'
                traceparent: '%REQ(TRACEPARENT)%'
                upstream_host: '%UPSTREAM_HOST%'
            path: /dev/stdout
          name: mcp-json-access-log
        # Retain all other configured extension providers.
----
+
Replace `_<istio_name>_` with the name of the existing `Istio` object and `_<control_plane_namespace>_` with its existing `spec.namespace` value. Do not substitute the `Gateway` namespace for this control-plane setting. Do not set `metadata.namespace` on this cluster-scoped resource.
+
Do not add the raw `Mcp-Session-Id` header to the access log format. Use `request_id` and `traceparent` to correlate requests, and use the router audit log `session` field for a log-safe session identifier.
+
[IMPORTANT]
====
If you have other extension providers configured, for example, OpenTelemetry tracing, include them in the `extensionProviders` array with the access log provider. The merge of the resources replaces the array.
====
