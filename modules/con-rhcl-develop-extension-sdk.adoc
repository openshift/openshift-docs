= Extension SDK with {prodname}

[role="_abstract"]
An extension is an ordinary workload that you own and deploy yourself. You can build, roll out, and roll back extensions that each add a new policy `Kind` against the {prodname} Operator on your own release cadence as required by using the Extension SDK.

Consider building an extension when the following situations exist:

* A workflow requires coordinating multiple `Kuadrant` policies behind a single interface. For example, when an `OIDCPolicy` custom resource (CR) creates `AuthPolicy` CRs and `HTTPRoute` CRs for OAuth purposes.
* You need information from the {prodname} topology to configure your implementation, such as when you need to extract `Gateway` listener details, `HTTPRoute` configurations, or other policy states.
* The decision you want to express depends on the request. For example, you want to evaluate rate limits that vary by user tier, or metric labels drawn from a header per request.
* You want your own service consulted on a request path, and its answer to decide whether the request proceeds.

If you do not need such advanced functions, writing a standard controller is best.
