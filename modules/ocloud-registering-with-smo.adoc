= Register the O-Cloud Manager with an SMO

[role="_abstract"]
Optionally, for telcommunications use cases, you can register the O-Cloud Manager with a Service Management and Orchestration (SMO) system by updating the `Inventory` custom resource (CR) with the SMO endpoint, OAuth credentials, and CA certificate configuration. Registration is a one-time operation that enables the SMO to manage infrastructure through the O2 IMS REST APIs.

.Prerequisites

* The O-Cloud Manager Operator is installed and running on the hub cluster.
* You configured mTLS for API access. For more information, see "Configure mTLS for API access".
* You have the SMO endpoint URL and registration endpoint path.
* You have OAuth2 client credentials for the O-Cloud Manager, obtained from the OAuth2 authorization server administrator.
* You have the CA certificate bundle if the SMO or OAuth2 server uses certificates signed by a non-public CA.

.Procedure

. If the SMO or OAuth2 server TLS certificates are signed by a non-public CA, create a `ConfigMap` with the CA certificate bundle and configure the cluster proxy by running the following commands:
+
[source,terminal]
----
$ oc create configmap -n openshift-config <ca_configmap_name> \
  --from-file=ca-bundle.crt=<path_to_ca_bundle>
$ oc patch proxy/cluster --type=merge \
  --patch='{"spec":{"trustedCA":{"name": "<ca_configmap_name>"}}}'
----
+
where:
+
`<ca_configmap_name>`:: Specifies a name for the `ConfigMap` that stores the CA certificate bundle, for example `custom-ca-certs`.
`<path_to_ca_bundle>`:: Specifies the local file path to the CA certificate bundle that contains the certificates needed to trust the SMO and OAuth2 server endpoints.
+
[WARNING]
====
If the cluster proxy already references a custom CA bundle, append the new certificates to the existing bundle rather than replacing it.
====

. Create a `ConfigMap` with the trust bundle injection label so that the O-Cloud Manager can access both private and public CA certificates:
+
[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  labels:
    config.openshift.io/inject-trusted-cabundle: "true"
  name: o2ims-trusted-ca-bundle
  namespace: oran-o2ims
----

. Apply the `ConfigMap` by running the following command:
+
[source,terminal]
----
$ oc apply -f <trusted_ca_bundle_filename>.yaml
----
+
* Replace `<trusted_ca_bundle_filename>.yaml` with the name of the file.

. Create a `Secret` containing the OAuth client credentials by running the following command:
+
[source,terminal]
----
$ oc create secret generic -n oran-o2ims oauth-client-secrets \
  --from-literal=client-id=<oauth_client_id> \
  --from-literal=client-secret=<oauth_client_secret>
----
+
where:
+
`<oauth_client_id>`:: Specifies the OAuth2 client ID issued by the SMO's authorization server.
`<oauth_client_secret>`:: Specifies the corresponding OAuth2 client secret.

. Update the `Inventory` CR in the `oran-o2ims` namespace to configure the SMO connection. For example, add the following to the `spec` section of the `Inventory` CR:
+
[source,yaml]
----
# ...
spec:
  smo:
    url: https://<smo_hostname>
    registrationEndpoint: <registration_endpoint>
    tls:
      secretName: oran-o2ims-tls-certificate
    oauth:
      url: https://<oauth_server_hostname>/realms/<realm>
      clientSecretName: oauth-client-secrets
      tokenEndpoint: /protocol/openid-connect/token
      scopes:
        - profile
        - openid
        - role:ocloud-manager
      usernameClaim: preferred_username
      groupsClaim: roles
  caBundleName: o2ims-trusted-ca-bundle
# ...
----
+
where:
+
`<smo_hostname>`:: Specifies the hostname or URL of the SMO server.
`<registration_endpoint>`:: Specifies the registration endpoint path on the SMO, for example `/mock_smo/v1/ocloud_observer`.
`spec.smo.tls.secretName`:: Specifies the TLS `Secret`, see "Configure mTLS for API access" for more information. The O-Cloud Manager uses this certificate for outgoing connections to the SMO.
`<oauth_server_hostname>/realms/<realm>`:: Specifies the OAuth2 authorization server hostname and realm used for token exchange.
`clientSecretName`:: Specifies the name of the `Secret` resource containing the OAuth client credentials created in the previous step.
`caBundleName`:: Specifies the name of the `ConfigMap` resource containing the trusted CA bundle. Omit this field if the SMO and OAuth server certificates are signed by a publicly trusted CA.

. Apply the updated `Inventory` CR by running the following command:
+
[source,terminal]
----
$ oc apply -f <inventory_filename>.yaml
----
+
* Replace `<inventory_filename>.yaml` with the name of the file.

.Verification

* Verify that registration with the SMO completed successfully:
+
[source,terminal]
----
$ oc describe inventories.ocloud.openshift.io default -n oran-o2ims
----
+
.Example output
[source,text]
----
Status:
  Deployment Status:
    Conditions:
      Last Transition Time:  2024-10-04T15:39:46Z
      Message:               Registered with SMO at: https://smo.example.com

----
