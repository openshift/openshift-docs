= Troubleshoot Loki per-stream rate limit errors

[role="_abstract"]
Resolve per-stream rate limit errors when a single log stream exceeds the configured per-stream ingestion rate for your LokiStack deployment.

Loki organizes logs into streams, where each stream represents a unique set of labels such as namespace, pod name, container name, and log type. When one stream's log volume exceeds the per-stream rate limit, Loki returns a per-stream rate limit error. Vector retries the request. If the rate limit persists, Vector might lose log records from the affected stream.

A common cause of per-stream rate limit errors is a single container producing an unusually high volume of logs, such as an application running in debug mode or an application in an error loop.

[NOTE]
====
{logging} 5.9 and later enables automatic stream sharding by default, which dynamically adjusts the ingestion rate for each stream. In most cases, the default automatic stream sharding is enough and you do not need to configure `perStreamRateLimit` attributes manually.
====

[IMPORTANT]
====
The `LokiStack` CR is not available on Grafana-hosted Loki. This procedure does not apply to Grafana-hosted Loki servers.
====

.Prerequisites

* You have administrator permissions.
* You have configured the Log Forwarder API to forward logs to Loki.
* The LokiStack ingester pod logs show errors similar to the following:
+
[source,text]
----
level=warn ... err="rpc error: code = Code(429) desc = entry with timestamp ... ignored, reason: 'Per stream rate limit exceeded (limit: 3MB/sec) while attempting to ingest for stream '{kubernetes_container_name="<container_name>", kubernetes_namespace_name="<namespace>", ...}'"
----

.Procedure

. Run the following query in the OpenShift web console under *Observe* -> *Metrics* to confirm per-stream rate limiting is active and to discover the tenants that the per-stream rate limit affects:
+
[source,promql]
----
sum by (tenant, reason) (rate(loki_discarded_samples_total[2m]))
----
+
A nonzero result with `reason="StreamRateLimit"` confirms that per-stream rate limiting is active.

. Find the container producing the high log volume by reviewing the ingester pod logs for the stream labels in the error message:
+
[source,terminal]
----
$ oc -n openshift-logging logs -l app.kubernetes.io/component=ingester | grep "Per stream rate limit exceeded"
----
+
The error message includes labels such as `kubernetes_namespace_name`, `kubernetes_pod_name`, and `kubernetes_container_name` that identify the source container.

. Reduce the volume of logs produced by the affected container:
+
--
* Reduce the log verbosity of the application if it is running in debug or verbose mode.
* Use drop or prune filters to discard log records that are not required before they reach LokiStack.
--
+
For more information, see xref:../configure/configure-filters.adoc#configure-filters[Configure filters].

. If reducing log volume is not enough, update the `perStreamRateLimit` and `perStreamRateLimitBurst` fields in the `LokiStack` CR. Do not exceed the recommended maximum values:
+
[source,yaml]
----
apiVersion: loki.grafana.com/v1
kind: LokiStack
metadata:
  name: logging-loki
  namespace: openshift-logging
spec:
  limits:
    global:
      ingestion:
        perStreamRateLimit: 5
        perStreamRateLimitBurst: 20
# ...
----
+
[NOTE]
====
The `ingestionRate` value must be greater than the `perStreamRateLimit` value.
====

`spec.limits.global.ingestion.perStreamRateLimit`::
  The maximum ingestion rate per second for a single stream, in MB. The recommended maximum value is `5`.

`spec.limits.global.ingestion.perStreamRateLimitBurst`::
  The maximum burst size for a single stream, in MB. The recommended maximum value is `20`.
