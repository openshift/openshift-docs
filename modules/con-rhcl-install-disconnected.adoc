= About {prodname} in disconnected environments

[role="_abstract"]
You can do many tasks on isolated clusters when you use {prodname} as a disconnected gateway. For example, securely route traffic, limit request rates, and handle automatic failover. You can also manage internal network policies, security rules, and automate TLS certificates.

Install {prodname} Operators in disconnected {ocp} environments by mirroring the Operator catalog and images to your internal registry. Use the `oc-mirror` tool to perform the following actions, in order:

. Mirror the Red Hat Operator catalog containing the {prodname} Operator package to your local registry.
. Configure your {ocp} cluster to use the mirrored catalog.
. Install the {prodname} Operator using Operator Lifecycle Manager (OLM).

The following policy requirements apply in disconnected environments:

* `DNSPolicy` objects: Require external DNS provider access. For example, AWS Route53, Google Cloud DNS, or Azure DNS. Limited or non-functional in fully disconnected environments.
//Q: CoreDNS doesn't work in this case?
* `AuthPolicy` objects: External identity provider integrations such as OIDC and OAuth require connectivity to external IdP endpoints - only internal/on-cluster identity providers fully supported
* `RateLimitPolicy` objects: Fully functional.
* `TLSPolicy` objects: Fully functional when cert-manager can access certificate authorities. Limited when external ACME providers such as Let's Encrypt are required.
