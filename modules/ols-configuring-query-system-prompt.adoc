= Configuring a custom query system prompt

[role="_abstract"]
You can replace the default system prompt that {ols-long} sends to the large language model (LLM) with a custom prompt by setting the `querySystemPrompt` field in the `OLSConfig` custom resource (CR).

[WARNING]
====
Setting `querySystemPrompt` replaces the entire default system prompt verbatim. The default system prompt contains the guardrails that restrict {ols-long} to allowed topics. When you provide a custom system prompt, you are solely responsible for including any topic restrictions or behavioral guardrails in that prompt. Omitting these guardrails may allow the LLM to respond to requests outside of the intended scope.
====

.Prerequisites

* You have logged in to the {ocp-product-title} web console as a user with the `cluster-admin` role.

* You have access to the {oc-first}.

* You have installed the {ols-long} Operator and deployed the {ols-long} service.

.Procedure

. Update the `OLSConfig` CR file and add the `querySystemPrompt` field under `spec.ols`:
+
[source,yaml]
----
spec:
  ols:
    querySystemPrompt: "<your_custom_system_prompt>"
----
+
Replace `<your_custom_system_prompt>` with your full prompt text. The value is stored and forwarded to the LLM verbatim, with no additional transformation applied by the operator.

. Run the following command to apply the modified {ols-long} custom configuration:
+
[source,terminal]
----
$ oc apply -f OLSConfig.yaml
----

.Verification

After you apply the configuration, the operator regenerates the service ConfigMap and triggers a rolling restart of the {ols-long} pod. No manual pod intervention is required. Verify that the pod restarted successfully:

[source,terminal]
----
$ oc get pods -n openshift-lightspeed
----

[NOTE]
====
To revert to the default system prompt, remove the `querySystemPrompt` field from the `OLSConfig` CR and reapply. When the field is absent or empty, no custom prompt is mounted and the default {ols-long} prompt is used.
====
