= Tracing

[role="_abstract"]

When you configure {TempoName} for the mesh, the Kiali console shows traces next to metrics, logs, and the traffic graph. Tracing is optional. If distributed tracing is disabled, the trace views stay empty. Users see traces only in namespaces they can access.

Configure the tracing endpoint in the `Kiali` custom resource as described in "Metrics and tracing". On {ocp-product-title}, point the console at {TempoName} and set `url_format` to `openshift` so *View in tracing* opens the {ocp-short-name} console plugin.

== Traces tab

On an application, service, or workload detail page, open the *Traces* tab to chart traces for the selected time range. Select a trace to see trace detail and span detail. The console highlights slow traces with a heatmap that compares each trace duration with inbound request metrics for the same workload.

Each cell in the heatmap is one metric aggregate. Green means the trace was faster than that aggregate. Red means the trace was slower and might be a bottleneck.

== Correlation with metrics, the graph, and logs

On a metrics chart, enable *spans* to overlay trace spans on the time series. Select a span to open the *Traces* tab on that trace.

On the graph, select a node and open the *Traces* tab in the side panel. The panel lists traces for the time range. Select a trace to overlay its spans on the graph and to open span detail.

On the workload *Logs* tab, enable *spans* to mix application logs, Envoy proxy logs, and trace spans in time order. Select a span to open that trace.

In {istio} ambient mode, traces appear after you deploy waypoint proxies. The console correlates workload traces with the waypoint that generated them.
