= Adding a downstream cluster

[role="_abstract"]
Register another downstream cluster with an upstream cluster that is already configured for nested SPIRE. Adding an entry restarts the upstream SPIRE server. Existing downstream servers continue to issue identities from their cached intermediate CAs.

.Prerequisites

* Nested SPIRE is already configured on the upstream cluster, including `spec.grpcEndpoint` and at least one `spec.nestedSpire.downstreamClusters` entry.
* You created a kubeconfig Secret on the upstream cluster for the new downstream cluster. For more information, see xref:#zero-trust-manager-nested-spire-kubeconfig_{context}[Creating a kubeconfig for a downstream cluster].
* The `UPSTREAM_KUBECONFIG` environment variable is set.

.Procedure

. Add the downstream cluster to the upstream `SpireServer` CR by running the following command:
+
[source,terminal]
----
$ oc patch spireserver cluster --type=json --kubeconfig="${UPSTREAM_KUBECONFIG}" -p '[{"op":"add","path":"/spec/nestedSpire/downstreamClusters/-","value":{"name":"<downstream_cluster_name>","kubeConfigSecret":"spire-downstream-<downstream_cluster_name>"}}]'
----
+
where:

`<downstream_cluster_name>`:: Specifies the new downstream cluster's `spec.clusterName`. The value must match the Secret name suffix you created for that cluster.

. Wait for the upstream SPIRE server to roll out by running the following command:
+
[source,terminal]
----
$ oc rollout status statefulset/spire-server -n zero-trust-workload-identity-manager --kubeconfig="${UPSTREAM_KUBECONFIG}" --timeout=300s
----
+
Onboard multiple clusters in one maintenance window when you want to avoid a restart for each cluster.

. Copy the upstream trust bundle to the new downstream cluster and set `spec.upstreamAuthority.spire` there. For more information, see xref:#zero-trust-manager-nested-spire-trust-bundle_{context}[Copying the upstream trust bundle] and xref:#zero-trust-manager-nested-spire-downstream_{context}[Configuring the downstream cluster].

.Verification

* Confirm that the new registration entries are rendered by running the following command:
+
[source,terminal]
----
$ oc get clusterstaticentries.spire.spiffe.io "nested-spire-<downstream_cluster_name>-downstream" -o jsonpath='{.status.rendered}{" "}{.status.masked}{"\n"}' --kubeconfig="${UPSTREAM_KUBECONFIG}"
----
+
The output is `true false`. The downstream server log shows `self_signed=false` after you configure `spec.upstreamAuthority.spire`. For more information, see xref:#zero-trust-manager-nested-spire-verify_{context}[Verifying nested SPIRE].
