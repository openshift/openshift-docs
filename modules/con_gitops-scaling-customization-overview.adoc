= GitOps scaling and customization overview

[role="_abstract"]
Customize and scale {gitops-title} to meet your performance, security, and operational requirements. The Argo CD custom resource (CR) provides configuration options for resource allocation, feature enablement, and component behavior.

*Common customization areas*

You can customize the following aspects of your {gitops-title} deployment:

* *Resource allocation* - Adjust CPU and memory requests and limits for Argo CD components based on workload.
* *High availability* - Configure Redis and other components for high availability and fault tolerance.
* *Scaling* - Implement cluster sharding to distribute application workload across multiple application controller replicas.
* *Repository access* - Configure credentials for private Git repositories and Helm chart repositories.
* *Security settings* - Enable RBAC, configure authentication, and manage TLS certificates.
* *Feature flags* - Enable or disable features such as ApplicationSets, anonymous access, or specific sync options.

*When to customize*

Consider customizing your Argo CD instance when:

* The default resource allocations are insufficient for your number of applications or clusters
* You need high availability for production environments
* You manage more than 100 applications and experience performance degradation
* You have specific security requirements beyond the default configuration
* You want to integrate with organizational infrastructure like monitoring, logging, or authentication systems

*Customization methods*

Apply customizations using one of these methods:

* *Edit the Argo CD CR* - Modify the `ArgoCD` custom resource directly using `oc edit` or declarative YAML manifests.
* *Patch the instance* - Use `oc patch` to update specific fields without modifying the entire CR.
* *GitOps-based management* - Store the Argo CD CR in a Git repository and manage it using GitOps principles.

[IMPORTANT]
====
Do not modify Argo CD deployment manifests directly. The {gitops-title} Operator continuously reconciles the Argo CD instance, so manual changes to deployments, services, or ConfigMaps are reverted automatically. Always make changes through the Argo CD custom resource.
====

*Impact of customization*

Be aware of the following when customizing Argo CD:

* Changes to the Argo CD CR trigger a reconciliation that may restart affected pods
* Resource changes may cause brief service interruptions during pod restarts
* Some configuration changes require manual intervention, such as rotating TLS certificates
* Incorrect configuration can prevent Argo CD from starting or functioning correctly

Test customizations in a non-production environment before applying them to production instances.
