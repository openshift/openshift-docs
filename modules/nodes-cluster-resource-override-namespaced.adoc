= Namespaced-level overcommit using the Cluster Resource Override Operator

[role="_abstract"]
You can set CPU and memory override ratios for a single project, or for subset of pods in that project, by creating a namespaced `ResourceOverride` object. A `ResourceOverride` object replaces the cluster-wide ratios for pods so that workloads do not have to share one overcommit profile.

By using a resource override, you can apply namespaced overcommit ratios to some pods in a project and leave other pods on the cluster-wide profile. This can be helpful when a namespace runs mixed workloads, for example batch jobs and databases, and you do not want to edit Helm charts or pod specs.

When the `ClusterResourceOverride` admission webhook admits a new or updated pod in an opted-in namespace, a matching `ResourceOverride` object in that namespace fully replaces the cluster-wide configuration for that pod. Unspecified ratio fields on the matching object are not inherited from the `ClusterResourceOverride` object. If no `ResourceOverride` object matches the pod, admission uses the `ClusterResourceOverride` object named `cluster`.

To opt-in a namespace, you must add the `clusterresourceoverrides.admission.autoscaling.openshift.io/enabled=true` label to the namespace.

If more than one resource override object in the namespace matches the same pod, the webhook applies the object whose name sorts first in lexicographic, or string, order. 

After you install the Cluster Resource Override Operator, the Operator creates aggregated cluster roles so that the default `admin`, `edit`, and `view` roles include `ResourceOverride` permissions.
Those permissions apply only in projects where a user is bound to the corresponding default role.

.Aggregated ClusterRole objects for a resource override
[cols="2,2,3", options="header"]
|===
| ClusterRole
| Aggregation labels
| Verbs on `autoscaling.openshift.io` `resourceoverrides`

| `resourceoverrides-admin-edit`
| `rbac.authorization.k8s.io/aggregate-to-admin: "true"`
`rbac.authorization.k8s.io/aggregate-to-edit: "true"`
| `get`, `list`, `watch`, `create`, `update`, `patch`, `delete`

| `resourceoverrides-view`
| `rbac.authorization.k8s.io/aggregate-to-view: "true"`
| `get`, `list`, `watch`
|===

The aggregated rules do not include the following permissions:

* `resourceoverrides/status`
* `deletecollection`
* `rbac.authorization.k8s.io/aggregate-to-cluster-reader`

If you use a custom role that does not aggregate to `admin`, `edit`, or `view`, grant the verbs that you need on `autoscaling.openshift.io` `resourceoverrides` in that role.
Do not create the Operator-managed `resourceoverrides-admin-edit` or `resourceoverrides-view` cluster roles yourself.

You cannot create a `ResourceOverride` object in a system namespace, which are namespaces whose names start with `openshift-`, `kube-`, or `kubernetes-`.

For more information, see "Creating a ResourceOverride in a project".
