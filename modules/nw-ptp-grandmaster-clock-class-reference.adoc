= Grandmaster clock class sync state reference

[role="_abstract"]
The following tables describe the PTP grandmaster clock (T-GM) `gm.ClockClass` states, timing offset thresholds, holdover specifications, and DPLL operational states.

Clock class states categorize T-GM clocks based on their accuracy and stability with regard to the Primary Reference Time Clock (PRTC) or other timing source.

Holdover specification is the amount of time a PTP clock can maintain synchronization without receiving updates from the primary time source.

[id="nw-ptp-grandmaster-clock-class-reference-states_{context}"]
== Clock Class states

.T-GM clock class states
[cols="1,3" options="header"]
|====
|Clock class state
|Description

|`gm.ClockClass 6`
|T-GM clock is connected to a PRTC in `LOCKED` mode.
For example, the PRTC is traceable to a GNSS time source.
Timing accuracy is ±40 nanoseconds relative to UTC (ITU-T G.8272 PRTC-B).

|`gm.ClockClass 7`
|T-GM clock is in `HOLDOVER` mode, and within holdover specification.
The clock source might not be traceable to a category 1 frequency source.
Timing accuracy degrades gradually during holdover but remains within ITU-T G.8273.2 Class-B specification (≤1.5 microseconds for ≥4 hours).

|`gm.ClockClass 248`
|T-GM clock is in `FREERUN` mode.
Holdover timeout expired or timing offset exceeded maximum in-spec threshold.
Timing is no longer traceable to PRTC.
|====

[id="nw-ptp-grandmaster-clock-class-reference-thresholds_{context}"]
== Timing offset thresholds

The following timing offset thresholds apply to Telecom Grandmaster deployments on Intel Granite Rapids-D hardware:

.Timing offset thresholds
[cols="1,1,2" options="header"]
|====
|Metric
|Threshold
|Health indicator

|`ts2phc` offset
|< 100 nanoseconds
|Offset within threshold indicates healthy synchronization between NAC adapter PHC and GNSS time source

|`ptp4l` offset
|< 100 nanoseconds
|Offset within threshold indicates healthy PTP message distribution to downstream devices

|`phc2sys` offset
|< 100 nanoseconds
|Offset within threshold indicates healthy synchronization between system clock and NAC adapter PHC
|====

[id="nw-ptp-grandmaster-clock-class-reference-holdover_{context}"]
== Holdover specifications

The following holdover specifications apply to Telecom Grandmaster deployments:

.Holdover specifications
[cols="1,2,2" options="header"]
|====
|Specification
|Value
|Description

|Holdover duration
|Minimum 4 hours
|ITU-T G.8273.2 Class-B requires minimum 4 hours holdover duration during GNSS signal loss

|Holdover accuracy
|Maximum 1.5 microseconds time error
|ITU-T G.8273.2 Class-B requires time error to remain within ±1.5 microseconds during the holdover period

|Holdover timeout configuration
|Default 14400 seconds (4 hours)
|Configurable via `HardwareConfig` `maxInSpecOffset` parameter

|Holdover slope
|`localMaxHoldoverOffset / localHoldoverTimeout` (nanoseconds per second)
|Determines the rate of timing degradation during holdover
|====

[id="nw-ptp-grandmaster-clock-class-reference-dpll_{context}"]
== DPLL operational states

The following DPLL operational states apply to Telecom Grandmaster deployments:

.DPLL operational states
[cols="1,1,2" options="header"]
|====
|DPLL state
|Clock Class
|Description

|LOCKED
|6
|DPLL is synchronized to GNSS time source.
Timing is traceable to PRTC.

|HOLDOVER
|7
|DPLL is maintaining timing without GNSS reference using internal oscillator.
Timing is within ITU-T G.8273.2 Class-B holdover specification.

|FREERUN
|248
|DPLL is not synchronized.
No valid timing reference or holdover timeout expired.
|====

[id="nw-ptp-grandmaster-clock-class-reference-timing-accuracy_{context}"]
== Timing accuracy specifications

The following timing accuracy specifications apply to Telecom Grandmaster deployments:

* ITU-T G.8272 PRTC-B: ±40 nanoseconds relative to UTC when locked to GNSS
* ITU-T G.8273.2 Class-B holdover: ≤1.5 microseconds time error for ≥4 hours during GNSS signal loss
