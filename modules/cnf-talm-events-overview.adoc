= Automating workflows with {cgu-operator-full} events

[role="_abstract"]
The {cgu-operator-first} emits Kubernetes events during `ClusterGroupUpgrade` reconciliation that you can use to trigger automated actions when cluster lifecycle changes occur.

You can use these events for tasks such as running platform readiness checks after provisioning, deploying applications after successful configuration, creating support tickets when policies go noncompliant, or alerting operations teams when remediation fails.
This event-driven approach avoids the need to poll the hub cluster for status changes and enables integration with existing backend systems.

[NOTE]
====
* The Multicluster Global Hub Operator must be installed on the hub cluster to transport events to external automation systems.
* If the Multicluster Global Hub agent runs on the same hub cluster as {cgu-operator}, set `installAgentOnLocal: true` in the `MulticlusterGlobalHub` CR to forward local events to the Kafka bus.
====

Managing large cluster fleets with traditional polling or webhook-based approaches creates challenges at scale:

* Polling repeatedly queries cluster state, creating unnecessary load on the hub cluster, especially when lifecycle events are infrequent.
* Filtering must occur within automation logic, which is inefficient when managing thousands of clusters.
* Failures in polling-based systems do not self-heal, requiring manual intervention.
* Debugging distributed polling logic across many clusters is complex and error-prone.

Event-driven automation addresses these challenges by generating events only when cluster state changes.
The cluster signals when it is ready, rather than external systems repeatedly asking.

{cgu-operator} emits standard Kubernetes events by using the `events.k8s.io/v1` API.
When you deploy the Multicluster Global Hub Operator, the Global Hub agent republishes these events to Kafka in `CloudEvents` format for consumption by external automation systems.
Each event contains metadata annotations that provide structured information about the event scope, affected clusters, and remediation status.

You can consume these events with any system that supports `CloudEvents`, including Event-Driven Ansible through the Multicluster Global Hub Operator.
