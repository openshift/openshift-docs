= Release notes and known issues

This section contains important known issues and limitations for DPF v26.4 on OpenShift 4.22.

[IMPORTANT]
====
Review these known issues before deployment to avoid common problems.
====

== Known issues and limitations

=== DPF uninstall support

* **Issue**: DPF uninstall is not fully supported
* **Workaround**: Set `spec.manageDPUServiceTemplates: false` in the DPFHCPProvisionerConfig resource before uninstalling DPF
* **Impact**: Prevents the dpf-hcp-provisioner operator from managing DPUServiceTemplates during the uninstall process

=== Secret references immutability

* **Issue**: Pull secret and SSH secret references cannot be modified after creation
* **Solution**: Ensure secrets contain the correct data before creating and referencing them in the DPFHCPProvisioner CR
* **Impact**: Secret configuration errors require recreation of the entire DPFHCPProvisioner resource

=== MTU configuration limitations

* **Issue**: MTU changes are not supported after deployment
* **Solution**: Choose MTU value carefully during initial deployment - standard (1500) or jumbo frames (9000)
* **Impact**: MTU changes require complete cluster redeployment

=== Secure boot requirements

* **Issue**: RHCOS BFB image requires DPU firmware version 3.1.0 or later for secure boot
* **Solution**: Use BFB firmware bundles to upgrade DPU firmware before deployment
* **Reference**: Consult NVIDIA DPU firmware update documentation

=== Multi-DPU host limitations

* **Issue**: Multiple DPUs per host are not supported in the current release
* **Impact**: Only one BlueField-3 DPU can be provisioned per physical server
* **Workaround**: Use multiple single-DPU hosts for scale-out deployments

=== HBN daemonset pod issues

* **Issue**: HBN daemonset pods may become stuck in `FailedCreatePodSandBox` state
* **Symptoms**: Pods remain in pending or error state during startup
* **Workaround**: Delete and recreate the problematic pods:
+
[source,terminal]
----
$ oc get pods -n dpf-operator-system | grep hbn
$ oc delete pod <pod-name> -n dpf-operator-system
----
* **Reference**: link:https://redhat.atlassian.net/browse/OCPBUGS-100251[OCPBUGS-100251]

== Troubleshooting common issues

=== Grafana "Application is not available" error

* **Issue**: Grafana route returns application unavailable error
* **Cause**: Grafana pods are scheduled on DPU-dependent worker nodes
* **Solution**: Apply control-plane scheduling to the Grafana CR:
+
[source,yaml]
----
spec:
  deployment:
    spec:
      template:
        spec:
          nodeSelector:
            node-role.kubernetes.io/control-plane: ""
          tolerations:
          - key: node-role.kubernetes.io/master
            operator: Exists
            effect: NoSchedule
          - key: node-role.kubernetes.io/control-plane
            operator: Exists
            effect: NoSchedule
----

=== Missing dashboards in Grafana

* **Issue**: No dashboards appear in the Grafana UI
* **Cause**: ServiceAccount RBAC or datasource configuration issues
* **Solution**: Verify RBAC and datasource connection:
+
[source,terminal]
----
$ oc -n dpf-operator-system get grafanadatasource prometheus
$ oc -n dpf-operator-system get serviceaccount grafana-prometheus-reader
$ oc get clusterrolebinding grafana-prometheus-reader-cluster-monitoring
----

=== DTS ServiceMonitor not finding services

* **Issue**: ServiceMonitor cannot locate DTS services
* **Cause**: Label mismatch or namespace configuration
* **Solution**: Verify the DTS service labels and ServiceMonitor selector:
+
[source,terminal]
----
$ oc -n dpf-operator-system get services -l dpu.nvidia.com/dpuservice-name
$ oc -n dpf-operator-system get servicemonitor doca-telemetry-service-monitor -o yaml
----
