= DPF Operator release notes and troubleshooting

This section provides release notes, known issues, and troubleshooting guidance for the DPF Operator.

== Known issues and limitations

The following known issues and limitations exist in this release:

**DPF Operator uninstall limitations**::
The DPF Operator does not provide an automated uninstall procedure. To completely remove DPF from your cluster, you must manually delete all DPF-related resources and perform cleanup tasks. For detailed uninstall procedures, see the link:https://github.com/NVIDIA/doca-platform/blob/public-release-v26.4/docs/DPF-uninstall.md[NVIDIA DPF uninstall guide].

**Secret references are immutable**::
Once created, DPF secrets cannot be modified. If you need to change credentials or certificates, you must delete and recreate the secret with the updated values.

**MTU configuration constraints**::
The MTU setting in the DPUServiceNAD must match the physical network infrastructure. Mismatched MTU values can cause connectivity issues between the management cluster and hosted cluster.

**Secure boot requirements**::
DPUs with secure boot enabled require signed BFB images. Ensure your BFB images are properly signed and compatible with your secure boot configuration before deployment.

**Multi-DPU host limitations**::
Hosts with multiple DPUs require careful network planning to avoid port conflicts and ensure proper traffic isolation between DPU instances.

**Host-Based Networking (HBN) dependency**::
The Host-Based Networking (HBN) daemonset must be running before DPU provisioning begins. Verify HBN pods are in `Running` state on all worker nodes before starting DPU provisioning.

== Unsupported OVN-Kubernetes features

[IMPORTANT]
====
The following OVN-Kubernetes features are not supported in this Technical Preview:

* User Defined Networks (UDN)
* Egress IP
* Administrative Network Policies (ANP)
* Hybrid Overlay
* Egress Firewall
* Quality of Service (QoS)
* Border Gateway Protocol (BGP)
* Multicast
* Local Gateway Mode
====

== Troubleshooting

=== DPU provisioning issues

**Problem**: DPU provisioning does not start immediately after adding worker nodes to the management cluster

**Cause**: Various configuration or connectivity issues can prevent DPU provisioning from starting automatically.

**Solution**: Follow these diagnostic steps to identify and resolve the issue:

. Verify that all worker CSRs are approved:
+
[source,terminal]
----
$ oc get csr
----
+
Ensure that all CSRs for the worker nodes show an `Approved` status.

. Verify that all DPF controller pods are running:
+
[source,terminal]
----
$ oc get pod -n dpf-operator-system
----
+
Ensure that all pods are in a `Running` state.

. Verify that worker nodes are labeled for DPU provisioning by Node Feature Discovery (NFD):
+
[source,terminal]
----
$ oc get nodes -l feature.node.kubernetes.io/dpu-enabled=""
----
+
.Example output
[source,terminal]
----
NAME                        STATUS     ROLES    AGE   VERSION
host-worker1.example.com   NotReady   worker   62s   v1.35.0
host-worker2.example.com   NotReady   worker   66s   v1.35.0
----

. Check BFB object to ensure the BFB image was downloaded and is ready:
+
[source,terminal]
----
$ oc describe bfb -n dpf-operator-system bf-bundle
----

. Check DPUDeployment object status for information about BFB object state, DPUServiceTemplate objects state, and DPUServiceConfiguration objects state:
+
[source,terminal]
----
$ oc get dpudeployments -n dpf-operator-system dpudeployment -o yaml
----
+
[source,terminal]
----
$ oc -n dpf-operator-system exec deploy/dpf-operator-controller-manager -- /dpfctl describe dpudeployments
----

=== DPU object state issues

**Problem**: DPU objects remain in "DPU Cluster Config" state indefinitely

**Cause**: Pending certificate signing requests (CSRs) in the hosted cluster prevent DPU objects from completing their configuration.

**Solution**: Check for and approve pending CSRs in the hosted cluster:

. Switch to the hosted cluster context:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/hosted-cluster.kubeconfig
----

. Check for pending CSRs and approve them:
+
[source,terminal]
----
$ oc get csr -A
----
+
Approve any pending CSRs related to DPU nodes.

=== Management cluster node readiness issues

**Problem**: Management cluster nodes do not become "Ready" after DPU provisioning is completed

**Cause**: OVN-Kubernetes CNI components may not be running correctly on management or hosted cluster nodes.

**Solution**: Verify OVN-Kubernetes components on both clusters:

. Check OVN-Kubernetes pods on the management cluster:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/management-cluster.kubeconfig
$ oc get pods -n openshift-ovn-kubernetes -o wide
----
+
Ensure all OVN-K pods are running on x86 workers and control plane nodes.

. Check OVN-Kubernetes pods on the hosted cluster:
+
[source,terminal]
----
$ export KUBECONFIG=/path/to/hosted-cluster.kubeconfig
$ oc get pods -n openshift-ovn-kubernetes -o wide
----
+
Ensure all OVN-K pods are running on DPU worker nodes.

=== Grafana deployment issues

**Problem**: Grafana deployment shows "Application is not available"

**Cause**: Grafana pods are scheduled on worker nodes that depend on DPU networking, creating a circular dependency.

**Solution**: Configure Grafana to run on control plane nodes by adding `nodeSelector` and `tolerations` to the Grafana CR:
+
[source,yaml]
----
spec:
  deployment:
    spec:
      template:
        spec:
          nodeSelector:
            node-role.kubernetes.io/control-plane: ""
          tolerations:
          - key: node-role.kubernetes.io/master
            operator: Exists
            effect: NoSchedule
          - key: node-role.kubernetes.io/control-plane
            operator: Exists
            effect: NoSchedule
----

=== DTS metrics collection issues

**Problem**: DTS metrics are not appearing in Prometheus or Grafana

**Cause**: ServiceMonitor is not configured correctly or DTS pods are not running properly.

**Solution**:

. Verify DTS pods are running:
+
[source,terminal]
----
$ oc get pods -n dpf-operator-system -l app=dts
----

. Check ServiceMonitor configuration:
+
[source,terminal]
----
$ oc get servicemonitor -n dpf-operator-system
$ oc describe servicemonitor <servicemonitor-name> -n dpf-operator-system
----

. Verify user-workload monitoring is enabled:
+
[source,terminal]
----
$ oc get configmap cluster-monitoring-config -n openshift-monitoring -o yaml
----

. Check Prometheus targets to ensure DTS endpoints are being scraped:
+
Access the Prometheus web console and navigate to **Status** → **Targets** to verify DTS endpoints are listed and healthy.

=== Certificate and BMC issues

**Problem**: DPU provisioning fails with certificate errors

**Cause**: BMC certificates are not trusted or have expired.

**Solution**:

. Verify BMC certificate validity:
+
[source,terminal]
----
$ openssl s_client -connect <BMC_IP>:443 -servername <BMC_HOSTNAME>
----

. Update certificates in the BMC configuration if needed.

. Ensure the BareMetalHost resource has correct BMC credentials and connection details.

=== Worker node CSR approval issues

**Problem**: Worker node CSR approval fails

**Cause**: Network connectivity issues between management and hosted clusters.

**Solution**:

. Check HBN bridge configuration on worker nodes:
+
[source,terminal]
----
$ oc get pods -n openshift-hbn -o wide
----

. Verify DPU network connectivity:
+
[source,terminal]
----
$ ping <DPU_MANAGEMENT_IP>
----

. Check firewall rules and security groups for required ports.

. Verify the `br-dpu` bridge is correctly configured on worker nodes.

=== DPU node status issues

**Problem**: DPU shows as "NotReady" in hosted cluster

**Cause**: DPU provisioning is incomplete or network configuration issues exist.

**Solution**:

. Check DPU provisioning status:
+
[source,terminal]
----
$ oc get dpuservice -n dpf-operator-system
$ oc get dpu -n dpf-operator-system
----

. Verify DPU node status in hosted cluster:
+
[source,terminal]
----
$ oc get nodes --kubeconfig=<HOSTED_CLUSTER_KUBECONFIG>
----

. Check DPU-related pod logs for specific error messages:
+
[source,terminal]
----
$ oc logs -n dpf-operator-system <DPU_RELATED_POD_NAME>
----

. Verify the DPU firmware and DOCA software versions are compatible with the DPF Operator version.

* DPU hardware model and firmware version
* Complete error messages from relevant log files

* Steps to reproduce the issue
