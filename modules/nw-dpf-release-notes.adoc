= Known issues and limitations

[role="_abstract"]
The following known issues and limitations apply to the NVIDIA DPF Operator on {product-title}.
For DPU provisioning, CSR approval, BMC certificate, and node readiness troubleshooting, see xref:dpf-troubleshooting.adoc#dpf-troubleshooting[Troubleshooting the DPF Operator].

== Known issues and limitations

DPF Operator uninstall limitations::
The DPF Operator does not provide an automated uninstall procedure. To completely remove DPF from your cluster, you must manually delete DPF-related resources and perform cleanup tasks. For detailed uninstall procedures, see the link:https://github.com/NVIDIA/doca-platform/blob/public-release-v26.4/docs/DPF-uninstall.md[NVIDIA DPF uninstall guide].

Secret references are immutable::
After you create DPF secrets, you cannot modify them. If you need to change credentials or certificates, delete and recreate the secret with the updated values.

MTU configuration constraints::
The MTU setting in the `DPUServiceNAD` must match the physical network infrastructure. Mismatched MTU values can cause connectivity issues between the management cluster and the hosted cluster.

Secure boot requirements::
DPUs with secure boot enabled require signed BFB images. Ensure that your BFB images are properly signed and compatible with your secure boot configuration before deployment.

Multi-DPU host limitations::
Hosts with multiple DPUs require careful network planning to avoid port conflicts and to ensure proper traffic isolation between DPU instances.

Host-Based Networking (HBN) dependency::
The Host-Based Networking (HBN) daemon set must be running before DPU provisioning begins. Verify that HBN pods are in the `Running` state on all worker nodes before you start DPU provisioning.

== Grafana deployment issues

Grafana shows that the application is not available::
Grafana pods might be scheduled on worker nodes that depend on DPU networking, which creates a circular dependency.
+
Configure Grafana to run on control plane nodes by adding `nodeSelector` and `tolerations` to the Grafana custom resource:
+
[source,yaml]
----
spec:
  deployment:
    spec:
      template:
        spec:
          nodeSelector:
            node-role.kubernetes.io/control-plane: ""
          tolerations:
          - key: node-role.kubernetes.io/master
            operator: Exists
            effect: NoSchedule
          - key: node-role.kubernetes.io/control-plane
            operator: Exists
            effect: NoSchedule
----

== DTS metrics collection issues

DTS metrics are not appearing in Prometheus or Grafana::
The `ServiceMonitor` might not be configured correctly, or DTS pods might not be running.
+
Verify that DTS pods are running:
+
[source,terminal]
----
$ oc get pods -n dpf-operator-system -l app=dts
----
+
Check the `ServiceMonitor` configuration:
+
[source,terminal]
----
$ oc get servicemonitor -n dpf-operator-system
$ oc describe servicemonitor <servicemonitor-name> -n dpf-operator-system
----
+
Verify that user workload monitoring is enabled:
+
[source,terminal]
----
$ oc get configmap cluster-monitoring-config -n openshift-monitoring -o yaml
----
+
Check Prometheus targets to ensure that DTS endpoints are being scraped.
Access the Prometheus web console and go to *Status* -> *Targets* to verify that DTS endpoints are listed and healthy.

== Getting support

For additional support and troubleshooting resources:

* NVIDIA DPF documentation: link:https://docs.nvidia.com/networking/display/dpf2504/[NVIDIA DPF User Guide]
* NVIDIA GitHub repository: link:https://github.com/NVIDIA/doca-platform[NVIDIA DOCA Platform on GitHub]
* NVIDIA DPF issues: link:https://github.com/NVIDIA/doca-platform/issues[Report issues on GitHub]
* Red{nbsp}Hat Support: Open a support case through the Red{nbsp}Hat Customer Portal if you have an active subscription

When you report issues, include the following information:

* {product-title} version and DPF Operator version
* DPU hardware model and firmware version
* Complete error messages from relevant log files
* Output of diagnostic commands listed in troubleshooting topics
* Network configuration and topology details
* Steps to reproduce the issue
* DPF resource configurations (`DPUCluster`, `DPUFlavor`, and related objects)
