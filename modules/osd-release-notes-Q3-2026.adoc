= Q3 2026

[role="_abstract"]
The following items were added during the third quarter of 2026.

Bring your own firewall rules for {product-title} on {gcp-short} with Workload Identity Federation for shared VPC deployments::
+
Starting with {product-title} version 4.21, for shared VPC deployments on {gcp-short}, you can create the required cluster firewall rules in the host project before installation instead of granting `compute.firewalls.create` and `compute.firewalls.delete` permissions to Workload Identity Federation (WIF) service accounts. This approach gives your network security team control over firewall rule management in the shared VPC host project and reduces the permissions granted to cluster-managed service accounts, aligning with the principle of least privilege.
+
You can create firewall rules by using the `ocm gcp create firewall-rules` command in manual mode, which generates a shell script containing the required `gcloud` commands for you to review and execute. The command supports both `public` and `private` firewall profiles for public and Private Service Connect clusters.
+
[IMPORTANT]
====
At this time, only manual mode is supported. Automatic mode is not yet available. Additionally, this permission reduction applies only to shared VPC deployment configurations. For service project deployments, the `compute.firewalls` permissions cannot yet be removed.
====
+
For more information, see link:https://docs.redhat.com/en/documentation/openshift_dedicated/4/html/planning_your_environment/gcp-ccs#osd-gcp-firewall-rules_gcp-ccs[Create firewall rules for reduced Workload Identity Federation permissions on {gcp-short}].

Reduced permissions for Shared VPC installations on {gcp-short}::
+
For Shared VPC deployments, you can now replace the broad `roles/compute.networkAdmin` and `roles/compute.securityAdmin` administrative roles on the host project with a custom role that grants only the minimal permissions required. Combined with pre-created firewall rules, this significantly reduces the privileges required across multi-project Shared VPC architectures.
+
For more information, see link:https://docs.redhat.com/en/documentation/openshift_dedicated/4/html/planning_your_environment/gcp-ccs#osd-gcp-shared-vpc-firewall-rules_gcp-ccs[Configuring reduced permissions for a Shared VPC host project on {gcp-short}].

Workload Identity Federation configuration version pruning with the {cluster-manager} CLI::
+
You can now prune older version support from existing Workload Identity Federation (WIF) configurations by using the `ocm` CLI. By restricting a WIF configuration to version 4.20 and later, you can remove legacy permissions that are no longer required, improving the security of your {gcp-short} environment.
+
When pruning WIF configurations, you must explicitly specify the versions to retain using the `--versions` parameter to avoid inadvertently re-adding deprecated versions. For example, use `--versions v4.20,v4.21,v4.22` to ensure that the WIF configuration supports only version 4.20 and later.
+
[NOTE]
====
Before removing deprecated CSI driver and Machine API permissions from your WIF configuration, you must first prune the configuration to include only version 4.20 and later. This ensures that the deprecated permissions from version 4.19 are not re-added during the update process.
====
+
For more information, see link:https://docs.redhat.com/en/documentation/openshift_dedicated/4/html/creating-a-gcp-cluster-with-workload-identity-federation/pruning-wif-configuration-versions_osd-creating-a-cluster-on-gcp-with-workload-identity-federation[Pruning Workload Identity Federation configuration versions].
