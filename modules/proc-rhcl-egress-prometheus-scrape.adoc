= Collect egress gateway metrics in your monitoring stack

[role="_abstract"]
Confirm that your monitoring stack scrapes the pods of your egress `Gateway` object. Gateway pods expose their metrics on the `/stats/prometheus` path of port `15020`.

When you set the `spec.observability.enable` field of the `Kuadrant` custom resource (CR) to `true`, the {prodname} Operator creates a `ServiceMonitor` object and a `PodMonitor` object in each gateway namespace. These monitors scrape every gateway in the namespace, including your egress `Gateway` object. No egress-specific monitor is required.

.Prerequisites

include::snippets/egress-gateway-prereqs.adoc[]

* You configured a monitoring stack on your {ocp} cluster.

.Procedure

. Confirm that the monitors exist in the namespace of your egress `Gateway` object by running the following command:
+
[source,terminal]
----
$ oc get servicemonitor,podmonitor -A -l kuadrant.io/observability=true
----

. If your monitoring stack discovers targets from pod annotations instead, inspect the annotations of the egress gateway pod by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc get pods -n _<gateway_system>_ \
    -l gateway.networking.k8s.io/gateway-name=_<kuadrant_egressgateway>_ \
    -o jsonpath='{.items[0].metadata.annotations}'
----
+
* Replace `_<gateway_system>_` with the namespace where you applied your egress `Gateway` object.
* Replace `_<kuadrant_egressgateway>_` with the name of your egress `Gateway` object.
* The output must contain the `prometheus.io/scrape: "true"` and `prometheus.io/port: "15020"` annotations.

.Verification

* In the metrics view of the {ocp} web console, run the following query:
+
[source,text,subs="+quotes"]
----
sum(rate(istio_requests_total{source_workload="_<kuadrant_egressgateway>_-istio"}[5m]))
----
+
The query returns a value greater than zero when the monitoring stack collects metrics from your egress `Gateway` object.
