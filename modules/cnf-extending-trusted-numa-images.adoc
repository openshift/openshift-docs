= Extending the trusted image list

[role="_abstract"]
If you need to use custom scheduler or Resource Topology Exporter (RTE) images that are not in the NUMA Resources Operator's default trusted lists, you can add the images' SHA-256 digests to the trusted lists by configuring environment variables in the NUMA Resources Operator subscription.

[WARNING]
====
Adding custom images to the trusted lists allows those images to run with elevated privileges. Ensure that you trust the source and integrity of any custom images before adding them to the trusted lists.

Only add custom images if required for your environment.
====

[id="cnf-extending-trusted-scheduler-images_{context}"]
== Extending the trusted scheduler image list

You can extend the trusted scheduler image list by adding custom scheduler image digests to the `SCHEDULER_IMAGE_DIGESTS` environment variable.

.Prerequisites

* You have the SHA-256 digest of your custom scheduler image.
* You have verified the integrity and source of the custom scheduler image.

.Procedure

. Obtain the SHA-256 digest of your custom scheduler image by running the following command:
+
[source,terminal]
----
$ oc image info <your_custom_scheduler_image> -o json | jq -r '.digest'
----
+
Below is an example of the output:
+
[source,terminal]
----
sha256:819186877851017bb783d0c291fb990b7136c64a1fac7b031942e4ee1e0c3d53
----

. Add the digest to the NUMA Resources Operator subscription's trusted list by running the following command:
+
[source,terminal]
----
$ oc patch subscription numaresources-operator \
  -n openshift-numaresources \
  --type=merge \
  -p '{"spec":{"config":{"env":[{"name":"SCHEDULER_IMAGE_DIGESTS","value":"sha256:819186877851017bb783d0c291fb990b7136c64a1fac7b031942e4ee1e0c3d53"}]}}}'
----
+
[NOTE]
====
To add multiple custom digests, use a comma-separated list of digests in the `value` field. For example:

[source,terminal]
----
$ oc patch subscription numaresources-operator \
  -n openshift-numaresources \
  --type=merge \
  -p '{"spec":{"config":{"env":[{"name":"SCHEDULER_IMAGE_DIGESTS","value":"sha256:digest1,sha256:digest2"}]}}}'
----
====

. Wait for the NUMA Resources Operator pod to restart with the new configuration:
+
[source,terminal]
----
$ oc get pods -n openshift-numaresources -w
----

. Verify that the NUMA Resources Operator deployment has the updated trusted image list:
+
[source,terminal]
----
$ oc get deployment numaresources-operator-controller-manager \
  -n openshift-numaresources \
  -o jsonpath='{.spec.template.spec.containers[0].env[?(@.name=="SCHEDULER_IMAGE_DIGESTS")].value}{"\n"}'
----
+
Below is an example of the output:
+
[source,terminal]
----
sha256:819186877851017bb783d0c291fb990b7136c64a1fac7b031942e4ee1e0c3d53
----

. Update the `NUMAResourcesScheduler` custom resource to use the digest-based image reference by running the following command:
+
[source,terminal]
----
$ oc patch numaresourcesscheduler numaresourcesscheduler \
  --type=merge \
  -p '{"spec":{"imageSpec":"<your_registry>/<your_image>@sha256:819186877851017bb783d0c291fb990b7136c64a1fac7b031942e4ee1e0c3d53"}}'
----

.Verification

. Verify that the scheduler is not in a degraded state by running the following command:
+
[source,terminal]
----
$ oc get numaresourcesscheduler numaresourcesscheduler \
  -o jsonpath='{.status.conditions[?(@.type=="Degraded")].status}{"\n"}'
----
+
Below is an example of the output:
+
[source,terminal]
----
False
----

. Verify that the scheduler pods are running with your custom image by running the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-numaresources -l app=secondary-scheduler \
  -o jsonpath='{.items[0].spec.containers[0].image}{"\n"}'
----

== Extending the trusted RTE image list

You can extend the trusted RTE image list by adding custom RTE image digests to the `RTE_IMAGE_DIGESTS` environment variable.

.Prerequisites

* You have the SHA-256 digest of your custom RTE image.
* You have verified the integrity and source of the custom RTE image.

.Procedure

. Obtain the SHA-256 digest of your custom RTE image by running the following command:
+
[source,terminal]
----
$ oc image info <your_custom_rte_image> -o json | jq -r '.digest'
----
+
Below is an example of the output:
+
[source,terminal]
----
sha256:b5d8e2a7c3f1a9d4e6f8b0c2d5e7a9b1c3d5e7f9a1b3c5d7e9f1a3b5c7d9e1f3
----

. Add the digest to the NUMA Resources Operator subscription's trusted list by running the following command:
+
[source,terminal]
----
$ oc patch subscription numaresources-operator \
  -n openshift-numaresources \
  --type=merge \
  -p '{"spec":{"config":{"env":[{"name":"RTE_IMAGE_DIGESTS","value":"sha256:b5d8e2a7c3f1a9d4e6f8b0c2d5e7a9b1c3d5e7f9a1b3c5d7e9f1a3b5c7d9e1f3"}]}}}'
----
+
[NOTE]
====
To add multiple custom digests, use a comma-separated list of digests in the `value` field. For example:

[source,terminal]
----
$ oc patch subscription numaresources-operator \
  -n openshift-numaresources \
  --type=merge \
  -p '{"spec":{"config":{"env":[{"name":"RTE_IMAGE_DIGESTS","value":"sha256:digest1,sha256:digest2"}]}}}'
----
====

. Wait for the NUMA Resources Operator pod to restart with the new configuration:
+
[source,terminal]

+
[source,terminal]

----
+
Below is an example of the output:
+
[source,terminal]
----
sha256:b5d8e2a7c3f1a9d4e6f8b0c2d5e7a9b1c3d5e7f9a1b3c5d7e9f1a3b5c7d9e1f3
----

. Update the `NUMAResourcesOperator` custom resource to use the digest-based image reference by running the following command:
+
[source,terminal]
----
$ oc patch numaresourcesoperator numaresourcesoperator \
  --type=merge \
  -p '{"spec":{"exporterImage":"<your_registry>/<your_image>@sha256:b5d8e2a7c3f1a9d4e6f8b0c2d5e7a9b1c3d5e7f9a1b3c5d7e9f1a3b5c7d9e1f3"}}'
----

.Verification

. Verify that the operator is not in a degraded state by running the following command:
+
[source,terminal]
----
$ oc get numaresourcesoperator numaresourcesoperator \
  -o jsonpath='{.status.conditions[?(@.type=="Degraded")].status}{"\n"}'
----
+
Below is an example of the output:
+
[source,terminal]
----
False
----

. Verify that the RTE daemon set pods are running with your custom image by running the following command:
+
[source,terminal]
----
$ oc get ds -n openshift-numaresources -l app=numaresources-operator \
  -o jsonpath='{.items[0].spec.template.spec.containers[?(@.name=="rte")].image}{"\n"}'
----
