= PublicAndPrivate topology for hosted clusters on {azure-short}

[role="_abstract"]
The `PublicAndPrivate` topology enables dual-path routing so that external automation and private workloads can reach the Kubernetes API Server endpoint simultaneously. As a result, you can meet compliance requirements without sacrificing CI/CD pipeline access. 

The topology you select at cluster creation determines which {azure-short} resources are provisioned and whether the Kubernetes API Server endpoint is reachable from the public internet, a private {azure-short} VNet, or both.

Hosted clusters on {azure-short} support 3 Kubernetes API Server endpoint access topologies: `Public`, `Private`, and `PublicAndPrivate`.

`Public` (default)::
The Kubernetes API Server endpoint is accessible from the public internet only. No private {azure-short} networking resources are created. Use this topology for non-regulated environments or CI/CD workloads that do not require private control-plane access.

`PublicAndPrivate`::
The Kubernetes API Server endpoint is accessible from the public internet and from a private {azure-short} VNet simultaneously. {azure-short} creates both public and private networking resources. Use this topology when external automation requires public API access and internal workloads require private network isolation.

`Private`::
The Kubernetes API Server endpoint is accessible only from a private {azure-short} VNet. No public {azure-short} Load Balancer is created for the Kubernetes API Server endpoint. Use this topology for regulated environments where the control plane must never be reachable from the public internet.

[NOTE]
====
The {azure-short} Private Link Service, {azure-short} Private Endpoint, and Private DNS Zones rows apply only to self-managed {hcp} clusters using the `PrivateLink` private type.
====

On self-managed hosted clusters ({azure-short} Private Link), the topology directly drives the `IngressController` `LoadBalancer` scope. A dedicated {azure-short} Private Link Service infrastructure is created per cluster for private access. The `PrivateLink` private type provisions an Internal Load Balancer, Private Link Service, Private Endpoint, and Private DNS zones for each cluster independently.
