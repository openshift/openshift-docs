= Access to VM pod networks from external networks on Google Cloud

[role="_abstract"]
The {gcp-short} Cloud Router installs the virtual machine (VM) pod network routes only as dynamic routes in the Virtual Private Cloud (VPC) network that hosts your cluster.

The Cloud Router does not advertise these routes to networks outside the VPC network, such as an on-premises network connected over {gcp-short} Cloud Interconnect or a VPN, or a peered VPC network.

The recommended architecture is to set static routes in external networks for the pod network Classless Inter-Domain Routing (CIDR) ranges, with a next hop that lands the traffic inside the VPC network.
The VPC network can then use the dynamic routes installed by the Cloud Router to forward the traffic to compute nodes.

[IMPORTANT]
====
Red{nbsp}Hat does not recommend using the BGP Cloud Connector to directly peer with routers in other networks or with services other than the Cloud Router.
When you use `platform: Manual`, the peer list does not get updates as compute nodes join or leave the cluster.
====

Configure external connectivity so that both of the following conditions are met:

* The external network has a route for the VM `_<pod_network_cidr>_` whose next hop lands the traffic inside the VPC network.
For example, if the external network is a VPC network connected to the VPC network of the cluster, the external network should have a route whose destination range matches a `BGPRouting.spec.network.subnets` entry and whose next hop forwards the traffic into the VPC network of the cluster.
You can add this route statically or by propagating the route through your dynamic routing configuration.
* No NAT device is placed in the path between the external host and the VM, because the VM must be reachable at its pod network IP address.
