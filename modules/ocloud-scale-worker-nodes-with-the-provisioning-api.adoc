= Scale worker nodes with the Provisioning API

[role="_abstract"]
You can scale worker nodes through the Provisioning REST API by sending an update request with a modified `nodes` array.

.Prerequisites

* You authenticated to the O-Cloud Manager REST API and set the `MY_TOKEN` environment variable.
* The cluster is fully provisioned with `provisioningPhase: fulfilled`.

.Procedure

. Get the O-Cloud Manager API hostname by running the following command:
+
[source,terminal]
----
$ export API_HOST=$(oc get routes -n oran-o2ims -o jsonpath='{.items[0].spec.host}')
----

. Set the Provisioning API base URL by running the following command:
+
[source,terminal]
----
$ export PROV_URL="https://${API_HOST}/o2ims-infrastructureProvisioning/v1"
----

. Retrieve the current provisioning request by running the following command:
+
[source,terminal]
----
$ curl -ks -H "Authorization: Bearer ${MY_TOKEN}" \
  "${PROV_URL}/provisioningRequests/<uuid>" | jq > current-request.json
----
+
where:
+
`<uuid>`:: Specifies the UUID of the provisioning request for the target cluster.
`@current-request.json`:: Specifies the output path to the file containing the returned JSON.

. Modify the `current-request.json` file to add or remove entries in the `templateParameters.clusterInstanceParameters.nodes` array. The following example adds a third worker node:
+
[source,json]
----
{
  "provisioningRequestId": "<uuid>",
  "templateName": "std-ran-du",
  "templateVersion": "v4-Y-Z-2",
  "templateParameters": {
    "nodeClusterName": "cluster1",
    "oCloudSiteId": "site-east-1",
    "clusterInstanceParameters": {
      "clusterName": "cluster1",
      "nodes": [
        { "hostName": "master-1.example.com" },
        { "hostName": "master-2.example.com" },
        { "hostName": "master-3.example.com" },
        { "hostName": "worker-1.example.com" },
        { "hostName": "worker-2.example.com" },
        { "hostName": "worker-3.example.com" } // Adding a new worker node
      ]
    }
  }
}
----
+
[NOTE]
====
The PUT request replaces the entire provisioning request. Retrieve the current state first, then send the complete modified payload. Do not send partial updates.
====

. Send the updated provisioning request by running the following command:
+
[source,terminal]
----
$ curl -ks -X PUT \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${MY_TOKEN}" \
  "${PROV_URL}/provisioningRequests/<uuid>" \
  -d @current-request.json | jq
----
+
where:
+
`<uuid>`:: Specifies the UUID of the provisioning request for the target cluster.
`@current-request.json`:: Specifies the path to the file containing the updated provisioning request.

.Verification

* Query the provisioning request status and verify that `provisioningPhase` returns to `fulfilled` by running the following command:
+
[source,terminal]
----
$ curl -ks -H "Authorization: Bearer ${MY_TOKEN}" \
  "${PROV_URL}/provisioningRequests/<uuid>" | jq -r '.status.provisioningStatus.provisioningPhase'
----
