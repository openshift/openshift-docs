= Limitations of egress IP addresses with host static routes

[role="_abstract"]
Egress traffic that uses an egress IP address hosted on the primary network interface of a node does not use static routes that are configured in the main routing table of the host, even when you set the `gatewayConfig.routingViaHost` parameter to `true` in the `Network` custom resource (CR).

For this traffic, the OVN-Kubernetes network plugin makes the routing decision by using the default route of the OVN gateway router, so a more specific static route in the main routing table does not apply. Egress traffic from pods that no `EgressIP` object selects is not affected.

To determine which network interface hosts an egress IP address, inspect the `k8s.ovn.org/node-primary-ifaddr` and `k8s.ovn.org/host-cidrs` annotations on the node. For more information, see "Considerations for using an egress IP address on additional network interfaces".

Consider a node that is labeled with `k8s.ovn.org/egress-assignable: ""` and that has the following network configuration:

* A default gateway of `192.168.1.1` on the `br-ex` interface.
* A static route in the main routing table for the `192.168.2.0/24` network with a next hop of `192.168.1.2`.

Egress traffic that uses an egress IP address on this node and that is destined for the `192.168.2.0/24` network leaves the node through the `192.168.1.1` default gateway instead of the `192.168.1.2` next hop that the static route specifies.
