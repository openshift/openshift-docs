= Security defaults by deployment mode

[role="_abstract"]
Use the following reference to understand which security controls {ols-long} applies by default, where each control applies, and how to verify and change it. The defaults depend on whether you deploy {ols-long} with the Operator or run the service directly.

[id="ols-security-defaults-table_{context}"]
== Default security controls

The following table summarizes the security controls in an Operator-managed deployment.

[cols="2,1,2,2",options="header"]
|===
| Security control | Default | Applies to | Configuration field

| Query filtering and redaction
| Disabled
| User query path in both Classic and agentic modes. Does not apply to tool results.
| `spec.ols.queryFilters`

| Tool-result safety inspection
| Enabled
| Tool results in Classic {ols-long} and the DeepAgents runtime.
| `spec.ols.guardrails.toolResultInspection.enabled`

| Cluster introspection (Observability MCP server)
| Enabled
| Cluster interaction in both Classic and agentic modes.
| `spec.ols.introspectionEnabled`

| Human-in-the-loop (HITL) approval for write operations
| Enabled when cluster introspection is enabled
| Non-read tool operations in both Classic and agentic modes.
| `spec.ols.toolsApprovalConfig`
|===

[NOTE]
====
Query filtering and redaction is disabled until you define at least one regular expression pattern in `spec.ols.queryFilters`. Even when enabled, redaction applies only to the user query path and does not filter tool results.
====

[NOTE]
====
When you run the service directly without the Operator, the tool-result safety inspection default differs: inspection is disabled when `ols_config.guardrails.tool_result_inspection.enabled` is omitted. The Operator writes an effective value of `true` when the `OLSConfig` field is omitted.
====

[id="ols-security-defaults-verify_{context}"]
== Verifying and changing the defaults

To verify the current configuration, inspect the `OLSConfig` CR:

[source,terminal]
----
$ oc get olsconfig cluster -o yaml
----

To change a default, edit the `OLSConfig` CR and set the corresponding field:

[source,terminal]
----
$ oc edit olsconfig cluster
----

The following example disables cluster introspection and enables tool-result safety inspection:

[source,yaml]
----
spec:
  ols:
    introspectionEnabled: false
    guardrails:
      toolResultInspection:
        enabled: true
----

After you save the change, the Operator regenerates the service configuration and restarts the {ols-long} pod. Verify that the pod restarted successfully:

[source,terminal]
----
$ oc get pods -n openshift-lightspeed
----
