[id="compliance-operator-cel-reference-things-to-know_{context}"]
= Things to know about CEL profiles

[role="_abstract"]
Review scanner constraints, `CustomRule` fields, and result formats before you deploy CEL tailored profiles in production.

[id="compliance-operator-cel-reference-limitations_{context}"]
== Limitations

* A `Profile` or `TailoredProfile` object supports only one scanner type.
  Do not mix CEL rules with OpenSCAP rules in the same profile.
* CEL scans do not produce Asset Reporting Format (ARF) results.
  Use `ComplianceCheckResult` objects to review CEL output.
* The Compliance Operator validates CEL expressions when you create or update a `CustomRule` object.
  Fix expression errors before you bind the tailored profile to a scan.

For the current support status of CEL scanning, see the Compliance Operator release notes in Additional resources.

[id="compliance-operator-cel-reference-customrule-fields_{context}"]
== CustomRule object fields for CEL checks

The following `CustomRule` `spec` fields are required for CEL platform checks:

[cols="1,2a",options="header"]
|===
|Field |Description

|`scannerType`
|Must be `CEL` for CEL checks.

|`checkType`
|Set to `Platform` for Kubernetes API checks or `Node` for node-level checks that the compliance SDK evaluates.

|`expression`
|CEL expression that evaluates to `true` when the check passes.

|`inputs`
|List of named inputs.
Each input loads Kubernetes resources through `kubernetesInputSpec` or node data through SDK inputs.

|`failureReason`
|Message that appears on failing `ComplianceCheckResult` objects.

|`severity`
|Rule severity, such as `high` or `medium`.
|===

When you reference a `CustomRule` object from a `TailoredProfile`, set `kind: CustomRule` on each `enableRules` entry.
Set the `compliance.openshift.io/product-type` annotation on the `TailoredProfile` object to `Platform` or `Node` to match the rule `checkType`.

[id="compliance-operator-cel-reference-output_{context}"]
== CEL scan output

CEL scans create `ComplianceCheckResult` objects in the `openshift-compliance` namespace.
Each result name includes the scan name and the `CustomRule` identifier.

When a `ProfileBundle` object references CEL content through `spec.celContentFile`, the parser validates expressions at ingest time and reports errors in the `ProfileBundle` status.
CEL scans do not write OpenSCAP ARF files.
To export or archive results, use the raw results workflow described in the raw results documentation in Additional resources.
