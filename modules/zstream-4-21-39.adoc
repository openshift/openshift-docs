== Fixed issues

* Before this update, the `AWSMachine` controller was requeuing machine instances before confirming the presence of tags. As a consequence, duplicate {aws-first} EC2 instances were created. With this release, the `AWSMachine` controller verifies tags before requeuing instances. As a result, duplicate EC2 instances are not created. (link:https://issues.redhat.com/browse/OCPBUGS-112498[OCPBUGS-112498])

* Before this update, when you removed failure domains from the infrastructure specification, the {vmw-first} Problem Detector (VPD) logged errors about failure domain labels missing from nodes. As a consequence, VPD logged warnings that were not relevant. With this release, VPD improves processing logic for failure domain changes in the infrastructure specification. As a result, these unnecessary warnings no longer appear. (link:https://issues.redhat.com/browse/OCPBUGS-127130[OCPBUGS-127130])

* Before this update, {vmw-first} machine reconciliation made repeated vCenter API calls for the same virtual machine state and attached tags, and could repeat operations when task references were missing or status updates failed. As a consequence, reconciliation generated unnecessary vCenter API load, could submit duplicate virtual machine operations, and slowed machine provisioning in large clusters. With this release, VM power state and tag lookups are cached, attached-tag queries are batched, redundant property calls are skipped, and clone task references are retained across reconciles. As a result, new machines provision more reliably and with less vCenter load in large {vmw-short}-backed clusters. (link:https://issues.redhat.com/browse/OCPBUGS-129659[OCPBUGS-129659])
