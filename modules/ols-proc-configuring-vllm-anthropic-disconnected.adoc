= Configuring the vLLM Anthropic provider in disconnected environments

[role="_abstract"]
In a disconnected or air-gapped environment, you host the vLLM server locally, for example, by using {rhelai}, and point {ols-long} at the local Anthropic-compatible `/v1/messages` endpoint. Because the LLM runs inside your restricted network, {ols-long} does not require external internet access to reach the model.

.Prerequisites

* You have a disconnected cluster in which the {ols-long} Operator images are mirrored. For more information, see "Mirroring in disconnected environments" in the {ocp-product-title} documentation.
* You have a vLLM server, version 0.24 or later, hosted locally within your restricted network that exposes the Anthropic-compatible `/v1/messages` endpoint.
* The {ols-long} deployment can reach the local vLLM endpoint over a secure connection.

.Procedure

. Confirm that the local vLLM server is reachable from the cluster and serves the Anthropic-compatible `/v1/messages` endpoint.

. Create the credentials secret and configure the `OLSConfig` custom resource (CR) as described in "Configuring vLLM with the Anthropic provider". For the provider `url`, use the internal address of your local vLLM server instead of an external endpoint.
+
[NOTE]
====
If your local vLLM server uses a certificate that is signed by a private or internal certificate authority (CA), configure a trusted CA certificate for the LLM so that {ols-long} can establish a secure connection. For more information, see "Configure a trusted CA certificate for the LLM".
====

. Verify the deployment as described in "Configuring vLLM with the Anthropic provider".
