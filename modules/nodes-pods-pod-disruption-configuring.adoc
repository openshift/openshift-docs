= Specify the number of pods that must be up with pod disruption budgets

[role="_abstract"]
You can use a `PodDisruptionBudget` object to specify the minimum number or percentage of replicas that must be up at a time. This ensures pod availability during voluntary disruptions such as node maintenance or cluster updates.

The following procedure shows how to configure a pod disruption budget.

Specify either `spec.minAvailable` or `spec.maxUnavailable`. These fields are mutually exclusive. The API rejects a pod disruption budget that sets both fields. The following examples show the fields as alternatives.

Set `spec.selector` to the labels of the pods that you want to protect. Use `matchLabels`, `matchExpressions`, or both. The results of `matchLabels` and `matchExpressions` are logically conjoined.

[WARNING]
====
An omitted `selector` matches no pods, so the budget does not protect any pods. An empty selector (`selector: {}`) selects every pod in the project. A budget that selects every pod can block node drains during maintenance.
====

.Procedure

. Create a YAML file with the an object definition similar to the following:
+
[source,yaml]
----
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: my-pdb
spec:
  minAvailable: 2
  selector:
    matchLabels:
      name: my-pod
----
+
where:
+
--
`apiVersion`:: Specifies the `policy/v1` API group.
`spec.minAvailable`:: Specifies the minimum number of pods that must be available simultaneously. This can
be either an integer or a string specifying a percentage, for example, `20%`.
`spec.selector`:: Specifies a label query over the pods to protect. Set `matchLabels` or `matchExpressions` to the labels of those pods. The results of `matchLabels` and `matchExpressions` are logically conjoined. An omitted `selector` matches no pods. An empty selector (`selector: {}`) selects every pod in the project and can block node drains.
--
+
Or:
+
[source,yaml]
----
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: my-pdb
spec:
  maxUnavailable: 25%
  selector:
    matchLabels:
      name: my-pod
----
+
where:
+
--
`apiVersion`:: Specifies the `policy/v1` API group.
`spec.maxUnavailable`:: Specifies the maximum number of pods that can be unavailable simultaneously. This can
be either an integer or a string specifying a percentage, for example, `20%`.
`spec.selector`:: Specifies a label query over the pods to protect. Set `matchLabels` or `matchExpressions` to the labels of those pods. The results of `matchLabels` and `matchExpressions` are logically conjoined. An omitted `selector` matches no pods. An empty selector (`selector: {}`) selects every pod in the project and can block node drains.
--

. Run the following command to add the object to project:
+
[source,terminal]
----
$ oc create -f </path/to/file> -n <project_name>
----
