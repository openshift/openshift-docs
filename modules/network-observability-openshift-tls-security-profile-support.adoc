= OpenShift TLS security profile support

[role="_abstract"]
The Network Observability Operator automatically inherits the cluster-wide TLS security profile configuration from {product-title}, applying consistent encryption standards to all managed components.

The Network Observability Operator reads the TLS security profile from the `APIServer` configuration and applies the profile's minimum TLS version, cipher suites, and cryptographic curve preferences to its internal servers and managed components. No manual configuration is required; the Network Observability Operator manages this automatically.

[id="network-observability-tls-profile-affected-components_{context}""]
== Affected components

The TLS security profile applies to the following network observability components:

* Operator metrics and webhook servers
* eBPF agent
* flowlogs-pipeline
* Console plugin

The Network Observability Operator detects profile updates and performs a graceful reload to apply the new settings to all managed components.

[id="network-observability-tls-profile-rollout-behavior_{context}""]
== Expected behavior during TLS profile changes

When the cluster TLS security profile changes, the API server rolls out the new configuration across the control plane. During this rollout, network observability components may temporarily report a degraded status, and flow collection or access to flows may be interrupted.

This occurs because the Network Observability Operator and its managed components reload to apply the updated TLS settings while the cluster reconciles the new security profile. Normal operation resumes after the rollout completes and all components have restarted with the new TLS configuration.
