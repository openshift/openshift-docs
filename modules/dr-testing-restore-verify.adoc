= Verifying that the restore was successful

[role="_abstract"]
After you simulate etcd failure on nonrecovery nodes and restore from backup, verify that the restore process was successful.

[WARNING]
====
You must have SSH access to the cluster. Without SSH access, you cannot disable etcd or manage the `kubelet` service on nonrecovery nodes.
====

.Prerequisites

* You have completed the steps in "Simulating an etcd failure".
* You have restored your cluster to an earlier state by using etcd backup.

.Procedure

. Monitor the recovery progress of the control plane by running the following command:
+
[source,terminal]
----
$ oc adm wait-for-stable-cluster
----

. After you restore the cluster and the API responds, use SSH to connect to each nonrecovery node and enable the `kubelet` service by running the following command:
+
[source,terminal]
----
$ sudo systemctl enable kubelet.service --now
----

. Exit every SSH session.

. Verify that your nodes return to the `READY` state by running the following command:
+
[source,terminal]
----
$ oc get nodes
----

. Verify that etcd is available by running the following command:
+
[source,terminal]
----
$ oc get pods -n openshift-etcd
----
