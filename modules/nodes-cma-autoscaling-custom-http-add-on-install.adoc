= Install the KEDA HTTP Add-on extension

[role="_abstract"]
After installing the Custom Metrics Autoscaler Operator, you can install the KEDA HTTP Add-on to enable HTTP traffic-based autoscaling for your applications. You configure the HTTP Add-on through the KedaController custom resource.

.Prerequisites

* The Custom Metrics Autoscaler Operator version 2.20 or later is installed in your cluster.

* You have cluster-admin permissions.

* You are logged in to the {product-title} web console.

.Procedure

. In the {product-title} web console, navigate to *Operators* -> *Installed Operators*.

. Ensure that the *All Namespaces* scope is selected, then select the `openshift-keda` project from the project dropdown.

. Click the *Custom Metrics Autoscaler* Operator name.

. On the Operator details page, find the *KedaController* section. Click the *KedaController* tab.

. Click the `keda` KedaController instance to open its details page.

. In the *YAML* tab, locate the `spec` section and add the HTTP Add-on configuration:

.. Find the `addons` field under `spec`. If it does not exist, add it.

.. In the `addons` section, add the `http` addon with the following configuration:
+
[source,yaml]
----
spec:
  addons:
    http:
      enabled: true
----

. Click *Save* to apply the configuration.

. Wait for the HTTP Add-on components to deploy. Check the status by running the following command:

+
[source,terminal]
----
$ oc get pods -n openshift-keda | grep http
----

. Verify that the HTTP Add-on interceptor and scaler pods are running. The output should show running pods with names similar to `http-add-on-interceptor-*` and `http-add-on-scaler-*`.

.Verification

. Verify that the KedaController custom resource has the HTTP Add-on enabled:

+
[source,terminal]
----
$ oc get keda keda -n openshift-keda -o yaml | grep -A 5 "addons:"
----

+
.Example output
[source,yaml]
----
spec:
  addons:
    http:
      enabled: true
----

. Verify that all HTTP Add-on components are running:

+
[source,terminal]
----
$ oc get deployment -n openshift-keda | grep http
----

+
.Example output
[source,terminal]
----
NAME                           READY   UP-TO-DATE   AVAILABLE   AGE
http-add-on-interceptor       1/1     1            1           2m
http-add-on-scaler            1/1     1            1           2m
----

. Verify that the HTTP Add-on custom resources are registered in your cluster:

+
[source,terminal]
----
$ oc api-resources | grep InterceptorRoute
----

+
.Example output
[source,terminal]
----
interceptorroutes       HTTP Add-on HTTPScalerRoutes
----

. Verify that you can create an InterceptorRoute custom resource by checking the custom resource definition:

+
[source,terminal]
----
$ oc get crd | grep interceptor
----

+
The output should show the `interceptorroutes.http.keda.sh` custom resource definition.

.Next steps

* Configure HTTP-based autoscaling for your application by creating an `InterceptorRoute` and `ScaledObject`. See "Configure HTTP-based autoscaling for your application".

* Review the HTTP Add-on trigger configuration options. See "HTTP Add-on ScaledObject trigger configuration".
