= Enable the HTTP Add-on extension

[role="_abstract"]
After installing the Custom Metrics Autoscaler Operator, you can enable the HTTP Add-on to configure HTTP-traffic-based autoscaling for your applications. You enable the HTTP Add-on through the `KedaController` custom resource.

.Prerequisites

* The Custom Metrics Autoscaler Operator version 2.20 or later is installed in your cluster.

* You have cluster-admin permissions.

* You are logged in to the {product-title} web console.

.Procedure

. In the {product-title} web console, click *Ecosystem* -> *Installed Operators*.

. Switch to the `openshift-keda` project.

. Click *Custom Metrics Autoscaler*.

. On the *Operator Details* page, click the *KedaController* tab.

. Click the `keda` custom resource, and then click the *YAML* tab.

. Set `spec.httpAddon.enabled` to `true`:
+
[source,yaml,subs="+attributes"]
----
apiVersion: keda.sh/v1alpha1
kind: KedaController
metadata:
  name: keda
  namespace: openshift-keda
spec:
  httpAddon:
    enabled: true
----
+
When `true`, the `spec.httpAddon.enabled` parameter enables the HTTP Add-on operator, interceptor, and scaler. The default is `false`.

. Click *Save*.

. Optional: Configure the HTTP Add-on interceptor: 
+
[source,yaml,subs="+attributes"]
----
spec:
  httpAddon:
    enabled: true
    interceptor:
      replicas: 3
      env:
        - name: KEDA_HTTP_DIRECT_POD_ROUTING
          value: "true"
----
+
where:

`spec.httpAddon.interceptor.replicas`:: Specifies the number of interceptor replicas. Increase this value when the interceptor itself needs more capacity.
`spec.httpAddon.interceptor.env`:: When the `KEDA_HTTP_DIRECT_POD_ROUTING` environment variable is set to `true`, the interceptor forwards requests directly to a pod IP and not the service itself. Set to 	`false` if your application uses session affinity, topology-aware routing, or a network policy on the service path. When `false`, direct pod routing is disabled so that the interceptor uses the service itself.

.Verification

* Confirm that the HTTP Add-on installation succeeded by running the following command:
+
[source,terminal]
----
$ oc get kedacontroller keda -n openshift-keda -o yaml
----
+
Confirm that `status.httpAddon.phase` is `Installation Succeeded`.
+
.Example output
[source,yaml]
----
apiVersion: keda.sh/v1alpha1
kind: KedaController
metadata:
  name: keda
  namespace: openshift-keda
# ...
status:
  httpAddon:
    phase: Installation Succeeded
    reason: HTTP Add-on v<version> is installed in namespace 'openshift-keda'
----
+
Where `<version>` is the HTTP Add-on operator version.

* Confirm that the HTTP Add-on workloads are operating by running the following command:
+
[source,terminal,subs="+attributes"]
----
$ oc get deploy,svc -n openshift-keda
----
+
The command lists deployments for the HTTP Add-on operator, the interceptor, and the scaler in the `openshift-keda` namespace. The services include `keda-add-ons-http-external-scaler` and `keda-add-ons-http-interceptor-proxy	`.
+
