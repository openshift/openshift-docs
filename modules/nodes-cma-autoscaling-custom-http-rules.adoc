= Configure HTTP routing rules

[role="_abstract"]
You can match requests to a workload by host, path prefix, and headers on the `InterceptorRoute` resource. A request that matches any rule on the resource is forwarded to that resource's target service.

All fields in one rule must match. If you omit `hosts`, the rule matches any host. If you omit `paths`, the rule matches the root path `/`. If you omit `headers`, the rule does not filter on headers.

When more than one `InterceptorRoute` resource matches a request, the interceptor selects a route in this order:

. Exact host, then the most specific wildcard host, then a catch-all host.
. Longest matching path prefix.
. Most specific header match. A header with a required value is more specific than a header that only must be present.
. The `InterceptorRoute` resource that was created first.
. The namespace and name of the `InterceptorRoute` resource, in descending lexicographic order.

.Prerequisites

* An `InterceptorRoute` resource exists for the workload.

.Procedure

. Add hosts, paths, and headers to `spec.rules`. For example:
+
.Example routing rules
[source,yaml]
----
apiVersion: http.keda.sh/v1beta1
kind: InterceptorRoute
metadata:
  name: sample-app
  namespace: my-namespace
spec:
  target:
    service: sample-app
    port: 8080
  rules:
    - hosts:
        - api.example.com <1>
      paths:
        - value: /api/v1 <2>
      headers:
        - name: X-Route <3>
          value: canary <4>
    - hosts:
        - "*.example.com" <5>
  scalingMetric:
    concurrency:
      targetValue: 100
----
<1> Specifies an exact host. Exact hosts take priority over wildcard hosts.
<2> Specifies a path prefix. A request to `/api/v1/users` matches `/api/v1`. A longer matching prefix takes priority over a shorter one.
<3> Specifies a required header name. To match any value, omit `value`.
<4> Specifies the header value that must match exactly.
<5> Specifies a wildcard host. Quote the value. `*.example.com` matches `api.example.com` and `foo.bar.example.com`. A more specific wildcard takes priority.

. Apply the updated resource by running the following command:
+
[source,terminal]
----
$ oc apply -f interceptorroute.yaml
----
