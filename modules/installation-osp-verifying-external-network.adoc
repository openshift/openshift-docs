= Verifying external network access

[role="_abstract"]
For installations that use floating IP addresses, verify that your project can access a network with the external router type in {rh-openstack-first}.

.Prerequisites

* The cluster machines can reach DNS servers that resolve the {rh-openstack} API endpoints and the image registries required for installation.
ifndef::osp-user[]
* If the installation program creates the cluster network, you can specify DNS servers by setting `platform.openstack.externalDNS` in the `install-config.yaml` file. If you use an existing subnet, configure its DNS servers in {rh-openstack} before you install the cluster.
endif::osp-user[]
ifdef::osp-user[]
* You have identified the DNS servers to configure on the cluster subnet when you create or update the network resources.
endif::osp-user[]

.Procedure

* Using the {rh-openstack} CLI, verify the name and ID of the 'External' network:
+
[source,terminal]
----
$ openstack network list --long -c ID -c Name -c "Router Type"
----
+
.Example output
[source,terminal]
----
+--------------------------------------+----------------+-------------+
| ID                                   | Name           | Router Type |
+--------------------------------------+----------------+-------------+
| 148a8023-62a7-4672-b018-003462f8d7dc | public_network | External    |
+--------------------------------------+----------------+-------------+
----
+
A network with an external router type is displayed in the network list. If no external network is available, ask your cloud administrator to provide one that your project can access.
ifdef::osp-custom[]
+
[IMPORTANT]
====
If the external network's CIDR range overlaps one of the default network ranges, you must change the matching network ranges in the `install-config.yaml` file before you start the installation process.

The default network ranges are:
[options="header"]
|====
|Network |Range

|`machineNetwork`
|10.0.0.0/16

|`serviceNetwork`
|172.30.0.0/16

|`clusterNetwork`
|10.128.0.0/14
|====
====
endif::osp-custom[]
ifdef::osp-custom[]
[WARNING]
+
If the installation program finds multiple networks with the same name, it sets one of them at random. To avoid this behavior, create unique names for resources in {rh-openstack}.
endif::osp-custom[]
+
[NOTE]
====
If the Neutron trunk service plugin is enabled, a trunk port is created by default. For more information, see https://wiki.openstack.org/wiki/Neutron/TrunkPort[Neutron trunk port].
====
