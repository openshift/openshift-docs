= Injecting cloud provider credentials into a virtual machine

[role="_abstract"]
You can inject cloud provider service account tokens into a VM by enabling the `ContainerPathVolumes` feature gate, configuring a `ServiceAccount` with the appropriate cloud provider annotation, and defining a VM manifest with a `containerPath` volume and `virtiofs` filesystem device.

.Prerequisites

* You have installed {VirtProductName}.
* You have cluster administrator privileges.
* You have installed the {oc-first}.
* The cluster’s OIDC provider is configured in AWS IAM.
* An IAM role exists with permissions for the AWS resources the application needs. The role’s trust policy allows `sts:AssumeRoleWithWebIdentity` through that OIDC provider for `system:serviceaccount::<service_account_name>`, matching the namespace and service account used by the VM.

.Procedure

. Enable the `ContainerPathVolumes` feature gate by running the following command:
+
[source,terminal]
----
$ oc patch hyperconverged kubevirt-hyperconverged \
  -n openshift-cnv \
  --type merge \
  -p '{
    "spec": {
      "featureGates": [
        {"name": "containerPathVolumes", "state": "Enabled"}
      ]
    }
  }'
----

. Create a `ServiceAccount` object with an IAM role ARN annotation:
+
[source,yaml]
----
apiVersion: v1
kind: ServiceAccount
metadata:
  name: <service_account_name>
  namespace: my-namespace
  annotations:
    eks.amazonaws.com/role-arn: <AWS_IAM_role_ARN>
----
+
where:
+
<service_account_name>:: Specifies the name of the service account. You reference this name in the VM manifest.
<AWS_IAM_role_ARN>:: Specifies the ARN of the AWS IAM role that grants the required permissions.

. Apply the `ServiceAccount` object by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----

. Create a `VirtualMachine` manifest that references the `ServiceAccount` and defines a `containerPath` volume with a `virtiofs` filesystem device.
+
[source,yaml]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: example-vm
  namespace: my-namespace
spec:
  running: true
  template:
    spec:
      serviceAccountName: <service_account_name>
      domain:
        devices:
          filesystems:
          - name: <filesystems_name>
            virtiofs: {}
        resources:
          requests:
            memory: 1Gi
      volumes:
      - name: <volume_name>
        containerPath:
          path: <path>
----
+
where:
+
<service_account_name>:: Specifies the name of the service account with the AWS IAM role annotation.
<filesystems_name>:: The `virtiofs` filesystem device name. This must match the volume name.
<volume_name>:: The `containerPath` volume name. This must match the filesystem device name.
<path>:: The path in the `virt-launcher` pod where the AWS webhook injects the token.

. Apply the `VirtualMachine` manifest by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----

.Verification

. Connect to the VM console by running the following command:
+
[source,terminal]
----
$ virtctl console example-vm
----

. Verify that the cloud provider token is available inside the guest. List the `virtiofs` mount by running the following commands:
+
[source,terminal]
----
$ mount -t virtiofs cloud-credentials /path/to/virtiofs/mount/
----
+
[source,terminal]
----
$ mount | grep virtiofs
----
+
[source,terminal]
----
$ ls /path/to/virtiofs/mount/
----
+
The mount point depends on the guest operating system configuration. Check for the token file in the `virtiofs`-mounted directory.
