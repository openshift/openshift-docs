= Injecting cloud provider credentials into a virtual machine

[role="_abstract"]
You can inject cloud provider service account tokens into a VM by enabling the `ContainerPathVolumes` feature gate, configuring a `ServiceAccount` with the appropriate cloud provider annotation, and defining a VM manifest with a containerPath volume and virtiofs filesystem device.

.Prerequisites

* {VirtProductName} is installed on a managed cloud platform (ROSA or ARO).
* You have cluster administrator privileges.
* You have installed the {oc-first}.

.Procedure

. Enable the `ContainerPathVolumes` feature gate by running the following command:
+
// TODO: Confirm feature gate path with SME - may be /spec/featureGates/- (array append) or /spec/featureGates/ContainerPathVolumes (boolean)
[source,terminal,subs="attributes+"]
----
$ oc patch {HCOCliKind} kubevirt-hyperconverged -n {CNVNamespace} \
  --type json -p '[{"op": "add", "path": "/spec/featureGates/-", \
  "value": {"name": "ContainerPathVolumes"}}]'
----

. Create a `ServiceAccount` with the appropriate cloud provider annotation.
+
--
* For AWS IRSA, create a `ServiceAccount` with an IAM role ARN annotation:
+
[source,yaml]
----
apiVersion: v1
kind: ServiceAccount
metadata:
  name: my-cloud-sa <1>
  namespace: my-namespace
  annotations:
    eks.amazonaws.com/role-arn: "arn:aws:iam::123456789012:role/my-role" <2>
----
<1> The name of the `ServiceAccount`. You reference this name in the VM manifest.
<2> The ARN of the AWS IAM role that grants the required permissions.

* For Azure Workload Identity, create a `ServiceAccount` with a client ID annotation:
+
[source,yaml]
----
apiVersion: v1
kind: ServiceAccount
metadata:
  name: my-cloud-sa <1>
  namespace: my-namespace
  annotations:
    azure.workload.identity/client-id: "<client-id>" <2>
----
<1> The name of the `ServiceAccount`. You reference this name in the VM manifest.
<2> The client ID of the Azure managed identity.
--

. Apply the `ServiceAccount` by running the following command:
+
[source,terminal]
----
$ oc apply -f my-cloud-sa.yaml
----

. Create a `VirtualMachine` manifest that references the `ServiceAccount` and defines a containerPath volume with a virtiofs filesystem device.
+
--
* For AWS IRSA:
+
// TODO: Confirm exact token path for ROSA - may vary by platform configuration
[source,yaml]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: example-vm
  namespace: my-namespace
spec:
  running: true
  template:
    spec:
      serviceAccountName: my-cloud-sa <1>
      domain:
        devices:
          filesystems:
          - name: cloud-credentials <2>
            virtiofs: {}
        resources:
          requests:
            memory: 1Gi
      volumes:
      - name: cloud-credentials <3>
        containerPath:
          path: /var/run/secrets/eks.amazonaws.com/serviceaccount <4>
----
<1> The name of the `ServiceAccount` with the AWS IAM role annotation.
<2> The virtiofs filesystem device name. This must match the volume name.
<3> The containerPath volume name. This must match the filesystem device name.
<4> The path in the virt-launcher pod where the AWS webhook injects the token.

* For Azure Workload Identity:
+
// TODO: Confirm exact token path for ARO
[source,yaml]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: example-vm
  namespace: my-namespace
spec:
  running: true
  template:
    metadata:
      labels:
        azure.workload.identity/use: "true" <1>
    spec:
      serviceAccountName: my-cloud-sa <2>
      domain:
        devices:
          filesystems:
          - name: cloud-credentials <3>
            virtiofs: {}
        resources:
          requests:
            memory: 1Gi
      volumes:
      - name: cloud-credentials <4>
        containerPath:
          path: /var/run/secrets/azure/tokens <5>
----
<1> Required label for Azure Workload Identity webhook injection.
<2> The name of the `ServiceAccount` with the Azure client ID annotation.
<3> The virtiofs filesystem device name. This must match the volume name.
<4> The containerPath volume name. This must match the filesystem device name.
<5> The path in the virt-launcher pod where the Azure webhook injects the token.
--

. Apply the `VirtualMachine` manifest by running the following command:
+
[source,terminal]
----
$ oc apply -f example-vm.yaml
----

.Verification

. Connect to the VM console by running the following command:
+
[source,terminal]
----
$ virtctl console example-vm
----

. Verify that the cloud provider token is available inside the guest by listing the virtiofs mount:
+
--
* For AWS IRSA:
+
[source,terminal]
----
$ mount | grep virtiofs
$ ls /path/to/virtiofs/mount/ <1>
----
<1> The mount point depends on the guest operating system configuration. Check for the token file in the virtiofs-mounted directory.

* For Azure Workload Identity:
+
[source,terminal]
----
$ mount | grep virtiofs
$ ls /path/to/virtiofs/mount/ <1>
----
<1> The mount point depends on the guest operating system configuration. Check for the token file in the virtiofs-mounted directory.
