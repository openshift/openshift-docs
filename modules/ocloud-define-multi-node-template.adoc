= Define a multi-node template with distinct node groups

[role="_abstract"]
You can define a `ClusterTemplate` CR with multiple node groups in `hwMgmtDefaults` when your cluster topology requires controller and worker nodes with distinct hardware. Each node group defines its own role, hardware profile, and resource selectors, allowing the O-Cloud Manager to allocate different classes of hardware for each node role. This base configuration applies to all clusters provisioned with this template unless overridden with `hwMgmtParameters` in the `ProvisioningRequest` CR.

.Prerequisites

* The O-Cloud Manager Operator is installed on the hub cluster.
* Multiple server types are onboarded with distinct resource selector labels.
* `HardwareProfile` CRs are defined in the O-Cloud Manager Operator namespace, `oran-o2ims`, for each server type that requires firmware or BIOS management.
* The `clusterinstance-defaults` ConfigMap includes node definitions for both `master` and `worker` roles.

.Procedure

. Create a `ClusterTemplate` CR with multiple entries in `hwMgmtDefaults.nodeGroupData[]`, one per node group. The following example defines a controller group and a worker group with distinct hardware requirements:
+
[source,yaml]
----
apiVersion: clcm.openshift.io/v1alpha1
kind: ClusterTemplate
metadata:
  name: multi-node-ran-du.v4-Y-Z-1
  namespace: ocloud-templates
spec:
  name: multi-node-ran-du
  version: v4-Y-Z-1
  release: 4.Y.Z
  templateDefaults:
    hwMgmtDefaults:
      hardwareProvisioningTimeout: "120m"
      nodeGroupData:
        - name: controller
          role: master
          hwProfile: rh-profile-bios-standard
          resourceSelector:
            server-type: dell-xr8620t
            hardwaredata/num_threads;gte: "64"
            hardwaredata/ramMebibytes;gte: "131072"
            hardwaredata/nics;speedGbps>=25;count>=4: "present"
        - name: worker
          role: worker
          hwProfile: rh-profile-bios-dpdk
          resourceSelector:
            server-type: dell-xr7620
            hardwaredata/num_threads;gte: "128"
            hardwaredata/ramMebibytes;gte: "262144"
            hardwaredata/nics;speedGbps>=100;count>=2: "present"
            hardwaredata/storage;type==NVME;count>=4: "present"
    clusterInstanceDefaults: clusterinstance-defaults-v1
    policyTemplateDefaults: policytemplates-defaults-v1
  templateParameterSchema:
    properties:
      nodeClusterName:
        type: string
      oCloudSiteId:
        type: string
      hwMgmtParameters:
        properties:
          hardwareProvisioningTimeout:
            type: string
          nodeGroupData:
            items:
              properties:
                name:
                  type: string
                hwProfile:
                  type: string
                resourceSelector:
                  type: object
                  additionalProperties:
                    type: string
              required:
                - name
              type: object
            type: array
        type: object
      policyTemplateParameters:
        properties:
          cpu-isolated:
            type: string
          cpu-reserved:
            type: string
        type: object
      clusterInstanceParameters:
        properties:
          clusterName:
            type: string
          baseDomain:
            type: string
          nodes:
            items:
              properties:
                hostName:
                  type: string
              required:
                - hostName
              type: object
            type: array
        required:
          - clusterName
          - nodes
        type: object
    required:
      - nodeClusterName
      - oCloudSiteId
      - policyTemplateParameters
      - clusterInstanceParameters
    type: object
----
+
where:
+
`nodeGroupData[].name`:: A unique identifier for the node group within the template. This name is used to match override entries in a `ProvisioningRequest` CR's `hwMgmtParameters.nodeGroupData[]`.
`nodeGroupData[].role`:: Maps the node group to a cluster node role. Valid values are `master` for control plane nodes and `worker` for compute nodes. The O-Cloud Manager uses this role when rendering the `ClusterInstance` CR.
`nodeGroupData[].hwProfile`:: Specifies the `HardwareProfile` CR to apply to this node group. Each group can reference a different profile, for example a standard BIOS profile for controllers and a DPDK-optimized profile for workers. The referenced `HardwareProfile` CRs must exist in the O-Cloud Manager Operator namespace, `oran-o2ims`, not in the `ClusterTemplate` namespace.
`nodeGroupData[].resourceSelector`:: Defines independent selection criteria for each node group. Each group's selector is evaluated separately against the pool of available `BareMetalHost` CRs. The controller and worker groups can target completely different server types and hardware specifications.
`templateParameterSchema.hwMgmtParameters`:: Enables per-site overrides of hardware profiles and resource selectors. Including this in the schema allows site engineers to adjust hardware selection for individual node groups in their `ProvisioningRequest` CR without modifying the template.

. Apply the `ClusterTemplate` CR to the hub cluster, or commit it to the GitOps repository for ArgoCD synchronization.

.Verification

. Verify that the multi-node template passes validation by running the following command:
+
[source,terminal]
----
$ oc get clustertemplates.clcm.openshift.io -n ocloud-templates multi-node-ran-du.v4-Y-Z-1
----
+
.Example output
[source,terminal]
----
NAMESPACE          NAME                         AGE   STATE       DETAILS
ocloud-templates   multi-node-ran-du.v4-Y-Z-1   12s   Completed   The cluster template validation succeeded
----
+
A `STATE` of `Completed` confirms that all node group configurations, resource selectors, and the parameter schema are valid. When a `ProvisioningRequest` references this template, the O-Cloud Manager allocates hosts independently per node group, matching each group's `resourceSelector` against available `BareMetalHost` CRs.
