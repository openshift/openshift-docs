= Custom dashboards

[role="_abstract"]

Add application metrics to the console by declaring dashboards in the `Kiali` custom resource. Dashboards in the custom resource apply to every namespace. A dashboard with the same name as a built-in dashboard replaces that built-in dashboard. A dashboard entry that sets only `name` removes the built-in dashboard of that name.

[source,yaml]
----
spec:
  custom_dashboards:
  - name: myapp
    title: My App Metrics
    discoverOn: thread_count
    items:
    - chart:
        name: Thread count
        spans: 6
        metricName: thread_count
        dataType: raw
----

`discoverOn` is a Prometheus metric name. When the console finds that metric for a workload, it shows the dashboard. Without `discoverOn`, attach the dashboard with the pod annotation `kiali.io/dashboards`, set to a comma-separated list of dashboard names.

`dataType` is `raw`, `rate`, or `histogram`. `spans` is a width from 1 to 12. `unit` can be `seconds`, `bytes`, or `bytes-si`. Set `unitScale` when the metric needs a multiplier, such as `0.001` to show milliseconds as seconds.

Limit a dashboard to one namespace or one workload with the annotation `dashboards.kiali.io/templates` on the namespace or the pod template. The annotation value is the same list of dashboard objects, in YAML.

Prometheus must scrape the application. Annotate the pod with `prometheus.io/scrape`, `prometheus.io/port`, and `prometheus.io/path`. The metrics need `app` and `version` labels, and the namespace label named by `spec.external_services.custom_dashboards.namespace_label`. The default namespace label is `namespace`.

Set `spec.external_services.custom_dashboards.discovery_enabled` to `true`, `false`, or `auto`. `auto` skips discovery when a workload has more pods than `discovery_auto_threshold`. Discovery that is off does not block dashboards selected by annotation.
