= OpenTelemetry metrics migration reference

In {pipelines-title} 1.24, the underlying observability infrastructure for Tekton components migrated from OpenCensus to OpenTelemetry (OTel). As a result, several infrastructure metrics have been renamed, some custom metrics have been deprecated, and new labels have been introduced. 

If you maintain custom Grafana dashboards or Prometheus alerts, you must update your queries to reflect these changes.

== Infrastructure metric renaming

Infrastructure metrics for the Go runtime, Kubernetes client, and workqueues no longer use the `tekton_pipelines_controller_` prefix. They now use standard OpenTelemetry and Knative namespaces.

.Workqueue metrics
[cols="3,3,2",options="header"]
|===
| Old metric name (OpenCensus) | New metric name (OpenTelemetry) | Change description

| `tekton_pipelines_controller_workqueue_adds_total`
| `kn_workqueue_adds_total`
| Prefix change

| `tekton_pipelines_controller_workqueue_depth`
| `kn_workqueue_depth`
| Prefix change

| `tekton_pipelines_controller_workqueue_queue_latency_seconds`
| `kn_workqueue_queue_duration_seconds`
| Renamed `latency` to `duration`

| `tekton_pipelines_controller_workqueue_work_duration_seconds`
| `kn_workqueue_process_duration_seconds`
| Renamed `work` to `process`

| `tekton_pipelines_controller_workqueue_retries_total`
| `kn_workqueue_retries_total`
| Prefix change

| `tekton_pipelines_controller_workqueue_unfinished_work_seconds`
| `kn_workqueue_unfinished_work_seconds`
| Prefix change
|===

.Kubernetes client and Go runtime metrics
[cols="3,3,2",options="header"]
|===
| Old metric name (OpenCensus) | New metric name (OpenTelemetry) | Change description

| `tekton_pipelines_controller_client_latency`
| `http_client_request_duration_seconds`
| Standard HTTP metric adoption

| `tekton_pipelines_controller_client_results`
| `kn_k8s_client_http_response_status_code_total`
| Detailed status tracking

| `tekton_pipelines_controller_go_*`
| `go_*` (For example, `go_goroutines`)
| Standard Prometheus Go collector adoption
|===

== Label changes for Tekton metrics

The core metric names for pipeline runs and task runs have been preserved. However, the following duration metrics now include a new `reason` label (such as `Completed` or `Succeeded`) to provide more granular duration breakdowns:

* `tekton_pipelines_controller_pipelinerun_duration_seconds`
* `tekton_pipelines_controller_pipelinerun_taskrun_duration_seconds`
* `tekton_pipelines_controller_taskrun_duration_seconds`

[IMPORTANT]
====
The addition of the `reason` label increases metric cardinality. If your existing queries aggregate these metrics, you might need to update your PromQL queries (for example, using `sum by (label)`) to account for this new dimension.
====

== Removed metrics

The following custom reconciliation metrics are no longer emitted:

* `tekton_pipelines_controller_reconcile_count`
* `tekton_pipelines_controller_reconcile_latency`

*Action required:* Use `kn_workqueue_process_duration_seconds` and `kn_workqueue_adds_total` to monitor controller performance instead.

== Preserved metrics and behaviors

To minimize disruption, the following critical metrics and behaviors remain unchanged:

* *Pod latency:* `tekton_pipelines_controller_taskruns_pod_latency_milliseconds` remains a Gauge metric, preserving its behavior despite OTel defaults preferring histograms.
* *Total counters:* `tekton_pipelines_controller_pipelinerun_total` and `tekton_pipelines_controller_taskrun_total` retain their original `status` labels and do not include the high-cardinality `reason` label.
* *Bucket boundaries:* Duration histograms (such as `taskrun_duration_seconds`) retain their specific explicit buckets (10s, 30s, 1m, and so on) instead of defaulting to OTel millisecond-focused buckets.
