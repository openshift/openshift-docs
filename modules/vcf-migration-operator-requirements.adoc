= Cluster migration with the {vcf-migration-operator}

[role="_abstract"]
You can move a cluster between vCenters by using the {vcf-migration-operator}. The Operator creates replacement compute and control plane machines on the target vCenter and removes the source machines and vCenter configuration from the cluster.

Plan a maintenance window for the migration. Replacing nodes can disrupt workloads, and replacing the control plane machines can take several hours.

The migration requires the following configuration:

* The cluster uses the Machine API, compute machine sets, and an existing control plane machine set. The cluster uses one source vCenter with exactly one data center configured in its `Infrastructure` resource.
* The `VSphereMultiVCenterDay2` feature gate is enabled for the running {product-title} version.
* The cluster has no persistent volumes (PVs) that use the {vmw-short} Container Storage Interface (CSI) driver, `csi.vsphere.vmware.com`. Migration of these volumes is not supported.
* The target vCenter has sufficient capacity for the replacement machines, and its data center, compute cluster, datastore, and network exist. An {op-system-first} virtual machine (VM) template for the cluster's version exists on the target vCenter.
* Source and target nodes can communicate during the migration. DNS, load balancers, firewalls, proxies, and IP address allocation are configured for the target machines. The Operator does not validate these external services.

// SME review: Confirm the supported network topology and storage configurations. The implementation rejects {vmw-short} CSI PVs but does not establish a support policy for other storage providers.

Target compute machine sets use one source compute machine set as a template. Different configurations across source compute machine sets are not preserved.

The target vCenter account must have the privileges required to manage {product-title} machines. The Operator also requires the following privileges to prepare the destination:

[cols="1,2",options="header"]
|===
|Scope
|Privileges

|Inventory objects that the Operator accesses
|`System.View`

|vCenter root folder
|`InventoryService.Tagging.Read`, `InventoryService.Tagging.AttachTag`, `InventoryService.Tagging.CreateCategory`, and `InventoryService.Tagging.CreateTag`

|Target data center, compute cluster, and cluster VM folder
|`InventoryService.Tagging.ObjectAttachable`

|Data center VM folder and parent folders in which cluster folders are created
|`Folder.Create`
|===

The target credentials are also used by the cluster to manage machines after migration. The privileges in this table do not replace the privileges required for machine creation and deletion.
