= Creating a kubeconfig for a downstream cluster

[role="_abstract"]
Create a least-privilege kubeconfig for the downstream cluster API server and store it in a Secret on the upstream cluster. The upstream SPIRE server uses this kubeconfig to validate projected service account tokens from the downstream cluster.

.Prerequisites

* You have installed {zero-trust-full} on the upstream cluster and the downstream cluster.
* You have deployed a `SpireServer` CR on both clusters.
* Both clusters are standalone {product-title} clusters. Nested SPIRE is not supported on {hcp}, {sno}, or {ms}.
* You have `cluster-admin` permissions on both clusters.
* You exported the admin kubeconfig path for each cluster:
+
[source,terminal]
----
$ export UPSTREAM_KUBECONFIG=<path_to_upstream_kubeconfig>
$ export DOWNSTREAM_KUBECONFIG=<path_to_downstream_kubeconfig>
----

.Procedure

. Read the trust domain and cluster name from each cluster by running the following commands:
+
[source,terminal]
----
$ export UPSTREAM_TRUST_DOMAIN=$(oc get ZeroTrustWorkloadIdentityManager cluster --kubeconfig="${UPSTREAM_KUBECONFIG}" -o jsonpath='{.spec.trustDomain}')
$ export DOWNSTREAM_TRUST_DOMAIN=$(oc get ZeroTrustWorkloadIdentityManager cluster --kubeconfig="${DOWNSTREAM_KUBECONFIG}" -o jsonpath='{.spec.trustDomain}')
$ export UPSTREAM_CLUSTER_NAME=$(oc get ZeroTrustWorkloadIdentityManager cluster --kubeconfig="${UPSTREAM_KUBECONFIG}" -o jsonpath='{.spec.clusterName}')
$ export DOWNSTREAM_CLUSTER_NAME=$(oc get ZeroTrustWorkloadIdentityManager cluster --kubeconfig="${DOWNSTREAM_KUBECONFIG}" -o jsonpath='{.spec.clusterName}')
$ echo "upstream trust domain: ${UPSTREAM_TRUST_DOMAIN}"
$ echo "downstream trust domain: ${DOWNSTREAM_TRUST_DOMAIN}"
$ echo "upstream cluster name: ${UPSTREAM_CLUSTER_NAME}"
$ echo "downstream cluster name: ${DOWNSTREAM_CLUSTER_NAME}"
----
+
The trust domain values must be identical. `spec.trustDomain` is immutable. If the values differ, nested SPIRE cannot be configured until both clusters are installed with the same trust domain.
+
The cluster names must be different. You register `DOWNSTREAM_CLUSTER_NAME` on the upstream cluster in a later procedure.

. On the downstream cluster, create a service account and bind it to TokenReview and read-only access to pods and nodes. Save the following manifest as `spire-upstream-attestor.yaml`:
+
[source,yaml]
----
apiVersion: v1
kind: ServiceAccount
metadata:
  name: spire-upstream-attestor
  namespace: zero-trust-workload-identity-manager
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: spire-upstream-attestor
rules:
- apiGroups:
  - ""
  resources:
  - pods
  - nodes
  verbs:
  - get
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: spire-upstream-attestor
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: spire-upstream-attestor
subjects:
- kind: ServiceAccount
  name: spire-upstream-attestor
  namespace: zero-trust-workload-identity-manager
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: spire-upstream-attestor-auth-delegator
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: system:auth-delegator
subjects:
- kind: ServiceAccount
  name: spire-upstream-attestor
  namespace: zero-trust-workload-identity-manager
----
+
[source,terminal]
----
$ oc apply --kubeconfig="${DOWNSTREAM_KUBECONFIG}" -f spire-upstream-attestor.yaml
----
+
[WARNING]
====
The `spire-upstream-attestor` service account can submit `TokenReview` requests and read pods and nodes on the downstream cluster. The upstream cluster stores these credentials. Do not grant this service account additional permissions.
====

. Create a service account token Secret for that service account by saving the following manifest as `spire-upstream-attestor-token.yaml`:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: spire-upstream-attestor-token
  namespace: zero-trust-workload-identity-manager
  annotations:
    kubernetes.io/service-account.name: spire-upstream-attestor
type: kubernetes.io/service-account-token
----
+
[source,terminal]
----
$ oc apply --kubeconfig="${DOWNSTREAM_KUBECONFIG}" -f spire-upstream-attestor-token.yaml
----
+
The token in this Secret does not expire. Rotate it by replacing the kubeconfig Secret on the upstream cluster.

. Wait until the token Secret is populated, and then build a kubeconfig file by running the following commands:
+
[source,terminal]
----
$ until oc get secret spire-upstream-attestor-token \
  -n zero-trust-workload-identity-manager \
  --kubeconfig="${DOWNSTREAM_KUBECONFIG}" \
  -o jsonpath='{.data.token}' | grep -q .; do sleep 1; done
$ DOWNSTREAM_API=$(oc whoami --show-server --kubeconfig="${DOWNSTREAM_KUBECONFIG}")
$ oc get secret spire-upstream-attestor-token \
  -n zero-trust-workload-identity-manager \
  --kubeconfig="${DOWNSTREAM_KUBECONFIG}" \
  -o jsonpath='{.data.ca\.crt}' | base64 --decode > ./downstream-ca.crt
$ DOWNSTREAM_TOKEN=$(oc get secret spire-upstream-attestor-token \
  -n zero-trust-workload-identity-manager \
  --kubeconfig="${DOWNSTREAM_KUBECONFIG}" \
  -o jsonpath='{.data.token}' | base64 --decode)
$ oc config set-cluster "${DOWNSTREAM_CLUSTER_NAME}" \
  --server="${DOWNSTREAM_API}" \
  --certificate-authority=./downstream-ca.crt \
  --embed-certs=true \
  --kubeconfig="./spire-${DOWNSTREAM_CLUSTER_NAME}.kubeconfig"
$ oc config set-credentials spire-upstream-attestor \
  --token="${DOWNSTREAM_TOKEN}" \
  --kubeconfig="./spire-${DOWNSTREAM_CLUSTER_NAME}.kubeconfig"
$ oc config set-context "${DOWNSTREAM_CLUSTER_NAME}" \
  --cluster="${DOWNSTREAM_CLUSTER_NAME}" \
  --user=spire-upstream-attestor \
  --kubeconfig="./spire-${DOWNSTREAM_CLUSTER_NAME}.kubeconfig"
$ oc config use-context "${DOWNSTREAM_CLUSTER_NAME}" \
  --kubeconfig="./spire-${DOWNSTREAM_CLUSTER_NAME}.kubeconfig"
----

. Store the kubeconfig in a Secret on the upstream cluster by running the following command:
+
[source,terminal]
----
$ oc create secret generic "spire-downstream-${DOWNSTREAM_CLUSTER_NAME}" --from-file=kubeconfig="./spire-${DOWNSTREAM_CLUSTER_NAME}.kubeconfig" -n zero-trust-workload-identity-manager --kubeconfig="${UPSTREAM_KUBECONFIG}"
----
+
{zero-trust-full} reads the kubeconfig from the `kubeconfig` key of this Secret. Record the Secret name. You set it in `spec.nestedSpire.downstreamClusters[].kubeConfigSecret`.

. Remove the local kubeconfig and token files by running the following command:
+
[source,terminal]
----
$ unset DOWNSTREAM_TOKEN
$ rm -f "./spire-${DOWNSTREAM_CLUSTER_NAME}.kubeconfig" ./downstream-ca.crt
----

.Verification

* Confirm that the Secret exists on the upstream cluster by running the following command:
+
[source,terminal]
----
$ oc get secret "spire-downstream-${DOWNSTREAM_CLUSTER_NAME}" -n zero-trust-workload-identity-manager --kubeconfig="${UPSTREAM_KUBECONFIG}"
----
