= Defining a localnet network by using the ClusterUserDefinedNetwork CR

[role="_abstract"]
You can define a localnet network by creating a `ClusterUserDefinedNetwork` (CUDN) custom resource (CR) that specifies how virtual machines attach to the physical network through the OVS bridge, and which namespaces have access.

.Prerequisites

* You are logged in to the cluster as a user with `cluster-admin` privileges.
* You have installed the {oc-first}.
* You have configured an OVS bridge mapping on the cluster nodes by creating a `NodeNetworkConfigurationPolicy` CR. For more information, see "Creating an OVS bridge mapping for a localnet network" in the _Additional resources_ section.

.Procedure

. Create a `ClusterUserDefinedNetwork` manifest to define the localnet network.
+
The following example creates a localnet network on VLAN 100 with jumbo frames, accessible to namespaces labeled with `provider-network-vlan: "100"`:
+
[source,yaml]
----
apiVersion: k8s.ovn.org/v1
kind: ClusterUserDefinedNetwork
metadata:
  name: provider-network-100
spec:
  namespaceSelector:
    matchLabels:
      provider-network-vlan: "100"
  network:
    topology: Localnet
    localnet:
      role: Secondary
      physicalNetworkName: provider-network
      ipam:
        mode: Disabled
      mtu: 9000
      vlan:
        mode: Access
        access:
          id: 100
----
+
where:
+
`spec.namespaceSelector`:: Selects namespaces that have access to the network. You can use `matchLabels` or `matchExpressions` selectors. Using label selectors is recommended because namespaces can be granted or revoked access by adding or removing a label, without modifying the `ClusterUserDefinedNetwork` CR.
`spec.network.topology`:: Specifies the topological configuration. Must be set to `Localnet` to connect the network to the physical underlay.
`spec.network.localnet.role`:: Specifies the network role. Must be set to `Secondary` for localnet topology.
`spec.network.localnet.physicalNetworkName`:: Specifies the name of the OVN-Kubernetes bridge mapping configured on the node. This value must match the `spec.desiredState.ovn.bridge-mappings.localnet` field in the `NodeNetworkConfigurationPolicy` manifest.
`spec.network.localnet.ipam.mode`:: Specifies whether IP address management (IPAM) is enabled or disabled. Must be set to `Disabled` because {VirtProductName} does not support IPAM for VMs on localnet networks.
`spec.network.localnet.mtu`:: Specifies the MTU for the localnet network. The default value is `1500`. This value must match the MTU of the node network and the physical network.
`spec.network.localnet.vlan`:: Specifies the VLAN configuration. Set `mode` to `Access` and specify the VLAN ID to isolate traffic for different tenants.
+
[IMPORTANT]
====
If you select namespaces by name using `matchExpressions` and later need to delete one of those namespaces, it can get stuck in `Terminating` state. The `ClusterUserDefinedNetwork` controller cannot remove the network attachment from a namespace that is still explicitly listed in the selector. To unblock deletion, you must first update the `ClusterUserDefinedNetwork` CR to remove the namespace from the list. To avoid this issue, select namespaces by label instead.
====
+
[NOTE]
====
OVN-Kubernetes does not support VLAN trunking.
====

. Apply the `ClusterUserDefinedNetwork` manifest by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----
+
where:
+
`<filename>`:: Specifies the name of your `ClusterUserDefinedNetwork` manifest YAML file.

. Create a `Namespace` manifest with a label that matches the `ClusterUserDefinedNetwork` namespace selector, as in the following example:
+
[source,yaml]
----
apiVersion: v1
kind: Namespace
metadata:
  name: red
  labels:
    provider-network-vlan: "100"
----

. Apply the `Namespace` manifest by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----
+
where:
+
`<filename>`:: Specifies the name of your `Namespace` manifest YAML file.
