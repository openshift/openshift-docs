= Configuring a vLLM server with the Anthropic provider

[role="_abstract"]
To use a self-hosted vLLM server for agentic and tool-calling workloads, configure the {ols-long} agentic deployment with the Anthropic provider. You create a credentials secret, an `LLMProvider` custom resource (CR) that points to your vLLM endpoint, and an `Agent` CR that uses that provider.

[NOTE]
====
This pathway uses the agentic deployment custom resources. The classic `OLSConfig` provider list and the `apitoken` credentials secret key do not apply to this configuration.
====

.Prerequisites

* You have installed the {ols-long} Operator.
* You have logged in to the {ocp-product-title} web console as a user with the `cluster-admin` role, or with permission to create cluster-scoped custom resources.
* You have a running vLLM server that exposes the Anthropic-compatible `/v1/messages` endpoint, and the {ols-long} deployment can reach it over a secure connection.
* You have the bearer token for your vLLM server, if the endpoint requires authentication.

.Procedure

. Create a credentials `Secret` in the `openshift-lightspeed` namespace that contains the authentication details for your vLLM server:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: vllm-credentials
  namespace: openshift-lightspeed
type: Opaque
stringData:
  ANTHROPIC_AUTH_TOKEN: <bearer_token> # <1>
  ANTHROPIC_API_KEY: placeholder # <2>
----
<1> The bearer token for your vLLM server. The provider sends this value as an `Authorization: Bearer <token>` header. If your vLLM endpoint does not require authentication, you can omit this key.
<2> A non-empty placeholder value. The deployment requires `ANTHROPIC_API_KEY` to be set to any non-empty value to pass its readiness check, even when the endpoint uses bearer token authentication.

. Apply the secret by running the following command:
+
[source,terminal]
----
$ oc apply -f <secret_filename>.yaml
----

. Create an `LLMProvider` CR that uses the Anthropic provider type and points to your vLLM endpoint:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: LLMProvider
metadata:
  name: vllm-anthropic
spec:
  type: Anthropic
  anthropic:
    credentialsSecret:
      name: vllm-credentials # <1>
    url: <vllm_endpoint_url> # <2>
----
<1> The name of the credentials secret that you created in the `openshift-lightspeed` namespace.
<2> The base URL of your vLLM server. {ols-long} calls the Anthropic-compatible `/v1/messages` endpoint against this URL internally, so you do not include the endpoint path.

. Create an `Agent` CR that references the `LLMProvider` and specifies the model to use:
+
[source,yaml]
----
apiVersion: agentic.openshift.io/v1alpha1
kind: Agent
metadata:
  name: default
spec:
  llmProvider:
    name: vllm-anthropic # <1>
  model: <model_id> # <2>
  maxTurns: 200
----
<1> The name of the `LLMProvider` CR that you created.
<2> The identifier of the model that your vLLM server serves.

. Apply the custom resources by running the following command:
+
[source,terminal]
----
$ oc apply -f <cr_filename>.yaml
----

.Verification

. Confirm that the `LLMProvider` and `Agent` resources exist by running the following commands:
+
[source,terminal]
----
$ oc get llmprovider vllm-anthropic
----
+
[source,terminal]
----
$ oc get agent default
----

. Submit a query that requires a tool call, and confirm that {ols-long} returns the tool result.
