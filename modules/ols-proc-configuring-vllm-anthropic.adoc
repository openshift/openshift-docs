= Configuring vLLM with the Anthropic provider

[role="_abstract"]
To activate a self-hosted vLLM server as your model provider through the Anthropic-compatible `/v1/messages` endpoint, create a credentials secret that contains your authentication token and then configure the {ols-long} agentic deployment to use your vLLM endpoint. Use this pathway for agentic and tool-calling workloads.

.Prerequisites

* You have logged in to the {ocp-product-title} web console as a user with the `cluster-admin` role. Alternatively, you have logged in to a user account that has permission to create a cluster-scoped CR file.
* You have installed the {ols-long} Operator.
* You have a running vLLM server, version 0.24 or later, that exposes the Anthropic-compatible `/v1/messages` endpoint.
* You have the authentication token for your vLLM server, and the {ols-long} deployment can reach the server over a secure connection.

.Procedure

. Create a `Secret` resource file within the `openshift-lightspeed` namespace that contains the authentication token for your vLLM server:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: anthropic-credentials
  namespace: openshift-lightspeed
type: Opaque
stringData:
  apitoken: <auth_token> # <1>
----
<1> The authentication (AUTH) token that is sent with each request. If your vLLM endpoint does not require a token, set this value to any valid string so that the request authenticates.
// TODO(OLS-4284): SME to confirm the exact secret key name the Anthropic provider expects (for example, apitoken vs. api_key vs. ANTHROPIC_API_KEY).

. Apply the configuration file to create your secret by running the following command:
+
[source,terminal]
----
$ oc create -f <secret_filename>.yaml
----

. Configure the {ols-long} agentic deployment to connect to your vLLM endpoint by providing the following settings:
+
--
Endpoint URL::
The URL of your vLLM server that exposes the Anthropic-compatible `/v1/messages` endpoint.

Bearer token::
The authentication token for your vLLM server, referenced from the `anthropic-credentials` secret that you created. If your vLLM endpoint does not require a token, use any valid string.

API key placeholder::
A non-empty placeholder value. The deployment requires this value to pass its readiness check, even when the endpoint uses bearer token authentication.
--
