= Configuring vLLM with the Anthropic provider

[role="_abstract"]
To activate a self-hosted vLLM server as your model provider through the Anthropic-compatible `/v1/messages` endpoint, create a credentials secret that contains your authentication token and then modify the cluster `OLSConfig` custom resource (CR) file. Use this pathway for agentic and tool-calling workloads.

.Prerequisites

* You have logged in to the {ocp-product-title} web console as a user with the `cluster-admin` role. Alternatively, you have logged in to a user account that has permission to create a cluster-scoped CR file.
* You have installed the {ols-long} Operator.
* You have a running vLLM server, version 0.24 or later, that exposes the Anthropic-compatible `/v1/messages` endpoint.
* You have the authentication token for your vLLM server, and the {ols-long} deployment can reach the server over a secure connection.

.Procedure

. Create a `Secret` resource file within the `openshift-lightspeed` namespace that contains the authentication token for your vLLM server:
+
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: anthropic-credentials
  namespace: openshift-lightspeed
type: Opaque
stringData:
  apitoken: <auth_token> # <1>
----
<1> The authentication (AUTH) token that the Anthropic SDK or LangChain wrapper sends with each request. If your vLLM endpoint does not require a token, set this value to any valid string so that the request authenticates.
// TODO(OLS-4284): SME to confirm the exact secret key name the Anthropic provider expects (for example, apitoken vs. api_key vs. ANTHROPIC_API_KEY).

. Apply the configuration file to create your secret by running the following command:
+
[source,terminal]
----
$ oc create -f <secret_filename>.yaml
----

. Open and edit your existing `OLSConfig` custom resource definition to define the new provider:
+
[source,terminal]
----
$ oc edit olsconfig cluster
----

. Update the `spec` section to add the Anthropic provider and declare your target model:
+
[source,yaml]
----
spec:
  ols:
    defaultProvider: vllm-anthropic
    defaultModel: <model_name> # <1>
  llm:
    providers:
    - name: vllm-anthropic
      type: anthropic # <2>
      url: <url> # <3>
      credentialsSecretRef:
        name: anthropic-credentials
      models:
      - name: <model_name>
----
<1> The name of the model that your vLLM server serves, for example, a Gemma model.
<2> The provider type for the Anthropic-compatible pathway.
<3> The URL endpoint for your vLLM server that exposes the Anthropic-compatible `/v1/messages` endpoint.
// TODO(OLS-4284): SME to confirm the provider `type` string (placeholder: anthropic) and the exact URL form to enter (for example, base URL vs. a URL ending in /v1 or /v1/messages).

. Save your modifications and exit the text editor. The Operator automatically reconciles the changes.

.Verification

. Verify that the Operator has completed reconciliation by running the following command:
+
[source,terminal]
----
$ oc get olsconfig cluster -o jsonpath='{.status.overallStatus}'
----
+
Expected output: `Ready`

. Submit a query that requires a tool call, and confirm that {ols-long} returns the tool result rather than suppressing the tool call.
