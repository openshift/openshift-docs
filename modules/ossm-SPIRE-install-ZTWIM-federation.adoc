= Install Zero Trust Workload Identity Manager for federated SPIRE

[role="_abstract"]
Deploy the Zero Trust Workload Identity Manager Operator and configure SPIRE components on both clusters in your federation.
This procedure installs the SPIRE server, agent, CSI driver, and OIDC discovery provider on each cluster with federation support enabled.

.Prerequisites

* You have satisfied all prerequisites for federated SPIRE deployment.
* You have set the required environment variables for both clusters.

.Procedure

. Install the Zero Trust Workload Identity Manager Operator on Cluster A:
+
[source,terminal]
----
$ export KUBECONFIG="${CLUSTER_A_KUBECONFIG}"
----
+
Follow the steps in link:https://docs.redhat.com/en/documentation/openshift_container_platform/latest/html/security_and_compliance/zero-trust-workload-identity-manager#zero-trust-manager-install[Installing the Zero Trust Workload Identity Manager] to install the Operator by using either the web console or CLI.

. Configure the Operator on Cluster A to work in `CreateOnly` mode:
+
[source,terminal]
----
$ oc -n zero-trust-workload-identity-manager patch subscription \
  openshift-zero-trust-workload-identity-manager \
  --type='merge' -p '{"spec":{"config":{"env":[{"name":"CREATE_ONLY_MODE","value":"true"}]}}}'
----
+
`CreateOnly` mode prevents the Operator from automatically overwriting your SPIRE configurations during {istio} integration.

. Define the required environment variables for Cluster A:
+
[source,terminal,subs="+quotes"]
----
$ export TRUST_DOMAIN_A=__<cluster-a.example.com>__
$ export ZTWIM_NS=zero-trust-workload-identity-manager
$ export JWT_ISSUER_A="https://oidc-discovery.$(oc get ingresses.config/cluster -o jsonpath={.spec.domain})"
----

. Deploy the SPIRE server on Cluster A with federation support:
+
[source,terminal]
----
$ cat <<EOF | oc apply -f -
apiVersion: spire.openshift.io/v1alpha1
kind: SpireServer
metadata:
  name: default
  namespace: ${ZTWIM_NS}
spec:
  trustDomain: ${TRUST_DOMAIN_A}
  federation:
    enabled: true
    bundleEndpoint:
      address: "0.0.0.0"
      port: 8443
EOF
----
+
The `bundleEndpoint` configuration enables other SPIRE servers to retrieve this cluster's trust bundle for federation.

. Deploy the SPIRE agent and CSI driver on Cluster A:
+
Follow the steps in link:https://docs.redhat.com/en/documentation/openshift_container_platform/latest/html/security_and_compliance/zero-trust-workload-identity-manager#zero-trust-manager-configuration_zero-trust-manager-install[Deploying Zero Trust Workload Identity Manager operands] to deploy the `SpireAgent` and CSI driver components.

. Configure the SPIRE agent on Cluster A to access federation bundles:
+
[source,terminal]
----
$ oc -n ${ZTWIM_NS} patch configmap spire-server \
  --type='merge' -p '{"data":{"server.conf":"server {\n  trust_domain = \"'${TRUST_DOMAIN_A}'\"\n  federation {\n    bundle_endpoint {\n      address = \"0.0.0.0\"\n      port = 8443\n    }\n  }\n}"}}'
----

. Repeat steps 1-6 on Cluster B:
+
[source,terminal]
----
$ export KUBECONFIG="${CLUSTER_B_KUBECONFIG}"
----
+
Use the environment variables and trust domain specific to Cluster B (`TRUST_DOMAIN_B`, `JWT_ISSUER_B`) when deploying components on the second cluster.

.Verification

. Verify the SPIRE server is running on both clusters:
+
[source,terminal]
----
$ oc get pods -n ${ZTWIM_NS} -l app=spire-server
----

. Verify the SPIRE agent is running on both clusters:
+
[source,terminal]
----
$ oc get pods -n ${ZTWIM_NS} -l app=spire-agent
----
+
All pods should show `Running` status before proceeding to the next step.
