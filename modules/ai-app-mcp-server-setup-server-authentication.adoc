= Configuring MCP server authentication to the cluster

[role="_abstract"]
Configure how the MCP server for Red{nbsp}Hat OpenShift authenticates to the {product-title} API server by passing the user's token through, or exchanging it for a token that the target cluster accepts, by using a per-cluster audience within the same realm, so that requests run with the user's identity.

There are two methods:

* _Passthrough_ (default): the server forwards the user's token directly to the cluster. Used when the cluster accepts the user's token as-is.
+
`cluster_auth_mode` = "passthrough"
+
This is the default when `cluster_auth_mode` is unset. 

* _Token exchange_: the server exchanges the token for one the cluster accepts (audience mismatch), preserving per-user identity. Exchange happens within passthrough when a [token_exchange] block is present.

The Keycloak v2 token exchange model works as follows:

* Single realm (inter-realm exchange not supported in v2).
* Each target cluster has its own audience, registered as a Keycloak client.
* MCP server acts as its own client.
* Each cluster API server is configured with external OIDC requiring its specific audience.
* Exchange switches audience (for example, mcp-server becomes cluster-prod-east), same realm.

.Prerequisites
* Access to OpenShift console with admin rights.
* MCP gateway is installed.
* MCP Lifecycle Operator is enabled.
* The MCP server is installed.
* MCP gateway is configured and verified.
* MCP-compatible client connected.
* RBAC is configured.
* You have revoked access to specific Custom Resources (CRs) as needed.
* MCP gateway authentication is configured.
* For passthrough: the cluster trusts the IdP as an external OIDC provider.
* For Keycloak v2 support:
** Keycloak realm established with MCP server client, plus one client/audience per target cluster.
** Each target cluster API server is configured with external OIDC requiring its audience.

.Procedure
* To set up passthrough token exchange, add the following content to the `config.toml` `ConfigMap`:
+
.Keycloak (RFC 8693)
[source,toml]
----
[token_exchange]
strategy = "rfc8693"
audience = "openshift"
scopes = ["mcp:openshift"]

[token_exchange.client_auth]
method = "client_secret_basic"
client_id = "mcp-server"
client_secret = "<client_secret>"
----
+
Or
+
.Entra (On-Behalf-Of)
[source,toml]
----
[token_exchange]
strategy = "entra-obo"
scopes = ["api://<downstream_api_app_id>/.default"]

[token_exchange.client_auth]
method = "private_key_jwt"   # certificate (recommended)
client_id = "<client_id>"
certificate_file = "/path/to/client.crt"
private_key_file = "/path/to/client.key"
----
+
[NOTE]
====
While `[token_exchange]` and `oauth_*/require_oauth` are reloadable, changes to the configuration do not take effect automatically. For information about how to apply configuration changes, see "Applying configuration changes to the MCP server for Red{nbsp}Hat OpenShift".
====

.Verification
* Confirm the server reaches the cluster API as the user, for example, a tool call against a specific spoke succeeds with cluster-specific audience; or check that the server logs show the audience switch.
