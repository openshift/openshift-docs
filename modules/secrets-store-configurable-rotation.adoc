= Understanding configurable secret rotation

[role="_abstract"]
You can configure the {secrets-store-operator} secret rotation settings to control how frequently the operator polls external secret stores for updates. Configuring secret rotation enables you to balance security requirements with operational efficiency by reducing transaction costs and performance overhead.

By default, the {secrets-store-operator} automatically rotates secret content in mounted volumes to maintain synchronization with external secret providers. While automatic rotation ensures that updates in the external store are reflected in your pods, frequent polling can result in high operational costs and performance overhead, especially in large-scale environments with many secrets.

The configurable secret rotation feature provides the following benefits:

* *Cost reduction*: Reduce transaction costs associated with polling external secret managers, such as Azure Key Vault, AWS Secrets Manager, or Google Secret Manager, by setting appropriate polling intervals based on your security and operational requirements.

* *Performance optimization*: Minimize performance overhead in environments with a large number of secrets by controlling the frequency of rotation polling. For example, a cluster managing 200 secrets can experience significant performance improvements with optimized polling intervals.

* *Operational flexibility*: Enable or disable secret rotation based on your specific use case. For secrets that change infrequently, you can disable rotation entirely or set longer polling intervals.

* *Fine-grained control*: Configure different rotation behaviors for different workloads by modifying the `Driver` custom resource for the {secrets-store-operator}.

The rotation configuration is managed through two primary parameters in the `Driver` custom resource:

* `rotation.enabled`: Enables or disables secret rotation globally for the operator
* `rotation.pollingInterval`: Sets the interval for checking external secret stores for updates

When rotation is disabled, the operator sets the `RequiresRepublish` flag to `false`, which prevents unnecessary kubelet calls and improves cluster performance.
