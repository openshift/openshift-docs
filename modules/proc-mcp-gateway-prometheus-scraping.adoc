= Prometheus metrics scraping methods

[role="_abstract"]
Get real-time, aggregated visibility into the health, performance, and resource usage of your {mcpg}. Prometheus metrics give you a high-level numerical overview of your system state over time.

* Use internal cluster scraping for ad hoc debugging and verification. Retrieve metrics through pod IP discovery.
* Use `PodMonitor` resources for automated configuration of continuous metrics scraping for Prometheus Operator deployments.

.Prerequisites

* You installed the Prometheus Operator.
* You configured your metrics endpoints.

.Procedure

. Optional. To manually verify that the metrics endpoint is responding locally before configuring Prometheus, run the following command to forward the port and inspect the payload:
+
[source,terminal,subs="+quotes"]
----
POD=$(oc get pod -n _<mcp_system>_ -l app.kubernetes.io/name=_<mcp_gateway_system>_ \
  -o jsonpath='{.items[0].metadata.name}')
oc port-forward -n _<mcp_gateway_system>_ pod/$POD 9090:9090 &
sleep 1
curl http://localhost:9090/metrics
----
+
* Replace `_<mcp_gateway>_` with the label value matching your deployment name.
* Replace `_<mcp_system>_` with the namespace where your {mcpg} pods are running.
+
[NOTE]
====
This command is for local manual inspection only.
====

. Configure Prometheus to scrape the pod-local endpoint directly. Use the following pod service discovery configuration:
+
.Example `PodMonitor` CR
[source,yaml,subs="+quotes"]
----
scrape_configs:
  - job_name: mcp-broker
    kubernetes_sd_configs:
      - role: pod
        namespaces:
          names: ["_<mcp_gateway_system>_"]
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_label_app_kubernetes_io_name]
        action: keep
        regex: mcp-gateway
      - source_labels: [__meta_kubernetes_pod_ip]
        target_label: __address__
        replacement: $1:9090
----
+
* User workload monitoring must be enabled. Ensure that you set `enableUserWorkload: true` in the `cluster-monitoring-config` ConfigMap in `openshift-monitoring`.
* Port must be named in the `Pod` spec. Ensure that your {mcpg} `Deployment` template either names port `9090`, such as `name: metrics`, or that you explicitly set `targetPort: 9090` in the `PodMonitor` spec.
