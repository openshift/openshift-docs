= Prometheus metrics scraping methods

[role="_abstract"]
Get real-time, aggregated visibility into the health, performance, and resource usage of your {mcpg}. Prometheus metrics give you a high-level numerical overview of your system state over time.

* Use internal cluster scraping for ad hoc debugging and verification. Retrieve metrics through pod IP address discovery.
* On {ocp}, use `PodMonitor` resources for automated configuration of continuous metrics scraping for Prometheus Operator deployments.
* If you use a standalone Prometheus instance, configure a `pod-IP` scrape job.

.Prerequisites

* You installed and configured Prometheus or the Prometheus Operator.
* If you are using the user-workload Prometheus instance in {ocp}, you enabled user workload monitoring by setting `enableUserWorkload: true` in the `cluster-monitoring-config` ConfigMap within `openshift-monitoring`.

.Procedure

. Optional. To manually verify that the metrics endpoint is responding locally before configuring Prometheus, run the following commands to forward the port and inspect the payload:
+
.. Start port-forwarding to a {mcpg} pod in a background terminal session by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc port-forward -n _<mcp_gateway_namespace>_ deployment/mcp-gateway 9090:9090
----
+
+
Replace `_<mcp_gateway_namespace>_` with the namespace where your {mcpg} pods are running.
+
.. In a separate terminal session, query the metrics endpoint by running the following command::
+
[source,terminal]
----
$ curl http://localhost:9090/metrics
----
+
[NOTE]
====
These commands are for local manual inspection only.
====

. If you are using {ocp} workload monitoring or the Prometheus Operator, create a `PodMonitor` CR by using the following example:
+
.Prometheus `PodMonitor` CR
[source,yaml,subs="+quotes"]
----
apiVersion: monitoring.coreos.com/v1
kind: PodMonitor
metadata:
  name: mcp-broker
  namespace: _<mcp_gateway_namespace>_
spec:
  selector:
    matchLabels:
      app.kubernetes.io/name: mcp-gateway
  podMetricsEndpoints:
    - port: http
      path: /metrics
      relabelings:
        - sourceLabels: [__meta_kubernetes_pod_ip]
          targetLabel: __address__
          replacement: $1:9090
----
+
* Replace the `metadata.namespace` parameter value with the namespace of your {mcpg} deployment.
* The `spec.podMetricsEndpoints.port` value of `http` selects one target per pod. The scrape goes to port `9090`.
* This relabeling rule targets port `9090` directly if the port is not explicitly exposed in the {mcpg} pod `containerPort` spec. The relabeling runs after the port filter and replaces `<pod-IP>:8080` with `<pod-IP>:9090`. Relabeling only changes where Prometheus scrapes. The broker component traffic on port `8080` is not affected.
+
[IMPORTANT]
====
Do not add `additionalScrapeConfigs` to the {ocp} user workload `Prometheus` resource because the Cluster Monitoring Operator removes it.

Prometheus instances run in the `openshift-user-workload-monitoring` namespace. User workload monitoring automatically discovers `PodMonitor` objects.
====

. If you are using a standalone Prometheus instance where you manually manage `prometheus.yml`, configure Prometheus to scrape the `pod-local` endpoint directly. Use the following pod service discovery configuration:
+
.Prometheus `scrape_configs` fragment
[source,yaml,subs="+quotes"]
----
scrape_configs:
  - job_name: mcp-broker
    kubernetes_sd_configs:
      - role: pod
        namespaces:
          names: ["_<mcp_gateway_namespace>_"]
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_label_app_kubernetes_io_name]
        action: keep
        regex: mcp-gateway
      - source_labels: [__meta_kubernetes_pod_ip]
        target_label: __address__
        replacement: $1:9090
----
+
* Replace `_<mcp_gateway_namespace>_` with the namespace where your {mcpg} pods are running.
* Add the scrape job to your Prometheus configuration.
+
[IMPORTANT]
====
Your Prometheus `ServiceAccount` needs permission to list and watch pods in the `Gateway` object namespace.
====
