= RHSA-2026:102896 - {product-title} {product-version}.48 bug fix and security update

Issued: 02 December 2026

[role="_abstract"]
{product-title} release {product-version}.48 is now available. The list of fixed bugs that are included in the update is documented in the link:https://access.redhat.com/errata/RHSA-2026:102896[RHSA-2026:102896] advisory. The RPM packages that are included in the update are provided by the link:https://access.redhat.com/errata/RHBA-2026:102892[RHBA-2026:102892] advisory.

Space precluded documenting all of the container images for this release in the advisory.

== Fixed issues

* Before this update, a security fix for a server-side request forgery (SSRF) vulnerability blocked access to Helm chart repositories, chart archives, and Open Container Initiative (OCI) registries on private networks. As a consequence, ProjectHelmChartRepository resources that pointed to internal Helm registries, such as registries on private IPv4 networks (RFC 1918), failed validation in the web console. With this release, the SSRF protection permits requests to private network addresses and in-cluster service names, but still blocks requests to localhost, loopback addresses, unspecified addresses, cloud metadata addresses, and Kubernetes API service names. As a result, you can use Helm chart repositories and registries on private networks. A chart URL must use an OCI scheme, or an HTTP or HTTPS scheme with a path that ends in .tgz or .tar.gz. A repository index URL must have a path that ends in /index.yaml. (link:https://redhat.atlassian.net/browse/OCPBUGS-128587[OCPBUGS-128587])

* Before this update, JSON merge patches could bypass field-level Common Expression Language (CEL) immutability rules on the `HostedCluster` custom resource by removing the `spec.infraID` or `spec.clusterID` specifications. As a consequence, the controller re-provisioned the infrastructure and orphaned existing resources. With this release, parent-level CEL validation rules reject API requests attempting to clear these fields. (link:https://issues.redhat.com/browse/OCPBUGS-129444[OCPBUGS-129444])

* Before this update, the {product-title} web console expected an Ingress Controller to exist even when the Ingress capability was disabled in hosted control plane clusters. As a consequence, hosted control plane clusters with disabled Ingress capability could not access the web console. With this release, the web console correctly handles hosted control plane clusters without Ingress Controllers. As a result, the web console is accessible in hosted control plane environments with disabled Ingress capability. (link:https://issues.redhat.com/browse/OCPBUGS-132382[OCPBUGS-132382])

* Before this update, VM live migration of virtual machines attached to localnet secondary networks had an implicit success window that required the migration to be reported as successful before the migration source pod was deleted. As a consequence, OVN-Kubernetes skipped the logical switch port update for the migration target, leaving the target pod's localnet logical switch port with `enabled=false` and no MAC address installed, so port security unconditionally dropped all traffic from the migrated VM. With this release, `DiscoverLiveMigrationStatus()` recognizes a completed migration when only the target pod remains and carries the `kubevirt.io/migration-target-ready-timestamp` annotation. As a result, after a live migration onto a localnet user-defined network, the target pod's logical switch port is enabled and populated with its MAC address, preserving connectivity across the migration. (link:https://issues.redhat.com/browse/OCPBUGS-133359[OCPBUGS-133359])

* Before this update, revealed values on the *Secret* details page could automatically become hidden when the page refreshed. With this release, the reveal state is preserved so that values remain visible until you click *Hide values*. As a result, secret values are not unexpectedly hidden. (link:https://issues.redhat.com/browse/OCPBUGS-136181[OCPBUGS-136181])

* Before this update, sometimes during startup the default Precision Time Protocol (PTP) Operator configuration failed to create because the webhook was not ready. As a consequence, the `linuxptp-daemon` service was not scheduled. With this release, the Operator waits for the webhook to become ready before creating the default PTP Operator configuration. As a result, the default PTP Operator configuration is populated reliably. (link:https://issues.redhat.com/browse/OCPBUGS-138073[OCPBUGS-138073])

* Before this update, large numbers of firing alerts could make the {product-title} web console slow or unresponsive. With this release, the notification drawer displays up to 50 alerts per group and dashboards display up to 50 alerts per list, improving responsiveness while preserving full counts and links to all alerts. (link:https://issues.redhat.com/browse/OCPBUGS-138375[OCPBUGS-138375])

*Previously, the Cluster Autoscaler's Cluster API provider could repeatedly reduce a node group's target size for the same pending Machine, potentially reducing the group to its minimum size. With this update, the provider skips pending Machines already marked for deletion. It also skips stale pending-machine deletion requests for Machines that have since registered as nodes, so those nodes go through the normal scale-down checks. (link:https://issues.redhat.com/browse/OCPBUGS-140548[OCPBUGS-140548])
