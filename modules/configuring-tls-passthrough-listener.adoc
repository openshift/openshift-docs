= Configure a TLS passthrough listener

[role="_abstract"]
To forward encrypted TLS connections without decrypting them at the gateway, you must add a listener that uses the `TLS` protocol and `Passthrough` mode. The listener inspects the Server Name Indication (SNI) hostname and passes the TLS stream to a `TLSRoute` custom resource (CR). The backend service presents the certificate and terminates TLS.

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the {oc-first}.
* You created a `Gateway` CR that the Ingress Operator manages.

.Procedure

. Edit your `Gateway` CR to add a TLS passthrough listener. Save the file as `gateway-tls-passthrough.yaml`:
+
--
The following example adds a `tls` listener on port `443`. For field details, see "Gateway listener configuration reference".

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: <example_gateway>
  namespace: openshift-ingress
spec:
  gatewayClassName: openshift-default
  listeners:
  - name: https
    protocol: HTTPS
    port: 443
    hostname: "app.<example_domain.tld>"
    tls:
      mode: Terminate
      certificateRefs:
      - name: <listener_cert>
        kind: Secret
    allowedRoutes:
      namespaces:
        from: Selector
        selector:
          matchLabels:
            env: "dev"
  - name: tls
    protocol: TLS
    port: 443
    hostname: "passthrough.<example_domain.tld>"
    tls:
      mode: Passthrough
    allowedRoutes:
      kinds:
      - kind: TLSRoute
      namespaces:
        from: Selector
        selector:
          matchLabels:
            env: "dev"
----
+
* `protocol: TLS` and `tls.mode: Passthrough` are required for `TLSRoute` attachment. Do not set `certificateRefs` on a passthrough listener. The backend terminates TLS.
* `hostname` must intersect with the `hostnames` on your `TLSRoute` CR.
* Distinct hostnames on the same port prevent listener conflicts. This configuration shares port `443` between an HTTPS listener that terminates TLS for `HTTPRoute` CRs and a TLS passthrough listener for `TLSRoute` CRs, similar to how {product-title} routes serve edge and passthrough traffic on the same router port by using SNI.
--

. Apply the `Gateway` CR by running the following command:
+
[source,terminal]
----
$ oc apply -f gateway-tls-passthrough.yaml
----
