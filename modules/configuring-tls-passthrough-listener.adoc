= Configure a TLS passthrough listener

[role="_abstract"]
To forward encrypted TLS connections without decrypting them at the gateway, you must add a listener that uses the `TLS` protocol and `Passthrough` mode. The listener inspects the Server Name Indication (SNI) hostname and passes the TLS stream to a `TLSRoute` custom resource (CR). The backend service presents the certificate and terminates TLS.

[IMPORTANT]
====
The `openshift-default` GatewayClass does not support `tls.mode: Passthrough`. Use a GatewayClass whose implementation supports TLSRoute passthrough, such as {SMProductName}.
====

.Prerequisites

* You have access to the cluster as a user with the `cluster-admin` role.
* You have installed the {oc-first}.
* You have a `GatewayClass` CR whose implementation supports TLSRoute passthrough. Do not use `openshift-default`.

.Procedure

. Edit your `Gateway` CR to add a TLS passthrough listener. Save the file as `gateway-tls-passthrough.yaml`:
+
--
The following example adds a `passthrough-listener` on port `443`. For field details, see "Gateway listener configuration reference".

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: <example_gateway>
  namespace: <gateway_namespace>
spec:
  gatewayClassName: <gatewayclass_name>
  listeners:
  - name: passthrough-listener
    protocol: TLS
    port: 443
    hostname: "db.<example_domain.tld>"
    tls:
      mode: Passthrough
    allowedRoutes:
      kinds:
      - kind: TLSRoute
----
+
* `gatewayClassName` must name a GatewayClass whose implementation supports TLSRoute passthrough. Do not set this field to `openshift-default`.
* `protocol: TLS` and `tls.mode: Passthrough` are required for `TLSRoute` attachment. Do not set `certificateRefs` on a passthrough listener. The backend terminates TLS.
* `hostname` must intersect with the `hostnames` on your `TLSRoute` CR.
--

. Apply the `Gateway` CR by running the following command:
+
[source,terminal]
----
$ oc apply -f gateway-tls-passthrough.yaml
----
