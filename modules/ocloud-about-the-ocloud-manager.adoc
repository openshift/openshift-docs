= Template-based cluster provisioning and management at scale

[role="_abstract"]
Managing bare-metal {product-title} clusters at scale introduces challenges that grow with fleet size. As the number of sites increases, maintaining consistency across cluster configurations, coordinating hardware allocation, and executing lifecycle operations such as upgrades and scaling become increasingly complex and error-prone when handled manually or through bespoke automation.

The O-Cloud Manager addresses these challenges by providing template-based infrastructure and cluster lifecycle management. It runs on a hub cluster alongside {rh-rhacm-first} and orchestrates the provisioning, configuration, scaling, and upgrading of managed clusters through declarative custom resources.

The O-Cloud Manager separates reusable cluster blueprints from site-specific deployment parameters:

* Platform engineers define immutable `ClusterTemplate` resources that specify the cluster topology, hardware requirements, and configuration policies for a class of clusters.
* Site engineers create `ProvisioningRequest` resources that reference a template and supply only the site-specific values such as network addresses and cluster names.

This separation means that platform-wide changes, such as a new firmware baseline or an updated network policy, can be rolled out by versioning a template rather than editing each cluster individually. The O-Cloud Manager validates each request against the template schema, allocates hardware from managed resource pools, and orchestrates the end-to-end lifecycle flow using the SiteConfig Operator, {gitops-title}, and the {cgu-operator-full}.

All lifecycle operations, provisioning, configuration, scaling, and upgrades, are driven through the `ProvisioningRequest` custom resource, providing a single point of control for each managed cluster.

The O-Cloud Manager also implements the O-RAN Alliance O2 IMS specification, which provides standardized REST APIs for integration with Service Management and Orchestration (SMO) systems in telco environments. However, SMO integration is optional. The Operator can be used standalone for any multi-cluster, bare-metal deployment that benefits from template-driven lifecycle management.
