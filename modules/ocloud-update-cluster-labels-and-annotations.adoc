= Update cluster labels and annotations

[role="_abstract"]
You can update labels and annotations on a provisioned cluster and its nodes by modifying the `clusterInstanceParameters` field in the `ProvisioningRequest` custom resource. The O-Cloud Manager propagates the changes to the `ManagedCluster` and `BareMetalHost` resources on the hub cluster.

[NOTE]
====
`ManagedCluster` and node labels and annotations are the only `clusterInstanceParameters` fields that can be edited after cluster installation. All other fields are immutable and are rejected by the O-Cloud Manager.
====

.Prerequisites

* The cluster is fully provisioned with `provisioningPhase: fulfilled` on the `ProvisioningRequest` CR.

.Procedure

. Edit the `ProvisioningRequest` CR to update cluster-level or node-level labels and annotations by running the following command:
+
[source,terminal]
----
$ oc edit provisioningrequests.clcm.openshift.io <uuid>
----
+
where:
+
--
`<uuid>`:: Specifies the UUID of the `ProvisioningRequest` CR for the target cluster.
--
+
To add or update cluster-level labels and annotations, modify the `extraLabels` and `extraAnnotations` fields:
+
[source,yaml]
----
spec:
  templateParameters:
    clusterInstanceParameters:
      extraAnnotations:
        ManagedCluster:
          environment: production
      extraLabels:
        ManagedCluster:
          region: us-east
----
+
To add or update node-level labels and annotations, modify the node entries:
+
[source,yaml]
----
spec:
  templateParameters:
    clusterInstanceParameters:
      nodes:
      - hostName: worker-1.cluster.example.com
        extraAnnotations:
          BareMetalHost:
            maintenance-window: "saturday-0200"
        extraLabels:
          BareMetalHost:
            rack: rack-a
----
+
* Cluster-level changes are propagated to the `ManagedCluster` CR on the hub cluster.
* Node-level changes are propagated to the corresponding `BareMetalHost` CRs.

. Apply the updated `ProvisioningRequest` CR to the hub cluster, or commit it to the GitOps repository for ArgoCD synchronization.

.Verification

* Verify that the changes are reflected in the `ProvisioningRequest` CR status conditions by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -o jsonpath='{.status.conditions}'
----
+
The `status.conditions` records the success or failure of the update.
