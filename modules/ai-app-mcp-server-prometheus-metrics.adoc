= Using metrics to monitor the MCP server for Red{nbsp}Hat OpenShift

[role="_abstract"]
The MCP server for Red{nbsp}Hat OpenShift exposes metrics that you can collect with OpenTelemetry Protocol (OTLP) export or Prometheus to monitor server health, request rates, and toolset activity.

.Available metric capturing methods
[cols="1,1,2,1",options="header"]
|===
|Mechanism|Direction|Method|Endpoint/config
|OTLP export|Push|Server pushes metrics every 30 seconds to a configured OTLP endpoint|`[telemetry]` in `config.toml` 
|Prometheus|Pull|Prometheus scrapes the server| `/metrics` endpoint and ServiceMonitor
|===

[NOTE]
====
The MCP server also exposes a Prometheus-compatible `/metrics` endpoint in OpenMetrics format on its HTTP port. If you prefer pull-based collection, create a ServiceMonitor that targets the server's metrics port. For more information, see xref:../../observability/monitoring/about-ocp-monitoring.adoc#about-ocp-monitoring[About OpenShift Container Platform monitoring].
====

.Available metrics
[cols="1,1,2",options="header"]
|===
|Metric |Type |Description
|`k8s_mcp_tool_calls_total`|Counter|Total MCP tool calls (labeled by `tool_name`) 
|`k8s_mcp_tool_errors_total`|Counter|Total MCP tool errors (labeled by `tool_name`)
|`k8s_mcp_tool_duration_seconds`|Histogram|Tool call duration in seconds
|`k8s_mcp_http_requests_total`|Counter|HTTP requests (labeled by `method`/`path`/`status` class)
|`k8s_mcp_server_info`|Gauge|Server info (labeled by version, `go_version`)  
|===

.Prerequisites
* MCP server for Red{nbsp}Hat OpenShift is installed and running.

.Procedure
. In the MCP server `config.toml` file, add a `[telemetry]` section that sets the OTLP endpoint and transport protocol as per the following example:
+
[source,toml]
----
[telemetry]
endpoint = "http://<otlp_endpoint>:4317"
protocol = "grpc"
----
+
* `endpoint`: The URL of your OTLP backend. Telemetry is enabled automatically when you set `endpoint`.
* `protocol`: Either `grpc` (the default, on port 4317) or `http/protobuf` (on port 4318). Set the port to match the protocol.

. Optional: For a secure (TLS) endpoint, use an https:// URL and, for a self-signed CA, provide the CA certificate.
