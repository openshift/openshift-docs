[id="virt-dashboard-panel-types_{context}"]
= Dashboard panel types

[role="_abstract"]
The {VirtProductName} dashboards use the following panel types to display data. Each panel type presents information in a different format depending on the metric.

[id="gauge-panels_{context}"]
== Gauge panels

Gauge panels display a single percentage value with color-coded thresholds. Green indicates a healthy state, amber indicates a warning, and red indicates a critical state.

The following table describes the gauge panels in the Nodes Memory dashboard:

[cols="1,2",options="header"]
|===
| Panel | Description

| *Node Utilization - max*
| Displays the highest node utilization in the cluster. Use this panel together with the *Node Utilization - min* panel to assess scheduling balance. A large gap between minimum and maximum node utilization indicates an imbalanced workload distribution.

| *Node Utilization - min*
| Displays the lowest node utilization in the cluster.

| *Cluster Utilization*
| Displays the aggregated memory utilization of the nodes in the cluster.

| *Cluster Virtual Committed*
| Displays the percentage of committed virtual memory out of all of the allocatable physical memory.

| *VM Virtual Committed*
| Displays the average VM overcommit ratio, which includes launcher overhead.

| *Node PSI - max*
| Displays the highest pressure stall information (PSI) value across all nodes. PSI shows the amount of time applications are stalled or delayed waiting for memory resources.
|===

[id="time-series-panels_{context}"]
== Time series panels

Time series panels display multi-line plots over a time range for identifying trends and comparing entities.

The following table describes the time series panels in the Nodes Memory dashboard:

[cols="1,2",options="header"]
|===
| Panel | Description

| *Cluster Utilization*
| Displays the trend over time of several memory metrics. Use this panel to compare actual utilization and virtual memory plans against total capacity.

| *Physical Memory Utilization & Requests*
| Displays total node memory capacity alongside actual memory utilization split into virtualization and non-virtualization workloads. This panel also shows the memory request plan so that you can compare actual usage to scheduler expectations.

| *Virtual Memory Assignment*
| Displays the worst-case scenario if all virtual memory is used at present. If the *VM assigned virtual memory* line nears or exceeds *Node capacity*, the cluster risks out-of-memory conditions under full VM memory pressure.

| *Cluster - Memory Pressure*
| Shows cluster-level memory PSI rates for `Waiting` (processes delayed by memory) and `Stalled` (processes completely blocked).

| *Cluster - Aggregated Swap*
| Shows total swap capacity and usage across the selected nodes. Rising swap usage indicates memory pressure that has not yet caused PSI stalls.

| *Utilization - Actual Overcommit Level*
| Displays the per-node allocatable memory utilization minus the system-reserved memory.

| *Plan - Pod Requests per Node*
| Shows the memory request fill level per node: the sum of all pod memory requests on a node divided by the node's allocatable memory.

| *Plan - Virtual Memory Commit Level*
| Displays the virtual memory commit ratio per node. The panel compares total active and assigned VM memory against the node's available memory.

| *Node - Pressure*
| Displays the memory PSI waiting rate per node. Each line represents one node to help you identify which nodes experience memory contention.

| *Utilization - Reserved System Memory*
| Displays the top 5 nodes by system-reserved memory utilization. This metric compares active system process memory against the reserved memory budget.

| *Utilization - min/max*
| Displays the minimum and maximum system-reserved memory utilization across all nodes over time.

| *VM Overcommit Ratio*
| Displays the ratio of assigned virtual memory to pod memory requests for each VM.

| *VM Virtual Memory Utilization vs Host VM Utilization*
| Displays the 10 VMs with the highest ratio between guest-reported memory usage and host-side container memory usage. Use this panel to identify VMs where guest-reported usage differs significantly from host-side accounting.

| *Number of Running VMs*
| Displays the total number of running virtual machine instances (VMIs) on the cluster to provide context for the other workload panels.
|===

[id="stat-panels_{context}"]
== Stat panels

Stat panels display a single numeric value with unit formatting, such as bytes, percentage, or hours.

The following table describes the stat panels in the Nodes Memory dashboard:

[cols="1,2",options="header"]
|===
| Panel | Description

| *Node Requests - min/max*
| Displays the minimum and maximum pod request ratios per node. Use this panel to quickly assess the cluster's remaining capacity to host new workloads.

| *Node Virtual - min/max*
| Displays the minimum and maximum virtual commit levels per node.

| *System Exceeding Reservation*
| Displays the percentage or number of nodes that are currently triggering the `SystemMemoryExceedsReservation` alert.
|===

[id="table-panels_{context}"]
== Table panels

Table panels display multi-column, sortable data with filtering and conditional formatting. The Virtual Machines Inventory, Virtual Machines Utilization, Virtual Machines Service Level, Virtual Machines Time in Status, and Top Consumers dashboards each use table panels as their primary display.
