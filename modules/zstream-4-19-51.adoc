== Fixed issues

* Before this update, when a node with an assigned EgressIP was rebooted, the cluster manager immediately reassigned the EgressIP to a new node without waiting for the old node to remove it. As a consequence, both the old and new nodes responded to ARP requests for the same EgressIP with different MAC addresses, causing MAC address flapping. Depending on the configuration, this could overload network switches, trigger port blocking, or disrupt network infrastructure depending on the configuration. With this release, the EgressIP removal process on the old node is prioritized to complete before the new node announces the IP address. As a result, MAC address flapping and associated network disruptions are prevented. (link:https://redhat.atlassian.net/browse/OCPBUGS-129151[OCPBUGS-129151])
