= Enable the HTTP add-on

[role="_abstract"]
You can enable the HTTP add-on so that the Custom Metrics Autoscaler Operator installs the interceptor, scaler, and HTTP add-on operator. The add-on stays disabled until you set `spec.httpAddon.enabled` to `true` on the `KedaController` custom resource. To remove the HTTP add-on and keep the Operator installed, set that field to `false`.

.Prerequisites

* The Custom Metrics Autoscaler Operator is installed.
* You have permission to edit the `KedaController` custom resource in the `{cma-namespace}` namespace.

.Procedure

. In the {product-title} web console, click *Ecosystem* -> *Installed Operators*.

. Switch to the `{cma-namespace}` project.

. Click *Custom Metrics Autoscaler*.

. On the *Operator Details* page, click the *KedaController* tab.

. Click the `keda` custom resource, and then click the *YAML* tab.

. Set `spec.httpAddon.enabled` to `true`:
+
[source,yaml,subs="+attributes"]
----
apiVersion: keda.sh/v1alpha1
kind: KedaController
metadata:
  name: keda
  namespace: {cma-namespace}
spec:
  httpAddon:
    enabled: true <1>
----
<1> Installs the HTTP add-on operator, interceptor, and scaler. The default is `false`.

. Click *Save*.

. Optional: Set interceptor replicas or environment variables in the same custom resource. For example, disable direct pod routing so that the interceptor uses the service, which honors service network policy:
+
[source,yaml,subs="+attributes"]
----
spec:
  httpAddon:
    enabled: true
    interceptor:
      replicas: 3 <1>
      env:
        - name: KEDA_HTTP_DIRECT_POD_ROUTING <2>
          value: "false"
----
<1> Specifies the number of interceptor replicas. Increase this value when the interceptor itself needs more capacity.
<2> When `false`, the interceptor forwards requests through the target service instead of directly to a pod IP.

.Verification

. Confirm that the HTTP add-on installation succeeded by running the following command:
+
[source,terminal,subs="+attributes"]
----
$ oc get kedacontroller keda -n {cma-namespace} -o yaml
----
+
Confirm that `status.httpAddon.phase` is `Installation Succeeded`.

. Confirm that the HTTP add-on workloads are running by running the following command:
+
[source,terminal,subs="+attributes"]
----
$ oc get deploy,svc -n {cma-namespace}
----
+
The command lists deployments for the HTTP add-on operator, the interceptor, and the scaler in the `{cma-namespace}` namespace. The services include `keda-add-ons-http-interceptor-proxy` and `keda-add-ons-http-external-scaler`.
