= Collect traces and metrics without instrumenting your application

[role="_abstract"]
To collect traces and metrics without instrumenting your application, you can run the OBI Receiver, which uses Linux capabilities.

.Prerequisites

* The OBI Receiver requires nodes that use the `amd64` or `arm64` CPU architecture. The OBI Receiver is not available on the IBM Z (`s390x`) or IBM Power (`ppc64le`) architectures.

.Procedure

. Apply the service account:
+
[source,yaml]
----
apiVersion: v1
kind: ServiceAccount
metadata:
  name: obi-collector
  namespace: <namespace>
# ...
----

. Apply the cluster role:
+
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: obi
rules:
  - apiGroups: ['apps']
    resources: ['replicasets']
    verbs: ['list', 'watch']
  - apiGroups: ['']
    resources: ['pods', 'services', 'nodes']
    verbs: ['list', 'watch']
----

. Apply the cluster role binding:
+
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: obi
subjects:
  - kind: ServiceAccount
    name: obi-collector
    namespace: <namespace>
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: obi
----

. Apply the security context constraints:
+
[source,yaml]
----
apiVersion: security.openshift.io/v1
kind: SecurityContextConstraints
metadata:
  name: obi-unprivileged
allowHostPorts: false
allowHostDirVolumePlugin: true
allowHostIPC: false
allowHostNetwork: false
allowHostPID: true
allowPrivilegedContainer: false
readOnlyRootFilesystem: true
allowedCapabilities:
  - BPF
  - SYS_PTRACE
  - NET_RAW
  - CHECKPOINT_RESTORE
  - DAC_READ_SEARCH
  - PERFMON
runAsUser:
  type: RunAsAny
seLinuxContext:
  type: RunAsAny
volumes:
  - emptyDir
  - hostPath
  - configMap
  - secret
  - downwardAPI
  - projected
users:
- system:serviceaccount:<namespace>:obi-collector
# ...
----
where:

`allowedCapabilities:`:: The listed Linux capabilities load the eBPF programs, inspect processes and executables through the `/proc` filesystem, attach socket filters to capture HTTP requests, and open the Executable and Linkable Format (ELF) files of the instrumented processes.

. Apply the `OpenTelemetryCollector` custom resource:
+
[source,yaml]
----
apiVersion: opentelemetry.io/v1beta1
kind: OpenTelemetryCollector
metadata:
  name: obi-collector
  namespace: <namespace>
spec:
  mode: daemonset
  serviceAccount: obi-collector
  hostPID: true
  securityContext:
    runAsUser: 0
    readOnlyRootFilesystem: true
    capabilities:
      add:
        - BPF
        - SYS_PTRACE
        - NET_RAW
        - CHECKPOINT_RESTORE
        - DAC_READ_SEARCH
        - PERFMON
      drop:
        - ALL
  volumes:
    - name: var-run-obi
      emptyDir: {}
    - name: cgroup
      hostPath:
        path: /sys/fs/cgroup
        type: Directory
  volumeMounts:
    - name: var-run-obi
      mountPath: /var/run/obi
    - name: cgroup
      mountPath: /sys/fs/cgroup
      readOnly: true
  config:
    receivers:
      obi:
        discovery:
          instrument:
            - k8s_namespace: <application_namespace>
              k8s_pod_labels:
                obi.instrument: "true"
        attributes:
          kubernetes:
            enable: "true"
    exporters:
      debug:
        verbosity: detailed
    service:
      pipelines:
        traces:
          receivers: [obi]
          exporters: [debug]
# ...
----
where:

`hostPID: true`::
Enables the OBI Receiver to access the processes on the host.

`discovery.instrument`::
Lists the processes the OBI Receiver attaches to. This example filters by namespace and pod labels, so that only pods matching all of the fields are instrumented.

`k8s_namespace: <application_namespace>`::
Selects the workloads to instrument.

`attributes.kubernetes.enable`::
Setting this field to `"true"` adds resource attributes such as `k8s.namespace.name`, `k8s.pod.name`, and `service.name` to the traces. Enables Kubernetes attribute enrichment. For enrichment, the Collector `ServiceAccount` requires the `list` and `watch` permissions on pods, services, and nodes in the core API group and on replica sets in the `apps` API group. These permissions are granted by the `ClusterRole` in a previous step.

. Add the matching label to the workload pod templates to opt them in:
+
[source,yaml]
----
apiVersion: apps/v1
kind: Deployment
metadata:
  name: <application>
  namespace: <application_namespace>
spec:
  template:
    metadata:
      labels:
        obi.instrument: "true"
    spec:
      containers:
        - name: <application>
          image: <application>:latest
# ...
----

.Verification

* The OBI Receiver mounts the host `/sys/fs/cgroup` directory as read-only so that it can monitor newly created sockets for outgoing requests.
