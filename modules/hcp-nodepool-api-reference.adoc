[id="hcp-nodepool-api-reference_{context}"]
= NodePool API reference for autoscaling

[role="_abstract"]
Get familiar with the `NodePool` specification fields related to autoscaling, including scaling to and from zero on supported platforms.

[id="hcp-nodepool-api-spec-autoscaling_{context}"]
== spec.autoScaling

[cols="1,1,3", options="header"]
|===
|Field |Type |Description

|`min`
|integer
|Minimum number of nodes for the pool when autoscaling is enabled.
`0` is valid on {aws-first} and {azure-short}.
Other platforms require `min` to be at least `1`.

|`max`
|integer
|Maximum number of nodes the cluster autoscaler can add to the pool.

|===

[id="hcp-nodepool-api-spec-replicas_{context}"]
== spec.replicas

[cols="1,1,3", options="header"]
|===
|Field |Type |Description

|`replicas`
|integer
|Fixed number of nodes when autoscaling is disabled.
Omit this field when `spec.autoScaling` is set.

|===

[id="hcp-nodepool-api-drain-detach-timeouts_{context}"]
== Drain and detach timeouts

[cols="1,1,3", options="header"]
|===
|Field |Type |Description

|`nodeDrainTimeout`
|duration
|Time the controller spends draining a node during scale-down.
A value of `0s` blocks draining until a positive timeout is set.

|`nodeVolumeDetachTimeout`
|duration
|Time the controller spends detaching volumes from a node during scale-down.
A value of `0` blocks detachment until a positive timeout is set.

|===

[id="hcp-nodepool-api-status-conditions_{context}"]
== status.conditions

[cols="1,3", options="header"]
|===
|Condition |Description

|`AutoscalingEnabled`
|Reports `True` when autoscaling is correctly configured and the autoscaler manages the pool.

|===

[id="hcp-nodepool-api-sm-operator-flags_{context}"]
== HyperShift Operator flags

[cols="1,3", options="header"]
|===
|Flag |Description

|`--scale-from-zero-provider`
|Provider used to fetch instance-type metadata on {aws-short} and {azure-short}.

|`--scale-from-zero-creds`
|Credentials for the scale-from-zero provider on {aws-short} and {azure-short}.

|===
