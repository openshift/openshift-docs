= Override upgrade parameters for a ProvisioningRequest

[role="_abstract"]
You can override the default upgrade parameters defined in the `ClusterTemplate` custom resource by specifying `upgradeParameters` in the `ProvisioningRequest` CR. Override values are deep-merged on top of the `ClusterTemplate` `upgradeDefaults`, with `ProvisioningRequest` values taking precedence.

[NOTE]
====
For image-based upgrades, the `plan` field is an array and is merged by index position. Element 0 of the override merges with element 0 of the defaults, element 1 with element 1, and so on. If the override array is longer, extra elements are appended.
====

[NOTE]
====
Both `upgradeDefaults` in the `ClusterTemplate` CR and `upgradeParameters` in the `ProvisioningRequest` CR must conform to the `upgradeParameters` sub-schema defined in the `ClusterTemplate` `templateParameterSchema`. Invalid overrides are rejected during validation.
====

.Prerequisites

* A `ClusterTemplate` CR is prepared for the target release with `upgradeDefaults` configured.
* The `templateParameterSchema` in the `ClusterTemplate` CR exposes the `upgradeParameters` sub-schema.

.Procedure

. Edit the `ProvisioningRequest` CR to add or update the `spec.templateParameters.upgradeParameters` field by running the following command:
+
[source,terminal]
----
$ oc edit provisioningrequests.clcm.openshift.io <uuid>
----
+
where:
+
--
`<uuid>`:: Specifies the UUID of the `ProvisioningRequest` CR for the target cluster.
--
+
For single-node image-based upgrades, you can override the seed image and stage timeouts:
+
[source,yaml]
----
spec:
  templateParameters:
    upgradeParameters:
      imageBasedGroupUpgrade:
        ibuSpec:
          seedImageRef:
            image: "quay.io/seed-repo/seed-image:4.Y.Z+1-v2"
        plan:
          - actions: ["Prep"]
            rolloutStrategy:
              timeout: 20
          - actions: ["AbortOnFailure"]
          - actions: ["Upgrade"]
            rolloutStrategy:
              timeout: 90
----
+
* The seed image is overridden to use a different image tag.
* The Prep timeout is set to 20 minutes and the Upgrade timeout is increased to 90 minutes.
* Fields not specified in `upgradeParameters` are inherited from the `ClusterTemplate` `upgradeDefaults`.
+
For multi-node ClusterVersion upgrades, you can override the timeout and channel:
+
[source,yaml]
----
spec:
  templateParameters:
    upgradeParameters:
      clusterUpgradeTimeout: "6h"
      clusterVersion:
        channel: "eus-4.22"
----
+
[NOTE]
====
During an in-progress upgrade, only `clusterUpgradeTimeout` is recognized as an update. Other parameter changes are ignored until the upgrade completes or fails.
====

. Apply the updated `ProvisioningRequest` CR to the hub cluster, or commit it to the GitOps repository for ArgoCD synchronization.

.Verification

* Verify that the override is accepted by checking that the upgrade proceeds with the modified parameters by running the following command:
+
[source,terminal]
----
$ oc get provisioningrequests.clcm.openshift.io <uuid> -o jsonpath='{.status.conditions[?(@.type=="UpgradeCompleted")]}'
----
