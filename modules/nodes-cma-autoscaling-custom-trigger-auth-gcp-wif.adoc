= Configure a trigger authentication for {gcp-wid-short}

[role="_abstract"]
You can configure a `TriggerAuthentication` object in a workload namespace so that the Custom Metrics Autoscaler Operator obtains a short-lived {gcp-short} access token for that workload.

The Operator requests a projected token for the service account in that namespace and exchanges the token with {gcp-short} Security Token Service. A workload in another namespace cannot use that identity. Create a `TriggerAuthentication` object for this configuration. A `ClusterTriggerAuthentication` object uses a service account in the Operator namespace, so it does not isolate the {gcp-short} identity to one workload.

.Prerequisites

* The Custom Metrics Autoscaler Operator 2.20 or later is installed.

* The cluster is a connected multi-node cluster that uses the `x86_64` or `aarch64` architecture.

* The cluster is self-managed or managed, including a cluster that uses hosted control planes.

* The cluster uses {gcp-wid-short}.
+
For more information, see xref:../../authentication/managing_cloud_provider_credentials/cco-short-term-creds.adoc#cco-short-term-creds[Short-term credentials for components].

* You have created a federated {gcp-short} service account.
+
For more information, see xref:../../nodes/pods/nodes-pods-short-term-auth.adoc#pod-short-term-auth-gcp-cloud-sa_nodes-pods-short-term-auth[Create a federated {gcp-short} service account].

* You have created an {product-title} service account for {gcp-wid-short} in the workload namespace.
+
For more information, see xref:../../nodes/pods/nodes-pods-short-term-auth.adoc#pod-short-term-auth-gcp-cluster-sa_nodes-pods-short-term-auth[Create an {product-title} service account for {gcp-short}].

* You are logged in to the {product-title} web console as a user who can create a `TriggerAuthentication` object in the workload namespace.

* You have access to the {oc-first} as a user who can create roles in the workload namespace.

.Procedure

. Create a YAML file that allows the Operator to request tokens for the workload service account:
+
.Example role for the workload service account
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: keda-gcp-token-creator
  namespace: my-namespace
rules:
- apiGroups:
  - ""
  resources:
  - serviceaccounts/token
  verbs:
  - create
  resourceNames:
  - my-workload-sa
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: keda-gcp-token-creator-binding
  namespace: my-namespace
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: keda-gcp-token-creator
subjects:
- kind: ServiceAccount
  name: keda-operator
  namespace: openshift-keda
----
+
where:

`metadata.namespace`:: Specifies the namespace of the workload.
`rules[].resourceNames[]`:: Specifies the service account that the Operator can request tokens for. Name only the service account that this workload uses for {gcp-wid-short}.
`subjects[].namespace`:: Specifies `openshift-keda`, the namespace where you installed the Custom Metrics Autoscaler Operator.

. Apply the file by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----

. In the {product-title} web console, click *Ecosystem* -> *Installed Operators*.

. Click *Custom Metrics Autoscaler*.

. On the *Operator Details* page, click the *TriggerAuthentication* tab.

. On the *TriggerAuthentication* tab, click *Create TriggerAuthentication*.

. Select *YAML view* and replace the YAML with the following example:
+
.Example trigger authentication for {gcp-wid-short}
[source,yaml]
----
kind: TriggerAuthentication
apiVersion: keda.sh/v1alpha1
metadata:
  name: gcp-triggerauthentication
  namespace: my-namespace
spec:
  podIdentity:
    provider: gcp
  boundServiceAccountToken:
    - parameter: token
      serviceAccountName: my-workload-sa
      audience: <identity_provider_audience>
----
+
where:

`metadata.namespace`:: Specifies the namespace of the workload. Set this to the workload namespace, not `openshift-keda`.
`spec.podIdentity.provider`:: Specifies `gcp` so that the Operator uses {gcp-wid-short}.
`spec.boundServiceAccountToken[].parameter`:: Specifies the authentication parameter that receives the projected service account token. Set this value to `token`.
`spec.boundServiceAccountToken[].serviceAccountName`:: Specifies the {product-title} service account in this namespace that you configured for {gcp-wid-short}.
`spec.boundServiceAccountToken[].audience`:: Specifies the audience of the {gcp-short} workload identity provider. Use the audience configured for the service account, such as the value of the `cloud.google.com/audience` annotation.
+
[IMPORTANT]
====
The {product-title} API server audience is not valid for this token exchange. Set `audience` to the workload identity provider audience.
====

. Click *Create*.

. Add the trigger authentication to the `ScaledObject` or `ScaledJob` object that uses the {gcp-short} identity.
+
The following example shows the `authenticationRef` fields. Set `spec.triggers[].type` and `spec.triggers[].metadata` for your metrics source.
+
.Example scaled object that uses the {gcp-wid-short} trigger authentication
[source,yaml]
----
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: scaledobject
  namespace: my-namespace
spec:
  scaleTargetRef:
    name: example-deployment
  maxReplicaCount: 100
  minReplicaCount: 0
  pollingInterval: 30
  triggers:
  - type: <trigger_type>
    authenticationRef:
      name: gcp-triggerauthentication
      kind: TriggerAuthentication
----
+
where:

`metadata.namespace`:: Specifies the namespace of the `TriggerAuthentication` object.
`spec.triggers[].type`:: Specifies the trigger that queries {gcp-short}. Include the `metadata` for that trigger type.
`spec.triggers[].authenticationRef.name`:: Specifies `gcp-triggerauthentication`, the name of the trigger authentication.
`spec.triggers[].authenticationRef.kind`:: Specifies `TriggerAuthentication`.

. Apply the scaled object by running the following command:
+
[source,terminal]
----
$ oc apply -f <filename>.yaml
----

.Verification

. Confirm that the trigger authentication uses the workload service account by running the following command:
+
[source,terminal,options="nowrap"]
----
$ oc get triggerauthentication gcp-triggerauthentication -n my-namespace -o jsonpath='{.spec.podIdentity.provider}{"\n"}{.spec.boundServiceAccountToken[0].serviceAccountName}{"\n"}'
----
+
.Example output
[source,terminal]
----
gcp
my-workload-sa
----
+
`gcp` is the pod identity provider. `my-workload-sa` is the service account in the workload namespace.
