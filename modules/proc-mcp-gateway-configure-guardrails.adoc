= Configure NeMo Guardrails on {mcpg}

[role="_abstract"]
Add text

.Prerequisites 

* You installed {mcpg}.
* You configured {mcpg} with at least `MCPServerRegistration` CR.
* You have NeMo Guardrails server configured and running via the TrustyAI operator on RHOAI. Must be in the same namespace as the MCP Gateway 

.Procedure

. Create the guardrails Secret CR that points to the NeMo guardrails server. The Secret must be in the same namespace as the MCP gateway.
+
.Example Secret CR 
[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: _<guardrails-config>_
  namespace: mcp-system
  labels:
    mcp.kuadrant.io/secret: "true"
type: guardrails/external/nemo
stringData:
  config.yaml: 
    url: https://nemo-guardrails.mcp-system.svc.cluster.local:8080
    configIDs:
      - "pii"
    model: "meta/llama-3.1-8b-instruct"
    failMode: deny
----
* The required `_<guardrails-config>_` parameter sets the name of your Secret CR. 
* The required `url` parameter sets the NeMo Guardrails server endpoint. 
* The optional `configID` sets the configuration IDs passed to all registered MCP servers.
* The required `model` parameter sets the LLM. 
* The optional `failMode` parameter controls behavior when the NeMo Guardrails server is unreachable. It defaults to deny, but can be set to allow.

. Update your `MCPGatewayExtension` CR to include the `mcp.kuadrant.io/guardrails-ref` annotation.  
+
.Example MCPGatewayExtension CR that includes the guardrails annotations. 
[source,yaml]
----
apiVersion: mcp.kuadrant.io/v1
kind: MCPGatewayExtension
metadata:
  name: _<mcp_gateway>_
  annotations:
    mcp.kuadrant.io/guardrails-ref: _<guardrails-config>_
spec:
  targetRef:
    name: _<mcp_gateway>_
    sectionName: mcp
----
+
This enabled guardrails globally for all servers registered under a gateway and names the Secret in the same namespace

. Apply the changes with the following command:
+
[source,terminal]
----
$ oc apply -f _<mcp_gateway>_
----

. Optional: If a server has access to high risk tools, you can extent the global guardrails policy with additional config IDs. You can enable additional guardrails for a specific server by updating the `MCPServerRegistration` CR with the following command:
+
[source,terminal]
----
$ oc annotate mcpserverregistration high-risk-server -n mcp-system \
mcp.kuadrant.io/guardrails-config-ids=toxicity,input-jailbreaking
----

.Verification 

. Verify that the `MCPGatewayExt` is ready with the following command: 
+
[source,terminal]
----
$ oc get mcpgatewayextension mcp-gateway -n mcp-system
----

. Test a tool call:
+
[source,terminal]
----
curl -X POST https://<your-gateway-host>/mcp \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "execute_sql",
      "arguments": {"query": "DROP TABLE users"}
    }
  }'
----
+
.Example output of a blocked tool call
[source,terminal]
----
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32000,
    "message": "tool call blocked by guardrails"
  }
}
----
