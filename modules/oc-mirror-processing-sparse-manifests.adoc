= How oc-mirror plugin v2 processes sparse manifests

[role="_abstract"]
You can use sparse manifests in oc-mirror plugin v2 with multi-architecture filtering to mirror only the architectures you specify in the `ImageSetConfiguration` file while keeping each manifest list digest unchanged.

Multi-architecture filtering relies on sparse manifest support in the target mirror registry. Without sparse manifests, omitting child manifests changes the digest and breaks the image references in the disconnected cluster.

When oc-mirror plugin v2 mirrors a multi-architecture image with filtering enabled, it uses sparse manifest support to push the manifest list while mirroring only the selected architecture blobs:

* Reads the manifest list from the source registry or disk archive.
* Mirrors child manifests and blobs only for the architectures listed in the `ImageSetConfiguration` file.
* Pushes the unmodified manifest list to the target mirror registry, preserving the upstream digest.

[IMPORTANT]
====
Using sparse manifests requires a target mirror registry that supports sparse manifest pushes and allows disabling manifest list checks. Registries that enforce the presence of all child manifests listed in a manifest list reject sparse pushes and cause the mirroring operation to fail.
====

[id="oc-mirror-sparse-manifest-imageset-config_{context}"]
== Interaction with the image set configuration file

You enable multi-architecture filtering by adding `platforms` fields to the `ImageSetConfiguration` file. oc-mirror plugin v2 evaluates those fields when it mirrors platform release payload images, Operator catalog images, and additional images.

For example, setting the `mirror.platform.platforms` value to `linux/amd64` restricts mirroring to `amd64` child manifests and blobs for images in that scope while preserving each manifest list digest.
