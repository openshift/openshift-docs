= How oc-mirror plugin v2 processes sparse manifests

[role="_abstract"]
You can use multi-architecture filtering in oc-mirror plugin v2 to mirror only the blobs for the compute architectures you specify in the `ImageSetConfiguration` file while keeping each manifest list unchanged.

oc-mirror plugin v2 multi-architecture filtering depends on sparse manifest support in the target mirror registry. A manifest list is a multi-architecture image index that references per-architecture child manifests. A sparse manifest is a manifest list where the mirror registry stores blobs only for the architectures you specify, while keeping the manifest list and its digest unchanged. Without sparse manifests, omitting per-architecture manifests from a mirrored manifest list would change the manifest list digest and break disconnected cluster image references.

[id="oc-mirror-sparse-manifest-mirroring-behavior_{context}"]
== Mirror process for sparse manifests

When oc-mirror plugin v2 mirrors a multi-architecture image with filtering enabled, it processes the image as a sparse manifest.

oc-mirror plugin v2 reads the manifest list from the source registry or from the image set archive on disk, then mirrors child manifests and blobs only for the architectures listed in the image set configuration file. oc-mirror plugin v2 pushes the manifest list to the target mirror registry without modifying its content, so the digest matches the upstream manifest list. oc-mirror plugin v2 does not push child manifests or blobs for architectures that you excluded in the filtering rules.

A client that pulls the mirrored manifest list by digest receives the same digest as upstream. If a client requests an architecture that oc-mirror plugin v2 did not mirror, the mirror registry does not have the corresponding per-architecture manifest or blobs.

[IMPORTANT]
====
Multi-architecture filtering requires a target mirror registry that supports sparse manifests and allows disabling manifest list validation checks. The feature works only with this kind of registry. Registries that require every child manifest referenced in a manifest list to be present reject or break sparse manifests.
====

[id="oc-mirror-sparse-manifest-imageset-config_{context}"]
== Interaction with the image set configuration file

You enable multi-architecture filtering by adding architecture selection fields to the `ImageSetConfiguration` file. oc-mirror plugin v2 evaluates those fields when it mirrors platform release payload images, Operator catalog images, and additional images defined in the configuration file.


For example, when you set `mirror.platform.platforms` to `linux/amd64` only, oc-mirror plugin v2 applies that filter to release payload content in the image set. oc-mirror plugin v2 mirrors only `amd64` child manifests and blobs for multi-architecture images in that scope while preserving each manifest list digest.
