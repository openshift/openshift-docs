= RAID configuration parameters

[role="_abstract"]
You can learn how to configure RAID levels in {lvms} by using the `raidConfig` field in the `LVMCluster` custom resource (CR) to protect your data and optimize storage performance for your workloads. 

Use the available RAID configuration parameters to choose the right balance of redundancy, capacity, and performance for your specific use case.


.raidConfig fields in LVMCluster CR
[cols="1,1,2,1",options="header"]
|====
|Field
|Type
|Description
|Required

|`type`
|string
|RAID level (`raid1`, `raid4`, `raid5`, `raid6`, `raid10`)
|Yes

|`stripes`
|integer
|Number of stripes for RAID configuration. The number should always be a power of 2. Valid for `raid4`, `raid5`, `raid6`, and `raid10` only. Not valid for `raid1`.
|Depends on RAID type

|`stripeSize`
|string (quantity)
|Size of each stripe chunk. Must be a power of 2 (for example, `64Ki`, `128Ki`, `256Ki`, `512Ki`). Default is `64Ki`.
|Optional. Valid for `raid4`, `raid5`, `raid6`, and `raid10` only. Not valid for `raid1`.

|`mirrors`
|integer
|Number of mirrors for RAID1 and RAID10 configuration
|For RAID1: typically 1.
For RAID10: required with stripes.
|====

.Supported RAID levels and characteristics
[cols="1,1,1,2,2",options="header"]
|====
|RAID level
|Minimum disks
|Capacity overhead
|Performance characteristics
|Recommended use cases

|RAID1
|2
|50% (mirroring)
|High read performance, redundancy for 1 disk failure
|Read-intensive databases, high-availability applications

|RAID4
|3
|50% (mirroring)
|High read performance, redundancy for 1 disk failure
|Read-intensive databases, high-availability applications

|RAID5
|3
|1 disk (parity)
|Balanced read/write, redundancy for 1 disk failure
|General-purpose workloads, balanced performance and capacity

|RAID6
|5
|2 disks (dual parity)
|Good read, slower write, redundancy for 2 disk failures
|Critical data requiring dual-disk failure protection

|RAID10
|4
|50% (mirroring + striping)
|High read/write performance, redundancy for multiple disk failures if the disk failures affect different mirror sets
|High-performance databases, I/O intensive workloads
|====

[NOTE]
====
* All RAID configurations require thick provisioning mode.
* Once you create a RAID array, you cannot modify the RAID parameters such as type, stripes, or mirrors. Only device paths can be changed for disk replacement.
====
