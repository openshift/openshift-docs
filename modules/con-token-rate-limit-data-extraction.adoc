= Token usage extraction and provider response format compatibility

[role="_abstract"]
The `TokenRateLimitPolicy` custom resource (CR) extracts token usage from a model response by evaluating JSON Pointers against the response body. Built-in extraction settings support common provider response formats. If your provider uses a different format, you can customize extraction without changing the provider's response.

The `spec.dataExtraction.response.totalTokens` parameter defines an ordered list of JSON Pointers. Each pointer identifies a location in the response body that can contain a token usage value. For example, `/usage/total_tokens` identifies the `total_tokens` field in the `usage` object.
The first pointer in the list that resolves to a numeric value is used. A JSON number or a string containing only a valid number can supply the value.
The extraction settings apply to all limits in the policy. If you omit `spec.dataExtraction.response.totalTokens`, the policy uses the built-in defaults. A custom list replaces the default list rather than extending it. Include any default pointers that your policy still needs.

For example, the following configuration explicitly specifies the built-in JSON Pointers:

[source,yaml]
----
spec:
  dataExtraction:
    response:
      totalTokens:
        - "/usage/total_tokens"
        - "/usageMetadata/totalTokenCount"
        - "/response/usage/total_tokens"
        - "/usage/totalTokens"
----

[id="token-rate-limit-default-provider-formats_{context}"]
== Built-in provider response formats

The built-in defaults evaluate the following JSON Pointers in order:

[cols="1,3,4",options="header"]
|===
|Order |JSON Pointer |Response format

|1
|`/usage/total_tokens`
|OpenAI Chat Completions, Azure OpenAI, OpenAI-compatible servers, and non-streaming OpenAI Responses API responses.

|2
|`/usageMetadata/totalTokenCount`
|Google Gemini responses.

|3
|`/response/usage/total_tokens`
|Streaming OpenAI Responses API responses, which nest usage in the response object of the `response.completed` event.

|4
|`/usage/totalTokens`
|Non-streaming AWS Bedrock Converse API responses.
|===

For a custom response format, specify a JSON Pointer that identifies the token usage value returned by your provider.

The same pointer list applies to JSON and Server-Sent Events (SSE) responses. If a provider uses different paths for streaming and non-streaming responses, include both paths. For OpenAI Chat Completions streams, clients must request token usage by setting `stream_options.include_usage` to `true`.

[id="token-rate-limit-extraction-limitations_{context}"]
== Response format limitations

* Native Anthropic responses provide separate input and output token counts without a total token count. Extraction does not calculate their sum. Selecting only the output token count omits input usage and does not enforce a limit on total token usage.
* Native Ollama streaming responses use newline-delimited JSON, and AWS Bedrock ConverseStream uses a binary event stream. These streaming formats are not SSE and are not supported by the SSE extraction mechanism. Adding a JSON Pointer does not add support for these streaming formats.
* If none of the pointers resolve, the default behavior allows the request and does not update its token usage counter. The gateway increments the `body_extraction_misses` Prometheus metric when body extraction fails. Ensure that extraction settings match the provider's response format and that responses include usage data.
