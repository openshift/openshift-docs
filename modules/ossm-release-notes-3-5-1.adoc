= Red Hat OpenShift Service Mesh 3.5.1

[role="_abstract"]

This release of OpenShift Service Mesh is included with the OpenShift Service Mesh Operator 3.5.1. To view the OpenShift Container Platform versions that support Service Mesh 3.5.1, see link:https://access.redhat.com/support/policy/updates/openshift_operators[OpenShift Operator Life Cycles].

Service Mesh 3.5.1 addresses Common Vulnerabilities and Exposures (CVEs), which you can view at link:https://access.redhat.com/errata-search/?q=&p=1&sort=portal_update_date+desc&rows=10&portal_product=Red%5C+Hat%5C+OpenShift%5C+Service%5C+Mesh&portal_advisory_type=Security+Advisory&extIdCarryOver=true&sc_cid=RHCTG0180000371695[OpenShift Service Mesh Security Advisories].

This release also includes the following enhancement and fixed issues:

[id="ossm-enhancements-3-5-1_{context}"]
== Enhancement

PQC hybrid key exchange offered by default for TLS connections::
Proxies offer the X25519MLKEM768 post-quantum hybrid key exchange algorithm by default, making quantum-resistant connections available without requiring manual configuration.
+
In Istio versions 1.30 and later, proxies automatically include X25519MLKEM768 in the list of supported key exchange algorithms. This applies to all TLS connections except mesh mutual TLS (mTLS) between services. When clients that support this algorithm connect, the TLS handshake negotiates quantum-resistant protection. Clients that do not support X25519MLKEM768 fall back to classical algorithms (X25519, P-256, or P-384).
+
[NOTE]
====
This feature is not available when Federal Information Processing Standards (FIPS) mode is enabled.
====

[id="ossm-fixed-issues-3-5-1_{context}"]
== Fixed issues

Kiali Server namespace authorization enforced by role-based access control (RBAC) policies::
Before this update, three related security vulnerabilities caused Kiali Server API endpoints to return information about namespaces that a user was not authorized to access. Note that the impact was limited to information disclosure. The calling user was unable to modify data, and no secrets were exposed. Following are examples of the disclosed information:
* Cached cluster health data
* `ztunnel` logs and mesh-wide `ztunnel` configuration dumps (for ambient mode)
* Distributed traces
* Validation results attached to the cluster-wide Istio configuration list

These issues no longer occur. As a result of fixes in this release, all affected endpoints validate a caller's namespace access and reject unauthorized requests with 403 Forbidden errors. Users with restricted RBAC might see 403 errors for namespaces that they could view earlier, and the OpenShift authentication strategy rejects tokens that cannot view any namespace.
