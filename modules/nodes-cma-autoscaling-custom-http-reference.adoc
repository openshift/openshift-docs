= HTTP add-on reference

[role="_abstract"]
The HTTP add-on uses an `InterceptorRoute` resource to describe routing and metrics, and a `ScaledObject` resource to connect those metrics to the Custom Metrics Autoscaler Operator.

.`InterceptorRoute` resource
[cols="2,1,4",options="header"]
|===
|Field
|Required
|Description

|`spec.target.service`
|Yes
|Name of the backend service in the same namespace as the `InterceptorRoute` resource.

|`spec.target.port`
|Yes
|Port on the backend service.

|`spec.rules[].hosts`
|No
|Hosts to match against the HTTP `Host` header. An exact host takes priority over a wildcard. Omit this field to match any host.

|`spec.rules[].paths[].value`
|No
|Path prefix to match. The longest matching prefix wins. Omit paths to match `/`.

|`spec.rules[].headers[].name`
|No
|Header that must be present. Add `value` to require an exact header value. All headers in one rule must match.

|`spec.scalingMetric.concurrency.targetValue`
|No
|Target number of in-flight requests for each replica. Set this field, `requestRate`, or both.

|`spec.scalingMetric.requestRate.targetValue`
|No
|Target requests per second for each replica.

|`spec.scalingMetric.requestRate.window`
|No
|Window used to average the request rate. The default is `1m`.

|`spec.scalingMetric.requestRate.granularity`
|No
|Bucket size inside `window`. The default is `1s`.

|`spec.timeouts.request`
|No
|Total request deadline. `0s` disables the timeout. Omit the field to use the interceptor default.

|`spec.timeouts.responseHeader`
|No
|Time to wait for response headers after the request is forwarded. This value does not include cold-start wait time.

|`spec.timeouts.readiness`
|No
|Time to wait for a ready pod during a scale-up from zero replicas.

|`spec.coldStart.placeholder.response`
|No
|Static response returned while the workload has no ready pods. The request is still counted for scaling.

|`spec.coldStart.fallback.service.name`
|No
|Service that receives requests after the readiness timeout expires. The service must be in the same namespace as the `InterceptorRoute` resource.

|`spec.coldStart.fallback.service.port`
|No
|Port on the fallback service.

|`spec.staticRoutes[].rules`
|No
|Host, path, and header match for requests that must not trigger autoscaling.

|`spec.staticRoutes[].responseMode`
|No
|`WhenUnavailable` returns `response` only while the target has no ready pods. `Always` returns `response` for every match. The default is `WhenUnavailable`.

|`spec.staticRoutes[].response.statusCode`
|No
|HTTP status code for the static response.

|`spec.staticRoutes[].response.body`
|No
|Response body for the static response.
|===

.Scaled object fields for the HTTP add-on
[cols="2,4",options="header"]
|===
|Field
|Description

|`spec.scaleTargetRef.name`
|Name of the deployment to scale. The deployment must be in the same namespace as the scaled object.

|`spec.minReplicaCount`
|Minimum replicas. Set this field to `0` to scale to zero.

|`spec.maxReplicaCount`
|Maximum replicas.

|`spec.cooldownPeriod`
|Seconds that the HTTP metrics must stay at zero before the workload scales down. The default is `300`. This field is on the scaled object, not on the `InterceptorRoute` resource.

|`spec.triggers[].type`
|Must be `external-push`.

|`spec.triggers[].metadata.scalerAddress`
|Scaler address. Use `keda-add-ons-http-external-scaler.{cma-namespace}.svc:9090`.

|`spec.triggers[].metadata.interceptorRoute`
|Name of the `InterceptorRoute` resource in the same namespace as the scaled object.
|===

.HTTP add-on services in the `{cma-namespace}` namespace
[cols="2,4",options="header"]
|===
|Service
|Description

|`keda-add-ons-http-interceptor-proxy`
|Proxy that receives client traffic. The default port is `8080`. Point the {product-title} route at this service.

|`keda-add-ons-http-external-scaler`
|gRPC service that the Custom Metrics Autoscaler Operator queries. The port is `9090`.
|===
