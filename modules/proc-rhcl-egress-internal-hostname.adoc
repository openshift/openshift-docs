= Route egress traffic using an internal hostname

[role="_abstract"]
Enforce centralized egress security, offload TLS management, and avoid risky cluster-wide DNS overrides by configuring your applications to route traffic through an internal `Gateway` used as the hostname.

The `Gateway` object rewrites the host header and routes the request to the real external service with TLS origination. This approach does not requires DNS configuration and has the most straightforward TLS model.

.Prerequisites

include::snippets/egress-gateway-prereqs.adoc[]

.Procedure

. Optional: If you prefer a friendlier hostname, create an `ExternalName` service that aliases the `Gateway` service by using the following command:
+
[source,yaml,subs="+quotes"]
----
apiVersion: v1
kind: Service
metadata:
  name: _<httpbin_egress>_
  namespace: _<application_namespace>_
spec:
  type: ExternalName
  externalName: _<kuadrant_egressgateway_istio.gateway_system.svc.cluster.local>_

----
+
* Replace the `metadata.name` parameter value with the name of your application.
* Replace `_<kuadrant_egressgateway_istio.gateway_system.svc.cluster.local>_` with your egress `Gateway` internal service.
* Replace the `metadata.namespace` parameter value with the namespace where your application runs. Applications in that namespace can then use `http://httpbin-egress/get`. This creates a DNS alias within the cluster, not a transparent override of the real external hostname. You must configure the application to use this alias instead of the original hostname.

. Apply the CR by running the following command:
+
[source,terminal]
----
$ oc apply -f httpbin-egress
----

. Create the `HTTPRoute` that matches the internal service name and rewrites the `Host` header to the real external hostname. This replaces the `HTTPRoute` deployed during egress `Gateway` object setup. Use the following example:
+
[source,yaml,subs="+quotes"]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: _<httpbin_internal_hostname>_
  namespace: _<gateway_system>_
spec:
  parentRefs:
    - name: _<kuadrant_egressgateway>_
      namespace: _<gateway_system>_
  hostnames:
    - kuadrant-egressgateway-istio.gateway-system.svc.cluster.local
  rules:
    - filters:
        - type: URLRewrite
          urlRewrite:
            hostname: _<httpbin.org>_
      backendRefs:
        - group: networking.istio.io
          kind: Hostname
          name: _<httpbin.org>_
          port: 443
----
+
* Replace the `metadata.name` parameter value with name you want to use for your `HTTPRoute`.
* Replace the `metadata.namespace` parameter value with the namespace where you applied your egress `Gateway` object.
* Replace the `spec.parentRefs.name` parameter value with the egress `Gateway` object name.
* Replace the `spec.parentRefs.namespace` parameter value with the namespace where you applied your egress `Gateway` object.
* Replace `_<httpbin.org>_` with your external target service. The `URLRewrite` filter changes the `Host` header from the internal hostname to `_<httpbin.org>_`, and the `Hostname` backend routes the request to the real external service.
+
[NOTE]
====
The `Gateway` object listener does not restrict by hostname, so it accepts traffic on any host, including the internal service name.
====

. Apply the CR by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc apply -f _<httpbin_internal_hostname>_
----
+
* Replace `_<httpbin_internal_hostname>_` with name of the `HTTPRoute` CR.

.Verification

* Send a request from a pod using the internal service name by running the following command:
+
[source,terminal,subs="+quotes"]
----
$ oc exec test-client -n egress-test -- \
    curl -s http://_<kuadrant_egressgateway_istio.gateway_system.svc.cluster.local>_/get
----
+
Replace `_<kuadrant_egressgateway_istio.gateway_system.svc.cluster.local>_` with your egress `Gateway` internal service.
+
.Expected output
[source,json,subs="+quotes"]
----
{
  "headers": {
    "Host": "_<httpbin.org>_",
    "X-Envoy-Original-Host": "_<kuadrant_egressgateway_istio.gateway_system.svc.cluster.local>_"
  },
  "url": "https://_<httpbin.org>_/get"
}
----
+
* Replace `_<httpbin.org>_` with your external target service.
* `Host: _<httpbin.org>_` confirms the `URLRewrite` correctly rewrote the host header.
* `X-Envoy-Original-Host` preserves the original internal hostname.
* `url: https://_<httpbin.org>_/get` confirms TLS origination occurred.
