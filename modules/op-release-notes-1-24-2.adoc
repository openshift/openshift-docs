= Release notes for {pipelines-title} 1.24.2

[role="_abstract"]
{pipelines-title} General Availability 1.24.2 is available on {OCP} 4.14 and later supported versions.

[id="new-features-1-24-2_{context}"]
== New features and enhancements

.Cache

//SRVKP-13166
Content digest verification for cached build artifacts::
With this update, {pipelines-shortname} cache uploads preserve archive digests, and cache fetches can verify artifact integrity.
+
The `cache-upload` step action exposes a `digest` step result that contains the `sha256` digest of the uploaded cache. For OCI targets, this value is the pushed image manifest digest. For S3 or Google Cloud Storage targets, it is the SHA-256 digest of the uploaded tarball computed during stream writing. The `upload` command also writes this value to the `digest.txt` file in its working directory.
+
The `cache-fetch` step action provides a `CACHE_DIGEST` parameter, and the `fetch` command provides a matching `--digest` flag. When configured, {pipelines-shortname} verifies the fetched archive against the expected digest before extraction. If a digest mismatch occurs, the fetch operation fails with an integrity error and rejects the modified archive.
+
The `CACHE_DIGEST` parameter defaults to empty. When omitted, digest verification is skipped, and cache fetching functions as in earlier releases.
+
link:https://redhat.atlassian.net/browse/SRVKP-13166[SRVKP-13166]

//SRVKP-13575
Hardened cache key computation and namespace isolation::
With this update, cache key computation is hardened with length prefixing and namespace salting. File paths and content lengths are length-prefixed before hashing to prevent key collisions between different file sets. In addition, the cache key incorporates the namespace where the step executes, preventing pipelines in different namespaces from sharing cache entries.
+
[NOTE]
====
This change modifies all computed cache keys. The first pipeline run after upgrading encounters a cache miss and repopulates the cache. Previous cache entries expire based on backend retention policies.
====
+
The `cache-fetch` and `cache-upload` step actions read the namespace from the downward API. As a result, cache entries created in one namespace cannot be accessed from another namespace. To share a cache across namespaces, run the `cache` command directly with a fixed `--namespace` flag.
+
link:https://redhat.atlassian.net/browse/SRVKP-13575[SRVKP-13575]

== Fixed issues

.Multi-cluster

//SRVKP-13803
Syncer service does not reconcile existing secrets on spoke clusters::
Before this update, when the syncer service pushed a secret to a spoke cluster, it treated `AlreadyExists` responses as successful without validating existing content. As a consequence, subsequent changes or credential rotations on the hub cluster did not synchronize to the spoke cluster. Workloads on spoke clusters continued using stale secrets without generating warning logs. With this update, the syncer service controller reconciles existing secrets on the spoke cluster by comparing their type and data against the hub cluster copy. If differences exist, the controller updates the spoke secret with the hub payload. Labels, annotations, and metadata on the spoke cluster are preserved. As a result, secrets on spoke clusters remain synchronized with the hub cluster.
+
link:https://redhat.atlassian.net/browse/SRVKP-13803[SRVKP-13803]

.User interface

//SRVKP-14864
`PipelineRun` list crashes when displaying canceled pipeline runs with task runs::
Before this update, the {pipelines-shortname} web console `PipelineRuns` list failed to render with a `TypeError: Cannot read properties of undefined (reading 'length')` error. This occurred when the list contained a `PipelineRun` that was canceled after one or more `TaskRun` resources were created. As a consequence, the `PipelineRuns` list page was unusable. With this update, task status resolution logic handles canceled pipeline runs correctly. As a result, the `PipelineRuns` list renders properly, including canceled pipeline runs with their task status bars.
+
link:https://redhat.atlassian.net/browse/SRVKP-14864[SRVKP-14864]

//SRVKP-11221
Overview page returns a 404 error when clicking resolver-based pipeline links::
Before this update, clicking a pipeline name or pipeline run count on the Overview page caused a 404 error for resolver-based pipeline runs. This occurred because resolver-based pipeline runs do not have an associated `Pipeline` custom resource in the cluster. As a consequence, users could not navigate from the Overview page for these runs. With this update, the web console verifies whether a matching `Pipeline` custom resource exists before generating navigation links. If no pipeline definition exists, the console displays plain text without a link and provides an explanatory tooltip. As a result, 404 navigation errors no longer occur on the Overview page.
+
link:https://redhat.atlassian.net/browse/SRVKP-11221[SRVKP-11221]

//SRVKP-12176
Overview page displays active navigation links for deleted namespaces::
Before this update, the Overview page displayed active navigation links for pipelines associated with deleted namespaces when viewing all projects. As a consequence, clicking these links caused navigation errors. With this update, pipelines from deleted namespaces remain in aggregated metrics to maintain consistent dashboard counts, but navigation links to the pipeline, pipeline run count, and namespace are disabled. In addition, the interface displays a tooltip indicating that the namespace was deleted. As a result, dashboard metrics remain consistent without causing navigation errors for deleted projects.
+
link:https://redhat.atlassian.net/browse/SRVKP-12176[SRVKP-12176]
