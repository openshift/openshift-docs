= Sizing requirements for Argo CD Redis

[role="_abstract"]
Argo CD uses Redis as a cache and message broker for the application controller and repo server. Proper Redis sizing ensures optimal performance, especially when managing large numbers of applications or repositories.

*Default Redis configuration*

The default Argo CD instance includes a single Redis pod with the following resource allocation:

[cols="1,1,1",options="header"]
|===
|Component |CPU request |Memory request
|Redis |250m |128Mi
|===

This configuration is suitable for small to medium deployments managing up to 100 applications.

*Redis scaling guidelines*

Scale Redis resources based on your deployment size:

[cols="1,1,1,1",options="header"]
|===
|Deployment size |Applications |CPU request |Memory request
|Small |1-100 |250m |128Mi
|Medium |100-500 |500m |256Mi
|Large |500-1000 |1 |512Mi
|Extra large |1000+ |2 |1Gi
|===

*Redis high availability*

For production environments, consider deploying Redis in high availability (HA) mode:

* *Redis HA* - Uses Redis Sentinel for automatic failover and maintains three Redis replicas.
* *Resource requirements* - Each Redis replica should have the same CPU and memory allocation as the sizing guidelines recommend.

Configure Redis HA by setting the `.spec.redis.ha.enabled` field to `true` in the Argo CD custom resource.

*Monitoring Redis performance*

Monitor the following metrics to determine if you need to scale Redis:

* *Memory usage* - Redis should stay below 80% of allocated memory.
* *CPU usage* - Sustained CPU usage above 70% indicates a need to increase CPU allocation.
* *Connection count* - High connection counts can indicate the need for Redis HA.
* *Cache hit rate* - Low hit rates may indicate insufficient memory allocation.
