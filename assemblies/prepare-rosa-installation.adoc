= Plan 

== Plan a {hcp-title-first} deployment

:context: rosa-prepare-environment

toc::[]

[role="_abstract"]
When I am planning a new {hcp-title-first} deployment, I want to make the foundational architecture decisions that cannot be changed after cluster creation, so I can avoid costly rebuilds and ensure the cluster meets my organization's requirements for its entire lifecycle.

*Choose the cluster architecture*
When I am choosing a cluster architecture, I want to evaluate whether the Hosted Control Planes architecture or the classic architecture best fits my operational and workload requirements, so I can commit to an architecture that optimizes performance and resilience before the decision becomes irreversible.


*Plan network capacity and placement*
When I am planning cluster networking, I want to choose the zone layout and size the address ranges for nodes, workloads, and services so that the cluster can scale reliably without IP exhaustion, routing conflicts, or post-deployment redesign.


*Choose the cluster networking plugin (HCP only)*
When I am planning the cluster's pod networking implementation, I want to decide whether to deploy the cluster with the default OVN-Kubernetes CNI plugin or without a CNI plugin so I can install a third-party alternative, so that the networking layer meets my workload and policy requirements.


*Define how users and applications access the cluster*
When I am defining how users and applications access the cluster, I want to choose how the cluster API and application routes are exposed so that administrators, users, applications, and Red Hat operations teams can access the cluster through a network model that satisfies my organization’s security, connectivity, and isolation requirements.

*Plan outbound connectivity*
When I am planning outbound network access from the cluster, I want to select an egress architecture that controls how cluster components and workloads reach external services so that I can balance security, compliance, operational control, and developer productivity.

*Choose the authentication model (HCP only)*
When I am planning how cluster users and workloads will authenticate, I want to decide whether to use the built-in OpenShift OAuth server with identity provider integrations or to directly integrate an external OpenID Connect identity provider for authentication, so that the cluster's authentication architecture aligns with my organization’s existing IAM infrastructure, supports the required machine-to-machine workflows, and satisfies security requirements before the choice becomes permanent.

*Choose the cluster encryption strategy*
When I am defining the cluster’s data protection model, I want to choose the right KMS key strategy for encryption at rest so that cluster data, backups, and audit artifacts meet my organization’s security, compliance, and tenancy requirements.


*Plan compute resources*
When I am planning worker node capacity, I want to choose the appropriate worker node size, node count, and machine pool layouts that match workload characteristics so that applications run reliably, efficiently, and with appropriate isolation.
