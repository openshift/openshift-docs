= Upgrade

== {hcp-title-first} Upgrade Jobs

:context: rosa-prepare-environment

toc::[]

[role="_abstract"]
*Manage cluster upgrades and version lifecycles*
When my {hcp-title-first} cluster is running in production, I want to upgrade the cluster in a controlled and predictable way by upgrading the hosted control plane and machine pools at appropriate times so that I can remain within supported life cycle policies, adopt fixes and improvements, and minimize disruption to running workloads.

*Plan your upgrade strategy to align with lifecycle policies and maintenance windows*
When planning to upgrade my {hcp-title-first} cluster, I want to determine which versions are available and supported and decide when to upgrade so that I remain within life cycle policies and align upgrades with operational windows.

*Orchestrate cluster upgrades to maintain version compatibility*
When preparing an upgrade, I want to decide which parts of the cluster to upgrade and in what order so that version compatibility is maintained and upgrades complete successfully.

*Upgrade HCP to enable node updates*
When a newer supported version is available, I want to upgrade the hosted control plane so that the cluster can adopt fixes and improvements and support subsequent machine pool upgrades.

*Execute rolling upgrades for machine pools while protecting running workloads*
When the control plane is upgraded, I want to upgrade one or more machine pools so that worker nodes run a compatible version while minimizing disruption to workloads.

*Validate IAM Permissions*
When preparing an independent Machine Pool upgrade on a {hcp-title-first} cluster,I want to verify that our local AWS account IAM roles and security tokens align with the target version's worker-node requirements, so that the automated node provisioning sequence doesn't fail midway due to unauthorized AWS API calls.

*Audit Cluster Workloads for Upgrade Readiness*
When scheduling a targeted Machine Pool upgrade on a {hcp-title-first} cluster, I want to review application Pod Disruption Budgets (PDBs) and workload configurations tied to those specific nodes, so that node draining can proceed smoothly per machine pool without violating availability rules or stalling the localized upgrade sequence.

== {rosa-classic-title} Upgrade Jobs
*Manage cluster upgrades and version lifecycles*
When my {rosa-classic-title} cluster is running in production, I want to upgrade the entire cluster uniformly in a controlled and predictable way so that I can remain within supported life cycle policies, adopt fixes and improvements, and minimize disruption to running workloads.

*Plan and Schedule {rosa-classic-title} Upgrade Window*
When planning to upgrade my {rosa-classic-title} cluster, I want to determine which versions are available and supported and decide when to upgrade so that I remain within life cycle policies and align upgrades with operational windows.

*Validate IAM Permissions*
When preparing a managed OpenShift cluster upgrade, I want to verify that the IAM roles and permissions align with the target version's requirements, so that the automated infrastructure upgrade sequence doesn't fail midway due to unauthorized API calls.

*Audit Cluster Workloads for Upgrade Readiness*
When preparing a managed OpenShift cluster upgrade, I want to review application Pod Disruption Budgets (PDBs) and workload configurations, so that node draining can proceed smoothly without violating availability rules or stalling the upgrade sequence.

*Execute Automated Machine Pool Upgrade and Node Drain*
When a scheduled cluster upgrade triggers, I want the platform's automated routine to sequentially update machine pools and safely drain nodes, so that my worker nodes reach the target version with zero manual intervention and minimal disruption to live workloads.
