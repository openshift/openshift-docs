= Nested SPIRE for Zero Trust Workload Identity Manager

include::_attributes/common-attributes.adoc[]

:context: zero-trust-manager-nested-spire

toc::[]

[role="_abstract"]
Configure nested {spire-full} (SPIRE) so that SPIRE servers on multiple {product-title} clusters issue workload identities in one trust domain. A downstream server obtains an intermediate signing certificate from an upstream server. X.509-SVIDs chain to that shared root. JSON Web Token (JWT) SVIDs are verified with signing keys that the topology propagates.

Use SPIRE federation when each cluster keeps its own trust domain. Use nested SPIRE when every cluster must issue identities in one trust domain.

Setting up nested SPIRE for two clusters involves the following high-level steps:

. Create a kubeconfig that lets the upstream SPIRE server call the downstream cluster API, and store that kubeconfig in a Secret on the upstream cluster.
. Set `spec.grpcEndpoint` and `spec.nestedSpire` on the upstream `SpireServer` custom resource (CR).
. Copy the upstream trust bundle into a Secret on the downstream cluster.
. Set `spec.upstreamAuthority.spire` on the downstream `SpireServer` CR.
